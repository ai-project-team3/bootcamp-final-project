# 결정서

## ① 결정
> 한 문장으로. "무엇을 이렇게 한다"

**데모/PoC에서는 녹음 시작 전 "미팅 참여자에게 녹음 사실을 안내했습니다" 체크박스를 제공하고, 백채널에는 음성을 전송하지 않는다.**

- 체크 여부만 세션 정보(`recording_notice`)에 저장한다
- 체크하지 않았다고 해서 녹음 기능을 강제로 차단하지는 않는다
- 체크박스는 법적 동의를 판단·보증하는 기능이 아니라 **녹음 사실 안내를 상기시키는 운영 장치**다
- **백채널 동석자에게는 원본 음성을 보내지 않고 분석 결과·상태 정보만 공유한다** (#14와 같은 결정)
- 최종 서비스에서는 실제 이용 환경과 적용 법령을 검토한 뒤 정식 동의·고지 절차로 확장한다

**화면**

```
☐ 미팅 참여자에게 녹음 사실을 안내했습니다.
```

**세션 정보**

```text
recording_notice = true / false
```

## ② 근거
> 왜 그렇게 정했나. 조사했으면 출처를 남기세요

**1. 당사자 녹음은 처벌 대상이 아닙니다** 🔍 확인 2026-09-09

| 조문 | 내용 |
|---|---|
| **제3조** (통신 및 대화비밀의 보호) | 누구든지 이 법과 형사소송법 또는 군사법원법의 규정에 의하지 아니하고는 우편물의 검열·전기통신의 감청 또는 통신사실확인자료의 제공을 하거나 **공개되지 아니한 타인간의 대화를 녹음 또는 청취하지 못한다** |
| **제14조** (타인의 대화비밀 침해금지) | 누구든지 **공개되지 아니한 타인간의 대화**를 녹음하거나 **전자장치 또는 기계적 수단을 이용하여 청취할 수 없다** |
| **제16조** (벌칙) | 제3조를 위반해 공개되지 아니한 타인간의 대화를 녹음·청취한 자 → **1년 이상 10년 이하의 징역과 5년 이하의 자격정지.** 그렇게 알게 된 내용을 **공개·누설한 자도 같은 처벌** |

세 조문 모두 **"타인간의 대화"** 를 대상으로 합니다. **본인이 참여한 대화를 스스로 녹음하는 경우는
여기에 해당하지 않아** 형사처벌 대상이 아니고 사전 고지 의무도 없습니다.
2022년 상대 동의 없는 녹음을 처벌하는 개정안이 발의됐으나 부정적 여론으로 철회됐습니다.

→ **강제할 법적 근거가 없는데 강제하면 마찰만 생깁니다.**

> **제16조의 "공개·누설" 처벌도 우리에게는 적용되지 않습니다.** 그 조항은
> **"제3조 위반으로 알게 된"** 내용을 전제하는데, 당사자 녹음은 제3조 위반이 아니기 때문입니다.
> 따라서 리포트를 팀 안에서 공유하는 것 자체는 이 조항에 걸리지 않습니다.

**2. 🔴 그런데 백채널이 이 안전지대를 깹니다**

**대법원 2024. 2. 29. 선고 2023도8603 판결** 🔍 확인 2026-09-09

| | |
|---|---|
| 사안 | 거실 홈캠에 자동 녹음된 배우자·처가 식구의 대화를 피고인이 재생해 들음 |
| 판시 | **대화가 종료된 뒤 녹음물을 재생해 듣는 것은 '청취'가 아니다** → **무죄(상고기각)** |
| 함의 | 그 과정에서 **'청취'를 "대화가 이루어지는 도중에 실시간으로 듣는 행위"로 확정**했습니다 |

> **사후 재생은 면책됐지만, 실시간으로 듣는 것은 여전히 '청취'의 정의 안에 있습니다.**
> 원격 동석자에게 음성을 실시간 전송하면 정확히 이 정의에 들어갑니다.

**3. 그래서 통제 지점을 "누가 접속하는가"가 아니라 "무엇을 보내는가"에 둡니다**

방 코드(#14)는 동석 여부를 기술적으로 검증하지 못합니다 — 코드는 전화로 불러줄 수 있습니다.
**실효적인 통제는 음성을 아예 보내지 않는 것입니다.** 음성이 전송되지 않으면 청취가 성립하지 않습니다.

기획안 §2-4의 백채널 설계(같은 신호등을 보고 탭 한 번으로 신호)는 **원래 음성이 필요 없습니다.**
제약이 기능을 깎지 않습니다.

**4. 체크박스를 두는 이유**

법적 효력이 아니라 사용자 환기용입니다. 비용이 거의 0인데 발표 Q&A에서 답이 생깁니다.
CLAUDE.md 설계 원칙 ②(*"틀리면 위험해지는 것은 자동으로 확정하지 않는다"*)와 같은 논리로,
제품이 "동의를 받았다"고 판정하지 않고 **사람이 체크합니다.**

> ⚠️ **법률 자문이 아닙니다.** 조문과 판례는 확인했으나, 이를 우리 제품 상황에 적용한
> 해석(특히 **"원격 동석자에게 실시간 전송하면 청취에 해당할 수 있다"**)은 담당자의 판단입니다.
> 데모 단계에서 보수적으로 잡아둔 운영 정책이며, 최종 서비스에서는 실제 이용 관계·녹음 방식을
> 기준으로 **변호사 검토가 필요합니다.**

## ③ 탈락 대안
> 무엇을 안 골랐고 왜. 최소 하나

**A. 체크하지 않으면 녹음을 완전히 차단**
법적 리스크를 줄이는 데는 유리합니다. 그러나 당사자 녹음은 합법인데 제품이 더 엄격한 규칙을
강요하면, 절차가 아예 없는 경쟁 제품(클로바노트 등)으로 갈아탈 이유가 됩니다.
또한 시스템이 동의 여부를 법적으로 판단하는 것처럼 보일 수 있습니다.
**→ 강제 차단하지 않고 안내 확인 방식으로 결정**

**B. 참여자 전원의 명시적 동의를 받아야 녹음 가능**
최종 서비스에서는 검토할 수 있는 방식입니다. 하지만 데모에서는 참여자별 인증·동의 수집·기록까지
구현 범위가 커집니다.
**→ 최종 서비스 확장 사항으로 보류**

**C. 녹음 동의 절차를 아예 두지 않음**
구현은 가장 단순하지만 녹음 사실을 인지시키는 장치가 없습니다. 발표 Q&A에서
"상대 동의는 어떻게 받나요"가 나올 확률이 높은데 답할 게 없습니다.
**→ 최소한의 안내 확인 절차를 두기로 결정**

**D. 원격 백채널을 열고 동의를 필수화**
동의를 받아도 제3자의 실시간 청취가 당사자 동의만으로 해소되는지 불확실합니다.
**→ 불확실한 법적 리스크를 제품 기본 기능에 넣지 않습니다**
