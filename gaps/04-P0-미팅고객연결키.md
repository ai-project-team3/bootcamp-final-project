## 왜 공백인가

"A사 2차 미팅"의 **"A사"를 무엇으로 동일 판정**하나요. 사용자 수동 선택인지 CRM ID인지 이름 매칭인지가 없습니다. 차수별 누적이 해자(§7-2)인데, 그 해자를 지탱하는 연결 규칙이 비어 있습니다.

# 결정서

## ① 결정

### 연결 단위는 **딜(건)** 이다

회사도 사람도 아닌 **"이 건"** 을 단위로 삼는다.

```
"A사 신규 도입" ─ 1차 (김대리)
                ─ 2차 (박부장)      ← 담당자가 바뀌어도 이력 유지
                ─ 3차 (박부장 + 재무팀)

"김OO님 종신보험" ─ 1차
                  ─ 2차
```

```python
class Deal(BaseModel):
    id:           str
    label:        str            # "A사 신규 도입" / "김OO님 종신보험"
    template_id:  str            # 이 딜에 쓰는 영업 유형
    counterpart:  str            # 표시용 상대 이름
    company:      str | None     # 개인 영업이면 없음
    external_ref: str | None     # 나중에 CRM ID 넣을 자리
    voice_ref:    str | None     # ← 01에서 등록한 상대 임베딩
    created_at:   datetime

class Meeting(BaseModel):
    id:         str
    deal_id:    str
    seq:        int              # 차수 — 딜 안에서 자동 부여
    started_at: datetime
    ended_at:   datetime | None
```

**차수(`seq`)는 자동이다.** 딜에 묶인 미팅을 시간순으로 세면 나온다.

> **`voice_ref` 한 줄이 `01`과 물린다.** 대면 모드에서 1차에 등록한 상대 목소리를 딜에 저장해두면 **2차부터는 등록 구간이 필요 없다.** 미팅 시작하자마자 신호등이 켜진다.

### 식별은 사용자 수동 선택. 자동 매칭 없음

미팅 시작 화면에서 기존 딜을 고르거나 새로 만든다. **이름·회사명 자동 매칭은 쓰지 않는다.**

이 결정의 유일한 치명적 실패 모드가 **잘못 이어붙이는 것**이다. 그러면 다른 고객의 미해결 항목이 화면 ①에 뜬다. *"지난번에 예산 승인이 되돌아갔습니다"* 를 처음 만나는 고객에게 띄우는 순간 제품 신뢰가 끝난다. **오탐의 대가가 이득보다 훨씬 크다.**

### 시작 전 연결이 기본, 사후 연결도 허용

| | |
|---|---|
| **기본** | 미팅 시작 화면(§3 화면 ①)에서 딜 선택 |
| **예외** | `나중에 연결`로 그냥 시작 가능 |

미연결 미팅은 **1차처럼 동작한다**(이월 없음, 기본 세트로 시작). 미팅이 끝나면 리포트 화면에서 딜에 붙이고, 그때 **차수가 재계산되고 리포트가 갱신된다.**

전화가 갑자기 걸려오는 상황에서 제품을 못 쓰게 되는 걸 막는다.

### `unlink`는 MVP 필수

잘못 이으면 다른 고객의 미해결 항목이 이월되어 리포트가 오염된다. **되돌릴 방법이 없으면 그 딜을 버려야 한다.**

추가로 **화면 ①에서 "지난번 미해결" 목록 바로 위에 딜 이름을 크게** 표시한다. 자동 매칭을 안 쓰는 대신 **사람이 0.5초 안에 검증할 수 있게** 만드는 장치다.

## 목록 UI

### 행 컴포넌트는 하나만 정의한다

`DealRow` 하나를 만들고 **목록 · 검색 결과 · 필터 적용 후 · 홈 · 리포트 상단이 전부 같은 행을 쓴다.** 필터가 있든 없든 리스트의 모양은 바뀌지 않는다.

| 필드 | 내용 | 값이 없을 때 |
|---|---|---|
| `status` | 신호등 🔴 / 🟡 / ⚪ | 항상 있음 |
| `label` | 건명 | 항상 있음 (넘치면 말줄임) |
| `seq` | 차수 | 첫 미팅이면 `1차` |
| `person` | 상대 | **`미정`** |
| `open` | 미해결 건수 | **`0건`** (생략하지 않음) |
| `recent` | 최근 미팅 | **`—`** (첫 미팅) |

**모든 필드를 항상 렌더링한다.** 값이 없으면 자리를 비우는 게 아니라 대체 문자를 넣는다. 정렬이 무너지지 않는 방법은 이것뿐이다.

### 화면 ① — 딜 선택

```
┌──────────────────────────────────────────────────────┐
│  🔍 회사 · 담당자 · 건명으로 찾기        ＋ 새로 만들기 │
├──────────────────────────────────────────────────────┤
```

| | 건명 | 차수 ⇅ | 상대 | 미해결 ⇅ | 최근 ▼ |
|:--:|---|:--:|---|--:|--:|
| 🔴 | A사 신규 도입 | 2차 | 박부장 | 2건 | 6일 전 |
| 🟡 | 김OO님 종신보험 | 1차 | 김영희 | 1건 | 3일 전 |
| ⚪ | B사 갱신 | 3차 | 이차장 | 0건 | 12일 전 |
| ⚪ | 신규 문의 | 1차 | 미정 | 0건 | — |

네 번째 행이 **정보가 하나도 없는 새 딜**인데도 같은 모양을 유지한다.

**위에서 아래로 읽으면 순서가 맞는다** — `찾기` → `좁히기` → `정렬해서 보기` → `고르기`.

`＋ 새로 만들기`는 검색창 오른쪽에 붙인다. 목록이 길어져도 손이 닿는다.

### 검색

**건명 · 회사 · 상대를 한 번에 훑는다.** "A사"를 쳐도, "박부장"을 쳐도, "종신보험"을 쳐도 같은 딜이 나온다.

이 셋은 서로 배타적인 분류가 아니라 **같은 딜의 속성**이므로 필터로 나누지 않는다. 나누면 사용자가 *"회사로 찾아야 하나 사람으로 찾아야 하나"* 를 한 번 더 생각하게 된다.

### 정렬 — 최근 순 기본, 열 헤더 화살표

**기본 정렬은 최근 순이다.** 목록을 여는 가장 흔한 동작이 "방금 그 미팅 확인"이고 이건 매번 일어난다. "막힌 딜 찾기"는 의도적 행동이라 클릭 한 번 요구해도 된다. 기준이 타임스탬프 하나라 동점 처리 고민도 없다.

| 표시 | 뜻 |
|---|---|
| `⇅` | 정렬 가능, 지금은 비활성 (흐리게) |
| `▼` | 이 열로 **내림차순** 정렬 중 |
| `▲` | 이 열로 **오름차순** 정렬 중 |

한 번에 **한 열만** 활성이다. 다른 열을 누르면 이전 열은 `⇅`로 돌아간다.

**첫 클릭 방향은 열마다 다르다.**

| 열 | 첫 클릭 | 이유 |
|---|---|---|
| **차수** | `▼` 높은 차수부터 | 3차+ 패턴을 보려고 누름 |
| **미해결** | `▼` 많은 것부터 | 막힌 걸 찾으려고 누름 |
| **최근** | `▼` 최신부터 | 기본값과 같은 방향 |

*"미해결"을 눌렀는데 0건짜리가 맨 위로 오면 헛클릭이다.* 첫 클릭은 항상 의미 있는 방향으로 가고, 반대가 필요하면 한 번 더 누른다.

**`건명`·`상대`는 화살표를 아예 표시하지 않는다.** 가나다 정렬을 쓸 일이 없고, 없으면 누를 생각을 안 한다.

**드롭다운은 두지 않는다.** 다만 폰에서 행이 2줄로 접히면 헤더가 사라지므로 그때만 정렬 드롭다운이 뜬다. 화살표와 드롭다운은 같은 상태를 공유한다.

### 필터 — 홈에만, MVP 밖

§3의 화면 3장에 홈이 없다. **MVP에는 화면 ①만 있으면 되고 거기엔 필터가 필요 없다.** 미팅 12분 전에 필터를 고르고 있을 사람은 없다.

홈을 만드는 W5에 넣을 것:

**1행 — 상태 세그먼트 (단일 선택)**
> `전체` `🔴 막힘` `🟡 진행중` `⚪ 없음`

목록을 여는 이유가 *"어디가 막혔지"* 하나뿐이라 상태가 유일한 1급 필터다.

**2행 — 조건 칩 (다중 토글, 확장)**
> `2회 연속 미해결` `30일+ 방치` `3차 이상`

`2회 연속 미해결`은 §5-2가 **"이 고객의 핵심 장벽"** 이라 부른 것이다.

**필터 규칙 넷**

| 규칙 | 왜 |
|---|---|
| 필터를 걸어도 **행 양식 불변** | 목록 시스템이 하나이기 때문 |
| **결과 0건도 표 헤더는 남기고** 아래에만 문구 | 껐다 켤 때 레이아웃이 튀지 않음 |
| 필터 옆에 **항상 건수 표시** (`막힘 · 4건`) | 지금 뭘 보고 있는지가 늘 보임 |
| 홈은 **필터·정렬 유지**, 검색어만 초기화 | 리포트 보고 돌아왔을 때 그대로여야 함 |

### 좁은 화면

열이 다 안 들어가면 **2줄로 접되, 접는 규칙은 모든 행이 동일하다.**

```
🔴  A사 신규 도입                          2차
    박부장 · 미해결 2건 · 6일 전
```
```
⚪  신규 문의                              1차
    미정 · 미해결 0건 · —
```

둘째 줄에서도 `미정` `0건` `—`가 자리를 지킨다.

## ② 근거

**딜 단위인 이유.** 영업의 실제 단위는 회사도 사람도 아니고 "이 건"이다. Salesforce·HubSpot·Pipedrive가 전부 Deal/Opportunity 단위이고, §4-3에 나온 CRM들이 그렇다.

- **회사 단위**로 하면 담당자 교체 시 이월이 어색해진다 — 1차에서 김대리가 한 말을 2차에 나온 박부장에게 *"지난번에 이렇게 말씀하셨죠"* 로 띄우게 된다. 보험·개인 영업에는 회사 개념도 없다
- **사람 단위**로 하면 B2B에서 파편화된다. 같은 건이 김대리 → 박부장 → 결재라인으로 옮겨 다니면 이력이 세 조각으로 쪼개진다
- **딜 단위**는 §2-2의 *"1차 발견 / 2차 변화 / 3차+ 패턴"* 과 정확히 맞는다. 그게 딜의 수명주기다

그리고 **CRM 연동(§9-1 2층 로드맵)의 접합면이 공짜로 생긴다.** Opportunity와 1:1로 매핑되므로 `external_ref` 한 줄이면 된다. 회사명 문자열로 잡아두면 나중에 마이그레이션이 아프다.

**자동 매칭을 안 쓰는 이유.** 잘못된 이월은 되돌려도 이미 화면에 뜬 뒤다. 자동화의 이득(클릭 한 번)이 실패의 대가(제품 신뢰)에 비해 너무 작다.

**기본 정렬이 최근 순인 이유.** 가장 흔한 동작을 무료로 만든다. 막힌 딜 찾기는 의도적 행동이라 한 번의 클릭을 요구해도 된다.

**행 양식을 하나로 고정하는 이유.** 필터·정렬·검색이 바꾸는 것은 **어떤 행이 보이는가**이지 **행이 어떻게 생겼는가**가 아니다. 이 둘을 섞으면 화면이 상황마다 달라 보여 훑을 수 없게 된다.

## ③ 탈락 대안

**(1) 회사 단위** — B2B에서 자연스럽지만 담당자 교체 시 이월의 유효성이 애매해지고, 개인 영업에 적용할 수 없다.

**(2) 사람 단위** — 보험 1:1 상담에 딱 맞지만 B2B에서 같은 건이 여러 사람으로 쪼개진다.

**(3) 이름·회사명 자동 매칭** — 클릭을 줄이지만 오탐 시 다른 고객의 미해결 항목이 뜬다. 이 결정의 유일한 치명적 실패 모드다.

**(4) 캘린더 연동 자동 제안** — 마찰이 거의 0이지만 CRM·캘린더 연동은 §9-1에서 로드맵이다. W5 이후.

**(5) 음성 지문 자동 식별** — `01`에서 상대 임베딩을 이미 저장하므로 기술적으로는 된다. 다만 음성 지문 저장은 민감정보에 가까워 공백 `13`과 얽히고, 오탐 위험은 (3)과 같다. **제안만 하고 확정은 사람이** 하는 형태라면 로드맵으로 좋다.

**(6) 시작 전 연결만 허용** — 데이터가 깨끗하지만 급하게 시작한 미팅을 놓친다.

**(7) 회사/담당자/영업대상 필터 버튼** — 셋은 배타적 분류가 아니라 같은 딜의 속성이라 나눌 축이 아니다. 검색이 함께 훑으면 필터보다 빠르고 생각할 게 없다.

**(8) 기본 정렬을 막힌 순으로** — 제품의 목적에는 맞지만, 가장 흔한 동작(방금 미팅 확인)에 클릭을 요구하게 된다.

## ⑤ 첫 구현 스텝

**W1 (9/14~18)** — 역할 5

1. **`Deal` `Meeting` 모델 + 마이그레이션.** `seq` 자동 부여 로직 포함. 반나절
2. **`DealRow` 컴포넌트 하나** — 빈 값 대체 규칙(`미정` `0건` `—`) 포함. 이 컴포넌트가 이후 모든 목록 화면의 단위가 된다
3. **화면 ① 딜 선택** — 검색(건명·회사·상대 통합) + 최근 순 정렬 + `＋ 새로 만들기`
4. **`나중에 연결` 경로** — 미연결 미팅이 1차처럼 동작하는지 확인

**W3**

5. **이월 규칙 엔진** — §5-2 프리로드를 코드로. `03`의 `carryover` 변화를 생성한다
6. **`unlink`** + 차수 재계산
