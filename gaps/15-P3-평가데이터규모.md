# 결정서

## ① 결정
> 한 문장으로. "무엇을 이렇게 한다"

**되돌아감 40건을 목표로 잡고 역산해, 역할극 25세션(총 300분)을 촬영한다.**

**역산**

```
목표 되돌아감 사례        40건
세션당 심는 수            2건        ← PoC 실측 상한 (②-2)
                        ─────────
양성 세션                 20세션

+ 음성 대조군             5세션      ← 되돌아감 0건. 오탐 측정용
                        ─────────
총                       25세션 × 12분 = 300분
총 작업량                 약 40 person-hour → 5명이면 1인당 8시간
```

**라벨링**

- 전량 1명이 라벨링하고, **20%(5세션)를 2명이 독립 라벨링**해 Cohen's κ 를 계산한다
- 평가 단위는 **발화**로 정의하고 모든 라벨링에 동일 기준을 적용한다

**목표 기준**

| 지표 | PoC 목표 |
|---|---:|
| Recall (되돌아감 탐지) | ≥ 0.80 |
| Precision | 함께 측정 |
| F1 | 함께 측정 |
| Cohen's κ | ≥ 0.61 |

※ Recall 0.80은 **최종 서비스의 성능 보증이 아니라 데모/PoC의 목표값**이다.

## ② 근거
> 왜 그렇게 정했나. 조사했으면 출처를 남기세요

**1. 왜 Recall이 핵심 지표인가**
되돌아감 감지는 **놓치는 것(FN)을 줄이는 것**이 중요한 기능입니다. 놓치면 제품이 존재할 이유가
없어집니다. 다만 잘못된 알림(FP)도 사용자 경험에 직접 영향을 주므로 Precision·F1도 함께 냅니다.

**2. 왜 세션당 2건인가 — PoC 실측** 🔍 확인 2026-09-08

PoC 평가셋(`poc/eval/scripts.js`)에 대화 5건을 직접 쓰면서 되돌아감을 심어봤습니다.

```
세션당 1건     자연스럽다
세션당 2건     가능하다. 다른 항목에 심으면 어색하지 않다
세션당 3건 +   부자연스럽다. 고객이 계속 말 바꾸는 사람이 된다
```

**2건이 자연스러움의 상한입니다.** 그래서 40건 ÷ 2 = **20세션**입니다.

**3. 왜 음성 대조군 5세션이 필요한가**
Precision과 오탐률을 재려면 **되돌아감이 전혀 없는 세션**이 있어야 합니다.
양성 세션만 모으면 "되돌아감이 없는데 있다고 한 경우"를 관측할 표본이 부족합니다.

**4. 40건은 통계적 최소치가 아니라 6주 안의 목표입니다**

40건에서 Recall 0.80을 관찰해도 표본이 작아 실제 성능의 불확실성이 큽니다.
(예: 40건 중 32건 탐지 = 0.80)
따라서 결과를 최종 AI 성능으로 해석하지 않고 **PoC 검증 결과로 제한해 보고합니다.**

**5. 🔴 심어서 측정한다는 사실을 먼저 말해야 합니다**

```
심어서 측정한 Recall  =  "우리가 만든 되돌아감을 우리가 잡았다"
실사용 Recall        =  측정하지 않았다
```

자연 발생만 기다리면 세션당 0~1건이라 40건에 50세션 이상이 필요하고 6주에 불가능합니다.
그래서 심습니다. **대신 발표에서 "통제된 역할극에서 측정했고 실사용 데이터가 아니다"를
먼저 말합니다.** 숨기면 Q&A에서 깨지고, 먼저 말하면 방법론을 안다는 신호가 됩니다.

**6. ⚠️ Recall 0.80은 현재 0.0에서 출발합니다** 🔍 확인 2026-09-08

PoC에서 규칙 기반 매칭으로 재보니, **사전을 보지 않고 쓴 대화 5건에서 되돌아감을 4건 중
0건 잡았습니다**(`poc/REVIEW.md` §3-5). 튜닝된 대본에서는 2/2였습니다.

**0.80은 규칙 기반으로는 도달할 수 없는 값이고, 학습 모델 트랙이 성공해야 나오는 숫자입니다.**
파일럿에서 격차가 크면 목표값을 낮추거나 사건 수 보고로 전환합니다.

**7. κ ≥ 0.61 인 이유**
Landis & Koch 기준에서 **0.61~0.80이 substantial agreement 구간**입니다.
사람끼리 이 선을 못 넘으면 그 라벨로 모델을 채점해도 숫자에 의미가 없습니다.
⚠️ 관례적 기준이지 절대 기준이 아닙니다. **못 넘으면 모델이 아니라 판정 기준부터 다시 씁니다.**

**8. 공개 데이터셋은 선택지가 아닙니다** 🔍 확인 2026-09-09
한국어 영업 대화 코퍼스를 찾지 못했습니다. AI Hub의 상담 데이터는 민원·감성·일상 대화이고
본인인증 후 신청이 필요합니다.

## ③ 탈락 대안
> 무엇을 안 골랐고 왜. 최소 하나

**A. 자연 발생 사례만 수집**
실제 대화에 가까운 데이터라는 장점이 있습니다. 하지만 발생 빈도가 일정하지 않아 40건 확보에
필요한 세션 수를 사전에 보장할 수 없고, 추정치로도 50세션 이상입니다.
**→ 시나리오 기반으로 심되, 심었다는 사실을 함께 보고**

**B. 40세션 이상 (양성 80건)**
신뢰도는 높아지지만 촬영 16h + 라벨링 27h 로 **person-hour가 60시간을 넘습니다.**
6주에 모델 학습·화면·통합까지 해야 하므로 데이터에만 그만큼 쓸 수 없습니다.
**→ 25세션을 PoC 목표로 설정**

**C. 15세션으로 축소 (양성 24건 + 음성 3)**
person-hour가 약 24h로 줄어듭니다. 다만 표본이 작아 **Recall을 비율이 아니라
"24건 중 n건"처럼 사건 수로 보고**해야 합니다.
**→ 축소가 필요하면 이쪽입니다** (아래 ⑤ 파일럿 결과에 따라 판단)

**D. Recall만 측정**
탐지 여부를 빠르게 확인할 수 있지만 잘못된 탐지를 볼 수 없어 사용성을 판단하기 어렵습니다.
**→ Recall을 핵심 지표로 두되 Precision/F1도 함께 측정**

**E. 전량 2명 이중 라벨링**
일치도가 정확해지지만 라벨링이 17h → 34h 로 2배입니다. **20% 표본으로도 κ 추정은 됩니다.**

**데이터 구조** — #16 데모 Fixture와 동일한 형식을 씁니다.

```text
평가 데이터
 ├─ timestamp
 ├─ speaker
 ├─ text
 └─ gold_label
      ├─ 되돌아감
      └─ 일반 발화
```

- 정답 라벨(`gold_label`)은 별도로 관리합니다
- 같은 구조를 써서 **평가 · 개발 테스트 · 데모 Fixture를 연결**합니다
- 2인 라벨링 데이터는 별도 구분해 κ 계산에 사용합니다
- 실제 고객 대화가 아닌 시나리오 기반 데이터를 써서 개인정보 부담을 줄입니다
