용어사전에 정의만 있고 본문에 답이 없습니다. **1차 미팅은 이월할 게 없는데** 그때 화면 ①이 뭘 보여주나요. §4-4의 차별점("지난번 미해결")이 1차에서는 존재하지 않습니다.

**힌트** 1차용 화면 ①을 따로 설계할지, 유형별 기본 세트 5개로 대신할지(§5-2)

# 결정서

## ① 결정
> 한 문장으로. "무엇을 이렇게 한다"

**1차 미팅에서는 "지난번 미해결" 대신 선택한 영업 유형의 기본 확인 항목 5개를 "이번 미팅 기본 체크"로 보여주고, 2차 미팅부터는 실제 이월된 미해결 항목을 최우선으로 표시한다.**

## ② 근거
> 왜 그렇게 정했나. 조사했으면 출처를 남기세요

- 1차 미팅에는 실제 과거 상태가 없기 때문에 "지난번 미해결"을 임의로 만들면 제품의 핵심인 **상태 지속성의 신뢰**를 훼손한다.
- 반대로 화면을 완전히 비우면 첫 사용 시 제품 가치가 약해 보이고, 발표에서도 "첫 미팅에서는 무엇을 해주나"라는 질문이 남는다.
- 기획안이 항목을 자유 생성하지 않고 **유형별 마스터 풀에서 고르는 방식**을 전제로 하므로, 기본 5개 역시 같은 항목 풀에서 선택하는 편이 현재 구조와 일관된다.
- 1차와 2차 이후의 목적을 명확히 나누면 제품 설명도 쉬워진다.
  - 1차: **이번 미팅에서 기본적으로 확인할 것**
  - 2차 이후: **지난 미팅에서 아직 해결되지 않은 것**
- 기본 5개는 과거 상태처럼 표시하지 않고 별도의 "기본 체크" 영역으로 보여주어 실제 고객 반응이 들어오기 전 상태 이력이 있는 것처럼 보이지 않게 한다.

## ③ 탈락 대안
> 무엇을 안 골랐고 왜. 최소 하나

1. **1차 미팅에서 화면 ①을 완전히 비우는 안**
   - 콜드 스타트가 그대로 빈 화면으로 노출된다.
   - 첫 미팅 데모에서 제품 가치를 보여주기 어렵다.

2. **가상의 과거 미해결 항목을 만들어 보여주는 안**
   - 실제 존재하지 않는 이력을 보여주게 되어 상태 추적 제품의 신뢰성을 해친다.
   - 실제 이월 데이터와 데모용 가상 이력이 섞일 수 있다.

3. **항목 풀 30~50개 전체를 처음부터 노출하는 안**
   - 실시간 화면의 정보량이 과도해지고 사용자가 무엇을 우선 봐야 하는지 알기 어렵다.
   - 콜드 스타트 하나를 해결하기 위해 MVP UI가 불필요하게 복잡해진다.

## ⑤ 첫 구현 스텝
> 이 결정대로면 W1(9/14~)에 내가 무엇부터 만드나

1. 1차 미팅용 기본 체크 영역의 UI 골격을 만든다.
2. 선택된 영업 유형에서 기본 항목 5개를 받아 화면에 노출하는 fixture 데이터를 만든다.
3. `meeting_index == 1`일 때는 기본 체크를, `meeting_index >= 2`일 때는 이월 미해결 항목을 우선 표시하는 분기 규칙을 구현한다.
4. 기본 체크 항목은 과거 상태처럼 보이지 않도록 "지난번 미해결"과 시각적으로 구분한다.
5. 2차 미팅 fixture에서 실제 이월 항목이 표시되는 흐름까지 연결해 발표 데모 시나리오를 준비한다.
