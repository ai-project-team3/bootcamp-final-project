# 결정서

## ① 결정

### 용어 — "재발"로 통일

기획안의 **"되돌아감(재악화)"을 "재발"로 바꾼다.** 측정 단위는 범위로 구분한다.

```python
class Recurrence:
    scope: Literal["within_meeting", "cross_meeting"]
```

| 범위 | 무엇 | 측정 |
|---|---|---|
| **미팅 내 재발** | §2-1의 18:40 → 26:05 → 31:20 | **사건 검출** — 재현율·정확도 |
| **차수 간 재발** | §2-2의 1차 🟢 → 2차 🔴 | 차수별 최종 상태 비교로 파생 |

역할 3의 핵심 지표는 **미팅 내 재발 재현율**이다.

### 상태는 4개, 재발은 사건이다

```python
State = Literal["unseen", "raised", "partial", "resolved"]
RANK  = {"unseen": 0, "raised": 1, "partial": 2, "resolved": 3}

@dataclass
class StateChange:
    item_id: str
    at:      float     # 미팅 내 시각(초)
    from_st: State
    to_st:   State
    trigger: str       # 근거 발화 원문, 또는 "carryover" / "manual"
```

**항목의 상태를 따로 들고 다니지 않는다. 변화 리스트만 저장한다.**

| 파생되는 것 | 어떻게 |
|---|---|
| 현재 상태 | 마지막 변화의 `to_st` |
| **재발** | `RANK[to_st] < RANK[from_st]` 인 변화를 **필터링** |
| 화면 ② 타임라인 | *"18:40 나옴 → 26:05 풀림 → 31:20 다시"* = **리스트 그 자체** |
| 리포트 이력 | 차수별 리스트를 이어 붙이면 끝 |

재발을 상태로 두면 재발 후 일부 풀렸을 때 이력이 사라지고, 두 번 재발한 것을 구분할 수 없다. **사건으로 두면 몇 번이든 쌓인다.**

### 전이표

| 현재 | 사건 | 다음 | 재발 |
|---|---|---|:--:|
| ⚪ unseen | 매칭, 슬롯 0충족 | 🔴 raised | |
| ⚪ unseen | 매칭, 슬롯 일부 | 🟡 partial | |
| ⚪ unseen | 매칭, 슬롯 전부 | 🟢 resolved | |
| 🔴 raised | 슬롯 일부 충족 | 🟡 partial | |
| 🔴 raised | 슬롯 전부 충족 | 🟢 resolved | |
| 🟡 partial | 슬롯 추가 충족 | 🟢 resolved | |
| 🟡 partial | **슬롯 전부 취소** | 🔴 raised | ✅ |
| 🟢 resolved | **슬롯 일부 취소** | 🟡 partial | ✅ |
| 🟢 resolved | **슬롯 전부 취소** | 🔴 raised | ✅ |
| 모든 상태 | 사용자 수동 변경 | 지정값 | ❌ |

**규칙 다섯**

1. **⚪로는 돌아가지 않는다.** 한 번 나온 걸 안 나온 걸로 되돌릴 수 없다
2. **상태가 내려가면 전부 재발이다.** 🟢→🟡도 포함
3. **`speaker != "them"` 이거나 `confidence` 미달인 발화는 전이를 일으키지 않는다** (`01`에서 결정)
4. **`trigger == "manual"` 인 변화는 지표에서 제외한다** — 사용자 수정이 정확도를 오염시킨다
5. **마지막 상승 이후 30초 안의 재등장은 재발로 보지 않는다** — *"그 정도면 됐네요. 아 근데 금액이…"* 는 같은 턴의 연장이다. **30초는 W3에 fixture로 확정한다**

### 슬롯 취소는 `blockers`가 판정한다

`02`에서 정한 `Slot.blockers`(차단 예문)에 고객 발화가 **임베딩 유사도로 매칭되면** 그 슬롯을 취소한다.

```yaml
- key: approval_process
  cues:     [제 선에서 결정할 수 있습니다, 팀장님 결재만 받으면]
  blockers: [위에서 좀, 다시 봐야 할 것 같은데, 보고를 한 번 더]
```

§2-1 예시의 31:20 *"근데 위에서 좀…"* 이 정확히 `approval_process`의 blocker다.

**모델에게는 "닮았나"만 묻고 판단은 규칙이 한다.** §2-3이 카드에서 *"LLM은 마지막 한 칸에서 문장만 쓴다"* 고 한 것과 같은 구조다.

**`blockers`가 없는 항목**(상위 12항목 외)은 **재등장 휴리스틱**으로 폴백한다 — 🟢/🟡인 항목에 고객 발화가 다시 매칭되면 재발 후보로 본다. 재현율은 높고 정확도는 낮다.

### 재발은 자동 확정한다

탐지되면 **바로 상태를 내리고 화면에 표시한다.** 확인 단계를 두지 않는다.

§5-1이 자동 판정을 금지한 건 **"완료" 처리**다 — 오탐이 사용자를 *안심시켜* 위험을 만들기 때문이다. **재발은 방향이 반대다.** 오탐이 나면 *"이미 푼 걸 다시 보세요"* 라고 말하는 것이고, 이건 위험을 만들지 않는다.

안전장치 둘을 붙인다.

- **탭하면 되돌린다** — 배지를 눌러 이전 상태로 복귀 (`trigger: "manual"`)
- **그 복귀가 로그로 남는다** — 오탐 데이터가 자동으로 쌓이고, **W4에 오탐률이 높으면 확인 방식으로 전환**한다

### 차수 이월 — 이전 차수 색을 그대로 가져온다

신호등의 정의는 *"상대가 지금 걸려 있는 것"* 이다. 1차에서 예산이 막혔고 그 사이 아무 일도 없었으면, 2차 시작 시점에도 **상대는 여전히 예산에 걸려 있다.** ⚪로 리셋하는 건 사실과 다르다.

| 1차 최종 | **2차 시작 색** |
|---|:--:|
| 🔴 못 끝냄 | **🔴** |
| 🟡 일부 끝남 | **🟡** |
| 🟢 끝남 | **🟢** |
| ⚪ 안 나옴 (기본항목) | **⚪** |

**이월은 변화 하나로 기록한다.**

```python
StateChange(
    item_id = "budget_approval",
    at      = 0.0,
    from_st = "unseen",
    to_st   = "raised",      # 1차 최종 상태
    trigger = "carryover",
)
```

미팅의 상태 리스트가 **자기 완결적**이 된다. 시작 상태가 어디서 왔는지가 리스트 안에 있다.

**`trigger == "carryover"` 인 변화는 지표에서 제외한다.** 이월은 사건이 아니라 초기값이고, 안 빼면 재발 재현율이 오염된다.

### 표시 규칙

| 채널 | 뜻 |
|---|---|
| **색** | 그 항목의 현재 상태 (이월 포함) |
| **스티커** | 이전 차수에서 넘어왔는가 |
| **근거 발화 줄의 유무** | **이번 미팅에서 다뤘는가** |

| 스티커 | 조건 |
|---|---|
| `(이월)` | 이전 차수에서 넘어옴 |
| `(연속 2회)` | 2회 연속 미해결 — 강조 |
| `(연속 3회)` | §2-2의 "이 고객의 핵심 장벽" — 강조 |

§5-2가 *"3차+: 2회 연속 미해결 → 최상단 + 경고"* 라고 한 그 경고가 이 스티커다.

```
예산 승인    🔴 (이월)              ← 1차에 막힘, 이번엔 아직 안 나옴
결정권자     🔴 (이월)              ← 1차에 막힘, 이번에 또 나옴
             12:05 "위에 물어봐야"
계약 기간    🔴                     ← 이번에 처음 나옴
             08:30 "기간이 좀 긴데"
기존 계약    🟢 (이월)              ← 1차에 풀린 채 유지
```

**새 UI 요소가 하나도 늘지 않는다.** 색·스티커·근거 줄 셋 다 §3 목업에 원래 있던 것이다.

### 미팅 중에는 순서를 고정한다

**프리로드 규칙(§5-2)이 미팅 시작 시 순서를 정하고, 미팅 내내 바뀌지 않는다.** 색·스티커·근거 줄만 갱신된다.

| 차수 | 프리로드 |
|---|---|
| **1차** | 2층 전부 + 1층 기본 세트 5개. 템플릿 `priority` 순 |
| **2차** | 위 + **1차 미해결 전부 무조건 켬**<br>① 1차 미해결 ② 1차에 나온 것 ③ 1차에 안 나온 기본 항목 |
| **3차+** | 위 + **2회 연속 미해결을 최상단** |

**순서를 고정하는 이유 셋**

1. §3이 화면 ②를 *"곁눈질로 읽어야 한다"* 고 못박았다. 색이 바뀔 때마다 재정렬하면 화면이 출렁이고 방금 본 항목을 눈으로 다시 찾아야 한다
2. **공간 기억**이 생긴다 — "예산은 맨 위"가 몸에 익으면 시선이 한 번에 간다
3. **우선순위는 카드가 담당한다.** §2-3의 `지금 다룰 것`이 이미 동적으로 알려주므로 목록이 순위를 표현할 필요가 없다

새로 등장한 항목(`_other` 포함)은 **목록 끝에 추가**하고 기존 위치는 건드리지 않는다.

### 노출 규칙

| | 노출 | 숨김 | 상한 |
|---|---|---|---|
| **1층 · 반대사유** | 🔴 🟡 | ⚪ · 🟢 (카운터로) | **6줄.** 넘으면 하위를 `+N개 더`로 접음 |
| **2층 · 필수 항목** | ☐ ☑ **전부** | 없음 | 12개 (`02` 검증 규칙) |

1층은 제목이 곧 필터다 — **"반대사유"**. ⚪는 아직 안 걸렸고 🟢은 풀렸다. 6줄인 이유는 **곁눈질로 색 패턴을 인식할 수 있는 한계**가 그 정도이기 때문이다.

🟢에서 재발하면 **원래 자리로 돌아온다.** 순서가 고정돼 자리가 예약돼 있다. **사라졌던 줄이 다시 나타나는 것 자체가 색 변화보다 강한 신호**라 재발 알림으로 적합하다.

## ② 2층 — 필수 항목은 별도 모델이다

**2층은 신호등이 아니다.** 상태 모델과 인터랙션이 다르므로 화면에서도 분리한다.

| | 1층 · 반대사유 | 2층 · 필수 항목 |
|---|---|---|
| 상태 | 4개 + 재발 | **2개** (☐ / ☑) |
| 방향 | 오르내림 | **단조 증가** — 되돌아가지 않음 |
| 판정 | 슬롯 충족/취소 | **언급 여부만** |
| 재발 | 있음 | **없음** |

### 자동 체크한다. 다만 라벨은 "언급"이다

**언급이 감지되면 체크박스가 자동으로 채워진다.** 대기 상태를 두지 않는다.

§5-1의 위험은 상호작용이 아니라 **단어**에 있다.

> *"해지하시면 좀 손해 보세요"* ← 말은 했다. **설명일까?**
> *"3년 내 해지 시 낸 돈의 40%만 돌려받습니다"* ← 이게 설명이다

`☑ 해지환급률 **설명 완료**` 라고 뜨면 앞 문장만 말한 설계사가 의무를 다했다고 믿게 된다. 금소법 §19 위반이 이렇게 만들어진다.

그런데 §5-1은 동시에 **"말했나까지는 됩니다"** 라고도 한다. 자동 감지 자체는 허용 범위다.

| | 위험 | 안전 |
|---|---|---|
| 목록 제목 | 필수 항목 **완료** | **필수 항목 · 언급 여부** |
| 체크 의미 | 설명을 다 했다 | **이 얘기가 나왔다** |

**이 한 단어로 자동 체크가 안전해진다.** 설계사가 `☑`를 보고 *"말은 했지, 충분했나?"* 를 스스로 묻게 된다.

### 체크 후에도 자리를 지킨다

| | 사라짐 | **자리 유지 + 흐림** |
|---|:--:|:--:|
| 위치 고정 | ❌ 아래 항목이 위로 올라옴 | **✅** |
| 미완료 도드라짐 | ✅ | ✅ (☐ + 진하기) |
| 내가 뭘 말했나 확인 | ❌ | **✅** |
| 체크 애니메이션 | ❌ 사라지며 소멸 | **✅** |

사라지면 **재배치가 일어나** 1층에서 세운 "순서 고정" 원칙과 충돌한다. 그리고 채워지자마자 없어져 **애니메이션을 볼 시간이 없다.**

| 항목 수 | 동작 |
|---|---|
| **~12개** | 전부 자리 유지. 체크되면 흐려짐 |
| **전부 완료** | **열 전체가 한 줄로 접힘** — `필수 항목 · 언급 7/7 ✓` |
| 13개 이상 (드묾) | 완료된 것만 상단에 `✓ 완료 N ▾` 로 묶어 접음 |

전부 완료되어 가운데 열이 접히면 **반대사유와 카드가 그 공간을 쓴다.** 미팅 후반에 정작 필요한 두 열이 넓어지는 구조라, 접힘이 정리가 아니라 **화면 재배분**이 된다.

### 안전망 — 미팅 종료 화면에서 한 번

```
언급된 것으로 표시된 항목 7개

☑ 해지환급률      "3년 40%, 7년 78%…"   12:40
☑ 면책 기간       "90일 동안은…"         18:05

실제로 설명하셨는지 확인해 주세요.
                        [모두 확인]  [수정]
```

**미팅 중에는 한 번도 방해하지 않고**, 끝난 뒤 여유 있을 때 확정한다. §5-1의 *"최종 확정은 사용자가"* 를 지키면서 미팅 중 UX는 매끄럽다.

리포트에는 **`언급됨`과 `확인됨`을 구분해 기록한다.** 금소법 대응 근거가 필요할 때 이 구분이 값어치를 한다.

> 미팅 종료 시 `☐`가 남아 있으면 어떻게 할지는 공백 `11`이 정한다.

**§3의 "요소 넷" 규율은 유지된다** — 헤더 / 반대사유 / 필수 항목 / 카드. 세로로 쌓여 있던 걸 가로로 폈을 뿐이다. 백채널은 6초 배너라 요소가 아니다(§2-4).

**3열이 세로 스택보다 나은 이유**

1. **스크롤이 사라진다.** 세로로 쌓으면 10줄이 아래로 흐르고 카드가 화면 밖으로 밀린다
2. **각 열이 다른 질문에 답한다** — 좌: 상대가 뭘 걸고 있나 → 중: 내가 뭘 안 했나 → 우: 지금 뭘 해야 하나. **상황 → 의무 → 행동** 순서라 시선이 자연스럽게 흐른다

**카드는 2순위까지.** 1순위는 항목 + 근거 + 제안 문장, **2순위는 항목명 한 줄만.** 같은 크기로 두면 미팅 중에 둘을 비교하게 되고, 그 비교 비용이 카드의 목적(빠른 행동)을 깎는다.

**좁은 화면**(§6-4)에서는 세로 스택이 아니라 **탭으로 접는다** — `[반대사유 3] [필수 4] [카드]`. 세로로 흘리면 스크롤이 생겨 곁눈질이 불가능해진다. 기본 탭은 `카드`.

## ③ 탈락 대안

**(1) 재발을 5번째 상태로** — 기획안 §2-1 표기 그대로지만, 재발 후 일부 풀리면 어디로 가는지가 정의되지 않고 **재발했던 사실이 사라진다.** 두 번 재발한 것도 구분 못 한다.

**(2) 재발을 카운터로만** — 가볍지만 언제 왜 재발했는지가 없어 §3 화면 ②의 *"18:40 나옴 → 26:05 풀림 → 31:20 다시"* 를 못 그린다.

**(3) 재등장만으로 재발 판정 (blockers 없이)** — MVP에 쓸 수 있고 재현율은 높지만 정확도가 낮다. *"예산 말인데 언제까지 결정하면 되죠?"* 는 재등장이지만 재발이 아니다. `blockers` 없는 항목의 폴백으로만 남긴다.

**(4) LLM에게 재발 판정을 맡김** — 유연하지만 **채점 기준이 사라지고** 항목마다 호출이라 비용·지연이 붙는다.

**(5) 재발을 사람이 확인 후 확정** — 안전하지만 미팅 중에 탭할 여유가 없고, 재발 오탐은 안심시키는 방향이 아니라 위험을 만들지 않는다.

**(6) 이월 시 ⚪로 리셋 + 배지** — 색과 배지 둘을 읽어야 해서 곁눈질에 불리하고, **⚪는 사실과 다르다** — 그 항목은 안 나온 게 아니라 막힌 채다.

**(7) 색이 바뀌면 위로 재정렬** — 중요한 게 위로 오지만 미팅 중 화면이 출렁여 곁눈질이 불가능해진다.

**(8) 2층을 신호등에 함께 표시** — 요소가 줄지만 5상태 체계에 2상태짜리를 끼워 넣는 것이고, 인터랙션(탭 확정)도 다르다.

**(9) 체크리스트 항목이 사라짐** — 남은 것만 보여 깔끔하지만 재배치가 일어나 순서 고정 원칙과 충돌하고, 오탭을 되돌릴 수 없다.
