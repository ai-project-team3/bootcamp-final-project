## 4. `mistral-small-2603` 실행 차단

Mistral Admin의 해당 조직 한도 화면에는 다음과 같이 표시됐다.

- 모델: `mistral-small-2603`
- 분당 토큰: 20,000 TPM
- 초당 요청: 1.00 RPS
- 확인 화면: <https://admin.mistral.ai/plateforme/limits>

실제 호출은 모두 다음 오류로 거절됐다.

```text
HTTP 429 from https://api.mistral.ai/v1/chat/completions
message: Rate limit exceeded
type: rate_limited
code: 1300
```

다음 조건으로 원인을 분리했다.

1. 팀 프롬프트로 단일 문항 호출: 즉시 429
2. 충분한 쿨다운 후 단일 문항 재호출: 즉시 429
3. `{}`만 반환하는 최소 프롬프트 사용: 즉시 429
4. 최대 출력 토큰을 16으로 축소: 즉시 429
5. 같은 키로 `ministral-3b-2512` 호출: 성공
6. 같은 키로 3B 100문항 실행: 성공

따라서 잘못된 키, `.env` 로딩 실패, 계정 전체 API 비활성화, 스트리밍 형식, 프롬프트 크기나 호출 간격 문제는 배제했다.
Mistral 응답은 RPS·TPM·월간 토큰 중 어느 제한인지 구분하지 않으므로, 현재 결론은 **이 무료 조직에서 Small 모델 경로가 사용 불가능한 상태**라는 것이다.

공식 참고:

- <https://help.mistral.ai/en/articles/698531-why-am-i-hitting-api-rate-limits-and-how-do-i-increase-them>
- <https://docs.mistral.ai/admin/billing-usage/usage-limits>

### Small 후속 실행

Tier 1 키 또는 Mistral 측 한도 정상화 후 Admin Limits 값을 다시 확인하고 실행한다.

```powershell
python -u -X utf8 -m eval.run_team_eval `
  --models mistral-small-4 `
  --request-delay 0.2 `
  --max-retries 4 `
  --yes-spend
```

새 한도가 낮다면 `--request-delay`를 그 한도에 맞춰 늘린다. 프롬프트는 비교 조건 보존을 위해 변경하지 않는다.

## 5. 자모 손상 실험

프리셋 정본은 Android 소스의 `THEMES.label`이다.

```text
android/app/src/main/java/com/example/finalproject_demo/demo/Model.kt
```

현재 프리셋은 `우주`, `바닷속`, `공룡 나라`이며 결과는 다음과 같다.

| 강도 | 매칭 전 | 자모 매칭 후 | 합격선 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 0% | 100% | 100% | 100% | 통과 |
| 10% | 0% | 100% | 95% | 통과 |
| 25% + 음절·띄어쓰기 오류 | 0% | 100% | 85% | 통과 |

실기기 측정에서 발견된 오프라인 STT의 어절 전체 누락은 이 실험과 분리했다. 현재 장소 정본은 한 단어 값이 2/3이므로 값 자체를 통째로 지우는 방식은 실제 발화 누락을 대표하지 못한다. 실제 발화·전사 쌍이 확보되면 별도 표로 평가한다.

## 8. 2026-09-21 보조 진단 — 까닭 표지와 `extra`

안치영의 까닭 표지 전수조사(`feature/ahnchiyoung`의 `a8d4950`)를 같은 100문항 평가셋과 3B raw에 적용했다. 기존 100문항 결과와 원본 프롬프트는 변경하지 않았고 API도 다시 호출하지 않았다. 수치는 `results.md`의 「판정 보조 진단」 섹션에 누적했다.

- 표지 문항 28개, 그중 gold `s1_reason=false` 함정 10개. `S1-순차함정` 층 이름으로 함정을 세면 안 된다.
- 3B의 표지 문항 중 스키마 성공은 23개. `s1_reason` F1은 전체 성공 89건 기준 `0.400`, 표지 성공 23건 기준 `0.636`이다.
- 표지 함정 10개 중 8개를 올바르게 false로 판정했다.
- `asked=extra` 22개, gold `slot_1=extra` 22개. 스키마 성공 중 gold extra는 16개이고 `slot_1=extra` 클래스 F1은 `0.476`이다. 전체 `slot_1` macro F1 `0.431`과 함께 읽는다.
- `type`과 `asked`는 채점 라벨이 아니다. 모든 정답은 gold에서 읽는다. `type=S1`이지만 gold `s1_reason=false`인 4문항(j034, j085, j092, j100)도 그대로 false로 채점한다.
- F1은 참음성(TN)을 세지 않는다. 표지 없는 false가 전체 F1을 부풀린다는 해석은 부정확하다. 실제 3B에는 표지 없는 성공 문항의 false positive가 13건 있어 전체 F1이 표지 부분집합보다 낮다.

재현 명령:

```powershell
python -X utf8 -m eval.score_existing --models ministral-3-3b --diagnostics-only
```

이 명령은 로컬 `eval/raw/ministral-3-3b.jsonl`이 있어야 한다. raw는 Git에 없으므로 다른 컴퓨터에서 수치만 재현하려면 해당 파일을 별도로 안전하게 전달받아야 한다.
