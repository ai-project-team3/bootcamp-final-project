## 팀 회의 안건 — `s1_reason` 해석 쟁점

`guidelines/7_프롬프트.md` §2 "주의": *"`s1_reason`은 아이가 스스로 붙였을 때만 true. 마스코트가 '왜?'라고 되물어서 나온 답은 false."*

이 문장이 두 가지로 읽힌다:
- **해석 A(현재 100개에 적용한 기준)**: "되물어서"는 "1차 답변 실패 후 재질문"만 가리킨다 → 마스코트가 **처음부터** "왜?"라고 물어도(예: j050 "문어는 왜 그랬을까?" → "배고파서") true로 센다.
- **해석 B(박진웅 제기)**: "되물어서"를 "마스코트 질문에 '왜'가 있었는지" 자체로 읽으면 → **마스코트가 '왜'를 직접 물은 답변은 전부 false**가 되고, **안 물었는데 스스로 이유를 붙인 답변(j054 "친구가 아프니까"처럼)만 true**가 원래 의도였을 수 있다.

**영향 범위**: 해석 B를 채택하면 `asked=cause`류(왜 그랬을까 직접 질문) 문항이 재검토 대상 — 이번 100개 중 대표 사례는 **j050·j098**(둘 다 "왜 그랬을까?" 직접 질문 + `-서`/`-니까` 인과 답). **판정 규칙을 원래 설계한 쪽(조장/구현대본 작성자)에게 의도 확인 필요.** 결정 전까지는 해석 A로 100개 라벨을 유지한다.

## 팀 회의 안건 — `unclear` 처리 방식(카드 vs 후속 질문)

`guidelines/7_프롬프트.md` §2: *"`unclear`가 true면 앱이 **확인 카드 3장**을 띄운다(예: '공룡' → 티라노·긴목공룡·뿔공룡)."* `eval/judge_prompt.md`는 이 원문대로 고쳐 놓았다(2026-09-20).

**다만 박진웅은 이 세션 초반(가이드 문서를 찾기 전)에 카드 UI 대신 다른 방식을 직접 설계했었다** — unclear면 마스코트가 리액션 후("와! 공룡이구나!") 같은 칸을 더 파고드는 **후속 질문**을 바로 생성하는 방식("그 공룡은 어떻게 생겼어?"). 카드 3장을 미리 준비해 둘 필요가 없고, 대화가 자연스럽게 이어진다는 장점이 있다. **어느 쪽으로 갈지 팀 결정 필요** — 카드 방식이 확정 스펙이면 그대로, 후속 질문 방식을 검토하고 싶다면 `guidelines/7_프롬프트.md` §2·`backend`쪽 반영이 같이 필요하다.

## 저장소 문서 자체의 모순 — `guidelines/7_프롬프트.md` §5 vs 실제 계약

`guidelines/7_프롬프트.md` §5(책 자막 프롬프트 원문)의 출력 예시는 `title_candidates`(제목 5개)+`pages[{n,text}]`인데, `guidelines/3_API_명세.md` §3-3과 실제 구현(`backend/app/schemas/story.py`)은 `scenes[{index,caption,keywords}]`다 — **title_candidates 없음, keywords(이미지 에셋용 영어) 새로 있음.** `eval/story_prompt.md`는 더 최신인 API 명세+실제 코드 쪽을 따랐다(2026-09-20). **`guidelines/7_프롬프트.md` §5 자체를 갱신해야 할 것 같다** — 조장 확인 필요.

## 안치영에게 전달할 것 — 평가셋 자체의 설계 이슈

- **"~까? 왜?" 이중 질문 패턴 — 3건**: `d_role_do`·`d_need_why` 프로브 템플릿에서 한 문장에 두 가지를 동시에 묻는다. `guidelines/7_프롬프트.md` §1 "한 번에 한 가지만 묻습니다" 원칙과 어긋난다. **개별 문항이 아니라 프로브 템플릿 자체의 설계 결함**(박진웅 확인, 2026-09-20).
  - j041 "누가 제일 잘할까? 왜?" → 답이 "왜"에 응하지 않음(까닭 없이 역할만 말함)
  - j058 "누가 제일 잘할까? 왜?" → 답이 "왜"에 응함(`-거든` 인과)
  - j067 "뭘 챙겨 가야 할까? 왜?" → 답이 "왜"에 응하지 않음(물건만 말함)
  - 참고: "어? 로켓이 흔들려. 왜 그럴까?"류(`?`가 2번 나오지만 "어?"는 감탄사)는 질문이 실질적으로 하나라 문제 없음 — 전수 스캔해서 구분함
  - 라벨 자체(`s1_reason` 등)는 안 바뀜, **프로브 질문을 둘로 나누는 걸 제안**

## 아직 못한 것

- **안치영 검수 20개와 대조 → 일치도 숫자로 기록**: 검수용 20개가 아직 없어서 못함. 안치영이 20개를 별도로 라벨하면 위 표의 경계 사례부터 먼저 맞춰보면 될 것 같다(특히 `무관`+`contradiction` 동시 처리, `S1` 라벨 내부의 숨은 순차 함정).
