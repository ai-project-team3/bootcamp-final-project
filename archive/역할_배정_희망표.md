# 역할 배정 희망표 — 말로 짓는 인형극

> 역할은 넷입니다. **조장 자리(이야기 엔진 · 앱 골격)는 이종훈이 맡고, 나머지 세 자리를 박진웅 · 안치영 · 최민우가 나눕니다.**
> 네 자리 전부 실었습니다. 서로 어떻게 물리는지 알아야 하니 다 읽어주세요.
> 기준 문서는 `docs/말로짓는인형극_기획안.md` §12(모듈과 역할)입니다.

---

## 어떻게 정하나

1. 각자 **1지망 · 2지망**과 이유를 적습니다
2. 겹치면 조장이 조율합니다. 희망을 우선하되 프로젝트 리스크를 함께 봅니다
3. **Kotlin · Android 경험도 함께 적습니다.** 구현 언어(Kotlin 네이티브 vs Capacitor)가 이 답으로 정해집니다

---

## 먼저 알아야 할 것

**① 각자 AI 문제 하나와 자기 화면을 함께 가집니다.**
"프론트 담당"은 없습니다. 자기 기능의 화면은 자기가 만듭니다. 네 자리 모두 AI 모듈(●)이 들어 있습니다.

**② 각자 지표를 하나씩 소유합니다.** 이게 배정의 기준입니다.

**③ 여러분의 무대는 발표가 아니라 Q&A입니다.**

```
발표 10분     조장. 문제 · 차별점 · 데모 · 지표 한 장
Q&A 20~30분   팀 전체. 모델 · 측정 방법 · 법 · 설계 이유는 전부 여기서 나옵니다
              → 질문이 오면 담당자가 직접 답합니다
```

**④ W5에 각자 "내 지표를 올린 개선 하나"를 만듭니다.**
> *"CER이 31%에서 시작했는데 도감 이름으로 키워드 바이어싱을 넣어 24%가 됐습니다"*

**⑤ 아이 데이터는 기기 밖에 저장하지 않습니다.** 네 자리 모두 이 전제 위에서 일합니다.
프록시는 중계만 하고, 평가용 아이 녹음은 지표를 낸 뒤 바로 지웁니다. 외부 API로 무엇을 보내는지는
사업자 약관을 먼저 확인합니다 (OpenAI는 13세 미만 개인정보 처리 전 ZDR 승인 필요, Gemini API는 18세 미만 사용 앱 금지).

## 네 자리가 어떻게 물리나

```
            [조장] 앱 골격 · 대화 화면 · 녹음 버튼 · 그림판
                         │
 마이크 ─► [음성] STT · 아이/어른 구분 ─► [조장] 슬롯 엔진 ─► [생성] 레이어 생성 · 책 · 만지며 놀기
                         │                      │
                         └──────────────► [리포트] 발화 지표 · 활동 점수 · 오늘의 기록

            [리포트] 평가 러너 — 네 명의 숫자가 전부 여기서 나옵니다
```

| 누가 | 누구에게 무엇을 넘기나 |
|---|---|
| 음성 → 조장 · 리포트 | 발화 한 줄: 누가 말했나(아이/어른/모름) · 신뢰도 · 전사 |
| 조장 → 생성 | 확정된 슬롯값 (장소 · 친구 · 문제 · 소리 · 등장인물 · 해결) |
| 조장 → 리포트 | 슬롯을 누가 채웠나 (아이가 스스로 / 물어봐서 / 선택지로) |
| 생성 → 리포트 | 도구별 만진 횟수 · 가장 오래 본 장면 |

**앞단을 기다리지 않는 방법은 픽스처(정답이 붙은 대화 기록)입니다.** W1에 형식을 정하고
팀원 성인 대화로 몇 개 만들어 두면, 음성이 안 끝나도 슬롯 엔진 · 생성 · 리포트가 각자 돌아갑니다.

# 자리 A — 음성

> **한 마이크에서 아이 말과 어른 말을 가려 글자로 바꾼다.** 파이프라인의 입구.

모듈: **A 아동 STT 적응 · 키워드 바이어싱 · CER 표** (난이도 5) + **B 아이/어른 구분** (5) + **M 백엔드 프록시 · 배포** (2)

## 하는 일

| 주차 | |
|---|---|
| **W1** | 스파이크 ④ 한국어 아이·이모 녹음으로 아이/어른 구분 DER 실측 (Whisper 분류기 · 세션 내 등록 · age-gender · 텍스트 후처리 각각). 스파이크 ⑤ 마스코트 TTS가 말하는 중에 마이크 열기 + 에코 제거 (실기기). 스파이크 ⑥ 프록시로 STT 한 경로. 스파이크 ⑦ 마스코트 목소리 후보 3개. **STT 사업자 약관 확인 (ZDR · 아동 데이터)** |
| **W2~W3** | CER 표 (STT 사업자 × 조용/놀이 소음 × 발화 길이, AI Hub 소아 자유대화). 구분 방법 투표 결합 v1. 도감 이름 · 슬롯값 키워드 바이어싱. 프록시 무저장 구조 + 배포 |
| **W4** | 지인 자녀 평가 세션으로 DER. "14번 중 11번을 셌어요"의 신뢰도 기준을 데이터로 정함 |
| **W5** | 지연 · 배포 안정화, **CER · DER 최종 수치** |

**화면**: 관리자 웹의 API 사용량 · 비용 · 지연 페이지 (프록시가 남기는 숫자를 보여주는 곳)

## 필요한 것

음성 모델 평가 · 분류기 · 오디오 처리 · 서버 배포. **가장 "ML 연구 + 인프라"스러운 자리.**

## 어필점

> **개발** *"한국어 아동 자유발화 STT 4종 비교 CER 표 설계·측정, 한 마이크 아이/어른 구분 DER 0.NN"*

**"남들이 안 된다고 한 문제를 다른 방법으로 풀었다"는 서사가 있습니다.** 한국어 유아와 여성 보호자는
클러스터링 방식에서 DER 154%가 나온 보고가 있습니다. 그래서 클러스터링이 아니라 분류로 접근합니다.
그리고 이 숫자는 부모 리포트에 **"14번 중 11번을 셌어요"로 그대로 드러납니다.** 정직하게 공개되는 지표입니다.

## Q&A에서 답할 것

- **"아이 말을 STT가 알아들어요?"** → 공개 숫자 대신 직접 잰 CER 표. 조용할 때와 놀이 소음, 짧은 말과 긴 말로 나눠서
- **"폰 하나로 아이랑 어른을 어떻게 구분해요?"** → 클러스터링이 왜 실패하는지, 분류기 + 등록 + 텍스트 + 턴 구조를 왜 합쳤는지
- **"아이 목소리를 서버로 보내요?"** → 프록시는 중계만, 저장 · 로그 없음. 사업자 약관을 어떻게 확인했는지
- **"틀리면 리포트는요?"** → 신뢰도 낮은 발화는 세지 않고 몇 개를 셌는지 보여줍니다

## 알고 고르세요

🔴 **네 자리 중 기술 난이도가 가장 높습니다** (5 + 5). 한국어 아동 대상 공개 성능이 없어 전부 직접 재야 합니다.

🔴 **W1 부담이 앞쪽에 몰립니다.** 스파이크 ④가 나쁘게 나오면 리포트의 "센 발화" 설계를 다시 봐야 합니다.

🟡 **실제 아이 녹음이 있어야 숫자가 나옵니다.** 성인이 아이 흉내를 낸 녹음은 정확도 지표에 못 씁니다.
동의서 절차를 거친 녹음이 W4에 들어옵니다. 그 전에는 AI Hub 데이터로 작업합니다.

**안 맞는 사람**: 결과가 안 나오는 기간을 견디기 힘든 사람.

# 자리 B — 생성

> **슬롯값을 만질 수 있는 종이 인형극 책으로 바꾼다.** 아이와 심사위원이 실제로 보는 것.

모듈: **D 레이어 생성 · 표정 4장 · 스타일 · 아이 그림 처리** (4) + **E 일관성 벤치** (3) + **I 레이어 터치 · 스프라이트 · 등장 연출** (4)

## 하는 일

| 주차 | |
|---|---|
| **W1** | 스파이크 ② 투명 PNG 3장 합성 + 알파 히트테스트 터치 + 흔들림 (Android 실기기). 스파이크 ③ 이미지 API 투명 배경 실제 호출, 알파 254 확인. **이미지 사업자 약관 확인.** 스타일 시트 1장 |
| **W2~W3** | 슬롯 → 배경 · 캐릭터 생성, 표정 4장, 선택지 그림 3개. 책 6~8쪽 조립. 도구 4종 반응 · 등장 연출 4종 |
| **W4** | 일관성 벤치 (정체성 DINOv2 · 스타일 CSD · 같은/다른 캐릭터 쌍 격차). 1권당 실제 생성 장수 · 비용 실측 |
| **W5** | **일관성 지표 최종 수치** · 데모 책 품질 |

**화면**: 표지 · 책 한 쪽 · 에필로그 · 만지며 놀기 (기획안 §3의 10~12번)

## 필요한 것

이미지 생성 API · 프롬프트 · 임베딩 기반 평가 · 2D 그래픽과 터치. **가장 "생성 AI 애플리케이션"스러운 자리.**

## 어필점

> **개발** *"투명 레이어 분리 생성으로 터치 반응 그림책 구현, 캐릭터 정체성 격차 0.NN"*

**"그림을 잘 뽑았다"가 아니라 "일관성을 숫자로 쟀다"가 차이입니다.** 얼굴 인식 계열 지표는 종이 인형에 안 맞아
DINOv2 · CSD로 바꾼 판단, 리깅(Meta AnimatedDrawings)을 버리고 스프라이트로 간 판단을 근거와 함께 말할 수 있습니다.

## Q&A에서 답할 것

- **"페이지마다 캐릭터 얼굴이 달라지지 않나요?"** → 레퍼런스 + edits로 표정만 바꾸고, 그걸 정체성 격차로 쟀습니다
- **"아이 그림은 AI가 다시 그려요?"** → 절대 안 바꿉니다. 눈 스티커만 얹습니다. 왜 그게 원칙인지
- **"장면을 통째로 한 장 생성하면 안 되나요?"** → 레이어로 나눠야 만질 수 있습니다
- **"한 권에 얼마 들어요?"** → 실측한 장수와 비용

## 알고 고르세요

🟡 **발표 데모에서 가장 눈에 띄는 자리입니다.** 책이 깨지면 바로 보입니다.

🟡 **슬롯값만 있으면 앞단 없이 작업할 수 있습니다.** 픽스처 슬롯으로 W1부터 혼자 돌릴 수 있습니다.

🟡 **화면 작업 비중이 큽니다** (I 모듈). Android · Kotlin 경험이 있으면 유리합니다.

**안 맞는 사람**: 시각적 완성도를 끝없이 만지고 싶어지는 사람. 지표와 데모 품질 사이에서 멈출 줄 알아야 합니다.

# 자리 C — 발화 리포트

> **아이가 한 말을 부모가 읽을 기록으로 바꾸고, 팀 전체의 숫자를 만든다.** 이 주제를 부트캠프 주제로 만드는 자리.

모듈: **F 발화 지표 NLP** (3) + **G 리포트 문안 LLM · 금지어 가드 · 활동 점수** (3) + **H 평가 러너 · 픽스처** (3) + **L 리포트 시각화** (2)

## 하는 일

| 주차 | |
|---|---|
| **W1** | **픽스처 형식과 평가 러너 골격** (전사 정답 · 슬롯 정답 · 캐릭터 쌍). 형태소 분석기(kiwi) 스파이크. 지표 목록 v0 |
| **W2~W3** | 지표 5절 구현 (말하기 · 낱말 · 문장 잇기 · 이야기 짓기 · 함께 놀기). 활동 점수 항목 · 가중치 초안 (팀 확인). 리포트 문안 LLM + 금지어 가드. 오늘의 기록 화면 |
| **W4** | 평가 세션 수동 전사 vs 리포트 지표 일치도. 관리자 웹 평가 대시보드 |
| **W5** | **일치도 최종 수치** · 가드 테스트 (금지어가 한 번도 안 새는지) |

**화면**: 오늘의 기록 (기획안 §3의 15번) · 관리자 웹 평가 대시보드

## 필요한 것

한국어 NLP · 평가 설계 · LLM 출력 통제 · 데이터 시각화. **가장 "데이터 · 평가"스러운 자리.**

## 어필점

> **개발** *"아동 자유발화 지표 파이프라인과 공통 평가 러너 구축, 수동 전사 대비 일치도 0.NN"*
> **기획** *"진단이 아닌 기록 — 의료기기 경계를 넘지 않는 리포트 설계"*

**팀의 지표 인프라를 소유합니다.** 네 명의 숫자가 이 러너에서 나옵니다.
그리고 **"무엇을 안 보여주기로 했나"를 설명할 수 있는 자리입니다.** 또래 비교 · 규준 · 발음 판정을 뺀 이유가
근거(MLU 판별력 AUC .63~.68, 자유발화용 공개 발음 모델 없음)와 함께 있습니다.

## Q&A에서 답할 것

- **"이거 언어발달 검사예요?"** → 아닙니다. 지난번의 우리 아이와만 비교합니다. 왜 또래 비교를 뺐는지
- **"그 지표 믿을 수 있어요?"** → 수동 전사와 비교한 일치도. **표본이 5명이라는 걸 먼저 말하고**
- **"LLM이 '발달이 늦어요' 같은 말을 쓰면요?"** → 금지어 가드가 거부합니다. 어떻게 테스트했는지
- **"활동 점수는 뭘로 매겨요?"** → 언어 수준이 아니라 활동량의 가중합. 가중치를 어떻게 정했는지

## 알고 고르세요

🟡 **가장 깊이 파고드는 질문을 받습니다.** "그 숫자 어떻게 쟀어요", "진단 아니라면서 왜 점수가 있어요"가 이쪽으로 옵니다.

🟡 **앞단 오류를 받아서 씁니다.** 음성 쪽 구분이 틀리면 지표가 흔들립니다. 그래서 "센 발화만 센다" 규칙이 이 자리 몫이기도 합니다.

🟡 **부하가 W4~W5에 몰립니다.** 평가 세션 뒤 수동 전사 · 일치도 · 대시보드가 겹칩니다.

**안 맞는 사람**: 파고드는 질문과 문구 하나하나의 법적 경계를 챙기는 게 부담스러운 사람.

# 조장 자리 — 이야기 엔진 · 앱 골격 ✅ 이종훈

> **대화를 이야기 칸으로 채우고, 앱의 뼈대를 세운다.**

모듈: **C 이야기 엔진** (4) + **K Android 앱 골격** (3) + **J 그림판 · 녹음** (3) + **N 관리자 웹** (2)

## 하는 일

| 주차 | |
|---|---|
| **W1** | 구현 언어 결정 (이 설문으로). 슬롯 JSON v0. 스파이크 ① 구현 언어 · ⑧ 종이 프로토타입 12분 세션. 평가 동의서. 레포 재작성 · 앱 골격 · 관리자 웹 골격 |
| **W2~W3** | 슬롯 엔진 (답 판정 · 모순 · 되묻기 · 그림 선택지 · 필터). 질문 생성 가드. 대화 화면 · 그림판 · 녹음 버튼. 세션 재개 |

# 포트폴리오로 어떻게 쓰나

**어떤 자리를 맡든, W5에 세 가지를 남깁니다.**

**① 내 지표 Before → After**
> *"정체성 격차가 0.08이었는데 레퍼런스를 기본 컷 1장으로 고정해 0.21이 됐습니다"*

**② 내가 안 만들기로 한 것 하나와 그 이유**
> *"또래 평균과 비교하는 점수를 넣을 수 있었지만 안 넣었습니다. AI Hub 데이터는 규준이 아니고,
> 수준 판정은 의료기기 경계를 넘기 때문입니다."*

**③ 틀렸던 판단 하나와 무엇을 바꿨는지**
> *"클러스터링으로 아이/어른을 나누려 했는데 한국어 유아에서 무너진다는 걸 확인하고 분류기로 바꿨습니다."*

**③번을 숨기지 마세요.** 실패를 정직한 수치로 말하는 게 신입 포트폴리오에서 가장 강한 장면입니다.

| | | 예시 (C 발화 리포트) |
|---|---|---|
| **WHY** | 왜 이 문제인가 | 아이가 놀면서 한 말은 검사실 30분보다 자연스러운 표본인데, 아무도 남기지 않는다 |
| **HOW** | 어떻게 검증했나 | 수동 전사와 자동 지표를 같은 세션에서 비교 |
| **WHAT** | 무엇을 만들었나 | 형태소 기반 지표 5절 + 금지어 가드 + 공통 평가 러너 |
| **RESULT** | 수치 | 일치도 0.NN (n=5, 세션별 병기) |
| **LEARN** | 배운 것 | 기록과 진단의 경계는 기능이 아니라 문구 하나에서 무너진다 |
