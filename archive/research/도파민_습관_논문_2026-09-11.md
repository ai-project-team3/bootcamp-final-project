# 도파민·스마트폰 과의존 트렌드 리서치 (B2C 기말 프로젝트 주제 탐색용)

작성: 2026-09-11 · 표기: **[확인]** = 1차 출처(논문 초록/PubMed/PMC/공식 보도)에서 수치까지 직접 확인,
**[미확인]** = 2차 기사·리뷰 사이트 경유이거나 원문 수치를 못 열어 봄. 추정·과장 없음을 원칙으로 함.

---

## 0. 한 줄 결론

"도파민 중독/디톡스"라는 **대중적 프레임은 과장**이지만, 그 밑의 **행동과학(보상학습·습관·자기통제 실패)은
견고**하고, **"마찰(friction) + 사전 약속(commitment) + 적시 개입(JITAI)"은 무작위 실험으로 효과가 확인**됨.
기존 앱은 대부분 "차단/타이머"에 머물러 **우회·이탈·습관화** 문제가 큼 → 온디바이스 LLM로 "맥락을 이해하는 개입"이 빈자리.

**보조 근거**
- 전 세계 스마트폰 중독 유병률 **26.99%** (Meng et al., 2022, *Clinical Psychology Review*, [PubMed 35150965](https://pubmed.ncbi.nlm.nih.gov/35150965/)) **[확인: 논문 / 수치는 2차 인용 → 미확인]**. 척도마다 기준이 달라 국가 비교는 조심.
- 흑백(grayscale) 화면: 대학생 −39.7분/일(n=161; *Social Science Journal*), 20대 −20분/일(n=84; Dekker & Baumgartner 2024 *Mobile Media & Communication*) **[미확인: 초록 요약 경유]**. 효과는 있으나 소규모·단기.
- JITAI(적시 적응형 개입) 메타분석: 객관적 행동변화 g=0.77(21개 효과크기, n=592, [PMC10373115](https://pmc.ncbi.nlm.nih.gov/articles/PMC10373115/)); 정신건강 결과는 g=0.15로 작음(2025 *BMJ Mental Health*, [PubMed 41027677](https://pubmed.ncbi.nlm.nih.gov/41027677/)) **[미확인: 검색 요약 경유]**.
- 실행의도(if-then 계획): 642개 검증에서 d=0.27~0.66, "if-then" 형식·높은 동기·반복 연습일 때 더 큼 (Sheeran, Listrom & Gollwitzer, 2024, *European Review of Social Psychology*, [T&F](https://www.tandfonline.com/doi/abs/10.1080/10463283.2024.2334563)) **[확인: 초록]**. MCII(심적 대비+실행의도) g=0.336 (Wang et al., 2021, [PMC8149892](https://pmc.ncbi.nlm.nih.gov/articles/PMC8149892/)) **[확인]**.

### "도파민" 대중 담론 판정

| 대중 주장 | 판정 |
|---|---|
| "도파민 디톡스로 도파민 수치를 리셋한다" | **과장/부정확.** 도파민은 비축분처럼 "비우는" 물질이 아니라 **보상예측오차(기대보다 좋으면 발화, 기대만큼이면 조용, 못 미치면 억제)** 신호. 원 제안자(Sepah)도 행동요법으로 의도함 [미확인: 대중 과학 매체 경유] |
| "알림/좋아요 = 도파민 폭발" | **근거 부족.** 사회적 보상에 선조체가 반응한다는 fMRI는 있지만, 알림이 도파민 방출을 일으킨다는 **직접 측정은 거의 없음**. 알림의 신경 효과는 연구가 적음 |
| "숏폼이 뇌를 망가뜨린다" | **인과 미확립.** 메타분석(#5)도 상관이며 중국 표본 편중. 반대로 "전혀 무해"도 근거 없음 |
| "가변 보상(슬롯머신)이 중독을 만든다" | **행동 수준에선 타당**(#1 보상학습, #6 습관성). 신경전달물질 수준의 설명은 추정 |

→ 제품 카피에서 "도파민"을 쓰더라도 **기능 근거는 행동과학(마찰·약속·적시개입)**에 두는 것이 면접·심사에서 안전함.

## 3. 근거로 본 개입법: 효과 있는 것 vs 약한 것

| 개입 | 근거 수준 | 판정 |
|---|---|---|
| **마찰(friction)** — 열기 전 대기·질문 | PNAS 현장실험(#7) + CHI 13주 로그(#8) | **효과 있음.** 열기 −57%. 단 사용자가 곧 적응하면 효과가 줄 수 있음(장기 RCT 부족) |
| **사전 약속(commitment device)** — 스스로 미리 한도 설정 | AER RCT(#6) | **효과 있음.** −17%. "미래의 나"를 묶는 구조가 핵심 |
| **금전 인센티브** | AER RCT(#6) | 기간 중 −39%, 종료 후에도 일부 지속. 비용 누가 대나가 B2C 과제 |
| **실행의도(if-then 계획)** | 642개 검증 메타분석 | **효과 있음(작~중).** 스마트폰 특화 RCT는 적음 **[미확인]** |
| **JITAI(적시 적응형 개입)** | 메타분석 2편 | 행동 변화엔 중간 이상, 정신건강 결과엔 작음. **"언제 개입할지"를 잘 고를 때만** |
| **완전 차단/디톡스** | RCT(#9) + 메타분석(#10) | 효과는 있으나 **작고 유지가 어려움**(완수율 25.5%). 이견 존재 |
| **흑백 화면** | 소규모 연구 3편 | 20~40분/일 감소. 저비용 보조책 |
| **자기모니터링(대시보드·주간 리포트)만** | HCI 체계적 고찰(#11) | **약함.** 인지는 올려도 습관은 안 바뀜. 한국 위험군 83%가 "이미 인식" |
| **타이머 알림("30분 지났어요")** | #11 | **약함.** 준수율 매우 낮음(2% **[미확인]**) — 무시하고 닫는 게 습관화 |
| **사회적 책임감(친구와 공유·감시)** | 스마트폰 특화 RCT 못 찾음 | **미확인.** 운동·금연 분야 근거를 빌려 온 추정 — 주장 시 주의 |

| **Brick** (NFC 물리 키, 약 $59) | 기기를 태그해야 차단 해제 → 물리적 commitment | 긴급 해제 5회 제한(재충전은 이메일), 데스크톱 차단 없음, 안드로이드 웹 차단 미지원, NFC 인식 불안정 [미확인: 리뷰] |
| **Forest** | 집중하면 나무가 자람(게이미피케이션) | 앱을 켜야 작동 → **이미 동기 높은 사람**만 씀. 효과 RCT 못 찾음 [미확인] |
| **iOS 스크린타임 / 안드로이드 디지털 웰빙** | 기본 한도·리포트 | "15분 더" 한 번 탭으로 무력화 → 사실상 자기모니터링(#11의 약점) |
| **사이버안심존** (국내, 무료) | 부모가 자녀 사용시간·앱·위치 관리 | **부모 통제형**이라 청소년 본인 동기 없음 · 원스토어→2024-07 구글플레이 [확인: 앱스토어] |
| **스마트쉼센터** (NIA) | 전국 17개 시도 상담·교육·자가진단 | 오프라인 상담 중심, 일상 속 적시 개입 없음 [확인: 공식 사이트] |
| **챌린저스** (국내) | 1만~20만 원 걸고 목표 달성 시 환급 | commitment 구조는 근거 있음(#6). 단 사진 인증 방식이라 **스크린타임 자동 검증 불가** [미확인] |
| **열품타** (국내, 공부 타이머) | 공부 시간 공유·랭킹 | 공부 시간 측정 도구이지 과의존 개입은 아님 [미확인: 검색에서 확인 못 함] |

**플랫폼 제약 (설계에 결정적)**
- **iOS Screen Time API**(FamilyControls/DeviceActivity/ManagedSettings): 앱은 불투명 토큰만 받고, **사용량 원자료는 확장(extension) 안에서만 화면 표시 가능·네트워크 차단** → 서버로 로그 수집 불가 [확인: WWDC21 문서 + 개발자 글 [riedel.wtf](https://riedel.wtf/state-of-the-screen-time-api-2024/)]. one sec 개발자 본인도 API 결함을 공개 비판.
- **Android UsageStatsManager**: `PACKAGE_USAGE_STATS`는 런타임 팝업 불가, 사용자가 설정에서 직접 허용해야 함 → 앱별·시간대별 이벤트 로그 접근 가능 [확인]. 화면 내용 인식은 AccessibilityService가 필요하나 Play 정책 심사가 까다로움 [미확인].
- → **"로그는 기기 밖으로 안 나간다"는 제약이 오히려 온디바이스 LLM 설계와 맞아떨어짐.**

## 5. 근거 기반 B2C 아이디어 (2025~2026 기술로 새로 가능)

> 공통 전제: 온디바이스 모델 — Apple **Foundation Models framework**(iOS 26, 약 3B 파라미터, 오프라인·API 비용 없음, [WWDC25](https://developer.apple.com/videos/play/wwdc2025/286/)) [확인],
> Android **Gemini Nano / ML Kit GenAI**(AICore, [Android Developers](https://developer.android.com/ai/gemini-nano)) [확인]. 기종 제한 있음(최신 기기만) [확인].

### A. "의도 묻는 문지기" — 맥락 인식 마찰
- **근거**: 마찰(#7·#8) + 실행의도(if-then).
- **새로운 점**: one sec은 일률적 대기. 여기선 열 때 "뭐 하려고요?"에 한 줄 답 → 온디바이스 LLM이 **목적형(DM 답장) vs 무의식형(심심해서)**을 분류해 마찰 강도를 조절하고, 나갈 때 목적 달성 여부를 확인.
- **데이터**: 사용자 본인 입력 + UsageStatsManager 열기 이벤트(Android) / DeviceActivity 이벤트(iOS). 서버 전송 없음.
- **검증 지표**: 열기 시도 수, "의도한 열기" 비율(#8과 같은 지표 → 논문과 비교 가능).

### B. "숏폼 루프 감지기" — 스크롤 중 JITAI
- **근거**: JITAI는 **언제 개입하느냐**가 효과를 좌우. 숏폼 1회 평균 21분·월 49시간(한국).
- **새로운 점**: 앱 오픈이 아니라 **스크롤 도중** 세션 길이·연속 스와이프 패턴으로 "무의식 루프"를 감지해 개입. CHI 2026 "Seeing Your Mindless Face"([arXiv 2604.19424](https://arxiv.org/html/2604.19424))처럼 전면 카메라로 **자기 얼굴 보여 주기** 개입도 연구 중 [미확인: 초록만 봄].
- **데이터**: Android 사용 이벤트 + (옵션) 접근성 서비스 스크롤 이벤트. iOS는 제약 커서 **Android 우선**.
- **위험**: 접근성 권한 심사, 배터리.

### C. "미래의 나와 계약" — 자동 검증 commitment
- **근거**: AER RCT(#6) — 사전 한도 설정 −17%, 인센티브 −39%.
- **새로운 점**: 챌린저스식 사진 인증 대신 **기기 사용 로그로 자동 검증**하는 보증금 챌린지. 친구/스터디 그룹 단위.
- **데이터**: 기기 로그(요약 지표만 온디바이스 계산 → 달성 여부 1비트만 서버 전송).
- **위험**: 금전 거래 규제·어뷰징(기기 2대). 포인트/기부로 바꾸면 완화.

### D. "청소년 자기결정형 코치" — 부모 통제의 대안
- **근거**: 청소년 위험군 43.0%·중학생 47.6%(한국), 위험군 83%가 이미 과의존 인식. 부모 통제형(사이버안심존)은 본인 동기가 없음.
- **새로운 점**: 온디바이스 LLM이 **본인 로그를 대화로 해석**("어제 밤 12시 이후 쇼츠 94분 — 내일 1교시 전날엔 어떻게 할래?") → if-then 계획 작성 → 다음 날 그 시점에 JITAI. 부모에겐 **원자료가 아닌 합의한 목표 달성 여부만** 공유.
- **데이터**: 본인 기기 로그 + NIA 과의존 척도(공개 문항)로 자가진단 + 공공데이터포털 원자료로 또래 비교 기준선.
- **위험**: 미성년자 개인정보(법정대리인 동의).

### E. "스크린타임 → 시간 가계부" 회고 리포트
- **근거**: 자기모니터링 **단독은 약함**(#11) → 반드시 A~D 중 하나의 행동 개입과 결합해야 함. 단독 아이디어로는 비추천.
- **새로운 점**: LLM이 주간 사용 로그를 "어떤 순간에 무너졌는지" 내러티브로 요약하고 다음 주 if-then 계획 1개를 제안.
- **데이터**: 기기 로그(iOS는 DeviceActivityReport 확장 안에서만 렌더링 가능 — **LLM 입력으로 쓸 수 있는지 미확인**, 기술 스파이크 필요).

## 6. 팀 결정 전 체크 포인트

1. **iOS는 사용량 원자료를 앱 본체·서버로 못 가져감** → 로그 기반 아이디어(B·C·E)는 **Android 우선**이 현실적.
