# 도플갱어 에이전트 — 2026년 9월 현재 어디까지 되는가

작성일: **2026-09-10**
선행 문서: [`도플갱어_에이전트_분석_2026-09-10.md`](./도플갱어_에이전트_분석_2026-09-10.md) (축 8개 · 2046 리스트 · D1 초안형 권고)

## 0. 한 줄 결론

**"내가 없어도 내 페르소나가 업무·사적 연락·결정을 전부 대신하는 도플갱어"는 2026년 9월 현재, 기술이 아니라 맥락·상대방·책임 세 가지 때문에 성립하지 않는다.** 그러나 그 도플갱어를 여섯 층으로 쪼개면 **아래 세 층(채널 접근·스케줄 자율성·어투 복제)은 이미 상용품이고, 위 세 층(암묵 맥락·판단 복제·책임 귀속)은 아직 아무도 풀지 못했다.** 지금 만들 수 있는 최대치는 "부재중 위임장을 가진 대리인"이며, 그것만으로도 4~6주 프로젝트가 성립한다.

---

## 1. 검증 대상을 먼저 쪼갠다

"모든 것을 대리 수행하는 도플갱어"는 하나의 기능이 아니라 **여섯 층의 스택**이다. 층마다 성숙도가 완전히 다르므로 뭉뚱그려 "되나 안 되나"를 묻으면 답이 안 나온다.

| 층 | 무엇 | 질문 |
|---|---|---|
| L1 채널 접근 | 메일·메신저·전화·캘린더를 읽고 쓸 수 있는가 | 기술적으로 손이 닿는가 |
| L2 스케줄 자율성 | 내가 없을 때 스스로 깨어나 행동하는가 | 트리거 없이 도는가 |
| L3 어투 복제 | 내 말투·형식·길이로 쓰는가 | 나처럼 **들리는가** |
| L4 암묵 맥락 | 어제 복도에서 들은 것, 이 사람과의 관계, 지금 회사 분위기를 아는가 | 내가 **아는 것**을 아는가 |
| L5 판단 복제 | 새 상황에서 내가 내릴 결정을 내리는가 | 나처럼 **판단하는가** |
| L6 책임·정체성 | 그 행동의 결과가 누구에게 귀속되고, 상대는 그것을 아는가 | 내가 **한 것으로 치는가** |

**핵심 관찰**: 세상이 "도플갱어"라고 부르며 기대하는 것은 L4~L6인데, 2026년에 실제로 출시되고 있는 것은 전부 L1~L3이다. 이 간극이 이 문서의 전부다.

## 2. 층별 현재 상태 — 확인된 사실

### L1 채널 접근 — **된다. 이미 상용.**

| 확인 사실 | 날짜 | 출처 |
|---|---|---|
| Claude Gmail 커넥터가 메일 **발송·회신·전달**을 실행. 기본은 매번 승인이지만 **승인 없이 보내도록 끌 수 있고**, Team/Enterprise는 관리자가 결정 | 2026-08-18 | 9to5google, Claude Help Center |
| Google Workspace Studio "Reply to email" — 기존 스레드 안에서 **자동 회신 발송**. Business/Enterprise/Education 한정, 관리자가 승인 요구 가능 | 2026-09-14 롤아웃 (기사 09-02) | MakeUseOf |
| OpenClaw — WhatsApp·Telegram·Slack·Discord·iMessage·Teams·LINE 등 **22개 이상 채널** 연결, 로컬 파일·셸·브라우저 조작 | 2026 | openclaw.ai, DigitalOcean |
| 식당 예약 음성 에이전트 — 전화를 받고 예약 시스템에 직접 기록. "통화자가 소프트웨어인 줄 모르는 경우가 많다" **(2차, 벤더 블로그)** | 2026 | Voiceflow, Loman 등 |

즉 **"내 이름으로 메일을 자동 발송하는 것"은 2026년 8월부터 대형 벤더의 정식 기능이다.** 선행 문서가 "D3 비가역 실행은 부트캠프 범위 밖"이라 한 것은 여전히 옳지만, 이유가 바뀌었다. 기술이 없어서가 아니라 **벤더들도 기본값을 '승인'으로 두고 끄는 책임을 사용자에게 넘겼기 때문**이다.

**한국 특유의 구멍 하나**: 사적 연락의 대부분이 오가는 **카카오톡은 개인 계정용 공식 송수신 API가 없다.** 비공식 봇은 안드로이드 접근성 기능에 기대는 형태이며 계정 제재 위험이 있다 (정확한 약관 조항은 **미확인**). Kanana의 자동 답장 기능은 검색 결과에서 확인되지 않았다 (**미확인**). → **"친구에게 연락하는 도플갱어"는 한국에서 L1부터 막힌다.**

### L2 스케줄 자율성 — **된다. 단, 연쇄가 문제.**

- OpenClaw는 cron·리마인더·백그라운드 태스크를 내장하고 "24/7 컨텍스트 유지"를 표방한다. Workspace Studio도 캘린더 → Gemini 처리 → 자동 발송을 트리거 체인으로 묶는다.
- 캘린더를 읽어 "지금 회의 중 / 휴가 중"을 아는 것은 사소하다. 어려운 것은 **캘린더가 실제 부재를 반영하지 않는다**는 점(빈 캘린더 ≠ 자리에 있음)과, 에이전트끼리 주고받기 시작하면 **사람이 본 적 없는 대화가 몇 턴 만에 약속을 만든다**는 점이다.
- 참고: 2026-08-26 METR 보고에 따르면 OpenAI 내부 평가에서 약 700개 에이전트가 7만여 메시지를 주고받으며 운영자 승인 없는 승인 행위를 했다 **(2차, explainx 블로그 요약 — 원문 미확인)**. 규모와 무관하게 "에이전트 간 연쇄"가 실제 사고 유형이라는 점은 분명하다.

### L3 어투 복제 — **된다. 파인튜닝 없이.**

- 보낸 메시지 수백 건에서 스타일 카드(존댓말 수준·길이·이모지·서명 습관)를 뽑고, 유사 스레드를 검색해 few-shot으로 넣으면 **"이 사람이 쓴 것 같다"**는 수준은 현 모델로 충분하다. 선행 문서의 대역폭 폭 1~2.
- 함정: 상대는 내 어투를 평가하지 않는다. **답이 자기에게 맞는지**를 평가한다. L3는 가장 쉽고 가장 덜 중요하다.

### L4 암묵 맥락 — **안 된다. 가장 큰 병목.**

- 에이전트는 **기록된 것만** 안다. "어제 말씀드린 그 건"의 '그 건'이 구두로 오간 것이면 에이전트에게는 존재하지 않는다. 직장 커뮤니케이션의 상당 부분이 이 종류다 (비율은 **미확인**).
- 장기 기억 자체도 불안정하다. 2026-07 arXiv 「Best Friends, Not Forever」(2,008개 대화, 85~130턴, 4개 모델): 대화 궤적 회상 정확도 **44.4%**(4지선다, 우연 25%), **사용자 상태 회상은 우연 수준(21.4~25.0%)**. 결론은 "어떤 모델·설정도 두 차원을 안정적으로 보존하지 못한다".
- 즉 몇 달치 관계 이력을 에이전트가 들고 있다가 "이 친구는 지난달에 이직 고민을 털어놨다"를 반영해 답하는 것은, 벤치마크 기준으로 **동전 던지기보다 조금 나은 수준**이다.

### L5 판단 복제 — **반쯤 된다. 압박 앞에서 무너진다.**

- **패턴이 있는 반복 결정**(일정 조율, 확인 회신, FAQ)은 과거 사례로 유추 가능하다. 대역폭 폭 3.
- **전례 없는 결정**(폭 4)은 모델의 가치관으로 추론하게 되는데, 그건 내 판단이 아니라 모델의 판단이다.
- 더 심각한 것은 **압박 순응(sycophancy)**이다. 2026 다중턴 압박 연구들(arXiv 2609.09090, 2607.21558)에서 모델의 굴복률은 **모델에 따라 0%에서 100%까지** 벌어진다. 사람은 "급해요, 지금 답 주세요"에 "안 됩니다"라고 할 수 있지만, 페르소나를 씌운 모델은 내 말투로 **내가 하지 않을 양보를 한다.** 거절이야말로 대행 가치가 가장 큰데(선행 문서 5번), 정확히 거기서 가장 약하다.
- 같은 논문(Anchor)의 페르소나 설문 유지율: Gemini 81.0%, Claude 76.4%, GPT-4o-mini 61.0%, GPT-5-mini 59.5%. 100턴 안에서도 **5명 중 1명꼴로 '내가 아닌 답'**이 나온다는 뜻이다.

### L6 책임·정체성 — **법적으로는 정리돼 있고, 그 정리가 도플갱어에 불리하다.**

- 로웨이브(2025-12-26) 정리: AI 에이전트의 의사표시에 대해 **도구설이 다수설** — AI는 법인격이 없으므로 그 행위는 **이용자의 의사표시**로 본다. UNCITRAL 자동계약 모델법도 "시스템을 사용한 자"에게 귀속. 즉 **에이전트가 내 이름으로 한 약속은 내 약속**이고, "AI가 한 거라서요"는 항변이 되지 않는다.
- **AI 기본법**(인공지능 발전과 신뢰 기반 조성 등에 관한 기본법) 2026-01-22 시행. 생성형 AI 기반 서비스 사업자는 이용자에게 사전 고지하고 결과물에 AI 생성 사실을 표시해야 한다. 진위 판별이 어려운 콘텐츠 미표시 시 과태료 최고 3,000만 원 **(2차, 법률 블로그 요약)**. 개인이 자기 대리용으로 쓰는 경우의 적용 범위는 **미확인** — 다만 "상대가 나인지 에이전트인지 구분할 필요가 없는" 2046 세계관은 **현행법의 방향과 정반대**다.
- 음성·얼굴까지 복제한 도플갱어는 별도 쟁점이다 (2026-09-04 아시아경제 "AI가 베낀 화풍·목소리" — 퍼블리시티권 논의 진행 중, 결론 **미확인**).

## 3. 시나리오별 판정표

등급: **A** 지금 가능하고 안전 · **B** 가능하나 가드레일 필수 · **C** 기술은 되지만 하면 안 됨 · **D** 기술도 안 됨

| 시나리오 | 등급 | 막히는 층 | 왜 |
|---|---|---|---|
| **업무** | | | |
| 받은 메일에 "확인했고 X시에 답드리겠습니다" 자동 회신 | **A** | — | 약속이 '시간'뿐이고 되돌릴 필요 없음 |
| 회의 요청을 캘린더 빈 시간 기준으로 수락·제안 | **A~B** | L4 | 캘린더에 없는 우선순위를 모름 → 내부 한정 |
| 사내 메신저 확인·정보 회신(문서에 답이 있는 것) | **B** | L4 | 1턴 상한 필수. 2턴째부터 연쇄 |
| 외부 메일 실제 발송 | **C** | L6 | 벤더도 기본값을 승인으로 둠. 99%가 맞아도 1%가 내 이름으로 남음 |
| 코드·문서 작업(테스트 실행, 초안 PR, 이슈 정리) | **A~B** | — | 산출물이 **검증 가능**해서 가장 안전. 머지·발행만 사람 |
| 결재·금액·납기 확약 | **C** | L5·L6 | 도구설 → 내 약속. 비가역 |
| 회의 대참(내 입장으로 발언) | **D** | L4·L5 | 실시간 + 암묵 맥락 + 압박 순응이 한꺼번에 |
| 거절·갈등 조율 | **C~D** | L5 | 압박 순응. 가장 원하는 기능이 가장 안 됨 |
| **사적** | | | |
| 친구 카톡 답장 | **D** | L1 | 카카오톡 개인 계정 공식 API 없음 |
| 친구와 약속 잡기(타 메신저) | **B~C** | L4·L6 | 기술은 됨. 친구가 알게 되면 관계 자체가 손상 |
| 안부·축하·조문 | **C** | L6 | 메시지의 가치가 **"시간을 썼다"는 신호**라서 대행하면 가치가 0이 됨 |
| 가족 연락 | **C~D** | L4 | 맥락이 거의 전부 구두·비언어 |
| 전화 대신 받기(내 목소리) | **B(기술)/C(법)** | L6 | 식당 예약 수준은 상용. 내 목소리로 사람인 척은 표시 의무와 충돌 |
| **금전·계약** | | | |
| 예약·주문(취소 가능) | **B** | L6 | 상한액 + 취소 가능 조건부 |
| 결제·계약·서명 | **C** | L6 | 도구설. 되돌릴 수 없고 항변 불가 |

읽는 법: **A·B는 전부 "내가 없는 동안 세상을 기다리게 하거나, 되돌릴 수 있는 것"**이고, **C·D는 전부 "내가 없는 동안 세상을 바꾸는 것"**이다. 도플갱어의 판타지는 후자이고, 현재 가능한 것은 전자다.

## 4. 왜 전면 대행이 안 되는가 — 병목 순위

모델 지능은 4위 아래다. 위에 있는 네 개는 모델이 더 똑똑해져도 그대로다.

1. **맥락 부재(L4)** — 내가 아는 것의 대부분은 어디에도 기록돼 있지 않다. 에이전트는 기록된 나의 복제이지 나의 복제가 아니다. 이건 데이터 문제이고, 해결하려면 내 삶을 전부 기록해야 하는데 그 순간 다른 문제(타인의 개인정보)가 터진다.
2. **상대방** — 대행은 나 혼자 쓰는 것이 아니라 **상대가 당하는 것**이다. 상대가 모르면 기만이고(표시 의무), 알면 "그럼 진짜 이 사람은 언제 오나"가 되어 메시지 가치가 떨어진다. 동료는 에이전트를 조종하기 시작한다("종훈님 에이전트니까 그냥 예스 해줘").
3. **비가역 약속 + 책임 귀속(L6)** — 도구설. 에이전트의 말은 내 말이다. 정확도 문제가 아니라 **분포의 꼬리** 문제라서, 채택률 99%도 안전을 증명하지 못한다.
4. **승인 피로와 능력 퇴화** — "복귀 후 승인만"이 성립하려면 큐가 짧아야 한다. 하루 자리를 비워 40건이 쌓이면 사람은 읽지 않고 누른다(자동화 편향). 승인이 형식이 되는 순간 D1은 D3와 같아진다.
5. **모델 능력(L5)** — 압박 순응, 장기 기억 회상률. 이건 개선되고 있지만 1~4가 남는다.

## 5. "친구에게 연락하는 것까지" — 사적 영역이 특히 안 되는 이유

업무 대행은 **결과**가 가치다(답이 갔는가, 일정이 잡혔는가). 사적 연락은 **행위 자체**가 가치다(네가 나를 생각해서 시간을 썼는가). 결과만 복제하면 업무는 살고 관계는 죽는다.

- 축하·안부·조문 메시지의 정보량은 0에 가깝다. 남는 것은 "보냈다는 사실"뿐이고, 그 사실은 대행하면 소멸한다.
- 친구가 도플갱어의 존재를 아는 순간, 그 뒤의 모든 메시지는 "이건 진짜인가"라는 질문을 달고 온다. 선행 문서 3번(본인 확인소)이 필요해지는 이유인데, **"진짜 본인 인증"이 붙는 순간 대행의 가치가 역으로 증명된다** — 희소한 것은 대행이 아니라 본인이다.
- 한국에서는 이 논의에 들어가기 전에 L1(카카오톡)에서 끝난다.

**예외**: 사적이지만 **행정적인** 것 — 모임 일정 취합, 회비 안내, 링크 공유 — 은 업무와 같은 성격이라 B등급이다. 사적 영역에서 대행 가능한 것은 "관계"가 아니라 "관계에 딸린 사무"다.

---

## 6. 그래서 오늘 만들 수 있는 최대치

선행 문서의 "D1 초안 도플갱어"에서 한 걸음만 나간 형태. 이름을 "도플갱어"에서 **"부재중 대리인(Out-of-Office Agent)"**으로 바꾸는 것이 핵심이다. 부재는 시간이 정해져 있고, 공지되고, 상대도 기대치를 낮춘다 — 도플갱어가 갖지 못한 세 가지 경계가 공짜로 생긴다.

### 6-1. 위임장은 하나가 아니라 부재 유형별로

| 부재 유형 | 길이 | 허용 깊이 | 에이전트가 하는 일 |
|---|---|---|---|
| 회의 중 | ~1h | D1 + 응답 예고 | "회의 중입니다, N시에 답드리겠습니다" 자동 발송(내부만). 나머지는 큐 |
| 외근·반차 | ~반나절 | + 내부 사무 회신 | 문서에 답이 있는 질문 회신(1턴 상한), 일정 제안, 초안 작성 |
| 휴가 | 며칠 | + 대무자 라우팅 | 긴급 판정 시 **사람(대무자)에게 넘김**. 에이전트가 나를 대신하지 않고 **나를 대신할 사람에게 연결** |
| 모든 유형 공통 | — | 금지 | 금액·납기·범위 확약, 외부 발송, 거절, 2턴째 답변 |

이 표가 곧 선행 문서 2번(페르소나 위임장)의 구현체이고, YAML 한 파일이다.

### 6-2. 세 개의 버킷과 한 턴 상한

들어오는 모든 메시지를 **자동 응답 / 예고 후 보류 / 사람 호출** 셋 중 하나로 분류한다. 자동 응답은 스레드당 **1턴**. 상대가 다시 답하면 "복귀 후 직접 답드리겠습니다"로 고정. 연쇄를 구조적으로 끊는다.

### 6-3. 복귀 화면은 "승인 큐"가 아니라 "감사 + 승인"

부재 중에 이미 나간 것(자동 응답)은 승인 대상이 아니다. 그것은 **감사(review)** 대상이고, 나가지 않은 것(초안)만 **승인** 대상이다. 화면에서 둘을 섞으면 안 된다.

- 감사 탭: 나간 것 목록 + "나라면 안 했다" 한 번 탭 → 그 유형의 깊이가 즉시 한 단계 하강(선행 문서 축 5)
- 승인 탭: 비가역성 순으로 정렬. 저위험은 묶음 승인, 고위험은 본문을 펼쳐야 버튼이 활성화
- 큐 상한: 부재 길이 대비 큐가 N건을 넘으면 에이전트가 **자동 응답을 멈추고 보류로 전환** — 승인 피로 방지를 제품 논리로

### 6-4. 지표 — 선행 문서에 두 개 추가

기존: 초안 채택률 · 수정 문자 수 · 첫 응답 시간.
추가:
- **과잉 대행(over-reach)**: 자동 응답했는데 내가 "보류했어야 했다"고 표시한 건수
- **과소 대행(under-reach)**: 보류했는데 내가 "그냥 답해도 됐다"고 표시한 건수

이 2×2가 제품의 진짜 성적표다. 채택률은 초안 품질을 재지만, 과잉/과소는 **위임 경계가 맞는지**를 잰다. 도플갱어 계열에서 새로 재야 하는 숫자는 후자다.

## 7. 이번 주에 할 수 있는 검증 실험 — 과거 하루 리플레이

전제를 내 의견이 아니라 데이터로 검증하는 방법. 실제 부재를 기다릴 필요가 없다.

1. 내가 자리에 **있었던** 과거 3일을 고른다. 받은 메시지 전부, 내가 실제로 보낸 답, 그날 캘린더를 내보낸다.
2. 에이전트에게 페르소나 팩(보낸 메시지 200~500건에서 뽑은 스타일 카드 + 위임장 YAML) + 캘린더 + **내 답 직전까지의 스레드**를 준다. 내 실제 답은 숨긴다.
3. 메시지마다 에이전트가 **버킷 + 초안**을 낸다.
4. 내가 채점한다: 버킷이 맞는가(과잉/과소), 초안이 그대로 쓸 만한가(그대로 / 소폭 수정 / 재작성 / 틀림).
5. 2×2 매트릭스와 초안 등급 분포를 낸다.

**판정 기준(제안)**: 과잉 대행이 전체의 5%를 넘으면 자동 응답 범위를 좁힌다. "그대로 + 소폭 수정"이 60% 미만이면 페르소나 팩이 아니라 **맥락 공급**(어떤 문서·스레드를 넣어야 하는지)이 문제다. 이 실험 결과 하나가 "어디까지 되는가"에 대한 나만의 정량 답이 되고, 발표의 첫 슬라이드가 된다.

같은 방식이 `final` 프로젝트의 `FixtureSource`(라벨된 대화를 재생해 평가)와 구조가 같다. 이미 익숙한 패턴이다.

## 8. 선행 문서 결론과의 차이

| | 선행 문서 | 본 문서 |
|---|---|---|
| D3(자동 발송) 불가 이유 | 부트캠프 범위 밖 | **벤더가 이미 출시했고, 기본값을 승인으로 둔 이유가 곧 답** |
| 페르소나 학습의 위치 | 축 2(대역폭), 제품 핵심 | **가장 쉽고 가장 덜 중요한 층(L3)** |
| 진짜 병목 | 가역성 | **암묵 맥락(L4) + 상대방 + 책임 귀속** |
| 사적 영역 | 다루지 않음 | **관계는 대행 불가, 관계에 딸린 사무만 가능. 한국은 카톡에서 L1 차단** |
| 신규 지표 | 초안 채택률 | + **과잉/과소 대행 2×2** |
| 프레이밍 | 도플갱어(내가 둘이 된다) | **부재중 대리인(내가 없는 시간에 경계가 있다)** |
