# 5. 기술 스택과 폴더 구조 🔒

폴더 구조 · 스택 · 환경변수 이름은 동결입니다. 자기 폴더 안은 자유입니다.

---

## 5-1. 스택

| 계층 | 선택 | 근거 |
|---|---|---|
| 프론트 | **React + Vite** | 미니프로젝트 승계 |
| 백엔드 | **FastAPI + SQLAlchemy** | 미니프로젝트 승계 |
| DB | **MySQL** | MariaDB에서 전환. 관리형 선택지가 넓고 참고 레포와 동일 |
| 실시간 | **FastAPI WebSocket 단일 채널** | 소켓 하나면 순서 보장이 공짜 |
| STT | ⚠️ **W1 스파이크로 확정** | 한국어 스트리밍 정확도는 실측 없이 못 고름 |
| LLM | **`claude-opus-5`** | 카드 문장 · 리포트 생성 |
| 임베딩 | ⚠️ **W1 스파이크로 확정** | 한국어 문장 유사도 |

**STT와 임베딩은 인터페이스만 먼저 동결하고 구현체를 교체 가능하게 둔다.**
`SpeakerSource`(§4-1)와 매칭기 내부 인터페이스가 그 경계다.

**LLM은 카드의 마지막 한 칸과 리포트 문장에만 쓴다.** 항목 생성·상태 판정·재발 판정에 쓰지 않는다.

```
bootcamp-final-project/

│   └── 구현기획안.md

│   ├── .env.example
│   └── app/
│       ├── config.py              ← pydantic-settings
│       ├── database.py            ← 엔진 · 세션 · Base
│       ├── schemas/               ← API 요청/응답 (2번 문서 그대로)

│       ├── matching/              ← 역할 2
│       ├── state/                 ← 역할 3
│       ├── generation/            ← 역할 4

│       └── templates/             ← 데이터. 코드 아님
│           ├── catalog.yaml
│           ├── insurance_consult.yaml
│           └── harvested/{item_id}.jsonl
├── fixtures/
│   └── meeting_001.json ...       ← 라벨된 역할극. 평가 정본
└── frontend/
    ├── package.json  vite.config.js  index.html
    └── src/

        └── styles/theme.css       ← 디자인 토큰 (CSS 변수)
```

**규칙**

- `routers/` 파일은 **개별 소유**다. 자기 파일만 고친다
- `main.py`에는 **자기 라우터의 `import`/`include_router` 두 줄만** 더한다
- `schemas/`와 `models/`는 **둘 다 유지한다.** API 모양과 DB 모양은 다르다
- 🔒 **`Base`는 `database.py`에 하나뿐이다.** 조장이 W1 스켈레톤에서 만든다.
  `models/` 파일은 **`from app.database import Base`로 가져다 쓰고, 두 번째 `Base`를 선언하지 않는다.**
  각자 선언하면 메타데이터가 갈라져 한쪽 테이블이 생성되지 않는다 — 통합 날에야 드러난다
- `templates/`와 `fixtures/`는 **데이터**다. 코드를 넣지 않는다
- 화면 컴포넌트는 **자기 역할 폴더**에. 둘째 화면이 쓰기 시작할 때만 `common/`으로 옮긴다

## 5-3. 환경변수 🔒

`.env`는 커밋하지 않는다. `.env.example`만 커밋한다.

```
MYSQL_HOST=
MYSQL_PORT=3306
MYSQL_USER=
MYSQL_PASSWORD=
MYSQL_DATABASE=

ANTHROPIC_API_KEY=
STT_PROVIDER=              # W1 스파이크 후 확정
STT_API_KEY=
EMBEDDING_PROVIDER=
EMBEDDING_API_KEY=

TEMPLATE_DIR=backend/app/templates
FIXTURE_DIR=fixtures

CONFIDENCE_THRESHOLD=0.7   # 이 미만 발화는 상태를 바꾸지 않는다
RECURRENCE_COOLDOWN_SEC=30 # 마지막 상승 이후 이 시간 안의 재등장은 재발 아님
CARD_MAX_RANK=2

ROOM_CODE_TTL_SEC=3600
CORS_ORIGINS=
```

**`config.py`가 `pydantic-settings`로 읽는다.** 코드에 접속 문자열이나 키를 하드코딩하지 않는다.

`CONFIDENCE_THRESHOLD`와 `RECURRENCE_COOLDOWN_SEC`는 **튜닝 대상**이다. W3에 fixture로 확정한다.

## 5-4. 명령어

```bash
# 백엔드 — backend/ 에서. 포트 8000 고정
uvicorn main:app --reload

# 프론트 — frontend/ 에서
npm run dev

# 평가 러너
python -m app.eval.run --fixtures fixtures/
```

⚠️ 테스트·린트 설정은 아직 없다. `requirements.txt` / `package.json`이 생기면 그때 확인한다.

## 5-5. Git

**브랜치는 자기 영어 이름으로 하나씩** (수정, E-5).

```
main
 ├── feature/leejaehwan      역할 1
 ├── feature/parkjinwoong    역할 2
 ├── feature/ahnchiyoung     역할 3
 ├── feature/choiminwoo      역할 4
 └── feature/leejonghoon     역할 5 · 조장
```

철자는 본인이 쓰던 것을 쓴다 — **원칙은 "한 사람당 브랜치 하나"이지 철자가 아니다.**
한글 브랜치명은 Windows 콘솔과 GitHub URL에서 깨지므로 **영문으로만** 만든다.

- 🔒 **`main`에 직접 push하지 않는다.** PR을 올리고 **조장이 검토 후 머지한다**
- 자기 브랜치 안에서는 커밋을 자유롭게 한다. 검토는 PR 단위다
- **`schemas/` · `main.py` · `theme.css` 충돌은 조장이 해소한다**
- 자기 폴더 안의 충돌은 그 오너가 해소한다
- **금요일이 통합일이다.** merge하고 E2E를 한 번 돌린다. 금요일에 안 도는 것은 그 주에 없는 것으로 친다

## 5-6. 배포 (`#17`)

**담당: 역할 1** (신설, A-1). 스켈레톤 · 첫 배포 · 발표 전 안정화까지 소유한다.
배포의 실제 난제가 **WebSocket 장시간 연결**이라 역할 1의 세션·복구 문제와 같은 뿌리다.

| 계층 | 선택 | 비용 |
|---|---|---|
| 프론트 | **Cloudflare Pages** | 무료 |
| 백엔드 | **Railway Hobby** | $5/월 최소 사용료 |
| DB | **Railway 관리형 MySQL** | 위 사용량에 포함 |
| Durable Objects | **채택하지 않음** | — |

**무료 티어를 쓰지 않는 이유**는 발표 안정성이다.

```
발표 순서를 기다린다 → 20~30분 무요청 → 무료 호스팅 sleep
→ 데모 시작 버튼 → 재기동 대기 → 실시간 데모 지연
```

Render 무료는 15분 무요청 시 sleep하고 재기동에 약 1분이 걸린다.
**Railway에서도 Serverless 기능을 사용하지 않는 상시 실행 구성으로 운영한다.**
WebSocket이 장시간 연결을 유지하는 구조라 sleep이 치명적이다.

**연결은 W1에 한 번만 한다.** Cloudflare Pages와 Railway 둘 다 GitHub 연동 자동 배포다 —
`main`에 merge되면 자동으로 올라간다. 상시 노동이 아니라 초기 설정이다.

**Cloudflare Workers를 백엔드로 쓰지 않는 이유**: Python Workers가 FastAPI를 지원하지만
**직접 소켓 접근이 없어 SQLAlchemy가 MySQL에 붙지 못한다.** 데이터 계층을 통째로 바꿔야 하고,
6주 안에 감당할 비용이 아니다.
