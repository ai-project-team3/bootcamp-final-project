## 5-7. 브랜치

**역할 배정은 아직 확정하지 않았다.** 모듈 경계만 정해 두고(`4_모듈_브리프.md`) 누가 맡을지는 나중에 붙인다.

```
feature/<본인이름>          개인 작업
main                        통합. 직접 푸시하지 않는다
```

**`main`에 직접 푸시하지 않는다.** PR을 열고 조장이 병합한다.
**예외**: 레포 구조·guidelines처럼 **팀 전체의 바닥을 까는 작업**은 조장이 직접 병합한다. 그걸 PR로 막으면 본인이 본인을 승인하는 형식이 된다.

브랜치를 팔 때는 **`main`에서** 판다.

## 5-10. 문서는 어디에 두나 — 레포와 노션을 나눈다

**중복이 생기면 어느 쪽이 최신인지 아무도 모른다. 그래서 겹치지 않게 나눈다.**

| | 무엇 | 왜 |
|---|---|---|
| **레포 `guidelines/`** | **코드가 지켜야 하는 것** — 이름 · 구조 · 프롬프트 · 금칙어 | **코드와 같이 바뀌어야 한다.** PR에서 diff로 보이고, 노션이 없어도 읽힌다 |
| **노션** | 사람이 맞춰야 하는 것 — 기획 · 발표 · 조사 · 오늘 할 일 · 리포트 설계 | 댓글이 달리고, 팀 밖에 보여줄 수 있다 |

**금칙어가 레포에 있는 이유**: 실제 목록이 `backend/app/filters/words/*.txt`에 있다. **규칙과 데이터가 떨어지면 `block.txt`를 고치는 사람이 과차단 경고를 못 본다.**
**프롬프트가 레포에 있는 이유**: `backend/app/schemas/judge.py`의 16필드가 그 계약을 구현한 것이다. 스키마를 고치면서 프롬프트를 못 보면 어긋난다.

**옛 문서는 지웠다.** 주제 선정 전 조사 25개와 영업 어시스턴트 시절 문서는 **git 이력에 있다** — `git log --all --diff-filter=D --name-only`로 찾는다.

## 5-11. 하드웨어 — 확정 (2026-09-18)

**부트캠프 GPU = RTX 3060 12GB.** 조장 PC와 같은 사양이다. 세 문서에 "미정"으로 남아 있던 칸이 닫혔다.

**이 카드에 들어가는 "큰 모델"은 하나뿐이다.** 실사용 10.8~11.5GB인데 SDXL fp16 1024px가 혼자 8.5~10GB를 먹는다.

→ **그림을 자체 호스팅으로 세션 중에 돌리려면 이 카드에 다른 게 못 올라간다.** 결정된 사항은
아니고, **그림을 어떻게 만들지 정할 때 같이 봐야 하는 제약**이다. 외부 API를 쓰면 이 제약이
사라지는 대신 아이 이야기가 밖으로 나간다.

**같은 3060에서 돌린 공개 구현의 실측치** ([thecodacus/pithagoras](https://github.com/thecodacus/pithagoras))

| | |
|---|---|
| LLM 상주 | 6,378~7,333 MiB |
| TTS (PyTorch) | 7.8~8.0 GiB → **Q8 GGUF로 3.7~4.4 GiB** (절반) |
| **LLM + TTS 동시** | **11,365 MiB — 여유가 546 MB뿐이다** |
| **Whisper** | **CPU에서 돌린다** (`GGML_CUDA=OFF`) |
| 첫 오디오 | 약 0.94초 |
| **말 끝 → 첫 응답 오디오** | **2.98~4.10초** |

**교훈 셋**
1. **STT를 CPU로 내려야 한다.** LLM과 TTS를 같이 올리면 500MB밖에 안 남는다
2. **양자화로 VRAM이 절반**이 된다
3. **"실시간 음성"의 현실적 지연이 3~4초다.** 아이는 안 기다린다 → **채우는 말(filler)이 선택이 아니라 필수다**

→ **모델 개수가 아니라 덩치가 제약이다.**

⚠️ **그 레포는 라이선스가 없다(전권 유보).** 코드를 복사하면 안 되고, 읽고 직접 구현만 가능하다. **Breeze-TTS-2는 한국어를 지원하지 않고** 가중치가 연구/비상업 라이선스라 **처음부터 배제한다.**

## 5-12. 수익 모델 계산의 전제 (2026-09-18 멘토 지시)

> *"BM 계산은 하루에 한 개 만든다 가정하고 구독료로 뽑아먹을 걸 계산."*

**하루 1권 × 30일 = 월 30권**이 기준이다.

| 구성 | 권당 원가 | 월 30권 |
|---|---|---|
| 전량 사전 제작 그림 | 약 11원 | 약 330원 |
| 런타임 생성 3장 | 78~160원 | 2,340~4,800원 |

⚠️ **둘 중 어느 쪽으로 갈지 아직 안 정했다.** 위 숫자는 두 경우의 추정이지 확정 원가가 아니다.
**그림을 언제·무엇으로 만들지가 원가를 10배 이상 가른다** — 그래서 한 장 생성 시간을 재는 것이
구독료를 정하는 일과 같은 일이다.
