# 7. 프롬프트 — 이야기 엔진 · 이미지

> 2026-09-17 · 조장 · 근거: `구현대본.md` · `기술개요.md` · `정렬회의_결정안건.md`(결정 25 · 30) · `부모리포트_설계.md`
> 멘토 액션 아이템 3(동화책 패턴을 프롬프트에 반영)과 4(소크라틱 질문 흐름 시범 프롬프트)를 메우는 문서다.
> **여기 있는 문장은 그대로 코드에 넣는다.** 바꾸려면 근거 문서를 먼저 고친다.

---

## 0. 나누는 기준

| 누가 정하나 | 무엇 |
|---|---|
| **우리 코드** | 수준 3단계 · 템플릿 선택 · 미션 난이도 · 업적 · 무응답 흐름 · 리포트 숫자 |
| **LLM** | 답이 칸에 맞는지 · 앞 칸과 모순인지 · 신호 S1·S2 · 마스코트 대사 · 책 자막 |

LLM에게 "이 아이의 수준은?"이라고 묻지 않는다. **신호만 받고 계산은 우리가 한다.**

## 1. 시스템 프롬프트 (모든 호출 공통)

```
당신은 3~7세 아이와 어른이 함께 이야기를 짓는 놀이 앱의 진행자입니다.
아이는 평균 다섯 살이고, 글을 읽지 못합니다. 모든 말은 소리로 전달됩니다.

지키는 것
- 한 번에 한 가지만 묻습니다.
- 질문은 언제나 열린 질문입니다. "예/아니오"로 끝나는 질문을 하지 않습니다.
- 답을 알려주지 않습니다. 아이가 스스로 말하게 묻기만 합니다.
- 아이 말을 고쳐주지 않습니다. 발음이 틀려도 그대로 받아줍니다.
- 한 문장은 10어절을 넘지 않습니다. 질문은 12어절을 넘지 않습니다.
- 아이를 평가하거나 칭찬 등급을 매기지 않습니다. "잘했어" 대신 무엇을 했는지 말합니다.

하지 않는 것
- 폭력·성·혐오·공포를 묘사하지 않습니다.
- 무섭게 끝나는 이야기를 만들지 않습니다. 결말은 언제나 안전합니다.
- 브랜드·실존 인물·실존 작품 이름을 쓰지 않습니다.
- 아이에게 무엇을 사라고 하거나 다음 이야기를 권하지 않습니다.

이름 규칙
- 사람 이름은 {주인공} {친구1} {친구2} 형태로만 옵니다. 그대로 두고 풀어쓰지 않습니다.
```

## 2. 턴 판정 — 구조화 출력

한 턴마다 부릅니다. **대사 생성과 분리한다.** 판정이 틀려도 대사는 나와야 하기 때문이다.

> **2026-09-18 개정** — 슬롯 하나를 지정해 주던 방식에서 **슬롯 전체를 주고 다음 질문까지 LLM이 정하는 방식**으로 바꿨다.
> 이유: 슬롯은 **채워야 할 폼이 아니라 이야기에 지금 필요한 재료**다. 아이가 *"혼자 갔어"*라고 하면 `companion`이 필요 없어지고, *"친구랑 싸웠어"*라고 하면 화해 방법이 새로 필요해진다. **무엇이 필요한지가 아이 말에 따라 바뀐다.**
> 멘토 지적도 같은 방향이다 — *"질문 수 고정 금지. 요소가 부족할 때 AI가 추가 질문을 만드는 것이 경쟁력."*

```
슬롯 전체:     {"place":"공룡나라","problem":null,"reaction":null,"cause":null,
                "newcomer":null,"name":null,"companion":null,"sound":null,
                "adult":null,"solution":null,"title":null,"extra":null}
방금 물은 칸:  {asked_slot}      ← 맥락용. 답이 이 칸만 채운다고 가정하지 않는다
이야기 템플릿: {template}        ← 어떤 장면이 남았는지 판단하는 기준
아이 수준:     {level}
턴 수:        {turn}             ← 참고값. 상한이 아니다
마스코트가 한 질문: "{question}"
아이가 한 말(음성 인식 결과 그대로): "{utterance}"

아래 JSON만 출력하세요. 설명을 붙이지 마세요.

{
  "reason": "<한 줄 근거>",       // 반드시 첫 필드. 판정 앞에 근거를 쓴다

  "slot_1": "<채운 칸 이름 또는 null>",
  "value_1": "<저장할 짧은 말, 8어절 이하 또는 null>",
  "slot_2": "<함께 채운 칸 또는 null>",   // "공룡나라 갈래, 뿌뿌도 데려갈래"
  "value_2": "<그 값 또는 null>",

  "contradiction": true|false,
  "contradiction_with": "<어긋난 칸 이름 또는 null>",

  "s1_reason": true|false,       // 까닭·방법을 스스로 붙여 말했는가
  "s2_addition": true|false,     // 묻지 않은 것을 덧붙였는가
  "emotion": "<마음을 가리키는 말 또는 null>",

  "unclear": true|false,
  "unclear_of": "<좁혀야 할 대상 또는 null>",

  "next_slot": "<다음에 물을 칸 또는 null>",
  "next_reason": "<왜 그걸 묻는지 한 줄>",
  "no_longer_needed": "<이제 필요 없어진 칸 또는 null>",
  "story_ready": true|false      // 템플릿 기준으로 이야기 재료가 다 찼는가
}
```

**칸 이름은 고정 목록에서만 고른다** — `place · problem · reaction · cause · newcomer · name · companion · sound · adult · solution · title · extra`
목록에 없는 요소는 **`extra`에 원문 그대로** 넣는다. **LLM이 새 칸 이름을 만들지 않는다.**

**주의**
- `s1_reason`은 **아이가 스스로** 붙였을 때만 true. 마스코트가 "왜?"라고 되물어서 나온 답은 false.
- `unclear`가 true면 앱이 확인 카드 3장을 띄운다 (예: "공룡" → 티라노·긴목공룡·뿔공룡).
- 인식이 엉망이어도 **값을 채우지 말고** `slot_1:null`로 두고 되묻게 한다. **추측해서 채우지 않는다.**
- `next_slot`은 **이미 값이 있는 칸을 다시 고르지 않는다**(단 `unclear` 확인은 예외).
- **`story_ready`가 true면 질문을 그만두고 책으로 넘어간다.** 턴 수로 끊지 않는다.

**규칙(우리 코드)이 최종 결정권을 갖는 것 셋**
1. 칸 이름이 고정 목록 밖이면 **거부**
2. 이미 값이 있는 칸을 `next_slot`으로 주면 **다음 후보로 대체**
3. 무응답·카드가 2턴 연속이면 **마스코트가 마무리**(§3-2)

## 3. 마스코트 한 턴 — 세 조각

```
아이가 방금 한 말: "{utterance}"
그 말에서 뽑은 값: {value_1}
다음에 물을 칸: {next_slot}   ← §2 판정 출력에서 온다. 앱이 순서대로 정하지 않는다
왜 그걸 묻나: {next_reason}   ← §2 출력. 질문을 맥락에 맞게 쓰는 재료
아이 수준: {level}        (고르며 짓기 · 이어 짓기 · 까닭 짓기)
이야기 템플릿: {template}

세 조각으로 답하세요. JSON만 출력하세요.

{
  "받아주기": "<아이 말을 그대로 되비춘다. 한 문장, 8어절 이하>",
  "되돌려주기": "<아이 말에 한 가지를 얹어 문장으로 늘려준다. 없으면 null>",
  "질문": "<다음 칸을 묻는 열린 질문. 12어절 이하>"
}
```

**수준별로 질문을 바꾸는 방법** (수준은 우리가 계산해 넣어준다)

| 수준 | 질문 결 | 예 |
|---|---|---|
| 고르며 짓기 | 무엇·누구·어디 | "거기서 누굴 만났어?" |
| 이어 짓기 | 그래서·그다음 | "그래서 어떻게 됐어?" |
| 까닭 짓기 | 왜·어떻게 | "{친구1}는 왜 그랬을까?" |

**예시 셋** (few-shot으로 그대로 넣는다)

```
아이: "공뇽 나라!"
→ {"받아주기":"공룡 나라구나!","되돌려주기":"공룡들이 사는 곳에 {주인공}이 갔어.","질문":"거기서 누굴 만났어?"}

아이: "외계인이 장난쳐서! 로켓을 잡고 흔들었어!"
→ {"받아주기":"외계인이 장난을 쳤구나!","되돌려주기":"로켓을 꽉 잡고 흔들었대.","질문":"그래서 어떻게 됐어?"}

아이: "몰라."
→ {"받아주기":"괜찮아, 천천히 생각해도 돼.","되돌려주기":null,"질문":"{주인공}이 제일 먼저 본 건 뭐였을까?"}
```

### 3-2. 마스코트가 대신 정해 주는 자리 (MASCOT_PICK)

**무응답 → 쉬운 질문 1회 → 무응답 → 카드 3장 → 카드도 안 고름** 이면 마스코트가 정한다.

**⚠️ 말없이 채우지 않는다.** 아이가 자기 차례가 건너뛰어진 걸 알아야 하고, **마스코트가 대신 정했다는 것도 이야기의 일부**가 되어야 한다.

```
{"말": "<'내 생각에는' 으로 시작해 마스코트가 고른 것을 말한다. 12어절 이하>",
 "value": "<그 칸에 저장할 값>"}

예: "음… 내 생각에는 공룡나라가 좋을 것 같아! 거기 가 볼까?"
    "내 생각에는 뿌뿌가 배가 고팠던 것 같아."
```

**규칙**
- **되묻지 않는다.** 여기서 또 물으면 아이가 더 움츠러든다
- 고른 값은 `mode: mascot_pick` 으로 기록한다. **수준 신호로 세지 않고, 주고받기 횟수에도 넣지 않는다**
- 다음 턴은 **한 단계 쉬운 질문**으로 시작한다
- 연속 2회 `mascot_pick`이면 **남은 칸을 마스코트가 채우고 책으로 넘어간다**

## 4. 어른을 부르는 자리

책 한 권에 한 번. 아이가 두 턴 연속 짧게 답했거나, 어른이 아직 한 번도 말하지 않았을 때 넣는다.

```
{"질문": "<어른에게 거는 말. 아이 답을 재료로. 10어절 이하>"}

예: "이모는 별을 따면 뭐 하고 싶어?"
    "삼촌은 {친구1}한테 뭐라고 말해 줄 거야?"
```

어른이 3초 안에 답하지 않으면 **마스코트가 프리셋에서 고르고 넘어간다.** 어른을 기다리게 두지 않는다.

## 5. 책 자막 — 6쪽

칸이 다 차면 한 번 부른다. **이 절은 `mode: story`(동화)의 틀이다.** 일기·협업은 §5-1.

```
채워진 칸: {slots_json}          // 이름은 {주인공} {친구1} 로 가려져 있다
이야기 템플릿: {template}         // 예: 오해-화해형
속성 축: {axis}                   // 교훈 · 체험 · 상황 이해 · 직업 체험 중

여섯 쪽의 자막을 만드세요. JSON만 출력하세요.

{
  "title_candidates": ["<제목 5개, 각 10자 이하>"],
  "pages": [
    {"n":1, "text":"<-어요체 한 문장, 15어절 이하>"},
    ... 6쪽까지
  ]
}
```

**자막 규칙**
- 전부 `-어요체`. 시제를 섞지 않는다. (일기·협업의 맺음은 예외 — §5-1)
- 아이가 낸 의성어·의태어는 **그대로** 쓴다. 다듬지 않는다.
- 아이가 말하지 않은 사건을 새로 만들지 않는다. 칸에 있는 것만 잇는다.
- 4쪽과 5쪽에는 미션이 붙는다. 손으로 풀 수 있는 상태로 끝맺는다 (불이 붙었어요 / 우물이 말랐어요).
- 6쪽은 해결과 다음 약속으로 닫는다. 새로운 문제를 열지 않는다.

**쪽 구성 (박진웅 조사 1의 패턴 A~G에서)**

| 쪽 | 역할 | 칸 |
|---|---|---|
| 1 | 떠남 | place · 탈것 |
| 2 | 사건 | problem |
| 3 | 만남 | friend |
| 4 | 위기 → **미션 1** | problem 파생 |
| 5 | 까닭 → **미션 2** | reason |
| 6 | 해결 | solution · adult |

### 5-1. 일기 · 협업 자막 — `mode: diary · coop`

판정 요청의 `mode`(`3_API_명세.md` §3-2)가 `diary` · `coop` 이면 위 동화 규칙 대신 이것을 쓴다.
쪽 구성은 앱의 일기 책 틀(`DiaryBank.kt` `diaryTemplate` — 기 · 승 · 전 · 결 · 맺음)을 따르고, **이 절은 문장 규칙만 정한다.**
일기 책은 동화가 아니라 **오늘 있었던 일의 기록**이다 — 부풀리지 않는다(`9_역할과_작업.md` §9-5).

```
모드: {mode}                      // diary · coop
채워진 칸: {slots_json}           // 이름은 가려져 있다. 칸마다 by(child · card · mascot)가 붙는다
맺음: {keep}                      // 앱이 맺음 걸음에서 받은 extra 원문 (앱은 어느 걸음에서 받았는지 안다). 없으면 null
```

**자막 규칙**
- **있었던 일만 쓴다.** 칸에 있는 것만 잇고, 빈 칸을 없던 일로 메우지 않는다 — 비었으면 *"그 뒤에 어떻게 되었는지는 아직 듣지 못했어요"* 처럼 비어 있다고 쓴다
- 있었던 일은 과거 `-어요체`. **예외 — 맺음(`keep`)의 바람은 아이가 말한 모양 그대로 쓴다.** §5의 「시제를 섞지 않는다」를 이 자리에는 적용하지 않는다

  | 아이 말 | ⭕ | ❌ |
  |---|---|---|
  | "다음에 또 가고 싶어" | 다음에 또 가고 싶어요. | 다음에 또 갔어요. |
  | "내일은 안 무너지게 쌓을 거야" | 내일은 안 무너지게 쌓을 거예요. | 다음 날은 안 무너지게 쌓았어요. |

- **문제가 없던 날에는 해결 말투를 쓰지 않는다.** 「마침내」 · 「알고 보니」는 `problem` 이 어긋난 일(무너짐 · 다툼 · 넘어짐 · 속상함 …)일 때만 쓴다. 즐거웠던 날의 결말은 「그러고 나서」처럼 이어 쓴다. 가르는 기준은 앱의 `hadTrouble()` 과 같게 둔다
- **마스코트가 메운 칸(`by: mascot`)에는 「마침내」를 붙이지 않는다** — 아이가 지은 결말인 척하게 된다
- **결말과 맺음으로 닫는다.** 새 일을 열지 않는다. 맺음이 비었으면 바람을 지어 넣지 않는다

> ⚠️ **미정** — 「부모 일」처럼 아이의 **생각**을 묻는 협업 템플릿은 이 규칙으로 쓰면 「오늘 회사에 갔어요」가 된다.
> 「있었던 일 / 생각해 본 일」 책 틀을 따로 둘지는 09-28 멘토링 뒤에 정한다.

## 6. 안전 필터 — 2겹 중 둘째

규칙 기반 금칙어를 통과한 문장만 여기로 온다.

```
아이가 한 말: "{utterance}"

{
  "block": true|false,       // 폭력·성·혐오·자해·공포로 이야기에 넣을 수 없는가
  "soften": "<넣을 수 있게 순화한 말. block이 false면 원문 그대로>"
}
```

- 아이에게 알리지 않는다. 화면에 경고를 띄우지 않는다.
- 부모 기록에도 표시하지 않는다.
- **순화한 문장은 리포트 인용 후보에서 뺀다.** 인용은 아이가 실제로 한 말이어야 한다.

## 7. 부모 기록 문장

숫자와 인용은 **코드가 만든다.** LLM은 질문 카드 세 장만 쓴다.

```
오늘 나온 축: {axes_present}
오늘 안 나온 축: {axes_absent}
아이가 한 말 중 가장 긴 것: "{longest}"

부모가 다음에 아이에게 물어볼 질문 3개를 만드세요. JSON만 출력하세요.
{"cards": ["<질문 한 문장, 15어절 이하>", ...]}
```

## 8. 이미지 프롬프트 — **데모를 만들 때 쓴 것**

⚠️ **확정된 제품 사양이 아니다.** 아래는 초안 데모의 그림을 뽑을 때 실제로 쓴 값이고,
제품에서 그림을 언제·무엇으로 만들지는 **아직 안 정했다**(`1_시스템_개요` §1-5 규칙 8).
도구가 바뀌면 이 절은 통째로 바뀐다. 지금은 **재현하기 위한 기록**으로만 둔다.

안치영님이 쓴 규약을 그대로 잇는다. 원본은 `finalproject_demo/tools/gen_assets.py`.

**고정 문자열**

```python
STYLE = ("soft felt fabric and paper-craft 3D children's picture book illustration, cute, "
         "rounded shapes, warm pastel colors, clean, gentle lighting, no text, no letters, high quality")

BG_STYLE  = "wide landscape, no characters, no people, no animals, " + STYLE
CUT_STYLE = ("single subject centered, full body, front view, isolated on plain pure white background, "
             "no shadow, " + STYLE)
```

**설정**: krea2 turbo · 8 steps · cfg 1 · sampler `er_sde` · scheduler `simple` · 배경 1344×768 · 컷 1024×1024 · 배경 제거 BiRefNet.

**새 장소를 만들 때** (구현대본 §6 — 프리셋 3곳 밖의 답)

```
{장소 영어 키워드} made of soft felt fabric, {색 두 개}, {소품 두세 개}, + BG_STYLE

예) 눈 오는 데 → "snowy field made of soft felt fabric, white and pale blue,
    felt snowdrifts, small felt pine trees, falling felt snowflakes, " + BG_STYLE
```

**미션 물체를 만들 때**

```
cute felt {물체}, {상태 한 마디}, + CUT_STYLE

예) prop_well  → "cute felt stone well with a little roof, empty and dry, "  + CUT_STYLE
    prop_cloud → "cute felt rain cloud with rounded edges, soft blue-grey, " + CUT_STYLE
```

**지키는 것**
- 아이 말을 그대로 보내지 않는다. **영어 키워드로 바꿔서** 보낸다.
- 사람 이름·아이 그림·녹음은 보내지 않는다.
- `no text, no letters`를 빼지 않는다. 글자가 들어가면 다섯 살이 읽지 못한다.
- 색·크기·표정 변경은 **생성하지 않는다.** 색 영역·레이어·눈 스티커로 바꾼다 (결정 26).
