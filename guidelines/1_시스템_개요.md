# 1. 시스템 개요

## 1-1. 한 문장

**영업 미팅 중 상대가 걸려 있는 것(반대사유)을 항목별 상태로 추적하고, 그 상태를 차수를 넘어 이어 붙이는 도구.**

두 가지가 차별점입니다.

1. **재발 탐지** — 풀렸다가 다시 막히는 순간을 잡는다 (미팅 내)
2. **차수별 누적** — 미팅을 낱개 문서가 아니라 이어 붙인다

## 1-2. 사용자는 한 명이다

**영업사원 본인**이 씁니다. 동석자는 백채널로 신호만 보냅니다.

| 사용자 | 무엇을 하나 | 무엇을 보나 |
|---|---|---|
| **영업사원** | 미팅을 시작하고 진행한다 | 화면 ① ② ③ 전부 |
| **동석자** | 항목을 탭해 신호를 보낸다 | 신호등 상태 (읽기 전용) |

⚠️ **매니저 → 담당자 관리 도구가 되지 않게 한다.** 그러면 회사가 사는 제품이 되고,
기획안 §8-4가 경계한 방향으로 끌려갑니다. 동석자는 **대등한 2인** 또는 **내 두 기기**입니다.

## 1-3. 화면 세 장

### 화면 ① — 미팅 전

딜을 고르고 지난 차수 상태를 확인한다. 30초.

```
🔍 회사 · 담당자 · 건명으로 찾기            ＋ 새로 만들기
─────────────────────────────────────────────────────
    건명              차수 ⇅  상대    미해결 ⇅  최근 ▼
🔴  A사 신규 도입      2차    박부장    2건     6일 전
🟡  김OO님 종신보험    1차    김영희    1건     3일 전
─────────────────────────────────────────────────────
지난번에 못 끝낸 것
  🔴 예산 승인    31:20에 재발
  🔴 계약 기간    아예 언급 안 됨
                                    [ 이 상태로 시작하기 ]
```

**1차 미팅에는 "지난번 미해결"이 없다.** 대신 **"이번 미팅 기본 체크" 5개**를
같은 항목 풀에서 골라 보여준다 (#10). 가상의 과거 이력을 만들지 않는다.

### 화면 ② — 미팅 중 (본체)

```
┌──────────────────────────────────────────────────────────────────────────┐
│  A사 2차 미팅 · 31:20                         ● 듣는 중 · 👤 2명          │
├───────────────────────┬────────────────────────┬─────────────────────────┤
│  반대사유      해결 2/5│ 필수 항목 · 언급 5/7 ▾ │  지금 다룰 것           │
├───────────────────────┼────────────────────────┼─────────────────────────┤
│  예산 승인   🔴 (이월) │  ☑  보험료             │  1순위   결정권자       │
│   31:20 "위에 좀…"    │  ☑  보장 범위          │   "위에 한 번 물어봐야" │
│                       │  ☐  계약 기간          │   31:20                 │
│  결정권자    🔴        │  ☑  해지환급률         │                         │
│   31:20 새로 나옴      │  ☑  면책 기간          │  💬 "결정 과정에 함께   │
│                       │  ☐  부담보 사항        │      하실 분이          │
│  기존 계약   🟡        │  ☑  청약철회권         │      계실까요?"         │
│                       │                        │  ─────────────────      │
│                       │                        │  2순위 · 계약 기간      │
├───────────────────────┴────────────────────────┴─────────────────────────┤
│  👤 동석자 · "예산 먼저"                                          (6초)   │
└──────────────────────────────────────────────────────────────────────────┘
```

🔒 **요소는 넷뿐이다** — 헤더 / 반대사유 / 필수 항목 / 카드.
미팅 중 곁눈질로 읽어야 하므로 **더 늘리지 않는다.** 백채널은 6초 배너라 요소가 아니다.

**3열인 이유**는 세로로 쌓으면 카드가 화면 밖으로 밀리기 때문이다. 그리고 각 열이 다른 질문에
답한다 — 좌: 상대가 뭘 걸고 있나 → 중: 내가 뭘 안 했나 → 우: 지금 뭘 해야 하나.

**좁은 화면**은 세로 스택이 아니라 **탭**으로 접는다 (`[반대사유 3] [필수 4] [카드]`).
세로로 흘리면 스크롤이 생겨 곁눈질이 불가능해진다. 기본 탭은 `카드`.

### 화면 ③ — 미팅 후

```
A사 2차 미팅 · 47분 · 결과: 미결 · 3차 예정

━━ 끝내 못 끝낸 것 ━━━━━━━━━━━━━━━━━━━
  예산 승인    1차 🔴  2차 🔴        ← 2회 연속
  계약 기간    1차 —   2차 🔴

━━ 언급 확인 ━━━━━━━━━━━━━━━━━━━━━━
  언급된 것으로 표시된 항목 7개
  실제로 설명하셨는지 확인해 주세요.   [모두 확인] [수정]

━━ 팀원 신호 ━━━━━━━━━━━━━━━━━━━━━━
  신호 3건 / 반영 2건
```

**차수에 따라 성격이 달라진다** — 1차 발견 / 2차 변화 / 3차+ 패턴.

## 1-4. 모듈과 오너

| 역할 | 소유 | 트랙 | 지표 |
|---|---|---|---|
| **1** 음성·실시간 | 오디오 캡처 · STT · 화자 분리 · WebSocket · 세션/방 · 백채널 전송 | A | WER · p95 지연 · 드롭률 |
| **2** 항목 매칭 | 표현사전 + 임베딩 하이브리드 · 기타 처리 · 임계값 | A | 매칭 F1 · 기타 오분류율 |
| **3** 상태 추적 | 상태 전이 · 재발 판정 · 공통 평가 러너 | A | 상태 정확도 · **재발 재현율** |
| **4** 생성 | 카드 후보 규칙 + LLM 문장 · 차수별 리포트 | B | 카드 채택률 · 근거 인용률 |
| **5** 템플릿·누적 | 항목풀 저작 · 이월/프리로드 규칙 · 딜 연결 | B | 이월 정확도 · 템플릿 커버리지 |

**각자 백엔드와 자기 화면을 함께 소유한다.** "프론트 담당"이라는 자리는 두지 않는다.
공통 셸(디자인 토큰 · WebSocket 클라이언트 · 레이아웃)만 역할 1이 소유한다.

**트랙 A(실시간)와 트랙 B(누적)의 접점은 미팅 종료 스냅샷 하나뿐이다.** 사실상 병렬로 간다.

## 1-5. 🔒 교차 규칙 — 모듈 경계를 넘지 않는다

이 절이 이 문서 묶음에서 가장 중요합니다. 위반하면 다른 사람이 깨집니다.

**① 항목은 만들지 않고 고른다**
LLM이 항목을 생성하지 않는다. 템플릿 항목 풀에서 꺼내 켤 뿐이다.
목록에 없는 발화는 `_other` 한 칸에 **원문 그대로** 담고 분류하지 않는다. (기획안 §2-1 · §5-2)

**② 카드 ≠ 항목**
카드는 매 턴 새로 만들고 버린다. **후보는 신호등 상태에서 규칙으로 뽑고, LLM은 마지막에 문장 한 줄만 쓴다.**
카드가 항목을 만들지 않는다. (기획안 §2-3)

**③ 필수 항목은 "완료"가 아니라 "언급"이다**
자동 체크는 하되 라벨은 `언급`이다. `완료`라고 표시하면 오탐이 사용자를 안심시켜
법정 의무 미이행을 만든다. 최종 확인은 **미팅 종료 화면**에서 사람이 한다. (기획안 §5-1 · `#3`)

**④ 재발은 자동 확정한다**
③과 방향이 반대다. 재발 오탐은 *"이미 푼 걸 다시 보세요"* 라 위험을 만들지 않는다.
탭으로 되돌릴 수 있고 그 복귀가 로그로 남는다. (`#3`)

**⑤ 신호등 순서는 미팅 중에 바뀌지 않는다**
프리로드가 시작 시 순서를 정하고, 색·스티커·근거 줄만 갱신된다.
우선순위는 카드가 담당한다. (`#3`)

**⑥ `confidence` 미달 발화는 상태를 바꾸지 않는다**
화자가 `unknown`이거나 임계값 미만이면 전이를 일으키지 않는다. (`#1` · `#3`)

**⑦ 백채널에 원본 음성을 보내지 않는다** 🔍
대법원 2023. 2. 29. 2023도8603이 '청취'를 **대화 도중 실시간으로 듣는 행위**로 확정했다.
동석자에게는 **분석 결과·상태·지원 정보만** 공유한다. 기획안 §2-4의 백채널은 원래 음성이
필요 없으므로 이 제약이 기능을 깎지 않는다. (`#13` · `#14`)

**⑧ 딜을 자동으로 잇지 않는다**
이름·회사명 자동 매칭을 쓰지 않는다. 잘못 이으면 **다른 고객의 미해결 항목이 화면에 뜬다.**
사용자가 고르고, `unlink`로 되돌린다. (`#4`)

**⑨ 프리로드는 이전 차수 색을 그대로 가져온다**
2차 시작 시 신호등은 1차 최종 색이다. ⚪로 리셋하지 않는다 —
그 항목은 안 나온 게 아니라 **막힌 채**다. 이월은 `trigger="carryover"` 변화로 기록하고
지표에서 제외한다. (`#3`)

## 1-6. 저장 구조

| 무엇 | 어디 | 왜 |
|---|---|---|
| 딜 · 미팅 · 상태변화 · 항목 상태 | **MySQL** | 관계형. 차수 간 조회 |
| 템플릿 · 항목 카탈로그 | **YAML 파일** (레포) | 조장이 손으로 쓰고 PR로 리뷰 |
| 수집된 실제 발화 | **JSONL** (레포) | 라벨링 결과가 표현 사전을 보강 |
| 실시간 세션 상태 | **서버 메모리 + MySQL 스냅샷** | 상태 변화마다 즉시 저장 (`#12`) |
| 오디오 원본 | **저장하지 않는다** (MVP) | 개인정보 최소 수집 |

## 1-8. 데모 모드

발표는 **전사 fixture 재생**이 기본 경로다. 라이브 마이크는 보조. (`#16`)

- fixture와 라이브는 **같은 `Utterance` 구조**로 파이프라인에 들어간다
- 재생은 `setInterval` 호출 횟수가 아니라 **timestamp와 경과 시간 비교**로 위치를 계산한다
  🔍 PoC에서 탭이 백그라운드가 되면 스로틀되어 9초에 8발화만 진행된 사례 확인
- 발표 10분 안에 **재발이 최소 1회** 나오도록 구성하고, 핵심 이벤트를 **2~4분 구간**에 배치한다
