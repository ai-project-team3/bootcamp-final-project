# 4. 역할별 요구사항 브리프

각 절은 그 역할 담당자가 **그대로 복사해 작업 지시로 쓸 수 있게** 썼습니다.
자기 절은 담당자가 고칠 수 있습니다. 다른 절은 건드리지 않습니다.

공통 전제 — `1_시스템_개요` §1-5 교차 규칙 아홉 개는 **모든 역할이 지킵니다.**

---

## 4-1. 역할 1 — 음성 · 실시간

**소유**: 오디오 캡처 · STT · 화자 분리 · WebSocket 서버 · 세션/방 · 백채널 전송
**화면**: 미팅 중 상단(전사 상태 · 접속자) · 공통 셸(디자인 토큰 · WS 클라이언트 · 레이아웃)
**지표**: 한국어 WER · `utterance_end → state_rendered` p95 · 세션 드롭률

### 만드는 것

`SpeakerSource` 인터페이스 뒤에 입력 구현체를 둔다. **MVP는 `DualChannelSource` 하나만.**

```python
class SpeakerSource(Protocol):
    async def stream(self) -> AsyncIterator[Utterance]: ...
```

| 구현체 | 언제 | `confidence` |
|---|---|---|
| `DualChannelSource` | **MVP** — 화상 · 노트북 통화 | 항상 `1.0` |
| `FixtureSource` | 데모 · 평가 | 라벨 값 |
| `EnrolledVoiceSource` | **W4 조건부** — 대면 · 스피커폰 | 임베딩 유사도 |

**2채널 물리 분리**: `getUserMedia`(내 마이크) + `getDisplayMedia({audio:true})`(탭 오디오).
미팅은 **브라우저로 참여**하는 것을 전제로 고정한다 — 네이티브 앱 + 시스템 오디오는
macOS에서 가상 오디오 장치가 필요해 MVP에서 제외.

### W1에 반드시 확인할 것

🔴 **탭 오디오에 내 목소리가 섞여 들어오는가.** Zoom 에코 캔슬 설정에 따라 달라질 수 있고,
여기서 새면 2채널 분리의 전제가 무너진다. **첫날에 확인한다.**

### 지연 예산 (`#9`)

여섯 지점에 타임스탬프를 남긴다 — `utterance_end` `stt_final` `match_done`
`state_updated` `state_rendered` `card_rendered`.

W1의 목표는 3초/5초 달성이 아니라 **어느 단계에서 시간이 소비되는지 보이는 상태**를 만드는 것.

### 세션 복구 (`#12`)

- 서버가 authoritative source
- **상태 변화가 발생할 때마다 즉시 스냅샷** (주기 저장 아님)
- 같은 `session_id`로 재접속하면 최신 스냅샷 전체를 보낸다
- 화면에 `연결 끊김 → 재연결 중 → 복구 완료`를 표시한다
- 끊긴 동안의 오디오 복원은 MVP 범위 밖

### 백채널 (`#14`)

6자리 방 코드 → `joinToken`(짧은 수명) → 접속. 미팅 종료와 동시에 폐기.
🔒 **원본 음성을 보내지 않는다.** 상태와 신호만.

### 하지 않는 것

- 항목 매칭 (역할 2)
- 상태 판정 (역할 3)
- 대면 오디오 (W4 게이트 통과 후)

## 4-2. 역할 2 — 항목 매칭

**소유**: 표현사전 lexical + 임베딩 하이브리드 · `_other` 처리 · 임계값 튜닝
**화면**: 매칭 검수·라벨링 화면 — **전원의 라벨링 부역이 이 도구 위에서 돈다**
**지표**: 매칭 F1 · `_other` 오분류율

### 만드는 것

```
발화 → [ 정규화 → lexical(aliases + keywords) → 임베딩 유사도 → 임계값 ] → item_id | "_other"
```

**인덱스는 두 소스를 합친다.**

| 소스 | 무엇 | 규모 |
|---|---|---|
| `Item.aliases` | 조장이 손으로 쓴 씨앗 | 항목당 5개 |
| `harvested/{item_id}.jsonl` | fixture 라벨링에서 나온 **실제 발화** | 라벨링할수록 증가 |

**`aliases`는 씨앗이고 `harvested`는 자란 것이다.** 라벨링 결과를 자동 적재해
표현 사전이 작업량에 비례해 두꺼워지게 한다.

**`blockers` 매칭도 역할 2의 인덱스에 들어간다.** 판정(재발인가)은 역할 3이 하고,
"이 발화가 저 blocker 예문과 닮았나"만 답한다.

### 규칙

🔒 **항목을 만들지 않는다.** 카탈로그에서 고를 뿐이다.
🔒 **임계값 미만은 `_other`로 보낸다.** 억지로 가까운 항목에 붙이지 않는다.
🔒 `_other`는 **원문 그대로** 담고 분류하지 않는다.

### 하지 않는 것

- 슬롯 충족 판정 (역할 3)
- 항목 풀 작성 (역할 5 / 조장)

## 4-3. 역할 3 — 상태 추적 ★

**소유**: 상태 전이 · 재발 판정 · **공통 평가 러너**
**화면**: 신호등 패널(좌) · 필수 항목 패널(중) · 타임라인
**지표**: 상태 정확도 · **미팅 내 재발 재현율** ← 프로젝트의 유일한 기술 차별점

### 만드는 것

`2_공통_데이터_모델` §2-3의 전이표를 그대로 구현한다.

```python
def apply(changes: list[StateChange], u: Utterance, item: Item) -> StateChange | None:
    """상태 변화가 있으면 새 StateChange를 반환. 없으면 None."""
```

**현재 상태를 따로 들고 다니지 않는다.** 변화 리스트에서 파생한다.

### 재발 판정

```
RANK[to_st] < RANK[from_st]  →  재발
```

취소 트리거는 **`Slot.blockers` 임베딩 매칭**이다. `blockers`가 없는 항목(상위 12개 외)은
**재등장 휴리스틱**으로 폴백한다 — 🟢/🟡인 항목에 고객 발화가 다시 매칭되면 후보로 본다.

**30초 규칙**: 마지막 상승 이후 30초 안의 재등장은 재발로 보지 않는다.
⚠️ 30초는 초기값. **W3에 fixture로 확정한다.**

**자동 확정한다.** 탭으로 되돌릴 수 있고(`trigger="manual"`) 그 복귀가 로그로 남는다.
W4에 오탐률이 높으면 확인 방식으로 전환한다.

### 필수 항목 (2층)

별도 모델이다. 상태 2개, 단조 증가, 재발 없음.

- **언급이 감지되면 자동 체크.** 대기 상태 없음
- 🔒 라벨은 `언급`이다. `완료`가 아니다
- 체크 후에도 **자리를 지키고 흐려진다.** 사라지지 않는다
- 전부 완료되면 **열 전체가 한 줄로 접힌다**
- 최종 확인은 미팅 종료 화면에서 사람이 한다

### 표시

| 채널 | 뜻 |
|---|---|
| 색 | 현재 상태 (이월 포함) |
| 스티커 `(이월)` `(연속 N회)` | 이전 차수에서 넘어왔는가 |
| 근거 발화 줄의 유무 | **이번 미팅에서 다뤘는가** |

🔒 **순서는 미팅 중에 바뀌지 않는다.** 프리로드가 정하고 색만 갱신된다.
🔒 **1층은 🔴🟡만 노출**하고 상한은 6줄. ⚪·🟢은 카운터로만.

### 임베딩 모델 선정 — 역할 2와 공동 (신설, C-1)

`6-8` #2의 임베딩 모델 확정은 **혼자 못 한다.** 후보를 비교하려면 재는 도구가 먼저 있어야 하고,
그게 평가 러너다. **역할 2가 후보 모델을 돌리고, 역할 3이 비교와 임계값 곡선을 소유한다.**

| | 역할 2 | 역할 3 |
|---|---|---|
| 후보 모델 실행 · 임베딩 추출 | ✅ | |
| **F1 측정 · 모델 간 비교표** | | ✅ |
| **임계값 곡선 (precision–recall)** | | ✅ |
| 최종 선정 | **공동 결정** | **공동 결정** |

> 매칭 F1은 아래 평가 러너의 지표 첫 줄이다. **역할 2의 성능을 재는 도구가 역할 3의 것이다.**

### 공통 평가 러너

**역할 3이 만들고 전원이 쓴다.** W1 작업이다.

```
fixture 읽기 → 각 역할의 함수 호출 → 지표 표 출력
```

| 지표 | 단위 |
|---|---|
| 매칭 F1 | 발화 |
| 상태 정확도 | 항목 × 시점 |
| **재발 재현율·정확도** | **사건** |
| 필수 항목 감지 정확도 | 항목 |

`trigger`가 `carryover`·`manual`인 변화는 **전부 제외한다.**

## 4-4. 역할 4 — 생성

**소유**: 카드 후보 규칙 + LLM 문장 · 차수별 리포트 분기
**화면**: 카드 패널(우) · 리포트 화면
**지표**: 카드 채택률 · 리포트 근거 인용률(할루시네이션 0)

### 카드

```
신호등 상태  →  [ 규칙으로 후보 뽑기 → 순위 매기기 ]  →  LLM이 문장 한 줄
                 ↑ 여기까지 코드                          ↑ 여기만 모델
```

🔒 **LLM이 후보를 만들지 않는다.** 무엇을 다룰지는 상태가 정한다.
🔒 **매 턴 새로 만들고 버린다.**
🔒 **2순위까지만.** 1순위는 항목+근거+문장, 2순위는 항목명 한 줄.

### 리포트

차수에 따라 성격이 달라진다.

| 차수 | `kind` | 핵심 문장 |
|---|---|---|
| 1차 | `discovery` | "이번에 이런 것들이 나왔습니다" |
| 2차 | `change` | "1차 대비 무엇이 풀렸고 무엇이 그대로인지" |
| 3차+ | `pattern` | "이 고객은 계속 여기서 막힙니다" |

**모든 서술에 근거 발화를 붙인다.** 근거 없는 문장을 쓰지 않는다 —
리포트 근거 인용률이 역할 4의 지표다.

### 콜드 스타트 (`#10`)

1차 미팅에는 이월이 없다. **"이번 미팅 기본 체크" 5개**를 같은 항목 풀에서 골라 보여준다.
🔒 **가상의 과거 이력을 만들지 않는다.** 기본 체크는 "지난번 미해결"과 **시각적으로 구분**한다.

### 필수 항목 미완료 (`#11`)

`종료 전 경고 → 리포트 상단 고정 → 다음 차수 자동 이월` 3단계.
🔒 **종료 자체를 막지 않는다.** 고객 사정으로 미팅은 갑자기 끝날 수 있다.
🔒 발표에서 이 기능이 **법적 준수를 보장한다고 말하지 않는다.** "미완료 항목 추적 및 경고"까지다.

## 4-5. 역할 5 — 템플릿 · 누적 (조장)

**소유**: 항목풀·표현사전 저작 · 이월/프리로드 규칙 엔진 · 딜 연결
**화면**: 미팅 전 브리핑(화면 ①) · 템플릿 저작 도구
**지표**: 이월 정확도 · 템플릿 커버리지

### W1의 가장 큰 작업 — 항목 풀 작성

| | 개수 | W1 분량 |
|---|---|---|
| 1층 반대사유 `aliases` | 약 30항목 × 5 | **150문장** |
| 2층 필수 항목 `aliases` | 12항목 이하 × 5 | **60문장** |
| 1층 슬롯 `cues` + `blockers` | 30항목 × 약 1.5슬롯 × 6 | **약 270문장** |
| | | **합 약 480문장** |

🔒 **`cues`·`blockers`를 W1에 채운다** (수정, E-2). 이전 판은 슬롯 예문을 W3으로 미뤘는데,
**`blockers`가 곧 재발 판정의 입력**이라 미루면 역할 3이 W3까지 재발 재현율을 측정할 수 없다.
§6-5의 심판일이 W4 금요일이므로 조정할 시간이 한 주밖에 남지 않는다.

### 순서 — 첫날에 팀을 먼저 풀어준다

480문장을 다 쓸 때까지 아무도 못 기다린다. **막고 있는 건 문장 수가 아니라 항목 ID다.**

| | 무엇 | 누적 | 이때부터 가능해지는 것 |
|---|---|--:|---|
| **1일차** | 항목 30개의 `id` · `label` · 슬롯 **구조** + `aliases` 5개씩 | 210 | 🔓 **역할 2 착수 · 전원 라벨링 시작** |
| 2~4일차 | 슬롯마다 `cues` 3 + `blockers` 3 | 480 | 역할 3의 재발 판정 |

**1일차 끝에 항목 ID가 얼면** 라벨링한 fixture가 나중에 무효가 되지 않는다.
표시 이름과 예문은 W3까지 계속 보강해도 된다.

> ⚠️ **`#8`이 낸 39개는 1층이 아니다.** A(오프닝)·B/C(니즈분석)·D(상품설명)·F(청약)·G(컴플라이언스)는
> 전부 "내가 해야 할 일"이고 **반대사유는 E 5개뿐**이다. **E를 세분화해 1층 30개를 따로 만들고,
> 2층은 G(4) + D 중 금소법 해당분에서 12개 이하로 추린다.** `6_통합_체크포인트`의 W1 차단 항목.

### 예문 저작 파이프라인 (신설, E-4)

480문장을 4일에 손으로만 쓰지 않는다. **1일차는 손으로, 2일차부터는 도구로 쓴다.**

| | 무엇 | 방식 |
|---|---|---|
| **1일차** | 항목 30개 `id`·`label`·슬롯 구조 + `aliases` 5개씩 (210) | **손으로.** 판단이라 대신 못 시킨다 |
| **2일차** | 저작 도구 — LLM 후보 생성 → 임베딩 유사도로 중복 제거 → 사람 검수 | 구현 |
| **3~4일차** | 슬롯 `cues`·`blockers` 약 270 | 도구로 초안 → **전량 사람 검수** |

```
항목 label + 기존 aliases
      ↓  LLM 후보 생성 (claude-opus-5)
후보 20~30문장
      ↓  임베딩 코사인 > 0.9 제거
남은 후보
      ↓  사람 검수 — 채택/기각
확정 예문
```

🔒 **역할 2의 런타임 매처와 다른 물건이다.** 이건 **오프라인 저작 도구**다.
같은 임베딩 모델을 쓰되 모델 선정 권한은 역할 2·3에 있다 (§4-2 · §4-3).

🔴 **검수를 건너뛰지 않는다.** LLM이 만든 문장을 그대로 쓰면 실제 영업 현장에서
안 쓰는 표현이 사전에 들어가고, 그게 곧 매칭 오분류가 된다.

### 프리로드 규칙 (§5-2)

| 차수 | 규칙 |
|---|---|
| **1차** | 2층 전부 + 1층 기본 세트 5개. 템플릿 `priority` 순 |
| **2차** | 위 + **1차 미해결 전부 무조건 켬**<br>① 1차 미해결 ② 1차에 나온 것 ③ 1차에 안 나온 기본 |
| **3차+** | 위 + **2회 연속 미해결을 최상단** |

🔒 **이월은 이전 차수 색을 그대로 가져온다.** `trigger="carryover"` 변화로 기록하고
지표에서 제외한다.

### 딜 연결 (`#4`)

- 🔒 **자동 매칭 없음.** 사용자가 고른다
- 사후 연결 허용 (`POST /meeting/{id}/link`)
- 🔒 **`unlink` 필수**
