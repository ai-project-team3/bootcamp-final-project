# 9. 역할과 작업 — 프로토타입 (2026-09-22)

**이 문서만 보고 각자 자기 몫을 시작할 수 있어야 한다.** 그게 안 되면 이 문서가 실패한 것이니 고쳐서 커밋한다.

---

## 9-1. 오늘의 기준

**세 모드가 각각 한 바퀴 도는 통합 버전.** 내일 이것을 캡처해 **사용자 흐름 순서로 어떤 기술이 쓰이는지** 발표한다(발표: 최민우).

**한 바퀴는 「대본으로」다.** 실제 음성 인식·LLM·음성 합성·그림 생성은 오늘 붙이지 않는다. 이유는 §9-2.

---

## 9-2. ⚠️ 시작 전에 알아야 하는 앱의 현재 상태

**모르고 시작하면 하루를 날린다. 세 줄만 기억하면 된다.**

**① 대화는 전부 대본이다.** 아이 발화는 `demo/StoryBank.kt`의 `Answer(...)` 문자열 약 220개다. 마이크 버튼은 녹음이 아니라 **대본 답을 꺼내는 스위치**다 — `demo/Director.kt:140` 주석에 그렇게 적혀 있다. 판정도 LLM이 아니라 Kotlin `when`문(`StoryBank.kt:751` `judge()`)이고, 그림 생성은 `pause(2400)`이다.

**② 앱은 네트워크를 못 쓴다.** `AndroidManifest.xml`에 `INTERNET` 권한이 없고 HTTP 클라이언트 의존성도 없다. **백엔드는 존재하지만 앱이 그 존재를 모른다.** 그리고 백엔드의 `/judge` · `/stt` · `/story`는 셋 다 `raise NotImplementedError`다.

**③ 진짜 음성 코드는 따로 있다.** `DiagnosticsActivity.kt`(312줄)에 Silero VAD · `SpeechRecognizer` · `TextToSpeech`가 **실제로 동작하고 실기기에서 측정까지 끝났다.** 앱 본체와 코드를 한 줄도 공유하지 않는다. **지우지 않는다** — 나중에 본체로 옮길 원본이다.

> **폴더를 새로 파지 않는다.** `android/`가 프로토타입 본체다. 화면 19개와 그림 122장이 이미 붙어 있고 죽은 선언은 4개뿐이다. 새 폴더는 되는 것을 다시 만드는 일이다.

## 9-3. 0단계 — 가름 작업 (**이게 끝나기 전에 아무도 시작하지 않는다**)

**맡는 사람: 이종훈**

지금 코드에 **모드라는 개념이 없다.** 세 사람이 이 상태로 동시에 모드를 붙이면 아래 네 곳에서 매 커밋 충돌한다.

| 파일 | 왜 터지나 |
|---|---|
| `demo/Model.kt:15` `enum class Scene` | 모드마다 화면을 더함 → 3자 충돌 |
| `demo/Scenes.kt:19` `runScene()` | 분기점이 하나뿐인 **1,420줄** 파일 |
| `demo/Model.kt:405` `DemoState` | 속성 70개 god object. 모두가 `resetStory()`를 같이 고침 |
| `ui/Screen.kt:202` `StageView` | `Stage` 20종을 모두가 확장 |

⚠️ **`Scenes.kt:45` `seedFor()`가 `Scene.entries.indexOf()`로 순서를 계산한다.** 화면을 맨 뒤가 아닌 곳에 끼우면 **남의 코드가 조용히 깨진다.**

**0단계에서 할 일**

1. `DemoState`에 `enum class AppMode { STORY, DIARY, COOP }` 추가
2. `Scenes.kt`를 `ScenesCommon.kt` / `ScenesStory.kt` / `ScenesDiary.kt` / `ScenesCoop.kt`로 쪼개고, `runScene()`이 **모드로 먼저 갈라지게** 한다
3. `seedFor()`의 순서 계산을 **명시적 목록**으로 바꾼다
4. 모드별 상태를 `DemoState`에서 분리해, 각자 자기 홀더만 고치게 한다
5. 이름 정리 세 가지 — §9-6

**끝나면 `main`에 올리고 팀에 알린다. 그 커밋 해시가 모두의 출발점이다.**

## 9-4. 역할

| 누구 | 맡는 것 | 왜 |
|---|---|---|
| **안치영** | **일반(동화) 모드** | 1지망 · 제일 큼 · 유일하게 이미 도는 모드 |
| **최민우** | **일기 모드** | 슬롯을 새로 안 만들고 **질문 세트만** 다름 → 제일 가벼움. 내일 발표 준비 시간이 필요하므로 |
| **박진웅** | **부모 협업 모드 + 부모 모드 화면** | 협업이 단순해져 화면 하나라, **리포트까지 묶어야** 크기가 맞음 |
| **이종훈** | **가름 작업 · 공통 파이프라인 · 판정 계약 · 병합** | 세 모드가 다 물려 있음 |

**바꿔도 된다.** 다만 **치영님 일반 모드**와 **조장 가름 작업**은 고정이다.

## 9-5. 역할별 — 소유 파일 · 첫 커밋 · 건드리면 안 되는 것

> **소유 파일**: 그 사람만 고친다. 남의 파일을 고쳐야 하면 **그 사람에게 말하고 PR을 따로 연다.**

### 안치영 — 일반(동화) 모드

**맡는 것**: 이미 도는 동화 한 바퀴를 **`AppMode.STORY`로 옮기고**, 가름 작업으로 깨진 곳을 복구한다. 오늘 이 모드가 **기준 구현**이 되어 나머지 둘이 베낀다.

- **소유**: `demo/ScenesStory.kt` · `demo/StoryBank.kt`의 `TEMPLATES`와 동화용 `BANK` 항목
- **첫 커밋**: 동화 모드가 `ADULT`부터 `END`까지 **끊기지 않고** 도는 것 확인 + 깨진 곳 수리
- **건드리지 않는다**: `ui/Parent.kt`(진웅) · `ScenesDiary.kt`(민우) · `Model.kt`의 공용 부분(조장)
- ⚠️ **틀 빈칸 14개를 지우거나 이름을 바꾸지 않는다** — §9-6

### 최민우 — 일기 모드

**맡는 것**: *"오늘 어디 갔었어?"*로 시작해 **실제 하루를 재료로** 같은 6~8쪽 책이 나오는 한 바퀴. 설계는 `docs/일기모드_설계.md`.

- **소유**: `demo/ScenesDiary.kt` · `StoryBank.kt`의 일기용 `BANK` 항목(접두사 `d_`)
- **첫 커밋**: 첫 질문을 바꾼 화면 하나라도 **모드 선택 → 일기 첫 질문**까지 연결
- **건드리지 않는다**: 동화 `TEMPLATES` · `ui/Parent.kt` · 공용 `Model.kt`
- **새 슬롯을 만들지 않는다.** 일기 모드도 **같은 12종**을 쓴다. 다른 건 질문 문장뿐이다
- ⚠️ 문서에 미결로 남은 것: **있었던 일을 얼마나 부풀려도 되는가.** 오늘은 **부풀리지 않는 쪽**으로 두고 진행한다
- 내일 발표자다. **발표 준비 시간을 먼저 확보하고 남는 시간으로 한다**

### 박진웅 — 부모 협업 모드 + 부모 모드 화면

**맡는 것**: 부모가 **부모 모드에서 질문을 미리 넣어 두고**, 아이가 그 질문에 답하는 한 바퀴. LLM은 **질문을 추천하는 정도**로만 쓴다(오늘은 추천도 대본).

- **소유**: `demo/ScenesCoop.kt` · `ui/Parent.kt` · `ui/Shelf.kt`
- **첫 커밋**: 부모 모드에 **질문을 넣는 화면** 하나 + 그 질문이 아이 화면에 뜨는 것
- **건드리지 않는다**: `ScenesStory.kt` · `ScenesDiary.kt` · 공용 `Model.kt`
- ⚠️ **`ui/Parent.kt:200-208`의 6개 축이 동화 모드 전용이다** — `s.dino.name`(:194) · `s.friendName`(:193) · `s.placeName`(:288)을 읽는다. **일기 모드에는 이 값들이 없어서 터지거나 헛소리를 낸다.** 모드별로 갈라 놓는 게 당신 몫이다
- ⚠️ `Parent.kt:267`의 *"지난번"* 비교 막대는 **문자열 상수**다. 기록이 없다. 오늘 고치지 않아도 되지만 **진짜인 척하지 않는다**

### 이종훈 — 가름 작업 · 공통 · 병합

- **소유**: `demo/Model.kt` · `demo/Director.kt` · `demo/ScenesCommon.kt` · `ui/Screen.kt` · `MainActivity.kt` · `backend/`
- **첫 커밋**: §9-3 가름 작업
- **그다음**: 모드 선택 화면(세 모드로 들어가는 입구) → 이름 정리(§9-6) → 병합
- **오늘 안 한다**: 네트워크 계층 · `/judge` 구현 · STT 이식. **A 기준이 먼저 확보된 뒤에만 본다**

## 9-6. 이름 — **두 종류가 있고 섞으면 안 된다**

**이걸 모르고 "문서 이름으로 통일"하면 책 문장이 전부 기본값으로 떨어진다.**

| | **판정 슬롯 12종** | **틀 빈칸 14종** |
|---|---|---|
| 정본 | `guidelines/2_공통_데이터_모델.md` §1-1 | `StoryBank.kt`의 `TEMPLATES` |
| 누가 이름을 정하나 | **LLM이 닫힌 목록에서 고른다** | **앱이 미리 정해 두고 직접 묻는다** |
| 쓰는 곳 | 다음에 뭘 물을지 · 부모 리포트 집계 | **책 쪽 문장 렌더링** |
| 늘어나도 되나 | ❌ 늘면 앱이 못 알아본다 | ✅ 틀이 늘면 같이 는다 |

틀 빈칸은 틀마다 다르다 — E는 `stop saw resolve goal`, C는 `response helper resolve`, D는 `need role resolve`, A는 `try1 fail resolve reflect`, G는 `consequence lesson resolve reflect`.

책 문장이 이렇게 쓴다:

```kotlin
"${it.c}은 씩씩한 ${it.slot("role", "구조대원")}이 되기로 했어요"
```

**`role`이 비면 "구조대원"이 들어간다.** 즉 빈칸을 없애면 **아이가 한 말 대신 우리가 써둔 말이 책에 들어간다.** 차별점 1번을 정면으로 어긴다.

### 0단계에서 고칠 세 가지

1. **`follow` → `reaction`** — 이건 빈칸이 아니라 **12종 중 하나**인데 빈칸 맵에 들어가 있다
2. **`friend` → `companion`**, **`partnerHelp` → `adult`** — 12종을 다른 이름으로 부르고 있다
3. **`extra` 추가** — 목록 밖 발화를 담을 곳이 없다. 규칙 1의 핵심 장치다

그리고 **빈칸 맵 이름을 `slots` → `blanks`로 바꾼다.** 안 그러면 부모 리포트가 `slot_filled` 이벤트를 집계할 때 12종과 빈칸이 섞여 숫자가 거짓이 된다.

## 9-7. 충돌을 줄이는 규칙 넷

1. **`feature/<본인이름>`에서 작업하고 `main`에 직접 푸시하지 않는다.** PR을 열고 조장이 병합한다
2. **남의 소유 파일을 고쳐야 하면 먼저 말하고 PR을 따로 연다.** 내 모드 PR에 끼워 넣지 않는다
3. **AI에게 맡길 때 diff를 작게 끊는다.** 한 번에 큰 diff를 만들면 충돌이 그만큼 커진다. **바이브코딩은 충돌을 줄여 주지 않는다 — 키운다**
4. **하루에 두 번 `main`을 받아 온다** (점심 · 저녁). 마지막에 몰아서 병합하지 않는다

## 9-8. 오늘 안 하는 것

**A 기준을 지키기 위해 의도적으로 뺀다.**

- **네트워크 · 실제 LLM 판정 · 실제 STT · 실제 TTS · 실제 그림 생성**
  이유: 앱에 `INTERNET` 권한조차 없고 백엔드 세 엔드포인트가 전부 미구현이다. 한 모드만 진짜로 만들어도 **약 10시간**이고, 오늘 잰 값으로 **아이가 기다리는 시간이 6.26초**(받아쓰기 2.54 + 판정 2.40 + 첫 소리 1.32)라 **느린 게 영상에 그대로 찍힌다**
- **화자 구분** — 설계가 바뀌어 빠졌다. 아이가 혼자 쓰고, 부모는 질문을 미리 넣는다
- **책장에서 다시 읽기** (`Scenes.kt:1375`에 이미 "아직 없다"고 적혀 있다)
- **저장** — `SharedPreferences` · `DataStore` · `Room` 아무것도 없다. 세션이 끝나면 다 사라진다. **오늘은 그대로 둔다**
- **죽은 코드 정리** — 안 쓰이는 선언 4개와 그림 2.2MB뿐이다. 5분짜리라 아무 때나 한다

## 9-9. 다 됐는지 보는 법

**네 줄이 전부 참이면 오늘 끝이다.**

- [ ] 모드 선택 화면에서 **세 모드로 각각 들어간다**
- [ ] 세 모드가 각각 **시작 화면부터 책이 나올 때까지 끊기지 않는다**
- [ ] **부모 모드가 세 모드 중 어느 것을 하고 와도 안 터진다**
- [ ] `main`에 병합돼 있고 **다른 사람 기기에서 빌드된다**
