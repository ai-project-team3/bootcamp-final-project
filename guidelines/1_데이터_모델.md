# 1. 공통 데이터 모델

**이 파일이 이름의 유일한 출처다.** 슬롯·이벤트·출처를 각자 코드에 박지 말고 여기서 가져간다.
바꾸려면 **조장에게 먼저 말한다.** 한 사람이 이름을 바꾸면 나머지 셋이 조용히 깨진다.

> 왜 이 문서가 필요한가 — 9/18에 세 사람이 같은 슬롯 이름을 각자 코드에 적기 시작했다. 한 곳에 안 적어 두면 다음 날 안 맞는다.

---

## 1-1. 슬롯 12종 — **닫힌 목록이다**

| 이름 | 무엇 | 질문 예 | 채우는 법 |
|---|---|---|---|
| `place` | 어디로 가나 | "오늘은 어디로 가 볼까?" | 말 → 장소 유형 매핑 |
| `problem` | 무슨 일이 생겼나 | "어? {사건}. 왜 그럴까?" | 말 |
| `reaction` | 그래서 어떻게 됐나 | "그래서 어떻게 됐어?" | 말 |
| `cause` | 왜 그랬나 | "{친구}는 왜 그랬을까?" | 말 |
| `newcomer` | 새로 나온 친구 | "{친구}를 그려 줄래?" | 그림판 또는 프리셋 |
| `name` | 그 친구 이름 | "이름은 뭐야?" | 말 |
| `companion` | 같이 간 친구 | "어떤 공룡이야?" | 말 |
| `sound` | 우는 소리 | "{공룡}은 어떻게 울어?" | 녹음 |
| `adult` | 어른의 한마디 | "{어른}은 ○○하면 뭐 하고 싶어?" | 어른 말 |
| `solution` | 어떻게 풀었나 | "{친구}랑 어떻게 친해질까?" | 말 |
| `title` | 책 이름 | "이 책 이름은 뭐라고 할까?" | 말 |
| **`extra`** | **위 어디에도 안 맞는 것** | — | **원문 그대로** |

**규칙 넷**

1. **LLM은 이름을 고르지, 만들지 않는다.** 목록 밖은 전부 `extra`에 원문 그대로. 새 이름이 들어오면 앱이 렌더링도 집계도 못 한다
2. **필수 여부는 고정이 아니다.** 아이가 *"혼자 갔어"*라고 하면 `companion`이 빠지고, *"친구랑 싸웠어"*라고 하면 화해 방법이 새로 필요해진다. 판정 응답의 `no_longer_needed`가 이걸 알린다
3. **수집 순서도 고정이 아니다.** LLM이 `next_slot`으로 정한다. 앱은 **이미 값이 있는 칸을 다시 묻지 않게만** 막는다
4. **끝나는 기준은 턴 수가 아니라 `story_ready`** — 템플릿 기준으로 이야기 재료가 찼는가

> **왜 턴 상한이 없나**: 8턴 상한은 우리 핵심 지표인 **「주고받기 횟수」를 스스로 깎는다.** 아이가 신나서 계속 말하는 건 제품이 원하는 일이다.

**끝나는 조건 셋** — `story_ready: true` · `mascot_pick` 2회 연속 · 15분 경과

## 1-2. 판정 응답 16필드

`backend/app/schemas/judge.py`가 구현이고, 프롬프트 전문은 `docs/프롬프트_모음.md` §2다.

```
reason              문자열   ← 반드시 첫 필드
slot_1 / value_1    채운 칸과 값
slot_2 / value_2    함께 채운 칸 (한 턴에 최대 2개)
contradiction       참/거짓
contradiction_with  어긋난 칸
s1_reason           까닭을 스스로 말했는가
s2_addition         묻지 않은 것을 덧붙였는가
emotion             마음을 가리키는 말
unclear / unclear_of  확인 카드 3장을 띄울지
next_slot           다음에 물을 칸
next_reason         왜 그걸 묻는지
no_longer_needed    필요 없어진 칸
story_ready         이야기 재료가 다 찼는가
```

**설계 규칙 셋** — 바꾸면 정확도가 떨어진다. 근거는 `docs/기능별_모델선정.md` §2-2.

| | |
|---|---|
| **`reason`이 첫 필드** | 판정 앞에 근거를 쓰게 하면 **15~24점 회복** |
| **1단 평면. 중첩 금지** | 깊어지면 *"값은 맞는데 필드가 틀리는"* 실패가 지배적이 된다 |
| **규칙을 스키마 `description`에 쓰지 않는다** | 시스템 프롬프트에 둔다. description에 넣으면 **11~13%p 낮다** |

**벤더 공통분모만 쓴다.** Anthropic 제약 디코딩은 `minimum`·`maxLength`·재귀·외부 `$ref`를 지원하지 않고, OpenAI strict는 모든 필드가 `required`여야 한다. **옵셔널 대신 `["string","null"]`.**

## 1-3. 이벤트 11종

리포트 숫자는 전부 여기서 나온다. **이벤트를 안 남기면 리포트가 빈칸이 된다.**

`story_start` · `utterance` · `slot_filled` · `signal` · `emotion_mention` · `make` · `image_request` · `redraw` · `mission` · `friend_rating` · `session_end`

```
{ name, at(초), by, slot, payload }
```

---

## 1-4. 출처 `by` 3종 — **끝까지 구분한다**

**아이가 한 말과 우리가 채운 말이 섞이면 부모 리포트가 거짓말을 시작한다.**

| | `child` (말로) | `card` (골라서) | `mascot` (대신 정해 줌) |
|---|---|---|---|
| **책 자막** | ✅ | ✅ | ✅ 이야기의 일부다 |
| **주고받기 횟수** | ✅ | ✅ 아이가 골랐다 | ❌ |
| **수준 신호 (S1·S2)** | ✅ | ❌ | ❌ |
| **리포트 원문 인용** | ✅ | ❌ | ❌ |
| **「말한 방식」 원그래프** | 말로 | 골라서 | **표시하지 않는다** |
| 이름 필터 | ✅ | 불필요 | 불필요 |
| 금칙어·안전 필터 | ✅ | 불필요 | ✅ LLM이 만든 말이면 |

> **`mascot`을 원그래프에 안 넣는 이유**: *"마스코트가 대신함 30%"*가 뜨면 **부모가 아이의 실패로 읽는다.** 그건 우리 필터 설계가 만든 숫자이지 아이의 행동이 아니다.

## 1-5. 수준 3단계 — **규칙이 계산한다. LLM은 신호만 표시한다**

| 단계 | 할 수 있는 것 | 증거 | 질문 결 |
|---|---|---|---|
| 고르며 짓기 | 고른다 | (신호 없음) | 무엇 · 누구 · 어디 |
| 이어 짓기 | **잇는다** | **S2** | 그래서 · 그다음 |
| 까닭 짓기 | **까닭을 댄다** | **S1** | 왜 · 어떻게 |

**올림** — 신호가 가리키는 단계가 지금보다 높고 **2턴 연속**이면 **한 칸.** 두 칸은 안 뛴다(못 답하면 실패 경험이 된다).
**내림** — 무응답·카드 2턴 연속, **또는 `mascot_pick` 1회.**
**유지** — 그 밖에 전부. 신호 없는 평범한 답은 **지금 단계가 맞다는 뜻**이다.

**첫 두 턴은 프로브다.** `place`(어디)·`problem`(왜)를 고정으로 던지고 2턴 답으로 초기 수준을 정한다. **나이를 묻지 않는다** — 만 3~7세는 개인차가 커서 나이가 능력을 예측하지 못하고, *"꼬리표를 저장하지 않는다"*는 원칙과도 어긋난다.

**미션 난이도는 수준과 분리한다.** 말하기와 손 쓰기는 다른 능력이고, **미션 실패가 리포트에 "말하기가 줄었다"로 잘못 읽히면 안 된다.**

**매 세션 다시 판단한다. 아이에게 단계를 저장하지 않는다.**

---

## 1-6. 부모에게 보이는 것 — **등급 이름은 안 쓴다**

앱은 안에서 3단계를 계산하지만 **그 이름은 부모 화면에 안 나온다.** 대신 **그 단계를 판단한 근거**를 보여준다.

| 안 씀 | 대신 |
|---|---|
| "까닭 짓기 단계" | **"까닭을 말한 것 4번"** + 원문 인용 |
| "향상됐습니다" | "지난번보다 3번 더" |
| 또래·평균·백분위 | (기본 화면에 안 씀) |

금지어 목록은 `docs/금칙어_목록.md` §3. **LLM이 만든 문장에 하나라도 있으면 그 답을 버리고 미리 만든 문장을 쓴다.**
