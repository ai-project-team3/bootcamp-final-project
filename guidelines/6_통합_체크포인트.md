## 6-2. 반드시 통과해야 하는 흐름

**이 14단계가 끝까지 끊기지 않으면 1차가 된 것이다.**

1. 앱을 켠다 → [같이 만들자]
2. 누구와 하는지 고른다
3. 주인공을 만든다 (프리셋 또는 그림)
4. 마스코트가 **기준 질문 ①** *"어디로 가 볼까?"*
5. 아이가 말한다 → **VAD가 구간을 자른다**
6. **STT → 폰에서 이름 가리기 → 금칙어 → 판정**
7. 판정이 `slot_1`·`value_1`을 돌려주고 **`next_slot`을 정한다**
8. 마스코트가 **받아주기 + 되돌려주기 + 다음 질문**
9. 마스코트가 **기준 질문 ②** *"왜 그럴까?"* → **2턴 답으로 초기 수준 확정**
10. **3턴째에 템플릿 확정** → 그 뒤 질문 결만 바뀐다
11. 중간에 **그림판 · 소리 녹음 · 미션**이 한 번씩
12. **`story_ready: true`** → 장면 6개 + 자막
13. **미리 만든 그림을 겹쳐 책이 되고, 그 자리에서 읽는다**
14. 부모 모드 → **오늘 아이가 한 말과 횟수**

**「친구 평가」는 책을 읽은 다음이다** (9/18 확정). 좋아/싫어로 다음에 또 볼지 정한다.

## 6-4. 재는 숫자 — 합격선

**측정값이 이 선을 넘어야 확정한다. 기준 없는 측정은 아무것도 결정하지 못한다.**

| 항목 | 합격선 | 못 넘으면 |
|---|---|---|
| 판정 JSON 성공률 | **≥ 99%** | 스키마를 더 평평하게 → 상위 모델 |
| 아이 발화 핵심 키워드 보존율 | **≥ 90%** | STT 상향 또는 자체 파인튜닝 |
| 프리셋 매칭 정답률 (자모 편집거리 적용 후) | **≥ 95%** | 발음 규칙 정규화 추가 |
| **아이가 듣는 첫 소리** | **≤ 2초** | 파이프라인 기법 먼저 → 그래도 안 되면 모델 교체.<br>⚠️ **같은 3060의 공개 구현 실측이 2.98~4.10초다.** 우리 목표가 공격적이라는 뜻이고, **채우는 말(filler)이 그래서 필수다** |
| 판정 완료 | ≤ 4초 | 첫 소리가 먼저 나가므로 여유가 있다 |
| 캐릭터 동일성 (팀 5점) | **평균 ≥ 4** | 부품 합성 비중 확대 |
| **이야기 금지 표현** | **0건** | **타협 없음** |
| **한 권 총 AI 원가** | **≤ 200원** | 런타임 생성 장수를 줄인다 |

**한 권 원가에서 이미지가 90%를 차지한다.** 텍스트 모델 교체로 아끼는 건 권당 몇 원이고, 런타임 생성 3장은 최대 141원이다.

## 6-5. 되돌릴 신호

**아래가 보이면 규모를 줄이거나 방향을 되돌린다.**

| 신호 | 그러면 |
|---|---|
| 판정 JSON 성공률이 **전 모델에서** 99% 미만 | **모델이 아니라 스키마 문제다.** 필드를 줄인다 |
| **다중채움·필수해제 F1이 낮다** | **설계를 되돌린다** — 슬롯 하나씩 주는 방식으로 |
| 프리셋 매칭이 강도 1에서 95% 미만 | 선택지 UI를 병행한다 |
| 첫 소리가 4초를 넘는다 | 마스코트가 먼저 반응하고 뒤에서 판정한다 |
| 자체 faster-whisper가 3060에서 안 돈다 | Azure 오프라인 컨테이너로 |

## 6-7. 측정은 발표 자료이기도 하다

**재기 전 숫자를 남기지 않으면 최종 발표에 쓸 것이 없다.**

*"무엇이 느렸고 어떻게 고쳤다"*가 성립하려면 **부끄러운 베이스라인이 먼저 있어야 한다.** 측정할 때 **개선 전/후를 같은 줄에** 기록한다. `eval/results.md`가 그대로 슬라이드가 된다.

⛔ **베이스라인은 최적화를 붙이기 전에만 잴 수 있다.** 파이프라인이 처음 이어지는 날, **VAD·문장 쪼개기·병렬 생성을 얹기 전에** 잰다.
