# 4. 모듈 브리프

> **역할 배정은 아직 확정하지 않았다.** 그래서 사람이 아니라 **모듈** 단위로 적는다.
> 맡게 되면 자기 절을 읽고 시작한다. 경계 밖은 건드리지 않는다.

---

## A. 대화 — 턴 엔진

**무엇을 만드나**: 마스코트가 묻고, 아이 말을 받고, 판정 결과대로 다음으로 넘어가는 루프.

```
ASK  ──► LISTEN ──► JUDGE ──► REACT ──► NEXT
           │
           ├─ 어른만 말함 ──► "지호는 어떻게 생각해?" 1회 ──► LISTEN
           └─ 무응답 ──► 쉬운 질문 1회 ──► 무응답
                              └─► 카드 3장 (최대 3회 교체)
                                     └─► MASCOT_PICK
```

**지켜야 할 것**

| | |
|---|---|
| **턴 상한 없음** | 끝나는 건 `story_ready` · `mascot_pick` 2연속 · 15분 |
| **`next_slot`을 앱이 정하지 않는다** | 판정 응답에서 온다. 앱은 **이미 찬 칸을 다시 묻지 않게만** 막는다 |
| **MASCOT_PICK은 소리 내어 말한다** | *"음… 내 생각에는 공룡나라가 좋을 것 같아!"* **말없이 채우지 않는다** |
| **되묻지 않는다** | MASCOT_PICK 뒤에 또 물으면 아이가 더 움츠러든다 |
| **`by`를 반드시 남긴다** | `child` · `card` · `mascot` |

**막히면**: 판정이 실패해도 **대사는 나와야 한다.** 판정과 대사 생성은 분리된 호출이다.

**재는 숫자**: **아이가 듣는 첫 소리까지 ≤ 2초** · 판정 완료 ≤ 4초

---

## B. 이야기 — 프롬프트와 스키마

**무엇을 만드나**: 판정 프롬프트 · 생성 프롬프트 · JSON 스키마 · 템플릿 A~G.

**지켜야 할 것** (`7_프롬프트.md`가 본문, 근거는 노션 「기능별 모델 선정」 §2-2)

| | |
|---|---|
| **`reason`이 첫 필드** | 판정 앞에 근거를 쓰게 하면 **15~24점 회복** |
| **1단 평면. 중첩 금지** | 깊어지면 *"값은 맞는데 필드가 틀리는"* 실패가 지배적 |
| **규칙을 스키마 `description`에 쓰지 않는다** | 시스템 프롬프트에 둔다. description에 넣으면 **11~13%p 낮다** |
| **벤더 공통분모만** | `minimum`·`maxLength`·재귀·`$ref` 금지. 옵셔널 대신 `["string","null"]` |
| **확정 후 모델마다 손대지 않는다** | 고치는 순간 **뭘 비교한 건지 알 수 없다** |

**함정 하나**: `-아서/-어서`가 **인과와 순차를 같은 형태로 쓴다.** "무서워**서** 도망갔어"(S1 참)와 "가**서** 먹었어"(S1 거짓). **few-shot에 이 둘을 반드시 넣는다.**

**재는 숫자**: JSON 성공률 **≥ 99%** · 다중채움 F1 · 필수해제 F1 · `next_slot` 적중

## C. 음성 — VAD · STT · 이름 필터 · TTS

**무엇을 만드나**: 마이크에서 글자까지, 그리고 마스코트 목소리.

| | |
|---|---|
| **VAD** | `com.github.gkonovalov.android-vad:silero` (MIT, ~2MB, minSdk 24) |
| **STT** | 자체 GPU faster-whisper large-v3-turbo(int8) · ML Kit `ko-KR` 폴백 |
| **이름 필터** | **폰에서.** 사전(등록 이름) + 규칙(호칭+이름 패턴) 2층 |
| **TTS** | **고정 대사 46변형은 사전 합성 번들.** ⚠️ 가변 자막은 미정 — 폰 `TextToSpeech`가 탈락했다(`eval/results.md` §6) |

**지켜야 할 것**

- **재현율을 정확도보다 앞에 둔다.** 이름인지 애매하면 **가린다.** 폰에서 되돌리니 잘못 가려도 아이는 원문을 본다
- **매핑표는 폰에만.** 서버가 가지면 서버가 개인정보를 갖는 것이다
- **아이 녹음(울음소리)은 폰을 떠나지 않는다.** 변조 없음
- **SSML에 의존하지 않는다.** 플랫폼이 보장하지 않는다

**구조적 함정**: Whisper는 오디오를 **고정 30초 창**으로 처리한다. 1.5초 발화가 28.5초 무음으로 채워지고 그 위에서 **없는 말을 생성한다.** 한국어 아동 CER 120.8%가 그것이다. **VAD가 대책이자 비용 절감(7배)이다.**

**출발점 수치** — 같은 RTX 3060에서 돌린 공개 구현([thecodacus/pithagoras](https://github.com/thecodacus/pithagoras))에서 읽은 값이다.
⚠️ **그 레포는 라이선스가 없다(전권 유보). 코드를 복사하면 안 된다. 읽고 직접 구현한다.**

| Silero VAD | 값 | 아동 대상 주의 |
|---|---|---|
| `positiveSpeechThreshold` | 0.65 | |
| `negativeSpeechThreshold` | 0.35 | |
| `minSpeechMs` | 256 | 옹알이 걸러내려면 재측정 |
| `preSpeechPadMs` | 320 | 발화 시작을 놓치지 않게 |
| `redemptionMs` | 1000 | ⚠️ **3~7세는 1500~2000으로 올린다.** 문장 사이 침묵이 길어 **말이 끊긴다** |

| 문장 청킹 | |
|---|---|
| 최대 길이 | 600자 (마스코트 대사는 훨씬 짧으니 낮춘다) |
| **3단어 이하 조각** | **다음 문장과 합친다** — 잘게 쪼개면 끊겨 들린다 |
| 경계 | 한국어는 **종결어미**(`다. 요. 까? 야!`)로 판정 |

| 재생 | |
|---|---|
| **TTS 큐 깊이** | **2** — GPU 요청 슬롯이 1개라 그 이상 미리 만들어도 낭비 |
| **재생 시작 버퍼** | **0.65초** 분량이 쌓이면 시작. 나머지는 만들면서 이어붙인다 |

| 채우는 말 (filler) | |
|---|---|
| 언제 | **1800ms 지나면** 발화. 빨리 답이 오면 타이머 취소 |
| 쿨다운 | **20초** |
| 반복 방지 | **직전에 쓴 문구를 연속으로 쓰지 않는다** |
| 우리 방식 | 마스코트 대사 3~5개를 **미리 합성해 캐싱** → 지연 0 |

**재는 숫자**: 아이 발화 **핵심 키워드 보존율 ≥ 90%** · 짧은 발화 환각률

## D. 그림 — 부품 합성, 그리고 아직 안 정한 것

⚠️ **언제 만들지와 무엇으로 만들지가 미정이다.** 미리 만들어 번들할지, 세션 중에 생성할지,
자체 호스팅일지 외부 API일지 — 전부 열려 있다. **한 장에 몇 초 걸리는지를 재고 정한다.**
그 숫자가 나오기 전까지 지연·원가·오프라인 동작을 확정된 것처럼 쓰지 않는다.

**정해진 것**

| | |
|---|---|
| **부품 합성** | 인형 부품을 겹쳐 그린다. **LoRA를 쓰지 않는다** |
| **아이 그림은 그대로** | **AI가 다시 그리지 않는다** |
| **투명 PNG로 만든다** | 배경 제거 단계가 통째로 사라진다 |
| **검사 없이 아이에게 보내지 않는다** | 자체 호스팅 모델에는 **안전 필터가 없고**, 외부 API는 **아이 이야기가 밖으로 나간다** |

**재야 정해지는 것** — 한 장 생성 시간 · 그때의 원가 · 오프라인에서 돌릴 수 있는가 ·
세션 중에 만든다면 무엇이 검사하는가.

**왜 LoRA가 아닌가**: LoRA는 캐릭터가 **미리 정해져 있을 때** 쓰는 도구인데, 이 제품의 핵심은 **아이가 그 자리에서 주인공을 만드는 것**이다. 즉석 학습은 60~80분, 세션은 15분. **제품 이름이 인형극이다** — 정해진 부품을 조합하는 것이 오히려 아이에게 *"내가 골랐다"*는 느낌을 준다.

**재는 숫자**: 캐릭터 동일성 팀 평가 **평균 ≥ 4/5** · **한 권 총 AI 원가 ≤ 200원**

## E. 기록 — 이벤트 · 수준 · 부모 리포트

**무엇을 만드나**: 이벤트 11종을 남기고, 수준을 계산하고, 부모 화면을 그린다.

**⚠️ 이벤트를 안 남기면 리포트가 통째로 빈칸이 된다.** 나중에 발견하면 처음부터 다시 짜야 한다.

| | |
|---|---|
| **수준은 규칙이 계산** | LLM은 S1·S2만 표시. 계산식은 `2_공통_데이터_모델` §5 |
| **한 번에 한 칸만** | 두 칸을 뛰면 갑자기 "왜"를 묻게 되고 **못 답하면 실패 경험**이 된다 |
| **미션은 수준과 분리** | 말하기와 손 쓰기는 다른 능력이다. **미션 실패가 "말하기가 줄었다"로 읽히면 안 된다** |
| **`by`로 걸러 센다** | `mascot`은 주고받기 횟수·신호·인용에서 전부 빠진다 |
| **등급 이름을 부모에게 안 쓴다** | *"까닭 짓기 단계"* ✗ → **"까닭을 말한 것 4번"** + 원문 인용 |
| **줄어든 날은 말하지 않는다** | 지적하지 않는다. 그 줄을 숨긴다 |

**재는 숫자**: 이벤트 누락 0건

## F. 평가 — 픽스처 · 러너 · 측정

**무엇을 만드나**: 같은 입력을 여러 모델에 돌려 같은 기준으로 점수를 내는 것. `eval/`.

### 재야 할 후보 다섯 (정본)

단가는 `eval/model_catalog.json`, 채택 근거는 노션 「기능별 모델선정」.

| 후보 | 자리 | 키 |
|---|---|---|
| **`gpt-5.6-luna`** | **1순위.** 한 모델, effort 두 설정 | `OPENAI_API_KEY` |
| `gpt-5-nano` | 더 싼 쪽이 되는지 | `OPENAI_API_KEY` |
| `claude-haiku-4-5` | OpenAI ZDR 승인 실패 시 대안 | `ANTHROPIC_API_KEY` |
| `mistral-small-4` | 대안 | `MISTRAL_API_KEY` |
| `ministral-3-3b` | 하한선 — 2026-09-20 **탈락** (`results.md`) | `MISTRAL_API_KEY` |

**후보를 자기 환경에 맞춰 줄이지 않는다.** 키는 조직 계정이라 각자 발급받으면 된다.
키가 없으면 `preflight`가 **`NO KEY`로 보고하게 두는 것이 맞다** — 그 빈칸 자체가 보고할 내용이고,
목록에서 지우면 **1순위가 미측정인 채로 측정이 끝난 것처럼 보인다.** 2026-09-20에 실제로 그렇게 됐다.


| | |
|---|---|
| **TTFT는 스트리밍으로 잰다** | 논스트리밍이면 **총 소요를 잰 것**이다 |
| **`next_slot`은 허용 집합으로 센다** | 맥락상 물어도 되는 칸이 여럿이다. 정답 하나를 강요하면 **정상 답을 오답으로 센다** |
| **`value_1`은 자모 편집거리 ≤ 0.3** | 자유 서술이라 표현이 갈린다 |
| **JSON 파싱 실패도 기록** | 실패율 자체가 지표다. 죽지 말고 넘어간다 |
| **결과를 누적한다** | 날짜 · 모델 · 조건 · 값. **이 표가 그대로 최종 발표 슬라이드가 된다** |

**⛔ 베이스라인은 최적화를 붙이기 전에만 잴 수 있다.** 파이프라인이 처음 이어지는 날, VAD·문장 쪼개기·병렬 생성을 얹기 **전에** 잰다. 붙이고 나면 *"○○초를 ○○초로 줄였습니다"*의 앞 숫자가 영영 사라진다.
