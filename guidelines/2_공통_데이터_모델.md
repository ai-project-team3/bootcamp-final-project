# 1. 공통 데이터 모델

**이 파일이 이름의 유일한 출처다.** 슬롯·이벤트·출처를 각자 코드에 박지 말고 여기서 가져간다.
바꾸려면 **조장에게 먼저 말한다.** 한 사람이 이름을 바꾸면 나머지 셋이 조용히 깨진다.

> 왜 이 문서가 필요한가 — 9/18에 세 사람이 같은 슬롯 이름을 각자 코드에 적기 시작했다. 한 곳에 안 적어 두면 다음 날 안 맞는다.

## 1-1. 슬롯 12종 — **닫힌 목록이다**

| 이름 | 무엇 | 질문 예 | 채우는 법 |
|---|---|---|---|
| `place` | 어디로 가나 | "오늘은 어디로 가 볼까?" | 말 → 장소 유형 매핑 |
| `problem` | 무슨 일이 생겼나 | "어? {사건}. 왜 그럴까?" | 말 |
| `reaction` | 그래서 어떻게 됐나 | "그래서 어떻게 됐어?" | 말 |
| `cause` | 왜 그랬나 | "{친구}는 왜 그랬을까?" | 말 |
| `newcomer` | 새로 나온 친구 | "{친구}를 그려 줄래?" | 그림판 또는 프리셋 |
| `name` | 그 친구 이름 | "이름은 뭐야?" | 말 |
| `companion` | 같이 간 친구 | "어떤 공룡이야?" | 말 |
| `sound` | 우는 소리 | "{공룡}은 어떻게 울어?" | 녹음 |
| `adult` | 어른의 한마디 | "{어른}은 ○○하면 뭐 하고 싶어?" | 어른 말 |
| `solution` | 이야기 끝에 어떻게 됐나(결말). 문제가 있었으면 어떻게 풀었나 | "{친구}랑 어떻게 친해질까?" · 일기 "다 놀고 나서 어떻게 됐어?" | 말 |
| `title` | 책 이름 | "이 책 이름은 뭐라고 할까?" | 말 |
| **`extra`** | **위 어디에도 안 맞는 것** | — | **원문 그대로** |

> **`solution` 과 `reaction` 의 경계** — `reaction` 은 **사건 바로 뒤**(그때 어땠나), `solution` 은 **이야기 끝**(결국 어떻게 됐나)이다.
> 동화의 결말은 늘 해결이라 동화에서는 전과 같다. 일기·협업에는 문제가 없던 날이 있어서 「풀었나」로는 칸이 안 찬다 (09-26).
>
> **바람은 `solution` 이 아니다.** *"다음에 또 가고 싶어"* 같은 앞일은 `extra` 에 원문 그대로 넣고,
> 일기·협업 책에서는 **맺음(`keep`) 자리**에 쓴다. `keep` 은 슬롯이 아니라 일기 책의 자리 이름이다(`DiaryBank.kt` 맺음 걸음) —
> 슬롯은 위 12개뿐이다. 바람을 결말에 넣으면 책이 바람을 **있었던 일로** 쓴다 (`7_프롬프트.md` §5-1).

**규칙 넷**

1. **LLM은 이름을 고르지, 만들지 않는다.** 목록 밖은 전부 `extra`에 원문 그대로. 새 이름이 들어오면 앱이 렌더링도 집계도 못 한다
2. **필수 여부는 고정이 아니다.** 아이가 *"혼자 갔어"*라고 하면 `companion`이 빠지고, *"친구랑 싸웠어"*라고 하면 화해 방법이 새로 필요해진다. 판정 응답의 `no_longer_needed`가 이걸 알린다
3. **수집 순서도 고정이 아니다.** LLM이 `next_slot`으로 정한다. 앱은 **이미 값이 있는 칸을 다시 묻지 않게만** 막는다
4. **끝나는 기준은 턴 수가 아니라 `story_ready`** — 템플릿 기준으로 이야기 재료가 찼는가

> **왜 턴 상한이 없나**: 8턴 상한은 우리 핵심 지표인 **「주고받기 횟수」를 스스로 깎는다.** 아이가 신나서 계속 말하는 건 제품이 원하는 일이다.

**끝나는 조건은 `story_ready: true` 하나다** (09-30 조장 결정)

- **아이가 답을 못 해도 이야기는 끝나지 않는다.** 그 칸만 사다리로 채운다 — 무응답 → 쉬운 질문 1회 → 무응답 → **카드 3장**(`by: card`, 최대 3번 교체) → 카드도 안 고르면 마스코트가 정한다(`by: mascot`, `guidelines/7` §3-2). 칸이 다 차면 `story_ready` 로 끝난다
- **「말했는데 못 알아들음」은 무응답이 아니다**(10-02 조장 · #79). 녹음에서 말소리는 들렸는데 받아쓰기가 비었거나 실패하면 사다리를 내려가지 않고 같은 질문으로 「한 번 더 말해 줄래?」라고 되묻는다. **두 번 연달아** 못 알아들으면 그때 무응답으로 넘긴다. 되물은 뒤 8초 동안 아무것도 안 하면 무응답이다. 카드 후보는 서버가 `/turn` `options` 로 낸다(`3` §3-2-1) — `Director.liveMic` · `unheard`
- 전에 있던 「`mascot_pick` 2회 연속이면 끝」은 **없앴다** — 기획은 칸을 채우는 것이지 이야기를 닫는 것이 아니었다
- **시간으로 끊지 않는다.** 전에 있던 「15분 경과」는 사용 시간 **예상치**였지 규칙이 아니었다

| 모드 | 시간 |
|---|---|
| 동화 | 없음 — 칸이 끝을 정한다 |
| 일기 | **30분쯤 되면 마스코트가 마무리를 제안한다.** 아이가 더 하고 싶다고 하면 계속한다. 제안은 한 번이고, 되묻지 않는다 |
| 협업 | **없음** — **뼈대 네 칸(`place` · `problem` · `cause` · `solution`)과 부모가 넣은 질문을 다 물으면** 마무리(09-30 확정 · 치영 #36). 부모 질문은 꼬리질문 자리에 끼워지므로 뼈대보다 먼저 떨어질 수 있다 — 그때 끝내면 뼈대를 묻지도 않고 마스코트가 채우게 되어 네 칸 조건을 함께 건다. 템플릿만 골랐으면 결말 칸을 물은 뒤 끝난다. 부모 쪽 「그만하기」로 언제든 끝내고 책은 만든다. 템플릿도 질문도 없이는 시작하지 않는다(소파가 막는다) |

**일기 모드는 예외다** (09-30 확정 · 진웅 #29) — 일기는 **있었던 일의 기록**이라 비어 있는 것이 사실이다. 사다리대로 채우면 아이가 안 간 곳 · 안 한 일을 마스코트가 「오늘 있었던 일」로 적게 된다.
- 사다리는 **쉬운 질문 1회까지만.** 카드 · 마스코트 채움 없이 칸을 비워 두고, 책은 「그 뒤에 어떻게 되었는지는 아직 듣지 못했어요」로 비었다고 쓴다. 그래서 그림일기의 모든 문장이 `by: child` 다(규칙 5)
- 필수 두 칸(`place` · `problem`)이 차면 `story_ready`. **다 그린 뒤에는 빈 칸을 칸마다 두 번(한 번 + 쉬운 질문)까지 묻고, 못 채운 칸은 비운 채 모인 것으로 책을 만든다** — 전체 질문 수 상한은 없다(10-02 #89 · 전에는 「물음 3개」라 결말이 빠졌다). 아이가 계속 말하는 것은 막지 않는다
- 그림도 말도 없는 날은 책 없이 조용히 끝난다
- 정본: `docs/일기모드_흐름.html` D3 · `demo/PictureDiary.kt`

방향(측정 전 · 미구현, 일기): 오래 이어질 때 마스코트는 **Jev 가 고른 미리 구운 리액션**으로 답한다 — 아이 말은 계속 받고 주고받기 횟수에 센다. 호출 상한 숫자는 #30 에서 단가를 잰 뒤 정한다

#### 세션당 호출 상한 (#30 · 10-02)

폭주(버그 · 반복 요청)를 막는 장치다. 턴 상한(규칙 3)이 아니다 — 상한을 넘어도 아이 말은 계속 받고(`by: child`, 주고받기 횟수에 센다) 마스코트만 미리 구운 리액션으로 답한다.

## 1-2. 판정 응답 16필드

`backend/app/schemas/judge.py`가 구현이고, 프롬프트 전문은 `guidelines/7_프롬프트.md` §2다.

```
reason              문자열   ← 반드시 첫 필드
slot_1 / value_1    채운 칸과 값
slot_2 / value_2    함께 채운 칸 (한 턴에 최대 2개)
contradiction       참/거짓
contradiction_with  어긋난 칸
s1_reason           까닭을 스스로 말했는가
s2_addition         묻지 않은 것을 덧붙였는가
emotion             마음을 가리키는 말
unclear / unclear_of  확인 카드 3장을 띄울지
next_slot           다음에 물을 칸
next_reason         왜 그걸 묻는지
no_longer_needed    필요 없어진 칸
story_ready         이야기 재료가 다 찼는가
```

**설계 규칙 셋** — 바꾸면 정확도가 떨어진다. 근거는 노션 「기능별 모델선정」 §2-2.

| | |
|---|---|
| **`reason`이 첫 필드** | 판정 앞에 근거를 쓰게 하면 **15~24점 회복** |
| **1단 평면. 중첩 금지** | 깊어지면 *"값은 맞는데 필드가 틀리는"* 실패가 지배적이 된다 |
| **규칙을 스키마 `description`에 쓰지 않는다** | 시스템 프롬프트에 둔다. description에 넣으면 **11~13%p 낮다** |

**벤더 공통분모만 쓴다.** Anthropic 제약 디코딩은 `minimum`·`maxLength`·재귀·외부 `$ref`를 지원하지 않고, OpenAI strict는 모든 필드가 `required`여야 한다. **옵셔널 대신 `["string","null"]`.**

## 1-4. 출처 `by` 3종 — **끝까지 구분한다**

**아이가 한 말과 우리가 채운 말이 섞이면 부모 리포트가 거짓말을 시작한다.**

| | `child` (말로) | `card` (골라서) | `mascot` (대신 정해 줌) |
|---|---|---|---|
| **책 자막** | ✅ | ✅ | ✅ 이야기의 일부다 |
| **주고받기 횟수** | ✅ | ✅ 아이가 골랐다 | ❌ |
| **수준 신호 (S1·S2)** | ✅ | ❌ | ❌ |
| **리포트 원문 인용** | ✅ | ❌ | ❌ |
| **「말한 방식」 원그래프** | 말로 | 골라서 | **표시하지 않는다** |
| 이름 필터 | ✅ | 불필요 | 불필요 |
| 금칙어·안전 필터 | ✅ | 불필요 | ✅ LLM이 만든 말이면 |

> **`mascot`을 원그래프에 안 넣는 이유**: *"마스코트가 대신함 30%"*가 뜨면 **부모가 아이의 실패로 읽는다.** 그건 우리 필터 설계가 만든 숫자이지 아이의 행동이 아니다.

## 1-5. 수준 3단계 — **규칙이 계산한다. LLM은 신호만 표시한다**

| 단계 | 할 수 있는 것 | 증거 | 질문 결 |
|---|---|---|---|
| 고르며 짓기 | 고른다 | (신호 없음) | 무엇 · 누구 · 어디 |
| 이어 짓기 | **잇는다** | **S2** | 그래서 · 그다음 |
| 까닭 짓기 | **까닭을 댄다** | **S1** | 왜 · 어떻게 |

**올림** — 신호가 가리키는 단계가 지금보다 높고 **2턴 연속**이면 **한 칸.** 두 칸은 안 뛴다(못 답하면 실패 경험이 된다).
**내림** — 무응답·카드 2턴 연속, **또는 `mascot_pick` 1회.**
**유지** — 그 밖에 전부. 신호 없는 평범한 답은 **지금 단계가 맞다는 뜻**이다.

**첫 두 턴은 프로브다.** `place`(어디)·`problem`(왜)를 고정으로 던지고 2턴 답으로 초기 수준을 정한다. **나이를 묻지 않는다** — 만 3~7세는 개인차가 커서 나이가 능력을 예측하지 못하고, *"꼬리표를 저장하지 않는다"*는 원칙과도 어긋난다.

**미션 난이도는 수준과 분리한다.** 말하기와 손 쓰기는 다른 능력이고, **미션 실패가 리포트에 "말하기가 줄었다"로 잘못 읽히면 안 된다.**

**매 세션 다시 판단한다. 아이에게 단계를 저장하지 않는다.**

## 1-6. 부모에게 보이는 것 — **등급 이름은 안 쓴다**

앱은 안에서 3단계를 계산하지만 **그 이름은 부모 화면에 안 나온다.** 대신 **그 단계를 판단한 근거**를 보여준다.

| 안 씀 | 대신 |
|---|---|
| "까닭 짓기 단계" | **"까닭을 말한 것 4번"** + 원문 인용 |
| "향상됐습니다" | "지난번보다 3번 더" |
| 또래·평균·백분위 | (기본 화면에 안 씀) |

금지어 목록은 `guidelines/8_금칙어.md` §3. **LLM이 만든 문장에 하나라도 있으면 그 답을 버리고 미리 만든 문장을 쓴다.**
