## 3-0. 공통

**오류는 전부 이 모양이다.**
```json
{ "error": true, "message": "사람이 읽을 수 있는 한 줄" }
```

| 코드 | 언제 |
|---|---|
| 400 | 요청 모양이 틀림 |
| 422 | 값이 스펙을 벗어남 (슬롯 이름이 목록 밖 등) |
| 502 | LLM·STT 사업자가 실패 |
| 500 | 그 밖 |

**앱은 오류에서 멈추지 않는다.** 판정이 실패하면 마스코트가 *"음, 한 번 더 말해 줄래?"*로 넘어가고, 두 번 실패하면 확인 카드 3장을 띄운다.

**시간 — 서버가 언제나 앱보다 먼저 답한다** (10-01). 앱이 먼저 포기하면 서버는 쓸모없는 호출을 끝까지 하고 돈을 쓴다. 그래서 서버 상한을 앱 기다림보다 짧게 둔다.

| 경로 | 서버 상한 (`backend/app/config.py`) | 앱 기다림 (`net/Server.kt`) | 실측 | 넘으면 |
|---|---|---|---|---|
| `/turn` | 25초 — 판정 18초, 대사는 남은 시간(3초 안 남으면 판정만) | 30초 | 3~6초 | 판정만 오면 앱이 기본 질문으로 · 둘 다 실패면 502 |
| `/story` | 55초 (`effort: high`) | 60초 (일기는 앱 쪽 상수 — 진웅) | 7.5~12.7초 · **10-01 한 번 30초 넘음** | 502 → 앱 틀 문장 |
| `/image` | 13초 전체 (작업 취소) · **다시 그리기 45초**(10-02 #32) | 16초 · 다시 그리기 50초 | 4~9초 | `preset: true` |
| `/tts` | 15초 | 20초 | 약 1초 | 502 → 앱이 소리 없이 넘어감 |
| `/stt` | 상한 없음 (GPU 하나씩 줄 섬) | 30초 | 1~3초 | — |
| `/report` | 상한 없음 (저장만 · §3-6) | 10초 | — | 실패 → 앱이 메일로 |
| 연결 | — | 6초 (공개 https · Cloudflare 경유) | — | — |

- LLM 호출마다 **전체 시간** 상한이다(`complete(timeout_s=…)`). httpx 의 `timeout` 은 단계마다라서 전체가 그보다 길어질 수 있었다
- 공개 주소 앞 Cloudflare 는 100초에 끊는다 — 위 값은 모두 그 안쪽

## 3-2. `POST /judge` — 한 턴에 한 번 (세션당 약 16회)

**슬롯 하나가 아니라 전체를 준다.** LLM이 어느 칸이 채워졌는지, 다음에 뭘 물을지, 이야기가 다 찼는지를 정한다. 프롬프트 전문은 `7_프롬프트.md` §2.

**요청**
```json
{ "mode": "story",
  "slots": { "place": "공룡나라", "problem": null, "reaction": null,
             "cause": null, "newcomer": null, "name": null,
             "companion": null, "sound": null, "adult": null,
             "solution": null, "title": null, "extra": null },
  "asked_slot": "problem",
  "template": "C",
  "level": "이어 짓기",
  "turn": 5,
  "question": "어? 로켓이 흔들려. 왜 그럴까?",
  "utterance": "{친구1}이 장난쳐서 흔들었어" }
```

| 필드 | 주의 |
|---|---|
| `mode` | `story` · `diary` · `coop` (앱 `StoryMode` 이름의 소문자). 생략하면 `story`. **슬롯 이름은 모드와 상관없이 같은 12개**다 — 모드는 같은 칸의 뜻을 바꿀 뿐이다(예: 일기의 `solution` 은 「어떻게 됐나」, 늘 「어떻게 풀었나」가 아니다). 모드별 판정·자막 차이는 `7_프롬프트.md` 에서 이 값으로 가른다 (09-26 추가) |
| `slots` | **12개 전부** 보낸다. 빈 칸은 `null` |
| `asked_slot` | **맥락용.** 답이 이 칸만 채운다고 가정하지 않는다 |
| `template` | 어떤 장면이 남았는지 판단하는 기준. 3턴째 전이면 `null` |
| `turn` | **참고값. 상한이 아니다** |
| `utterance` | **이름이 이미 가려진 문장.** 실명이 들어오면 안 된다 · ⚠️ 10-02 규칙 6 개정 뒤로 앱은 이름을 가리지 않는다 — 호칭 · 친구 이름이 그대로 온다 |
| `partner` | (선택 · 10-07 #303) 지금 아이 옆에서 같이 하는 사람 — `adult` · `peer` · `none`(혼자거나 못 알아들음). `none` 이면 서버가 `adult` 칸을 묻지도 채우지도 않는다(아래 강제 4). 앱은 동화에서 「누구랑?」 답으로, 같이 만들기는 늘 `adult`, 그림일기는 보내지 않는다. 생략하면 예전과 같다 |
| `names` | (선택 · 10-06) 이 세션의 이름들 — `[주인공 호칭, 친구1, 친구2, …]` 순서. 서버는 **Jev(TypeSafe)로 보낼 때만** 이 이름을 `{주인공}` · `{친구n}` 으로 바꿔 보낸다(판정에 이름은 필요 없다). 루나 · 목소리에는 그대로. 돌아온 `value_1` 의 자리표시자는 앱 `NameMask.unmask` 가 되돌린다. 비우면 가리지 않는다 |

**응답** — 16필드, 1단 평면. 필드 정의는 `2_공통_데이터_모델.md` §2.
```json
{ "reason": "왜 그랬는지를 스스로 말했다",
  "slot_1": "problem", "value_1": "{친구1}이 로켓을 흔들었다",
  "slot_2": null, "value_2": null,
  "contradiction": false, "contradiction_with": null,
  "s1_reason": true, "s2_addition": false, "emotion": null,
  "unclear": false, "unclear_of": null,
  "next_slot": "reaction", "next_reason": "무슨 일이 생겼는지 나왔으니 결과를 묻는다",
  "no_longer_needed": null, "story_ready": false }
```

**백엔드가 강제하는 것 셋** (그 밖은 LLM 판단을 따른다)
1. 슬롯 이름이 목록 12개 밖이면 **`null`로 버린다**
2. **이미 값이 있는 칸을 `next_slot`으로 주면 버린다** — `unclear` 확인은 예외
3. 금칙어에 걸린 발화는 **LLM을 부르지 않고** 되돌린다
4. **`partner: "none"` 이면 `adult` 칸을 쓰지 않는다** (10-07 #303) — `next_slot` 이 `adult` 면 `place → problem → reaction → cause → solution` 중 첫 빈 칸으로 바꾸고(없으면 `null`), `slot_n` 이 `adult` 면 값을 `extra` 로 옮긴다. 비워 두기만 하면 앱이 매 턴 「조금 더 들려줄래?」를 되풀이했다

## 3-2-1. `POST /turn` — 판정 + 마스코트 대사, 한 번에 (09-29 추가)

`/judge` 요청에 **`ask`** 하나를 더 받는다. 서버가 판정을 먼저 돌리고, 그 결과로 마스코트 한 턴 세 조각(`7_프롬프트.md` §3)을 만든다. 프롬프트 파일은 `eval/line_prompt.md` · `eval/line_schema.json`.

```json
요청  { ...`/judge` 와 같음..., "ask": true }
응답  { "judge": { 16필드 } | null,
        "line": { "ack": "공룡 나라구나!", "expand": "공룡들이 사는 곳으로 가는구나.", "question": "거기서 무슨 일이 생길까?",
                  "options": ["아기 공룡을 만났어", "화산이 쿵쿵 울렸어", "커다란 알을 찾았어"] } | null }
```

| 필드 | 주의 |
|---|---|
| `ask` | 협업 모드에서 **부모가 적어 둔 질문이 있으면 `false`**. 마스코트는 받아주기 · 되돌려주기만 하고 `question` 은 `null` |
| `reason` | (10-03 · #53 C) **협업만.** 부모가 고른 이유 `"done"` · `"soon"` · `"dream"` — **질문 시제**를 정한다(지난 일 · 앞으로 할 일 · 상상). 없으면 `done`(있었던 일). 앱은 이야기를 골랐는데 이유가 없으면 `"dream"`, 이야기를 안 골랐으면 `null`. 다른 모드는 `null` |
| `template` (협업) | 동화의 틀 키 대신 **고른 이야기 글** — `"같이 만들기 · 직업 · 소방관 · 곧 체험해요(앞으로 할 일)"`. 이름은 가려서 보낸다. 시제는 이 글이 아니라 `reason` 이 정한다 |
| `ack` | 받아주기 — 아이 말을 되비춘다 |
| `expand` | 되돌려주기 — 모습 · 소리 · 마음을 얹는다. **아이가 안 한 사건은 얹지 않는다.** 없으면 `null` |
| `question` | 다음 칸을 묻는 열린 질문. `ask: false` 이거나 `story_ready` 면 **서버가 `null` 로 비운다** |
| `options` | (10-02 · #79) `question` 이 묻는 칸의 **짧은 답 후보 최대 3개**. 이야기 흐름에 가장 맞는 것이 첫 번째. 아이가 쉬운 질문에도 답하지 못하면 앱이 **카드로** 보이고(`by: card`), 그래도 안 고르면 **마스코트가 첫 번째를 고른다**(`by: mascot` — 규칙 5). 금칙어 · 모르는 자리표시자가 든 후보는 서버가 그 하나만 버린다. **`question` 이 `null` 이거나 `mode: diary` 면 `null`**(오늘 실제로 있었던 일은 대신 고르지 않는다 · `2` §1-1) |

**둘 중 하나는 없을 수 있다 — 앱은 빈 쪽을 대본으로 메운다.**
- 판정이 실패해도 대사는 온다(`judge: null` · 질문은 이야기를 잇는 쪽으로)
- 대사가 실패하거나 **금칙어 · 모르는 자리표시자**가 들어 있으면 대사를 버린다(`line: null`). 길이는 기록만 하고 버리지 않는다
- 금칙어에 걸린 발화는 판정이 `blocked_by_filter` 로 돌아오고, 대사 LLM 도 부르지 않는다(`line: null`)
- **둘 다 없을 때만 502**

지연: 약 **3.3초**(판정 2.1 + 대사 1.2 · 09-29 실측 6건, 첫 호출 제외). 리액션 두 마디(4.11초)로 덮인다. 대사 프롬프트는 **측정 전 초안**이다.

### 대화 수선 — `history` · `act` · `retract` (10-08 · #323 · 측정 중)

아이가 「그거 아니야」 · 「오또는?」 · 「뭐라고?」처럼 **답이 아닌 반응**을 하면 다음 칸으로 넘어가지 않고 그 반응을 받는다. 세 필드 모두 **선택**이다 — 앱이 `history` 를 보내지 않으면 지금과 똑같이 동작하고, 응답의 `act` 는 `null` · `retract` 는 `[]` 이다.

```json
요청  { ...위와 같음...,
        "history": [ { "turn": 1, "asked_slot": "companion",
                       "otto":  { "ack": "강아지랑 놀았구나!", "expand": null, "question": "누구랑 같이 갔어?" },
                       "child": { "text": "강아지랑", "by": "child" },
                       "fills": [ { "slot": "companion", "value": "강아지", "prev": null } ],
                       "act": null } ] }
응답  { "judge": {...}, "line": { ..., "act": "repair" }, "retract": ["companion"] }
```

| 필드 | 주의 |
|---|---|
| `history` | 지난 턴 목록(오래된 것부터 · 세션 전체). **앱이 쌓고 매 턴 다시 보낸다** — 서버는 턴 사이에 아무것도 저장하지 않고, 무엇을 쓸지는 서버가 고른다. 오또가 한 말은 `otto` 에만, 아이 말은 `child` 에만(`by`: `child` · `card` — 규칙 5). `fills[].slot` 은 12칸 목록 안(규칙 1), `prev` 는 그 값이 덮어쓴 이전 값 |
| `line.act` | 이번 대사가 아이 반응을 어떻게 받았나. `repair`(잘못 들은 칸을 되돌리고 다시 묻기) · `answer_back`(짧게 답하고 같은 질문) · `rephrase`(같은 칸을 쉬운 말로) · `aside`(받아 주고 같은 질문) · `continue`(「그래서?」) · `null`(평소 턴). 거부 · 「몰라」는 `act` 없이 각 모드의 기존 단계를 따른다 |
| `retract` | 아이가 틀렸다고 한 칸. **앱이 자기 `history` 에서 그 칸의 `prev` 로 되돌린다.** 판정이 같은 턴에 새 값을 주면 되돌린 뒤 채운다 |

설계와 성공 기준은 #323, 측정은 `eval/results.md`. 기준을 넘기 전에는 앱이 `history` 를 보내지 않는다.

## 3-2-2. `POST /partner` — 「누구랑?」 답 읽기 (10-07 · #303)

동화 시작의 「오늘은 누구랑 같이 이야기를 만들어?」 답 한 번. **Jev 선택 질문 하나**(약 0.2초)로 같이 하는 사람을 고른다. 앱의 낱말 목록(`demo/Model.kt` `partnerIn`)은 서버가 없거나 답이 비었을 때의 비상구로 남는다.

**요청** `{ "utterance": "혼자 안 할래, 엄마랑" }` — 1~200자

**응답** `{ "kind": "mom", "confidence": 0.93 }`

| 필드 | 주의 |
|---|---|
| `kind` | 앱 `PARTNERS` 키(`mom` · `dad` · `aunt` · `grandma` · `grandpa` · `uncle` · `teacher` · `sibling` · `friend`) · `solo` · `unknown`. **0.6 미만이면 `null`** — 앱은 낱말 목록으로 읽는다. `unknown` 이면 앱이 다시 묻는다 |
| 부르는 말 | 서버는 종류만 준다. 아이가 부른 말(「할미」 · 「민수」)은 앱이 낱말에서 그대로 가져간다 |

- 금칙어에 걸리면 Jev 를 부르지 않고 `{ "kind": null }` · `MOCK=1` 이면 `unknown` · Jev 실패는 **502**(앱은 `null` 로 받아 낱말 목록)
- 하루 상한에서 `/judge` 값(0.63원)으로 센다 — Jev 단가는 아직 재지 않았다
- 근거: 10-07 같은 51문항에서 낱말 목록(#300 병합본) 48/51 · Jev 153/153(3회) — 낱말 목록은 목록에 없는 호칭 · 이름(「아부지」 · 「하윤이랑 같이 왔어」)을 놓친다 (`eval/results.md`)

## 3-3. `POST /story` — 칸이 다 차면 (세션당 1~2회)

지연 예산이 넉넉하다. `effort`를 높게 준다.

**요청**
```json
{ "mode": "story", "slots": { "place": "공룡나라", "...": "..." },
  "template": "C", "level": "이어 짓기",
  "pages": [ {"kind": "DEPART"}, {"kind": "SHAKE"}, {"kind": "TALK"},
             {"kind": "RUB", "mission": "A6"}, {"kind": "TALK"},
             {"kind": "DRAG", "mission": "E1"}, {"kind": "TOGETHER"} ] }
```

**응답**
```json
{ "title": "공룡 나라의 불 끄기",
  "scenes": [
    { "index": 1, "kind": "DEPART", "caption": "{주인공}이 공룡 나라에 갔어요.",
      "keywords": "dinosaur land, paper cutout" } ] }
```

**`pages` — 책의 모양은 앱이 정한다 (09-29 · 최민우 지적)**
템플릿마다 6~8쪽이고 미션 쪽도 템플릿마다 다르다(E·F 4/5 · B·C 4/6 · D 5/6 · A·G 5/7). 서버가 고정 순서로 추측하면 미션이 엉뚱한 쪽에 간다. 그래서:
- 앱이 템플릿의 쪽 목록을 **차례대로** 보낸다. `kind` 는 앱 `PageKind` 이름(`COVER · DEPART · SHAKE · MEET · TALK · JOURNEY · FAIL · RUB · DRAG · TOGETHER`), `mission` 은 `docs/맞춤미션_설계.md` §4 번호 22개(`A1`~`E2` · 10-05에 `A7 · A8 · A9 · C3 · D4 · D5` 추가). **목록 밖이면 422**
- 위 예시는 `StoryBank.kt` 템플릿 C 의 `pages` 그대로다. **지금 앱에서 도는 미션은 `A6` 문지르기 · `E1` 건네주기 · `A3` 퍼즐(A · G 템플릿)뿐** — 다른 번호는 그 동작을 앱에 만든 뒤에 보낸다(09-29 최민우)
- **미션을 고르는 건 앱 규칙**(기획안 §4 틀 ↔ 해결 동사)이다. 서버는 그 쪽을 **미션 앞 상황**(「연기가 퍼져 뿌옇게 되었어요」)으로 끝내고 풀지 않는다
- **이야기 속 사건이 아닌 미션**(`A3` 퍼즐 · `B2` 순서 맞추기 · `D3` 박자)은 상황을 만들지 않는다 — 그 쪽은 평범한 장면으로 쓴다. 퍼즐을 「그림이 조각났어요」로 쓰면 없던 일이 책에 들어간다
- **미션 뒤 처리는 앱이 정한다.** 지금은 완료 문장을 자막에 붙이지 않고 위쪽 안내문으로 띄운다(`Scenes.kt`). 완료 뒤 자막을 어떻게 바꿔 책장에 저장할지는 앱(민우)이 구현한다. ⚠️ `A3` 에 「물건을 건넸다」 완료 문장을 재사용하지 않는다
- **쪽 수 제한은 API 의 일이 아니다.** 지금 템플릿이 6~8쪽인 것은 앱의 선택이다. 서버는 「응답이 요청 목록과 정확히 같은가」만 본다(상한 30 은 폭주 요청 방지용)
- 응답 쪽 수가 요청과 다르면 **서버가 책을 버린다**(502) → 앱은 템플릿 책. 응답의 `kind` 는 **요청에서 그대로 찍은 것**이다(모델 답이 아니다)
- `pages` 를 안 보내면 예전 모양이다(동화 6장면 · 일기·협업 3~6쪽)
- 실측(09-29, 템플릿 C 7쪽 · A 8쪽): 쪽 수 · 종류 모두 요청대로, 10~23초

## 3-3-1. `POST /image` — 세션 중 배경 (09-29 추가 · 규칙 8)

장소 칸이 차는 순간 **뒤에서** 부른다. 아이는 기다리지 않는다.

```json
요청  { "kind": "background", "place": "공룡나라", "mode": "story" }
응답  { "preset": false, "reason": "ok", "scene": "a dinosaur land with tall ferns ...", "png_base64": "iVBOR..." }
      { "preset": true,  "reason": "check: flagged: violence", "scene": "...", "png_base64": null }
```

**「그려졌고 검사를 통과했다」가 아니면 전부 `preset: true`(200)** — 앱은 자기 그림을 쓴다. 오류가 아니라 정상 결과다.

| 단계 | 프리셋으로 가는 때 |
|---|---|
| 1 금칙어 | `place` 가 걸리면 **서버 밖으로 안 나간다** |
| 2 장면 LLM | 영어 장면으로 바꾼다(사람 · 글자 · 무서움 없이). 장소가 아니거나(「몰라」) 그릴 수 없으면 |
| 3 ComfyUI | SDXL + Lightning 8스텝(09-21 확정). 꺼져 있거나 실패하면 |
| 4 **안전 검사** | 그린 그림을 OpenAI `omni-moderation` 으로 검사. **걸리거나, 답이 없거나, 키가 없으면** — 검사 없이 아이 화면에 보내지 않는다 |
| 기한 | **13초** — 앱의 15초 프리셋 선보다 먼저 답한다. 넘기면 ComfyUI 작업을 **취소**한다(뒤 요청이 밀리지 않게). 13초는 **줄 선 시간까지** 센다 |
| GPU 순서 (10-02 #32) | 아이가 기다리는 그림(배경 · 캐릭터)이 **줄 맨 앞**으로 간다. 다시 그리기는 한 번에 한 장씩 그 뒤에 서고 기한이 **45초** — 다음 붓 멈춤에 보여 주면 되므로 늦게라도 준다 |

- 서버를 켜면 **한 장을 미리 그려 모델을 올린다** — 차가운 첫 장이 48.9초였다(09-29)
- 실측(09-29, 모델이 올라간 뒤): 5곳 모두 그려지고 검사 통과 **7.8~9.3초** · 「무서운 동굴」은 밝은 동굴로 · 「몰라」는 1.1초에 프리셋
- 앱 8초 「조금 뒤에 올 거야」는 앱의 몫이다
**캐릭터 (`kind: character` · 09-29)** — 아이가 말한 등장인물을 **뼈대를 붙일 수 있는 자세로** 그려 오려 준다(`docs/캐릭터_생성_규격.md`).

```json
요청  { "kind": "character", "description": "빨간 드레스 입은 공주", "mode": "story" }
응답  { "preset": false, "reason": "ok", "scene": "little princess in a red dress ...", "rig": "human", "png_base64": "iVBOR..." }
```
- `description` 은 **이름을 가린** 글자. `rig` 는 뼈대 종류 — `human`(두 발) · `quad`(네 발) · `blob`(다리 없음 · 둥근 것)
- 그림은 **640×640 · 배경 투명 · 발이 세로 93% 선**(앱 `FEET_IN_ART`) · 몸 폭 75% 이하 — 치영 규격 그대로
- 만드는 법: 장면 LLM(`eval/character_prompt.md`)이 영어 묘사 + `rig` → **회색 마네킹 틀에서 img2img**(자세 고정 · 사람형 0.85 · 네발형 0.8 · 덩어리형 0.9) → 치영의 오려 내기(테두리에 이어진 배경만 지움 · 구멍 메움) → 규격에 맞춤 → **안전 검사**
- 실패는 배경과 같이 **전부 `preset: true`** — 오려 낼 게 없으면(`cutout: …`)도 프리셋
- 실측(09-29, 모델이 올라간 뒤): 로봇 · 공룡 · 문어 · 괴물 모두 깔끔 · **6.6~8.2초**. 서버를 막 켠 직후는 준비 그림과 겹쳐 13초에 걸릴 수 있다 → 프리셋. 한 종류 두세 장만 봤다 — 믿기 전에 더 뽑아 본다
- 앱: `Server.character(description, mode)` → `Character(png, rig)` 또는 null

**오또가 대신 그려 주기 (`kind: redraw` · 09-30 · 이슈 #32)** — 일기 화이트보드에서 아이가 **고른** 조각 하나를 오또 그림으로 다시 그린다.

```json
요청  { "kind": "redraw", "description": "우리 집", "png_base64": "iVBOR...", "mode": "diary" }
응답  { "preset": false, "reason": "ok", "scene": "small red house with a blue roof", "rig": null, "png_base64": "iVBOR..." }
      { "preset": true,  "reason": "check: flagged", "png_base64": null }
```
- 보내는 것: 조각 한 장(**배경 투명 · 그린 부분만** · base64 400만 자 이하) + 조각 이름(**이름을 가린** 글자)
- 받는 것: **640×640 · 배경 투명 · 가운데** 놓인 그림. 뼈대(`rig`)는 없다 — 책에서 조각은 움직임 효과만 받는다
- 만드는 법: 조각 이름 → 캐릭터와 같은 주문 LLM(글자만 · 그림은 안 보냄) → 흰 종이 위에 올린 조각에서 **img2img(세기 0.9)** → 오려 내기 → **안전 검사(만든 그림만)**
- **아이 원본을 지키는 법** (`guidelines/1` §1-5): ComfyUI 기본 입출력(`/upload/image` · `SaveImage`)은 **PC2 디스크에 파일을 남긴다** → 그림을 요청 안에 실어 보내고 결과도 메모리로 받는 노드 둘(`backend/comfy_nodes/otto_memory.py`)을 쓰고, 받자마자 ComfyUI 기록을 지운다. 로그 · 오류 메시지에도 그림을 찍지 않는다. **이 노드가 없는 ComfyUI 면 프리셋**(원본은 그때도 디스크에 안 남는다)
- 실패는 전부 `preset: true` — 앱은 **아이 원본을 그대로** 쓴다
- **`role`** (10-06 · #168 · 선택) — `"background"` 면 일기의 **배경 조각**(땅 · 하늘 · 바다처럼 판을 가로지르는 선 · 앱 `PieceRole.BACKGROUND`). 앱은 조각을 잘라 보내지 않고 **판 전체**(선이 그려진 자리 그대로 · 배경 투명)를 보낸다. 서버는 판 비율 그대로 높이 768 로 놓고, 선이 나타내는 띠를 옅게 칠한 뒤(위쪽 1/3 의 선은 위로 · 나머지는 아래로) 색연필 풍경으로 **세기 0.9** 에 그리고 **오려 내지 않는다** — 받는 것은 판 비율의 장면 그림(예: 1232×768). 아이 그림을 받는 길(우리 서버까지만 · 만든 그림만 검사 · 쓰고 지움)은 같다. 없으면(`null` · `"object"`) 위의 조각 그대로. 실측 `eval/results.md` 「10-06 — 일기 배경 조각 다시 그리기」
- 실측(09-30, 조장 PC · 모델이 올라간 뒤): **3.8~4.9초**. 세기 0.6~0.8 은 선 그림이 **그대로 돌아온다**, 0.9 부터 오또 그림이 되지만 **씨앗(seed)에 따라 선 그림으로 남기도 한다** — 스크립트로 그린 조각 3개 × 6장뿐, **진짜 아이 그림으로 다시 재야 한다**(`eval/results.md` 09-30)
- 앱: `Server.redraw(png, description, mode)` → `ByteArray?` (null = 원본 유지)

## 3-4. `POST /stt` — 말소리 구간만

`multipart/form-data`, 필드 `file`. **폰이 VAD로 자른 구간만 보낸다.**
마이크를 15분 흘려보내면 240~300원, 실발화 2분만 보내면 32~40원 — **7배 차이**다.

**응답**
```json
{ "text": "공뇽나라 갈래", "unsure": false }
```

`unsure` (10-06 · #149) — 받아쓴 글자는 있지만 모델이 자신 없어 했다(구간 `avg_logprob` 가 `STT_UNSURE_BELOW` 기본 -0.8 아래). 폰은 **질문 하나에 한 번만** 「한 번 더 말해 줄래?」로 되묻고, 두 번째는 그대로 받는다. 글자가 비었으면 늘 `false`. 근거 `eval/results.md` 10-06 #149

⚠️ **전사 직후 음성 파일을 삭제한다.** 디스크에 남기지 않는다.
⚠️ **여기서 나온 글자에는 아직 실명이 들어 있다.** 이름 가리기는 **폰에서** 한다.
헛문장(「감사합니다」·「다음 영상에서 만나요」 등)으로 판정되면 `{ "text": "" }` — 폰은 **무응답**으로 다룬다.

## 3-4-1. `POST /tts` — 마스코트 목소리 (09-28 추가)

**마스코트 대사만** 여기로 온다. 아이가 녹음한 소리는 폰 밖으로 안 나간다(차별점 1). 고정 대사는 목소리마다 미리 구워 번들에 넣고, 이 경로는 **가변 대사**(되받기 · 판정이 정한 다음 질문)용이다.
TypeCast 키는 **서버에만** 있다.

**요청**
```json
{ "text": "놀이터 갔구나! 거기서 뭐 했어?",
  "voice_id": null,
  "previous_text": null, "next_text": null }
```

| 필드 | 주의 |
|---|---|
| `text` | 1~300자. **아이 실명이 들어가면 안 된다** — 외부 업체로 나간다 (`0928_멘토링_준비.md` §4-1) |
| `voice_id` | 페르소나 목소리. `null` 이면 서버 기본값(09-28 팀 점수 1위 Ruri · 문맥 따라) |
| `previous_text` · `next_text` | 앞뒤 대사 — 감정을 문맥으로 고르는(`smart`) 데 쓴다. 없어도 된다 |
| `provider` | (선택 · 10-06) `"typecast"` = 보호자가 **타입캐스트 목소리 선택 동의**(제3자 제공)를 했다. 서버는 `TYPECAST_OPT_IN=true` 일 때만 이 집을 타입캐스트로 읽고, **동의 없는 요청은 `TTS_PROVIDER` 가 무엇이든 타입캐스트로 보내지 않는다.** `null` = 기본 목소리 |

**응답** — `audio/mpeg` 바이트 (가짜 응답 모드는 0.3초 무음 `audio/wav`).

## 3-4-2. 서버 띄우기 · 가짜 응답 모드 (09-28)

## 3-5. 책장 · 체크포인트 (2026-09-18 멘토 지시로 범위에 들어옴)

> 이전에 "1차 범위 밖"으로 적어 뒀던 것을 정정한다. 멘토가 **구조까지 지시**했다 —
> *"앱을 설치하면 앱에 대한 식별키가 나옴. 기기 아이디랑 책장에 연결되는 아이디키랑, 체크포인트 같은 걸 api로 만들어라."*
> *"피처 완성에 먼저 집중"*은 **순서**였지 취소가 아니었다.

**왜 필요한가 — 쓰임이 둘이다**

| 쓰임 | 없으면 |
|---|---|
| **중간 보관** | **세션 도중 앱이 꺼지면 이야기가 통째로 날아간다.** 다섯 살이 15분 쌓은 것이 사라진다 |
| **책장 보관** | 만든 책이 안 남는다. **책장은 제품의 절반이다** — 추억이 쌓이는 곳 |

**책장은 모드별로 따로, 한 책장에 12권** (09-30 조장 결정 · #37). 동화 `StoryBookStore` · 일기 `DiaryBookStore` · 협업은 각자 저장소.
**책장이 꽉 차면 이야기를 시작하기 전에 알린다** (10-02 조장 결정 · #80, 09-30 「13권째를 꽂을 때 뺄 책 고르기」를 대체). 다 만든 책 앞에서 고르게 하면 아이가 방금 만든 책을 두고 고민하게 된다.

1. 아이가 방에서 모드를 고르는 순간 **그 모드 책장이 12권이면 들어가지 않고 알림** — 예: 「책장이 꽉 찼어! 엄마·아빠랑 책장을 정리해 볼까?」
2. 버튼 둘 — **[부모 모드로]** → PIN → 부모 모드의 **그 모드 책장 정리**로 바로 · **[닫기]** → 방으로(그 모드로 들어가지 않는다)
3. 아이 화면에 결제 · 업그레이드 안내를 띄우지 않는다. 늘리는 안내가 필요하면 부모 모드 책장 화면에 붙인다
4. **책 빼기는 부모 모드 안에서만** — 아이 말과 그림이 같이 사라지는 일이다. 가장 오래된 책을 몰래 지우지 않는다. 책을 지우면 그 책의 소리(`ChildSound.deleteBook`)와 아무 책도 안 쓰는 그림도 같이 지운다
5. 세 저장소는 「몇 권 · 목록 · 한 권 빼기」를 **같은 모양**으로 내준다 — 목록 한 줄은 `id · title · madeAt · pages · mode`(#70). 권수를 안전하게 셀 수 없으면 `null` 이며 0권으로 보지 않는다

검사: 그 모드 12권 → 모드를 고르면 알림 · [닫기] 면 방 · [부모 모드로] → PIN → 그 모드 책장 정리 · 한 권 빼면 다시 들어갈 수 있다 · 다른 모드는 영향 없음.

**로그인 없이 시작한다.** 기기 식별키로 먼저 돌리고, **구글 로그인은 나중에 얹는다**(멘토: *"구글로그인 붙여보기"*).
아동 앱이라 이 순서가 맞다 — **계정을 만들게 하면 만 14세 미만 동의 절차가 첫 화면에 온다.**

### `POST /device/register`

앱 첫 실행 때 한 번. **개인정보를 받지 않는다.**

```json
요청  { "install_id": "<앱이 만든 UUID>" }
응답  { "device_key": "dk_...", "shelf_id": "sh_..." }
```

### `GET /shelf/{shelf_id}` · `POST /shelf/{shelf_id}/book`

```json
{ "books": [ { "book_id": "bk_...", "title": "공룡나라 친구",
               "made_at": "2026-09-18T19:02:00+09:00", "pages": 6 } ] }
```

### `PUT /session/{session_id}/checkpoint` — **중간에 꺼질까 방지**

턴이 끝날 때마다 덮어쓴다. **작게, 자주.**

```json
{ "shelf_id": "sh_...", "slots": { "place": "공룡나라", "...": null },
  "template": "C", "level": "이어 짓기", "turn": 5 }
```

### `GET /session/{session_id}/checkpoint` — 복구

앱을 다시 켰을 때 **"이어서 할래?"**를 띄울 재료.

### 지켜야 할 것

| | |
|---|---|
| **실명·음성·그림은 서버에 안 보낸다** | 체크포인트에도 **이름이 가려진 값**만 넣는다 |
| **기기 식별키는 개인정보가 아니게 만든다** | 광고 ID·IMEI·전화번호를 쓰지 않는다 (Play Families 정책) |
| **로그인은 나중** | 붙일 때도 **책장을 옮기는 것**이지 처음부터 요구하지 않는다 |

### 아직 없는 것

| 무엇 | 언제 |
|---|---|
| 이미지 생성 | **런타임에 없다.** 전부 사전 제작 |
| TTS | **런타임에 없다.** 고정 대사는 번들. **가변 자막은 미정** — 폰 TTS가 9/19 측정에서 탈락했다 |

**엔드포인트를 새로 만들기 전에 조장에게 말한다.** 유일한 예외는 `main.py`에 자기 라우터의 `include_router` 한 줄을 더하는 것.

## 3-6. 문제 신고 (10-07 · #283 · 설계 `docs/문제신고_서버_설계_283.md`)

부모 모드의 「문제 신고」를 서버로 받는다. 구현 `backend/app/reports.py`. 서버에 닿지 못하면 앱은 지금처럼 메일로 보낸다(메일에는 첨부가 가지 않는다).

### `POST /report` — 공개 (앱이 부름 · 로그인 없음)

```json
{
  "category": "image",              // image | text | error | other
  "mode": "story",                  // story | diary | coop | null (설정에서 왔을 때)
  "page": 3,                        // 1~40 | null
  "note": "주인공 얼굴이 무서워요",   // 0~1000자
  "app_version": "0.5-closed",      // 1~32자
  "attachment": null                // 보호자가 체크했을 때만 아래 셋 중 하나
}
```

| 첨부 `kind` | 함께 오는 키 | 저장 |
|---|---|---|
| `image` | `source`(`background` · `hero` · `friend` · `diary_otto`) · `data_base64`(JPEG · PNG · WebP) | 서버가 다시 굽는다 — 긴 변 1024 · JPEG 85 · 메타데이터 없음 · 투명은 흰 바탕 |
| `preset` | `name`(영문 · 숫자 · `_` 64자) | JSON 안 |
| `text` | `text`(1~500자 · 아이 호칭 · 이름은 앱이 자리표시로 바꿔서) | JSON 안 |

- **모르는 키는 422** — 맨 위든 첨부 안이든(`audio` · `drawing` · `device_id` · `wav_base64` …). 저장 전에 튕긴다
- 첨부는 자기 종류의 키만 — `text` 첨부에 `name` 이 같이 오면 422

| 검사 | 값 | 넘으면 |
|---|---|---|
| 본문 전체 | 2.5MB | 413 |
| 첨부 그림(디코드 뒤) | 1.5MB | 413 |
| 그림 형식 · 크기 | JPEG · PNG · WebP 머리 · 가로세로 각 64~4096 | 422 |
| 주소당 (메모리만) | 10분에 5건 | 429 |
| 서버 하루 (메모리만) | 100건 | 503 |
| 저장 폴더 | 200MB | 503 |

응답 200: `{"id": "R-1007-3FA2", "keep_days_after_done": 30}` · `MOCK=1` 이면 저장하지 않고 `{"id": "R-0000-MOCK", …}`

앱 기다림 10초(앱 PR 에서) · 서버 상한 없음(저장만) · 실패 · 429 · 503 이면 앱은 메일 길로.

### 관리자 API — 앱은 부르지 않는다

모두 관리자 세션(`app/admin.py` 쿠키)이 있어야 한다. 없으면 401. 모니터 도메인의 nginx `location /admin/` 가 그대로 넘긴다.

| 메서드 · 경로 | 하는 일 |
|---|---|
| `GET /admin/reports?status=open\|done\|all` | 목록(기본 `open` = 접수 + 확인 중) · 새것부터 · `counts{open, done, all, stale}` · 행마다 `stale`(처리 전 14일 넘음) |
| `GET /admin/reports/{id}` | 상세 — 저장된 JSON 전부 + 완료면 `delete_at` |
| `GET /admin/reports/{id}/attachment` | 첨부 그림 `image/jpeg` · `Cache-Control: no-store` · `nosniff` |
| `POST /admin/reports/{id}/status` `{"status": …}` | `received` · `reviewing` · `done` — `done` 이면 `done_at` 기록, `done` 에서 나오면 지움 |
| `DELETE /admin/reports/{id}` | 바로 지우기 — 보호자가 접수 번호로 요청할 때 |

`id` 는 `R-MMDD-XXXX`(받은 날 KST · 16진 4자리). 모양이 다르면 422 · 없으면 404.

### 지켜야 할 것

| | |
|---|---|
| **아이 원본은 어떤 경로로도 안 실린다** | 아이가 그린 그림 · 녹음한 소리 · 목소리 · 화면 캡처. 첨부는 그 쪽의 **AI 가 만든** 그림 하나 또는 문장 하나 |
| **보낸 사람을 쓰지 않는다** | IP · User-Agent · 쿠키 · 헤더는 저장 JSON 에 없다. 남용 막기는 메모리만 |
| **30일** | 처리 완료 후 30일이 지나면 JSON 과 첨부를 지운다(서버 시작 때 · 하루 한 번 · 관리자 목록 열 때). 처리 전 신고는 지우지 않는다 |
| **저장 위치** | `REPORT_DIR` — PC1 은 `/state/reports`(호스트 `C:\otto\state\reports` · 배포해도 남음) |
