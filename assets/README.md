# assets — 미리 만든 그림

**데모용으로 미리 만들어 둔 그림이다.** 앱이 이것을 겹쳐서 책을 만든다.

**언제·어디서 만들지는 09-21에 재서 정했다** (`eval/results.md`) — 배경은 **세션 중에 우리 GPU에서**
만들고 **한 장 3.74초**, 만지는 것들은 **미리 만들어 얹어 0초**다.
⚠️ **아직 안 정한 것은 「어느 모델이냐」다.** 지금까지 SDXL 하나만 재봤다.

- **부적절한 그림은 사람이 검수한다.** 자체 호스팅 모델에는 안전 필터가 없고,
  **세션 중에 만들기로 정했으므로 무엇이 대신 거를지가 실제 숙제가 됐다** (규칙 8)
- FLUX 비상업 라이선스도 **오프라인 제작 도구로는 허용**된다 (모델의 서비스 투입만 금지)

| | |
|---|---|
| `tools/render.py` | **ComfyUI HTTP API 호출.** 배경(가로)은 **8스텝 LoRA · cfg 1.0 · euler/sgm_uniform**, 인형·소품은 **28스텝 · cfg 6.5 · dpmpp_2m/karras**. **주석에 프롬프트 요령 7개**가 있다 |
| `tools/bench_lightning.py` | 스텝·세기를 바꿔가며 **시간과 화풍을 같이** 재는 도구. 회차마다 seed를 바꾼다 — 안 그러면 ComfyUI가 캐시를 돌려줘 0.25초가 찍힌다 |
| `tools/cutout.py` | **배경 제거** (BiRefNet 없이). 흰 배경 → 투명 PNG. ⚠️ **이미 자른 RGBA를 또 자르지 않게** 가드가 있다 |
| `tools/gen_*.py` | 에셋 일괄 생성 |

### ⚠️ 왜 배경만 8스텝인가

09-21 측정: 배경 한 장이 **19.07초 → 3.74초**로 5.1배 빨라지고 VRAM은 그대로다.
4스텝도 재봤는데 **종이 결이 물감처럼 뭉개지고 네거티브가 풀려서** 버렸다 —
되돌리는 손잡이는 **세기가 아니라 스텝 수**였다.

**인형·소품에는 켜지 않는다.** 여기 있는 것들이 28스텝으로 만들어져서, 섞으면 결이 달라 보인다.

### ⚠️ `cutout.py`의 성패는 생성 단계에서 갈린다

흰 배경이 안 나오면 **덩어리 100%**로 실패한다 — 기준이 *"배경은 채도가 낮고 **밝다**"*라
청록 배경 같은 건 아예 안 걸린다. **흰 배경을 프롬프트 맨 앞으로** 빼고 네거티브에
`teal/blue/colored/gradient background`를 넣어야 한다. 그래도 **2장 중 1장**이었다.
