# 기획 초안 — 사진 한 장이 브레인롯 캐릭터가 된다

> 부트캠프 주제가 아니라 **개인 사이드 프로젝트** 초안입니다. 혼자 만드는 것을 전제로 썼습니다.
> 작성 2026-09-13

---

## 0. 한 줄

**아무 물건이나 찍으면, 거기에 눈·입·팔다리가 붙어 살아 움직이는 캐릭터가 되고, 말도 안 되는 이름과 목소리를 얻는다.**

## 1. 왜 이게 되는가

이탈리안 브레인롯 밈이 성립하는 조건이 셋인데, 지금 전부 싸다.

| 조건 | 지금 상태 |
|---|---|
| 사물에서 형태를 잘라내기 | 세그멘테이션 모델이 실시간·온디바이스로 돎 |
| 사물 + 신체 부위를 자연스럽게 합성 | 이미지 편집 모델이 단일 이미지 인페인팅으로 처리 |
| 무의미하지만 그럴듯한 이름·내레이션 | LLM + TTS가 초당 단가 수준 |

**핵심은 완성도가 아니라 부조화다.** 어설프게 붙은 팔다리가 더 웃기기 때문에, 품질 바가 낮은 쪽이 오히려 유리한 드문 장르다.

## 2. 핵심 루프

```
물건 촬영  →  캐릭터 생성  →  이름·목소리 부여  →  짧은 영상  →  공유
                    ↑                                              │
                    └──────  친구가 만든 걸 보고 나도 만든다  ←──────┘
```

**한 번에 끝나면 안 된다.** 모은 캐릭터가 남고, 서로 만나고, 도감이 채워져야 다시 연다.

## 3. 생성 파이프라인

| 단계 | 하는 일 | 비고 |
|---|---|---|
| ① 피사체 분리 | 사진에서 주 물체를 잘라냄 | 배경 제거. 실패하면 전부 무너지므로 여기 품질이 제일 중요 |
| ② 부착점 추정 | 어디에 눈·입·팔·다리를 붙일지 | 물체의 장축·바닥면·대칭축을 찾아 규칙으로 배치. 학습 없이 기하로 상당 부분 가능 |
| ③ 합성 | 부위를 실제로 그려 넣음 | (a) 미리 만든 눈·팔 에셋을 얹기 ← **MVP는 이것** (b) 이미지 생성 모델로 인페인팅 |
| ④ 작명 | 이탈리아어풍 무의미 이름 | 음절 조합 규칙 + LLM. 물체 종류를 살짝 반영하면 훨씬 웃김 |
| ⑤ 목소리 | 과장된 내레이션 | TTS. 속도·피치를 과하게 |
| ⑥ 움직임 | 흔들·점프·걷기 | 뼈대 두 개짜리 간단 리깅이면 충분. 물리 시뮬 불필요 |
| ⑦ 영상 | 세로 짧은 클립 | 자막 + 내레이션 + BGM 자리 |

**③에서 (a)로 시작할 것.** 생성 모델로 바로 가면 매번 다른 그림체가 나와서 도감이 안 예뻐지고, 비용도 든다. 에셋 얹기는 결과가 일관되고 즉시 돌아간다.

## 4. 혼자 만드는 MVP — 주말 두 번 분량

목표: **찍으면 5초 안에 캐릭터가 나오고, 흔들리고, 이름이 붙는다.** 그 이상 아무것도 하지 않는다.

- 배경 제거 1종
- 눈·팔·다리 에셋 3세트 (동그란 눈 / 실눈 / 화난 눈 …)
- 부착점: 바운딩 박스 기준 규칙 배치만 (정교화는 나중)
- 이름: 음절 표 + 규칙 조합 (LLM도 아직 없이)
- 움직임: 상하 흔들 애니메이션 하나
- 저장: 로컬 도감

**여기까지 재미가 없으면 그 뒤를 만들어도 재미없다.** 판단 지점으로 둘 것.

## 5. 그다음에 붙일 것 (우선순위 순)

1. **도감** — 모은 캐릭터가 쌓이고 희귀도가 생김. 재방문 이유는 여기서 처음 생긴다
2. **목소리** — 웃김의 절반은 내레이션이다
3. **만남** — 캐릭터 둘을 붙이면 대화하거나 합체
4. **영상 내보내기** — 세로 클립. 공유가 곧 유통
5. **속성** — 재질·크기를 읽어 능력치를 주고 대전

## 6. 미리 정해 둘 것

**희귀도를 무엇으로 정하는가.** 아무거나 찍어도 다 나오면 모으는 재미가 없다. 후보 —
물체 종류의 드묾 / 사용자들 사이 등록 빈도(적게 등록된 물체일수록 희귀) / 조합의 우연성.
**등록 빈도 기반이 가장 자연스럽다.** 남들이 다 찍는 텀블러는 흔하고, 아무도 안 찍은 물건은 귀하다.

**같은 물건 재등록을 어떻게 볼 것인가.** 막으면 답답하고 열면 도감이 무의미해진다.
같은 물체라도 **다른 각도·다른 조명이면 다른 개체로** 치되, 거의 동일한 사진은 중복 처리.

## 7. 리스크

- **밈 수명** — 브레인롯 유행이 식으면 껍데기만 남는다. 그래서 **밈에 의존하지 않는 핵심 재미**(사물이 살아나는 것, 모으는 것)를 먼저 세워야 한다
- **저작권** — 상표·캐릭터 상품을 찍으면 그 형태가 그대로 들어간다. 공유 기능을 붙이는 순간 문제가 된다
- **남의 사진 도용** — 인터넷 이미지를 등록하는 것. 도감·희귀도를 붙이는 순간 발생한다
- **생성 비용** — ③을 생성 모델로 가면 장당 비용이 든다. MVP를 에셋 방식으로 하는 이유

## 8. 한 문장으로

**사물이 살아나는 것 자체가 재미이고, 밈 형식은 그 위에 입히는 옷이다.** 옷부터 만들면 유행과 함께 죽는다.

# 부록 — 다른 개인 아이디어

## 내 AI 키워서 겨루기

> 놀았더니 데이터셋이 만들어져 있는 구조. 브레인롯과 무관한 별개 아이디어입니다.

### 한 줄

**사용자가 몇 장을 라벨링하면 자기 모델이 생기고, 그 모델끼리 붙는다. 이기려면 더 좋은 데이터를 줘야 한다.**

### 왜 재밌는가

라벨링은 세상에서 가장 지루한 일인데, **"내 모델이 남의 모델한테 졌다"**는 순간 갑자기 하고 싶어진다.
ESP game(사람들이 놀면서 이미지 태그를 만든 구글의 실험)이 증명한 구조이고, 거기에
**모델 대전**이라는 즉각적 피드백이 붙으면 동기가 훨씬 세진다.

### 핵심 루프

```
라벨링 몇 장  →  내 모델 학습  →  대전  →  패배  →  "어디가 약한지" 리포트  →  그 부분만 라벨링
                                     ↑                                              │
                                     └──────────────────────────────────────────────┘
```

**패배 리포트가 이 구조의 심장이다.** 그냥 지면 그만두지만, *"당신 모델은 역광 사진에서 무너집니다"*를
보여주면 역광 사진을 찾아 라벨링하러 간다. 이게 능동학습(active learning)을 게임으로 바꾼 것.

### 구성 요소

| | 하는 일 | 어려운 지점 |
|---|---|---|
| 능동학습 | 다음에 뭘 라벨링해야 가장 효율적인지 고름 | 불확실성 샘플링. 이게 재미의 엔진 |
| 학습 파이프라인 | 몇십 장으로 쓸 만한 모델을 뽑음 | 소량 데이터 → 파인튜닝·few-shot |
| 대전·평가 | 두 모델을 공정하게 붙임 | 평가셋이 한쪽에 유리하면 안 됨 |
| 품질 관리 | 엉터리 라벨·어뷰징 걸러냄 | 일부러 틀린 라벨을 넣어 남을 방해하는 것 |
| 리더보드 | 랭킹·메타 분석 | 상위권이 고이면 신규가 안 들어옴 |

### 과제를 무엇으로 할 것인가 — 이게 제일 중요

너무 쉬우면 다 100점이라 대전이 성립하지 않고, 너무 어려우면 몇십 장으로 모델이 안 만들어진다.
**"사람은 쉽게 하는데 모델은 자주 틀리는" 것**이 정답이다. 후보 —

- 손으로 쓴 글씨의 감정·필체 주인 맞히기
- 사진이 **찍힌 계절** 맞히기
- 두 사진이 **같은 장소**인지 (각도·시간대가 다름)
- 밈 이미지의 **맥락** 맞히기

### 리스크

- **초기 사용자 수 문제.** 대전 상대가 없으면 게임이 아니다. 봇 모델을 여러 난이도로 미리 심어둘 것
- **라벨 어뷰징.** 리더보드가 걸리면 반드시 발생한다
- **계산 비용.** 사용자마다 모델을 학습시키면 돈이 든다. 임베딩 고정 + 마지막 층만 학습으로 시작할 것

### 한 문장으로

**지루한 일에 즉각적인 패배를 붙이면 게임이 된다.** 라벨링이 아니라 패배 리포트가 제품이다.
