## 항목별 상세

### 1. 단안 깊이 추정 — 문턱은 "상대 깊이 → 절대 거리(metric)"

**무엇이 언제 바뀌었나.** 2023년까지의 단안 깊이는 **상대값**이었다. "저기가 여기보다 멀다"는 알지만 "2.4m"는 모른다. 실측·치수·부피를 다루려면 이게 치명적이었다.

- **2024-01 Depth Anything V1**, **2024-06 V2** — 제로샷 일반화가 실용선을 넘음. V2 Small은 **24.8M 파라미터 / fp16 약 50MB**.
- **2024-10 Apple Depth Pro** — **카메라 메타데이터 없이** 절대 스케일. 초점거리를 모델 내부 서브네트워크가 추정. 2.25메가픽셀 깊이맵을 **표준 GPU에서 0.3초**. (ICLR 2025)
- **2024 UniDepth / 2025 UniDepthV2** — 테스트 시점 카메라 정보 없이 metric.
- **2025-11 Depth Anything 3 (ByteDance)** — DA3-metric이 ETH3D에서 **δ1 0.917 / AbsRel 0.104**, 2등 UniDepthV2(δ1 0.863)를 유의미하게 앞섬. SUN-RGBD AbsRel 0.105(1위), DIODE δ1 0.838(2위). 전부 **공개 학술 데이터만으로 학습**했다고 명시.

**라이선스 (원문 확인).** ByteDance-Seed/Depth-Anything-3 모델 표 기준:

| 모델 | 라이선스 |
|---|---|
| DA3-SMALL, DA3-BASE | **Apache-2.0** |
| DA3METRIC-LARGE, DA3MONO-LARGE | **Apache-2.0** |
| DA3-LARGE, DA3-GIANT, DA3NESTED-* | **CC-BY-NC-4.0** |

→ **절대거리용 METRIC-LARGE가 Apache-2.0이라는 게 핵심.** 우리가 쓸 조합은 라이선스가 깨끗하다. 다만 Depth Anything V2 쪽에는 "학습 데이터 라이선스 리스크" 이슈(#320)가 열려 있음 — **미확인**, 상업화 전 확인 필요.

**속도·환경.** DA3 리포지토리에 **FPS 수치 없음(확인)**. "DA3-LARGE가 VGGT와 비슷한 결과"라는 정확도 비교만 있음. 반면 **DA V2 Small은 2024-06 시점에 이미 브라우저 실시간**이 공개 데모로 존재(transformers.js + WebGPU, Xenova). 즉 정확도 최상위는 서버, 브라우저 실시간은 한 세대 아래 모델.

**6주 난이도: 하.** 사전학습 가중치를 그대로 추론만 한다. 학습 불필요.

**평가 데이터: 만들 수 있음.** 줄자로 잰 실측 길이 vs 모델 추정 길이. 팀 5명이 2주 안에 물체 200~300개 라벨 가능. **측정 숫자가 "cm 오차"로 딱 떨어짐** — 포트폴리오에 가장 좋은 형태.

### 2. 브라우저 실행 환경 — 지난 조사에서 후보를 죽였던 제약이 **부분적으로 풀렸다**

**caniuse 직접 확인:**
- **Safari on iOS 26.0 이상 = WebGPU 지원.** (26.0~26.6 모두 지원)
- Chrome for Android 152 지원.
- **전 세계 커버리지 87.35%.**

iOS 26 출시는 통상 2025년 9월 — **월 단위는 미확인**, 발표 전 애플 릴리스 노트로 확인할 것.

**중요한 구분 — WebGPU ≠ WebXR.**
지난 조사에서 후보 F1(가구 반입 시뮬레이터)이 죽은 이유는 **iOS 사파리의 WebXR 미지원**이었다. WebGPU가 열린 것이 WebXR을 여는 것은 **아니다**.

| | iOS 사파리 | 의미 |
|---|---|---|
| **WebGPU** | ✅ 26.0+ | 브라우저에서 **모델 추론·3D 렌더** 가능 |
| **WebXR** | ❌ 여전히 미지원(이전 조사) | 카메라 위에 **AR 오버레이** 불가 |

→ **"폰 카메라로 찍어서 브라우저에서 AI가 처리하고 3D로 보여준다"는 iOS에서 된다. "실공간에 겹쳐 보여준다"는 여전히 안 된다.** 이 선을 넘지 않는 기획이면 앱 없이 웹으로 갈 수 있다.

**스택.** transformers.js v3 + ONNX Runtime Web(WebGPU EP). 같은 ONNX 그래프를 변환 없이 WASM/WebGPU 양쪽에 태울 수 있음. WASM 대비 5~20배(2차).

**6주 난이도: 하.** 팀에 모바일 네이티브 경험자가 없다는 제약(Q8·Q11)을 **웹으로 우회**할 수 있다는 점이 크다.

### 3. 자세·동작 인식 — 2D는 옛날에 끝났고, **문턱은 "세계좌표 3D"와 "품질 평가"**

**2D 포즈는 문턱이 아니다.** MediaPipe Pose(33개 랜드마크, MobileNetV2 계열)는 2020~2023년 기술이고 이미 온디바이스 실시간이다. **발표에서 "이제야 가능"이라고 말하면 안 되는 항목.**

**진짜 2024~2026 문턱 두 가지:**

**(a) 단안 영상 → 세계좌표계 3D 인체 (2024)**
- **WHAM** (CVPR 2024) — 인체 메시 복원 + SLAM 카메라 추적 결합. 카메라가 움직여도 사람의 **월드 좌표** 궤적을 복원. **라이선스 MIT (리포지토리 직접 확인).** 단 리포지토리에 FPS·MPJPE 수치 없음(확인) — 논문 원문 확인 필요.
- **NLF** (NeurIPS 2024) — EMDB에서 **MPJPE 68.4mm**, 2등 98.0mm 대비 30% 개선. **속도 10 FPS**로 "대화형 속도보다 빠름" 수준. **모델은 비상업 연구 전용 — 지뢰.**

**(b) 동작 "품질" 평가 벤치마크가 2025년에 생김**
- **FLEX (2025)** — 피트니스 AQA 최초의 대규모 멀티모달·멀티뷰. 20종 웨이트 동작 × 38명(숙련도 다양) × 7,500+ 녹화, RGB + 3D 포즈 + **sEMG(근전도)** + 생체신호 동기화. 전문가 주석을 **Fitness Knowledge Graph**(동작–핵심단계–오류유형–피드백)로 구조화. **CC BY-NC-SA 4.0.**
- **FitAQA (2025)** — 맨몸 운동 30종, 2,219 영상 / 5,512 QA.
- AQA 종합 서베이 arXiv 2412.11149 (2024-12).

**한국어 데이터 (AI Hub) — 평가셋 제작 부담을 크게 줄임:**

| 데이터셋 | 규모 |
|---|---|
| 사람 인체/자세 3D 데이터 | 동작 **70종**, 3D 모델 50만 건 + 2D 이미지 200만 건. 용도에 **"홈트레이닝 자세 분석·추천" 명시** |
| 한국인 신체 3D 스캐닝 데이터 | 남 265 / 여 265, 신체 동작 20종, 360도 + 핸드헬드 촬영 |
| 실내 공간 3D 종합 데이터 | 공간·객체 인식용 |

**6주 난이도: 중~상.** 사전학습 모델 추론은 쉬우나, "좋은 자세/나쁜 자세"의 **정답 라벨을 팀이 만드는 것이 어렵다** — 전문가 판단이 필요한 영역. FLEX의 지식그래프 구조를 그대로 빌려 쓰면 가능성 있음. 단 CC BY-NC-SA라 **상업 전시는 불가, 학술 발표는 가능**.

### 4. 온디바이스 음성 — **영어는 넘었고, 한국어는 아직 절반**

**(a) 스트리밍 STT**
- **Moonshine** (2024-10) — CPU 우선 설계. **v2**(2026-02, arXiv 2602.12241)는 Ergodic Streaming Encoder로 지연 최적화. 245M 파라미터로 MacBook Pro **107ms**, Whisper Large V3(6배 큰 모델)보다 정확도 높다고 주장.
- **라이선스 — 이게 지뢰다 (공식 리포 직접 확인).** **영어 모델만 MIT.** 비영어 레거시 비스트리밍 모델은 **Moonshine Community License = 비상업**. 상업 이용은 별도 문의. **한국어 지원 여부 자체가 문서에 없음 — 미확인.**
- Parakeet(NVIDIA)는 GPU 필수·서버 전용. 온디바이스 후보 아님.

**(b) 한국어의 현실 (2차, 발표 전 재확인 권장)**
- Whisper large-v3: LibriSpeech-other(영어) **CER 3.91%** vs KsponSpeech eval-other(한국어) **CER 11.13%**. **한국어는 여전히 영어의 3배 어려움.**
- ENERZAi EZWhisper-small: **70MB**(기존 3GB 대비 40배 축소) 저비트 양자화로 온디바이스, 한국어 추가 학습 후 원본 초과 — **벤더 자기 발표**라 독립 검증 없음.
- **OpenKoASR** 한국어 ASR 공개 리더보드 존재(WER/CER/RTFx/지연) → **평가 기준을 새로 만들 필요 없음.** 이건 큰 장점.

**(c) 실시간 화자분리 — 2025년이 문턱**
- **Streaming Sortformer** (2025-07, arXiv 2507.18446) — 도착순 화자 캐시. 16kHz 모노 PCM을 480ms 단위로 증분 처리, 560ms 룩어헤드 확보 후 **500ms 푸시당 중앙값 12.4ms 지연**.
- **pyannote-audio — 코드 MIT(확인), 상업 이용 가능.** `community-1` 파이프라인 DER은 데이터셋별로 **8.9%(REPERE) ~ 46.8%(Ego4D)**. H100에서 1시간 오디오당 31초(RTF 약 0.0086). **편차가 매우 크다는 점이 중요** — 조용한 스튜디오와 실환경의 차이. 사전학습 가중치 사용 조건은 HF 모델 카드 별도 확인 필요(미확인).

**(d) 실시간 음성 변환**
- StreamVC(2024-01, Google) → **RT-VC**(ACL 2025 데모): **엔드투엔드 CPU 61.4ms**, StreamVC 대비 13.3% 빠름. StreamVoice는 124.3ms.
- 기존 조사(`검증_걸음걸이_음성필터`)의 Pixel 7 CPU 70.8ms와 일관됨.

**6주 난이도: 하~중.** 추론만 하면 하. 한국어 파인튜닝까지 가면 중.

### 5. 세분화·추적 — SAM 2가 영상을 열었고, SAM 3이 "말로 찾기"를 열었다

- **SAM 2** (2024-07, **Apache-2.0**) — 스트리밍 메모리 구조로 프레임 간 객체 상태 유지. 가림·이동·장면 변화를 넘어 추적. Tiny 38.9M **91 FPS**(A100), Large 224.4M **~30 FPS**. 네 크기 전부 Apache-2.0.
- **SAM 3** (2025-11-19) — **개념 프롬프트**. "shipping container"라고 쓰면 이미지·영상에서 해당 개념 전부를 검출·분할·추적. 코드·체크포인트·SA-Co 벤치마크 공개.
- **SAM 3 라이선스 = 메타 자체 라이선스.** 연구 + 상업 이용을 폭넓게 허용하되 군사·ITAR·핵·무기 관련 금지. **표준 퍼미시브 라이선스보다 제한적.** 제품 출시 전 원문 조항 확인 필수 — **세부 조항 미확인.**

**검출 쪽 라이선스 전환 (중요):**
- **Ultralytics YOLOv8 / YOLO11 / YOLO26 = AGPL-3.0.** 배포하는 제품에 넣으면 소스 공개 의무 또는 상용 라이선스 구매. **부트캠프 데모를 공개 배포하면 걸린다.**
- **RF-DETR** (2025-03, Roboflow, **Apache-2.0**) — **실시간 모델 최초 COCO 60 AP 돌파**, RF100-VL 도메인 전이 벤치마크 1위. 카피레프트 의무 없음.
→ **"실시간 검출 = YOLO"라는 습관이 2025년에 라이선스 이유로 깨졌다.** 이것 자체가 발표 소재가 된다.

### 7. 추가로 문턱을 넘은 것 — 피드포워드 3D 재구성 (조사 항목 밖, **가장 유망**)

지난 라운드에서 후보 F(3D 실측·기록)가 "기술은 마음에 드는데 주제가 아니다"로 남았다. **그 기술의 문턱이 2025년에 한 번 더 크게 이동했다.**

- **VGGT** (CVPR **2025 Best Paper Award**) — 사진 1장~수백 장에서 **카메라 파라미터·깊이맵·포인트맵·3D 트랙을 한 번에 피드포워드로** 추론. **1초 미만.** 기존의 "SfM 돌리고 번들 조정하고 최적화" 파이프라인 없이도 그것들을 능가.
- **라이선스 (리포 직접 확인)** — 코드는 **2025-07-29부터 상업 이용 가능 라이선스**로 변경. 그러나 **가중치는 둘로 갈림**: 기본 `VGGT-1B`는 **비상업 전용**, `VGGT-1B-Commercial`은 상업 허용이나 **신청 폼 제출 필요**(LLaMA식 자동 승인). ← **놓치면 죽는 지점.**
- **MapAnything** (3DV 2026) — 범용 피드포워드 **metric** 3D 재구성.
- **3DGS 웹화** — 2024년에 WebGL2/WebGPU 실시간 뷰어들이 나왔고, **2025-08 Khronos가 glTF에 `KHR_gaussian_splatting` 확장을 공식 추가**해 포맷이 표준화. 앱 설치 없이 URL로 3D 공유. Zillow가 SkyTours로 첫 대형 부동산 플랫폼 적용, Apartments.com(CoStar)이 Matterport 3D Exteriors로 대응.

**의미.** "폰으로 찍는다 → 서버가 1초 만에 3D로 만든다 → iOS 사파리 포함 브라우저에서 본다"가 **2025년에 전 구간이 처음으로 이어졌다.** LiDAR 불필요(단안 metric), 앱 불필요(WebGPU), 최적화 파이프라인 불필요(VGGT), 포맷 표준 존재(glTF 확장).

**6주 난이도: 중.** 추론 서버 1대 + 웹 뷰어. 학습 없음.

## 발표 문장 초안

각각 "X가 Y를 넘은 게 Z년이라서 이제 가능하다" 형태. **굵은 숫자는 확인/2차 표기를 지킬 것.**

1. **단안 metric 깊이** — "단안 카메라 깊이 추정이 **상대값에서 절대거리(metric)로** 넘어간 게 2024년이고, 2025년 Depth Anything 3가 ETH3D에서 δ1 0.917에 도달했습니다. **LiDAR도 카메라 정보도 없이 폰 사진 한 장에서 cm 단위를 말할 수 있게 된 게 이때부터**입니다."
2. **브라우저 실행** — "**iOS 사파리가 WebGPU를 지원하기 시작한 게 2025년 9월(Safari 26)이고, 지금 전 세계 브라우저의 87%가 됩니다.** 그 전까지 이런 서비스는 앱을 깔아야 했습니다. 이제 링크 하나로 됩니다."
3. **피드포워드 3D** — "사진 여러 장에서 3D 공간을 복원하는 데 최적화 파이프라인이 필요 없어진 게 2025년 VGGT(CVPR 베스트 페이퍼)입니다. **수십 분 걸리던 게 1초 미만**이 됐고, 그래서 이걸 **사용자가 기다릴 수 있는 시간 안에** 돌릴 수 있습니다."
4. **3D 웹 공유** — "가우시안 스플래팅이 **2025년 8월 glTF 표준에 정식 편입**되면서, 3D 공간을 뷰어 앱 없이 URL로 주고받을 수 있게 됐습니다."
5. **세계좌표 3D 인체** — "움직이는 카메라로 찍어도 사람의 3D 움직임을 **월드 좌표**로 복원할 수 있게 된 게 2024년(WHAM·NLF)이고, NLF는 EMDB 오차를 98mm에서 **68.4mm로** 줄였습니다."
6. **동작 품질 평가** — "**운동 자세의 '좋고 나쁨'에 정답이 붙은 공개 데이터셋이 처음 나온 게 2025년(FLEX)**입니다. 그전까지는 '무슨 동작인가'만 맞힐 수 있었고 '잘했는가'는 평가할 기준 자체가 없었습니다."
7. **온디바이스 STT** — "음성인식이 **서버 없이 폰 CPU에서 100ms대**로 도는 게 2024년 Moonshine부터입니다. 245M 파라미터로 6배 큰 모델의 정확도를 냅니다." *(단, 한국어는 별개 — 아래 지뢰 참조)*
8. **실시간 화자분리** — "**'지금 말하는 사람이 누구인가'를 실시간으로 가르는 게 2025년(Streaming Sortformer)**에 500ms당 12.4ms 지연까지 내려왔습니다. 녹음을 다 받고 나서야 나누던 게 대화 중에 됩니다."
9. **영상 객체 추적** — "이미지 분할 모델이 **영상으로 넘어간 게 2024년 SAM 2**, **말로 된 개념으로 찾을 수 있게 된 게 2025년 11월 SAM 3**입니다."
10. **검출 라이선스** — "실시간 객체 검출에서 **상업적으로 자유로운(Apache-2.0) 모델이 COCO 60 AP를 처음 넘은 게 2025년 3월 RF-DETR**입니다. 그전까지 이 성능대는 AGPL이라 서비스에 못 넣었습니다." ← **기술이 아니라 라이선스가 문턱이었던 사례로 쓰면 인상적**
11. **센서 자기지도** — "웨어러블 행동 인식이 **70만 person-day 무라벨 데이터로 사전학습해 다른 기기·다른 환경까지 일반화된 게 2024년**입니다. 그전 모델들은 실험실 밖을 못 나갔습니다."

**가장 센 조합 (추천):** 1 + 2 + 3 → **"LiDAR 없이(2024), 앱 없이(2025-09), 기다릴 수 있는 시간 안에(2025-06). 세 개가 다 2024~2025에 열렸고, 하나만 없었어도 이 서비스는 안 됩니다."**

## 이 문서가 주제 선정에 주는 결론

- **기술 축으로 가장 안전한 것**: 단안 metric 깊이(1) + 브라우저 WebGPU(2) + 피드포워드 3D(7). **라이선스가 Apache-2.0으로 정리 가능하고, 평가 지표가 "cm 오차"로 명확하며, 학습이 필요 없어 6주에 들어간다.**
- **기술은 멋있지만 6주에 위험한 것**: 동작 품질 평가(정답 라벨을 팀이 못 만듦, 데이터셋 NC), 3D 인체 메시(정확도 1등 모델이 비상업).
- **한국어 음성은 "문턱을 넘었다"고 발표하면 안 된다.** 영어는 넘었고 한국어 CER은 여전히 11%대. 다만 **OpenKoASR 리더보드가 있어 측정은 정직하게 할 수 있음** — Q7(측정 결과가 남는 설계)에 부합.
- **라이선스가 문턱이었던 사례(RF-DETR)**는 발표에서 "기술만이 문턱이 아니다"라는 한 문장으로 쓰면 차별화된다.
