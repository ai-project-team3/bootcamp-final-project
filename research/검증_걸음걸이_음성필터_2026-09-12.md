## 주제 1 — 얼굴 없이 체형·걸음걸이로 사람 구분

### 1-1. 기술 수준 (2024-2026)
- **확인** GaitRDAE 논문(arXiv 2510.16541, 2025-10) 비교표 Rank-1:
  | 방법 | Gait3D | GREW | OU-MVLP | CASIA-B |
  |---|---|---|---|---|
  | GaitBase | 66.3 | 60.1 | 90.8 | – |
  | DyGait | 66.3 | 71.4 | – | – |
  | GaitRDAE(제안) | 73.6 | 78.6 | 91.5 | 95.5 |
- **정리**: 통제 환경(CASIA-B·OU-MVLP)은 90%대 포화, 야외 실환경(Gait3D·GREW)은 60~78%대.
  즉 "카메라 각도·옷·가방이 바뀌는 실제 집안"은 여전히 난이도가 높음.
- **미확인** SPOSGait(NAS 기반) 수치는 검색 결과마다 상충(예: Gait3D 64.94 vs 79.4). 인용 금지.
- **확인** OpenGait(github.com/ShiqiYu/OpenGait): CASIA-B/OUMVLP/GREW/Gait3D/SUSTech1K/CCPG 등 지원,
  GaitBase·GaitEdge·DeepGaitV2·SwinGait·BigGait·SkeletonGait++ 재현.
  **라이선스가 결정적 리스크**: "This code is only used for academic purposes, people cannot use this
  code for anything that might be considered commercial use" → **B2C 상용 제품에 사용 불가.**
- 온디바이스/실시간 (**확인**, arXiv API 초록):
  - StrikeWatch(2025-10): 손목 IMU + 저전력 FPGA, 추론 지연 **0.140ms**, F1 0.847, 320mAh로 13.6일.
  - TinyML+IMU(2025-07): XIAO-nRF52840에서 엣지 추론, 정확도 80%+.
  - H-MoRe(2025-04): 34fps, 보행인식 CL@R1 +16.01%.
  → **주의**: 실시간·초저전력 사례는 전부 **착용형 IMU 센서** 계열. **카메라 실루엣 기반 gait 인식을
  폰/엣지에서 실시간 구동한 수치는 확보 실패(미확인)** — 프로젝트 리스크로 남겨야 함.

### 1-3. 한국 법 — 여기가 주제 1의 최대 관문

  원본영상 즉시 파기·별도 동의 UI가 **기획 단계부터 필수**. 데모조차 동의서 없이는 부적절.

## 주제 2 — 실시간 음성 필터 (콜센터·상담원 용도 제외)

### 2-1. 기술 수준: <300ms는 이미 달성됨
- **확인** StreamVC(arXiv 2401.03078, ICASSP 2024, Google): **Pixel 7 CPU 단일 코어**에서
  **end-to-end 70.8ms**(계산 10.8ms/20ms 청크 + 아키텍처 60ms), WER 6.22%, CER 2.17%.
  → **폰에서 실시간 음성 변환이 가능함을 보인 결정적 근거.** 다만 코드 공개 언급 없음.
- **확인** 스트리밍 익명화(arXiv 2406.09277, Texas A&M) PDF 원문 표 추출:
  - base 지연 230ms / **lite(파라미터 0.1배) 66ms**.
  - CPU 실측: 20ms 청크에서 base 83.82ms(RTF 3.19 → 실시간 불가), lite 43.01ms(RTF 1.15).
    **40ms 청크 lite CPU는 66.27ms / RTF 0.66 → CPU만으로 실시간 성립.**
  - 프라이버시 EER(높을수록 좋음): base 43.83 / lite 42.57 (VPC22 B2 = 25.10 대비 크게 우수).
- **확인** 최신 동향(arXiv API): DarkStream(ASRU 2025, EER≈50%, WER<9%), StreamVoiceAnon+(2026-03,
  EER 49.0%·WER 5.77%·**180ms**), Stream-Voice-Anon(ICASSP 2026), PHONOS(<241ms GPU),
  TVTSyn(<80ms GPU), Zero-VC(zero-lookahead, Interspeech 2026). → 레드오션에 가까울 만큼 연구가 몰림.
- 오픈소스 라이선스 (**확인**, 저장소 원문):
  - **RVC**(Retrieval-based-Voice-Conversion-WebUI): **MIT**, end-to-end **170ms**(ASIO 시 90ms), 학습 데이터 10분.
  - **seed-vc**(Plachtaa): **GPL-3.0** — 상용/배포 시 강한 제약. RTX 3060 Laptop에서 총 430ms, GPU 권장.
  → **제품화 관점에서는 MIT인 RVC 계열이 안전. GPL인 seed-vc는 앱 배포 시 소스 공개 의무 검토 필요.**
- **확인** VoicePrivacy 2024 평가계획(arXiv 2404.02677v2): 지표 **EER(프라이버시)·WER(내용)·UAR(감정)**,
  목표 EER 조건 10/20/30/40%. 베이스라인 B5가 EER 34.34% 최고, B1이 WER 2.91% 최저.
  데이터는 LibriSpeech(ASV/ASR) + IEMOCAP(감정). → **평가 프로토콜을 그대로 차용 가능.**

### 2-2. 안드로이드에서 통화 오디오를 실시간으로 거를 수 있는가 — **결론: 일반 통화는 불가**
- **확인**(AOSP MediaRecorder.java javadoc 원문): `VOICE_CALL` / `VOICE_UPLINK` / `VOICE_DOWNLINK`는 모두
  `CAPTURE_AUDIO_OUTPUT` 권한 필요이며 **"This permission is reserved for use by system components and is
  not available to third-party applications."**
- **확인**(Google Play 접근성 API 정책 원문): **"The Accessibility API is not designed and cannot be
  requested for: remote call audio recording"**, 플랫폼 보안·프라이버시 통제 우회 금지.
- **부분확인**(GrapheneOS 이슈 #3401, 커뮤니티 출처): Android 10+ 이후 루팅 없이 서드파티 실시간 통화
  녹음 경로가 차단됨.
- **확인** 반면 `VOICE_COMMUNICATION`(VoIP용)은 특별 제한 없음.
- → **판정: 통신사 통화(CS/VoLTE)의 마이크 업링크를 가로채 변조하는 앱은 루팅 없이 만들 수 없음.
  실현 가능한 형태는 "자체 VoIP 통화 앱 안에서의 변조"뿐.** 이것이 주제 2의 범위를 결정하는 사실.
- 방증(**확인**, 제목·날짜): 통화 중 실시간 보이스피싱 탐지는 전부 제조사·통신사가 제공 —
  삼성 갤럭시 실시간 탐지(데일리안 2025-08-21), SKT 에이닷(SKT 뉴스룸 2025-12-01),
  삼성+이통3사(경향신문·노컷 2026-02-12). **서드파티가 통화 오디오에 접근할 수 없다는 방증.**

- → **측정 가능한 핵심 지표 설계**: 필터 적용 전/후 화자검증 **EER 상승폭**(익명화 강도) +
  **WER**(내용 보존) + **end-to-end 지연(ms)**. VoicePrivacy 프로토콜을 한국어로 이식하면
  "우리 필터가 실제로 화자 식별을 무력화했다"를 한 장의 표로 증명 가능.
