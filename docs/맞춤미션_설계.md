## 0. 한 줄로

**미션 동작을 여러 개 미리 만들어 두고, 아이가 만든 이야기의 기승전결을 보고 그 책의 두 미션 자리에 들어갈 동작과 소품을 고른다.**
동작 화면은 생성하지 않는다. 이야기에 따라 바뀌는 것은 **어떤 미션인가**와 **무엇을 소품으로 쓰나**다.

적용 순서 — **① 협업 → ② 동화 → ③ 그림일기** (사용자 결정 10-01). 카메라를 쓰는 미션은 만들지 않는다.

## 1. 지금 상태 (`f6d5791` 기준)

| 모드 | 미션 1 (사건 직후 쪽 · `PageKind.RUB`) | 미션 2 (해결 쪽 · `PageKind.DRAG`) |
|---|---|---|
| 동화 | 문지르기. 소품은 `newcomerKind` 하나로 고른다 — 목록 밖이면 「불 + 물대포」로 떨어져 **거의 매번 같다** | 건네주기. 틀 A · G 만 퍼즐 |
| 협업 | 문지르기. 소품은 아이가 말한 단어 → 장소 → 먼지 순(`diaryMission1` — 협업도 `isDiary` 가 참이다) | 건네주기 |
| 그림일기 | 없음 (`DiaryBook.kt` — 미션 쪽이 없다) | 없음 |

- 손으로 하는 동작은 **문지르기 · 건네주기 · 퍼즐 셋**뿐이다. 소품만 바뀐다(`demo/Missions.kt` `mission1()` · `mission2()`)
- 불기(마이크 음량)는 독립 미션이 아니라 **문지르기의 덤**이다 — 소품이 먼지 · 모래 · 가루일 때만 켜진다(`ui/Book.kt` `RubPage` · `ui/Blow.kt`)
- 움직임 센서(가속도 · 자이로)를 쓰는 코드는 없다
- 서버 `/story` 는 쪽마다 미션 ID(A1~E2, `backend/app/schemas/story.py` `MissionId`)를 받아 그 미션 직전까지 자막을 쓴다(`MISSION_SETUP`). 동화는 `storyPagePlan()` 이 RUB→A6 · DRAG→A3/E1 을 보내고, **협업은 미션 ID를 보내지 않는다**(`coopWriteBook` 의 `Server.Page(kind)`)
- 미션 결과가 책 문장에 들어가는 자리: `m1Result` · `m2Result` → `storyMissionResult()` · `m1Done()` · `m2Done()`

## 2. 목표 · 성공 기준

**목표** — 아이 답에 따라 이야기가 달라지듯 **미션 동작도 달라진다.** 그리고 그 미션이 그 이야기의 문제와 해결에 맞아 보인다.

**성공 기준**
1. 같은 모드에서 이야기가 다르면 다른 **동작**의 미션이 나온다(소품만 바뀌는 것이 아니다)
2. 고른 미션이 그 책의 사건 · 해결 문장과 맞는다 — 불이 난 이야기에 불기 · 물대포, 물이 샌 이야기에 돌려 잠그기
3. **어떤 기기에서도 미션 때문에 책이 막히지 않는다** — 센서 · 마이크가 없거나 권한이 없어도 탭으로 끝난다
4. 미션 결과가 그 쪽 책 문장에 남는다
5. 고르는 규칙이 표로 검사된다 — 이야기 → 기대 미션

**하지 않는 것** — 카메라 미션 · 미션 화면 생성 · 미션 자리 수 변경(두 자리 유지 · 사용자 결정 10-01) · 점수 · 시간 초과

## 3. 원칙 — `미션_구상.md` §1 다섯 + 이번에 더하는 셋

`미션_구상.md` 의 다섯은 그대로다: ① 아이가 말한 것이 재료 ② 반응 고리 ③ 실패 없음 ④ 1인칭 기본 ⑤ 한 동작 = 한 발달 목표.

더하는 것:

6. **모든 미션에 탭 길이 있다.** 센서 · 마이크 미션은 입력이 안 들어오면(기기에 없음 · 권한 거부 · 8초 진전 없음) **같은 화면에서 탭으로 끝내는 길**이 보인다. 지금 불기가 「문질러도 된다」로 하는 것과 같은 정신이다
7. **고르는 것은 목록 안에서만.** 규칙이든 LLM 이든 미션 ID 목록 밖의 값은 버리고 규칙 기본값으로 간다
8. **실제 일은 지어내지 않는다.** 협업의 「다녀왔어요 · 곧 해요」와 그림일기는 아이의 실제 일이라, 아이가 말하지 않은 소품(불 · 먹물 …)을 미션에 넣지 않는다. 상상 이야기(동화 · 협업 「좋아해요」)만 이야기에서 소품을 지어 쓸 수 있다 — `diaryMission1` 의 「못 찾으면 먼지」 규칙과 `CoopTemplatePack` 의 마스코트 규칙과 같다

## 5. 구조

```
아이와 대화 → 칸이 다 참 (place · problem · cause · solution + 꼬리질문 · 협업이면 coopPick)
   ↓
StoryFacts — 미션을 고르는 데 쓰는 재료만 모은 값 (모드별로 만든다)
   ↓
MissionPicker — 자리 1 · 자리 2 에 하나씩 { MissionSpec, Prop }
   ├ 규칙 (늘 동작)
   └ LLM (서버가 켜져 있을 때 · §6-3 · 나중)
   ↓
DemoState.missions — 이 책의 두 미션 (책을 다시 열어도 같아야 하므로 책과 함께 저장)
   ↓
① 쪽 계획 → /story 에 미션 ID 를 보낸다 → 서버가 그 미션 직전까지 자막
② 책 RUB · DRAG 쪽 → MissionPage 가 spec.id 로 화면을 고른다
③ 끝나면 spec.doneLine → 그 쪽 책 문장
```

### 5-1. 단위와 책임

| 단위 | 하는 일 | 파일 (제안) |
|---|---|---|
| `MissionSpec` | 미션 하나의 정의 — id · 입력 · 자리 · 신호 단어 · 기본 소품 · 탭 길 여부 · 성공 기준 · 완료 문장 틀 | `demo/missions/MissionCatalog.kt` |
| `Prop` | 소품 — 그림 이름 · 이모지 대체 · 이름(조사 계산용) · 「지어낸 것인가」 표시 | `demo/missions/Props.kt` |
| `StoryFacts` | 고르기 재료 — 칸 값 · 아이 원문 · 모드 · 실제 일인가(§3-8) · 협업 템플릿 | `demo/missions/StoryFacts.kt` |
| `MissionPicker` | 규칙으로 두 자리를 고른다. 순수 함수 — 화면 · 감독을 모른다 | `demo/missions/MissionPicker.kt` |
| 미션 화면 | 미션마다 컴포저블 하나. 공통 틀(`MissionShell`)이 힌트 · 파티클 · 소리 · 탭 길 · 완료 신호를 맡는다 | `ui/missions/*.kt` |
| 센서 | `rememberBlowLevel`(있음) · `rememberLoudness` · `rememberTilt` · `rememberShake`. 못 쓰면 null → 화면이 탭 길을 바로 보인다 | `ui/sensors/*.kt` |

- **`Missions.kt` 의 `Mission1` · `Mission2` 는 A6 · E1 의 소품 표로 옮긴다.** 지금 소품 선택 규칙(`diaryMission1` · `newcomerKind` · `diaryGiveItem`)은 버리지 않고 각 미션의 「소품 고르기」가 된다
- **`PageKind.RUB` · `DRAG` 는 이름만 그대로 두고 「미션 자리 1 · 2」로 읽는다.** 서버 `PageKindName` 과 템플릿 쪽 순서를 바꾸지 않기 위해서다. 화면은 `PageKind` 가 아니라 `missions[slot].spec.id` 로 고른다
- 지금 `RubPage` · `DragPage` · `PuzzlePage`(`ui/Book.kt`)는 A6 · E1 · A3 화면으로 `ui/missions/` 에 옮긴다. `Book.kt` 는 자리만 안다
- 미션 결과 신호는 지금 그대로다 — 화면이 끝나면 `Reply.Tapped("mission", …)`, 감독이 `m1Result` · `m2Result` 를 채운다. 「helped」(마스코트가 도와줌 → 미션 2 쉬워짐)도 유지

### 5-2. 책에 남기는 것

- 쪽 계획에 미션 ID 가 들어가 **서버 자막이 그 미션을 향해 끝난다**(`MISSION_SETUP`). 서버가 꺼져 있으면 템플릿 문장의 미션 부분을 `spec` 의 문장 틀로 채운다(지금 `m1Caption()` 자리)
- 미션 결과 문장(「촛불이 다 꺼졌어요」)은 **앱이 쓴다** — 서버 스키마 주석 그대로(`the result line stays the app's`)
- 책장 · 다시 읽기에서 같은 미션이 나와야 하므로 고른 결과(`id` · 소품)를 책 기록에 함께 남긴다

## 6. 고르기

### 6-1. 규칙 (1단계 · 늘 동작)

자리마다 **이야기의 다른 부분**을 본다.

| 자리 | 보는 칸 | 이유 |
|---|---|---|
| 1 (사건 직후 · 워밍업) | `problem` · `cause` · 꼬리질문 `detail` | 문제가 생긴 것을 손으로 느낀다 |
| 2 (해결) | `solution` · 꼬리질문 `try` | 아이가 말한 해결 방법을 손으로 해낸다 — `미션_구상.md` §4 해결 동사 |

순서:

1. **아이 말에서 신호 단어 찾기** — §4 표의 신호 단어가 그 칸 원문에 있으면 후보. 여럿이면 표 순서가 아니라 **해결 동사 > 사물 단어** 로 고른다(「불을 껐어」의 「껐어」가 「불」보다 세다)
2. **협업이면 템플릿 맥락** — 신호가 없을 때 고른 이야기로 후보를 좁힌다(§7-2)
3. **못 찾으면 기본값** — 자리 1 = A6 문지르기, 자리 2 = E1 건네주기. 지금과 같다
4. **기기 거르기** — 센서가 없는 기기는 D2 · D4 · D5 를 후보에서 뺀다(탭 길이 있어도 「흔들어 봐」를 시키지 않는다). 태블릿은 D2(흔들기)를 뺀다
5. **같은 것 연달아 피하기** — 같은 아이의 바로 앞 책과 같은 미션이면 다음 후보로. 후보가 하나뿐이면 그대로 쓴다

소품은 그 미션의 「소품 고르기」가 정한다 — 아이 말 → 장소 → 미션 기본 소품. **§3-8: 실제 일이면 아이가 말하지 않은 소품을 쓰지 않는다**(기본 소품도 「먼지」처럼 어느 날에나 맞는 것만).

### 6-2. 규칙의 검사 — 표로

`MissionPickerTest` 는 **이야기 → 기대 미션** 표다. 예:

| 이야기 (칸 원문) | 자리 1 | 자리 2 |
|---|---|---|
| problem 「생일 촛불이 너무 많았어」 · solution 「물을 부어서 껐어」 | C1 (촛불) | A1 (껐어) |
| problem 「수도꼭지에서 물이 샜어」 · solution 「꽉 잠갔어」 | A6 | A4 |
| problem 「블록이 무너졌어」 · solution 「다시 쌓았어」 | A6 | A5 |
| problem 「친구가 멀리 갔어」 · solution 「크게 불렀어」 | A6 | C2 |
| problem 「먼지가 쌓였어」 · solution 「같이 치웠어」 | C1 (먼지) | E1 (기본값) |
| 아무 신호 없음 | A6 | E1 |

- **한 책에 같은 미션 두 번 금지** — 자리 2 를 먼저 고르고(해결이 더 중요하다), 자리 1 은 그것을 뺀 후보에서 고른다

### 6-3. LLM (나중 · 서버가 켜져 있을 때만)

- 규칙이 기본값으로 떨어질 때만 부른다 — 규칙이 신호를 찾으면 LLM 을 부르지 않는다(비용 · 지연)
- 입력: 이름을 가린 기승전결 네 칸 + 협업 템플릿. 출력: `{ "slot1": "C1", "slot2": "A4", "prop1": "candle", "prop2": "faucet" }` — **ID 와 소품 키는 목록 안에서만**(구조화 출력 · enum)
- 목록 밖 · 시간 초과 · 서버 꺼짐 → 규칙 결과 그대로
- 자리: 새 엔드포인트보다 **`/story` 요청에 「미션을 골라 달라」 표시**를 더해 한 번에 받는 쪽을 먼저 검토한다 — 왕복이 한 번 준다. 서버 담당(이종훈 · `backend/` 소유 · `guidelines/9` §9-5)과 정한다

## 7. 단계

### 7-1. 1단계 — 협업 (먼저)

**1-a. 틀 옮기기 (동작 변화 없음)**
- `MissionSpec` · `Prop` · `StoryFacts` · `MissionPicker`(기본값만) · `MissionShell`
- A6 · E1 · A3 화면을 `ui/missions/` 로 옮기고 `Book.kt` 는 자리로 디스패치
- 협업 `coopWriteBook` 이 쪽 계획에 미션 ID 를 보낸다
- **검사: 지금 모든 테스트 · 스크린샷이 그대로 통과해야 한다** — 이 단계는 구조만 바꾼다

**1-b. 협업에 맞는 미션부터**

| 순서 | 미션 | 왜 |
|---|---|---|
| 1 | C1 불기 (독립) | 이미 반쯤 있다. 「바람 · 촛불 · 생일」이 협업 답(장소 · 상상)에 자주 나온다 |
| 2 | C3 소리 흉내 | 「말로 짓는」 앱 성격 · 스포츠(「슛!」) · 직업(「삐뽀삐뽀」) 템플릿에 맞다 |
| 3 | A4 돌려 잠그기 · A1 물대포 | 직업 템플릿(소방관 · 요리사) 해결 동사 「껐어 · 잠갔어」 |
| 4 | D4 기울여 굴리기 | 스포츠 템플릿(공) · 태블릿에서도 안전 |
| 5 | E2 고쳐 주기 · A5 쌓기 | 협업 해결 답 「고쳤어 · 다시 쌓았어」 |
| 6 | 나머지 | `미션_구상.md` §5 순서 |

### 7-2. 협업만의 재료 — 템플릿 맥락

신호 단어가 없을 때 고른 이야기로 후보를 좁힌다(§6-1 ②). **실제 일(다녀왔어요 · 곧 해요)이면 소품은 기본 소품만**(§3-8).

| 템플릿 | 자리 1 후보 | 자리 2 후보 |
|---|---|---|
| 장소 · 탐험 | C1 불기(먼지 · 민들레) · B3 비추기 | D4 굴리기 · A8 길 잇기 · E1 |
| 직업 · 임무 | C3 소리 흉내(사이렌) · A7 길게 누르기 | A1 물대포 · A4 잠그기 · E2 고쳐 주기 |
| 스포츠 · 도전 | C3 소리 흉내(응원) · D3 박자 | D4 굴리기 · A5 쌓기 · C2 부르기(응원) |

### 7-3. 2단계 — 동화

- `mission1()` 의 `newcomerKind` 하나짜리 선택을 `MissionPicker` 로 바꾼다 — **「거의 매번 물대포」가 여기서 풀린다**
- `storyPagePlan()` 의 RUB→A6 · DRAG→A3/E1 고정을 고른 ID 로
- 틀 A · G 의 퍼즐(A3)은 「해결 동사가 맞추다 · 되돌리다」라는 신호로 규칙 표에 들어간다 — 틀 키를 직접 보지 않는다
- 동화는 상상 이야기라 소품을 이야기에서 지어 써도 된다(§3-8)

### 7-4. 3단계 — 그림일기 (담당과 정한 뒤)

- 지금 그림일기 책에는 미션 쪽이 없다(`DiaryBook.kt`). 「있었던 일의 기록」이라 비어 있는 것이 사실이라는 원칙이 있다(`guidelines/2` §1-1 일기 예외)
- **넣는다면** 아이가 말한 일에서만 — 실제로 한 일을 손으로 다시 해 보는 자리(「블록을 쌓았어」→ A5 쌓기 · 「촛불을 불었어」→ C1). 신호가 없으면 **미션 쪽을 만들지 않는다**(기본값으로 채우지 않는다)
- 쪽 구성은 일기 담당(박진웅)의 영역이다 — 이 문서는 제안까지

## 10. 정하지 않은 것

- **성공 문턱값** — 몇 % 가 「다 꺼졌다」인지, 음량 얼마가 「후~」인지, 몇 도가 「기울였다」인지. 실기기 · 아이 손으로 정한다(`미션_구상.md` §6 과 같다)
- **소리** — 미션마다 효과음 · 구운 리액션 목소리
- **소품 그림** — 미션마다 기본 소품 + 자주 나올 소품을 ComfyUI 펠트 화풍으로. 몇 개를 미리 만들지
- **D1 연타** — 「때리는 게임」으로 읽히지 않는 표현(`미션_구상.md` 같이 생각해 볼 질문)
- **3~4세** — A9 벌리기 · B2 순서 · 자리 2 의 두 단계 미션이 되는지. 「8초 진전 없음 → 마스코트가 첫 단계를 보여 준다」로 충분한지
- **LLM 고르기를 부를지** — 규칙만으로 다양성이 충분하면 안 붙여도 된다. 1단계 뒤 협업 책 10권쯤으로 본다
- **마이크 고지** — 미션 중 마이크가 켜진 것을 부모가 어떻게 아나(지금 불기의 「듣고 있어요」 표시를 모든 마이크 미션에)
- **소유** — 미션 화면 · 고르기는 안치영, `sceneBook`(`Scenes.kt`)의 책 흐름 · 동화 템플릿은 조장 영역과 겹친다. 2단계 전에 맞춘다
