# 받아쓰기 미세조정 — AI-Hub 3~6세로 `large-v3` LoRA

**읽은 것**: `eval/whisper_ft/`의 스크립트(`prepare.py` · `train_lora.py` · `merge_convert.py` · `evaluate.py` · `download.sh`)와 그 실행 로그, `eval/results.md`의 2026-10-07 절. **읽지 않은 것**: AI-Hub 데이터셋 108 자체의 전수 검수(클립 149,473개를 다 듣지 않았다), 서버(PC1) 쪽 코드. **따라서 이 문서는 AI-Hub 라벨 품질에 대한 감사가 아니고, 서버 반영 여부를 대신 정하는 문서도 아니다.**

날짜는 **측정일**이다 — 2026-10-06(small 파일럿·1차 학습 시작) ~ 2026-10-07(1차 평가·기록). 2차(11~13번)가 끝나면 이 문서를 갱신한다.

---

## 왜 했나

받아쓰기(`large-v3`, 서버 설정)가 3~6세에서 약하다 — 2026-09-23 측정으로 CER 3세 37% · 5세 15%, 어절 보존 53~81%(합격선 90%에 못 미침). 같은 데이터셋으로 미세조정한 전례(whisper base 120.8%→19.1%)가 있었지만, `large-v3`는 출발점이 달라 **얼마나 오를지는 재 봐야 안다.** 하룻밤 분량으로 싸게 확인하고, 미리 고정한 기준을 넘을 때만 서버에 쓴다는 게 이 작업의 전제다.

## 데이터

AI-Hub 데이터셋 108 「자유대화 음성(소아남여, 유아 등 혼합)」 원천 zip 8 — 3~6세 260명 · 149,473클립. 화자 단위로 나이별 분리(seed 20261006):

| | 화자 | 클립 |
|---|---:|---:|
| 학습 | 185명(3세15·4세28·5세58·6세84) | 35,997(3세5,997·4세10,000·5세10,000·6세10,000) |
| 확인 | 10명(3세1·4세2·5세3·6세4) | 1,495 |
| **평가** | **65명(3세5·4세10·5세20·6세30)** | 1,806 |

평가 화자는 학습에 전혀 쓰지 않는다(화자 단위 분리). 학습은 나이마다 같은 몫(1만 클립, 3세는 전량 5,997)으로 뽑아 6세 쪽으로 쏠리지 않게 했다. 안에 글자가 든 태그(「(SP:버)」 등)가 있는 클립 1,615건은 학습·확인에서 뺐다.

**확인된 것**: 위 화자·클립 수는 `prepare.py` 실행 로그 그대로다.
**확인되지 않은 것**: AI-Hub 라벨(`stt`) 자체의 오표기율 — 전수 검수를 하지 않았다.

## 방법

원래 `large-v3` 무게는 얼리고(fp16) 주의(attention) 층 옆에 LoRA(rank 32, alpha 64, `q_proj`·`k_proj`·`v_proj`·`out_proj`)만 학습한 뒤, **원래 모델에 합쳐** faster-whisper(CTranslate2) 형식으로 바꾼다. 합친 모델은 크기·구조가 원래와 같아 서버 추론 속도가 그대로다.

| | 값 |
|---|---|
| GPU | NVIDIA GeForce RTX 3060, 12GB |
| 걸음 수 | 2,500(실효 배치 16 = batch 4 × accum 4) |
| 학습률 | 3e-4, linear, warmup 200 |
| 걸린 시간(large) | 8시간 17분(29,800초) — 첫 25걸음 11.60초/걸음으로 처음 추정한 것과 거의 같다 |
| train_loss → eval_loss(large) | 1차 걸음에서 꾸준히 줄어 최종 0.873 → 0.1723 |

## 채택 기준 — 데이터를 보기 전에 고정 (2026-10-06, 조장)

평가는 **학습에 안 쓴 아이**(화자 단위로 뗌)와 어른 녹음(`eval/audio/bias` · 짧은 답 「응·아니·몰라」 포함 · 깃 밖)으로, 원래 모델과 **같은 서버 설정**(`int8_float16` · beam 5)으로 나란히 잰다. **다섯 개 모두 통과해야 채택한다.**

| | 기준 |
|---|---|
| 1 | 3~5세 어절 보존 **+10%p 이상**, 화자 부트스트랩 95% 구간 아래끝 **> 0** |
| 2 | 6세 CER 악화 **≤ 1%p** |
| 3 | 어른 세트에서 원래 맞히던 것을 놓친 수 **≤ 1** |
| 4 | 헛문장으로 버린 아이 말 증가 **≤ 0.5%p** |
| 5 | 지연 p50 증가 **≤ 100ms** |

숫자는 `evaluate.py` 맨 위 상수와 같다.

**확인된 것**: 3~6세 아이 CER·어절 보존은 모든 나이에서 크게 나아졌다. 어른 세트 전체 정답률도 올랐다(40→44/57).
**조건부 함의**: 아이 목소리로만 학습하면 어른의 짧은 답(「아니」) 일부를 깎아먹을 수 있다 — 다만 표본이 「아니」 소수 클립이라 이 둘이 우연히 걸린 것인지, 체계적인지는 더 봐야 안다.
**확인되지 않은 것**: 이 2건이 학습 데이터 분포(아이 목소리 위주) 때문인지, 다른 원인(디코딩 변화·beam search 민감도)인지는 이 평가만으로는 가르지 못한다.

## 2차 계획과 결과

**계획**(README 11~13번과 같음, 조장 승인 받음 — 2026-10-07): 1차와 **같은 아이·같은 클립**을 뽑되, 학습 클립의 소리만 앱과 비슷하게 손질한다 — Silero VAD로 말 구간 앞 0.5초·뒤 0.3초만 남기기(`--vad-trim`), 다른 아이 목소리·분홍 잡음을 섞기(`--noise`). 평가·확인 클립은 손대지 않는다.

**2차를 1차 대신 쓰는 조건**(미리 고정): 원래 `large-v3` 대비 채택 기준 다섯 개를 통과하고, **그리고** 1차 모델 대비 3~5세 어절 보존 95% 구간 아래끝이 0보다 커야 한다(1차보다 확실히 나아야 한다).

**결과**(2026-10-07, `eval/results.md` 2026-10-07 절의 2차와 같은 값): 데이터 손질 — 다른 아이 말소리 겹침 10,800건 · VAD 트림 17,465건 · 분홍 잡음 7,159건. 학습 8시간17분 · train_loss→0.981 · eval_loss→0.1725.

| | 원래 large-v3 대비(⑩) | 1차 모델 대비(⑪) |
|---|---|---|
| 3~5세 어절 보존 | +23.9%p[+20.1,+27.7] ✅ | +0.8%p[+0.0,+1.5] — 거의 차이 없음 |
| 어른 세트 놓친 것 | 3개 ❌ | 5개(1차 대비로는 더 나빠짐) |

**판정: 탈락.** 원래 모델 대비 기준3(어른)에서 1차와 마찬가지로 넘어졌고(이번엔 3건), 1차 모델과 비교해도 아이 쪽 이득은 거의 없는데 어른 세트는 더 나빠졌다(44/57→42/57). **1차보다 나은가: 아니다.** 「2차를 1차 대신 쓰는 조건」(⑩ 다섯 기준 통과 **그리고** ⑪ 아래끝>0)의 첫 조건부터 못 채워 2차는 1차를 대신하지 않는다.

**확인된 것**: VAD 트림·잡음 섞기(2차 손질)는 3~5세 어절 보존을 1차보다 더 끌어올리지 못했고(사실상 동일), 어른 세트 손상은 줄지 않고 오히려 늘었다.
**조건부 함의**: 어른 짧은 답 손상의 원인이 "학습 클립의 무음 길이·잡음"이라는 가설이었다면, 이 결과는 그 가설과 맞지 않는다 — 다른 원인(학습 데이터의 화자 나이 분포 자체, 디코딩 방식 변화 등)일 가능성이 남는다.
**확인되지 않은 것**: 왜 어른 세트가 1차보다도 나빠졌는지는 이 두 번의 실험만으로는 가르지 못한다(학습 난수 차이일 수도, 체계적일 수도 있다).

## 한계

- AI-Hub 데이터에는 「응·몰라」 같은 짧은 답이 없다(클립당 평균 5어절) — 짧은 답 성능은 이 데이터로는 직접 못 잰다.
- 우리 앱의 실제 녹음 조건(마이크·거실 소음)과 AI-Hub 녹음 조건이 다르다.
- 3세 평가 화자가 5명뿐이라 3세 숫자는 특히 흔들린다.
- 어른 세트 59클립 중 `preset_22`·`short_몰라_4` 2개는 이 PC의 `eval/audio/bias/` 최상위 폴더에 최종 녹음이 없다(오래된 `_run1/`에만 있다) — 이번 평가(57클립)에는 못 넣었다. 둘을 넣으면 기준3 수치가 바뀔 수 있다.
- `faster-whisper==1.2.1`이 최신 `av`(PyAV, 19.x)와 안 맞아(`metadata_errors` 인자가 없어짐) `requirements.txt`에 `av<14`를 추가해 고쳤다(2026-10-07) — 더 새 `av`가 나오면 다시 안 맞을 수 있다.
- 이 PC 한 대, 한 번의 학습 실행 결과다 — 같은 설정으로 다시 돌리면 난수(데이터 순서·초기화)에 따라 숫자가 약간 달라질 수 있다.

## 서버 반영 방법 (참고 — 이번엔 탈락이라 적용하지 않는다)

기준 다섯 개를 모두 통과하면, PC1의 `.env`에 `STT_MODEL=<ct2 폴더>` 한 줄을 추가해 반영한다. 되돌리기는 그 줄을 지우면 된다. 모델(LoRA 포함) 자체는 공개 레포로 옮길 수 없으므로, 반영을 결정하면 조장 PC에서 같은 스크립트로 다시 학습하거나 모델을 옮길 방법을 그때 정한다.

---

**같이 생각해 볼 질문**: 2차(VAD 트림·잡음)가 어른 세트 손상을 줄이지 못했다는 것은, 손상 원인이 "학습 클립의 무음·잡음 모양"이 아닐 수 있다는 뜻이다 — 그렇다면 남는 후보는 ① 학습 데이터의 화자 나이 분포 자체(아이 목소리만 봐서 어른 음향 특징이 밀렸다) ② 짧은 발화(「아니」 1~2음절)에 LoRA가 유독 민감하다 ③ 우연(화자·클립 수가 적어 생긴 표본 흔들림) 중 하나다. 다음 할 일 순서는 ① 어른 세트의 짧은 답 클립 수를 늘려(지금은 「아니」가 몇 개뿐이라 1~2건 차이가 %를 크게 흔든다) 체계적인지 우연인지부터 가르고, ② 그게 체계적이라면 학습 데이터에 어른 음성(또는 짧은 발화)을 소량 섞어 다시 학습해 보는 쪽이 — ①이 더 싸고, ①의 답이 ②가 필요한지(그리고 어떤 모양으로 섞을지)를 정해 주기 때문이다.
