## 0. 이 데모가 무엇이고, 무엇이 아닌가

**맞다**: 구현대본의 화면 S1~S12를 폰에서 손으로 만져 볼 수 있게 만든 **흐름 확인용 앱** (장면 16개 + 곁장면 3개).
아이가 말한 것으로 **수준을 판단하고, 수준에 맞는 동화 템플릿(6~8쪽)** 을 골라 책 · 미션을 만들고, 책장에 꽂히는 것까지 실제로 동작한다.
시작 화면에서 **이야기 모드 셋** 중 하나를 고른다 (§4-8).

**아니다**: 서버도, 음성 인식도, LLM도, 저장소도 없다. 앱을 끄면 전부 초기화된다.
아이 답은 질문마다 준비된 **더미 답(질문당 4~9개, 수준 ①②③ 표시)** 중에서 들어간다(진짜 Whisper 대신).
시연 서랍에서 **"고르며 · 이어 · 까닭 짓기처럼"** 을 고르면 그 수준의 답이 70%로 나온다.

> **(10-05 바뀜)** 위 「아니다」 문단은 9/16~9/22 때의 모습이다. 지금은 셋 다 있다.
>
> - **서버** — `net/Server.kt` 한 곳이 팀 서버를 부른다: 받아쓰기 `/stt` · 판정 `/judge` · 대사와 다음 질문 `/turn` · 책 문장 `/story` · 그림 `/image` · 목소리 `/tts`.
>   **실패해도 예외를 던지지 않고 null** 을 돌려 앱은 대본대로 계속 간다. 주소(`Server.base`)가 있고 그 모드가 켜져 있을 때(`Server.liveFor(mode)`)만 쓴다 —
>   디버그 빌드는 인자 없이 켜면 공개 주소(`DEFAULT_SERVER`)로 세 모드를 다 켜고, **스토어(release) 빌드 · 화면 검사(Robolectric)는 꺼진 채 대본**이다.
>   진짜 마이크와 오또 목소리는 `net/Voice.kt`(Silero VAD → `/stt`, 문장 → 구운 소리 또는 `/tts`)
> - **폰 안 저장** — 책장(`story_books` · `coop_books` · `diary_books`) · 그림(`story_images` · `diary_images`) · 아이가 낸 소리(`noBackupFilesDir`) ·
>   부모가 준비한 같이 만들기 이야기(`coop_plan`) · 아이를 부르는 말(`child_call`) · 앱 틀 상태(`otto_shell`) · 보호자 계정(`otto_account`).
>   **앱을 꺼도 남는다.** 서버로는 보내지 않는다
> - **보호자 계정** — 카카오 · 네이버 · Google · 이메일 로그인(§4-22). 다만 **서버에 계정 기능이 아직 없어** 계정은 이 폰 안에만 있다
> - 시연 서랍 · 더미 답은 그대로 있다. 서버가 꺼진 모드는 위 설명대로 더미 답으로 돈다

**왜 HTML 데모 말고 앱인가**: 19번 결정(Kotlin 네이티브)에 맞춰, 실제로 만들 때 쓸 구조를
미리 잡아 두려고. 엔진(`demo/`)과 화면(`ui/`)이 나뉘어 있어서 진짜 STT · LLM을 붙일 때
`Director.ask()`(말 받기)와 `judge()`(신호 표시)만 바꾸면 된다.

## 1. 팀원이 받아서 여는 법

1. 압축 파일을 풀고 폴더를 **Android Studio에서 `Open`** (`File → Open` → `finalproject_demo` 폴더)
2. 처음 열면 Gradle이 라이브러리를 받는다(인터넷 필요, 3~5분). `local.properties`는 각자 스튜디오가 자동으로 만든다
3. 에뮬레이터나 폰을 연결하고 ▶ Run

터미널만 써도 된다.

```
gradlew installDebug
adb shell am start -n com.example.finalproject_demo/.MainActivity
gradlew :app:testDebugUnitTest --tests "*StoryTextTest*"   # 책 문장 검사 (결과: app/build/story_samples.txt)
```

> **(10-05 바뀜)** 앱 아이디가 `kr.clap.otto` 로 바뀌었고, **개발용(debug) 빌드는 `kr.clap.otto.dev`**(앱 이름 「오또 개발」)로 깔린다.
> Play 비공개 테스트 앱(`kr.clap.otto`, Play 가 서명)을 지우지 않고 **그 옆에 따로** 깔리게 한 것이다(조장 3b68f02). 데이터도 따로다.
> 그래서 위 `am start` 는 지금 이렇게 쓴다:
>
> ```
> adb shell am start -n kr.clap.otto.dev/com.example.finalproject_demo.MainActivity
> ```
>
> 코드 패키지(`com.example.finalproject_demo`)는 그대로다. 단위 테스트는 10-05 저녁 기준 **681개**.

### 보호자 로그인 키 넣기 (10-05)

카카오 · 네이버 · Google 로그인은 키가 있어야 진짜로 된다. 키는 **레포에 올리지 않고** `android/local.properties`(깃 무시) 또는
같은 이름의 환경 변수에 넣는다. 빌드가 읽어 `BuildConfig` 로 넘긴다(`app/build.gradle.kts` 의 `loginKey()`).

```
# android/local.properties — sdk.dir 아래에 덧붙인다
OTTO_KAKAO_APP_KEY=...          # 카카오 네이티브 앱 키 — 개발용(kr.clap.otto.dev)
OTTO_KAKAO_APP_KEY_STORE=...    # 카카오 네이티브 앱 키 — 스토어용(kr.clap.otto). release 빌드만 쓴다
OTTO_NAVER_CLIENT_ID=...
OTTO_NAVER_CLIENT_SECRET=...
OTTO_GOOGLE_WEB_CLIENT_ID=...   # Google 은 Android 가 아니라 「웹」 클라이언트 ID
```

- 카카오는 **네이티브 앱 키 하나에 패키지 하나**라 개발용과 스토어용 키가 따로다. `OTTO_KAKAO_APP_KEY_STORE` 가 없으면 release 도 개발용 키를 써서 스토어 빌드의 카카오 로그인은 실패한다
- 카카오 로그인 복귀 주소 `kakao{키}://oauth` 는 `manifestPlaceholders` 가 키로 만든다
- 키를 받는 곳 · 등록할 패키지 이름 · 키 해시 · 팀원 PC 값 뽑기는 **[`docs/소셜로그인_키_발급.md`](소셜로그인_키_발급.md)**
- **키가 없어도 빌드는 된다** — 디버그 빌드는 그 버튼이 「개발용」 가짜 계정으로 넘어가고, release 는 「준비 중」을 띄운다(§4-22)

**가로 전용**이므로 에뮬레이터를 가로로 돌려 놓는다. 세로면 화면이 잘린다.

```
adb shell settings put system accelerometer_rotation 0
adb shell settings put system user_rotation 1
```

## 2. 그림 파일은 어떻게 공유되나 *(질문받은 것)*

**압축해서 보내면 팀원 화면에도 똑같이 보인다.** 그림은 내 PC가 아니라 **프로젝트 안에** 있다.

- 위치: `app/src/main/res/drawable/*.png` (122장)
- 앱을 빌드할 때 APK 안에 함께 들어간다 → 인터넷도, ComfyUI도 필요 없다
- **ComfyUI는 그림을 다시 뽑을 때만** 필요하다. 그냥 돌려 보는 데는 전혀 필요 없다

### 압축할 때 반드시 빼야 하는 것

| 빼는 것 | 왜 |
| --- | --- |
| `build/`, `app/build/` | 빌드 산출물. 각자 다시 만든다 (이것만 **436MB**) |
| `.gradle/`, `.idea/`, `.kotlin/` | 내 PC 전용 캐시 · 설정 |
| `local.properties` | 내 PC의 Android SDK 경로가 박혀 있다. 팀원 스튜디오가 자동 생성한다. **(10-05)** 보호자 로그인 키도 여기 있다 — 절대 공유하지 않는다(§1) |

빼면 **20MB대**, 안 빼면 **500MB가 넘는다**. `.gitignore`에 이미 다 적혀 있으니 git으로 주고받으면 자동으로 걸러진다.

**이미 만들어 뒀다: `C:/Android/finalproject_demo_공유.zip` (v0.9 · 크기는 변경이력 참고).**
안에 `docs/` 폴더가 있고, 이 문서를 포함한 문서 4개가 들어 있다.
다시 만들려면:

```powershell
# 파워셸에서 공유용 압축 만들기
# 0) 문서 4개를 프로젝트 안 docs/ 로 먼저 복사한다 (zip 하나로 끝나게)
Copy-Item "C:/dev/final_project/안드로이드데모_*.md" `
          "C:/Android/finalproject_demo/docs" -Force

$src = "C:\Android\finalproject_demo"
$dst = "C:/Android/finalproject_demo_공유.zip"
$tmp = "$env:TEMP\fp_demo"
Remove-Item $tmp -Recurse -Force -ErrorAction SilentlyContinue
robocopy $src $tmp /E /XD build .gradle .idea .kotlin /XF local.properties | Out-Null
Compress-Archive -Path "$tmp\*" -DestinationPath $dst -Force
Remove-Item $tmp -Recurse -Force
```

### 그림 용량을 줄여 놨다

처음엔 전부 1024×1024라 90MB였다. 화면에 실제로 보이는 크기 기준으로 줄여서 **18MB**가 됐다
(배경 1344px · 캐릭터 · 함께 하는 사람 512~640px · 아이콘 256px · 그림체 견본 384px). 눈으로 봐서 차이 없다. **APK는 34.6MB (v0.9).**

v0.10 이후로 그림이 많이 늘었다(일기 장소 10 · 같이 갈 친구 9 · 주인공 하의 54 …). 줄이는 일을
손으로 하지 않게 `tools/shrink_assets.py` 로 옮겨 놨다 — **그림을 만든 다음에는 항상 한 번 돌린다** (§6).

## 3. 구조 — 어디를 고치면 무엇이 바뀌나

```
demo/                      ← 엔진과 대본 (화면을 모른다)
├── Model.kt      상태 · 장면 이름 · 수준(Level) · 더미 아이 수준 · 함께 하는 사람(PARTNERS) · 배경 속 것 좌표(HOTSPOTS)
│                 · 장소(Theme) · 같이 갈 친구(DinoKind · 장소마다 셋) · 답(Answer: 신호 표시) · 턴 기록(TurnNote)
│                 · 이야기 모드(StoryMode) · 일기 장소 그림(DIARY_PLACES) · 책장 · 그림체 · 부모 설정
├── StoryBank.kt  질문 은행(변형 46 · 더미 답 258) · 질문 고르기 · 판단(judge) · 템플릿 7종(A B C D E F G) · 제목 · 책 자막
├── ui/Motion.kt  불 · 물 · 김 · 연기 · 반짝임(파티클) · 숨쉬기 · 눌림과 늘어남 · 눈 깜빡임 · 검사 멈춤 스위치
├── ui/Sfx.kt     효과음을 **계산해서** 만든다 (톡 · 치익 · 반짝 · 툭) — 녹음 파일이 없다
├── ui/Blow.kt    마이크를 **음량으로만** 읽는다 (후~ 불기 미션). 받아쓰기가 아니다
├── DiaryBank.kt  **일기 · 협업 모드의 질문 열한 걸음**(DIARY_STEPS) · 기승전결 네 자리(DIARY_REQUIRED) · 일기 책 한 장(diaryTemplate)
├── Missions.kt   대화로 만드는 미션 — 장면 4 "누가" → 미션 1 · 장면 10 "어떻게" → 미션 2 · 일기는 아이가 말한 일에서 · 안내 문장
├── Director.kt   질문 엔진. ask() 하나가 마이크 · 무응답 흐름(힌트 · 사다리 · 카드) · askSlot()(은행 + 판단) · askPartner()
├── Scenes.kt     동화 모드 장면 19개(곁장면 포함) 대본 · 고정 질문 2개 · 이야기 잇기(장면 6↳) · 비밀번호 관문
├── DiaryScenes.kt **일기 모드**의 장면과 걸음 (sceneDiary · askDiaryStep). 협업 갈고리 셋만 남는다
├── CoopScenes.kt **부모 협업 모드** (9/22 분리 · 진웅) — coopIntro · askOrCoopAsk · coopFinishLog
└── Behind.kt     장면별 "뒤에서" 설명 · 체크리스트 · 금지 목록

ui/                        ← 화면 (대본을 모른다)
├── Chrome.kt     맨 위 진행 막대(별) · 화면 이름 · 하루 별 재화 · 떠 있는 마스코트 말풍선 · 🎤➡️ · 누르면 글자가 뜨는 Tappable
├── Screen.kt     무대 · 시작 화면(세 모드) · 함께 하는 사람 · 도감(지우기 포함) · 그림판(12색 · 지우개) · 친구 평가 · 선물 · 시연 서랍
├── ParentBand.kt **부모 띠** — 협업 모드에서 질문을 소리 없이 어른에게 보여 주는 유일한 새 화면
├── Hotspots.kt   배경 그림 속 것이 반짝이고 통 튀는 층 (새 그림을 얹지 않음)

> **(10-05 바뀜)** 4-21 ~ 4-33 을 더했다 — 앱 틀 · 계정 · 동의 · 같이 만들기 · 미션 · 살아 있는 배경 (v0.21 ~ v0.27).

### 4-1. 감독(Director)이 대본을 "읽어 내려간다"

각 장면은 **중단 가능한 함수(suspend fun)** 하나다. 장면을 옮기면 이전 장면의 코루틴이 취소되므로 상태가 섞이지 않는다.

```kotlin
private suspend fun Director.scenePlot() {
    val t = s.template!!                    // 3턴째 정해진 템플릿
    for (slot in t.plot) {                  // 예: C → ["response", "helper"]
        val (_, r) = askSlot(slot)          // 은행에서 변형을 골라 묻고 판단까지
        valueOf(r)?.let { s.slots[slot] = it }   // 답이 그대로 책 문장 재료
    }
    go(Scene.DINO)
}
```

### 4-2. 질문 하나가 무응답 흐름을 통째로 안다

`ask(Question)` 하나에 ⭐5 · ⭐22 흐름이 다 들어 있다. 질문은 소크라틱 — 선택지를 말하지 않고, 말이 없어도 **생각할 거리(힌트)** 를 먼저 준다.

| 질문 종류 | 카드 | 무응답일 때 |
| --- | --- | --- |
| **열린 질문 · `noCards`** (누가 흔들었을까 · 뭐가 있을까 · 이름 · 이야기 잇기 · 기분 · 소리) | 없음 | 쉬운 질문 → 힌트 질문 → `fallback`이 있으면 "혹시 ○○일까?" (source=mascot) |
| **열린 질문 · 카드 준비** (장소 · 까닭 · 해결 · 바꿀 곳 · 주인공 속성) | 무응답 뒤에만 | 쉬운 질문 → **그때** 카드 3장(7초) → 교체 최대 3번 → 마스코트가 고름 |
| **CHOICE** (장면 7 "공룡? …" 모호한 말 확인만) | 질문과 함께 바로 | 다시 읽기 1 → 교체 최대 3번 → 마스코트가 고름 |
| **함께 하는 사람** (장면 1↳) | **없음 — 녹음만** | 다른 말로 두 번 더 → 그래도 없으면 "엄마"로 두고 진행 |
| **`askPartner`** (장면 10 참여) | 없음 | **대신 채우지 않는다** — null · 책에도 넣지 않음 |

- 함께 하는 사람만 말하면 **2.5초** 뒤 "○○는 어떻게 생각해?"를 한 번 (⭐5 · 구현대본 §0-2) — 장면 5는 늘 이 흐름
- 이야기 턴이 8을 넘으면 남은 칸을 마스코트가 채우고 책으로 간다 (`budgetOver()`)

### 4-3. 질문 은행 — 처음 두 질문만 고정, 나머지는 매번 다르게

```kotlin
QVariant("c_resp_how", slot = "response", levels = {이어, 까닭}, kind = HARD,
    probe = "'어떻게' 질문에 방법을 담나 (S1)",
    text = { "어떻게 하면 ${f}가 흔드는 걸 멈출까?" },
    answers = { listOf(
        Answer("말해!", "그만해!", lv = 1),
        Answer("그만하라고 말해.", "그만해 줘!", reason = true, lv = 2),
        Answer("손을 들고 멈춰! 하고 말해. 그러면 알아들어.", "멈춰! 손 들었지?", reason = true, el = {"결과"}, con = true, lv = 3), …) })
```

- 칸(slot)마다 변형 2~6개 · 변형마다 더미 답 4~7개 · 수준 ①②③이 섞여 있다
- 고르는 순서: **지금 수준에 맞는 것 → 이번 이야기에서 안 쓴 것 → 지난 이야기에서 안 쓴 것 → 가장 오래전에 쓴 것**
- 여러 템플릿이 함께 쓰는 칸(해결)은 **지금 템플릿의 변형만** (id 앞머리 `e_ c_ d_ a_ g_`)
- 가정 질문(`hypo`) · 돌아보기(`reflect`)는 **까닭 짓기일 때만** (역할1 조사2 #5)

### 4-4. 발달 판단 — 규칙이 계산한다 (역할1 조사2 §3~4)

답마다 표시가 붙어 있다: `reason`(S1: 왜 · 어떻게에 까닭 · 방법) · `el`(S2: 묻지 않은 배경 · 계기 · 시도 · 결과) · `con`(A1: 잇는 말) · `emo`(마음 — 신호 아님) · `kind`(까닭 종류).
실제 앱에서는 LLM이 이 표시만 달고, **수준은 규칙이 계산**한다.

| 규칙 | 내용 |
| --- | --- |
| 세는 것 | 말로 답한 이야기 턴만 (탭 · 그림 · 마스코트 · 마음 질문 · 이름 · 소리는 안 셈) |
| 올림 (2턴 연속) | 고르며 → 이어: S1 **또는** S2 / 이어 → 까닭: S1 **그리고** 구조(계기 · 시도 · 결과 또는 잇는 말) |
| 내림 (2턴 연속) | 카드 · 무응답 · 마스코트 · 두 어절 이하에 신호 없음 |
| 템플릿 확정 | **3턴째**(장소 · 누가 · 까닭 뒤) — 그 뒤 이동은 질문 난이도와 다음 세션 시작점만 |
| 세션 누적 추정 | S1 ≥ 2 & 요소 ≥ 2 → 까닭 / 짧은 답 · 카드 ≥ 60% & 신호 없음 → 고르며 / 나머지 → 이어 |
| 부모에게 | 수준 이름은 보이지 않는다 — 6축 기록(이유 말하기 · 이야기 채우기 …)으로만 |

### 4-13. 움직임은 그림이 아니라 **계산**이다 (9/23)

*"게임엔진을 쓰면 퀄리티가 더 좋아질까?"* 에서 나온 원리다. 답은 **아니오** 였다.

캐릭터가 살아 보이지 않는 까닭은 엔진이 아니라 **그림이 정지 PNG 한 장**이어서다.
엔진을 바꿔도 그 PNG는 안 움직인다. 반대로 **불 · 물 · 연기 · 반짝임은 그림이 아니라 계산**이라
화가 없이도 만들 수 있다. 소리도 같다 — 녹음이 없으면 사인파와 잡음으로 만든다.

| 무엇 | 어디서 | 원리 |
| --- | --- | --- |
| 불 | `ParticleField.flame` | 밑이 좁고 **가운데 축으로 당겨 와야** 불끝이 뾰족해진다 |
| 물 | `ParticleField.jet` | **노즐은 제자리, 겨눈 곳이 움직인다** — 소방차처럼. 둘이 붙어 있으면 물이 찔끔 나온다 |
| 꺼짐 | `flame(strength)` | 그림이 **작아지는** 게 아니라 **입자 수가 줄어든다.** 눈에 아주 다르게 보인다 |
| 살아 있음 | `Modifier.breathing` · `rememberBlink` | 1.4% 크기 변화와 불규칙한 깜빡임. 가장 싼 방법이다 |
| 손맛 | `Modifier.pressPop` | 누르는 **그 순간** 납작해지고, 뗄 때 1을 **지나쳐** 부풀었다 돌아온다 |
| 소리 | `Sfx` | 0.3초 · 음량 절반 이하. 거슬리면 아이가 화면을 안 만진다 |

⚠️ **검사에서는 전부 멈춘다** (`motionFrozen`). Robolectric 의 `Build.FINGERPRINT` 로 스스로 알아차리므로
검사 파일을 고칠 필요가 없다. 대신 **멈춘 것은 검사되지 않는다** — 트러블슈팅 6-19.

### 4-14. 무대 배치 — 깊이 한 칸이 높이와 크기를 정한다 (9/23)

`docs/무대_배치_규칙.md` 의 구현이다. 조장 지적 *"캐릭터가 중앙에 붕 떠 있다"* 를 고쳤다.

```
WorldItem(art, xf, yf, wf, shake, depth)
                  ↑          ↑     ↑
           가로 가운데   크기 견줌  1 = 앞줄 · 0 = 지평선
```

`depth` 하나가 **발 높이(0.62H→0.84H)와 키(0.30H→0.58H)** 를 같이 정하고, 발밑에 접지 그림자를 깐다.
배경을 한 번 더 깔아 발끝을 풀에 묻는다(우주·바닷속 제외).

- **발 높이는 비율이 아니라 크롬에서 뺀다** — `min(0.84H, H − BottomChrome)`.
  말풍선이 아래 76dp 를 쓰므로, 비율로 두면 세로가 짧은 기기에서 발이 말풍선 밑으로 들어간다

### 4-23. 약관 동의 — 국내 앱 방식 · 판이 바뀌면 다시 (10-05)

`ui/shell/Terms.kt` · `Onboarding.kt` 의 동의 단계. 토스 · 카카오 · 당근 · 배민 같은 국내 앱 동의 화면을 보고 맞췄다.

- 선택 항목은 **미리 체크하지 않는다.** 소식 알림은 따로 받고 동의한 날을 토스트로 알린다(정보통신망법 제50조)

- 동의한 판(`TERMS_VERSION`, 지금 `"2026-10-05"`)을 저장한다. 판이 오르면 **이미 동의한 보호자도** 타이틀 뒤에 다시 동의한다
- 문구는 `docs/공개용_개인정보처리방침.md`(조장 10-05판)를 따른다 — 그 문서가 바뀌면 여기도 바꾸고 판을 올린다. 계정 탭에서 약관 다시 보기 · 소식 알림 켜고 끄기

### 4-25. 탈퇴 — 막히지 않는 본인 확인 · 폰 안 데이터는 목록으로 지운다 (10-05)

### 4-26. 동의 · 마이크는 **계정마다** — 안드로이드 버전에 따라 다르다 (10-05)

- 고른 것은 [저장하기] 전까지 초안이고, 저장한 이야기 · 질문은 수정 · 삭제할 수 있다. **앱을 껐다 켜도 남는다**(`CoopPlanStore` · `coop_plan`)

- 오또의 반응은 서버의 받아주기 · 되돌려주기(`CoopServerLine`) — 못 쓸 조각(빈 · 거친 · 질문 · 자리표시자 · 너무 긴)은 버리고 앱의 짧은 받아주기(`coopAck`)로 돌아간다
- 책 문장은 `/story` 가 쓴다(고른 이유별로 프롬프트가 갈린다 · 고른 장소 안의 자리를 무대로). 실패하면 앱 문장
- 질문 블록(`CoopHeard` · `CoopGuard` · `CoopQuestions` · `CoopReact` · `CoopSignals`) — 들은 이름을 다음 질문에 넣고, 엉뚱한 답을 가드하고, 따라 묻고, 같은 받아주기를 두 번 연달아 하지 않는다. 판정이 두 번 거절해도 **아이 말은 지우지 않는다**

**책장** (`demo/CoopBookStore.kt`)
- 같이 만들기 책은 **따로 저장**(`coop_books` · 12권 · 동화 책장과 섞지 않는다). 쪽 재료(`CoopBookSnapshot`)를 같이 남겨 다시 열면 **만들 때와 같은 책**(그림 · 읽어 주기 · 미션 쪽)으로 열린다.

- 부모 리포트 말은 고른 이유와 부모 질문을 썼는지로 가른다(`CoopReport`) — 「곧 해요」 이야기를 다녀온 것처럼 쓰지 않게

쪽 문장은 **앞 쪽의 결과를 받아 다음 쪽을 연다**("하지만 …" · "게다가 …" · "그다음 …" · "이번엔 달랐어요!").

### 4-6. 아이 답 = 글 + 그 말이 뜻하는 값 → 책이 매번 다르다

| 고르는 것 | 어디에 쓰이나 |
| --- | --- |
| 함께 하는 사람 (녹음) | 모든 호칭 · 말투(할머니 · 할아버지 높임 · 친구 말투) · 참여 질문 · 표지 · 마지막 쪽 그림 · 부모 기록 |
| 장소 (우주 · 바닷속 · 공룡 나라 · 눈 오는 데) | 배경 · 배경 속 것 · 탈것 · 사건 · 새 친구 후보 · 지나갈 곳 · 도착할 곳 · 책 · 제목 |
| "거기엔 뭐가 있을까?" | 배경 그림 속 그 자리가 반짝 → 이후 모든 장면 · 책에서 계속 |
| 새 친구 (외계인 · 운석 · 문어 …) | 창문 장면 · 그림판 대상 · **미션 1 흔적과 도구** |
| 까닭 (심심 · 장난 · 길 잃음 …) | **템플릿 갈래 · 속성** · 친구의 말 · 미션 2 안내 |
| 이야기 잇기 답 (대응 · 도움 · 필요 · 역할 · 시도 · 실패 · 결과 · 깨달음 · 지나간 곳 · 본 것) | 그 템플릿의 쪽 문장 · 제목 |
| 이름 · 그림 | 이름 사전 · 자막 · 표지 (그림은 AI로 다시 그리지 않음, 27) |
| 공룡 · 색 · 소리 | 마지막 쪽 · 누르면 녹음 소리 (색은 생성 없이 색상만 회전, ⭐26) |
| 해결 방법 | 미션 2에서 건넬 물건 · 마지막 쪽 문장 · 해결 방법 도감 |
| 함께 하는 사람의 답 | 마지막 쪽 한 줄 · 함께하기 기록 (답이 없으면 아무 데도 안 들어감) |

### 4-7. 배경은 "있는 그림을 살린다" · 그림은 "있으면 쓰고 없으면 그린다"

- 배경마다 **이미 그려진 것** 6~9곳을 좌표로 정해 둔다(`HOTSPOTS`). 화면에 잘려 깔린 배경(Crop)과 같은 계산으로 자리를 맞추고, 그 자리의 **배경 조각**을 통 튀게 하고 둘레에 금빛 고리 · ✨ 를 띄운다. **새 그림은 얹지 않는다.**
- `AssetImage(이름) { 대신 그릴 것 }` — `res/drawable`에서 이름으로 찾고, 없으면 벡터 그림으로 대신 그린다.

### 4-8. 이야기 모드 셋 — 같은 엔진, 다른 물음 (v0.10 ~ v0.12)

시작 화면에서 셋 중 하나를 고른다. **질문 엔진(`Director.ask`)은 셋이 똑같이 쓴다.**
다른 것은 *무엇을 묻는가*와 *누가 읽는가*뿐이다.

| 모드 | 무엇을 묻나 | 걸음 | 책 |
| --- | --- | --- | --- |
| **동화** (`STORY`) | 상상 — 어디로 갈까 · 누가 흔들었을까 · 같이 갈 친구 · 소리 | 장면 19개 대본 (`Scenes.kt`) | 수준별 템플릿 7종 (A B C D E F G) · 6~8쪽 |
| **일기** (`DIARY`) | **오늘 진짜 있었던 일** — 어디 갔었어 · 무슨 일이 있었어 · 왜 그랬을까 · 어떻게 됐어 | 열한 걸음 (`DIARY_STEPS`) | 기승전결 한 장 (`diaryTemplate`) · 6~8쪽 |
| **부모 협업** (`COOP`) | 일기와 **같은 열한 걸음** | 같음 | 같음 (쪽마다 누가 지었는지 작은 표시) |

**일기 모드가 동화 모드와 다른 점**

- 묻지 않는 칸이 있다 — `sound`(공룡 소리는 상상 세계의 것) · `adult` · 탈것 · 동행 친구 (일기 설계 §2-2)
- **답을 고르게 하지 않는다.** 말이 없으면 그림 카드 3장을 띄우는 대신 **질문을 바꿔 다시 묻는다**(사다리).
  일기에서 카드 3장은 앱이 아이 하루를 *추측해* 보여 주는 것이 되기 때문이다 (§7-6)
- **지어내지 않는다.** 사다리를 다 내려와도 칸이 비면 비운 채로 간다. 특히 장소 —
  아이가 가지 않은 곳이 그 아이의 하루로 적히면 안 된다 (§3-2)
- 끝나는 조건이 셋이다 — 기승전결 네 자리가 다 참(`story_ready`) · 마스코트가 두 번 연속 대신 채움 · 15분 경과

**부모 협업 모드가 일기 모드와 다른 점 — 딱 하나**

질문을 **마스코트가 소리 내어 읽지 않는다.** 질문은 화면 아래 **부모 띠**에 뜨고, 어른이 읽고 *자기 말로* 묻는다
(협업 설계 §2-1 ASK′). 마스코트가 읽어 주면 부모가 물을 이유가 없어지기 때문이다.
4~5세는 글을 못 읽으므로 아이는 위쪽 그림을, 부모는 아래쪽 글자를 본다. 띠 왼쪽에 마스코트가 서 있어
아이에게는 "마스코트가 물어본다"로 보인다.

> **9/21에 뺀 것** — 띠에 [다르게 물어볼래] · [내가 답할래] 두 버튼이 있었다. 버튼을 고르는 것이 일이 되어
> 아이와 이야기하는 흐름이 끊겼고, 그 버튼이 보내던 값(`coop:adult`)이 칸으로 새어 화면에 글자 그대로 나오기도 했다.
> 지금 띠는 **읽을 것만 보여 준다.** 질문을 바꾸는 것도 마지막에 채우는 것도 동화 모드와 똑같이 마스코트가 한다.

**출처는 `by` 세 가지뿐이다** — `child`(아이가 말함) · `card`(탭 · 그림) · `mascot`(마스코트가 대신 채움).
협업 모드에서 부모가 한 말도 **`by: parent` 를 새로 만들지 않고** `payload.speaker: adult` 로만 남긴다 (협업 §4-1 · §8).

### 4-9. 책이 아이 말과 어긋나지 않게 (v0.12)

책은 아이가 말한 것으로만 서야 한다. 9/21에 어긋나 있던 네 곳을 맞췄다.

| 어긋나 있던 것 | 어떻게 맞췄나 |
| --- | --- |
| 어디를 가든 **공룡**이 따라왔다 | `Theme.buddies` — 장소마다 같이 갈 친구 셋 (우주: 외계인 친구 · 로봇 · 아기 별 / 바닷속: 돌고래 · 해마 · 불가사리 / 공룡 나라: 그대로 / 눈 오는 데: 눈사람 · 북극곰 · 펭귄). 아이가 먼저 하는 말도 소리도 같이 바뀐다 |
| 일기 미션이 **뜬금없었다** | 소품을 ① 아이가 말한 일 ② 장소 ③ 둘 다 없으면 **지어내지 않고 하루 먼지** 순으로 고른다 |
| 책이 **거꾸로** 읽혔다 | 승(承) 쪽이 일어난 일을 먼저 쓰고 하던 일을 뒤에 붙였다. **하던 일 → 그런데 → 일어난 일** 순으로 놓고 잇는 말을 넣는다(`joinWith`) |
| 적힌 대로 **움직이지 않았다** | 쪽 자막에 "타고"가 있으면 탈것 위에 올리고, "손을 흔들"이 있으면 몸을 흔든다 |

배경도 같은 규칙이다. 일기 모드는 아이가 말한 장소에 맞는 그림을 고르고(`DIARY_PLACES` 10곳),
**어디에도 안 맞으면 엉뚱한 장소를 보여 주지 않는다** — 농장에 갔다는 아이에게 놀이터를 보여 주면
앱이 하루를 지어내는 셈이다. 9/22에 **어디라고 말하지 않는 `bg_today`** 를 만들어 그 자리에 넣었다
(그전에는 이름만 있고 파일이 없어 **배경이 통째로 비어 보였다**).

### 4-10. 그림이 **글을 따라간다** — 쪽 종류가 아니라 적힌 내용이 정한다 (v0.13)

v0.12에서 "타고" · "손을 흔들"을 읽어 자세를 정하게 했는데, 9/22에 그 원리를 **소리말과 움직임까지** 넓혔다.
계기는 일기 모드의 「오늘 있었던 일」 쪽이 동화 모드의 「흔들림」 쪽과 **같은 자리(`PageKind.SHAKE`)** 를
쓴다는 것이었다. 쪽 종류로 연출을 정하니 **그림 그린 날에도 "쿵!" 이 뜨고 화면이 흔들렸다.**

| 읽는 것 | 무엇을 정하나 | 맞는 게 없으면 |
| --- | --- | --- |
| `ridingFrom` | 탈것 위에 올릴지 (**자리**) | 옆에 세운다 |
| `wavingFrom` | 손을 흔들지 | 가만히 |
| `effectFrom` | 소리말 (`와르르! · 쿵! · 촤악! · 훌쩍… · 까르르!` …) | **아무것도 안 띄운다** |
| `quakeFrom` | 화면을 흔들지 | 안 흔든다 |
| `motionFrom` | 자세 (그네 · 미끄럼틀 · 뛰기) | 가만히 |

**두 가지를 못 박았다.**

- **없는 것을 지어내지 않는다.** 맞는 소리말이 없으면 안 띄운다. 일기 §3-2의 "앱이 아이 하루를 추측하지 않는다"와 같은 판단이다
- **어긋난 쪽에서는 움직이지 않는다.** "달리다가 넘어졌어요" 가 '달리'에 걸려 통통 뛰면 넘어진 이야기가 신나는 그림이 된다. 웃거나 우는 쪽을 안 흔드는 것도 같은 이유다 — 아이가 무서워한다

⚠️ **동화 모드가 잃은 게 없는지 검사로 지킨다.** 전에는 무조건 "쿵!" 이었으므로, 템플릿 다섯의
흔들림 쪽이 전부 소리말을 얻고 흔들리는지 본다(`theSoundWordComesFromTheCaptionNotThePageKind`).

### 4-11. 보여 주는 시간은 **보여 주는 자리**에서 잰다 (v0.13)

상호작용 원(배경 속 누를 수 있는 것)은 **책을 편 처음 4.5초만** 반짝인다. 처음에는 "여기 눌러 볼 수 있어"
를 알려 주는 좋은 신호지만, 계속 반짝이면 그림 읽기를 방해하고 아이 눈이 그리로만 간다.

이것을 세 번 고쳐서야 제대로 돌았다. 남은 규칙 셋:

| | |
| --- | --- |
| **시간은 `HotspotLayer` 가 잰다** | 부르는 쪽(`BookPageView`)에서 쟀더니 **배경이 없는 표지를 보는 동안 시간이 갔다.** 원이 뜨기도 전에 안내가 끝났다 |
| **소개는 일부러 켜야 켜진다** (`introducing` 기본값 `false`) | 기본값을 `true` 로 두었더니 안 넘긴 호출부 하나 때문에 **질문 화면부터 전부 반짝였다** |
| **소개할 때는 자리를 전부 보여 준다** | 아이가 말한 것만 켜면 일기·협업에서는 겹치는 낱말이 없는 날이 많아 **안내가 아예 안 떴다** |

역할이 둘로 갈린다 — `introducing`(전부 반짝 = 안내 · 책)과 `glowMentioned`(아이가 말한 것만 · 질문 화면).

### 4-12. 진행 막대는 **물은 질문 수**로 찬다 (v0.13)

전에는 필수 칸(일기 4 · 동화 6)을 셌다. 그런데 실제로 묻는 질문은 일기가 열 걸음 남짓, 동화가
필수 여섯에 템플릿 질문 서넛이다. **질문을 여러 개 답해도 막대가 안 움직이다가 한 번에 껑충 뛰었다.**

바꾸고 나서도 두 번 더 어긋났다 — 기준을 맞추는 일이었다.

1. **마지막 질문에서 안 찼다.** 꼬리질문은 `turn` 을 안 올리는데 총량에는 세었고, 동화 모드의
   `resolve` 는 `slots` 가 아니라 `solution` 으로 들어가 **절대 안 차는 칸**이 하나 있었다
2. **3턴째에 뒤로 물러났다.** 템플릿이 그때 정해져 분모가 6 → 9로 늘면서 비율이 줄었다

지금은 **지나온 걸음 수**(`stepsDone`)로 세고, 이야기가 끝나면(`endReason`) 끝까지 찬다.
템플릿이 정해지기 전에는 분모를 최대치로 잡아 두고, 분모가 줄어도 막대가 뒤로 가지 않는다.

⚠️ **끝나는 조건은 그대로다.** `story_ready` 는 여전히 기승전결 네 자리(`filled` · `reqCount`)가 정한다.
여기서 바꾼 것은 **보이는 막대뿐**이다 (일기 §3).

## 5. 마이크 — 온/오프, 시간 제한 없음

🎤를 누르면 듣기 시작(파형), 다시 누르면 끝. **기다리는 시간 제한이 없다.** ➡️는 "말 없이 넘김"(= 무응답).

데모에는 진짜 음성 인식이 없으므로 **마이크를 끄는 순간** 그 질문의 더미 답 하나가 들어간다
(서랍의 더미 아이 수준을 따름). 서랍의 대본 버튼으로 특정 답을 고를 수도 있다.

> **(10-05 바뀜)** 서버가 켜진 모드는 진짜 받아쓰기를 한다 — `net/Voice.kt` 가 Silero VAD 로 말이 끝난 뒤 500ms 에 끊어 `/stt` 로 보낸다(§0).
> 위 더미 답은 서버가 꺼진 모드(스토어 빌드 · 검사 · 서랍에서 끈 모드)의 동작이다.

실제 앱 규칙(⭐5 · 쉬운 5초 · 어려운 8초 · 선택지 7초)은 서랍의 **"무응답 타이머 켜기"** 로 볼 수 있다.

  에뮬레이터를 GPU 가속으로 띄우면 **드라이버가 멈춰 데스크톱 전체가 언다.** 전원 버튼 말고는 방법이 없다

- 새 그림은 `res/drawable`에 이름 그대로 넣으면 코드 수정 없이 바로 쓰인다 · **넣은 뒤 `shrink_assets.py` 를 돌린다**
  (1024px 그대로 두면 한 장에 1MB씩이라 금세 100MB가 넘는다)
- **배경을 새로 뽑으면 `HOTSPOTS` 좌표도 다시 잡는다** (트러블슈팅 3-12)

### 일기 모드 · 부모 협업 모드의 걸음 (v0.10 ~ v0.12 · §4-8)

동화 모드의 장면 번호 대신 **기승전결 네 자리 + 꼬리질문**으로 간다. 한 걸음 = 칸 하나 + 사다리 하나.

| 자리 | 걸음 | 묻는 것 | 기승전결 |
| --- | --- | --- | --- |
| 기 | 장소 ★ | "오늘 어디 갔었어?" — 여기서 **배경이 아이가 말한 곳으로 바뀐다** | 필수 |
| 기 | 같이 있던 사람 | "거기 누구랑 있었어?" — 뒤 질문이 물을 데를 얻는다. **사람은 지어내지 않는다** | 꼬리 |
| 승 | 무슨 일 ★ | "○○에서 무슨 일이 있었어?" — 앞 답을 되받아 잇는다 | 필수 |
| 승 | 하던 일 | "그때 ○○는 뭐 하고 있었어?" — 책에서 **일어난 일보다 앞에** 놓인다 | 꼬리 |
| 승 | 마음 | "그때 기분이 어땠어?" — 이미 말했으면 묻지 않는다 | 꼬리 |
| 전 | 까닭 ★ | 어긋난 날이면 "왜 그렇게 됐을까?", 즐거웠던 날이면 "그게 왜 제일 좋았어?" | 필수 |
| 전 | 남의 말 | "○○가 뭐라고 했어?" — 사람이 나온 날에만 묻는다 | 꼬리 |
| 전 | **내가 한 일** | "그래서 ○○는 어떻게 했어?" — 어긋난 일과 끝 사이를 잇는다 (v0.12에 더함) | 꼬리 |
| 결 | 어떻게 됐어 ★ | "그래서 어떻게 됐어?" — ⚠️ 순차 답("가서 밥 먹었어")을 까닭으로 세지 않는다 | 필수 |
| 결 | 집에 와서 | "집에 와서는 뭐 했어?" | 꼬리 |
| 맺음 | 내일 | "내일 또 하고 싶은 거 있어?" | 꼬리 |

★ = 기승전결 네 자리. 이 넷이 다 차면 `story_ready` 로 끝난다.
그리기는 질문마다 붙이지 않고, **오늘 만난 사람을 그리는 걸음 하나**에만 둔다 (부모 리포트의 '만들기' 축도 그 걸음이 채운다).

| --- | --- | --- | --- |

## 8. 회의에서 정할 것 · 알려진 제한

1. **구현대본과 다르게 간 곳 (9/17 요청)** — 장면 3 그리기 없음 · 장면 4 카드 없음 · 제목 자동 · 미션이 대화 기준 · 설정 항목 ·
   **함께 하는 사람을 녹음으로 묻기(장면 1↳)** · **이야기 잇기 장면(6↳)** · **책 6~8쪽** · **배경 오브젝트 대신 배경 속 것**. 시나리오 문서 부록 E → **조장 확인**
2. **템플릿 B(오해-화해형)는 쓰지 않는다** — 조사2 표에서 수준이 아니라 속성(상황 이해)에 묶여 있어 데모의 수준 → 템플릿 표에 넣지 않았다. F(일상형)도 마찬가지
3. **더미 답의 한계** — 수준 흉내는 70% 확률이라 흉내 수준과 다르게 판단될 수 있다(그것 자체가 규칙 시연). 실제 판단은 LLM 표시 + 규칙
4. **주인공 조합 27장**은 데모 전용 대역 (실제는 ⭐20 생성)
5. 데모에 없는 것: 저장(앱 끄면 초기화 — "지난 이야기에서 쓴 질문"도 사라짐) · 책장에서 다시 읽기 · 책 이름 바꾸기 · 동의 화면 · 업적 전체 · PDF · 그림체 3종의 실제 그림
6. D · G 템플릿은 기기에서 끝까지 돌리지 않았다 — 글자 검사 테스트로만 확인 (변경이력 v0.9 확인)
7. **일기 모드의 장소 그림은 미리 만든 10곳뿐이다** — 실제 앱은 아이가 말한 장소로 배경을 그때그때 만든다(규칙 8 · §6).
   데모는 그럴 수 없어 흔한 열 곳을 미리 뽑아 두고 낱말로 고른다. 어디에도 안 맞으면 **엉뚱한 장소를 보여 주지 않고** 색 배경으로 간다
8. **협업 모드의 `adult` 칸은 지금 비어 있다** — [내가 답할래] 버튼을 뺐기 때문이다(§4-8). 부모가 읽어 준 질문은
   `payload.speaker: adult` 로 남고 부모 리포트의 "어른이 한 말"이 된다. 어른이 칸을 직접 짓는 흐름이 필요하다면 **회의에서 다시 정한다**

> **(10-05 바뀜)** 5번의 「저장 · 책장에서 다시 읽기 · 동의 화면」은 이제 있다 — 책장은 폰 안에 저장되고(모드별 12권) 다시 열 수 있으며, 약관 동의 화면이 처음 설정에 있다(§0 · §4-23 · §4-31).

9. **서버에 계정이 없다** — 보호자 계정은 폰 안(`otto_account`)에만 있다(`LocalAccountApi`). 다른 폰에서 같은 이메일로 로그인할 수 없고,
   「서버 계정 즉시 삭제」도 지금은 폰 안 기록을 지우는 것이다. 이메일 비밀번호 다시 정하기도 메일 링크가 아니라 앱 안에서 바로 바꾼다. 서버 자리는 `ServerAccountApi`(TODO) (§4-22)
10. **안드로이드 12 이하는 마이크 권한을 앱이 돌려줄 수 없다** — 로그아웃 · 탈퇴해도 휴대폰 마이크 권한은 켜진 채라 탈퇴 마지막 화면에서 「설정에서 끄기」를 안내만 한다.
    시험할 때는 설정 → 앱 → 권한 또는 `adb shell pm revoke` 로 끈다 (§4-26)
11. **이용약관은 법무 검토 전 초안이다** — 처리방침은 조장 10-05판을 따르지만, 출시 전에 검토를 받아야 한다. 문구가 바뀌면 `TERMS_VERSION` 을 올린다 (§4-23)
12. **앱 밖에서 탈퇴를 요청할 웹 페이지가 없다** — 탈퇴는 앱 안(부모 영역 → 계정)에서만 할 수 있다. Google Play 는 계정을 만들 수 있는 앱에 **앱 안과 앱 밖(웹 페이지) 둘 다**에서 삭제를 요청할 길을 요구하고, 그 주소를 Play Console 에 적어야 한다 — 계정이 생기는 #119 빌드를 올리기 전에 조장이 맞추기로 했다(10-05 리뷰)
13. **로그인 키가 없으면 소셜 로그인이 안 된다** — 디버그는 「개발용」 가짜 계정, release 는 「준비 중」. 스토어 빌드의 카카오는 `OTTO_KAKAO_APP_KEY_STORE` 가 따로 있어야 한다 (§1)
14. **스토어(release) 빌드는 서버를 쓰지 않는다** — 처리방침 · 데이터 보안이 먼저라 대본으로 돈다. 서버 연결은 디버그 빌드(「오또 개발」)만 (§0)
15. **살아 있는 배경은 시험판이다** — 공원 조각에서만 확인했고, 책 · 같이 만들기 무대로는 아직 넓히지 않았다 (§4-33)
