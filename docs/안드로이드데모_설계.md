## 0. 이 데모가 무엇이고, 무엇이 아닌가

**맞다**: 구현대본의 화면 S1~S12를 폰에서 손으로 만져 볼 수 있게 만든 **흐름 확인용 앱** (장면 16개 + 곁장면 3개).
아이가 말한 것으로 **수준을 판단하고, 수준에 맞는 동화 템플릿(6~8쪽)** 을 골라 책 · 미션을 만들고, 책장에 꽂히는 것까지 실제로 동작한다.

**아니다**: 서버도, 음성 인식도, LLM도, 저장소도 없다. 앱을 끄면 전부 초기화된다.
아이 답은 질문마다 준비된 **더미 답(질문당 4~9개, 수준 ①②③ 표시)** 중에서 들어간다(진짜 Whisper 대신).
시연 서랍에서 **"고르며 · 이어 · 까닭 짓기처럼"** 을 고르면 그 수준의 답이 70%로 나온다.

**왜 HTML 데모 말고 앱인가**: 19번 결정(Kotlin 네이티브)에 맞춰, 실제로 만들 때 쓸 구조를
미리 잡아 두려고. 엔진(`demo/`)과 화면(`ui/`)이 나뉘어 있어서 진짜 STT · LLM을 붙일 때
`Director.ask()`(말 받기)와 `judge()`(신호 표시)만 바꾸면 된다.

## 1. 팀원이 받아서 여는 법

1. 압축 파일을 풀고 폴더를 **Android Studio에서 `Open`** (`File → Open` → `finalproject_demo` 폴더)
2. 처음 열면 Gradle이 라이브러리를 받는다(인터넷 필요, 3~5분). `local.properties`는 각자 스튜디오가 자동으로 만든다
3. 에뮬레이터나 폰을 연결하고 ▶ Run

터미널만 써도 된다.

```
gradlew installDebug
adb shell am start -n com.example.finalproject_demo/.MainActivity
gradlew :app:testDebugUnitTest --tests "*StoryTextTest*"   # 책 문장 검사 (결과: app/build/story_samples.txt)
```

**가로 전용**이므로 에뮬레이터를 가로로 돌려 놓는다. 세로면 화면이 잘린다.

```
adb shell settings put system accelerometer_rotation 0
adb shell settings put system user_rotation 1
```

## 2. 그림 파일은 어떻게 공유되나 *(질문받은 것)*

**압축해서 보내면 팀원 화면에도 똑같이 보인다.** 그림은 내 PC가 아니라 **프로젝트 안에** 있다.

- 위치: `app/src/main/res/drawable/*.png` (122장)
- 앱을 빌드할 때 APK 안에 함께 들어간다 → 인터넷도, ComfyUI도 필요 없다
- **ComfyUI는 그림을 다시 뽑을 때만** 필요하다. 그냥 돌려 보는 데는 전혀 필요 없다

### 압축할 때 반드시 빼야 하는 것

| 빼는 것 | 왜 |
| --- | --- |
| `build/`, `app/build/` | 빌드 산출물. 각자 다시 만든다 (이것만 **436MB**) |
| `.gradle/`, `.idea/`, `.kotlin/` | 내 PC 전용 캐시 · 설정 |
| `local.properties` | 내 PC의 Android SDK 경로가 박혀 있다. 팀원 스튜디오가 자동 생성한다 |

빼면 **20MB대**, 안 빼면 **500MB가 넘는다**. `.gitignore`에 이미 다 적혀 있으니 git으로 주고받으면 자동으로 걸러진다.

**이미 만들어 뒀다: `C:/Android/finalproject_demo_공유.zip` (v0.9 · 크기는 변경이력 참고).**
안에 `docs/` 폴더가 있고, 이 문서를 포함한 문서 4개가 들어 있다.
다시 만들려면:


## 4. 설계 — 원리 7가지

### 4-1. 감독(Director)이 대본을 "읽어 내려간다"

각 장면은 **중단 가능한 함수(suspend fun)** 하나다. 장면을 옮기면 이전 장면의 코루틴이 취소되므로 상태가 섞이지 않는다.

```kotlin
private suspend fun Director.scenePlot() {
    val t = s.template!!                    // 3턴째 정해진 템플릿
    for (slot in t.plot) {                  // 예: C → ["response", "helper"]
        val (_, r) = askSlot(slot)          // 은행에서 변형을 골라 묻고 판단까지
        valueOf(r)?.let { s.slots[slot] = it }   // 답이 그대로 책 문장 재료
    }
    go(Scene.DINO)
}
```

### 4-2. 질문 하나가 무응답 흐름을 통째로 안다

`ask(Question)` 하나에 ⭐5 · ⭐22 흐름이 다 들어 있다. 질문은 소크라틱 — 선택지를 말하지 않고, 말이 없어도 **생각할 거리(힌트)** 를 먼저 준다.

| 질문 종류 | 카드 | 무응답일 때 |
| --- | --- | --- |
| **열린 질문 · `noCards`** (누가 흔들었을까 · 뭐가 있을까 · 이름 · 이야기 잇기 · 기분 · 소리) | 없음 | 쉬운 질문 → 힌트 질문 → `fallback`이 있으면 "혹시 ○○일까?" (source=mascot) |
| **열린 질문 · 카드 준비** (장소 · 까닭 · 해결 · 바꿀 곳 · 주인공 속성) | 무응답 뒤에만 | 쉬운 질문 → **그때** 카드 3장(7초) → 교체 최대 3번 → 마스코트가 고름 |
| **CHOICE** (장면 7 "공룡? …" 모호한 말 확인만) | 질문과 함께 바로 | 다시 읽기 1 → 교체 최대 3번 → 마스코트가 고름 |
| **함께 하는 사람** (장면 1↳) | **없음 — 녹음만** | 다른 말로 두 번 더 → 그래도 없으면 "엄마"로 두고 진행 |
| **`askPartner`** (장면 10 참여) | 없음 | **대신 채우지 않는다** — null · 책에도 넣지 않음 |

- 함께 하는 사람만 말하면 **2.5초** 뒤 "○○는 어떻게 생각해?"를 한 번 (⭐5 · 구현대본 §0-2) — 장면 5는 늘 이 흐름
- 이야기 턴이 8을 넘으면 남은 칸을 마스코트가 채우고 책으로 간다 (`budgetOver()`)

### 4-3. 질문 은행 — 처음 두 질문만 고정, 나머지는 매번 다르게

```kotlin
QVariant("c_resp_how", slot = "response", levels = {이어, 까닭}, kind = HARD,
    probe = "'어떻게' 질문에 방법을 담나 (S1)",
    text = { "어떻게 하면 ${f}가 흔드는 걸 멈출까?" },
    answers = { listOf(
        Answer("말해!", "그만해!", lv = 1),
        Answer("그만하라고 말해.", "그만해 줘!", reason = true, lv = 2),
        Answer("손을 들고 멈춰! 하고 말해. 그러면 알아들어.", "멈춰! 손 들었지?", reason = true, el = {"결과"}, con = true, lv = 3), …) })
```

- 칸(slot)마다 변형 2~6개 · 변형마다 더미 답 4~7개 · 수준 ①②③이 섞여 있다
- 고르는 순서: **지금 수준에 맞는 것 → 이번 이야기에서 안 쓴 것 → 지난 이야기에서 안 쓴 것 → 가장 오래전에 쓴 것**
- 여러 템플릿이 함께 쓰는 칸(해결)은 **지금 템플릿의 변형만** (id 앞머리 `e_ c_ d_ a_ g_`)
- 가정 질문(`hypo`) · 돌아보기(`reflect`)는 **까닭 짓기일 때만** (역할1 조사2 #5)

### 4-4. 발달 판단 — 규칙이 계산한다 (역할1 조사2 §3~4)

답마다 표시가 붙어 있다: `reason`(S1: 왜 · 어떻게에 까닭 · 방법) · `el`(S2: 묻지 않은 배경 · 계기 · 시도 · 결과) · `con`(A1: 잇는 말) · `emo`(마음 — 신호 아님) · `kind`(까닭 종류).
실제 앱에서는 LLM이 이 표시만 달고, **수준은 규칙이 계산**한다.

| 규칙 | 내용 |
| --- | --- |
| 세는 것 | 말로 답한 이야기 턴만 (탭 · 그림 · 마스코트 · 마음 질문 · 이름 · 소리는 안 셈) |
| 올림 (2턴 연속) | 고르며 → 이어: S1 **또는** S2 / 이어 → 까닭: S1 **그리고** 구조(계기 · 시도 · 결과 또는 잇는 말) |
| 내림 (2턴 연속) | 카드 · 무응답 · 마스코트 · 두 어절 이하에 신호 없음 |
| 템플릿 확정 | **3턴째**(장소 · 누가 · 까닭 뒤) — 그 뒤 이동은 질문 난이도와 다음 세션 시작점만 |
| 세션 누적 추정 | S1 ≥ 2 & 요소 ≥ 2 → 까닭 / 짧은 답 · 카드 ≥ 60% & 신호 없음 → 고르며 / 나머지 → 이어 |
| 부모에게 | 수준 이름은 보이지 않는다 — 6축 기록(이유 말하기 · 이야기 채우기 …)으로만 |

### 4-5. 수준별 템플릿 · 6~8쪽 (역할1 조사2 표 #1 · 역할2 · 결정 13)

| 수준 | 까닭 종류 | 템플릿 | 쪽 | 속성 |
| --- | --- | --- | --- | --- |
| 고르며 짓기 | 무엇이든 | **E 여정형** — 길 나섬 → 지나감 → 도착 · 되풀이 말 | 6 | 체험 |
| 이어 짓기 | 심심 · 놀고 싶음 · 인사 · 장난 · 힘자랑 | **C 위험-대응-도움형** — 위협 → 대응 → 믿는 사람에게 알림 → 해결 | 7 | 상황 이해 / 교훈 |
| 이어 짓기 | 길 잃음 · 배고픔 · 다침 | **D 방문자-직업수행형** — 어려움 → 맡은 일로 도움 → 해냄 | 7 | 직업 체험 |
| 까닭 짓기 | 장난 · 힘자랑 | **G 우화-교훈형** — 뽐냄 → 곤란 → 깨달음 → 화해 | 8 | 교훈 |
| 까닭 짓기 | 그 밖 | **A 도전-성취형** — 시도 → 실패 → 다시 시도 → 성공 | 8 | 상황 이해 |

쪽마다 종류가 있다: 출발 · 흔들림 · 대화 · 여정 · 실패 · 문지르기(미션 1) · 끌어다 놓기(미션 2) · 함께.
쪽 문장은 **앞 쪽의 결과를 받아 다음 쪽을 연다**("하지만 …" · "게다가 …" · "그다음 …" · "이번엔 달랐어요!").

### 4-6. 아이 답 = 글 + 그 말이 뜻하는 값 → 책이 매번 다르다

| 고르는 것 | 어디에 쓰이나 |
| --- | --- |
| 함께 하는 사람 (녹음) | 모든 호칭 · 말투(할머니 · 할아버지 높임 · 친구 말투) · 참여 질문 · 표지 · 마지막 쪽 그림 · 부모 기록 |
| 장소 (우주 · 바닷속 · 공룡 나라 · 눈 오는 데) | 배경 · 배경 속 것 · 탈것 · 사건 · 새 친구 후보 · 지나갈 곳 · 도착할 곳 · 책 · 제목 |
| "거기엔 뭐가 있을까?" | 배경 그림 속 그 자리가 반짝 → 이후 모든 장면 · 책에서 계속 |
| 새 친구 (외계인 · 운석 · 문어 …) | 창문 장면 · 그림판 대상 · **미션 1 흔적과 도구** |
| 까닭 (심심 · 장난 · 길 잃음 …) | **템플릿 갈래 · 속성** · 친구의 말 · 미션 2 안내 |
| 이야기 잇기 답 (대응 · 도움 · 필요 · 역할 · 시도 · 실패 · 결과 · 깨달음 · 지나간 곳 · 본 것) | 그 템플릿의 쪽 문장 · 제목 |
| 이름 · 그림 | 이름 사전 · 자막 · 표지 (그림은 AI로 다시 그리지 않음, 27) |
| 공룡 · 색 · 소리 | 마지막 쪽 · 누르면 녹음 소리 (색은 생성 없이 색상만 회전, ⭐26) |
| 해결 방법 | 미션 2에서 건넬 물건 · 마지막 쪽 문장 · 해결 방법 도감 |
| 함께 하는 사람의 답 | 마지막 쪽 한 줄 · 함께하기 기록 (답이 없으면 아무 데도 안 들어감) |

### 4-7. 배경은 "있는 그림을 살린다" · 그림은 "있으면 쓰고 없으면 그린다"

- 배경마다 **이미 그려진 것** 6~9곳을 좌표로 정해 둔다(`HOTSPOTS`). 화면에 잘려 깔린 배경(Crop)과 같은 계산으로 자리를 맞추고, 그 자리의 **배경 조각**을 통 튀게 하고 둘레에 금빛 고리 · ✨ 를 띄운다. **새 그림은 얹지 않는다.**
- `AssetImage(이름) { 대신 그릴 것 }` — `res/drawable`에서 이름으로 찾고, 없으면 벡터 그림으로 대신 그린다.

## 5. 마이크 — 온/오프, 시간 제한 없음

🎤를 누르면 듣기 시작(파형), 다시 누르면 끝. **기다리는 시간 제한이 없다.** ➡️는 "말 없이 넘김"(= 무응답).

데모에는 진짜 음성 인식이 없으므로 **마이크를 끄는 순간** 그 질문의 더미 답 하나가 들어간다
(서랍의 더미 아이 수준을 따름). 서랍의 대본 버튼으로 특정 답을 고를 수도 있다.

실제 앱 규칙(⭐5 · 쉬운 5초 · 어려운 8초 · 선택지 7초)은 서랍의 **"무응답 타이머 켜기"** 로 볼 수 있다.

| --- | --- | --- | --- |

## 8. 회의에서 정할 것 · 알려진 제한

1. **구현대본과 다르게 간 곳 (9/17 요청)** — 장면 3 그리기 없음 · 장면 4 카드 없음 · 제목 자동 · 미션이 대화 기준 · 설정 항목 ·
   **함께 하는 사람을 녹음으로 묻기(장면 1↳)** · **이야기 잇기 장면(6↳)** · **책 6~8쪽** · **배경 오브젝트 대신 배경 속 것**. 시나리오 문서 부록 E → **조장 확인**
2. **템플릿 B(오해-화해형)는 쓰지 않는다** — 조사2 표에서 수준이 아니라 속성(상황 이해)에 묶여 있어 데모의 수준 → 템플릿 표에 넣지 않았다. F(일상형)도 마찬가지
3. **더미 답의 한계** — 수준 흉내는 70% 확률이라 흉내 수준과 다르게 판단될 수 있다(그것 자체가 규칙 시연). 실제 판단은 LLM 표시 + 규칙
4. **주인공 조합 27장**은 데모 전용 대역 (실제는 ⭐20 생성)
5. 데모에 없는 것: 저장(앱 끄면 초기화 — "지난 이야기에서 쓴 질문"도 사라짐) · 책장에서 다시 읽기 · 책 이름 바꾸기 · 동의 화면 · 업적 전체 · PDF · 그림체 3종의 실제 그림
6. D · G 템플릿은 기기에서 끝까지 돌리지 않았다 — 글자 검사 테스트로만 확인 (변경이력 v0.9 확인)

## 9. 시연 대본 (6분)

1. 첫 화면 → **[이야기 만들기]** → "오늘은 누구랑…?" → 🎤 **"할머니랑 같이!"** → 할머니 그림 · "할머니, 잘 부탁드려요!"
2. 서랍 🎮 **더미 아이 답 = 까닭 짓기처럼** → 도감에서 주인공
3. "오늘은 어디로 가 볼까?" → 🎤 → 도착 · 할머니 한마디 → "뭐가 있을까?" → **배경의 별 · 행성이 반짝, 눌러 보기**
4. "누가 흔들었을까?" → 이어 묻기 → 할머니가 먼저 말함 → "지호는 어떻게 생각해?" → 서랍 🧠 **발달 판단**에서 신호와 **템플릿 확정(A 8쪽)** 보여 주기
5. 가정 질문(까닭 짓기라서) → 그림판 → **이야기 잇기 "처음엔 어떻게 해 봤을까?"** → 공룡 · 소리 · 확인
6. 해결 → 돌아보기 → 마음 → **"할머니, … 뭘 도와주실래요?"** → 책 8쪽 — 실패 쪽 · 미션 2개 · 마지막 쪽 "할머니께서는 …"
7. 친구 평가 → 선물 → 책장 → 부모 모드 "할머니와 함께 · 8쪽"
8. [🏠 처음으로] → 서랍에서 **고르며 짓기처럼** → 다시 한 권: **다른 질문 · E 6쪽** 으로 달라지는 것
