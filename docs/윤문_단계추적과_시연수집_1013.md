# 윤문 단계 추적과 다음 성인 시연 수집

2026-10-13 · #462 · 조사 기준 `65396751`에서 동화 경로를 읽었다. 이후 확인한 main `5e1725bc`의 추가 변경은 협업·일기와 평가 기록이며 아래 동화 경로는 같았다. 기존 성인 시연 2권의 생성 당시 버전은 확인되지 않았으므로 이 코드가 그 두 결과를 만들었다고 단정하지 않는다.

## 기존 자료에서 확인된 것과 확인할 수 없는 것

사용자가 AI 대조 설명을 보고 해결 행동 변경 1건과 결말 누락 2건에 모두 동의했다. 두 책 모두 사전 등록한 핵심 정보 보존의 필요조건을 위반한다. 사람의 동의 범위는 그 세 항목이며 페이지 이해 점수·모호한 인물 귀속·미션 출처까지 승인한 것은 아니다. 실제 아동 효과나 독립 전문가 정답 대비 정확도로 해석하지 않는다.

기존 저장 자료는 앱에 기록된 응답 텍스트와 최종 책이다. 음성 전사 정답·최종 전체 슬롯·요청·생성 직후 자막·fallback·생성 당시 버전이 없다. 누락이 **최초 발생한 단계는 미확인**이다. 원본 대화와 전체 대조표는 로컬 개인 자료이며 이 저장소에 넣지 않는다.

## 수집 방식과 한계

개발 빌드에서 사용자가 직접 켰을 때만 `story_eval` 이벤트를 기존 `OttoTrace` 로그에 출력한다. 기본은 꺼짐이다. release에서는 켜도 출력되지 않는다. 책·리포트·초안 저장 schema는 바꾸지 않는다. 음성/그림 파일·인증 자료·주소·전체 환경설정·서버 오류 본문을 담지 않는다. **응답 텍스트 자체는 개인 자료이며 이름을 자동 비식별 처리하지 않는다.** 외부 게시 기능은 없다.

세션 ID, 순번, 생성 시도 ID로 연결한다. 긴 JSON은 Unicode 글자 경계를 유지해 여러 로그 조각으로 나눈다. 64KiB를 넘으면 `truncated=true`와 `omission_reason=payload_limit`, 자료 구성 자체가 실패하면 `omission_reason=observation_failed`로 표시하며 예외 본문을 담지 않는다. 사유 없는 구버전 불완전 조각은 `truncated_event`로만 표시한다. 수집 전체는 32MiB 상한이며 중단 사유를 남긴다. 파일 수집기는 순서가 뒤섞여도 조합하고, 유실·충돌·지원하지 않는 schema·한도 초과는 완전한 이벤트로 사용하지 않는다. 자연 EOF/연결 끊김과 읽기 실패도 표시하고 앞서 수집한 자료를 보존한다. 중간 활성화와 앱 복원은 새 수집 구간이며 이전 원문은 복원하지 않는다. 빠진 자료를 성공이나 오류 0건으로 채우지 않는다. Logcat은 저장소가 아니므로 PC 수집을 시연 전에 시작해야 한다.

앱 메타데이터의 실제 버전명/코드와 서버 연결 활성화 여부를 남긴다. 빌드 커밋·운영 서버 릴리스는 자동 확보되지 않으므로 `unknown`으로 남기고, 별도 배포 근거를 확인한 경우에만 연결한다. 수집 manifest의 해시는 내용 보존 확인용이며 비식별화나 출처 정답의 증명은 아니다.

## 다음 시연 순서

1. 이 변경을 포함한 개발 APK가 준비되면 기존 데이터 보존·동일 서명 업데이트 설치를 별도 확인한다. 이번 준비 작업에서는 폰을 설치·재시작·조작하지 않았다. 기존 미완료 책을 평가 때문에 이어 쓰지 않는다. **앱은 미완료 초안을 하나만 보관한다.** `sceneAdult`에서 새 이야기를 시작하면 `discardStorySound()`와 `discardDraft()`를 호출하므로 ‘기존 초안을 그대로 둔 채 같은 앱에서 새 책 시작’을 안내하지 않는다. 보호할 초안이 있으면 새로 시작을 누르지 않고, 독립된 시험 저장 공간 또는 초안·참조 자료의 실제 복원 가능성을 먼저 확인한다. 필요한 선택·보관·설치는 별도 사용자 지시에 따라 진행한다.
2. PC에서 실제 연결을 확인한다. 이 도구에는 **현재 확인한 기기 serial**과 `adb` 실행 파일을 명시한다. 폴더는 저장소 밖에 새로 만든다. 저장소 내부 출력과 기존 폴더 덮어쓰기를 거부한다.
3. 새 성인 시연을 시작하기 전에 개발 서랍 기록 탭의 윤문 수집을 켜고 아래 수집기를 먼저 실행한다. 기존 Logcat을 지우지 않는다. 실제 아동 시연은 이번 범위에 넣지 않는다.
4. 답 → 생성 → 최종 책 저장까지 진행한다. 실패/fallback/취소가 나와도 해당 시도를 제외하거나 로그를 지우지 않는다. 끝나면 수집을 끄고 PC에서 Ctrl+C로 종료한다.
5. `manifest.json`의 issues·수집 시작점·attempt 목록을 먼저 확인한다. `source_start_available`은 시작 메타데이터가 확인되고 발견된 유실이 없다는 뜻이지 전체 자료 보증이 아니다. `required_events_observed`도 단계 이름이 모였다는 뜻이며 `source_stages_complete`는 검토 전 `null`이다. 실제 요청/응답 필드·시간 순서·최종 책 ID 연결은 내용을 보고 확인한다. `books_saved`는 관측한 `book_saved`의 ID 수, `books_persisted`는 `status=stored`로 표시된 수, `runtime_books_only`는 스토어 없이 메모리에만 완료된 수다. 생성 채택과 스토어 저장 성공을 따로 확인하고 없는 단계는 미확인으로 남긴다.
6. `events.json`에서 같은 시도의 원문 → 판정 전후 → 투영 → 요청 → 파싱 응답 → 복원/채택 → 최종 저장을 대조한다. 최초로 핵심 정보가 바뀐 단계만 수정 후보로 정하고 고정 사례로 회귀 검사한다.

```powershell
# 현재 PC에서 확인한 값으로 채운다. 아래 값은 실행용 실제 경로/기기 번호가 아니다.
python eval/collect_story_rewrite_trace.py --adb "<adb 실행 파일>" --serial "<연결 확인한 serial>" --out "<저장소 밖 새 개인 폴더>"

# 이미 개인 PC에 저장한 UTF-8 로그를 오프라인으로 다시 조합할 때
python eval/collect_story_rewrite_trace.py --input "<개인 로그 파일>" --out "<새 개인 폴더>"
```

요약 출력에는 원문을 쓰지 않는다. 결과는 `events.json`, `manifest.json` 두 파일이며 새 모델 호출·서버 설정 변경·앱 데이터 초기화·녹화가 없다. 생성 성공률·윤문 통과율은 이 도구가 자동 평가하지 않는다. 평가 모집단과 자료 누락을 검토한 뒤 사전 기준에 따라 별도로 계산한다.

문체만 바꾸는 병렬 실험은 [문체 비교 계획](윤문_문체비교_계획_1013.md)에 분리한다. 내용 보존 지시/입력 계약을 바꾸는 실험과 혼합하지 않는다.
