## A. 일기 — 화이트보드 + 인터뷰 (최민우)

### 흐름

```
① 화이트보드  마스코트 「오늘 있었던 일을 그려 볼래?」 → 아이가 그린다
② 알아보기    붓이 멈추면 인식(데모는 가짜) → 마스코트 「공룡 그리는 거야?」
③ 확인        아이가 말로 답한다 → 이 답이 아이 말(child)
④ 인터뷰      지금의 일기 질문(DIARY_STEPS)으로 이어 간다 — 첫 질문에 그림 낱말을 넣는다
               예) 「공룡이랑 뭐 했어?」
⑤ 책          그린 그림은 원본 그대로 책에 들어간다(지금과 같다)
```

### 코드 자리

| 무엇 | 어디 | 지금 |
|---|---|---|
| 일기 시작 | `DiaryScenes.kt:115` `sceneDiary()` | 첫 대사 「오늘 뭐 했어?」 뒤 `DIARY_STEPS` 를 돈다 → **이 사이에 화이트보드 걸음을 넣는다** |
| 그리기 화면 | `Stage.DrawPad()` · `Screen.kt:829` `DrawPadView` | 이미 있다 — 새로 그리지 않는다 |
| 그리기 걸음 본보기 | `DiaryScenes.kt:269` `diaryDrawStep()` | 그리기 → 완료/안 그림 버튼 → `setDiarySlot(..., "child")` — **이 모양을 본떠** 첫 걸음을 만든다 |
| 가짜 인식 | 시연 버튼 | 예: `DemoBtn("(시연) 공룡으로 알아봄")` — 버튼이 낱말을 정한다. 진짜 ML Kit 는 다음 단계 |

### 결정은 주인 몫

**먼저 — 그림일기를 어떤 모양으로 만들까 (09-26 조장 요청: 민우가 설계).**
그림일기는 보통 **위에 그림 한 장, 아래에 짧은 글**이다. 멘토 메모: *「화이트보드를 하나 줌. 처음부터 끝까지 무슨 일이 있었는지
그리라고 하기. '뭐 그리는 거야?' 말하면서 그림을 그리는 느낌. 그림일기처럼 진행해도 됨. 거기서 질문 추출. (ADHD 많음)」*

| | **ㄱ. 한 장씩 이어 그리기** | **ㄴ. 중요한 장면 하나 + 말로 이야기** |
|---|---|---|
| 흐름 | 장면마다 그림 한 장 + 그 장면 이야기 → 다음 장 | 가장 기억나는 장면 **하나**를 그리는 동안 마스코트와 말로 주고받아 글을 만든다 |
| 책 | 여러 쪽 — 쪽마다 아이 그림 + 글 (기승전결 네 칸과 짝지을 수 있다) | 한 쪽 — 위에 그림, 아래에 대화로 모은 글. **가장 전통적인 그림일기 모양** |
| 아이 부담 | 그림 여러 장 — 3~4세·집중이 짧은 아이(멘토: ADHD)는 지칠 수 있다 | 그림 한 장 — 짧고 끝이 분명하다 |
| 「주고받기 횟수」 | 장마다 대화가 끊긴다 | 그리는 내내 말할 수 있다 — 핵심 지표에 유리할 수 있다 |
| 그림 알아보기 | 장마다 한 번 | 붓이 멈출 때마다 여러 번 — **실시간**이라 Jev 속도가 필요한 자리 |
| 이번 상태 | `sceneDrawing` 한 칸 — **여러 장이면 목록이 필요하다**(조장에게 말하기) | `sceneDrawing` 한 칸으로 된다 |

섞는 것도 된다(예: 한 장을 그리며 말하다가, 원하면 한 장 더). **월요일 데모는 하나만** 보여 줘도 된다 — 화면은 **「위 그림 · 아래 글」 한 쪽**이 있으면 멘토에게 그림일기가 바로 읽힌다.

- 인식한 낱말을 **어디에 둘지** — ⚠️ 칸에 바로 쓰지 않기를 권한다. 인식은 아이 말이 아니라서(규칙 5) 칸은 **③ 아이 답**으로 채우고, 낱말은 **질문 문구에만** 쓴다
- 알아보지 못했거나 자신 없을 때 — 「뭐 그리는 거야?」로 **열어서** 묻는 규칙(틀린 짐작보다 낫다)
- 지금의 「오늘 만난 사람 그리기」(`diaryDrawStep`)를 남길지 · 화이트보드에 합칠지
- 한 번만 그릴지 · 인터뷰 중간에도 그릴 수 있게 할지

### 다음 단계 (월요일 뒤)

폰 안 낙서 인식 — **ML Kit Digital Ink Recognition 의 AutoDraw 모델**(오프라인 · 모델 약 20MB) → 낱말 → 조장의 Jev API.

## B. 협업 — 템플릿 (박진웅)

### 흐름

```
① 부모 모드 「협업」 탭   템플릿 카드 넷 중 하나를 탭
② 채워짐                 질문 네 자리(+ 더)가 한 번에 채워진다
③ 조금 고치기             장소 같은 한두 칸만 바꾼다(예: 할머니 집 → 외할머니 집)
④ 같이 만들기             지금처럼 마스코트가 순서대로 읽는다 — 이 뒤는 안 바뀐다
```

### 템플릿 초안 — 문구는 주인이 고친다

**⚠️ 네 자리 순서를 지킨다** — `CoopScenes.kt:31` `COOP_PART_SLOTS = place · problem · cause · solution`.
입력 탭의 1~4번 줄이 이 순서로 칸에 짝지어진다. 순서가 어긋나면 **다른 칸에 답이 들어간다.**

| 템플릿 | ① 어디서 (place) | ② 무슨 일 (problem) | ③ 왜 (cause) | ④ 어떻게 됐어 (solution) |
|---|---|---|---|---|
| **오늘 어린이집** | 오늘 어린이집에서 어디서 제일 많이 놀았어? | 거기서 무슨 일이 있었어? | 왜 그랬을까? | 그래서 어떻게 됐어? |
| **주말 {장소}** (할머니 집 등) | {장소}에 가서 어디에 있었어? | {장소}에서 뭐가 제일 재밌었어? | 왜 재밌었어? | 다음에 가면 뭐 하고 싶어? |
| **엄마 · 아빠 일** | 엄마(아빠)는 어디서 일할까? | 거기서 무슨 일을 할까? | 왜 그 일을 할까? | {아이}도 해 보고 싶어? |
| **오늘 뭐 했니** | 오늘 어디 갔었어? | 거기서 무슨 일이 있었어? | 왜 그랬어? | 그래서 어떻게 됐어? |

### 코드 자리

| 무엇 | 어디 | 지금 |
|---|---|---|
| 입력 탭 | `Parent.kt:446` `CoopQuestionsTab()` | 네 자리 `TextField` + 「＋ 하나 더」 → **이 위에 템플릿 카드를 얹는다.** 카드는 `set(i, text)` 로 채우기만 하면 된다 |
| 질문 저장 | `Model.kt:763` `parentQuestions` | 그대로 쓴다 — 새 홀더가 필요 없다 |
| 마스코트가 읽기 | `CoopScenes.kt` | **안 바뀐다** |

### 결정은 주인 몫

- 커스텀을 **어디까지** — 멘토는 「약간」. 장소 하나 · 부모 호칭 정도가 선
- 템플릿을 고른 뒤 **줄 단위 수정**을 열어 둘지(지금 `TextField` 가 그대로 있다)
- **말로 넣기**(멘토: 아이 옆에서 말해도 됨) — 이번 데모는 빼도 된다
