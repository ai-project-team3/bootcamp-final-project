## 1. 프로젝트 · 빌드

### 1-1. Views 템플릿으로 만든 프로젝트에 Compose가 없다

`9/16 · v0.1`

**증상** — 사용자가 Android Studio에서 "No Activity"(또는 Empty Views Activity)로 만든 프로젝트에
Compose 코드를 넣으면 `Unresolved reference: androidx.compose`.

**원인** — Views 템플릿은 `appcompat` + `material`만 넣는다. Compose 플러그인도 의존성도 없다.

**해결** — 세 군데를 고친다.

```kotlin
// gradle/libs.versions.toml
kotlin-compose = { id = "org.jetbrains.kotlin.plugin.compose", version.ref = "kotlin" }
androidx-compose-bom = { group = "androidx.compose", name = "compose-bom", version = "2024.09.00" }

// build.gradle.kts (루트)
alias(libs.plugins.kotlin.compose) apply false

// app/build.gradle.kts
plugins { alias(libs.plugins.kotlin.compose) }
android { buildFeatures { compose = true } }
dependencies {
    implementation(platform(libs.androidx.compose.bom))
    implementation(libs.androidx.ui); implementation(libs.androidx.material3)
    implementation(libs.androidx.activity.compose)
}
```

> Kotlin 2.0부터는 `composeOptions { kotlinCompilerExtensionVersion }` 이 아니라
> **`kotlin.plugin.compose` 플러그인**을 쓴다. 옛 블로그를 따라 하면 버전 충돌이 난다.

### 1-2. 첫 빌드가 오래 걸리거나 실패한다

`9/16 · v0.1`

**증상** — 처음 열면 Gradle이 멈춘 것처럼 보인다.

**원인** — Compose 라이브러리를 처음 받는다(3~5분, 인터넷 필요).

**해결** — 기다린다. 사내망 등으로 `maven.google.com`이 막히면 받을 수 없다.

### 1-3. 코드 일부를 스크립트로 갈아 끼웠더니 클래스가 두 번 생겼다

`9/17 · v0.9`

**증상** — `Director.kt`가 534줄에서 854줄이 되고 `class Director`가 두 번 · 컴파일 오류가 쏟아짐.

**원인** — Python으로 "이 주석부터 저 주석 앞까지"를 바꿨는데, 끝 표시로 잡은 `/** [직접 그리기` 가 **파일 앞쪽 `Question` 안에도** 있었다. `index()`가 첫 번째 것을 잡아 앞부분이 통째로 복사됐다.

**해결** — 중복 구간을 지웠다. 앞으로는 바꿀 구간의 **시작 · 끝 표시가 파일에 한 번만 있는지** 먼저 센다(`s.count(표시) == 1`). 바꾼 뒤 `grep -n "^class\|fun "`으로 함수 목록을 한 번 본다.

## 2. Kotlin · Compose

### 2-1. ⭐ `R`이 리소스가 아니라 다른 것으로 잡힌다

`9/16 · v0.3`

**증상** — `Font(R.font.jua)` 에서 `Unresolved reference 'font'`. 리소스 파일은 분명히 있다.

**원인** — 같은 패키지(`ui`)의 `Theme.kt`에 **`val R = 26.dp`**(모서리 반지름)가 있었다.
같은 패키지의 이름이 자동 import보다 우선하므로 `R`이 `Dp`로 잡힌다.

**해결** — 리소스 쪽을 완전한 이름으로 쓴다.

```kotlin
val Jua = FontFamily(Font(com.example.finalproject_demo.R.font.jua))
```

> 한 글자 상수(`R`, `S`)를 패키지 최상위에 두면 이런 일이 난다. 새로 만들 때는 피한다.

### 2-2. ⭐ 문자열 템플릿 뒤에 한글이 붙으면 변수명으로 읽힌다

`9/16 · v0.4 · v0.5 두 번`

**증상** — `Unresolved reference 'v에'` 같은 오류. 소스에는 `$v` 만 썼다.

**원인** — Kotlin은 한글을 식별자 문자로 본다. `"$v에 불이"` 는 **`v에`** 라는 변수를 찾는다.

**해결** — 중괄호로 끊는다. `"${v}에 불이"`

이 프로젝트에서만 17곳이 걸렸다. 한 번에 고치는 스크립트:

```python
import re
s = re.sub(r'\$([a-zA-Z_][a-zA-Z0-9_]*)(?=[가-힣])', r'${\1}', s)
```

> 조사 처리 함수(`ga()` `eun()`)를 쓰면 `"$v${ga(v)} 흔들려"` 처럼 되어 이 문제가 안 난다.
> 한글이 바로 붙는 자리만 조심하면 된다.

### 2-3. Canvas에 그린 글자가 터무니없이 크다

`9/16 · v0.1`

**증상** — `drawText`로 그린 이모지가 카드를 뚫고 나온다.

**원인** — `scale(k)` 안에서 `fontSize = 70.sp` 를 주면 **sp가 density로 한 번,
`scale`로 또 한 번** 곱해진다.

**해결** — DrawScope 안에서는 px를 sp로 되돌려 준다.

```kotlin
tm.measure(text, TextStyle(fontSize = size.toSp()))   // size.sp (X)
```

### 2-4. `Modifier.layout` / `density` 를 못 찾는다

`9/16 · v0.1 · v0.5 두 번`

**증상** — `Unresolved reference 'layout'`, `Unresolved reference 'density'`.

**원인** — `androidx.compose.ui.layout.layout` import 누락 / `density`는 `DrawScope`·`PointerInputScope`
안에서만 쓸 수 있는데 일반 Composable에서 씀.

**해결** — 위치 계산은 `Modifier.layout` 대신 **`BoxWithConstraints` + `padding(maxWidth * 비율)`** 이 읽기 쉽다.
Composable에서 density가 필요하면 `LocalDensity.current.density`.

### 2-5. `quadraticTo` 가 없다

`9/16 · v0.1`

**증상** — Compose 1.7 이하에서 `Path.quadraticTo` 를 못 찾는다.

**해결** — `quadraticBezierTo` 를 쓴다(deprecated 경고는 나지만 동작한다).


### 2-6. `data object` → `data class`로 바꾸면 쓰던 곳이 깨진다

`9/16 · v0.7`

**증상** — `Stage.DrawPad`에 인자를 추가했더니 `Classifier 'data class DrawPad' does not have a companion object, so it cannot be used as an expression`.

**원인** — `data object`는 이름만 써도 값이지만 `data class`는 생성자 호출이 필요하다. `when`의 `Stage.DrawPad ->` 도 `is Stage.DrawPad ->`로 바꿔야 한다.

**해결** — 쓰던 곳을 전부 `Stage.DrawPad()`로. `grep -n "Stage.DrawPad" -r` 로 먼저 찾는다.

### 2-7. `key { … return@key }` 가 컴파일은 되는데 빌드(dex)에서 죽는다

`9/17 · v0.9`

**증상** — `compileDebugKotlin`은 통과, `assembleDebug`에서
`dexBuilderDebug … Method name '<anonymous>' in class '$$$$$NON_LOCAL_RETURN$$$$$' cannot be represented in dex format.`
`clean`을 해도 그대로.

**원인** — Compose의 `key(…) { }` 블록 안에서 `return@key`로 빠져나가게 쓴 것(`Hotspots.kt`). 컴파일러가 만든 클래스 이름을 dex가 받지 못한다.

**해결** — `return@key` 대신 **조건을 밖으로**: `if (보이는가) key(i) { … }`. Composable 람다 안에서는 라벨 return을 쓰지 않는다.

---

### 2-8. ⭐ 문자열 안에서 `$변수` 뒤에 **한글이 바로 붙으면** 변수를 못 찾는다

`9/22 · v0.13`

**증상**

```
e: Unresolved reference 'where남은'.
e: Unresolved reference 'after그렇게'.
```

**원인** — **한글도 식별자로 쓸 수 있는 문자**다. 그래서 Kotlin은 `"$where남은 모래를"` 에서
`where남은` 을 **변수 이름 하나**로 읽는다. 영어라면 `$whereLeft` 처럼 붙는 경우가 드물어 잘 안 걸리는데,
이 프로젝트는 문장이 전부 한글이라 **자주 걸린다.** 하루에 두 번 나왔다.

**해결** — 한글이 바로 뒤에 붙는 자리는 **반드시 중괄호로 끊는다.**

```kotlin
"${where}남은 모래를"      // ✅
"${after}그렇게 하루가"     // ✅
"$where 남은 모래를"       // ✅ 띄어쓰기가 있으면 괜찮다
```

**찾는 법** — 아래로 한 번에 훑을 수 있다.

```bash
grep -rnE '\$[a-zA-Z_][a-zA-Z0-9_]*[가-힣]' --include=*.kt .
```

**원인** — 좌표를 0~1로 정규화해 저장하면 **그림판의 가로세로 비율**이 사라진다.
그리고 캔버스 전체를 그리면 빈 여백까지 그려진다.

**해결** — 완료할 때 `drawingAspect = 폭/높이` 를 같이 저장하고,
그릴 때 **획의 바운딩 박스만 잘라** 비율을 지키며 채운다.


### 3-6. 질문이 바뀌었는데 앞 화면의 버튼이 남는다

`9/16 · v0.7`

**증상** — "이름은 뭐야?" 동안 그림판과 [다 그렸어]가, "어떤 게 마음에 안 들어?" 동안 좋아/싫어 카드가 그대로 보인다.

**원인** — `ask()`는 열린 질문에서 **무대를 바꾸지 않는다**(카드를 안 띄우니까). 앞 장면의 `stage`가 그대로 남는다.

**해결** — 열린 질문 전에 무대를 정리한다. 그림 한 장만 보여 주는 `Stage.Show(art, caption)`을 만들어 썼다.
**규칙: 열린 질문을 부르기 전에 `s.stage`가 누를 수 있는 것을 담고 있지 않은지 본다.**

### 3-7. 가로 화면에서 카드 3장 · 버튼 2개가 잘린다

`9/16 · v0.7`

**증상** — 중간 확인의 세 번째 카드가 화면 밖, 친구 평가의 [안녕 👋]이 카드 밖, 서랍의 칩 하나가 안 보임.

**원인** — Pixel 3a 가로는 **폭 약 740dp · 높이 약 360dp**(아래 띠 116dp 빼면 무대는 약 244dp). `Row`는 넘쳐도 줄바꿈하지 않는다.

**해결** — 넣을 것의 폭을 더해 본다. `그림 170 + 카드 158×3 + 간격` 처럼 줄이거나, 버튼은 세로로 쌓고, 칩은 두 줄로 나눈다.


### 3-8. 누르면 네모난 박스가 생긴다

`9/17 · v0.8`

**증상** — 책에서 인물 · 버튼을 누르면 회색 네모가 잠깐 번진다.

**원인** — 오류가 아니다. Compose `clickable`의 기본 눌림 효과(리플)가 그림의 사각 영역 전체에 그려진다.

**해결** — 그림을 누르는 곳은 `indication = null` 인 `noRippleClickable`(`ui/Chrome.kt`)을 쓴다. 반응은 흔들림 + 위에 뜨는 글자로 대신한다.

### 3-9. 떠 있는 요소가 무대 내용과 겹친다

`9/17 · v0.8`

**증상** — 아래 띠를 없앤 뒤 진행 막대가 그림판을, 책 인물이 안내문 · ▶를, 부모 모드 이름이 스크롤 내용을 덮는다.

**원인** — 떠 있는 요소는 레이아웃을 차지하지 않는다. 무대 쪽이 그 자리를 비워 두지 않으면 겹친다.

**해결** — 무대 안쪽 여백을 상수로(`TopChrome` 80dp · `BottomChrome` 76dp) 두고 `Centered {}` 로 감싼다.
스크롤 화면은 이름을 **스크롤 밖 고정 머리**로 옮긴다. 비율 배치(`Layer`)는 좌표를 더해 겹치지 않는지 본다(3-7과 같은 방식).

### 3-10. 진행 막대 밖에 반투명 네모가 떠 있다

`9/17 · v0.8`

**증상** — 막대 왼쪽 바깥에 흐린 사각형이 깜빡인다.

**원인** — 빛이 지나가는 효과의 x가 `-0.3 × 폭`부터 시작하는데, 채워진 부분 안에 있는지만 봤다(음수 검사 없음).

**해결** — `sx >= 0 && sx + h <= 채운 폭` 일 때만 그린다.

### 3-11. 고른 카드 뒤에 흰 네모가 생긴다

`9/17 · v0.9`

**증상** — 함께 하는 사람 카드를 고르자 그 카드의 그림 · 이름 뒤에 옅은 흰 네모.

**원인** — `.scale()` · `.alpha(1f)` · `.shadow()`를 겹치면서 생긴 그리기 층(에뮬레이터에서 보임). 그림 PNG는 투명이었다(확인함).

**해결** — `graphicsLayer { scaleX; scaleY; alpha }` 하나로 합쳤다. 이후 사용자 요청으로 카드 방식 자체를 녹음으로 바꿔 이 화면은 없어졌다.
**그림 뒤 네모가 보이면 먼저 PNG 투명도를 확인하고(`getpixel((5,5))`), 투명이면 층 겹침을 의심한다.**


### 3-12. 배경 속 것의 자리가 그림과 안 맞는다 · 빈 곳에 고리가 뜬다

`9/17 · v0.9`

**증상** — 눈밭에서 "눈 언덕" 고리가 아무것도 없는 눈 위에 뜸 · 눈송이 고리가 그려진 눈송이보다 훨씬 큼.

**원인** — 좌표를 눈대중으로 잡았다. 배경은 화면을 채우려고 **위아래가 잘려(Crop)** 그림 좌표와 화면 좌표가 다르다.

**해결**
- 자리 계산은 Crop과 똑같이: `scale = max(W/1344, H/768)` · `off = (그림 크기 × scale − 화면) / 2` (`Hotspots.kt`)
- 좌표를 정하면 **배경 4장 위에 원을 그려 한 장으로 확인**한다 (빨간 원 · 초록 선 = 화면에 보이는 띠 0.074~0.926)
- 뚜렷한 모양이 없는 것(언덕)은 넣지 않는다 → 먼 나무 2곳으로 바꿈


### 3-13. 반짝임이 스크린샷에 잡혔다 안 잡혔다 한다

`9/17 · v0.9`

**증상** — 같은 화면인데 어떤 캡처에는 금빛 고리가 있고 어떤 캡처에는 없음 → 연결이 끊긴 줄 알았음.

**원인** — 반짝임이 숨 쉬듯 밝기 0.25~0.8을 오가는데, 옅은 쪽에서 캡처하면 거의 안 보였다. 기능은 동작 중.

**해결** — 밝기 0.45~1 · 속이 빈 **금빛 고리** + ✨로 바꿔 어느 순간에도 보이게. **움직이는 효과는 캡처 한 장으로 판단하지 말고 두세 장 찍는다.**

### 3-14. CLAP 스플래시 전에 마스코트 아이콘이 잠깐 보인다

`9/17 · v0.9.1`

**증상** — 앱을 켜면 크림색 바탕에 마스코트(앱 아이콘)가 먼저 잠깐 → 그다음 CLAP.

**원인** — 오류가 아니다. Android 12부터 모든 앱은 켜질 때 **시스템 스플래시(앱 아이콘)** 를 먼저 보여 주고, 이것은 끌 수 없다. 우리 CLAP 화면은 앱이 뜬 뒤에 그려진다.

**해결** — 두 화면의 바탕색을 같게(`splash_bg`, `values-v31/themes.xml`의 `windowSplashScreenBackground`) 맞춰 이어져 보이게 했다.
시스템 스플래시 자체에 CLAP를 넣고 싶으면 `windowSplashScreenAnimatedIcon`에 **CLAP 글자 그림(가운데 원 안에 들어가는 정사각형)** 을 넣으면 된다 — 아이콘 자리가 작아 글자가 작게 보여서 이번에는 넣지 않았다.

### 3-15. 아이가 그린 그림이 책에서 더 두껍게(뚱뚱하게) 나온다

`9/21 · v0.12`

**증상** — 그림판에서 가늘게 그린 선이 동화책 쪽에서는 통통하게 부풀어 있다. 작게 그린 그림일수록 심하다.

**원인** — 붓 굵기를 **두 곳에서 따로** 정하고 있었다.
그림판은 화면 픽셀 고정(`Stroke(16f)`), 책은 그리는 영역 크기 기준(`Stroke(k * 0.05f)`).
저장하는 것은 점 좌표뿐이라 굵기가 따라가지 않았고, 책에서 그림을 키워 그릴수록 선이 굵어졌다.

**해결** — 굵기를 **그림판 폭에 대한 비율**(`PEN_W = 0.014f`) 하나로 정하고 `Stroke` 에 실어 보낸다.
책에서는 `s.w * (aspect * sc)` 로 되돌린다 — 그림판 폭 한 칸이 책에서 몇 픽셀인지를 곱하는 것이라
**그릴 때와 같은 굵기**가 된다. 흰 테두리도 선 굵기의 1.9배로 따라간다.

> 정규화할 때 x는 폭으로, y는 높이로 나눈다는 것을 기억할 것. 굵기는 **폭** 기준이다.

**해결** — 틀에서 뺐다. **답 값과 문장 틀 중 한 곳에만 이름을 넣는다.** 후보를 추가할 때 6쪽 자막을 소리 내 읽어 본다.


### 4-8. 어른이 답하지 않았는데 책에 어른 내용이 들어간다

`9/17 · v0.8`

**증상** — 장면 10에서 뜬금없는 "이모는 별을 따면 뭐 하고 싶어?"가 나오고, 아무도 안 눌렀는데 카드가 골라지고, 책 6쪽에 이모 문장이 나온다.

**원인** — v0.7 어른 칸이 "3초 안에 답이 없으면 마스코트가 프리셋에서 고른다"(구현대본 §2 문구)를 그대로 따랐고, 질문도 이야기 흐름과 이어지지 않았다.

**해결** — 질문을 흐름에 맞춰 "이모, ○○와 ○○가 친해지게 이모는 뭘 도와줄까?"로. 어른 질문 전용 `askAdult()`는 **답이 없으면 null** → 책 · 표지에 넣지 않는다.
**규칙: 어른 몫은 대신 채우지 않는다.** (아이 칸은 마스코트가 채워도 됨)

### 4-9. "처음으로"를 누르면 부모 기록이 비어 있다

`9/17 · v0.8`

**증상** — 책장 → 처음으로 → 부모 모드에서 "오늘은 아직 만든 책이 없어요".

**원인** — 처음으로에서 이야기 상태를 바로 지웠다.

**해결** — 이야기는 **다음 이야기를 시작할 때** 지운다(`sceneAdult` 시작 부분). 처음으로는 책장의 "새 책" 표시만 끈다.

### 4-10. 한국어 문장이 어색하게 붙는다 (v0.8에서 또)

**원인** — 답 값(`causeLine = "…했어"`)을 그대로 이어 붙였다 / 틀과 값에 같은 말이 겹쳤다 / 그리기 여부를 보지 않았다 (4-7과 같은 종류).

### 4-11. "이어 짓기처럼" 답하게 했는데 3턴째 까닭 짓기로 올라간다

`9/17 · v0.9`

**원인** — 이어 짓기 아이의 답("같이 놀고 싶어서!")도 까닭(S1)을 담는다. 올림 조건이 "S1 또는 S2 2턴 연속"뿐이라 쉽게 올라갔다.

**해결** — 조사2 §4 표대로 **이어 → 까닭 올림은 S1 + 구조(계기 · 시도 · 결과 또는 잇는 말)** 일 때만 (`StoryBank.kt judge()`). 고르며 → 이어는 그대로 S1 또는 S2.
더미 답을 새로 넣을 때 ②(이어)는 **3어절 이상 · 구조 없음**, ③(까닭)은 **까닭 + 구조**로 맞춘다.

### 4-13. 한국어 문장이 어색하게 붙는다 (v0.9에서 또)

```
./gradlew :app:testDebugUnitTest --tests "*StoryTextTest*"
```
**자동 검사는 "마을을"처럼 맞는 말도 잡는다 — 걸린 줄은 반드시 눈으로 본다. 흐름(앞뒤가 맞나)은 샘플을 읽어야만 보인다.**

### 5-9. 안경 쓴 주인공에 반달 · 별 눈을 얹으면 렌즈 속에 살구색 동그라미가 생긴다

`9/21 · v0.12`

**증상** — 안경(동글 · 네모) + 눈(반달 · 별) 조합만 이상하게 나온다. 렌즈 한가운데에 살구색 원이 찍힌다.

**원인** — 두 가지가 겹쳤다.
① `find_eyes.py` 가 안경 쓴 그림에서는 **안경테**를 눈으로 잡았다 — 반지름이 0.04~0.06으로 **렌즈 크기**다(5-5의 잔여 문제).
② 눈 스티커는 원래 눈을 가리려고 그 위에 **살색 패치**를 먼저 칠한다. 자리는 렌즈 한가운데라 맞는데,
   렌즈 속에 살색을 칠하니 살구색 동그라미가 됐다.

**해결(1차)** — 안경이면 패치를 **렌즈 색**(`0xFFFCF8F1`)으로 칠한다. 살구색 동그라미는 사라졌다.

**그런데 에뮬레이터에서 보니 원래 눈이 별 아래에 그대로 남아 있었다.** 두 가지가 더 있었다.

① **눈 위치 표를 다시 안 돌렸다.** 주인공 그림 54장을 새로 뽑고 `find_eyes.py` 를 돌리지 않아
   `HeroEyes.kt` 가 28개에 멈춰 있었고, 새 그림은 전부 `DEFAULT_EYES`(r=0.022)로 떨어졌다.
   **그림을 새로 뽑으면 반드시 다시 돌린다**(5-5에 이미 적혀 있던 것을 또 어겼다). 돌리니 75개가 됐다.

② **무엇을 잡았는지가 그림마다 다르다.** 안경 그림이라고 늘 안경테를 잡는 것이 아니다 —
   **반지름을 보면 안다.**

```kotlin
val rim = eyes.r >= 0.03f            // 크면 안경테(렌즈 크기) · 작으면 눈동자
val unit = (if (rim) minOf(eyes.r, 0.06f) else maxOf(eyes.r, 0.016f)) * k
val patchR = if (rim) unit * 0.92f else unit * 1.9f
val patchTall = if (rim) 1f else 1.35f        // 눈동자는 세로로 긴 타원이라 타원으로 덮는다
val patch = if (onGlasses) Color(0xFFFCF8F1) else Color(0xFFFFDCC2)   // 렌즈 속 / 살색
```

> 교훈 둘. **좌표가 맞는데도 이상하면 덮어 그리는 색과 크기를 의심할 것.**
> 그리고 **검출 결과를 "무엇을 잡았는지" 모른 채 쓰지 말 것** — 여기서는 반지름이 그 답이었다.

### 5-11. ⭐ 토글을 바꾸면 캐릭터가 통째로 다른 아이가 된다

`9/21 · v0.12`

**증상** — 「골라서 만들기」에서 한 가지만 바꿨는데 다른 것까지 바뀐다.
머리를 길게 하면 **얼굴이 여자아이가 되고**, 옷 색을 노랑으로 바꾸면 **하의가 치마가 되고**,
안경을 바꾸면 **몸 비율이 달라진다.**

**원인** — 머리 3 × 옷 3 × 안경 3 × 하의 3 = **완성본 81장을 갈아 끼우고** 있었다.
81장이 각각 **독립적으로 생성된 그림**이라 서로 아무 관계가 없다.
아이가 고른 것은 "머리를 길게" 인데 앱은 **다른 아이를 뽑아** 보여 준 셈이다.

> 이건 그림의 문제가 아니라 **구조의 문제**다. 완성본을 갈아 끼우는 한 몇 장을 다시 뽑아도 같은 일이 난다.

**해결** — 그림을 **부품으로 나눈다.**

```
몸 27장 (옷 3 × 하의 3 × 머리 3)   ← 얼굴 · 자세 · 비율이 모두 같은 아이
  └ 안경 (gl_round · gl_square)     ← 얹는다. 그림 이름에 넣지 않는다
      └ 눈 (반달 · 별)              ← 벡터로 그린다 (전부터 그랬다)
```

**같은 아이로 27장을 만드는 법** — 두 단계로 나눈다.
1. 얼굴 · 자세 · 비율을 **말로 못 박은** 프롬프트로 옷 × 하의 **9장**을 뽑는다 (`gen_hero_parts.py`).
   못 박으면 9장이 실제로 같은 아이로 나온다.
2. 그 9장을 **출발점으로 img2img** 해서 머리만 바꿔 18장을 더 만든다 (`gen_hero_hair.py`).
   새로 뽑는 것보다 얼굴이 훨씬 잘 남는다. `denoise` 는 **0.42** —
   0.55 로 해 봤더니 티셔츠의 공룡 무늬가 사라졌다.

**해 봤지만 버린 방법** — 머리를 **투명 조각으로 얹기**(`gen_hero_parts.py` 의 `hair_*`).
구조는 맞았지만 조각마다 얼굴 구멍의 크기와 모양이 달라 **얼굴 위로 어두운 테두리가 지나갔다.**
(`cut_hair_face.py` 로 안쪽을 비우고 `check_parts.py` 로 겹쳐 봤지만 맞출 수 없었다.)

**곁들여 고친 것**
- 「바지」가 **다리 구분 없는 통짜**로 나와 치마와 구분이 안 됐다 → 프롬프트에
  "두 다리가 갈라지고 발이 보이게" 를 못 박았다
- **안경 + 반달/별 눈 어긋남**(5-9)도 이 구조 변경으로 **원인부터 사라졌다** —
  얼굴이 27장 모두 같으니 눈 자리가 고정된다
- 안경은 **고정 좌표로 두면 안 된다.** 27장은 같은 아이지만 그림마다 몸이 화면을 채우는 정도가 달라
  눈 높이가 0.27~0.33 사이로 움직인다. `find_eyes.py` 가 잰 **그 그림의 눈 자리**를 따라간다

**검사로 막았다** — `changingOneToggleChangesOnlyThatThing`(다섯 줄을 한 장에 그려 눈으로 대조) ·
`theHeroBuilderAsksForLooksNotForGender`(안경 · 눈을 바꿔도 몸 그림 이름이 안 바뀌는지).
안경을 다시 그림 이름에 박아 보니 **검사 5개가 즉시 실패**했다.

**증상** — 에뮬레이터를 켜고 작업하는 동안 화면이 얼어 전원 버튼으로 재부팅. 한두 번이 아니라 **여러 번** 그랬다.

**원인** — 이 기기는 **하이브리드 그래픽 노트북**이다 (Intel UHD 내장 + NVIDIA RTX 4060 Laptop).
ComfyUI가 모델을 올려 VRAM을 거의 다 쥐고 있는 상태에서 에뮬레이터를 `-gpu host` 로 띄우면
**둘이 같은 NVIDIA GPU에 OpenGL을 요청한다.** 드라이버가 멈추면(TDR) 앱 하나가 아니라
**데스크톱 전체가 얼어서** 되돌릴 방법이 전원 버튼밖에 없다.

여기에 메모리 압박이 겹친다 — 에뮬레이터 2GB + Gradle 데몬 2~3GB + Kotlin 데몬 + Android Studio + ComfyUI.
실제로 **에뮬레이터와 Gradle 데몬만 내려도 남은 RAM이 13.4GB → 18.1GB** 로 돌아왔다.

**해결** — `tools/run_emulator.ps1` 이 아래를 순서대로 한다. 에뮬레이터가 필요하면 이 스크립트를 쓴다.

| | 왜 |
| --- | --- |
| ComfyUI가 떠 있으면 **멈추고 알린다** | 이 한 줄이 강제 재부팅을 막는다 |
| `-gpu swiftshader_indirect` (소프트웨어 렌더링) | **NVIDIA 드라이버를 아예 건드리지 않는다.** 화면을 캡처해 확인하는 데는 GPU 가속이 필요 없다 — 같은 화면이 그대로 나온다 (9/21 확인) |
| `-memory 2048 -cores 2` | 사용자가 쓸 CPU를 남긴다 |
| 켜기 전에 `gradlew --stop` | 데몬이 쥔 2~3GB를 돌려받는다 |
| 끌 때 `adb emu kill` | 강제 종료하면 다음에 `offline` 로 올라온다 (6-8) |

```
powershell -ExecutionPolicy Bypass -File tools\run_emulator.ps1          # 켜고 설치 · 실행
powershell -ExecutionPolicy Bypass -File tools\run_emulator.ps1 -Stop    # 정상 종료
```

**소프트웨어 렌더링이 느리지 않나** — 부팅이 조금 느리고 애니메이션이 덜 부드럽다.
화면을 캡처해 확인하는 용도에는 차이가 없고, **컴퓨터가 안 멈추는 값으로는 싸다.**
손으로 만져 보며 시연할 때만 ComfyUI를 끈 것을 확인하고 `-gpu host` 를 쓴다.

**해결** — 눌러 놓고 **화면이 실제로 움직였는지 확인하고, 안 움직였으면 다시 누른다.**

```kotlin
private suspend fun Director.push(part: String): Boolean {
    repeat(12) {
        val b = s.buttons.firstOrNull { part in it.label } ?: return false
        val before = s.lineId
        b.onClick()
        if (await(600) { s.lineId != before || s.buttons.none { x -> part in x.label } } != null) return true
    }
    return false
}
```

> "말이 없으면 사다리가 내려간다"를 검사하려면 시간이 지나기를 기다릴 게 아니라

### 6-12. ⭐ 소프트웨어 렌더링으로 띄웠는데도 또 멈춰서 강제 재부팅했다

`9/21 · v0.12` — **하루에 세 번째 강제 재부팅.** 6-10의 대응을 다 지키고도 일어났다.

**증상** — ComfyUI를 끄고 `-gpu swiftshader_indirect` 로 띄웠는데도, 에뮬레이터로 화면을 확인하는 중에
데스크톱 전체가 얼었다. 전원 버튼 말고는 방법이 없었다.

**6-10과 무엇이 다른가** — 이벤트 로그가 **GPU를 가리키지 않았다.**

| 무엇을 봤나 | 6-10(GPU 멈춤) | 이번 |
| --- | --- | --- |
| BugCheck(1001) · 메모리 덤프 | 있을 수 있음 | **없음** |
| `nvlddmkm` · TDR(4101) | **있음** | **없음** |
| 시스템 로그 | 드라이버 복구 기록 | 그냥 **끊김** → Kernel-Power **41** |
| `HypervisorPresent` | — | **False** (Hyper-V/WHPX가 아니다) |

가속기를 직접 확인하니 **HAXM이 아니라 AEHD**였다 — `emulator -accel-check` 가
`AEHD (version 2.2) is installed and usable.` 라고 답하고, `aehd` 커널 드라이버가 `RUNNING` 이다.
AEHD(Android Emulator Hypervisor Driver)는 HAXM의 후속으로 같은 계통의 **서드파티 커널 드라이버**다.

덤프도 벌체크도 없이 로그가 끊기는 것은 **드라이버가 죽고 복구된 것이 아니라 기계가 통째로 하드 행**한 모습이다.
커널 드라이버가 인터럽트를 막은 채 멈추면 이렇게 된다 — 그래서 **AEHD 같은 가상화 커널 드라이버**가 유력한 자리다.
즉 `-gpu swiftshader_indirect` 는 **GPU 경로만 막는다** — 멈춤의 원인이 그것만은 아니었다.

⚠️ 확실히 **증명된 것은 아니다.** 덤프가 없어 범인을 못 짚었고, AEHD는 정황 증거(가상화 커널 드라이버가
돌고 있었고, 그 계통이 덤프 없는 하드 행으로 알려져 있다)일 뿐이다. 그래서 아래 대응은 "고쳤다"가 아니라
**"위험을 줄였다"** 이다.

**지금 하는 것** (근본 원인을 아직 못 짚었으므로 **위험을 줄이는 쪽**으로)

1. **에뮬레이터를 마음대로 켜지 않는다.** 확인이 필요하면 **사람에게 먼저 묻는다.**
   한 번 더 얼면 그 사람이 또 전원 버튼을 눌러야 한다.
2. **짧게 쓰고 바로 끈다.** 확인할 화면 목록을 미리 적어 두고 한 번에 훑은 뒤 `adb emu kill`.
   스크린샷을 수십 장 찍으며 오래 띄워 두지 않는다.
3. **에뮬레이터 없이 되는 검증을 먼저 다 한다** — `./gradlew test`(41개) · 문장 검사 ·

### 6-13. `run_emulator.ps1` 이 한글 주석에서 파싱 오류를 낸다

`9/21 · v0.12`

**증상** — `Unexpected token '}'` · `The string is missing the terminator` 가 잔뜩 나오고 스크립트가 아예 안 돈다.
오류가 가리키는 줄은 멀쩡한 한글 주석이다.

**원인** — **Windows PowerShell 5.1은 BOM 없는 UTF-8 파일을 시스템 ANSI 코드페이지(949)로 읽는다.**
한글이 깨지면서 따옴표·괄호 짝이 어긋나 파싱이 무너진다. (PowerShell 7은 UTF-8이 기본이라 이 문제가 없다.)

**해결** — `.ps1` 은 **UTF-8 BOM 포함**으로 저장한다.

```python
s = io.open(p, encoding='utf-8').read()
io.open(p, 'w', encoding='utf-8-sig').write(s)   # BOM 붙이기
```

> `bash tools/run_emulator.ps1` 처럼 Bash 도구로 부르면 `-File tools
un_emulator.ps1` 의 역슬래시가
> 먹혀서 `toolsrun_emulator.ps1` 이 된다. PowerShell 도구로 `& "전체경로"` 를 쓴다.

### 6-14. 가속기를 AEHD → WHPX 로 바꾸기 · GPU를 앱별로 나누기

`9/21 · v0.12` — 6-12(덤프 없는 하드 행)의 **후속 선택지**. 둘 다 기기 설정을 바꾸는 일이라 **사람이 직접 한다.**

#### 지금 상태 확인 (권한 필요 없음)

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\emulator\emulator.exe" -accel-check
sc.exe query aehd
(Get-CimInstance Win32_ComputerSystem).HypervisorPresent
```

이 기기는 `AEHD (version 2.2) is installed and usable.` · `aehd` 드라이버 `RUNNING` · `HypervisorPresent: False` 였다.

#### ① AEHD → WHPX (관리자 PowerShell · 재부팅 필요)

**WHPX**(Windows Hypervisor Platform)는 마이크로소프트가 Windows에 넣어 둔 가상화 계층이라
**서드파티 커널 드라이버를 쓰지 않는다.** AEHD 같은 드라이버가 하드 행의 자리라면 이걸로 비켜 갈 수 있다.

```powershell
# 1) AEHD 제거 — SDK에 들어 있는 설치 스크립트로 (권장)
cd "$env:LOCALAPPDATA\Android\Sdk\extras\google\Android_Emulator_Hypervisor_Driver"
.\silent_install.bat -u
#    스크립트가 없으면 드라이버를 직접 지운다
#    sc.exe stop aehd ; sc.exe delete aehd

# 2) WHPX 켜기
DISM /Online /Enable-Feature /All /FeatureName:HypervisorPlatform
DISM /Online /Enable-Feature /All /FeatureName:VirtualMachinePlatform

# 3) 재부팅

# 4) 확인 — "WHPX ... is installed and usable" 이 나와야 한다
& "$env:LOCALAPPDATA\Android\Sdk\emulator\emulator.exe" -accel-check
```

**대가도 있다.** 알고 고르는 편이 낫다.

| | AEHD (지금) | WHPX |
| --- | --- | --- |
| 커널 드라이버 | 서드파티 | **Windows 내장** |
| 에뮬레이터 속도 | 대체로 빠름 | **조금 느림** |
| 호스트 전체 | 그대로 | **하이퍼바이저 위에서 돌게 된다** (전반적으로 약간 느려질 수 있다) |
| 다른 가상화 | — | 구버전 VMware · VirtualBox와 **충돌할 수 있다** |

되돌리려면 `DISM /Online /Disable-Feature /FeatureName:HypervisorPlatform` 후 재부팅하고 AEHD를 다시 깐다.

> ⚠️ 이게 **고친다고 보장된 방법은 아니다.** 6-12에서 범인을 덤프로 짚지 못했다.
> 바꾼 뒤에도 얼면 원인은 다른 데 있다 — 그때는 실물 폰(USB 디버깅)으로 확인하는 쪽이 확실하다.

#### ② GPU는 "쪼개는" 게 아니라 **앱별로 나눈다**

이 기기는 두 개가 다 살아 있다 — Intel UHD(내장)와 RTX 4060 Laptop(외장). Optimus 구성이라
**평소에는 Intel이 화면을 그리고, 필요할 때만 NVIDIA가 깨어난다.** 작업 관리자에서 NVIDIA만 보였다면
그건 그때 GPU를 쓰던 프로그램(ComfyUI)이 NVIDIA에 붙어 있어서다.

- **한 작업을 두 GPU에 나눠 돌리는 것은 안 된다.** SLI 같은 건 노트북 하이브리드 구성에 없고,
  DirectX · OpenGL · CUDA 모두 **어댑터 하나를 골라서** 쓴다.
- **프로그램마다 다른 GPU를 주는 것은 된다.** 이게 실질적인 "분할"이다.

```
설정 → 시스템 → 디스플레이 → 그래픽 → 앱별 기본 그래픽 설정
  · ComfyUI(python.exe)      → 고성능 (NVIDIA)   ← CUDA가 필요하니 선택지가 없다
  · emulator.exe             → 전력 절약 (Intel)  ← 기본 GL만 있으면 된다
```

그러면 그림을 뽑으면서 에뮬레이터를 켜도 **같은 GPU를 두고 다투지 않는다**(5-1 · 6-10의 원래 원인).
다만 지금 `run_emulator.ps1` 은 `-gpu swiftshader_indirect`(CPU 소프트웨어 렌더링)라
**애초에 두 GPU를 다 안 쓴다.** Intel로 돌리고 싶으면 `-gpu host` 로 바꾸고 위 설정을 같이 해야 한다 —
소프트웨어 렌더링보다 빠르고, NVIDIA는 건드리지 않는다.

> 6-12의 멈춤은 TDR 기록이 없어 **GPU 다툼이 아니었다.** 그러니 ②는 6-12를 고치는 방법이 아니라,
> 6-10(GPU 다툼)을 피하면서 **속도를 되찾는** 방법이다.

### 6-15. ⭐ 에뮬레이터 없이 화면을 그림으로 찍어 검사한다

`9/21 · v0.12`

**왜 필요했나** — 이 기기에서 에뮬레이터가 하루 **네 번** 컴퓨터를 얼렸다(6-10 · 6-12).
그런데 그날 찾은 가장 값진 버그 둘은 **화면을 봐야만** 보이는 것이었다:
[이걸로 할래] 버튼이 말풍선에 가려진 것, 안경 쓴 주인공의 눈 패치가 원래 눈을 못 덮은 것.
단위 검사로는 **픽셀이 겹치는지**를 못 본다.

**해결** — Robolectric이 안드로이드 화면을 **JVM 안에** 만들고, Roborazzi가 그것을 PNG로 떨군다.
하이퍼바이저를 안 쓰므로 기계가 얼지 않고, 27초면 끝난다.

```
./gradlew :app:recordRoborazziDebug   # 기준 그림을 app/screens 에 찍는다 (화면을 일부러 바꿨을 때)
./gradlew :app:test                   # 기준과 달라지면 실패한다
```

일부러 성별 줄을 되살려 보니 **스크린샷 검사 2개가 바로 실패**했다. 제대로 문다.

⚠️ **dp 를 픽셀로 착각하지 말 것.** 처음에 `qualifiers = "w2220dp-h1080dp"` 로 적었는데,
Pixel 3a 는 2220×1080 **픽셀** · 440dpi 라 density 2.75, 즉 화면은 **807 × 393 dp** 다.
2.75배짜리 화면에서 그리니 레이아웃이 실제와 달라져 **버튼이 잘려 보이는 가짜 문제**가 났다.
제대로 적으면(`w807dp-h393dp-land-440dpi`) 나온 그림이 에뮬레이터 스크린샷과 **픽셀 크기까지 같다**(2219×1080).

⚠️ **KDoc 안에 `/*` 를 쓰지 말 것.** Kotlin은 중첩 주석을 지원해서
`build/screens/*.png` 라고 적으면 그 `/*` 가 주석을 열고 파일 끝까지 먹어 버린다 (`Unclosed comment`).

**터치와 애니메이션도 된다** (처음엔 "폰이 필요하다"고 적었는데 틀렸다 · 9/21).
Compose 검사 도구가 손가락을 흉내내고 Robolectric이 JVM 안에서 받는다:

```kotlin
compose.mainClock.autoAdvance = false                 // 시간을 손으로 민다
compose.onRoot().performTouchInput { down(a); moveTo(b); up() }
compose.mainClock.advanceTimeBy(1500)
```

미션 1(문지르기) · 미션 2(끌어다 놓기) · 쪽 애니메이션을 이렇게 확인했다.
**"화면이 실제로 달라졌나"** 로 판정한다 — 감독이 돌고 있지 않으면 미션 완료 신호가 채널에 남아
상태에 안 보이므로, 이벤트 수가 아니라 **그림 두 장의 다른 화소 비율**을 본다(`BitmapFactory` 로 읽는다).

⚠️ `javax.imageio` 는 안드로이드 유닛 테스트 classpath 에 **없다.** `android.graphics.BitmapFactory` 를 쓴다.

⚠️ **중간 산출물을 그냥 찍으면 안 된다.** 비교용으로 찍은 그림까지 Roborazzi 가 "기준 그림" 으로 여겨
다음 검사에서 달라졌다고 실패한다. `RoborazziOptions(taskType = RoborazziTaskType.Record)` 로 **기록만** 하게 한다.
(`captureToImage()` 로 피해 가려 했더니 `mainClock.autoAdvance = false` 라 화면 갱신을 기다리다 시간 초과가 났다.)

**그래도 못 보는 것** — 장면을 처음부터 끝까지 사람처럼 이어서 돌려 보기(감독 수준에서는 `DiaryFlowTest` 가 한다),

### 6-16. ⭐⭐ 도감에서 화면이 멎는다 — 그리기 코드에 `toPixelMap()` 을 그냥 두면 안 된다

`9/22 · v0.13`

**증상** — 동화책을 만들고 다음 이야기를 시작하면 **도감(주인공 고르기)에서 더 넘어가지 않는다.**

**왜 찾기 어려웠나** — 흐름 검사로는 **재현되지 않았다.** 책을 만들고 끝까지 넘겨 두 번째 이야기의
도감까지 가는 검사를 일기·동화 모드로 각각 써서 돌렸는데 둘 다 통과했다. 검사는 감독(Director)
수준에서 도는 것이라 **Compose가 화면을 몇 번 다시 그리는지는 보지 않는다.**

**원인** — 같은 날 넣은 「눈 살색을 그림에서 뽑기」를 `remember` 없이 두었다.

```kotlin
// 이렇게 두면 안 된다 — 다시 그릴 때마다 41만 화소를 읽는다
val skin = skinNear(ImageBitmap.imageResource(id), eyes)
```

`toPixelMap()` 은 **640×640 = 41만 화소를 통째로 읽어 새 배열을 만든다.**
도감은 주인공 카드를 **네 장 동시에** 그리는 화면이라 한 번 다시 그릴 때마다 164만 화소다.
애니메이션이 도는 동안 이것이 반복되면 기기가 버티지 못한다.

**해결** — 그림 이름이 같으면 색도 같으므로 `remember` 로 묶는다.

```kotlin
val bodyBitmap = ImageBitmap.imageResource(id)
val skin = remember(name) { skinNear(bodyBitmap, eyes) }
```

**남는 규칙** — 그리기(`@Composable`) 안에서 **화소를 읽거나 이미지를 훑는 계산은 반드시 `remember`** 에 담는다.
`toPixelMap` · `asAndroidBitmap().getPixel` · 이미지 전체 순회가 여기 해당한다.
한 장이면 티가 안 나다가 **같은 그림을 여러 장 띄우는 화면(도감 · 책장)에서 터진다.**

⚠️ **아직 실기기로 확인하지 못했다.** 재현이 안 돼서 정황으로 짚은 것이다. 같은 증상이 또 나오면 원인이 다른 데 있다.

### 6-18. ⭐⭐ 흐름 검사가 다 초록인데 실기기에서 앱이 멎는다 — 서랍 버튼과 아이 화면은 다르다

**증상** (9/22 · 진웅님 실기기 보고) — 일기·협업 모드에서 책을 다 읽고 선물 화면에 오면 **앱이 멎는다.**
그림을 한 획도 안 그린 날에만 난다. 흐름 검사(`DiaryFlowTest` · `CoopFlowTest` · `StoryFlowTest`)는
**전부 초록이었다.**

**원인** — 파일 두 개가 서로 다른 것을 보고 있었다.

```
Scenes.kt  sceneEnd()   안 그린 날은 크레용을 건너뛴다 → Stage.Gifts(1) 에 머문다
Screen.kt  GiftsView    [📚 책장에 꽂기] 를 stage.shown >= 2 일 때만 그린다
Scenes.kt  sceneEnd()   awaitValue("shelf") — 누를 버튼이 없으니 영원히 기다린다
```

**왜 검사가 못 잡았나 — 이게 핵심이다.**

`sceneEnd` 는 같은 버튼을 **시연 서랍에도** 넣는다.

```kotlin
buttons(DemoBtn("📚 책장에 꽂기") { send(Reply.Tapped("shelf", "책장")) })
awaitValue("shelf")
```

흐름 검사는 **서랍 버튼을 눌러** 화면을 민다. 서랍에는 버튼이 멀쩡히 있으니 검사는 그냥 지나간다.
정작 멎는 것은 **아이 화면**이고, 아이 화면의 버튼은 `Screen.kt` 가 따로 그린다.

> **아이가 눌러야 넘어가는 자리는 서랍 버튼 말고 `Stage` 를 봐야 한다.**
> `assertTrue(s.buttons.any { "책장에 꽂기" in it.label })` 는 **서랍**을 본 것이고,
> `assertTrue((s.stage as Stage.Gifts).done)` 이 **아이 화면**을 본 것이다.

**고친 방법** — 선물 개수로 「끝났는가」를 판단하던 것을 고쳐, 끝을 직접 말하게 했다.
`Stage.Gifts(val shown: Int, val done: Boolean = false)` — `shown` 은 불이 켜진 선물 수,
`done` 은 더 나올 선물이 없다는 뜻이다. 화면은 `if (stage.done)` 으로 본다.

**확인** — 고친 줄을 잠깐 되돌리면 `CoopFlowTest.theShelfButtonAppearsOnTheChildScreenAfterTheGifts`
가 빨갛게 된다. 결함을 실제로 잡는 검사인지 이렇게 되짚어 본다.

### 6-17. 화면을 옮겼는데 안내가 한 번도 안 보인다 — 시간을 **보이는 자리**에서 재야 한다

`9/22 · v0.13`

**증상** — 상호작용 원을 「책을 편 처음 4.5초만」 보여 주게 고쳤는데, 실제로는 **한 번도 안 보였다.**

**원인** — 시간을 `BookPageView` 가 열릴 때부터 쟀다. 그런데 **책 표지(0쪽)에는 배경 자리를 그리지 않는다**
(`PageKind.COVER` 는 `Scenery()` 를 부르지 않는다). 아이가 표지를 4.5초 넘게 보면
**원이 화면에 뜨기도 전에 안내가 끝나 버린다.** 아이는 표지를 그보다 오래 본다.

**해결** — 시간을 `HotspotLayer` 안에서 잰다. 원을 **실제로 그리는 자리**이므로, 거기서 세면
보이기 시작한 순간부터 센다. 다 보여 주면 `onIntroShown()` 으로 알린다.

**남는 규칙** — "몇 초 동안 보여 준다"는 **보여 주는 쪽**에서 잰다. 부르는 쪽에서 재면
그 사이에 화면이 안 떠 있는 구간이 끼어든다.

곁들여 같은 날 나온 것 둘:
- 소개 여부를 **안 넘기는 호출부가 하나** 남아 기본값 `true` 로 **질문 화면부터 전부 반짝였다.**
  기본값을 `false` 로 바꿔, 부르는 쪽이 일부러 켜야 켜지게 했다
- `hotspotIntroShown` 을 **이야기 초기화 목록에 안 넣어** 두 번째 이야기부터 안내가 안 떴다

## 7. 공유 · 배포

### 7-1. ⭐ 압축 파일이 500MB가 넘는다

`9/16 · v0.6`

**원인** — `app/build/` 만 436MB다(빌드 산출물).

**해결** — `build` `.gradle` `.idea` `local.properties` 를 빼면 **21MB**.
`안드로이드데모_설계.md` §2의 파워셸 명령을 쓴다.

### 7-2. 팀원이 열었더니 SDK 경로 오류

`9/16 · v0.6`

**원인** — `local.properties` 에 내 PC의 SDK 경로가 박혀 있다.

**해결** — 압축에서 뺀다. 팀원의 Android Studio가 자동으로 만든다.

### 7-3. `Compress-Archive` 가 경로를 못 찾는다

`9/16 · v0.6`

**증상** — `The path 'C:\Users\...\Desktop' either does not exist`.

**원인** — 바탕화면이 OneDrive로 리디렉션돼 있다.

**해결** — 절대 경로를 직접 지정한다(이 프로젝트는 `C:\Android\finalproject_demo_공유.zip`).

### 7-4. 그림이 내 PC에서만 보이는 것 아닌가?

`9/16 · v0.6`

**아니다.** 그림은 `app/src/main/res/drawable/` 에 있고 빌드할 때 APK에 들어간다.
**ComfyUI는 그림을 다시 뽑을 때만 필요하다.** 압축해 보내면 팀원 화면에도 똑같이 보인다.
