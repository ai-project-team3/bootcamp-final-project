## 1. 질문을 구워 두는 안은 빠르지만 아이 말을 받아 묻지 못합니다

| | ① 구운 질문을 Jev 가 고르고, 안 맞으면 생성 | ② Jev 는 리액션, 질문은 생성 |
|---|---|---|
| 질문 첫 소리 (추정) | 맞는 게 있으면 약 1.8초 | 지금 약 7.5초 → §2 개선 뒤 약 5초 |
| 아이 말을 받아 묻기 | 못 한다 — 구운 질문은 칸마다 일반 문장 | 한다 — 「문어가 먹물을 쐈구나! 그럼 바다는?」 |
| 차별점 2 「질문 순서가 고정이 아니다」 | 칸 고르기는 유지, **문장은 고정** | 칸 · 문장 모두 그때그때 |
| 같은 아이가 같은 질문을 다시 듣나 | 듣는다 | 거의 안 듣는다 |

### 확인된 것
- 서버 모드 동화는 이미 판정이 다음 칸을 고르고(`next_slot`), `/turn` 이 그 질문 문장을 쓴다 — `StoryPrompt.kt` `nextStoryPrompt()`. 앱이 직접 쓴 질문은 첫 두 턴(장소 · 사건)과 서버가 질문을 못 줬을 때의 비상 질문뿐이다
- `guidelines/10` §5 — 마스코트 받아주기 · 되돌려주기는 **아이 말을 인용한다**
- `guidelines/10` §6 원칙 — 구운 리액션은 **내용 중립**(판정 전에 나가므로 아이 말을 모른다)

### 조건부 함의
- ①을 택하면 칸마다 질문 변형을 많이 구워도 아이의 구체적인 말(「먹물」「해파리」)을 이어 받을 수 없으므로, 소크라틱 질문의 핵심인 「방금 한 말을 파고들기」가 약해진다
- ②에서 구운 질문은 **비상용과 첫 두 질문**에만 남기는 것이 설계와 맞는다

### 확인되지 않은 것
- ①의 「맞는 구운 질문」이 실제로 몇 % 나 나올지 — 잰 적 없다
- 아이가 질문 문장이 고정이라는 걸 알아차리는지 — 관찰한 적 없다

### 같이 생각해 볼 질문
- 비상 질문을 칸마다 몇 개 두면 「같은 질문을 또 듣는」 일이 체감되지 않을까 — 한 세션에 비상 질문이 몇 번 나가는지를 세면 정해진다
- 첫 두 질문(장소 · 사건)을 고정으로 두는 것이 차별점 2 와 충돌하나 — 동화 담당(민우)의 설계 이유를 들으면 정해진다

## 2. 아이가 기다리는 7.5초 중 판정이 2.3초로 가장 줄이기 쉽습니다

`eval/results.md` 10-01 22:00~23:00 · 공개 주소 기준 · 말 끝 → 마스코트 첫 소리.

| 단계 | 지금 | Jev 를 넣으면 (추정) |
|---|---|---|
| 말 끝 감지 (VAD) | 0.5초 | 0.5초 |
| 받아쓰기 `/stt` | 약 1.1초 | 약 1.1초 |
| 판정 (루나) | **약 2.3초** | **Jev 약 0.7초** (p95 0.73초 · 09-22) |
| 대사 (루나) | 약 1.8초 | 약 1.8초 — 받아주기를 리액션이 맡으면 더 짧을 수 있다 |
| 목소리 `/tts` | 약 1.8초 | 약 1.8초 |
| **첫 질문 소리까지** | **약 7.5초** | **약 5.9초** |
| 그 사이 들리는 것 | 없음 (10-01 밤 빌드부터 0초 중립 소리) | 0초 중립 · 약 1.8초 Jev 감정 리액션 |

### 확인된 것
- `/turn` 은 판정 → 대사를 **차례로** 돈다. 판정 약 2.3초 · 대사 약 1.8초(`bench_turn_split.py`, 답 3종 × 6회)
- Jev 9필드 품질은 새 루나와 **동률**(88.6% 대 88.0%, 875개 판단 중 5개 차이 · 09-26)
- Jev 는 확신도가 보정돼 있다 — 문턱 0.6 에서 선택 4필드 94.0%(09-26)
- Jev 는 9필드만 답한다. `value_1`(아이 말 원문) · `reason` 등 **책에 들어가는 글**은 루나에 남는다(`guidelines/10` §4)

### 조건부 함의
- 판정을 Jev 로 옮기면 루나 대사 호출은 남지만, 대사가 Jev 의 `next_slot` 만 보고 바로 시작할 수 있다면 판정 시간이 약 1.6초 준다
- 루나가 `value_1` 을 위해 판정을 계속 해야 한다면 **호출이 셋**(Jev · 루나 판정 · 루나 대사)이 되고, 이득은 병렬로 돌릴 수 있을 때만 생긴다

### 확인되지 않은 것
- **둘로 쪼갰을 때의 실제 총 지연** — `guidelines/10` §4 「붙일 때 재는 것」 ① · 아직 안 쟀다. **이 측정이 Jev 판정을 쓸지 가른다**
- 9필드만 Jev 로 받고 `value_1` 을 대사 호출에 함께 맡길 수 있는지
- 위 「추정」 칸 — 계산이지 측정이 아니다

### 같이 생각해 볼 질문
- `value_1` 을 대사 호출이 같이 쓰게 하면 호출을 둘로 유지할 수 있나 — 대사 스키마에 한 필드를 더해 재 보면 정해진다
- Jev 의 확신이 0.6 아래일 때 루나 판정으로 떨어뜨리면 평균 지연은 얼마가 되나 — 확신 분포를 보면 정해진다
