# 예상 질문과 답 (우리 덱 기준)

덱 부록의 예상 질문을 옮겨 온 것이다. 덱 부록이 줄어도 여기는 남긴다. 숫자는 [숫자_정본.md](숫자_정본.md)를 따른다.

## 기술과 검증

### 코딩 AI가 다 짠 것 아닌가요? (종훈)
코딩 에이전트를 적극적으로 썼습니다. 사람이 정한 건 규칙 아홉과 데이터 모델 정본, 데이터를 보기 전에 고정한 채택 기준, PR 리뷰와 CI입니다. AI가 만든 결과도 기준을 못 넘으면 버렸습니다.

### 받아쓰기를 왜 폰 안에서 하나요? 서버가 더 정확하지 않나요? (종훈)
서버용 large-v3는 3~5세 오류율 9%로 더 정확합니다. 그래도 폰 안 small(16%)을 고른 건 아이 음성이 폰 밖으로 나가지 않고, 받아쓰기에 GPU 비용이 붙지 않기 때문입니다. 원래 small은 37%였고 같은 학습법으로 16%까지 내렸습니다. 폰에서 한 마디 처리는 1.7초입니다.

### 앱이 무거워지지 않나요? (종훈)
앱은 약 93MB이고, 받아쓰기 모델 264MB는 설치 뒤 첫 실행 때 한 번 내려받습니다. 설치는 부모가 하니 와이파이에서 받게 안내합니다.

### 학습이 어른 말을 망가뜨리지 않나요? (종훈)
서버용 모델은 1차 학습에서 어른의 「아니」를 「하였니」로 적어 탈락시켰고, 반영 강도 0.75로 기준을 넘겼습니다. 폰용 small은 어른 짧은 대답 57개 중 36개로, 원래 small(39개)보다 3개 적습니다. 그래서 어른 대답 평가를 늘리는 것이 다음 과제입니다.

### AI로 만든 데이터면 점수가 부풀려진 것 아닌가요? (치영)
평가 100문항은 학습에 쓰지 않았고 비슷한 문장은 걸렀습니다. 그래도 실기기에서 지름길이 드러나 새 시험 96문항으로 68% → 15%로 고쳤습니다. 실제 아이 말로는 아직입니다.

### 규칙이 고르면 에이전트가 아니지 않나요? (진웅)
AI가 직접 고르는 방식도 같은 75문항으로 3번씩 비교했습니다. 정확도는 비겼고(97.8% 대 96.4%), 값은 규칙 쪽이 쌌습니다. AI는 뜻을 읽고 규칙이 행동을 고릅니다. 늘어난 기다림 0초.

### 지표 검증이 실패했는데 왜 계속하나요? (민우)
공개 데이터 답의 84%가 같은 문장 반복이고 질문 정보가 없었습니다. 재료가 맞지 않았다고 보고, 질문별 대답을 오또가 직접 쌓는 기록부터 만들었습니다.

## 제품과 운영

### 아이가 한 번 말하고 얼마나 기다리나요? (종훈)
아이가 말을 마치면 약 1.3초에 오또가 구워 둔 맞장구를 하고, 대답 대사는 실기기 8턴 가운데 약 8초에 나옵니다. 받아쓰기는 폰에서 1.7초입니다.

### 아이 개인정보는요? (종훈)
녹음한 소리와 말한 음성은 폰 밖으로 나가지 않습니다. 받아쓰기를 폰 안에서 하고 음성은 바로 지웁니다. 그림 원본은 아이가 「오또가 그려 줘」를 고를 때만 저희 GPU까지 가고 바로 지웁니다. 판정과 대사, 책 문장에는 글자가 외부 AI로 가고, 아이 호칭과 이름도 그 글자에 들어 있습니다. 보호자 동의를 먼저 받습니다.

### 사용자가 늘면 서버는 어떻게 되나요? (종훈)
테스트 PC에서 동시 30세션을 돌려 서버 오류가 0이었습니다. 한 달 1,600권을 넘으면 GPU 한 대를 켜 두는 쪽이 싸다는 것까지 계산해 뒀습니다. 받아쓰기는 폰에서 하므로 GPU는 그림에만 씁니다.

### 부모가 정말 돈을 낼까요? (종훈)
아직 모릅니다. 그래서 전환율, 이탈률, 한 달 권수를 베타에서 잽니다. 스탠다드는 한 달 별 30개를 다 써도 남도록 가격을 잡았습니다.

### 4명이 한 레포에서 어떻게 안 부딪혔나요? (진웅)
모드 단위로 담당을 나누고, 남을 깨뜨리는 규칙 아홉과 데이터 모델을 문서 한 곳에만 적었습니다. 기능 하나를 PR 하나로, CI가 초록이어야 병합합니다.

### 유튜브와 무엇이 다른가요? (민우)
유튜브는 아이가 보기만 합니다. 오또는 아이가 말해야 이야기가 굴러가고, 부모에게 남는 것도 시청 시간이 아니라 아이가 한 말입니다.
