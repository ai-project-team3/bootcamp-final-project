## 0. 결론 (예측 기준)

| 종류 | 판정 | 가장 유력한 길 |
|---|---|---|
| `background` | **대체 가능** | 우리 ComfyUI 워크플로를 그대로 쓰는 서버리스 GPU(C · Modal 또는 RunPod) — 그림체 그대로 · 책 한 권 ≈ 4~5원(예측). 그림 API(A)는 그림체 블라인드를 통과해야 해서 다음 순위 |
| `character` | **조건부 → C 면 가능** | 자세 틀 img2img · 오려 내기 · 발 93% 선을 그대로 가져가려면 워크플로 실행형(C)이어야 한다. A 는 틀을 따르는지 미확인 |
| `redraw` | **외부 그림 API 불가 · CPU 불가 · C(우리 계정 컨테이너)만 가능** | SDXL 을 CPU 로 돌리면 한 장 90~120초(예측)로 45초 밖. 원본을 메모리로만 받는 우리 노드(`otto_memory`)를 그대로 올릴 수 있는 C 만 남는다. 「빌린 GPU 를 우리 서버로 볼지」는 종훈 판단 |

- 13초를 지키는 열쇠는 **콜드 스타트**다. 0대까지 내리는 서버리스는 처음 켜질 때 20~60초(예측)라 그대로는 넘는다. Modal 메모리 스냅샷(「3초 아래」 · 공식 블로그) 또는 1대를 늘 켜 두는 설정이 필요하다 — 늘 켜 두면 값이 D 에 가까워진다.
- 실측으로 확정해야 할 것 하나만 꼽으면: **Modal(또는 RunPod)에 우리 워크플로를 올렸을 때의 첫 요청 시간.**

### 0-1. 클라우드로 옮길 때 한 달 그림 값 · 비용 기준 우선순위 (예측)

### 0-2. Modal 로 옮긴 구조

```
폰 ──▶ 백엔드(클라우드 CPU 서버) ──HTTP──▶ Modal 주소 ──▶ [GPU 컨테이너: 우리 ComfyUI + SDXL·Lightning + 자세 틀 · 오려 내기 + otto_memory]
        LLM · 안전 검사 · 기한 판단 · DB                       부탁이 올 때만 켜지고, 한동안 안 쓰면 꺼짐 · 켜진 초만 과금
```

- 백엔드는 GPU 가 필요 없다 — OpenAI 를 부르듯 Modal 주소를 부를 뿐. `comfy_url` 을 PC2 에서 Modal 주소로 바꾸는 정도(그림 순서 LLM · `omni-moderation` · 13초 판단은 그대로 백엔드).
- 모델 파일(약 7GB)은 Modal Volume 에, ComfyUI · 우리 노드는 컨테이너 이미지에 한 번 넣어 둔다.
- 단, 받아쓰기 · 라야 판정도 GPU 를 쓰므로 그 둘이 API · CPU 로 빠져야 백엔드가 CPU 만으로 된다(§6).
- 그림 한 장 계산 시간은 지금 PC2 약 3.7초(`config.py` 「3.74 s alone」) · Modal L4 약 2.5~3.5초(예측)로 비슷하다. 차이는 콜드 스타트뿐(§7).

### 0-4. 메모리 스냅샷 · 미리 깨우기 · 실제 책 흐름 재생 (10-12 실측 · 사용자 요청)

**스냅샷** — ComfyUI 를 별도 프로세스로 띄운 첫 구성은 7번 켜는 동안 한 번도 복원되지 않았다. ComfyUI 노드를 **같은 프로세스 안에서** 부르고(그래프 · 노드 코드는 서버와 같음) 모델을 GPU 에 올린 상태로 GPU 스냅샷(`enable_gpu_snapshot`, Modal 시험 기능)을 찍게 바꾸자 됐다.
- 처음 3번은 GPU 서버 종류마다 저장본을 만드는 회차(각 2~3분) — 공식 문서 「GPU 종류당 2~3개」와 같음
- 그 뒤 복원 **9~20초**(로그 `Restoring` → 준비, 4번) — 스냅샷 없이 약 40초
- 그러나 복원 시작 전 **GPU 배정 대기 15~200초**가 자주 붙었다(19시대 KST). 스냅샷으로 못 줄이는 부분

**실제 책 흐름 재생** — 흐름은 기기 기록 · 코드에서(동화 10턴 · 턴당 약 25초 `eval/results.md:113,3571` · 같이 만들기 21분 실기기 `:3197` · 그림일기 다시 그리기는 붓 멈춤 시점이라 3분 · 6분 가정). 꺼지는 대기 20초, 컨테이너가 켜진 시간을 2초마다 기록해 값을 냈다($0.000241/초 = 첫 청구 내역의 GPU+CPU+메모리 합산 단가).

| 책 | 미리 깨우기 | 첫 그림 기다림 | 둘째 그림 | GPU 켜진 시간 | 권당 |

| 동화(4.9분) | 시작 때 | **218.9초** ❌ — 깨우기도 GPU 배정을 기다림 | 5.1초 | 60초 | 약 19원 |

**책 내내 켜 두기**(책 시작에 깨우고 끝날 때까지 GPU 대기) — 초 단위 과금이라 계산으로 정확하다. 단가 $0.000241/초 ≈ **1분 19원**(1,344원/$).

**해 봤지만 뺀 것**
- **GPU 여러 종류 허용**(L4 · A10 · A10G): 스냅샷이 GPU 종류마다 따로 만들어져 콜드가 오히려 늘었다(§0-5 ③).
- **아시아 리전**(`region`): Modal 이 요청을 미국 동부에서 받아 넘겨서 켜져 있을 때 속도가 미국과 같았다(`routing_region` 에 동북아 없음). 값 1.75배, 꺼진 데서 첫 요청은 48.6~399.1초로 미국보다 나빴고, 일본은 10분 동안 컨테이너가 안 떴다(#460 ③).
