## 1. 프로젝트 · 빌드

### 1-1. Views 템플릿으로 만든 프로젝트에 Compose가 없다

`9/16 · v0.1`

**증상** — 사용자가 Android Studio에서 "No Activity"(또는 Empty Views Activity)로 만든 프로젝트에
Compose 코드를 넣으면 `Unresolved reference: androidx.compose`.

**원인** — Views 템플릿은 `appcompat` + `material`만 넣는다. Compose 플러그인도 의존성도 없다.

**해결** — 세 군데를 고친다.

```kotlin
// gradle/libs.versions.toml
kotlin-compose = { id = "org.jetbrains.kotlin.plugin.compose", version.ref = "kotlin" }
androidx-compose-bom = { group = "androidx.compose", name = "compose-bom", version = "2024.09.00" }

// build.gradle.kts (루트)
alias(libs.plugins.kotlin.compose) apply false

// app/build.gradle.kts
plugins { alias(libs.plugins.kotlin.compose) }
android { buildFeatures { compose = true } }
dependencies {
    implementation(platform(libs.androidx.compose.bom))
    implementation(libs.androidx.ui); implementation(libs.androidx.material3)
    implementation(libs.androidx.activity.compose)
}
```

> Kotlin 2.0부터는 `composeOptions { kotlinCompilerExtensionVersion }` 이 아니라
> **`kotlin.plugin.compose` 플러그인**을 쓴다. 옛 블로그를 따라 하면 버전 충돌이 난다.

### 1-2. 첫 빌드가 오래 걸리거나 실패한다

`9/16 · v0.1`

**증상** — 처음 열면 Gradle이 멈춘 것처럼 보인다.

**원인** — Compose 라이브러리를 처음 받는다(3~5분, 인터넷 필요).

**해결** — 기다린다. 사내망 등으로 `maven.google.com`이 막히면 받을 수 없다.

### 1-3. 코드 일부를 스크립트로 갈아 끼웠더니 클래스가 두 번 생겼다

`9/17 · v0.9`

**증상** — `Director.kt`가 534줄에서 854줄이 되고 `class Director`가 두 번 · 컴파일 오류가 쏟아짐.

**원인** — Python으로 "이 주석부터 저 주석 앞까지"를 바꿨는데, 끝 표시로 잡은 `/** [직접 그리기` 가 **파일 앞쪽 `Question` 안에도** 있었다. `index()`가 첫 번째 것을 잡아 앞부분이 통째로 복사됐다.

**해결** — 중복 구간을 지웠다. 앞으로는 바꿀 구간의 **시작 · 끝 표시가 파일에 한 번만 있는지** 먼저 센다(`s.count(표시) == 1`). 바꾼 뒤 `grep -n "^class\|fun "`으로 함수 목록을 한 번 본다.

## 2. Kotlin · Compose

### 2-1. ⭐ `R`이 리소스가 아니라 다른 것으로 잡힌다

`9/16 · v0.3`

**증상** — `Font(R.font.jua)` 에서 `Unresolved reference 'font'`. 리소스 파일은 분명히 있다.

**원인** — 같은 패키지(`ui`)의 `Theme.kt`에 **`val R = 26.dp`**(모서리 반지름)가 있었다.
같은 패키지의 이름이 자동 import보다 우선하므로 `R`이 `Dp`로 잡힌다.

**해결** — 리소스 쪽을 완전한 이름으로 쓴다.

```kotlin
val Jua = FontFamily(Font(com.example.finalproject_demo.R.font.jua))
```

> 한 글자 상수(`R`, `S`)를 패키지 최상위에 두면 이런 일이 난다. 새로 만들 때는 피한다.

### 2-2. ⭐ 문자열 템플릿 뒤에 한글이 붙으면 변수명으로 읽힌다

`9/16 · v0.4 · v0.5 두 번`

**증상** — `Unresolved reference 'v에'` 같은 오류. 소스에는 `$v` 만 썼다.

**원인** — Kotlin은 한글을 식별자 문자로 본다. `"$v에 불이"` 는 **`v에`** 라는 변수를 찾는다.

**해결** — 중괄호로 끊는다. `"${v}에 불이"`

이 프로젝트에서만 17곳이 걸렸다. 한 번에 고치는 스크립트:

```python
import re
s = re.sub(r'\$([a-zA-Z_][a-zA-Z0-9_]*)(?=[가-힣])', r'${\1}', s)
```

> 조사 처리 함수(`ga()` `eun()`)를 쓰면 `"$v${ga(v)} 흔들려"` 처럼 되어 이 문제가 안 난다.
> 한글이 바로 붙는 자리만 조심하면 된다.

### 2-3. Canvas에 그린 글자가 터무니없이 크다

`9/16 · v0.1`

**증상** — `drawText`로 그린 이모지가 카드를 뚫고 나온다.

**원인** — `scale(k)` 안에서 `fontSize = 70.sp` 를 주면 **sp가 density로 한 번,
`scale`로 또 한 번** 곱해진다.

**해결** — DrawScope 안에서는 px를 sp로 되돌려 준다.

```kotlin
tm.measure(text, TextStyle(fontSize = size.toSp()))   // size.sp (X)
```

### 2-4. `Modifier.layout` / `density` 를 못 찾는다

`9/16 · v0.1 · v0.5 두 번`

**증상** — `Unresolved reference 'layout'`, `Unresolved reference 'density'`.

**원인** — `androidx.compose.ui.layout.layout` import 누락 / `density`는 `DrawScope`·`PointerInputScope`
안에서만 쓸 수 있는데 일반 Composable에서 씀.

**해결** — 위치 계산은 `Modifier.layout` 대신 **`BoxWithConstraints` + `padding(maxWidth * 비율)`** 이 읽기 쉽다.
Composable에서 density가 필요하면 `LocalDensity.current.density`.

### 2-5. `quadraticTo` 가 없다

`9/16 · v0.1`

**증상** — Compose 1.7 이하에서 `Path.quadraticTo` 를 못 찾는다.

**해결** — `quadraticBezierTo` 를 쓴다(deprecated 경고는 나지만 동작한다).


### 2-6. `data object` → `data class`로 바꾸면 쓰던 곳이 깨진다

`9/16 · v0.7`

**증상** — `Stage.DrawPad`에 인자를 추가했더니 `Classifier 'data class DrawPad' does not have a companion object, so it cannot be used as an expression`.

**원인** — `data object`는 이름만 써도 값이지만 `data class`는 생성자 호출이 필요하다. `when`의 `Stage.DrawPad ->` 도 `is Stage.DrawPad ->`로 바꿔야 한다.

**해결** — 쓰던 곳을 전부 `Stage.DrawPad()`로. `grep -n "Stage.DrawPad" -r` 로 먼저 찾는다.

### 2-7. `key { … return@key }` 가 컴파일은 되는데 빌드(dex)에서 죽는다

`9/17 · v0.9`

**증상** — `compileDebugKotlin`은 통과, `assembleDebug`에서
`dexBuilderDebug … Method name '<anonymous>' in class '$$$$$NON_LOCAL_RETURN$$$$$' cannot be represented in dex format.`
`clean`을 해도 그대로.

**원인** — Compose의 `key(…) { }` 블록 안에서 `return@key`로 빠져나가게 쓴 것(`Hotspots.kt`). 컴파일러가 만든 클래스 이름을 dex가 받지 못한다.

**해결** — `return@key` 대신 **조건을 밖으로**: `if (보이는가) key(i) { … }`. Composable 람다 안에서는 라벨 return을 쓰지 않는다.

## 3. 화면 · 배치

### 3-1. ⭐ 에뮬레이터가 세로로 뜬다

`9/16 · v0.1`

**증상** — `screenOrientation="sensorLandscape"` 인데 세로로 나오고 화면이 잘린다.

**원인** — 에뮬레이터의 자동 회전이 켜져 있고 기기가 세로 상태.

**해결**

```
adb shell settings put system accelerometer_rotation 0
adb shell settings put system user_rotation 1
```

### 3-2. 첫 탭이 먹히지 않는다

`9/16 · v0.1`

**증상** — 앱을 켜고 버튼을 눌렀는데 반응이 없다.

**원인** — 전체 화면 진입 안내("Swipe down to exit full screen · Got it") 토스트가 위를 덮고 있다.

**해결** — 한 번 아무 데나 탭해 없앤 뒤 진행한다. 시연할 때 미리 한 번 켜 두면 안 나온다.

### 3-3. 글자가 서로 겹친다

`9/16 · v0.4`

**증상** — 미션 힌트가 별 6개와, 우물 이름이 도구 줄과 겹친다.

**원인** — 겹치는 두 요소를 모두 `TopCenter`·`BottomEnd`에 붙였다.

**해결** — 한쪽을 옮기거나 숨긴다. 이 프로젝트에서는 **책 장면에서 별 6개를 숨겼다**
(이미 다 찼고, 칸 진행은 책 단계에서 의미가 없다).

```kotlin
s.starsVisible = scene !in setOf(Scene.ADULT, Scene.PARENT, Scene.END, Scene.BESTIARY, Scene.MAKEHERO, Scene.BOOK)
```

### 3-4. 시작 화면 패널이 아래가 잘린다

`9/16 · v0.3`

**증상** — 작은 폰(높이 ~360dp)에서 "같이 시작하기" 아래 글씨가 안 보인다.

**원인** — 가로 모드 높이가 생각보다 낮다. 세로 여백을 넉넉히 잡으면 넘친다.

**해결** — 여백·글자 크기를 줄이고 문장을 합쳤다. 가로 데모는 **높이 360dp 기준**으로 잡는다.

### 3-5. 아이가 그린 그림이 찌그러지거나 너무 작다

`9/16 · v0.4`

**증상** — 가로로 길게 그린 그림이 세로로 늘어나고, 구석에 작게 그리면 책에서 점처럼 보인다.

**원인** — 좌표를 0~1로 정규화해 저장하면 **그림판의 가로세로 비율**이 사라진다.
그리고 캔버스 전체를 그리면 빈 여백까지 그려진다.

**해결** — 완료할 때 `drawingAspect = 폭/높이` 를 같이 저장하고,
그릴 때 **획의 바운딩 박스만 잘라** 비율을 지키며 채운다.


### 3-6. 질문이 바뀌었는데 앞 화면의 버튼이 남는다

`9/16 · v0.7`

**증상** — "이름은 뭐야?" 동안 그림판과 [다 그렸어]가, "어떤 게 마음에 안 들어?" 동안 좋아/싫어 카드가 그대로 보인다.

**원인** — `ask()`는 열린 질문에서 **무대를 바꾸지 않는다**(카드를 안 띄우니까). 앞 장면의 `stage`가 그대로 남는다.

**해결** — 열린 질문 전에 무대를 정리한다. 그림 한 장만 보여 주는 `Stage.Show(art, caption)`을 만들어 썼다.
**규칙: 열린 질문을 부르기 전에 `s.stage`가 누를 수 있는 것을 담고 있지 않은지 본다.**

### 3-7. 가로 화면에서 카드 3장 · 버튼 2개가 잘린다

`9/16 · v0.7`

**증상** — 중간 확인의 세 번째 카드가 화면 밖, 친구 평가의 [안녕 👋]이 카드 밖, 서랍의 칩 하나가 안 보임.

**원인** — Pixel 3a 가로는 **폭 약 740dp · 높이 약 360dp**(아래 띠 116dp 빼면 무대는 약 244dp). `Row`는 넘쳐도 줄바꿈하지 않는다.

**해결** — 넣을 것의 폭을 더해 본다. `그림 170 + 카드 158×3 + 간격` 처럼 줄이거나, 버튼은 세로로 쌓고, 칩은 두 줄로 나눈다.


### 3-8. 누르면 네모난 박스가 생긴다

`9/17 · v0.8`

**증상** — 책에서 인물 · 버튼을 누르면 회색 네모가 잠깐 번진다.

**원인** — 오류가 아니다. Compose `clickable`의 기본 눌림 효과(리플)가 그림의 사각 영역 전체에 그려진다.

**해결** — 그림을 누르는 곳은 `indication = null` 인 `noRippleClickable`(`ui/Chrome.kt`)을 쓴다. 반응은 흔들림 + 위에 뜨는 글자로 대신한다.

### 3-9. 떠 있는 요소가 무대 내용과 겹친다

`9/17 · v0.8`

**증상** — 아래 띠를 없앤 뒤 진행 막대가 그림판을, 책 인물이 안내문 · ▶를, 부모 모드 이름이 스크롤 내용을 덮는다.

**원인** — 떠 있는 요소는 레이아웃을 차지하지 않는다. 무대 쪽이 그 자리를 비워 두지 않으면 겹친다.

**해결** — 무대 안쪽 여백을 상수로(`TopChrome` 80dp · `BottomChrome` 76dp) 두고 `Centered {}` 로 감싼다.
스크롤 화면은 이름을 **스크롤 밖 고정 머리**로 옮긴다. 비율 배치(`Layer`)는 좌표를 더해 겹치지 않는지 본다(3-7과 같은 방식).

### 3-10. 진행 막대 밖에 반투명 네모가 떠 있다

`9/17 · v0.8`

**증상** — 막대 왼쪽 바깥에 흐린 사각형이 깜빡인다.

**원인** — 빛이 지나가는 효과의 x가 `-0.3 × 폭`부터 시작하는데, 채워진 부분 안에 있는지만 봤다(음수 검사 없음).

**해결** — `sx >= 0 && sx + h <= 채운 폭` 일 때만 그린다.

### 3-11. 고른 카드 뒤에 흰 네모가 생긴다

`9/17 · v0.9`

**증상** — 함께 하는 사람 카드를 고르자 그 카드의 그림 · 이름 뒤에 옅은 흰 네모.

**원인** — `.scale()` · `.alpha(1f)` · `.shadow()`를 겹치면서 생긴 그리기 층(에뮬레이터에서 보임). 그림 PNG는 투명이었다(확인함).

**해결** — `graphicsLayer { scaleX; scaleY; alpha }` 하나로 합쳤다. 이후 사용자 요청으로 카드 방식 자체를 녹음으로 바꿔 이 화면은 없어졌다.
**그림 뒤 네모가 보이면 먼저 PNG 투명도를 확인하고(`getpixel((5,5))`), 투명이면 층 겹침을 의심한다.**


### 3-12. 배경 속 것의 자리가 그림과 안 맞는다 · 빈 곳에 고리가 뜬다

`9/17 · v0.9`

**증상** — 눈밭에서 "눈 언덕" 고리가 아무것도 없는 눈 위에 뜸 · 눈송이 고리가 그려진 눈송이보다 훨씬 큼.

**원인** — 좌표를 눈대중으로 잡았다. 배경은 화면을 채우려고 **위아래가 잘려(Crop)** 그림 좌표와 화면 좌표가 다르다.

**해결**
- 자리 계산은 Crop과 똑같이: `scale = max(W/1344, H/768)` · `off = (그림 크기 × scale − 화면) / 2` (`Hotspots.kt`)
- 좌표를 정하면 **배경 4장 위에 원을 그려 한 장으로 확인**한다 (빨간 원 · 초록 선 = 화면에 보이는 띠 0.074~0.926)
- 뚜렷한 모양이 없는 것(언덕)은 넣지 않는다 → 먼 나무 2곳으로 바꿈


### 3-13. 반짝임이 스크린샷에 잡혔다 안 잡혔다 한다

`9/17 · v0.9`

**증상** — 같은 화면인데 어떤 캡처에는 금빛 고리가 있고 어떤 캡처에는 없음 → 연결이 끊긴 줄 알았음.

**원인** — 반짝임이 숨 쉬듯 밝기 0.25~0.8을 오가는데, 옅은 쪽에서 캡처하면 거의 안 보였다. 기능은 동작 중.

**해결** — 밝기 0.45~1 · 속이 빈 **금빛 고리** + ✨로 바꿔 어느 순간에도 보이게. **움직이는 효과는 캡처 한 장으로 판단하지 말고 두세 장 찍는다.**

**원인** — 이전 장면의 코루틴이 아직 살아 있고, 채널에 이전 입력이 남아 있다.

```kotlin
job?.cancelAndJoin()

s.buttons.clear(); s.stage = Stage.Empty; inputs(false, false)
job = scope.launch { runScene(scene) }
```

**원인** — 대본 버튼(시연용 지름길)과 화면 조작(아이가 실제로 쓰는 것)을 헷갈렸다.

**해결** — 아이가 해야 하는 동작은 **반드시 화면에도** 둔다. 대본 버튼은 지름길일 뿐이다.
이 프로젝트에서 뒤늦게 추가한 것: 책 ◀▶, [🔁 다시] [👍 이 소리로], [📚 책장에 꽂기], [👪 부모 모드].

### 4-4. "처음부터"를 눌렀더니 "연결할 수 없음" (웹 데모)

`9/15 · v0.0`

**증상** — HTML 데모에서 처음부터 버튼이 오류 페이지를 띄운다.

**원인** — `location.reload()` 인데, 확인용으로 띄웠던 로컬 서버를 꺼서 주소가 죽었다.

**해결** — 새로고침 대신 **페이지 안에서 상태만 되돌린다**(초기 상태를 JSON으로 저장해 두었다가 복원).

### 4-5. 답이 매번 똑같다

`9/16 · v0.4`

**증상** — 마이크를 눌러도 늘 같은 대사가 나온다.

**원인** — 질문에 답이 하나만 달려 있다.

**해결** — `spoken = listOf(Answer(...) × 5)`. 답마다 **뜻하는 값**을 붙여야 이야기가 그 답대로 이어진다.
`demo/Scenes.kt`에서 해당 질문을 찾아 후보를 늘린다.


### 4-6. 아이가 말한 장소와 책 제목이 다르다

`9/16 · v0.7`

**증상** — "눈 오는 데!"라고 했는데 제목이 『지호의 **공룡 나라** 여행』.

**원인** — 프리셋에 없는 장소는 가장 가까운 유형(`themeKey = dino`)의 뼈대를 쓰는데, 제목 후보가 `th.label`(유형 이름)을 읽었다.

**해결** — 화면에 보이는 장소 이름은 전부 `s.placeName`(아이가 말한 것 · 없으면 유형 이름)을 쓴다. 뼈대(탈것 · 미션)만 `th`에서 가져온다.

### 4-7. 책 문장에 같은 낱말이 두 번 나온다

`9/16 · v0.7`

**증상** — "지호와 몽몽이는 티라노와 **티라노** 등에 타고 별을 땄어요."

**원인** — 답 후보의 값(`solutionLine`)에 이미 "티라노 등에 타고…"가 있는데 문장 틀이 앞에 "티라노와"를 또 붙였다.

**해결** — 틀에서 뺐다. **답 값과 문장 틀 중 한 곳에만 이름을 넣는다.** 후보를 추가할 때 6쪽 자막을 소리 내 읽어 본다.


### 4-8. 어른이 답하지 않았는데 책에 어른 내용이 들어간다

`9/17 · v0.8`

**증상** — 장면 10에서 뜬금없는 "이모는 별을 따면 뭐 하고 싶어?"가 나오고, 아무도 안 눌렀는데 카드가 골라지고, 책 6쪽에 이모 문장이 나온다.

**원인** — v0.7 어른 칸이 "3초 안에 답이 없으면 마스코트가 프리셋에서 고른다"(구현대본 §2 문구)를 그대로 따랐고, 질문도 이야기 흐름과 이어지지 않았다.

**해결** — 질문을 흐름에 맞춰 "이모, ○○와 ○○가 친해지게 이모는 뭘 도와줄까?"로. 어른 질문 전용 `askAdult()`는 **답이 없으면 null** → 책 · 표지에 넣지 않는다.
**규칙: 어른 몫은 대신 채우지 않는다.** (아이 칸은 마스코트가 채워도 됨)

### 4-9. "처음으로"를 누르면 부모 기록이 비어 있다

`9/17 · v0.8`

**증상** — 책장 → 처음으로 → 부모 모드에서 "오늘은 아직 만든 책이 없어요".

**원인** — 처음으로에서 이야기 상태를 바로 지웠다.

**해결** — 이야기는 **다음 이야기를 시작할 때** 지운다(`sceneAdult` 시작 부분). 처음으로는 책장의 "새 책" 표시만 끈다.

### 4-10. 한국어 문장이 어색하게 붙는다 (v0.8에서 또)

`9/17 · v0.8`

**증상** — "심심했어**대**" · "로켓**에 엔진에** 불이 붙었어요" · 프리셋을 골랐는데 "지호가 **그린** 상어".

**원인** — 답 값(`causeLine = "…했어"`)을 그대로 이어 붙였다 / 틀과 값에 같은 말이 겹쳤다 / 그리기 여부를 보지 않았다 (4-7과 같은 종류).

**해결** — 전하는 말 도우미 `reported("…했어") = "…했대"`(`Missions.kt`) · 흔적 문장에서 겹치는 말 삭제 · `drawing.isEmpty()`면 "고른".
**새 답 후보를 넣으면 그 값이 들어가는 문장(질문 · 안내 · 자막)을 전부 소리 내 읽어 본다.**

### 4-11. "이어 짓기처럼" 답하게 했는데 3턴째 까닭 짓기로 올라간다

`9/17 · v0.9`

**증상** — 서랍에서 [이어 짓기처럼]을 골랐는데 가정 질문("지호가 외계인이었다면…")이 나오고 A/G 템플릿이 됨.

**원인** — 이어 짓기 아이의 답("같이 놀고 싶어서!")도 까닭(S1)을 담는다. 올림 조건이 "S1 또는 S2 2턴 연속"뿐이라 쉽게 올라갔다.

**해결** — 조사2 §4 표대로 **이어 → 까닭 올림은 S1 + 구조(계기 · 시도 · 결과 또는 잇는 말)** 일 때만 (`StoryBank.kt judge()`). 고르며 → 이어는 그대로 S1 또는 S2.
더미 답을 새로 넣을 때 ②(이어)는 **3어절 이상 · 구조 없음**, ③(까닭)은 **까닭 + 구조**로 맞춘다.


### 4-12. 템플릿과 상관없는 질문이 나온다

`9/17 · v0.9`

**증상** — C(위험-대응-도움형) 이야기 끝에서 "도착하면 보리랑 뭐 하고 놀까?"(E 여정형 질문).

**원인** — 해결 칸 `resolve`를 템플릿 다섯이 함께 쓰는데, 뽑을 때 템플릿을 보지 않았다.

**해결** — 변형 id 앞머리(`e_ · c_ · d_ · a_ · g_`)로 **지금 템플릿 것만** 뽑는다(`pick()`). 단위 테스트 `sharedSlotsUseOnlyTheCurrentTemplatesQuestions`.


### 4-13. 한국어 문장이 어색하게 붙는다 (v0.9에서 또)

`9/17 · v0.9`

**증상** — "과자를 건넸어요. 하지만 **목소리가 너무 커서** 잘 되지 않았어요" · "그러다 뭉치**도** 넘어졌어요" · "별이가 **둘이** 신나게 춤을 춰!" · 눈밭 이야기에 "공룡 알 둥지".

**원인** — 칸이 늘어나 조합이 수천 가지가 됐는데, 칸끼리 서로를 모른 채 이어진다(실패 까닭 ↔ 첫 시도, 결과 ↔ 앞 문장, 장소 ↔ 빌려 온 뼈대).

**해결** — 어떤 조합에도 맞는 말로 고침 · 눈밭 전용 지나갈 곳 · 도착할 곳 · 본 것. 그리고 **글자 검사 테스트**(`app/src/test/.../StoryTextTest.kt`)를 만들었다 —
템플릿 × 함께 하는 사람 × 장소 × 답을 모두 만들어 자리표시 · 겹친 조사 · 높임말 누락을 찾고, 문장을 `app/build/story_samples.txt`에 남긴다.
```
./gradlew :app:testDebugUnitTest --tests "*StoryTextTest*"
```
**자동 검사는 "마을을"처럼 맞는 말도 잡는다 — 걸린 줄은 반드시 눈으로 본다. 흐름(앞뒤가 맞나)은 샘플을 읽어야만 보인다.**


### 4-14. 앱을 다시 켜면 지난번과 같은 질문이 나온다

`9/17 · v0.9`

**증상** — 1회 · 3회 · 4회 모두 장면 4에서 "누가 제일 깜짝 놀랐을까?".

**원인** — "지난 이야기에서 쓴 질문"은 메모리에만 있다(데모는 저장소 없음). 시험하며 앱을 매번 강제 종료했다.

**해결** — 한계로 둔다. **같은 실행 안에서** [🏠 처음으로] → 새 이야기로 확인한다. 실제 앱은 폰 로컬 DB에 저장할 자리.

## 5. 그림 생성

### 5-1. ⭐ ComfyUI가 조용히 죽는다

`9/16 · v0.3`

**증상** — 그림 생성 중 서버가 응답하지 않는다. 로그 마지막이 `Requested to load Krea2`.

**원인** — **에뮬레이터와 ComfyUI가 GPU 8GB를 같이 쓴다.** 모델을 올리다 메모리가 모자라 죽는다.

**해결** — **그림을 뽑을 때는 에뮬레이터를 끈다.**

```
adb emu kill
powershell -ExecutionPolicy Bypass -File D:\ComfyUI\start_comfyui_silent.ps1
```

### 5-2. `generate_image` 가 체크포인트를 못 찾는다

`9/16 · v0.3`

**증상** — checkpoints가 비어 있다고 나온다.

**원인** — 이 PC의 모델은 `checkpoints/`가 아니라 **`diffusion_models/`** 에 있다(krea2 turbo).

**해결** — 자동 선택에 맡기지 말고 `UNETLoader + CLIPLoader + VAELoader` 로 그래프를 직접 짠다.
`tools/gen_assets.py`의 `txt2img()` 가 그 형태다.

### 5-3. 배경이 안 지워지거나 반대로 지워진다

`9/16 · v0.3`

**증상** — 캐릭터가 사라지고 배경만 남는다.

**원인** — `RemoveBackground` 가 내놓는 마스크의 방향이 반대다.

**해결** — `InvertMask` 를 한 번 거쳐 `JoinImageWithAlpha` 에 넣는다(`tools/gen_assets.py`의 `bgremove()`).

### 5-4. 첫 생성이 한 번 실패한다

`9/16 · v0.3`

**증상** — 모델을 처음 올릴 때 `HostBuffer.read_file_slice failed`.

**원인** — 콜드 로드 시 간헐적으로 난다(RTX 4060 Laptop + NVFP4 양자화).

**해결** — **같은 작업을 다시 큐에 넣으면 통과한다.** 스크립트에 재시도 2회가 들어 있다.
1024² 8스텝에 약 50초가 걸리는 것은 정상이다(NVFP4 에뮬레이션).

### 5-5. 눈 스티커가 엉뚱한 곳에 붙는다

`9/16 · v0.4`

**증상** — 반달눈·별눈이 머리카락이나 안경테 위에 그려진다.

**원인** — "어두운 픽셀"만으로 눈을 찾으면 **갈색 머리와 안경테**가 같이 걸린다.

**해결** — `tools/find_eyes.py` 는 세 단계로 찾는다.
① 살색 픽셀로 **얼굴 덩어리**를 찾고 → ② 얼굴 상자 안쪽(가로 15~85% · 세로 28~66%)에서만 어두운 덩어리를 모아
→ ③ **같은 높이에 나란한 두 덩어리**를 눈으로 본다. 못 찾으면 기본값을 쓴다(앱은 그대로 돈다).
주인공 그림을 새로 뽑았으면 **반드시 다시 돌린다.**

### 5-6. 그림을 넣었는데 화면에 안 나온다

`9/16 · v0.5`

**증상** — `res/drawable`에 넣었는데 이모지가 그대로 나온다.

**원인** — 파일 이름이 코드가 찾는 이름과 다르다. 이름으로 찾는 구조라 **오타가 조용히 무시된다.**

**해결** — `Art.Img("이름", 대신그릴것)` 의 "이름"과 파일명(확장자 제외)을 맞춘다.
파일명은 소문자 · 숫자 · 밑줄만 쓴다(대문자·한글·하이픈은 Android 리소스 이름으로 못 쓴다).


### 5-7. `gen_icons.py`를 import하면 전체 생성이 돌아간다

`9/16 · v0.7`

**증상** — 새 그림 4장만 만들려고 `from gen_icons import ...` 했더니 기존 42장 작업이 시작될 뻔했다.

**원인** — 생성 스크립트들은 파일 맨 아래에서 바로 서버를 기다리고 작업을 돈다(`if __name__ == "__main__"` 없음).

**해결** — 필요한 도우미를 복사한 독립 스크립트 `tools/gen_extra.py`를 만들었다. 새 그림은 여기에 줄을 추가한다.
만든 뒤 소품은 **512px**로 줄인다(다른 소품과 같은 크기 · v0.6 규칙).


### 5-8. 그림 스크립트를 돌리는 동안 코드를 고쳐도 된다 · 끝나면 크기를 줄인다

`9/17 · v0.8`

**증상** — 새 그림 26장(약 25분) 기다리는 시간이 길다 · 그대로 넣으면 1024px라 용량이 커진다.

**원인** — ComfyUI와 에뮬레이터가 GPU를 같이 못 쓴다(5-1) · 생성 크기는 1024px.

**해결** — 에뮬레이터를 끄고 `python gen_extra.py > log &` 로 **뒤에서** 돌리고, 그동안 코드를 고친다(그림이 없어도 `AssetImage` 대체 그림으로 빌드된다 · 4-4 설계).
끝나면 오브젝트 · 소품은 **512px**, 그림체 견본은 **384px**로 줄이고 한 장짜리 모아보기(contact sheet)로 눈으로 확인한다.

## 6. 에뮬레이터 · 확인

### 6-1. 스크린샷 좌표가 안 맞는다

`9/16 · v0.1`

**증상** — 스크린샷을 보고 누른 자리가 엉뚱하다.

**원인** — 스크린샷은 2220×1080인데 보이는 이미지가 축소돼 있다.

**해결** — 보이는 좌표 × 1.11 = 실제 좌표. `adb shell input tap <실제x> <실제y>`.

### 6-2. 에뮬레이터가 부팅됐는지 알 수 없다

`9/16 · v0.1`

```
adb wait-for-device
adb shell getprop sys.boot_completed     # 1이면 완료
```

### 6-3. 앱을 다시 설치했는데 옛 화면이 나온다

`9/16 · v0.2`

**해결** — `adb shell am force-stop com.example.finalproject_demo` 후 다시 시작한다.
`installDebug` 만으로는 실행 중인 프로세스가 안 바뀐다.

### 6-4. 빌드가 "up-to-date"라 바뀐 그림이 반영되지 않는다

`9/16 · v0.6`

**증상** — 그림 파일을 바꿨는데 APK 크기가 그대로다.

**원인** — Gradle이 리소스 변경을 못 알아챘다(파일을 덮어쓰면 타임스탬프만 바뀐 것으로 볼 때가 있다).

**해결** — 용량을 재거나 최종 확인을 할 때는 `./gradlew clean assembleDebug`.


### 6-5. 시연 서랍이 안 열린다 (앱을 막 켰을 때)

`9/16 · v0.7`

**증상** — 오른쪽 위를 길게 눌러도 서랍이 안 열리거나, 첫 탭이 먹지 않는다.

**원인** — 3-2와 같다. 전체 화면 안내가 첫 입력을 가져간다. 오른쪽 위에는 시작 화면의 ⭐도 있다.

**해결** — 아무 데나 한 번 탭한 뒤 길게 누른다. adb로는 `input swipe 2170 60 2170 60 1200` 처럼 **구석 끝 · 1.2초**.

### 6-6. 에뮬레이터가 어느새 꺼져 있다

`9/16 · v0.7`

**증상** — `adb: no devices/emulators found`.

**원인** — 그림 생성 전에 `adb emu kill`로 끈 뒤(5-1) 다시 켜지 않았다.

**해결** — 그림을 다 만든 뒤 다시 켜고 부팅을 기다린다.

```
emulator -avd Pixel_3a -no-snapshot-load -no-boot-anim &
until [ "$(adb shell getprop sys.boot_completed | tr -d '\r')" = "1" ]; do sleep 5; done
adb shell settings put system user_rotation 1
```


### 6-7. adb로 순서대로 누르는 시연 스크립트가 중간에 어긋난다

`9/17 · v0.8`

**증상** — 🎤 두 번 → 다음 장면… 을 고정 순서로 누르면 어느 순간 엉뚱한 버튼(직접 그리기 등)을 누르고 멈춘다.

**원인** — 아이 답이 **무작위**라 장면마다 질문 수가 다르다(예: 까닭 짓기 조건이면 가정 질문이 하나 더 · 프리셋 친구면 화면이 다름).

**해결** — 고정 순서는 짧게 끊고 **매 구간 스크린샷으로 확인**한다. 특정 장면만 볼 때는 시연 서랍 **장면 이동** + 대본 버튼을 쓴다.
서랍은 스크롤 위치가 매번 달라지므로 좌표를 외우지 말고 캡처로 찾는다.

### 6-8. 에뮬레이터가 계속 `offline` 이다

`9/17 · v0.9`

**증상** — `adb devices` → `emulator-5554 offline` 이 10분 넘게 · `adb kill-server` · 창 없이(`-no-window`) · 소프트웨어 그래픽으로 다시 켜도 그대로. 창에는 `UpdateLayeredWindowIndirect failed` 경고.

**원인** — 확실하지 않다. 앞서 멈춘 에뮬레이터를 강제 종료한 뒤라 **사용자 데이터 디스크가 깨진 것**으로 보인다(경고는 창 표시 문제라 무관).

**해결** — 데이터를 지우고 새로 부팅: `emulator -avd Pixel_3a -wipe-data -no-snapshot -no-boot-anim -gpu host` → 1분 안에 부팅.
지우면 설치한 앱 · 설정(가로 고정 등)이 사라지므로 **다시 설치 · `user_rotation 1`**. 이 AVD에는 데모 앱만 있어 잃은 것은 없다.


### 6-9. 화면 글자를 읽어 가며 자동으로 진행한다 (고정 대기 대신)

`9/17 · v0.9`

**증상** — 고정 `sleep` 순서(6-7)가 매번 어긋남 — 함께 하는 사람이 먼저 말하는 동안 🎤를 눌러 답이 안 들어가고, 그 뒤 순서가 하나씩 밀림.

**해결** — `uiautomator dump`로 **Compose 글자를 읽을 수 있다**. 스크래치 스크립트 `drive.py`가
맨 위 화면 이름 · 아래 말풍선을 읽고 → 물음표로 끝나면 🎤 두 번 → 말풍선이 바뀌었는지 확인 → 장면마다 스크린샷 · 로그(`<이름>_log.txt`).
**한계** — 따옴표가 든 자막과 시연 서랍의 대본 버튼 글자는 dump에 안 나와서, 그 부분은 스크린샷으로 본다. 서랍에서 특정 답을 누르는 건 자동으로 못 했다.

## 7. 공유 · 배포

### 7-1. ⭐ 압축 파일이 500MB가 넘는다

`9/16 · v0.6`

**원인** — `app/build/` 만 436MB다(빌드 산출물).

**해결** — `build` `.gradle` `.idea` `local.properties` 를 빼면 **21MB**.
`안드로이드데모_설계.md` §2의 파워셸 명령을 쓴다.

### 7-2. 팀원이 열었더니 SDK 경로 오류

`9/16 · v0.6`

**원인** — `local.properties` 에 내 PC의 SDK 경로가 박혀 있다.

**해결** — 압축에서 뺀다. 팀원의 Android Studio가 자동으로 만든다.

### 7-3. `Compress-Archive` 가 경로를 못 찾는다

`9/16 · v0.6`

**증상** — `The path 'C:\Users\...\Desktop' either does not exist`.

**원인** — 바탕화면이 OneDrive로 리디렉션돼 있다.

**해결** — 절대 경로를 직접 지정한다(이 프로젝트는 `C:\Android\finalproject_demo_공유.zip`).

### 7-4. 그림이 내 PC에서만 보이는 것 아닌가?

`9/16 · v0.6`

**아니다.** 그림은 `app/src/main/res/drawable/` 에 있고 빌드할 때 APK에 들어간다.
**ComfyUI는 그림을 다시 뽑을 때만 필요하다.** 압축해 보내면 팀원 화면에도 똑같이 보인다.

5. 자주 걸릴 것 같으면 제목 앞에 ⭐ 를 붙이고 맨 위 "빠른 찾기"에도 줄을 추가
