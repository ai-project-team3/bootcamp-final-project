## 0. 한 줄로

**일기 모드는 일기를 만들지 않는다.** 아이에게 오늘 무슨 일이 있었는지 묻고,
그 **실제 사실을 재료로 동화책을 만든다.** 결과물은 동화 모드와 똑같은 6~8쪽 동화책이다.

⚠️ **"일기"는 팀 안에서만 쓰는 이름이다.** 아이 화면에 "일기"라고 쓰지 않는다 — 아이에게 숙제처럼 들린다.
마스코트가 *"오늘 뭐 했어?"* 로 시작하는 것으로 충분하다.

| | 동화 모드 | 일기 모드 |
| --- | --- | --- |
| 첫 질문 | "오늘은 어디로 **가 볼까**?" | "오늘 어디 **갔었어**?" |
| 재료 | 상상 | **아이의 실제 하루** |
| 결과물 | 6~8쪽 동화책 | **같다** |
| 끝나는 조건 | `story_ready` · `mascot_pick` 2회 · 15분 | **같다** (§3) |
| 칸이 안 찰 때 | 마스코트가 대신 고른다 | **먼저 질문을 바꿔 다시 묻는다**(§4). 그다음은 같다 |
| 마스코트가 채우면 | 무해하다 — 지어낸 이야기다 | ⚠️ **아이가 하지 않은 일이 하루로 적힌다**(§3) |

아이가 얻는 것: 오늘 있었던 일이 동화책이 된다.
**부모 리포트에 원문이 남는 것은 앱의 기존 동작이지 이 모드의 목적이 아니다** (§6).

## 1. 무엇을 새로 만드나 — S3의 질문 세트 하나

```
S1 시작 ─[오늘 뭐 했어?]─→ S3′ ──→ S8 책 만드는 중 ──→ S9 책 ──→ S10 ──→ S11
                            │        (그대로)          (그대로)
                  질문 세트와 칸 목록만 갈아끼움
            └─[이야기 만들기]─→ (동화 모드 그대로)
```

| 재사용하는 것 | 손대는 것 |
| --- | --- |
| 마스코트 한 턴 3조각(§0-2) · 기다리는 시간(§0-3) · 무응답 흐름(§5) | **S3의 질문 세트** |
| 판정 스키마와 프롬프트 · 러너 · 채점기 | S1에 버튼 한 개 |
| 수준 3단계 · 템플릿 확정 규칙(§3) | 칸 목록(필수/선택) |
| S8 책 만들기 · S9 책 · 미션 2개 · S10 친구 평가 · S11 끝내기 | — |
| 이름 사전 · 데이터 경로(§0-4) · 이벤트(§0-5) | — |

**새 화면은 없다.** 이것이 지시서 §2-5의 *"칸 구조는 그대로 쓴다"* 를 가장 싸게 만족시키는 형태다.

## 2. 칸 — 새 칸 이름을 만들지 않는다

⚠️ **판정 스키마의 enum 11개 안에서 끝낸다.** 칸 이름을 하나라도 추가하면
박진웅이 9/18에 확정한 스키마가 바뀌고, 최민우에게 넘긴 **평가셋 100개가 무효가 된다.**

### 2-1. 기승전결 네 자리 (필수)

| 기승전결 | 칸 | 묻는 것 | 신호 |
| --- | --- | --- | --- |
| **기** | `place` | 오늘 어디 있었어 | 기준 질문 ① |
| **승** | `problem` | 무슨 일이 있었어 | 기준 질문 ② |
| **전** | `cause` | 왜 그랬을까 | **S1** |
| **결** | `solution` | 어떻게 됐어 | S2 |

### 2-2. 선택 칸

| 칸 | 묻는 것 | 쪽수에 미치는 영향 |
| --- | --- | --- |
| `reaction` | 그래서 어떻게 됐어 · 기분 | 전을 2쪽으로 |
| `newcomer` | 그 친구를 그려 줄래 | 등장 쪽 1장 |
| `name` | 이름은 뭐야 | — |
| `title` | 이 책 이름은 | 표지 |

**묻지 않는 칸**: `sound`(공룡 소리는 상상 세계의 것) · `adult`(어른 칸은 동화 모드 전용) · `companion`

필수 칸이 동적(`no_longer_needed`)이므로 스키마는 이 형태를 이미 허용한다.

## 3. 끝나는 조건 — 셋이고, 동화 모드와 같다

`guidelines/2` §1-1: **`story_ready: true` · `mascot_pick` 2회 연속 · 15분 경과.**
새로 만들지 않는다. 일기 모드는 **같은 셋을 쓰고, 도달하는 방식만 다르다.**

```
질문 → 답 → 판정 → 칸 채움 ──┐
  ↑                          │
  └── 기승전결 네 자리 중 빈 곳이 있으면 ──┤
      사다리를 내려가며 질문을 바꾼다(§4)   │
                                          │
      네 자리가 다 차면 ──────→ story_ready ──┐
      사다리가 다 떨어지면 ───→ mascot_pick 2회 ─┼→ S8 책 만들기
      15분이 지나면 ─────────────────────────┘
                                                └ 모인 칸으로 만든다 (§5)
```

| 조건 | 동화 모드 | 일기 모드에서 뜻하는 것 |
| --- | --- | --- |
| `story_ready` | 이야기 재료가 찼다 | 같다 — 기승전결 네 자리(§2-1) |
| **`mascot_pick` 2회 연속** | 마스코트가 두 번 대신 골랐다 | **질문을 바꿔 묻는 사다리가 다 떨어진 지점**이다. §5가 여기서 시작한다 |
| 15분 경과 | 시간 초과 | 취침 루틴이라 15분이 길다 → §7-5 |

### 3-1. 턴 상한을 두지 않는 이유

`CLAUDE.md` 「규칙 아홉」 ③:

> 턴 상한을 두지 않는다. 8턴 상한은 우리 핵심 지표인 **「주고받기 횟수」를 스스로 깎는다**

동화 모드의 *"8턴이 지나면 남은 칸은 마스코트가 채운다"* 를 쓰지 않는 이유가 이것이다.
아이가 신나서 계속 말하는 건 제품이 원하는 일이다.

⚠️ **전에 여기에 "마스코트가 채우면 수준 판단과 리포트가 오염된다"고 적었는데 틀렸다.**
출처 `by` 3종(§5-1)이 이미 막아 준다. `mascot`은 주고받기 횟수·수준 신호·리포트 인용에서 전부 빠진다.

### 3-2. ⚠️ 그래서 일기 모드에만 남는 문제

데이터는 안 깨진다. **깨지는 것은 내용이다.**

| | 동화 모드 | 일기 모드 |
| --- | --- | --- |
| 마스코트가 `place`를 "우주"로 채움 | 무해하다. 처음부터 지어낸 이야기다 | **아이가 가지 않은 곳이 그 아이의 하루로 적힌다** |

그래서 일기 모드는 **마스코트가 대신 고르기 전에 사다리를 먼저 다 내려간다**(§4).
사다리가 재는 것은 "아이가 답할 수 있는 질문이 아직 남았는가"다. 남아 있으면 마스코트가 나설 자리가 아니다.

- 쪽수는 **6~8쪽**(§7-1 ①). 기획안: 기 1 / 승 1~2 / 전 2 / 결 1 / 에필로그 1 → 기본 6쪽, 선택 칸까지 차면 8쪽.

## 4. 질문 넷과 사다리 ⭐ 오늘의 산출물

동화 모드와 **같은 자리**에 놓인다. 1턴이 기준 질문 ①, 2턴이 ②, **3턴째에 템플릿을 확정**한다(구현대본 §3).

**말을 안 할 때는 답을 고르게 하지 않고 질문을 바꾼다.** 아래로 갈수록 기억을 덜 꺼내고 눈앞의 것에 답하게 된다.
조사2: 쉬운 질문으로 다시 묻는 구조가 반응률과 맞는 답을 둘 다 올렸다.

### 4-1. 1턴 · 어디 (`place` · 쉬움 5초 · 기준 질문 ①)

```
1  "오늘 어디 갔었어?"
2  "어린이집, 놀이터, 할머니 집. 오늘은 어디 있었어?"      ← 선택지 먼저, 질문 마지막
3  "아침에 밥 먹고 어디 갔어?"                            ← 시간 단서
```

### 4-2. 2턴 · 무슨 일 (`problem` · 어려움 8초 · 기준 질문 ②)

```
1  "거기서 무슨 일이 있었어?"
2  "오늘 뭐 하고 놀았어?"                                ← 놀이로 좁힘
3  "오늘 제일 재밌었던 거 하나만 말해 줄래?"                ← 하나만
4  "속상한 일도 있었어? 아니면 다 재밌었어?"                ← 순서를 매번 섞는다
```

### 4-3. 3턴 · 왜 (`cause` · 어려움 8초 · **S1이 나오는 자리**)

```
1  "왜 그랬을까?"
2  "{친구1}는 왜 그랬을 것 같아?"                         ← 남의 입장
3  "그래서 {주인공}는 어떻게 했어?"                        ← 까닭이 안 나오면 시도로
```

### 4-4. 4턴 · 어떻게 됐어 (`solution` · 어려움 8초 · S2)

> 지시서 §2-5는 *"오늘은 질문 3개까지"* 라고 했지만 **기승전결은 네 자리다.** 셋으로는 책이 안 나온다.
> 지시서의 "3"은 기승전결 요구가 정해지기 전에 적힌 숫자로 보고 넷째까지 썼다.

```
1  "그래서 어떻게 됐어?"
2  "그다음에 뭐 했어?"                                  ← 순차로 좁힘
3  "누가 도와줬어?"                                     ← 의문사 하나 · 도움
4  "다 끝나고 뭐 했어?"                                 ← 마무리
```

⚠️ **여기서 나오는 순차 답은 S1이 아니다.** *"가서 먹었어"* · *"일어나서 밥 먹었어"* 는 일이 일어난 차례를 말한 것이다.
2번 사다리("그다음에")가 순차 답을 **유도하는** 자리라 여기서 판정이 가장 많이 틀린다.
평가셋의 `-서` 함정과 같은 지점이다(`eval/평가셋_라벨링_지침.md` §2-8).

### 4-5. 질문을 쓸 때 지킨 규칙 (조사2 · 진웅에게 부탁한 것과 같다)

| 규칙 | 왜 |
| --- | --- |
| **의문사 하나만** | "누구랑 뭐 했어?" 는 아이가 하나만 답하고 만다 |
| **선택지 먼저, 질문 마지막** | 중간에 질문 억양이 있으면 말이 끝나기 전에 대답한다 |
| **예/아니오로 확정하지 않는다** | 3~4세는 "응"으로 기울어진다 |
| **선택지 순서를 매번 섞는다** | 뒤에 들은 것을 고르는 경향이 있다 |
| **'언제' 질문은 낮은 단계에서 뺀다** | 시간 표현이 아직 안 선다 |

⚠️ **일기 모드의 질문은 동화 모드보다 어렵다.** 상상이 아니라 **기억을 꺼내야** 한다.
같은 아이가 일기 모드에서 낮은 수준으로 나올 수 있다 → §7-3.

## 5. 기승전결이 안 뽑히면 — 모인 답변으로 만든다

**책은 언제나 나온다.** 구현대본 §5: *"말을 안 해도 책은 완성돼. 벌점·아쉬움 표현 없음."*

시작 지점은 **`mascot_pick` 2회 연속**이다(§3). 사다리가 다 떨어졌다는 뜻이고, 이미 있는 종료 신호라
새로 만들 것이 없다. 그때까지 **모인 답변을 그대로 재료로 넘겨 6~8쪽을 만든다.**

```
모인 칸이 2개 ("블록 쌓았어" · "민준이가 무너뜨렸어")
  → 기: 블록을 쌓았다        아이 말
  → 승: 무너졌다            아이 말
  → 전: (LLM이 이야기로 메움)
  → 결: (LLM이 이야기로 메움)
  → 6쪽
```

**왜 메워도 되나**: 이 모드는 일기가 아니라 **동화책**이다(§0). 아이 말은 씨앗이고 나머지는 원래 이야기다.
동화 모드도 같은 자리에서 마스코트가 칸을 채운다.

### 5-1. 출처 `by` 를 끝까지 구분한다 — 이게 리포트를 지킨다

`guidelines/2` §1-4. **이 표가 "메워도 된다"의 근거다.**

| | `child` (말로) | `card` (골라서) | `mascot` (대신 정해 줌) |
| --- | --- | --- | --- |
| **책 자막** | ✅ | ✅ | ✅ 이야기의 일부다 |
| **주고받기 횟수** | ✅ | ✅ | ❌ |
| **수준 신호 (S1·S2)** | ✅ | ❌ | ❌ |
| **리포트 원문 인용** | ✅ | ❌ | ❌ |
| 「말한 방식」 원그래프 | 말로 | 골라서 | **표시하지 않는다** |

LLM이 메운 자리는 `by: mascot`으로 들어간다. **책에는 보이고, 수준 판단과 리포트 인용에는 안 들어간다.**
그래서 부모 리포트가 거짓말을 하지 않는다.

> 원그래프에 `mascot`을 안 넣는 이유도 같은 절에 있다 — *"마스코트가 대신함 30%"* 가 뜨면
> **부모가 아이의 실패로 읽는다.** 그건 우리 설계가 만든 숫자이지 아이의 행동이 아니다.

- 아이가 한 말은 `utterance` 이벤트로 원문이 남는다(`by: child`).
- 칸이 하나도 안 찼을 때(완전 무응답)만 남는 문제 → §7-4.

## 6. 이름과 데이터 경로 — 기존 규칙 그대로

```
아이 말 "근데 민준이가 무너뜨렸어"
   ├─ utterance 이벤트에 원문 그대로 ──────────→ 부모 리포트가 이걸 인용
   └─ 이름 사전(민준이 → {친구1}) → LLM ──────→ 자막 "친구가 무너뜨렸어요"
```

- **자막은 다듬고, 리포트 인용은 원문**이다(기획안). 기존 규칙이고 일기 모드에서 바뀌지 않는다.
- **친구 실명은 아이 이름과 같은 취급.** 이름 사전에 넣고 폰에만 둔다. LLM·서버로 보내지 않는다(조사3 §3-2).
- 일기 모드에서 실명이 더 많이 나온다(어린이집 친구 · 선생님). **이름 사전에 들어가는 항목이 늘어난다**는 점만 다르다.

| 3 | **⭐ 1개를 쓴다** | 동화 모드와 같다 → 7-2 |
| 4 | **기승전결이 안 뽑히면 모인 답변으로 만든다** | §5 |
| 5 | **멘토 #9 부모-자녀 협업은 보류** | 이 설계에 넣지 않는다. 9/23 범위에서 뺀다 |

### 7-2. ⚠️ ⭐와 월 권수 — 수익모델과 부딪힌다

⭐는 재화가 아니다. **하루에 만들 수 있는 이야기 개수**이고 부모가 설정에서 정한다(구현대본 §S12).
아이 화면에 구매 버튼도 가격도 없다(결정 28).

**문제는 ⭐가 아니라 요금제의 월 권수다.**

| | 값 | 일기 모드를 매일 하면 |
| --- | --- | --- |
| 기본 · 3,900원 | 월 2권 | **이틀 만에 끝난다** |
| + · 9,900원 | 월 8권 | 8일 |

일기 모드는 6~8쪽 동화책을 만들므로 **원가도 월 권수 소모도 동화 모드와 같다.**
그런데 취침 루틴으로 매일 쓰라고 파는 기능이다. **월 2권과 정면으로 부딪힌다.**

| 안 | 뜻 |
| --- | --- |
| 일기 모드는 권수를 따로 센다 | 매일 가능. 원가가 요금제를 넘는지 계산이 필요하다 |
| 쪽수를 줄여 원가를 낮춘다 | 6~8쪽 확정(7-1 ①)과 어긋난다 |
| 월 권수를 올린다 | 원가 계산부터 |

→ **조장·멘토 #11(수익모델)과 함께 정해야 한다.** 이 설계만으로는 못 정한다.
1차에는 결제를 코드에 넣지 않으므로(기획안 §15) **9/23 발표까지는 막히지 않는다.**

### 7-3. 수준을 모드별로 볼까, 공유할까

지시서 §2-5는 *"판정·수준·리포트는 공유"* 라고 했고 기본은 공유다.
다만 일기 모드의 질문은 기억 인출이라 더 어렵다(§4-5). 공유하면 **일기 모드에서 낮게 나온 수준이 다음 동화 모드 세션을 쉽게 만든다.**

| 안 | 뜻 |
| --- | --- |
| 공유 (기본) | 구현대본 §3 그대로. 코드 변경 0 |
| 모드별로 따로 | 정확하지만 수준 상태를 두 벌 들고 가야 한다 |

→ 9/18 아이 피드백에서 일기 질문에 실제로 답이 얼마나 나오는지 보고 정한다.

### 7-4. 칸이 하나도 안 찼을 때

§5는 **모인 칸이 하나라도 있으면** 책을 만든다. 완전 무응답이면 씨앗이 0개다.
이때만 *"오늘은 여기까지 하고 잘까?"* 로 끝내거나 동화 모드로 넘긴다. 어느 쪽인지는 아직 안 정했다.

### 7-5. 15분 종료 조건을 그대로 쓸까

`guidelines/2` §1-1의 종료 조건 셋 중 하나가 **15분 경과**다. 동화 모드 기준이다.
일기 모드는 취침 루틴으로 매일 쓰는 기능이라 15분이 길다. 줄이면 종료 조건이 모드마다 갈리고,
그대로 두면 재우려는 부모와 부딪힌다. **아이 피드백에서 실제 세션 길이를 보고 정한다.**

### 7-6. 사다리가 다 떨어진 뒤 그림 3장으로 갈까

구현대본 §5의 무응답 흐름은 **쉬운 질문 → 그림 3장(최대 3회 교체) → 마스코트가 골라줌**이다.
일기 모드의 사다리(§4)는 그 앞단을 늘린 것인데, 그 뒤에 그림 3장을 붙일지가 정해지지 않았다.

| 안 | 뜻 |
| --- | --- |
| 사다리 → 그림 3장 → `mascot_pick` | 동화 모드와 흐름이 같다. 단 일기에서 그림 3장은 **아이 하루를 앱이 추측해 보여 주는 것**이 된다 |
| 사다리 → 바로 `mascot_pick` | 추측하지 않는다. 대신 한 칸에서 무응답이 더 빨리 끝난다 |

→ 후자로 기운다(§3-2와 같은 이유). 다만 `card` 출처가 일기 모드에서 거의 안 나오게 되므로,
**「말한 방식」 원그래프가 동화 모드와 달라진다**는 점을 리포트 담당과 맞춰야 한다.

## 8. 이벤트 — 리포트 6축에 그대로 들어간다

`guidelines/2` §1-3의 이벤트 11종을 그대로 쓴다. 형태는 `{ name, at, by, slot, payload }`.
**새 이벤트는 없고, 더하는 필드가 하나다.**

| 이벤트 | 일기 모드에서 |
| --- | --- |
| `story_start` | `mode: diary` 를 더한다 ← **새로 더하는 필드 하나** |
| `utterance` | 그대로. `by: child` 의 원문이 부모 리포트 인용이 된다 |
| `slot_filled` | 그대로. **`by` 에 `mascot` 이 나온다** — §5에서 LLM이 메운 자리다. 리포트에서 빠지는 건 `by` 가 처리한다(§5-1) |
| `signal` | 그대로. S1·S2 판정이 같다. `by: child` 만 센다 |
| `emotion_mention` | 그대로 |
| `make` | 아이가 [직접 그리기]로 친구를 그렸을 때만 |
| 나머지 | 그대로 |

⚠️ **`by` 를 빼먹으면 이 설계가 무너진다.** §5가 "빈 자리를 이야기로 메워도 된다"고 말할 수 있는 근거가
`by: mascot` 하나다. 이걸 안 남기면 메운 문장이 아이가 한 말과 섞여 **부모 리포트가 거짓말을 시작한다.**

⚠️ **[직접 그리기] 버튼은 일기 모드에도 남긴다.** 구현대본 §0-1의 *"아이가 원할 때 늘 보인다"* 원칙이고,
이게 없으면 일기 모드만 하는 날에 **부모 리포트의 '만들기' 축이 빈칸으로 나온다.**
