## 0. 이 발표가 해야 하는 것

운영이 요구한 세 가지 위에, **우리가 진짜 보여주고 싶은 것 하나**를 얹는다.

| 요구 | 우리가 넣는 것 |
|---|---|
| 최종 서비스 목표 | 1부 (3장) |
| 일정 및 협업 과정 | 2부 (3장) |
| 진행 상황 · 시연 영상 | 3부 (7장) |
| — | **사용자가 한 번 말할 때 기술이 어떤 순서로 도는가** ← 3부의 뼈대 |

**총 13~15장 · 10분 기준.** 세 가지를 다 채우기보다 **3부가 살아야 한다.**

### 이 발표의 한 문장

> **"아이가 말하면 그림책이 됩니다. 그 한 마디가 지나가는 길을 전부 재봤습니다."**

### ⚠️ 넣지 않는 것

- **평가 중인 외부 판정 모델 후보** — 아직 우리끼리만 본다. 슬라이드·발표·PDF 어디에도 쓰지 않는다
- 아직 못 정한 것을 정한 것처럼 쓰지 않는다. **「아직」이라고 적는 게 더 세다**
- 점수·등급·또래 비교 표현 (제품 원칙이자 발표 원칙)

## 1부 · 무엇을 만드는가 (3장)

### 1. 표지

- **말로 짓는 인형극** / 만 3~7세 · 종이 인형극 그림책
- 팀 4명 이름 · 2026.09 ~ 10
- 배경: 오늘 만든 배경 그림 한 장

### 2. 이 앱이 무엇인가 — **대화 한 토막으로 보여준다**

**메시지**: 그림책 앱은 읽어 준다. **이 앱은 아이가 짓게 한다.**

화면 가운데에 실제 대화를 크게:

```
🗣  마스코트   "오늘은 어디로 가 볼까?"
🧒  아이      "공룡나라 갈래! 근데 뿌뿌도 데려갈 거야."
                 └ 묻지 않은 걸 스스로 덧붙였다  ← 이게 기록된다
🗣  마스코트   "공룡 나라구나! 거기서 누굴 만났어?"
```

밑에 한 줄: **끝나면 부모에게 「오늘 아이가 한 말 그대로」가 남습니다.**

### 3. 다른 점은 둘뿐이다

**메시지**: 기능을 늘린 게 아니라 **두 가지를 다르게 했다.**

| | |
|---|---|
| **① 아이가 만든 건 AI가 다시 그리지 않는다** | 아이 그림은 그대로 책에. **아이가 녹음한 소리는 폰을 떠나지 않는다** |
| **② 질문 순서가 고정이 아니다** | *"혼자 갔어"* 하면 「누구랑?」이 사라지고, *"친구랑 싸웠어"* 하면 화해 방법이 새로 필요해진다. **무엇을 물을지는 방금 한 말이 정한다** |

아래에 세 모드를 한 줄씩: **동화 / 일기(오늘 하루를 재료로) / 부모 협업(부모가 질문을 미리 넣어 둔다)**

## 2부 · 어떻게 일하고 있는가 (3장)

### 4. 6주 일정과 지금 위치

**메시지**: 지금은 **4주차, 프로토타입이 막 돈 시점**이다.

가로 타임라인 하나. 지난 것은 채우고 남은 것은 비워 둔다.

| 시점 | 무엇 |
|---|---|
| 9월 초 | 기획 확정 · 문서 체계 · 그림체 후보 |
| 9/19~21 | **측정 주간** — 음성·판정·그림을 전부 실측 |
| **9/22** | **프로토타입 — 세 모드가 각각 한 바퀴** ← 지금 |
| 9/23 | **중간 발표** |
| 10/5 | 추석 |
| 10월 중 | 최종 발표 |

### 5. 협업 방식

**메시지**: 네 명이 **같은 파일을 안 건드리게** 만들어 두고 일한다.

- **문서가 정본이다.** `guidelines/` 0~9번 — 이름·슬롯·프롬프트·금칙어·역할. **같은 것을 두 곳에 적지 않는다**
- **`feature/<이름>` 브랜치 → PR → 조장 병합.** `main`에 직접 푸시하지 않는다
- **역할은 모드별로 하나씩** + 공통 파이프라인 한 명 (`guidelines/9`)
- **멘토링 9회차** 진행

### 6. 우리 팀 규칙 하나 — **측정값만 결정을 바꾼다**

**메시지**: 이 발표의 숫자는 전부 **우리가 직접 잰 것**이다.

- 가격만으로 안 바꾸고, 추천만으로 안 바꾸고, **신뢰구간이 겹치면 동률로 읽는다**
- **평가 하네스를 먼저 만들었다** — 정답 라벨 100문항, **팀원이 나눠 라벨링하고 교차 검증**
- **부끄러운 베이스라인을 먼저 남긴다** — *"무엇이 느렸고 어떻게 고쳤다"*가 성립하려면 고치기 전 숫자가 있어야 한다

> 실제 사례 한 줄: **문서에 「그래픽카드 한 장에 모델 둘은 못 올린다」고 적어 뒀는데, 재보니 셋이 들어갔다.**

## 3부 · 지금 어디까지 왔나 (7장)

### 7. 시연 영상 — 프로토타입 한 바퀴

**메시지**: 말 한 마디가 그림책이 되는 전 과정.

- 30~60초. **동화 모드 한 바퀴**를 끊김 없이
- 자막으로 단계 이름만: *말한다 → 알아듣는다 → 판단한다 → 되묻는다 → 그린다 → 책이 된다*
- 여유가 있으면 일기·부모 협업 모드는 **첫 화면만 3초씩**
- ⚠️ **지금은 대본으로 도는 시연**이다. 다음 장에서 각 단계에 무엇이 들어가는지 설명한다고 넘긴다

### 8. 아이가 한 번 말하면 — 이 순서로 돕니다

**메시지**: 이 그림이 3부의 지도다. 이후 장들은 이 위를 왼쪽부터 짚는다.

가로 흐름도 한 장. 각 칸 아래에 **어디서 도는지**를 색으로 구분(폰 / 우리 서버 / 밖).

```
🧒 말한다
   → ① 말이 끝난 걸 안다        [폰]
   → ② 글자로 바꾼다            [우리 서버]
   → ③ 이름 가리기 · 금칙어      [폰]
   → ④ 무슨 말인지 판단          [밖]
   → ⑤ 마스코트가 대답한다        [폰 + 밖]
   → ⑥ 그림을 만든다            [우리 서버]
📖 책이 된다 → 👨‍👩‍👧 부모에게 남는다
```

한 줄: **밖으로 나가는 것은 글자뿐입니다. 아이 목소리 원본과 그림은 나가지 않습니다.**

### 9. ①말이 끝난 걸 안다 · ②글자로 바꾼다

| | 쓰는 것 | 잰 값 | 상태 |
|---|---|---|---|
| ① 말 끝 감지 | **Silero VAD** (폰) | **p50 550ms** — 폰 내장 방식보다 **8.4배 빠름** | **정함** |
| ② 받아쓰기 | **faster-whisper large-v3-turbo** (우리 서버) | 폰만으로 해봤더니 **프리셋 매칭 65%** — 합격선 95% 미달 | **아직** |

**왜 아직인가**: **아이 목소리 30발화가 있어야 모델을 고른다.** 어른 목소리로 재면 순위가 안 나온다 — 같은 모델이 **성인 7.8% · 아동 120.8%**로 갈린다.

### 10. ④무슨 말인지 판단한다 — **여기가 이 앱의 심장**

**메시지**: 슬롯 12칸 중 **어디가 찼고 다음에 뭘 물을지**를 매 턴 정한다.

- **정했다** — JSON 성공률 **100%** · p95 **2.4초** · **권당 21.6원**
- 같은 한국어 프롬프트인데 모델에 따라 **토큰이 6,129 vs 3,987**로 갈려 값이 **7배** 차이 났다 → 그래서 값도 같이 잰다
- **수준은 규칙이 계산한다. 모델은 신호만 표시한다** — *"이 아이 수준이 어때?"*라고 묻지 않는다

작게: 이야기 틀 **7가지 중 5가지**를 데모에 넣었고, 아이 수준에 따라 틀과 쪽수(6~8쪽)가 달라진다.

### 11. ⑤마스코트가 대답한다 — 기다림을 소리로 덮는다

**메시지**: **폰 목소리는 탈락했다.** 귀로 들어보니 셋 다 아니오였다(다섯 살이 들을 만한가 · 사람 같은가 · 마스코트 같은가).

핵심 그림: **시간 막대 하나**

```
아이 말 끝 ──▶ [리액션 재생 0초 시작] ───────────────▶ 마스코트 본 대사
                 "잠깐만, 생각 좀 하고!" + "음~"  =  4.11초
                 └ 이 뒤에 받아쓰기 · 판단 · 목소리가 전부 숨는다 (3.72초)
```

- **리액션은 미리 구워 앱에 넣는다** — 6개에 **184KB**, 재생 지연 **0초**
- **본 대사는 매번 만든다** — 아이가 한 말이 문장 안에 들어가서 미리 못 굽는다. 첫 소리까지 **1.32초**
- ⚠️ **한 마디로는 모자란다**(가장 긴 게 2.86초) → **두 마디를 잇는다**

### 12. ⑥그림을 만든다 — 19초를 3.7초로

**메시지**: 아이를 기다리게 하지 않으려고 **대화 뒤에서** 만든다.

| 만드는 것 | 전 | 지금 |
|---|---:|---:|
| 배경 1장 | 19.07초 | **3.74초** |
| 등장인물 후보 3장 | 35.8초 | **8.0초** |
| 입 벌린 그림 1장 | — | **2.32초** |
| 만지는 것(바위·나무·별) | — | **0초** (미리 만들어 얹는다) |

- **손잡이는 세기가 아니라 스텝 수였다.** 4스텝까지 내리면 **종이 결이 물감처럼 뭉개져서** 8스텝으로 정했다
- **말하는 입**: 캐릭터를 쪼개려는 시도는 전부 실패했고, **쪼개지 않고 입만 다시 그려** 두 장을 번갈아 보여주는 방식으로 풀었다 (오늘 만든 그림 2장 나란히)
- ⚠️ **어느 그림 모델을 쓸지는 아직이다** — 지금까지 하나만 재봤다

### 13. 그래픽카드가 한 장뿐입니다 — 자리는 되는데 **같이 돌리면 안 된다**

**메시지**: 이 발표에서 **가장 최근에 뒤집힌 결론**이다.

- **셋이 다 올라간다** — 그림 + 받아쓰기 + 음성 처리로 **10,437 / 12,287 MiB**
- **그런데 동시에 돌리면 받아쓰기가 0.71초 → 2.54초(3.6배)** 느려진다. 그림을 쥔 쪽이 이기고, **작은 계산을 많이 하는 받아쓰기가 줄을 선다**
- → **시간을 나눠 쓴다.** **아이가 말하는 동안에는 그림을 안 만들고**, 마스코트가 말하는 동안(6.4~7.0초) 만든다. 그림 한 장이 2.4초라 **한 턴에 두 장**이 들어간다

한 줄: **그래서 아이 목소리가 회사 밖으로 나갈 이유가 없어졌습니다.**

### 14. 한눈에 — 일곱 가지 중 셋을 정했습니다

**메시지**: 정직한 현황표. **「아직」이 네 개인 게 이 발표의 신뢰도다.**

| | 무엇 | 어디서 | 상태 |
|---|---|---|---|
| ① | 말 끝 감지 | 폰 | **정함** |
| ② | 받아쓰기 | 우리 서버 | 아직 — 아이 목소리 필요 |
| ③ | 말뜻 판단 | 밖 | **정함** · 21.6원/권 |
| ④ | 그림 만드는 방식 | 우리 서버 | **정함** · 배경 3.7초 |
| ⑤ | 그림 모델 | 우리 서버 | 아직 — 하나만 재봄 |
| ⑥ | 마스코트 목소리 | 폰 + 밖 | 아직 — 귀로 안 들어봄 |
| ⑦ | 부모 리포트 | 폰 | 진행 중 |

### 15. 남은 2주에 할 것

**메시지**: 지금 막고 있는 것과 다음 순서.

- **아이 목소리 30발화** — 이것 하나가 받아쓰기 모델 선정 전체를 막고 있다 (AI-Hub 신청 중)
