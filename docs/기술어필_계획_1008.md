## 이 문서의 범위

- **근거로 쓴 것**
  - `origin/main` 10-08 코드와 문서: `docs/받아쓰기_미세조정.md` · `docs/멀티에이전트_검토.md` · `docs/Jev_붙일_자리_검토.md` · `eval/results.md` · `guidelines/2` §1-5 · `StoryBank.kt`의 수준 규칙 · 이슈 #220 · #172
  - 10-08 웹 조사: 각 절 끝 「출처」에 적었다
- **근거로 쓰지 않은 것**: 학습 PC의 실행 로그 · 실제 아이 세션 데이터
- **⚠️ 조사 수치**: 웹 조사 수치는 논문 초록 · 모델 카드 · 기사에서 옮겼다. 원문 대조는 하지 않았으므로 **슬라이드에 넣기 전에 원문을 확인한다**
- **이 문서가 정하지 않는 것**: 각 갈래의 성공 기준 숫자. 담당자가 **데이터를 보기 전에** 자기 이슈에 적는다. 아래 「기준 후보」는 제안이다

공통 규칙

- **기준은 측정 전에 고정하고, 결과를 본 뒤 바꾸지 않는다.** 바꿔야 하면 왜 바꾸는지를 문서에 남긴다(① 기준3이 그 예다)
- **신뢰구간이 겹치면 동률이다.** 동률이면 값과 지연으로 정한다
- **평가 문항으로 학습하지 않는다.** 100문항(`eval/fixtures_judge.jsonl`)은 평가 전용이다
- 결과는 `eval/results.md`에 절 하나로 남기고, 원자료는 `eval/raw/`(깃 제외)에 둔다. 기준선으로 계속 쓸 원자료는 `eval/baselines/`에 둔다
- 발표 슬라이드에는 「문제 → 시도 → 결과(숫자 하나) → 한계」만 쓴다. 숫자가 없으면 「설계 + 다음 단계」로 쓰고, 「구현했다」고 쓰지 않는다
- 레포는 공개 상태다. 이슈와 문서에 키 · 개인정보 · 아이 원문 데이터를 올리지 않는다

## ① 아동 음성 받아쓰기 미세조정 — 종훈

**엔드픽처.** 아이 말이 그대로 적혀 「다시 한번 말해 줄래?」 없이 한 번에 다음 질문으로 넘어간다. 부모 리포트의 「아이가 한 말」 인용도 실제와 같아진다.

**지금 있는 것.** `docs/받아쓰기_미세조정.md` · `eval/whisper_ft/`

| | 원래 `large-v3` 대비 | 판정 |
|---|---|---|
| 1차 LoRA | 3~5세 어절 보존 +23.1%p [+19.4, +26.8] · 3세 CER 43.3% → 13.8% · 3세 헛문장 22.8% → 0% · 어른 세트 전체 40 → 44/57이지만 원래 맞히던 「아니」 2개 잃음 | 기준3 탈락 |
| 2차 (VAD 트림 · 잡음) | +23.9%p [+20.1, +27.7] · 어른 세트 3개 잃음 | 기준3 탈락 |

**조사로 본 위치**
- 공개 논문의 Whisper 아동 미세조정 개선 폭은 대체로 **상대 12~31%**다(영어 · 초등생 위주). 우리 3세 CER은 **상대 약 68% 감소**다. 언어 · 나이 · 지표가 달라 직접 비교는 안 된다
- **한국어 3~6세 받아쓰기 CER을 낸 2025~26 논문은 못 찾았다.** 공개 수치가 없는 영역이라는 점이 어필 포인트다
- 「아니」 손상과 닮은 사례가 있다. 스위스 독일어 LoRA 연구(2026-06)에서 미세조정 뒤 무음 입력의 「말 없음」 판단이 무너졌고, **LoRA 반영 강도(alpha)만 낮춰** 환각이 사라지고 전체 성능도 올랐다
- Interspeech 2025 비교 연구: 모델 병합 · alpha 낮추기 · **이전(어른) 데이터 섞어 재학습** 중 섞어 재학습이 가장 효과적이었다

**계획 (싼 것부터)**

1. **잃은 클립이 무엇으로 받아 적혔는지 본다.** 재학습 없이 기존 결과에서 꺼낸다. 비슷한 소리면 어른 목소리 문제, 빈칸이나 엉뚱한 문장이면 짧은 말 문제다
2. **alpha를 낮춰 다시 평가한다.** 재학습이 필요 없어 몇 시간이면 된다. 다섯 기준을 그대로 적용한다
3. **안 되면 어른 데이터 · 짧은 답 클립을 섞어 재학습한다.** 아이의 「응 · 아니 · 몰라」가 평가 세트에 없어서 지금은 측정되지 않았다. 짧은 답 평가 세트를 더한다
4. **오류 분석표.** 연령별 · 발화 길이별 · 헛문장과 무음 처리. 「왜 좋아졌는지」를 설명하는 표라 면접에서 가장 설득력이 있다
5. 기준3을 고쳐야 한다면 근거를 남긴다: 앱에서 어른 말이 받아쓰기로 들어오는 곳은 동화 모드의 「함께할 사람」 어른 질문뿐이다(협업 모드는 부모가 만든 질문으로 아이 혼자 한다)

**선택.** 2026년에 나온 공개 모델(Qwen3-ASR-1.7B · Cohere Transcribe, 둘 다 Apache-2.0 · 한국어 포함)과 같은 평가 세트로 비교한다. 한국어 아동 성능 수치는 아직 아무 데도 없다. 상용 API 비교는 아이 음성이 외부로 나가므로 하지 않는다(차별점 1).

**발표 숫자.** 3~5세 어절 보존 +23%p, 3세 CER 43.3% → 13.8%, 헛문장 22.8% → 0%. 서버 반영 여부는 2~3번 결과로 정해진다.

## ② 에이전트 — 진웅

**엔드픽처.** 오또가 앞서 아이가 한 말을 기억하고 이어서 묻는다.
- 전: 「누구랑 갔어?」 → 「아빠」 → (몇 턴 뒤) 「누구랑 갔어?」
- 후: 「아까 아빠랑 갔다고 했지? 아빠는 바다에서 뭐 했어?」

그리고 **어디에 LLM 에이전트를 쓰고 어디에 규칙을 쓰는지를 측정으로 정한다.** 아이가 기다리는 실시간 대화와, 시간이 넉넉한 책 만들기가 나뉘어 있어 이 판단을 보여 주기 좋은 구조다.

**조사로 본 위치**
- MCP · A2A 같은 연결 표준과 트레이싱(관측)은 이미 기본기다. LangChain 설문(2026-06 공개)에서 운영 중인 팀의 89%가 관측 도구를 쓴다
- 반면 **오프라인 평가는 52%, 운영 중 평가는 37%** 뿐이다. 운영을 막는 이유 1위는 품질, 2위는 지연이다
- Gartner는 기존 챗봇에 이름만 바꿔 다는 「agent washing」을 경고했다. 정해진 순서를 그대로 「에이전트」라고 부르면 이렇게 읽힌다
- Anthropic 원칙: 「가장 단순한 해법부터, 필요할 때만 복잡하게」. **규칙 기준선과 비교하지 않은 LLM 오케스트레이터는 감점**이다
- LLM이 근거 없이 자기 답만 다시 보는 자기수정은 오히려 성능을 떨어뜨릴 수 있다(ICLR 2024). **외부 도구 결과가 근거일 때만** 도움이 된다
- 국내 공고(네이버클라우드 · NHN · 현대오토에버)에도 오케스트레이션 · MCP · 「LLM 평가 파이프라인」이 명시돼 있다

**지금 있는 것**
- 역할별 모델: 듣기(받아쓰기) · 판정 · 빠른 판단(Jev) · 작가 · 검열 · 목소리. **누가 다음에 일할지는 규칙(`Director`)이 정한다**
- `docs/멀티에이전트_검토.md`(09-28): LLM 오케스트레이터 측정 기준 넷을 미리 고정했다. **§6 결과는 비어 있다**

  | 기준 | 넘는 선 |
  |---|---|
  | 한 턴 서버 처리 p95 | 규칙 대비 +0.5초 이내 |
  | 판정 한 권 비용 | 규칙의 1.5배 이내 |
  | 판정 에이전트를 부른 비율 | 99% 이상 |
  | 작가를 부를 때(`story_ready`) 맞히기 | F1 0.9 이상 |

**계획**

1. **ⓐ 실시간 — 경로 평가 + pass^k로 규칙 vs LLM 오케스트레이터 (1.5~2일).** 정답 대화 세트를 두고 둘을 각각 k번 돌린다. pass^k는 같은 과제를 k번 모두 성공하는 비율이다(τ-bench 방식). 위 기준 넷에 pass^k와 「이미 답한 걸 다시 묻는 횟수」를 더한다. **결과가 「규칙 유지」여도 성과다** — 「LLM 에이전트를 써 보고, 아이가 기다리는 자리에서는 X초 늦어 규칙을 택했다」
2. **ⓑ 책 만들기 — 도구 근거가 있는 작가-검수 루프 (1.5~2.5일).** 작가가 쓰면 검수 에이전트가 도구로 확인하고, 걸리면 이유를 붙여 되돌린다. 고쳐 쓰기는 최대 1바퀴, 20초(p95) 안
   - 검수 도구: 금칙어 검사기(`eval/forbidden.py`) · 아이 원문 대조(슬롯 값이 책에 남았나) · 쪽 수 확인
   - 검수 판정을 사람 라벨 약 50건과 비교해 일치율을 보고한다(LLM-as-judge 보정)
   - 첫 적용은 그림일기 책이다. 일기 책 문장 규칙(#192)과 바로 이어진다
3. **ⓒ (치영과 함께) 확신도 기반 단계 처리.** 빠른 판정이 먼저 답하고 확신이 낮을 때만 루나로 넘긴다. 확신도 임계값별 정확도 · 지연 곡선을 낸다

**기준 후보**: ⓐ 09-28 기준 넷 그대로 + pass^k · ⓑ 지어낸 사건 0건 · 아이 원문 누락 0건 · 20초 안 p95 · 검수-사람 일치율. 숫자는 진웅이 데이터를 보기 전에 #323에 적는다.

**피할 것.** 정해진 순서를 「에이전트」라고 부르기 · 한 번 돌린 정확도만 내기 · 근거 없는 자기 검토 루프 · 규칙 기준선 없는 비교.

## ③ 아이 발화 발달 기반 질문 유도 — 민우

**엔드픽처.** 아이 개인의 발화 기록으로 지금 어떤 말을 해 보면 도움이 될지 파악하고, 그 말을 끌어내는 질문을 한다.
- 짧게만 답하던 아이 → 고르는 질문으로 대답을 이끌고, 다음엔 「그래서 어떻게 됐어?」로 잇게 한다
- 「~해서」를 쓰기 시작한 아이 → 「왜 그랬을까?」를 더 일찍 받는다
- 부모 리포트는 지금처럼 횟수와 원문만: 「지난번보다 까닭을 2번 더 말했어요 — "비가 와서 못 갔어"」

**조사로 본 위치**
- **같은 사례를 못 찾았다.** 측정만 하는 쪽(케어인텔리전스, 2026-01 · 박연정 2024)과 질문만 조절하는 쪽(StoryPal, ACM IDC 2025)은 따로 있다. 한국어 형태소 지표를 대화 중에 계산해 질문을 바꾸는 3~7세 앱이나 논문은 없었다
- **필요성 근거:** AI 대화 상대와 읽은 아이는 이야기 이해는 사람과 같았지만, 사람과 읽은 아이보다 답이 짧고 어휘가 적었다(Ying Xu 2021, 3~6세 117명). 「AI는 아이 말을 늘리는 데 약하다」는 결과다
- **한국 아동 규준:** MLU-m 3;0–3;5 5.02 → 5;6–5;11 9.09(Lee & Lim 2025, 240명). 원인 연결어미는 2세부터 나오고, 2·3세와 4세 이후 사이에 유의한 차이가 있다(Lee 외 2023, 250명)
- **⚠️ 신뢰할 만한 MLU에는 아이 발화 50~100개가 필요하다.** 한 세션으로는 모자랄 가능성이 크다. 그래서 **세션을 넘어 지표를 쌓아야 한다** — 아래 「규칙 개정」의 기술적 근거다
- 같은 나이 안에서도 표준편차가 2~3으로 크다. 규준으로 한 아이를 판정하지 않는다

**지금 있는 것 — 처음부터 만드는 게 아니다.** 수준 3단계와 올림 · 내림 규칙이 이미 돌고 있다(`guidelines/2` §1-5 · `StoryBank.kt`).

| 단계 | 질문 결 | 지금 쓰는 신호 |
|---|---|---|
| 고르며 짓기 (PICK) | 무엇 · 누구 · 어디 | — |
| 이어 짓기 (CHAIN) | 그래서 · 그다음 | S2(이야기 요소를 이었다) — LLM 표시 |
| 까닭 짓기 (REASON) | 왜 · 어떻게 | S1(까닭을 댔다) — LLM 표시 |

- 올림: 신호 2턴 연속이면 한 칸. 내림: 짧은 답(**2어절 이하**) · 카드 · 무응답 2턴 연속
- 세션 추정(`ruleEstimate`)에 이미 **평균 어절 수**가 있다. 판단에는 쓰지 않고 로그에만 남는다
- 같은 앱 실행 안에서는 다음 이야기를 지난 이야기의 마지막 단계에서 시작한다(`nextLevel`). 디스크에 저장하지 않아 앱을 껐다 켜면 사라진다

**이 기술이 더하는 것.** 「짧은 답」을 어절 수 하나로, 「까닭」을 LLM 표시 하나로 보던 것을 **아동 언어 연구의 지표를 규칙으로 계산한 값**으로 바꾸고, 세션을 넘어 쌓는다. 질문 종류를 고르는 일은 규칙이 하고, LLM은 문장만 쓴다(규칙 4).

| 지표 | 무엇 | 계산 |
|---|---|---|
| MLU-m | 평균 발화 길이(형태소) | 형태소 분석기(Kiwi — Android용 있음)로 아이 발화(`by == child`)의 형태소 수 평균 |
| NDW | 서로 다른 낱말 수 | 아이 발화의 서로 다른 내용어 수 |
| 까닭 말 | 「왜냐하면 · ~해서 · ~니까」 | 원인 연결어미 · 접속 부사 목록 대조 |

**계획**

1. **지표 계산을 순수 함수로 만든다.** 입력은 아이 발화 목록, 출력은 세 값이다. `mascot` · `card` 발화는 뺀다(규칙 5). 단위 테스트를 붙인다
2. **타당성 확인 — 민우가 데이터 받기부터 계산까지 맡는다**(종훈 10-08)
   - **AI-Hub 108(자유대화 음성 · 소아 유아)** 의 3~6세 전사문으로 나이별 MLU-m를 계산해 Lee & Lim(2025) 곡선 옆에 그린다. 나이와 같은 방향으로 올라야 쓸 수 있다
   - ⚠️ 540(한국어 아동 음성)은 약 75%가 읽기 발화라 쓰지 않는다. 아이가 스스로 만든 말이 아니다
   - 전사문만 쓰고 음성은 쓰지 않는다. 데이터는 본인인증 후 바로 신청해 받고, 레포에 올리지 않는다
   - 분석기와 사람 기준이 형태소 경계를 다르게 셀 수 있다. 50발화 정도를 손으로 세어 일치율을 함께 낸다
3. **질문 규칙표를 문헌 근거와 나란히 만든다.** 예: 짧은 답이 이어지면 고르는 질문(CROWD의 완성 질문) · 원인 어미가 나오면 「왜」 질문(4세 전후 급증)
4. **수준 규칙에 넣는다.** 단계 이름 · 질문 결 · 템플릿은 그대로 둔다
5. **측정한다.** 같은 대본 세션(짧게 답하는 아이 · 길게 답하는 아이 · 까닭을 대는 아이)으로 전후 비교: 까닭 질문에 도달하는 턴 수 · 짧게 답하는 아이의 주고받기 횟수

**주의.** 고르는 질문에는 누구나 짧게 답한다. **열린 질문에 한 답만으로 지표를 계산**하거나 질문 종류별로 나눠 본다. 안 그러면 「쉬운 질문 → 짧은 답 → 더 쉬운 질문」으로 갇힌다.

**규칙 개정 — 이슈 #343으로 먼저 알렸다 (규칙 아홉 · 데이터 모델 변경)**

| 지금 | 제안 |
|---|---|
| `guidelines/2` §1-5 「매 세션 다시 판단한다. 아이에게 단계를 저장하지 않는다」 | **아이 발화에서 계산한 원 지표만** 기기에 세션별로 보관한다. 단계 이름은 저장하지 않는다. 시작값으로만 쓰고 첫 두 턴 탐색 질문으로 언제든 덮어쓴다. 보관 기간과 지우기를 둔다 |

## ④ 판정 Jev → 라야 — 치영

**엔드픽처.** 같은 정확도와 빠르기로 판정을 우리 서버에서 한다. 판정 단계에서는 아이 말이 외부 업체로 나가지 않고(대사 · 책 문장은 여전히 루나), 업체 크레딧이 떨어져도 판정이 멈추지 않는다.

**라야가 무엇인가 (10-08 조사).** Convai Innovations가 2026-09-18에 Apache 2.0으로 공개한 판정 전용 모델이다. 스스로 「TypeSafe Jev의 오픈 웨이트 대안」이라고 소개한다. 글을 쓰지 않고, 질문 세 종류(choice · score · noul)에 한 번의 계산으로 확률이 붙은 답을 낸다.
- 체크포인트: 영어 ModernBERT-large(421M) · **다국어 mmBERT-base(322M)** · typed-decisions(421M)
- 제작사 발표: T4 GPU p50 약 33ms. 우리 Jev p95 0.73초는 네트워크 왕복을 포함한 값이라 바로 비교할 수 없다
- ⚠️ **미세조정 전에는 다수 클래스만 찍는 기준선보다 낮다**(0.362 대 0.461). 제작사도 「zero-shot이 아니라 특화용 베이스」라고 한다
- ⚠️ 공개 직후 신뢰도 보정 오차(ECE) 0.466 → 질문 유형별 temperature 보정 후 0.081
- ⚠️ **한국어 수치가 없다.** 선택지 20개를 넘으면 약해진다(우리 슬롯은 12개). noul 답이 라벨 쪽으로 쏠리는 문제가 보고돼 있다

**지금 있는 것**
- Jev 기준선(09-22 · 09-26): 100문항 · 실패 0건 · **p95 0.73초** · 9필드 정확도 **88.6%**(루나 88.0%와 동률) · 100문항 29.2원
- 원자료: **`eval/baselines/jev-latest_0922.jsonl`**(#330) — 09-22 측정 그대로(100줄 · 문항 id · 9필드 답 · 확신도). `eval/bench_jev.py`를 다시 돌리면 `eval/raw/jev-latest.jsonl`(깃 제외)을 덮어쓰므로 기준선은 이 사본을 쓴다
- Jev는 9필드만 답하고 글(`value_1` · `reason` 등)은 못 쓴다

**계획**

1. **100문항은 평가 전용으로 봉인한다.** 합성 데이터를 만드는 프롬프트에 예시로도 넣지 않는다
2. **학습 데이터 — 루나 합성 라벨(증류).** 루나가 아이 발화를 만들고 9필드 라벨을 붙인다. 라벨 100개 정도부터 작은 미세조정 모델이 큰 LLM과 대등해진다는 연구가 있다(EACL 2026). 보정용 데이터는 합성셋에서 따로 떼어 둔다
3. **라야 다국어판(322M) 미세조정 + 질문 유형별 temperature 보정.** 미세조정 노트북은 Kaggle 2×T4에서 돈다
4. **대조군 — 한국어 인코더**(KLUE-RoBERTa 등)에 필드별 분류 헤드를 붙여 같은 데이터로 학습한다. 라야의 한국어 약점을 드러낼 기준선이다
5. **같은 100문항 · 같은 9필드로 비교한다.** 필드별 정확도와 신뢰구간 · p95(같은 서버 조건) · 문항당 값 · 보정 곡선. 총점만 나란히 두지 않는다(`eval/results.md` 09-22 절의 함정)
6. **(진웅과 함께) 확신도 기반 단계 처리.** 확신이 낮은 것만 루나로 넘긴다. 「몇 %를 루나로 넘겼고 그때 정확도가 얼마인가」 곡선을 낸다

**기준 후보**: 9필드 정확도가 Jev와 동률 이상 · p95 0.73초 이하 · 아이 말이 외부 업체로 나가지 않음. 숫자는 치영이 #324에 적는다.

## 공통 — LLMOps — 종훈 (#345)

**무엇.** DevOps가 「코드가 안 깨지게」라면, LLMOps는 「AI의 답이 조용히 나빠지거나 비싸지지 않게」다. 프롬프트 · 모델 · 설정이 바뀔 때 평가로 확인하고, 운영 중 품질 · 지연 · 원가를 감시한다.

| 요소 | 지금 있는 것 | 할 것 |
|---|---|---|
| 평가 | 100문항 판정 벤치 · 모드별 벤치 · 신뢰구간 규칙 | 프롬프트 파일을 바꾼 PR에서 **작은 회귀 평가가 자동으로** 돈다 |
| 추적 | 엔드포인트 모니터 · 세션 호출 수와 원가 측정(#172) | 턴마다 단계별(판정 → 대사 → TTS) 지연 · 원가 · 프롬프트 판 · 가드 걸림을 남긴다 |
| 감시 | — | 업체 잔액 · 원가 경보. 10-07 OpenAI 크레딧 소진(#298)이 없던 감시의 사례다 |

- **⚠️ SaaS 추적 도구(LangSmith 등)는 아이 말이 그 업체로 나간다.** 자체 로그나 자체 호스팅 도구만 쓴다
- 발표에서는 「네 기술 모두 같은 평가 틀 위에서 전후를 쟀다」는 한 장이 된다

**왜 종훈인가 (10-08 결정).** CI · 서버 · 배포 · 모니터가 이미 종훈 담당이고(§9-0), ①은 남은 일이 가장 적다. 범위는 둘로 좁힌다: **프롬프트 PR 회귀 평가 자동 실행 · 턴별 지연 · 원가 추적.** ② 진웅의 경로 평가 도구는 이 틀 위에 얹는다(평가 실행 · 결과 기록 형식을 같이 쓴다).
