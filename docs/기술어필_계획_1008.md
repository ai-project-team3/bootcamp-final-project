## 이 문서의 범위

- **근거로 쓴 것**: `origin/main` 10-08 코드와 문서 — `docs/받아쓰기_미세조정.md` · `docs/멀티에이전트_검토.md` · `docs/Jev_붙일_자리_검토.md` · `eval/results.md` · `guidelines/2` §1-5 · `StoryBank.kt`의 수준 규칙 · 이슈 #220 · #172
- **근거로 쓰지 않은 것**: 학습 PC의 실행 로그 · 실제 아이 세션 데이터 · 라야 모델 자체(레포에 기록이 없다)
- **이 문서가 정하지 않는 것**: 각 갈래의 성공 기준 숫자. 담당자가 **데이터를 보기 전에** 자기 이슈에 적는다. 아래 「기준 후보」는 제안이다

공통 규칙

- **기준은 측정 전에 고정하고, 결과를 본 뒤 바꾸지 않는다.** 바꿔야 하면 왜 바꾸는지를 문서에 남긴다(① 기준3이 그 예다)
- **신뢰구간이 겹치면 동률이다.** 동률이면 값과 지연으로 정한다
- **평가 문항으로 학습하지 않는다.** 100문항(`eval/fixtures_judge.jsonl`)은 평가 전용이다
- 결과는 `eval/results.md`에 절 하나로 남기고, 원자료는 `eval/raw/`(깃 제외)에 둔다
- 발표 슬라이드에는 「문제 → 시도 → 결과(숫자 하나) → 한계」만 쓴다. 숫자가 없으면 「설계 + 다음 단계」로 쓰고, 「구현했다」고 쓰지 않는다

## ① 아동 음성 받아쓰기 미세조정 — 종훈

**문제.** 아이 말은 어른 말보다 훨씬 많이 틀리게 받아 적힌다. AI-Hub 3세 평가 클립에서 `large-v3` 원래 모델의 글자 오류율(CER)이 43.3%다.

**지금 있는 것.** `docs/받아쓰기_미세조정.md` · `eval/whisper_ft/`

| | 원래 `large-v3` 대비 | 판정 |
|---|---|---|
| 1차 LoRA | 3~5세 어절 보존 +23.1%p [+19.4, +26.8] · 3세 CER 43.3% → 13.8% · 어른 세트 전체 40 → 44/57이지만 원래 맞히던 「아니」 2개 잃음 | 기준3 탈락 |
| 2차 (VAD 트림 · 잡음) | +23.9%p [+20.1, +27.7] · 어른 세트 3개 잃음 | 기준3 탈락 |

**계획**

1. **잃은 클립이 무엇으로 받아 적혔는지 본다.** 재학습 없이 기존 결과에서 꺼낸다
   - 비슷한 소리로 잘못 들었으면 어른 목소리 문제다 → 2번으로
   - 빈칸이나 엉뚱한 문장이면 짧은 말 문제다 → 3번으로
2. **어른 목소리 문제면 기준3을 고친다.** 근거: 앱에서 어른 말이 받아쓰기로 들어오는 곳은 동화 모드의 「함께할 사람」 어른 질문뿐이다(협업 모드는 부모가 만든 질문으로 아이 혼자 한다). 고친 이유를 문서에 남긴 뒤 1차 모델을 서버에 올린다(`STT_MODEL` · 종훈 결정)
3. **짧은 말 문제면 아이에게도 손해다.** 아이의 「응」 · 「아니」 · 「몰라」가 평가 세트에 없어서 지금은 측정되지 않았다. 짧은 답 클립을 평가 세트에 더하고, 학습에도 섞어 다시 학습한다

**발표 숫자.** 3~5세 어절 보존 +23%p, 3세 CER 43.3% → 13.8%. 서버 반영 여부는 위 1번 결과로 정해진다.

## ② 대화형 에이전트 — 진웅

**문제.** 비어 있는 칸을 같은 질문을 되풀이해서 채우면 아이가 지루해하고, 주고받기가 대화가 아니라 설문이 된다.

**지금 있는 것**

- 구조는 이미 역할별 에이전트다: 듣기(받아쓰기) · 판정 · 빠른 판단(Jev) · 작가 · 검열 · 목소리. **누가 다음에 일할지는 규칙(`Director`)이 정한다**
- `docs/멀티에이전트_검토.md`(09-28): 이 순서 정하기를 LLM 오케스트레이터로 바꿀지 측정할 기준 넷을 미리 고정해 두었다. **§6 결과는 비어 있다**

  | 기준 | 넘는 선 |
  |---|---|
  | 한 턴 서버 처리 p95 | 규칙 대비 +0.5초 이내 |
  | 판정 한 권 비용 | 규칙의 1.5배 이내 |
  | 판정 에이전트를 부른 비율 | 99% 이상 |
  | 작가를 부를 때(`story_ready`) 맞히기 | F1 0.9 이상 |

- 이슈 #220: 그림일기에서 **그림 그리는 동안 오또와 나눈 말로 일기 칸을 채우는** 설계. 진웅 담당 모드 안의 일이다

**계획 — 둘 중 하나를 진웅이 고른다**

- **(가) 그리는 중 대화로 칸 채우기(#220) 추천.** 진웅 모드 안에서 끝나고, 아이가 체감하는 변화다
  - 측정: 같은 대본 세션으로 전/후 비교. 일기 한 편당 채운 칸 수 · 같은 질문 반복 횟수 · 주고받기 횟수
  - 함께 볼 것: 한 편 비용(#172 측정 약 137원)과 하루 호출 상한(#30). 그리는 중 대화를 `/turn`에 보내면 호출이 늘어난다
- **(나) 오케스트레이터 측정(09-28 문서 §4 그대로).** 이미 기준이 고정돼 있어 바로 돌릴 수 있다. 결과가 「규칙으로 되돌렸다」여도 발표 이야기가 된다(문서 끝 「발표에서 할 말」)

**기준 후보 ((가)를 고를 때)**: 반복 질문 0회 · 채운 칸 +1 이상 · 한 편 비용 1.5배 이내. 숫자는 진웅이 데이터를 보기 전에 #323에 적는다.

**확인 안 된 것.** 「대화형 에이전트」는 멘토 피드백에 팀원이 답한 안에서 나왔다. 그때 말한 것이 (가)인지 (나)인지는 진웅에게 확인한다.

## ③ 언어 발달 지표로 질문 조절 — 민우

**문제.** 같은 나이라도 아이마다 말하는 힘이 다르다. 너무 어려운 질문을 받으면 답을 못 해 실패 경험이 되고, 너무 쉬운 질문을 받으면 「응」으로 끝난다.

**지금 있는 것 — 처음부터 만드는 게 아니다.** 수준 3단계와 올림 · 내림 규칙이 이미 돌고 있다(`guidelines/2` §1-5 · `StoryBank.kt`).

| 단계 | 질문 결 | 지금 쓰는 신호 |
|---|---|---|
| 고르며 짓기 (PICK) | 무엇 · 누구 · 어디 | — |
| 이어 짓기 (CHAIN) | 그래서 · 그다음 | S2(이야기 요소를 이었다) — LLM 표시 |
| 까닭 짓기 (REASON) | 왜 · 어떻게 | S1(까닭을 댔다) — LLM 표시 |

- 올림: 신호 2턴 연속이면 한 칸. 내림: 짧은 답(**2어절 이하**) · 카드 · 무응답 2턴 연속
- 세션 추정(`ruleEstimate`)에 이미 **평균 어절 수**가 있다. 다만 판단에는 쓰지 않고 로그에만 남는다

**이 기술이 더하는 것.** 지금은 「짧은 답」을 어절 수 하나로, 「까닭」을 LLM 표시 하나로 본다. 이것을 **아동 언어 발달 연구에서 쓰는 지표를 규칙으로 계산한 값**으로 바꾼다. 규칙 4(수준은 규칙이 계산, LLM은 신호만)를 그대로 지킨다.

| 지표 | 무엇 | 계산 |
|---|---|---|
| MLU-m | 평균 발화 길이(형태소) | 형태소 분석기로 아이 발화(`by == child`)의 형태소 수 평균 |
| NDW | 서로 다른 낱말 수 | 세션 안 아이 발화의 서로 다른 내용어 수 |
| 까닭 말 | 「왜냐하면 · ~해서 · ~니까」 | 연결어미 · 접속 부사 목록 대조 |

**계획**

1. **지표 계산을 순수 함수로 만든다.** 입력은 아이 발화 목록, 출력은 세 값이다. `mascot` · `card` 발화는 뺀다(규칙 5). 단위 테스트를 붙인다
2. **지표가 말하는 힘을 재는지 먼저 확인한다(타당성).** AI-Hub 108(3~6세) 전사문으로 나이별 MLU-m를 계산한다. 나이가 오를수록 값이 올라야 쓸 수 있다. 학습 PC에 있는 전사문을 쓰고, 음성은 쓰지 않는다
3. **수준 규칙에 넣는다.** 내림 신호의 「2어절 이하」를 MLU-m 기준으로 바꾸고, 까닭 말 목록을 S1 표시의 보조로 쓴다. 단계 이름 · 질문 결 · 템플릿은 그대로 둔다
4. **측정한다.** 같은 대본 세션(짧게 답하는 아이 · 길게 답하는 아이 · 까닭을 대는 아이)으로 전/후를 비교한다. 수준별 칸 채움률과 주고받기 횟수를 본다

**주의.** 답 길이는 질문이 정하기도 한다. 고르는 질문에는 누구나 짧게 답한다. 그래서 **열린 질문에 한 답만으로 지표를 계산**하거나, 질문 종류별로 나눠 본다. 이것을 안 하면 「쉬운 질문 → 짧은 답 → 더 쉬운 질문」으로 스스로 갇힌다.

**부모 화면.** 지표 값과 단계 이름은 부모에게 보이지 않는다(규칙 9 · `guidelines/2` §1-6). 리포트는 지금처럼 횟수와 원문 인용만 쓴다.

**기준 후보**: 2번에서 3세 < 6세 MLU-m(구간이 겹치지 않을 것) · 4번에서 짧게 답하는 아이의 주고받기 감소 없음 · 길게 답하는 아이가 까닭 질문에 도달하는 턴이 빨라짐. 숫자는 민우가 #320에 적는다.

### 시간이 되면 — 부모 목소리 TTS

- **무엇.** 부모 목소리를 본떠 책 낭독 등에 쓴다
- **조건**
  - **자체 호스팅만 쓴다.** 부모 음성을 외부 업체로 보내지 않는다
  - **보호자 동의를 먼저 받는다.** 선택 항목이고 기본은 끔이다. 목소리 샘플의 보관 기간과 지우는 방법을 동의 화면에 쓴다
  - **아이 목소리는 복제하지 않는다.** 미성년자 생체 정보이고, 업체 이용 정책에서도 막혀 있다
- **먼저 할 일.** 한국어 음성 복제 모델 후보를 조사한다(라이선스 · 한국어 품질 · GPU 메모리). PC1 GPU에는 받아쓰기와 그림 생성이 함께 올라가 있다. 화자분리 모델 하나를 더 올렸을 때 배경 생성이 3.86초에서 5.10초로 늘었다(규칙 8)

## ④ 판정 Jev → 라야 — 치영

**문제.** 판정(아이 말이 어느 칸을 채웠나)은 매 턴 아이를 기다리게 한다. 루나 판정은 약 2.3초, Jev는 약 0.7초다. Jev는 외부 업체(TypeSafe) 모델이다.

**지금 있는 것**

- Jev 기준선(09-22 · 09-26): 100문항 · 실패 0건 · **p95 0.73초** · 9필드 정확도 **88.6%**(루나 88.0%와 동률) · 100문항 29.2원
- 원자료: `eval/raw/jev-latest.jsonl`(깃 제외, 10-08에 치영에게 전달). 측정 도구 `eval/bench_jev.py`
- Jev는 9필드만 답하고 글(`value_1` · `reason` 등)은 못 쓴다

**계획**

1. **같은 100문항 · 같은 9필드로 비교한다.** Jev 원본을 기준선으로 두고 필드별 정확도와 신뢰구간을 낸다. 총점만 나란히 두지 않는다(`eval/results.md` 09-22 절의 함정)
2. **지연 p95와 한 문항 값을 함께 잰다.** 같은 서버 조건에서 잰다
3. **학습 데이터와 평가 문항을 나눈다.** 100문항으로 학습하면 비교가 무효다

**기준 후보**: 9필드 정확도가 Jev와 동률 이상 · p95 0.73초 이하 · 아이 말이 외부 업체로 나가지 않음(자체 호스팅이면 차별점 1 쪽으로 이득). 숫자는 치영이 #324에 적는다.

**확인 안 된 것.** 라야가 어떤 모델인지(크기 · 라이선스 · 어디서 돌리나)가 레포에 아직 없다. 치영이 #324 첫머리에 적는다.
