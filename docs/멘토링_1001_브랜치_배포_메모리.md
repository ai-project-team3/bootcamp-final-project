- [ ] **멘토 아티팩트 공유** — 오늘 만든 HTML 3개(브랜치 현황 · 런북 등)를 카톡으로 팀에 — 담당: 멘토

### 브랜치 · PR 흐름

## 1. 기술 이슈 현황

- **TypeCast 차단** — 무료 토큰을 다 쓰고 새 API 키로 갈아 끼우다 TypeCast 쪽에서 감지해 막았다
- **TTS/STT 품질 하락** — OpenAI TTS 로 폴백하면서 목소리 품질이 떨어졌고, 받아쓰기도 같이 나빠졌다
- **Claude 오동작** — 세션 사이 맥락을 못 잡고 `release` 브랜치를 임의로 고쳤다. 원하지 않는 변경이 자동 배포로 올라갔다
- **GPU 분산** — PC1 이미지 생성 · PC2 Whisper 받아쓰기 + 백엔드

## 2. 깃 브랜치 리뷰

- 멘토가 브랜치 현황을 HTML 그래프로 그렸다. `main` 이 왼쪽에 붙어 있고 갈라진 가지가 오래 가지 않는 모양이 좋다
- 지금은 이름 브랜치가 따로 살면서 `main` 에 안 합쳐진 게 많다. 남의 작업을 보려면 그 사람 브랜치로 HEAD 를 옮겨야 한다
- 종훈이 각자 변경을 받아 Claude 로 정리해서 `main` 에 올리는 구조 — 필요 없는 중간 단계이고 히스토리가 꼬일 위험
- **Trunk-based flow** 권장. 4인 팀에 Git Flow(release · hotfix · develop 분리)는 과하다

## 3. CI/CD · 배포 파이프라인

- 배포 스크립트가 백엔드 서버를 내리고 빌드한다 → 고칠 대상
- 안드로이드 유닛 테스트 포함 CI 전체 약 8분 50초. 캐시가 없어서다
- GitHub Actions → 강의실 PC1 에 붙은 self-hosted runner 로 자동 배포
- Play 스토어는 조장이 Play Console 에 손으로 올린다
- 단기 목표: **배포 3분**

## 4. 메모리 파일 · 시스템 프롬프트

- 메모리 파일이 매 세션 약 14,000 토큰 로드된다 (컨텍스트의 1.5% 수준)
- **Pace layering** — 자주 바뀌는 것(코드·현황)과 바뀌면 안 되는 것(규칙)을 층으로 나눈다
- 규칙이 많으면 모델이 그것만 따른다. *"모델을 똑똑하게 쓰려면 룰을 좀 많이 걷어내야 한다"*
- 처음부터 말한 **북극성**을 메모리에 명시하라

## 5. PR 리뷰

- 종훈이 머지 중재자일 필요 없다 — 팀원이 `main` 으로 직접 PR
- 리뷰할 때 Claude 에게 *"이 PR 이 무슨 내용인지 설명해 줘"* 로 맥락을 잡으면 된다
- 코드 줄보다 **무엇을 왜 하는지**가 중요하다
- 머지 순서·체크리스트는 **런북을 HTML 로** 만들어 따른다

## 6. 데모 현황

- 일기 모드 빼고(부모 협업 모드 포함) 한 바퀴 완료
- 일기 모드는 받아쓰기 단계에서 막혔다 — 낮에는 됐다가 이후 작업하면서 망가짐
- **부모 모드 ≠ 부모 협업 모드** — 부모 모드는 비밀번호 4자리로 들어가는 설정 화면, 부모 협업 모드는 별도 기능 모드
- 앱 다이어그램이 너무 복잡하다. 살을 붙이려면 뼈대가 단순해야 한다

## 7. TTS 대안

- OpenAI TTS 품질이 너무 낮다는 의견
- 멘토가 커스텀한 GPT 음성을 시연 → 팀 반응 *"나쁘지 않다"* → 쓰라고 권장
- 아이 목소리에 집착하지 말고, 출시 가능한 수준으로 먼저 간다. 품질은 나중에 올릴 수 있다
