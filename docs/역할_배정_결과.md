# 역할 배정안

> 희망표 네 장 모두 받았습니다. 아래가 배정안입니다.
> **확정은 9/14(월) 계약 동결 회의**입니다 — 그 전에 의견 있으면 말씀해 주세요.

## 배정

| 역할 | 담당 | 지망 |
|---|---|---|
| **1 음성 · 실시간 · 배포** | **이재환** | 1지망 |
| **2 항목 매칭** | **박진웅** | 1지망 |
| **3 상태 추적 · 측정** | **안치영** | — |
| **4 생성** | **최민우** | 1지망 |
| **5 템플릿 · 누적** | 이종훈 (조장) | 사전 확정 |

## 한 줄로 말하면

| | 무슨 일인가 |
|---|---|
| **1 이재환** | **말을 글자로 바꿔 넘깁니다.** 마이크 소리를 실시간으로 받아 문장으로 만들고, 프로그램이 인터넷에서 끊기지 않게 띄웁니다 |
| **2 박진웅** | **그 말이 어느 항목 얘기인지 맞힙니다.** *"가격이 좀…"* 을 듣고 `예산 부담` 항목을 찾아냅니다 |
| **3 안치영** | **그 항목이 지금 막혔는지 풀렸는지 판정합니다.** 그리고 다섯 명의 성적표를 만드는 채점 도구를 만듭니다 |
| **4 최민우** | **지금 상황을 사람이 읽을 문장으로 바꿉니다.** 화면에 뜨는 조언 카드와 미팅 후 리포트 |
| **5 이종훈** | **무엇을 추적할지 목록을 정하고, 지난 미팅과 이번 미팅을 이어붙입니다** |

```
[5] 무엇을 추적할지 정한다
     │
[1] 소리→글자  →  [2] 어느 항목?  →  [3] 막혔나 풀렸나?  →  [4] 뭐라고 말할까
                                            │
                                       [5] 차수를 잇는다
```

## 왜 이렇게 나눴나

희망표에 공지한 조율 기준 순서를 그대로 적용했습니다.

> ① 역할 2에 기술적으로 가장 깊은 사람 → ② 역할 3에 파고드는 질문이 편한 사람
> → ③ 역할 1에 W1 압박을 견딜 사람 → ④ 나머지가 역할 4

## 근거

### 역할 1 — 이재환 · 기준 ③

**W1이 네 자리 중 가장 무겁습니다.** 첫날 오디오 스파이크에 스켈레톤과 첫 배포까지 겹칩니다.

배포가 이 자리에 붙어 있는데 **AWS 배포 경험**을 갖고 계신 게 결정적이었습니다. 스택은 다르지만 "배포가 처음이라 W1에 배우면서 한다"와 "해봤다"는 첫 주 위험도가 다릅니다.

이미지 OCR 파이프라인을 설계해보셨다는 점도 맞습니다 — 모달리티만 바뀔 뿐 **입력을 받아 구조화된 출력으로 흘려보내는 설계**는 같습니다. Q&A도 가능하다고 하셨습니다.

### 역할 2 — 박진웅 · 기준 ①

**이 자리가 프로젝트의 실제 병목입니다.** 재발 탐지가 여기 매칭 품질에 달려 있어서, 기준 ①에 "기술적으로 가장 깊은 사람"을 둔 것입니다.

네 분 중 **임베딩을 직접 만져보신 유일한 분**입니다. 문장 단위 임베딩과 모델 특성까지 찾아보셨다는 건 이 자리에서 첫 주부터 쓰입니다.

*"단순히 모델을 사용하는 것보다 실제 데이터에서 어떤 기준으로 매칭하고 성능을 어떻게 측정·개선하는지"* — 이게 정확히 역할 2가 W1부터 W5까지 하는 일입니다.

### 역할 3 — 안치영 · 기준 ②

**기준 ②에 해당하는 분입니다.** Q&A에서 가장 깊은 질문이 오는 자리인데, 깊은 질문을 받는 게 편하다고 답해 주셨습니다. 우리 차별점이 재발 탐지라 심사위원 질문이 이쪽으로 몰립니다.

**Django · API · DB 경험이 이 자리와 직접 맞물립니다.** 상태 전이는 규칙 구현이고, 공통 평가 러너는 백엔드입니다. 기존 강점 위에 쌓는 구조가 됩니다.

그리고 역할 3에 쓰신 지망 사유가 이 자리를 정확히 설명하고 있었습니다.

> *"상태 전이 로직과 성능 평가 지표를 구현하고 분석하면서 AI 시스템의 결과를 평가하고 개선하는 경험"*

**F1 · 임계값 튜닝은 이 자리에도 있습니다.** `CONFIDENCE_THRESHOLD`(0.7)와 `RECURRENCE_COOLDOWN_SEC`(30초)를 데이터로 확정하는 게 W3 과제입니다 (`guidelines/6` §6-8 #3·#4). 여기에 **공통 평가 러너를 소유**하십니다 — 다섯 명의 지표가 전부 이 러너에서 나옵니다. Cohen's κ 계산도 이쪽입니다.

**임베딩 모델 선정도 역할 2와 공동입니다** (`guidelines/4` §4-3). 후보 모델을 비교하려면
재는 도구가 먼저 있어야 하고 그게 평가 러너입니다 — **매칭 F1이 평가 러너 지표 첫 줄입니다.**
역할 2가 후보를 돌리고, **비교표와 임계값 곡선(precision–recall)은 역할 3이 소유합니다.**

**발표의 핵심 숫자인 재발 재현율이 이 자리 지표입니다.**

### 역할 4 — 최민우 · 기준 ④

유일한 1지망자이고, 강점으로 적어주신 게 이 자리의 정의와 겹칩니다.

> *"생성 모델이 판단 영역을 침범하지 않도록 입력·출력 경계를 정리"*

이건 우리 교차 규칙 2번 — **후보는 규칙으로 뽑고 LLM은 마지막 한 줄만 쓴다** — 을 이미 이해하고 쓰신 문장입니다. 이 경계를 지키는 게 역할 4의 핵심입니다.

*"출력 형식이나 동작 조건을 명확하게 정의해서 구현 방향을 잡는 편"* 이라는 것도 구조화 출력·리포트 3종 설계와 맞습니다.

## Q&A 답변자

발표는 조장이 단독으로 10분, **Q&A 20~30분은 팀 전체가 나갑니다.** 질문이 오면 담당자가 직접 답합니다.

| 질문 | 답변자 |
|---|---|
| 왜 이 제품인가 · 시장 · 경쟁사 · 수익 모델 | **이종훈** |
| 일정 · 협업 방식 · 역할 분담 | **이종훈** |
| 도메인 · 항목 체계 · 차수 이월 · 스키마 | **이종훈** |
| 실시간 · 지연 · 오디오 · 화자 분리 · 세션 복구 · **배포·인프라** | **이재환** |
| 매칭 정확도 · 임베딩 · 표현 사전 · 데이터 | **박진웅** |
| **재발 탐지 · 상태 모델 · 측정 방법 · 지표** | **안치영** |
| LLM · 카드 · 리포트 · 환각 방지 · 데모 | **최민우** |

자질구레한 질문은 조장이 받습니다. **한 명도 답변 기회 없이 끝나지 않게** 조장이 화제를 돌립니다.
W5에 예상 질문 20개를 뽑아 담당자별로 연습합니다.

## 일하는 방식

**브랜치는 자기 영어 이름으로 하나씩 만듭니다.**

```
main
 ├── feature/leejaehwan
 ├── feature/ahnchiyoung
 ├── feature/parkjinwoong
 ├── feature/choiminwoo
 └── feature/leejonghoon
```

철자는 본인이 쓰던 걸로 하시면 됩니다 — **원칙은 "한 사람당 브랜치 하나"이지 철자가 아닙니다.**
한글 브랜치명은 Windows 콘솔과 GitHub URL에서 깨지니 영문으로만 만듭니다.

🔒 **`main`에는 직접 push하지 않습니다.** PR을 올리면 **조장이 검토 후 머지**합니다.
데이터 모델과 API가 다섯 명 사이에서 흔들리지 않게 하는 장치입니다.

**금요일이 통합일입니다** — merge → E2E 1회 → 지표 갱신.
금요일에 안 도는 것은 그 주에 없는 것으로 칩니다.
