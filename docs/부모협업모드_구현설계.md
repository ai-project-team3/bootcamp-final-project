## 0. 한 줄로

**부모가 부모 모드에서 질문을 미리 적어 두고, 이야기 중에 마스코트가 그 질문으로 아이에게 묻는다.**
부모는 그 자리에 없어도 된다. 무엇을 물을지의 **저자만 부모**다(설계 §2-2).

지금 코드는 이것이 아니다 — `CoopScenes.kt`는 일기 흐름에 「마스코트 음소거 + 어른이 읽는 띠」를 얹은 9/21 설계다.
홀더(`parentQuestions`)는 들어갔지만 **아무도 채우지 않고 아무도 읽지 않는다.**

## 1. 비어 있던 결정 여섯 — 제안

| # | 무엇 | 제안 | 왜 |
|---|---|---|---|
| ① | **누가 소리 내어 읽나** (설계 머리말 미결 ①) | ✅ **확정 — 마스코트가 읽는다.** `coopAsk`의 `silent = true`를 뺀다 | 부모가 옆에 없는 것이 기본이다. 소리가 없으면 글을 못 읽는 아이는 질문을 못 받는다. 부모가 옆에 있으면 띠에 같은 글이 떠 있으니 따라 읽어도 된다 |
| ② | **소진 뒤** (조장: "진웅이 정한다") | ✅ **확정 — 이야기를 만들 만큼 질문이 모자라면, 그때까지 찬 칸을 보고 필요한 질문을 그 자리에서 만들어 마스코트가 묻는다.** `story_ready`까지 | 동화 모드와 같은 원리다 — 판정이 `next_slot`을 정하고(`guidelines/7` §2) 마스코트 프롬프트가 그 칸을 묻는다(§3). **LLM이 붙기 전의 대역은 일기 사다리**: `DIARY_STEPS`가 안 찬 자리만 골라 묻는다(`step.ask(s)`). 구조는 같고, 나중에 대본 질문 자리에 생성 질문이 들어간다. ⚠️ 치영님 문서의 폴백 「AI 귀띔 → 부모가 읽기」와 다르다 — ①대로면 부모가 없으므로 그 길은 없다. §5에서 알린다 |
| ③ | **개수** | **1~6개.** 화면은 4칸(기·승·전·결)을 먼저 보여 주고 [＋]로 늘린다 | 6쪽 책에 장면이 6개다. 기승전결 4자리는 일기 §2-1이 이미 필수로 정한 틀이라 부모에게 "어디 · 무슨 일 · 왜 · 어떻게 됐나"로 안내하기 쉽다. 0개면 협업 모드가 아니라 일기 모드다 — 시작을 막지 않고 **일기 모드로 돈다고 알려 준다** |
| ④ | **질문이 어느 칸을 채우나** | **부모가 자리(기·승·전·결)를 고른다.** 자유 질문에는 「자유」 자리 | 판정 LLM은 지금 대본(`judge()`는 `QVariant` 기반)이라 **부모 질문에는 더미 답이 없다.** 자리를 알면 그 자리의 일기 사다리 더미 답을 빌려 쓸 수 있어 데모가 돈다. 실제 LLM이 붙으면 `asked_slot`이 이 값이다 — 자리 → 슬롯 매핑은 일기 §2-1(`place` · `problem` · `cause` · `solution`) 그대로 |
| ⑤ | **입력 방식** | **글자 입력 + 추천 카드 탭.** 음성 입력은 안 한다 | 부모는 글을 읽고 쓴다. 추천 카드는 지금 대본(일기 사다리 첫 칸)이고 나중에 LLM 추천으로 바뀐다(§9 "추천하는 정도로만") |
| ⑥ | **질문 규칙 검사** (설계 §5-1 · §7) | **입력할 때 귀띔만, 막지 않는다.** 규칙 5개 중 코드로 볼 수 있는 셋 — 예/아니오로 끝나는가 · 의문사가 둘 이상인가 · '언제'가 있는가 | 이 모드가 파는 것이 "질문하는 법"인데(설계 §7) 9/23 밖으로 밀려 있었다. 규칙 기반이면 LLM 없이 오늘 된다. **점수 없음** — "이렇게 바꿔 보면 아이가 더 길게 답해요" 한 줄과 고친 예시 하나 |

**⑥의 판정 규칙** (전부 어절 단위 · 정규식)

| 규칙 | 걸리는 예 | 귀띔 |
|---|---|---|
| 예/아니오 종결 | "재밌었어?" · "좋았어?" · "~했어?"(서술어만 있고 의문사 없음) | "'뭐가' '누구랑' 같은 말을 넣으면 아이가 더 길게 답해요 — 예: 오늘 제일 재밌었던 게 뭐였어?" |
| 의문사 둘 | "누구랑 뭐 하고 놀았어?" | "한 번에 하나만 물어보세요. 아이는 마지막 것만 답해요" |
| '언제' | "언제 그랬어?" | "'언제'는 아직 어려워요. '어디서'나 '누구랑'으로 바꿔 보세요" |

## 2. 화면

### 2-1. 부모 모드 — 새 탭 「협업 질문」 (`ui/Parent.kt`)

```
┌ 부모 모드 › 협업 질문 ───────────────────────────────┐
│ 오늘 아이에게 물어볼 것을 적어 두세요. 마스코트가 대신 물어봐요 │
│                                                        │
│ 기 · 어디        [ 오늘 어디 갔었어?            ] [🗑]  │
│ 승 · 무슨 일     [ 거기서 무슨 일이 있었어?      ] [🗑]  │
│                  ⚠ '뭐가' 같은 말을 넣으면 아이가 더 길게 답해요 │
│ 전 · 왜          [                              ]      │
│ 결 · 어떻게      [                              ]      │
│ [＋ 하나 더]                                            │
│                                                        │
│ 추천  「오늘 제일 재밌었던 게 뭐였어?」 「누구랑 있었어?」 … │
└────────────────────────────────────────────────────────┘
```

- 탭 라우팅은 `sceneParent()`의 `tab:*`가 범용이라 **`Scenes.kt`를 안 건드리고** 탭을 더할 수 있다
- 저장은 홀더에만. **이야기마다 비운다**(조장 결정) — 화면에도 "이 질문은 오늘 이야기에만 쓰여요"
- 글자 입력은 Compose `TextField`. 데모 서랍에는 「예시 질문 4개 채우기」 버튼 하나

### 2-2. 아이 화면 — 띠의 뜻이 바뀐다 (`ui/ParentBand.kt`)

| 지금 | 바꾼 뒤 |
|---|---|
| "어른이 읽고 물어봐 주세요" + 질문. 마스코트는 소리 없음 | **"엄마가 넣어 둔 질문이에요"** 배지 + 질문. **마스코트가 소리 내어 읽는다** |
| 일기 사다리로 넘어가도 띠가 그대로 | 소진되면 띠가 **내려간다** — 그 뒤는 마스코트 질문이라 표시할 것이 없다 |

「엄마」는 지어내지 않는다 — 협업 모드는 함께할 사람을 묻지 않으므로 **"어른이 넣어 둔 질문"**으로 쓴다.
아이 화면 제목 "오늘 있었던 일 말하기"는 `Scene.DIARY.label`(`Model.kt`, 조장 소유)이라 **바꾸려면 요청**한다.

### 2-3. 부모 모드 「오늘의 기록」

이미 ③ 기준으로 맞춰 놓았다(`fdfa6d7`). 여기에 더할 것 하나 — **넣어 둔 질문별로 아이가 뭐라고 답했나** 한 줄씩.
그것이 "부모가 궁금해한 것을 묻는 책"(설계 §0)의 결과물이고, 리포트 인용은 `by: child`만 쓴다(§4-1).

## 3. 흐름과 데이터

```
부모 모드 「협업 질문」에서 parentQuestions 를 채운다 (자리 · 글)
  ↓ 아이 모드 → [같이 만들기] → 주인공
sceneDiary (isCoop)
  ├ coopIntro: "어른이 물어보고 싶은 게 있대. 내가 대신 물어볼게!"
  ├ hasParentQuestion 인 동안:  nextParentQuestion() → 마스코트가 읽고(띠에도) → 아이 답 → 판정 → 받아주기
  │     이벤트: utterance(speaker: adult, text: 질문) · 그 뒤 아이 utterance(by: child) — 설계 §8 그대로
  └ 소진: 띠 내림 → 찬 칸을 보고 필요한 질문을 만들어 마스코트가 묻는다
        지금(대본): DIARY_STEPS 가 안 찬 자리만 골라 묻는다 · 나중(LLM): 판정 next_slot → 마스코트 프롬프트 §3
        (이미 찬 자리는 건너뜀 = 규칙 "이미 값이 있는 칸을 다시 묻지 않는다")
  ↓ story_ready → 책
부모 모드 「오늘의 기록」: 넣은 질문 N개 · 질문별 아이 답
```

- **홀더에 자리(기·승·전·결)를 같이 담아야 한다.** 지금은 `List<String>`이다 → `Model.kt`에 `parentQuestionParts` 하나 더 요청하거나, 문자열에 접두("승|거기서 무슨 일이 있었어?")로 담는다. **접두 방식은 임시**로만 — 조장에게 `data class ParentQuestion(part, text)` 요청이 맞다 (§5)
- 새 이벤트 없음. `story_start mode: coop` 그대로
- `author` · `parentTooMuch` · `pageAuthor` — 9/21 [내가 답할래]의 잔재. ③에는 부모가 칸을 채우는 자리가 없으므로 **지운다**(`Model.kt` · `Book.kt`에 걸쳐 있어 조장과)

## 6. 안 하는 것

- 화자 분리 — §9-8대로 범위 밖. 부모가 옆에서 읽어 줘도 `unsure`는 버린다(설계 §9-2)
- 부모 질문 LLM 채점(설계 §7) — 규칙 귀띔(§1-⑥)까지만
- 질문 저장 — 저장 자체가 없다. 이야기마다 비운다
- `by` 늘리기 — 안 한다(설계 §4-1)
