## 범위와 현재 상태

현재 동화 서버 입력 구성과 프롬프트의 누락 가능성을 확인하고, 내용 보존 후보를 비교할 계획이다. 기준 소스는 `714584e461c5412177853d5a63facb738482e60c`다. 운영 `backend/app/routers/story.py`와 `eval/story_prompt.md`는 변경하지 않는다. 실측·조장 검토 전에는 후보를 운영에 적용하지 않는다.

합성 입력 6개와 실행 도구의 오프라인 검사는 실제 모델 품질 검증을 대신하지 않는다. 기존 성인 시연 두 책의 원문이나 실제 아이 발화는 사용하지 않으며, 두 책이 어디에서 처음 달라졌는지도 이 비교로 소급 확정하지 않는다. 앱의 입력 보존 수정은 별도 검증한다.

## 유료 호출 전 준비와 실행

먼저 기본 실행 또는 `--dry-run`으로 양쪽의 실제 system/user와 요청 해시를 확인한다. 설정 파일은 읽지 않고 API 호출은 0회다. 결과 폴더가 있으면 덮어쓰지 않고 중단한다.

```powershell
python eval/bench_story_rewrite_fidelity.py --dry-run --out eval/raw/story_fidelity_dry_1013
```

실측은 팀의 **기존** 평가 설정을 사용한다. 새 키 발급을 요청하거나 설정 파일 내용을 열거나 붙여 넣지 않는다. `--run`이 명시된 경우에만 유료 호출을 수행한다. 환경 변수에 기존 설정이 있다면 `--env`를 생략한다. 예시의 경로는 실행 PC에서 기존 설정 파일의 경로로 바꾸되 결과 문서에 그 내용이나 경로를 저장하지 않는다.

```powershell
python eval/bench_story_rewrite_fidelity.py --run --env "<기존-평가-설정-파일>" --out eval/raw/story_fidelity_run_1013
```

`--runs 1` 또는 `--limit 1`로 더 작게 시작할 수 있다. 도구는 2회·6개 상한을 늘리는 요청을 거절한다. 실행 전 호출 수·모델·effort와 현재 설정의 비용 조건을 담당자가 확인한다. API가 설정되지 않았으면 호출 없이 중단한다. 이 저장소 변경에는 유료 호출이나 운영 배포가 포함되지 않는다.

## 기록과 사람 판정

`requests.jsonl` 또는 `results.jsonl`에 arm·입력·회차·요청/쪽 목록·system/user·각 SHA256·출력·사용 토큰·지연·상태를 남긴다. `manifest.json`에는 예정/실제 호출 수·생성·거절·오류·건너뜀과 설정의 모델/effort를 남긴다. 설정 파일 경로·키·헤더·원문 vendor 오류는 저장하지 않는다. 결과는 합성 입력과 출력만 포함하므로 기존 제외 경로 `eval/raw/`에 둘 수 있다.

도구는 `manual_book_pass`와 `manual_book_pass_rate`를 `null`로 둔다. 사람이 각 출력과 입력을 대조한 뒤 별도 검토표에 판정·근거 문장·쪽 번호를 기록한다. 양쪽 이름을 가린 출력 순서로 먼저 검토하면 조건 선호를 줄일 수 있다.

책 합격 기준은 필수 사실 전부 보존, 고유 표현 보존, 허용되지 않은 새 핵심 사실 0건, 의미 반전 0건, 주체·출처 변경 0건, 미션 완료 행동의 선행 서술 0건, 기존 쪽 수·금칙어·자리표시자 검사 통과다. #462의 사전 기준대로 모든 쪽의 이해 가능성도 1~3점 중 2점 이상이어야 한다(1=뜻 파악이 어렵거나 비문, 2=뜻은 분명하나 표현이 어색함, 3=뜻이 분명하고 자연스러움). 불명확한 원문·출력은 보류하고 보류를 통과로 세지 않는다. FID05는 미션 쪽의 결과 금지를 따로 확인한다. 그 뒤 결말에서 입력의 완료 행동을 쓰는 것은 미션을 미리 끝내는 것과 구분한다.

각 조건의 전체 분모는 고정 입력 6개 × 2회 = 12권이다. 오류·거절·중단 뒤 건너뜀·보류도 따로 표시하고 분모에서 숨기지 않는다. 같은 입력의 반복을 서로 다른 아동 표본처럼 세지 않는다. 검토자와 AI 도움 사용 여부를 남기고 독립 전문가 정답 대비 정확도로 표시하지 않는다.

후보 도입 판단은 실패 사례·합격 수·호출 오류·후검사 거절을 양쪽에 함께 제시한 뒤 조장이 검토한다. 6입력 × 2회는 작은 목적 표본이며 전체 품질·운영 지연·실제 아이 사용 개선이나 통계적 우월성을 주장하지 않는다. 실패가 남으면 원인별로 후보를 좁히고 새 입력/기준을 기록한 뒤 다시 비교한다.
