## 1. 박진웅 — 프롬프트와 스키마 확정

**목표**: 모델이 바뀌어도 **절대 안 바뀌는** 프롬프트 2벌을 만든다.

**산출물**: `eval/judge_prompt.md` · `eval/judge_schema.json` · `eval/story_prompt.md` · `eval/story_schema.json`

### 1-1. 판정 스키마 (오전 · 먼저)

> ⚠️ **새로 만들지 않는다. `프롬프트_모음.md` §2에 이미 있다.** 오늘 할 일은 그것을 **JSON Schema로 옮기고 벤더 둘에서 통과시키는 것**이다.

**설계 결정 (9/18 확정)** — 상세는 `프롬프트_모음.md` §2
- **슬롯 하나가 아니라 슬롯 전체 + 템플릿을 준다.** 슬롯은 폼이 아니라 **이야기에 지금 필요한 재료**다
- **다음에 뭘 물을지도 LLM이 정한다**(`next_slot`). 앱이 순서대로 돌지 않는다
- **필수 칸은 동적**이다(`no_longer_needed`). **턴 상한은 없다** — 끝내는 기준은 `story_ready`
- **칸 이름은 고정 enum**(11개 + `extra`). LLM이 새 이름을 만들지 못한다

**필드 순서가 중요하다. `reason`이 반드시 첫 필드다** — 판정 필드보다 앞에 근거를 쓰게 하면 정확도가 15~24점 오른다(arXiv 2608.25358).

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["reason","slot_1","value_1","slot_2","value_2",
               "contradiction","contradiction_with",
               "s1_reason","s2_addition","emotion",
               "unclear","unclear_of",
               "next_slot","next_reason","no_longer_needed","story_ready"],
  "properties": {
    "reason":             { "type": "string" },
    "slot_1":             { "type": ["string","null"], "enum": [null,"place","problem","reaction","cause","newcomer","name","companion","sound","adult","solution","title","extra"] },
    "value_1":            { "type": ["string","null"] },
    "slot_2":             { "type": ["string","null"], "enum": [null,"place","problem","reaction","cause","newcomer","name","companion","sound","adult","solution","title","extra"] },
    "value_2":            { "type": ["string","null"] },
    "contradiction":      { "type": "boolean" },
    "contradiction_with": { "type": ["string","null"] },
    "s1_reason":          { "type": "boolean" },
    "s2_addition":        { "type": "boolean" },
    "emotion":            { "type": ["string","null"] },
    "unclear":            { "type": "boolean" },
    "unclear_of":         { "type": ["string","null"] },
    "next_slot":          { "type": ["string","null"], "enum": [null,"place","problem","reaction","cause","newcomer","name","companion","sound","adult","solution","title","extra"] },
    "next_reason":        { "type": ["string","null"] },
    "no_longer_needed":   { "type": ["string","null"] },
    "story_ready":        { "type": "boolean" }
  }
}
```

⚠️ **nullable 처리가 벤더마다 다르다.** OpenAI strict는 모든 필드가 `required`여야 하므로 **옵셔널 대신 `["string","null"]`**을 쓴다. Anthropic 제약 디코딩에서도 이 형태가 되는지 **1회 호출로 확인**한다. 안 되면 `null` 대신 빈 문자열 `""`로 통일한다.

⚠️ **벤더 공통분모만 쓴다.** Anthropic 제약 디코딩은 `minimum`/`maximum`/`minLength`/재귀/외부 `$ref`를 **지원하지 않고**, OpenAI strict 모드는 `additionalProperties:false`와 **모든 필드 required**를 요구한다. 위 스키마는 둘 다 만족한다. **여기에 뭘 더 넣지 마라.**

⚠️ **중첩 금지.** 1단 평면이다. 깊어지면 *"값은 맞는데 필드가 틀리는"* 실패가 지배적이 된다.

### 1-2. 판정 시스템 프롬프트

**규칙을 스키마 `description`이 아니라 여기에 쓴다.** description에 넣으면 정확도가 11~13%p 떨어진다(arXiv 2608.08254).

뼈대 — 살을 붙이되 구조는 유지한다:

```
너는 만 3~7세 아이와 이야기를 만드는 놀이의 판정기다.
아이의 대답 한 문장을 읽고 아래 넷을 판정해 JSON으로만 답한다.

[아이 말의 특징]
- 비문·조사 탈락·반복·의성어가 흔하다. 문법이 틀려도 뜻이 통하면 맞는 답이다.
- 음성 인식 오류로 글자가 틀릴 수 있다. 발음이 비슷하면 같은 말로 본다.
- 이름은 {주인공}·{친구1} 자리표시자로 들어온다. 이 표시자를 절대 바꾸지 마라.

[판정 기준]
slot_match  : 지금 묻고 있는 칸에 대한 답인가. 엉뚱한 말이면 false.
contradicts : 앞에서 정한 것과 어긋나는가. 앞 내용이 없으면 false.
s1 (까닭)   : 왜 그런지를 말했는가. "~니까" "~해서" "~때문에" "왜냐하면" 등.
              단 순서를 말한 "가서 먹었어"는 까닭이 아니다.
s2 (덧붙임) : 묻지 않은 것을 스스로 더 말했는가. 절이 둘 이상이면 대개 true.

[출력]
reason에 한 줄 근거를 먼저 쓰고, 그다음 네 값을 정한다.
JSON 외에는 아무것도 출력하지 마라.
```

**예시(few-shot) 2~3개를 붙인다.** 반드시 **S1 참인 것 1개 · S1 거짓인 `-서` 함정 1개**를 포함한다. `~서`가 인과와 순차를 같은 형태로 쓰기 때문에 여기가 제일 많이 틀린다.

### 1-3. 생성 프롬프트 (오후)

**제약을 프롬프트에 명시적으로 박는다.** 자동 채점이 이걸 그대로 잰다.

- 장면 **정확히 6개**
- 자막은 **`-어요`체**
- 자막은 **15어절 이하**
- 이름은 **`{주인공}`·`{친구1}` 그대로**. 실명으로 바꾸면 안 된다
- 무섭거나 공격적인 표현 금지 (금지어 목록은 최민우와 공유)

### 1-4. 라벨 100개 (오후 2시간) — **판정 규칙을 정의한 사람이 붙인다**

안치영이 추출한 100개에 정답을 붙인다. 기준표는 §2-2. **나누지 않는 이유는 거기 적혀 있다.**

- **정답형 30 · 무관 15는 거의 즉답**이다. 시간이 드는 건 **S1·S2 40개**
- **경계 사례는 표시해 둔다.** 50번째쯤 기준이 선명해지면 **앞으로 돌아가 고친다.** 혼자 붙이는 가장 큰 이유가 이것이다
- 다 붙인 뒤 **기준표(§2-2)를 실제로 적용한 대로 고쳐 둔다.** 다음 100개를 붙일 때 같은 고민을 반복하지 않게

## 2. 안치영 — 평가셋 두 벌

**목표**: 모델을 채점할 **정답지**를 만든다. 이게 없으면 아무도 점수를 못 낸다.

**산출물**: `eval/fixtures_judge.jsonl` (100줄) · `eval/fixtures_story.jsonl` (3줄)

### 2-1. 판정 평가셋 100개 (오전)

데모 v0.9의 **더미답 258개**에서 뽑는다.

| 유형 | 개수 | 예 | 정답 라벨 핵심 |
|---|---|---|---|
| 칸에 맞는 답 | 25 | "공룡나라 갈래" | `slot_1`+`value_1` |
| **까닭 (S1)** | 20 | "무서워서 도망갔어" | **`s1_reason` ✓** · `emotion` |
| **덧붙임 (S2) — 다중채움** | 20 | "공룡나라 갈래 근데 뿌뿌도" | **`slot_1`+`slot_2` 둘 다** |
| **필수해제** | 10 | "혼자 갔어" | **`no_longer_needed`** |
| 무관·엉뚱 | 10 | "엄마 어디 있어?" | `slot_1: null` |
| **짧거나 미완결** | 15 | "응" · "몰라" · "공뇽…" | 대개 `slot_1: null`, `unclear` |

**⚠️ `-서` 함정을 S1 20개 안에 최소 5개 넣는다.** 인과 3개("무서워**서** 울었어") + 순차 2개("가**서** 먹었어"). **순차는 s1이 false다.** 이게 모델을 가르는 지점이다.

### 2-2. 라벨 붙이는 규칙 — 애매하면 이 기준으로

| 필드 | true로 찍는 조건 | false 예 |
|---|---|---|
| `slot_match` | 지금 묻는 칸에 대한 답. **문법이 틀려도 뜻이 통하면 true** | 질문과 무관한 말, 되묻기 |
| `contradicts` | **앞에서 정한 것과 어긋날 때만.** 앞 내용이 없으면 무조건 false | — |
| `s1` | **왜**에 답했을 때. `~니까`·`~때문에`·`왜냐하면`·인과의 `~서` | **순차의 `~서`**, 단순 서술 |
| `s2` | 묻지 않은 것을 더 말함. **절이 둘 이상이면 대개 true** | 한 절짜리 단답 |

**⚠️ 라벨은 한 사람이 100개 전부 붙인다 — 박진웅이 붙인다.**

**나눠 붙이면 안 된다.** 25개씩 나누면 각 항목이 **한 사람에게 한 번씩만** 라벨된다. 그건 **서로 다른 기준 넷을 서로 다른 구간에 적용하는 것**이지 교차 검수가 아니다. 일관성도 중복도 없다.

| 왜 한 사람인가 |
|---|
| 우리가 잡으려는 **모델 간 F1 차이가 몇 %p**다. **라벨 잡음이 5~10%면 그 차이가 묻힌다** |
| 하필 **`-서`(인과 vs 순차)가 사람마다 갈리는 지점**이라 잡음이 거기 몰린다 |
| 50번째쯤에서 기준이 선명해지면 **앞의 것들을 되돌아가 고칠 수 있다.** 여럿이면 못 한다 |
| **판정 규칙을 정의한 사람이 붙여야 기준이 하나가 된다** — 그래서 박진웅이다 |

**분담은 이렇게**
- **안치영: 추출만** (258 → 100, 라벨 없이). 오전 1시간 → **최민우에게 바로 넘긴다** → 오후는 **일기 모드**
- **박진웅: 라벨 100개.** 오후 2시간. 정답형 30·무관 15는 거의 즉답이고, **시간이 드는 건 S1·S2 40개**다
- **최민우: 라벨을 기다리지 않는다.** 라벨 없는 100개로 **예측을 먼저 수집**하고, 채점만 저녁에 한다

**검수**: 안치영이 **20개만 따로 라벨**해 박진웅 것과 대조한다(20분). **일치도를 숫자로 남긴다** — 불일치가 3개 넘으면 **모델 탓하기 전에 위 기준표부터 고친다.** 정답지를 못 믿으면 점수가 의미 없다.

         "s1_reason":false,"s2_addition":false,"emotion":null,
         "next_slot_ok":["problem","newcomer"],
         "no_longer_needed":"companion","story_ready":false},"type":"필수해제"}
```

### 2-4. ⚠️ `next_slot`은 **정답 하나로 채점하지 않는다**

맥락에 따라 **물어도 되는 칸이 여럿**이다. 정답 하나를 강요하면 **정상 답을 오답으로 세게 된다.**
→ **`next_slot_ok`에 허용 집합을 적고, 그 안에 들어가면 맞은 것**으로 센다.

**새로 라벨할 항목 둘도 각각 최소 10개씩 넣는다.**

| 유형 | 개수 | 예 |
|---|---|---|
| **S2-다중채움** | 10 | "공룡나라 갈래 근데 뿌뿌도" → `slot_1`+`slot_2` 둘 다 |
| **필수해제** | 10 | "혼자 갔어" → `no_longer_needed: companion` |

**이 둘이 이번 설계 변경의 핵심이다.** 슬롯 하나만 주는 방식으로는 원리적으로 못 잡는 항목이라, **여기서 갈린다.**

### 2-4. 생성 입력 3벌 (오후)

`엔드픽처_초안.md` · `구현대본.md`에서 **칸이 다 찬 상태** 3개를 뽑는다. **세계·주인공·사건이 서로 다르게.**

```

## 3. 최민우 — 러너와 채점기

**목표**: **같은 입력을 여러 모델에 돌려 같은 기준으로 점수를 내는** 스크립트.

**산출물**: `eval/run_judge.py` · `eval/score.py` · `eval/corrupt.py` · `eval/results.md`

### 3-1. 판정 러너 (오전 · 골격부터)

```
python eval/run_judge.py --model gpt-5.6-luna --fixtures eval/fixtures_judge.jsonl --out eval/raw/luna.jsonl
```

**벤더마다 호출이 다르다. 이 세 가지만 맞추면 된다.**

| 벤더 | 구조화 출력 | 추론 끄기 |
|---|---|---|
| OpenAI | `response_format={"type":"json_schema","json_schema":{"name":"judge","schema":{...},"strict":true}}` | `reasoning_effort="none"` |
| Anthropic | 제약 디코딩 (structured outputs) | Haiku는 **기본 OFF** — 건드리지 않는다 |
| Mistral | `response_format={"type":"json_object"}` + 프롬프트에 스키마 명시 | — |

**⚠️ TTFT는 반드시 스트리밍으로 잰다.**
```
t0 = time.perf_counter()
# stream=True 로 호출
# 첫 content 토큰이 도착한 순간
ttft = time.perf_counter() - t0
# 마지막 토큰까지
total = time.perf_counter() - t0
```
**논스트리밍으로 재면 TTFT가 아니라 총 소요다.** 우리 1순위 기준이 TTFT라 이걸 틀리면 실험 전체가 무의미하다.

**기록할 것** (한 줄에 하나):
```json
{"id":"j001","model":"...","ok":true,"ttft":0.71,"total":1.62,
 "pred":{"reason":"...","slot_match":true,"contradicts":false,"s1":false,"s2":false},
 "in_tok":880,"out_tok":74}
```

**JSON 파싱 실패도 죽지 말고 `{"ok":false,"error":"..."}` 로 기록하고 넘어간다.** 실패율 자체가 지표다.

### 3-2. 채점기

**필드별 F1** — 불리언 4개를 각각 이진 분류로 본다.
```
TP = gold true  & pred true
FP = gold false & pred true
FN = gold true  & pred false
F1 = 2TP / (2TP + FP + FN)
```

**`next_slot`은 다르게 센다** — 정답 하나가 아니라 **`next_slot_ok` 집합에 들어가면 정답**이다. 맥락상 물어도 되는 칸이 여럿이라 하나만 정답으로 두면 정상 답을 오답으로 센다.

**`value_1`은 완전 일치로 세지 않는다** — 자유 서술이라 표현이 갈린다. **자모 편집거리 ≤ 0.3이면 맞은 것**으로 센다(§3-4 로직 재사용).

**출력 표**:

| 모델 | JSON | slot_1 F1 | **다중채움(slot_2) F1** | **필수해제 F1** | s1 F1 | s2 F1 | **next_slot 적중** | TTFT p50/p95 | 세션 원가 |
|---|---|---|---|---|---|---|---|---|---|

> **가운데 셋이 이번 설계 변경의 핵심 지표다.** 슬롯 하나만 주는 방식으로는 원리적으로 못 잡는 항목이라, **여기 숫자가 설계를 정당화하거나 뒤집는다.**

**세션 원가** = (입력토큰 평균 × 16 × 입력단가 + 출력토큰 평균 × 16 × 출력단가) × 1400 / 1e6

### 3-3. 생성 자동 채점기 (오후 · 30분)

**LLM도 사람도 필요 없다. 전부 정규식이다. 오늘 가장 싸고 확실한 지표다.**

| 항목 | 방법 | 합격선 |
|---|---|---|
| **−어요체** | 자막 문장의 종결이 `요[.!?]?$` 또는 `어요`·`예요`·`에요` | ≥ 95% |
| **15어절 이하** | `len(자막.split())` ≤ 15 | ≥ 95% |
| **금지 표현** | 금지어 목록 대조 (박진웅과 공유) | **0건** |
| **이름 무결성** | `{주인공}`·`{친구1}`이 **원형 그대로** 남아 있고 실명이 없다 | **100%** |
| 장면 수 | 정확히 6 | 100% |

### 3-4. 자모 손상 주입 ⭐ **오늘 가장 값진 실험**

**"STT가 틀려도 게임이 도는가"를 오디오 없이 잰다.**

**한글 분해 공식** (라이브러리 불필요):
```python
CHO = 588; JUNG = 28; BASE = 0xAC00
c = ord(ch) - BASE
cho, jung, jong = c // CHO, (c % CHO) // JUNG, c % JUNG
# 합성: chr(BASE + cho*CHO + jung*JUNG + jong)
```

**한국어 STT가 실제로 내는 오류만 넣는다** (무작위 아님):

| 자리 | 바꾸는 쌍 |
|---|---|
| 초성 | ㄹ↔ㄴ · ㄱ↔ㅋ · ㅂ↔ㅍ · ㄷ↔ㅌ · ㅅ↔ㅆ · ㅈ↔ㅊ |
| 중성 | ㅐ↔ㅔ · ㅗ↔ㅜ · ㅓ↔ㅗ · ㅑ↔ㅕ |
| 종성 | **탈락(→0)** · ㄴ↔ㅇ · ㄱ↔ㅋ |

| 강도 | 손상률 | 추가 | 예 |
|---|---|---|---|
| 0 | 0% | — | 공룡나라 |
| 1 | **10%** | — | 공**뇽**나라 |
| 2 | **25%** | 음절 탈락 + 띄어쓰기 오류 | 고뇽 나과 |

**그다음 자모 편집거리 매칭을 돌린다** — 손상된 문자열을 자모로 펼쳐 프리셋 후보들과 편집거리를 재고 가장 가까운 것을 고른다.

| 재는 것 | 합격선 |
|---|---|
| 강도 1에서 프리셋 매칭 정답률 | **≥ 95%** |
| 강도 2에서 | ≥ 85% |
| **매칭 적용 전/후** | — (**발표 슬라이드가 된다**) |

> **녹음보다 나은 점**: 강도를 조절할 수 있어 **곡선**이 나온다. 녹음 30개로는 점 하나만 찍힌다.

| 결과 | 뜻 |
|---|---|
| 강도 1에서 매칭 ≥ 95% | **"CER이 나빠도 게임은 돈다"가 참.** STT 예산 전체가 풀린다 |
| 강도 1에서 95% 미만 | 발음 규칙 정규화를 더 넣는다. 그래도 안 되면 **선택지 UI 병행** |

> **팀원 친척 경로가 오전에 성사되면 오늘 최종 확정까지 간다.** 넷 중 한 명만 3~7세 조카가 있으면 된다. **오전 중에 확인한다.**

## 6. 오늘 하면 안 되는 것

| 하지 말 것 | 이유 |
|---|---|
| **모델마다 프롬프트를 손보는 것** | **비교가 무의미해진다.** 결과가 나쁘면 고치고 싶어지는데, 고치는 순간 뭘 비교한 건지 알 수 없다 |
| 결과가 나쁘다고 스키마를 중첩시키는 것 | *"값은 맞는데 필드가 틀리는"* 실패가 늘어난다 |
| 조용한 방에서 녹음하는 것 | 우리 앱이 쓰이는 환경이 아니다 |
| 어른 모사 CER로 모델을 고르는 것 | 15배 차이가 난다 |
| 자체 호스팅 LLM을 켜보는 것 | 14B는 3060에 안 올라간다. 유료화 이후 |
| **VAD·병렬화를 먼저 붙이는 것** | ⛔ **베이스라인이 영영 사라진다** |

## 7. 막히면

| 상황 | 이렇게 |
|---|---|
| **키가 안 나온다** | Haiku 단독으로 파이프라인과 평가셋을 완성한다. 러너가 `--model` 인자를 받으므로 키가 생긴 날 **다시 돌리기만** 하면 된다 |
| **스키마가 벤더에서 거부된다** | 필드를 빼서 공통분모로 줄인다. `minimum`/`maxLength`/중첩/`$ref`가 원인일 가능성이 높다 |
| **JSON 성공률이 낮다** | **프롬프트를 고치지 말고** 먼저 기록한다. 그게 그 모델의 점수다. 전 모델이 낮으면 그때 스키마를 의심한다 |
| **라벨이 사람마다 다르다** | 모델 탓하기 전에 §2-2 기준표를 고친다. **정답지를 못 믿으면 점수가 의미 없다** |
| **TTFT가 이상하게 크다** | 스트리밍으로 쟀는지 확인. 논스트리밍이면 총 소요를 잰 것이다 |
| **시간이 모자란다** | **판정 하나만 끝낸다.** 생성은 내일도 된다. 판정이 세션당 16회라 제품에 미치는 영향이 가장 크다 |
