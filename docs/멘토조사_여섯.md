## 조사 1 — 데이터 지도와 합성 요청 예시

조사 이종훈 · 멘토 검토(09-22) 「함께 해볼 조사 순서」 1번

**밖으로 나가는 요청은 둘이고, 실어 나르는 것은 「아이가 지금까지 한 말 전부」다.** 판정 요청은 매 턴 **슬롯 상태 전체**를 보내므로, 3턴째 요청에는 1·2턴에 아이가 한 말이 함께 실린다. 대신 **대화 이력·기기 식별키·계정·시각·위치·음성은 나가지 않는다** — 코드에 그런 필드가 없다. 그래서 지금 확인해야 하는 것은 *"무엇이 나가나"*가 아니라 ***"세션 id를 왜 보내고 있나"***와 ***"낭독 요청에는 무엇이 실리나"***다.

---

### 이 조사의 범위

**근거로 쓴 것** — `backend/app/schemas/judge.py` · `backend/app/llm/client.py` · `eval/run_judge.py`(프롬프트를 실제로 만드는 코드) · `eval/bench_tts.py` · `eval/raw/*.jsonl`(실제 호출 기록)

**근거로 쓰지 않은 것** — 앱에서 나가는 실제 요청. **앱은 네트워크를 못 쓴다**(`INTERNET` 권한 없음) 그리고 `/judge`·`/stt`·`/story`가 전부 `NotImplementedError`다.

**따라서 아래 본문은 「코드가 만들면 이렇게 될 것」이고, 실제로 배포된 요청이 아니다.** 유일하게 실제로 호출한 것은 **평가 하네스**이고, 아래 판정 요청은 그 하네스가 만드는 것과 **같은 함수로 만든 것**이다.

아래 다섯 절은 **확인된 것 · 조건부 함의 · 확인되지 않은 것**으로 나눠 적었다. 세 번째 칸이 비어 있다는 것은 **없다는 뜻이 아니라 이 근거로는 알 수 없다는 뜻**이다.

---

### 1. 데이터가 지나가는 자리

#### 확인된 것

```
① 아이가 말한다                              [폰]
      ↓ 말소리 구간만 자름 (Silero VAD)
② 음성 → 글자                                [자체 인프라 / 외부 처리자 — 미정]
      ↓ 음성 사본 즉시 삭제
③ 이름 가리기 · 금칙어                        [폰]  ← 실명이 여기서 {친구1} 이 된다
      ↓
④ 판정                                       ██ 밖으로 나간다 ██
      ↓
⑤ 마스코트 대사 · 책 낭독                     ██ 밖으로 나간다 ██
      ↓
⑥ 그림                                       [자체 인프라 — ComfyUI]
      ↓
⑦ 기록                                       [폰] — ⚠️ 저장이 아직 없다
```

**굵은 두 자리가 외부 처리자에게 요청이 나가는 지점**이다. ②는 어디서 돌릴지 아직 안 정했다
(`docs/발표_0923_기획안.md` 8장).

⑦에 대해 정확히 적으면 — `SharedPreferences`·`DataStore`·`Room` 아무것도 없다.
**세션이 끝나면 다 사라진다.** 기록이 남지 않으므로 보존 기간도 삭제 경로도 지금은 **없는 것이 아니라 대상이 없다.**

#### 조건부 함의

**③이 ④보다 먼저인 것이 이 설계의 핵심이다.** 실명은 폰에서 `{주인공}`·`{친구1}`로 바뀌고 매핑표는 폰에만 남는다(규칙 6). 그래서 ④·⑤로 나가는 글에는 **실명이 없다.**

다만 **실명이 없다는 것과 식별되지 않는다는 것은 다른 말이다.** 아래 2절 참고.

#### 확인되지 않은 것

②를 외부로 보내기로 하면 **음성 원본이 나가는 자리가 하나 더 생긴다.** 그때 ③이 ② 뒤에 있으므로 **가려지기 전의 실명이 실린 음성**이 나간다. 지금 흐름도에서는 이 순서가 문제가 안 되는데, ②가 밖으로 가면 **문제가 된다.**

#### 같이 생각해 볼 질문

- ②를 외부로 보내면 ③(이름 가리기)을 그 앞으로 옮길 수 있나요? 음성에서 이름을 가릴 수 있나요?
- ⑦에 저장이 붙는 순간 무엇이 함께 정해져야 하나요? 저장이 없는 지금이 오히려 설계하기 쉬운 시점인가요?

### 2. 판정 요청 — 실제로 나가는 것

#### 확인된 것

`eval/run_judge.py`의 `build_user_prompt()`가 만드는 것이고, **평가 하네스가 실제로 이 모양으로 호출했다.** 3턴째 합성 예시다.

**system** (8,193자) — 판정 지침 전문 + JSON 스키마 16필드 전문. **매 턴 같은 내용이 반복해서 나간다.**

**user** (224자) — 전문이다. 줄인 것이 없다.

```
id:s_7f3a1c
slots:{"place":"공룡나라","companion":"뿌뿌","problem":null,"reaction":null,"cause":null,"solution":null}
asked:problem
template:C
utterance:{친구1}가 뿌뿌를 밀었어. 그래서 뿌뿌가 울었어.
현재 슬롯 전체와 아이 발화를 함께 보고 판정하세요. JSON 외에는 출력하지 마세요.
```

| | 나가나 |
|---|---|
| **아이가 지금까지 한 말 전부** (`slots`) | **나간다** — 매 턴 상태 전체 |
| 아이가 방금 한 말 (`utterance`) | 나간다 |
| **세션 id** (`id`) | **나간다** |
| 실명 | **안 나간다** — ③에서 `{친구1}`로 바뀜 |
| 대화 이력(턴별 기록) | **안 나간다** — `slots` 스냅샷만 |
| 기기 식별키 · 계정 · 시각 · 위치 | **안 나간다** — 코드에 필드가 없다 |
| 음성 | **안 나간다** |

#### 조건부 함의

**「매 턴 상태 전체」가 이 요청의 성격을 정한다.** 한 권이 약 19턴이면 마지막 요청에는 **그 세션에서 아이가 한 말이 거의 다 실린다.** 요청 하나만 보면 문장 한두 개인데, **세션 전체를 보면 아이 하루의 서술이 누적된다.**

#### ⚠️ 정정 — `id`는 제품이 보내는 것이 아니다 (09-22)

처음에 *"세션 id가 나간다"*고 적었는데 **틀렸다.** 확인해 보니 이렇다.

| | `id` 가 있나 |
|---|---|
| **제품 스키마** `backend/app/schemas/judge.py` `JudgeRequest` | **없다.** `slots`·`asked_slot`·`template`·`level`·`turn`·`question`·`utterance` 일곱 개뿐 |
| **평가 하네스 프롬프트** `eval/run_judge.py:44` | **있다** — `id:{item['id']}` |

**즉 `id:`는 평가 하네스가 문항 번호를 붙인 것이고 제품 설계에는 없다.** 제품은 애초에 세션 식별자를 안 보낸다.

**그래도 하네스에서 빼는 것을 권한다** — 모델이 읽지 않는 값이고, 평가 기록에 아이 말과 문항 번호가 같이 남는다. 파급효과는 아래 「빼면 무엇이 깨지나」 참고.

**그리고 한계가 하나 겹친다.** Jev를 쓰면 *"쓸데없는 맥락이 많으면 정확도가 떨어진다"*(한계 문서 5번)가 걸리는데, 지금 system 8,193자가 매 턴 나간다. **걸러 보내는 것이 정확도에도 전송량에도 유리하다.**

#### 빼면 무엇이 깨지나 — **채점은 안 깨진다. 비교 가능성이 깨진다**

`id:` 줄을 프롬프트에서 빼면 어디에 영향이 가는지 전부 훑었다.

| | 영향 |
|---|---|
| **채점** | **없다.** `eval/score.py:109`가 **출력 레코드의 `id`**로 짝을 맞추고, 그 값은 러너가 픽스처에서 써 넣는다(`run_judge.py:190`) — **모델이 돌려주는 값이 아니다** |
| 재시도·중복 제거 | 없다. `id`를 그렇게 쓰지 않는다 |
| 디버깅 | 거의 없다. 모델이 `reason`에 id를 되풀이하는 경우가 있는데, 어차피 행으로 짝이 맞는다 |
| 토큰 | `id:s_7f3a1c\n` ≈ **12토큰 / 3,964토큰 = 0.3%.** 값·속도에 실질 영향 없다 |
| **비교 가능성** | ⚠️ **여기가 걸린다** |

⚠️ **`judge_prompt.md` 머리말이 「확정 후 모델마다 손대지 않는다. 고치는 순간 뭘 비교한 건지 알 수 없다」고 적어 뒀다.** 09-20에 루나·하이쿠·나노를 **`id:` 줄이 있는 프롬프트로** 쟀다. 빼면 그 측정과 새 측정이 **엄격히는 비교 불가**가 된다.

**세 가지 중 하나를 골라야 한다.**

| | 무엇 | 값 |
|---|---|---|
| **A** | **빼고 루나를 다시 돌린다** — 기준선을 새로 만든다 | **약 30원** · 3분 |
| B | 빼고 각주로 남긴다 — *"09-20 측정은 id 줄이 있던 프롬프트"* | 0원 |
| C | 그냥 둔다 | 0원 |

**A를 권한다.** 30원에 3분이고, `guidelines/0`의 *"측정값만 결정을 바꾼다"*를 지키려면 기준선이 같은 프롬프트에서 나와야 한다. **B는 각주가 쌓이면 나중에 아무도 안 읽는다.**

#### 확인되지 않은 것

벤더가 요청에 **자동으로 붙이는 것** — 요청 식별자·조직 id·프로젝트 id는 **SDK가 붙으므로 우리 코드에서는 안 보인다.** 조사 2번에서 계정 설정을 봐야 확인된다. **우리가 안 보낸다는 것과 아무 식별자도 안 실린다는 것은 다른 말이다.**

**⚠️ 러너가 요청 본문을 기록하지 않는다.** `eval/raw/*.jsonl`은 응답(`pred`)·지연·토큰만 남기고 **무엇을 보냈는지는 안 남긴다.** 지금은 함수로 재현할 수 있어서 문제가 없지만, **프롬프트가 바뀌면 옛 측정이 무엇을 보고 나온 값인지 알 수 없게 된다.**

#### 같이 생각해 볼 질문

- `id`를 빼면 잃는 것이 있나요? 응답을 문항에 맞추는 건 순서로도 되지 않나요?
- system 8,193자 중 **매 턴 다시 보내야 하는 것**은 얼마인가요? 프롬프트 캐싱으로 줄 수 있나요?
- 러너가 요청 본문을 남기게 하면 무엇이 좋아지나요? 남기면 그 파일에 아이 말이 쌓이는데, 그건 어디 두나요?

### 3. 낭독 요청 — 판정과 별개의 자리다

#### 확인된 것

`eval/bench_tts.py`로 **실제로 호출했다**(09-21). 요청 본문은 이렇다.

```json
{
  "model": "gpt-4o-mini-tts",
  "voice": "coral",
  "input": "공룡 나라구나! 공룡들이 사는 곳에 {주인공}이 갔어. 거기서 누굴 만났어?",
  "instructions": "여섯 살 또래 친구처럼, 높고 밝게. 또박또박, 조금 빠르게.",
  "response_format": "mp3"
}
```

| | |
|---|---|
| **나가는 것** | 마스코트가 말할 **문장 전문**. 그 안에 **아이가 한 말이 들어 있다** |
| 안 나가는 것 | 슬롯 상태 · 세션 id · 이력 · 음성 |

**리액션 6개는 미리 구워 앱에 넣으므로 나가지 않는다**(184KB). **본 대사와 책 낭독만 매번 나간다.**

#### 조건부 함의

**판정 요청과 낭독 요청은 따로 열어봐야 한다** — 멘토 검토 1절이 그렇게 적었고, 실제로 그렇다.
낭독 요청은 **상태를 안 보내는 대신 아이 말이 문장 안에 녹아서** 나간다. *"공룡 나라구나!"*의 「공룡 나라」가 아이가 한 말이다.

**그리고 OpenAI TTS 이용 정책이 AI 생성 음성임을 고지하도록 요구한다**(멘토 검토 4절). **화면에 그 고지가 없다.**

#### 확인되지 않은 것

책 낭독(6~8쪽)을 **한 번에 보내나 쪽마다 보내나.** 한 번에 보내면 **책 전문이 한 요청에 실린다.** 아직 구현이 없어서 정해지지 않았다.

#### 같이 생각해 볼 질문

- 낭독을 쪽 단위로 쪼개면 전송량이 아니라 **한 요청에 실리는 아이 말의 양**이 줄어듭니다. 그게 의미 있는 차이인가요?
- AI 음성 고지를 **아이와 부모에게 각각** 어떻게 하나요? 같은 방식이 맞나요?

### 4. 받아쓰기 요청 — 아직 자리가 안 정해졌다

#### 확인된 것

`backend/app/routers/stt.py`가 `UploadFile` 하나를 받는 모양이고 **본문은 `NotImplementedError`**다. 주석에 *"폰은 말소리 구간만 보낸다(Silero VAD) — 환각·값·지연을 한 번에 줄인다"*와 *"전사되는 즉시 음성을 지운다"*가 적혀 있다.

#### 조건부 함의

**자체 인프라로 가면** 음성이 우리 서버까지만 가고, **외부로 가면 음성 원본이 외부 처리자에게 간다.** 그리고 흐름도에서 **이름 가리기(③)가 받아쓰기(②) 뒤에 있으므로, 외부로 보낼 때는 실명이 실린 음성이 나간다.**

#### 확인되지 않은 것

어디서 돌릴지. 그리고 외부로 갈 경우 **VAD로 자른 조각이 몇 초짜리인지** — 조각이 짧으면 실린 내용도 적다.

#### 같이 생각해 볼 질문

- 외부로 보낸다면 **한 번에 보내는 조각의 길이**를 얼마로 하겠어요? 짧게 자르면 무엇을 잃나요?
- 음성에서 이름을 가리는 것이 가능한가요? 불가능하면 ②·③의 순서가 선택을 제한하나요?

## 조사 2 — 벤더 약관 매트릭스

조사 이종훈 · 멘토 검토(09-22) 「함께 해볼 조사 순서」 2번

**이 문서는 답이 아니라 빈 칸이다.** 멘토 검토 3절이 정정한 대로 **「아동 승인」이라는 하나의 승인은 없고**, 보존 통제 · 대상 연령 제한 · 보호자 동의가 **각각 따로** 걸린다. 그 셋을 벤더별로 나눠 놓으면 *"이 벤더는 되고 저 벤더는 안 된다"*가 아니라 ***"이 조건에서는"***이라고 말할 수 있게 된다. **아래 표에서 공개 문서로 채울 수 있는 칸은 채웠고, 계정 설정을 봐야 하는 칸은 「확인 필요」로 뒀다.**

---

### 이 조사의 범위

**근거로 쓴 것** — 멘토 검토 보고서(09-22)가 인용한 공개 정책 문서 목록, 우리 레포의 모델 카탈로그(`eval/model_catalog.json`)와 `.env` 키 이름.

**근거로 쓰지 않은 것** — **벤더 콘솔의 실제 설정.** 어느 조직·프로젝트에서 어느 엔드포인트를 부르고 있고 거기에 어떤 보존 조건이 걸려 있는지는 **로그인해서 봐야 한다.** 이 문서로는 알 수 없다.

**정책 문서는 멘토가 2026-09-22에 열람한 것을 그대로 인용한다.** 열람일이며 효력일이나 최신성을 보증하는 날짜가 아니고, **내가 직접 다시 열어본 것이 아니다.**

**따라서 이것은 준수 여부 판단이 아니라 「무엇을 확인하면 판단할 수 있는가」의 목록이다.**

---

### 1. 우리가 실제로 부르는 것

#### 확인된 것

레포에서 키를 읽는 곳과 카탈로그에 올라간 후보다.

| 자리 | 벤더 | 모델 | 키 이름 | 상태 |
|---|---|---|---|---|
| **판정 · 생성** | OpenAI | `gpt-5.6-luna` | `OPENAI_API_KEY` | **쓰는 중** (09-20 확정) |
| 판정 (대안) | Anthropic | `claude-haiku-4-5` | `ANTHROPIC_API_KEY` | 측정 완료 · 값 7배로 보류 |
| 판정 (평가 중) | TypeSafe | `jev-latest` | `TYPESAFE_API_KEY` | 09-22 측정 · 8필드 89.6% |

#### 조건부 함의

**판정과 낭독이 같은 키를 쓴다.** `OPENAI_API_KEY` 하나로 두 엔드포인트를 부른다. 그래서 **어느 조직·프로젝트에 어떤 보존 조건이 걸려 있는지는 두 요청에 똑같이 적용된다** — 나누고 싶으면 키를 나눠야 한다.

**Jev가 후보에 들어온 것이 이 표를 하나 늘렸다.** 벤더가 넷이 되면 **약관을 넷 다 읽어야 한다.** 멘토 검토의 교훈이 *"한 벤더에서 읽은 문장을 다른 벤더에 옮겨 붙이지 않는다"*였다.

#### 확인되지 않은 것

- **어느 조직·프로젝트의 키인가.** 학원 계정인지 개인 계정인지, 조직 안에 프로젝트가 나뉘어 있는지
- **TypeSafe 약관은 아무도 안 읽었다.** 오늘 후보에 넣었고 `legal/terms`·`legal/privacy-policy` 링크만 확인했다

#### 같이 생각해 볼 질문

- 판정과 낭독의 키를 나누면 무엇이 좋아지나요? 조건을 따로 걸 수 있는 것 말고 또 있나요?
- 벤더가 넷이면 **어느 하나가 조건을 바꿨을 때 그걸 무엇으로 알게 되나요?** 알아채는 장치가 설계 안에 있나요?

### 2. 세 칸으로 나눈 매트릭스

#### 확인된 것 (공개 문서 — 멘토 인용)

| | **① 보존 통제** | **② 대상 연령 제한** | **③ 보호자 동의** |
|---|---|---|---|
| **OpenAI** | ZDR은 **데이터 보존에 대한 통제**이지 아동 서비스 승인이 아니다 | under-18 가이던스: **만 13세 미만 개인정보 처리 전에 ZDR을 먼저 구현**하라고 안내 | **서비스 계약 §3.3(c)** — 보호자 동의 없이 미성년 이용을 허용하는 것을 금지 |
| **Anthropic** | ZDR 정책 문서가 **따로** 있다 | 미성년 대상 조직 가이드라인이 **따로** 있다 | 확인한 범위에서 확인되지 않음 |
| **Google (Gemini)** | 확인한 범위에서 확인되지 않음 | **표준 Developer API 약관이 만 18세 미만 대상 클라이언트를 제한** | 〃 |
| **TypeSafe** | **보존 기간 명시 없음** — *"서비스 제공에 합리적으로 필요한 기간"*. **ZDR 같은 무보존 옵션이 문서에 없다.** 단 **Input으로 학습·파인튜닝하지 않는다**고 두 번 명시 | ⚠️ **개인정보 정책이 만 18세 미만을 배제한다** — 아래 §2-1 | 약관·정책에 **보호자 동의 조항이 없다** |

⚠️ **「아동 승인 = ZDR」이라는 보편적 등가는 없다.** Anthropic의 경우 두 문서가 별개이고, 멘토가 확인한 범위에서 그 등가를 뒷받침하는 근거가 확인되지 않았다 — **없다고 확정한 것이 아니라 확인되지 않았다는 뜻이다.**

⚠️ **Gemini에 대해 "승인 경로가 존재하지 않는다"고 단정하면 확인된 범위를 넘는다.** 정확한 서술은 *"현재 표준 약관이 이 대상군을 제한한다"*이고, 검토된 조항 안에서 예외 절차가 확인되지 않았다는 것까지다.

#### 2-1. ⚠️ TypeSafe — 약관은 조용한데 개인정보 정책이 막는다 (09-22 읽음)

**약관에는 나이 조항이 아예 없다.** 연령 제한도, 아동 조항도, 규제 분야 제한도 없다. 처음엔 *"제한이 없으니 괜찮다"*로 읽힐 수 있다.

**그런데 개인정보 정책에 이렇게 적혀 있다.**

> *"We do not knowingly collect, maintain, or use personal data from children under 18 years of age, and **no part of the Services is directed to children**."*

**우리 앱은 만 3~7세 대상이고, 아이가 한 말을 이 API로 보낸다.** 정면으로 부딪히는 문장이다.

**다만 단정하면 안 된다.** 정확히 읽으면 두 갈래가 있다.

| 읽는 방법 | 그러면 |
|---|---|
| **① 자기 사이트 이용자(개발자)에 대한 진술** | 우리가 보내는 것은 **최종 사용자 데이터 = `Input`**이고, Input에는 별도 조항이 걸린다 |
| **② 서비스 전반에 대한 선언** | 아동 대상 제품에서 쓰는 것 자체가 정책과 어긋난다 |

**Input 조항은 오히려 좋다** — *"(1) Input으로 어떤 AI·ML 모델도 학습·파인튜닝하지 않고 (2) 서비스 제공자 외 제3자에게 Input을 공개하지 않는다"*를 **두 번** 명시한다.

→ **①과 ②가 어디까지 겹치는지는 확인한 범위에서 확인되지 않았다.** 없다고 확정한 것이 아니다.

**그리고 OpenAI와 비교하면 차이가 분명하다.**

| | 아동 대상 사용 경로 |
|---|---|
| **OpenAI** | **경로가 문서화돼 있다** — under-18 가이던스 + 13세 미만은 ZDR 먼저 |
| **TypeSafe** | **경로가 문서에 없다.** 정책이 18세 미만을 배제한다 |

⚠️ **「나이 조항이 없다」가 「써도 된다」가 아니었다.** 오히려 OpenAI가 **길을 열어 둔 쪽**이고 TypeSafe는 **길이 문서에 없는 쪽**이다. 처음 인상과 반대다.

**그 밖에 걸리는 것 둘**
- **책임 한도가 $100 USD**다. 아동 데이터를 다루는 서비스에서 이 숫자는 작다
- **미국 호스팅**이고 하위 처리자 목록이 상세하지 않다

#### 해야 할 일 — 물어보는 것

**`privacy@typesafe.ai`에 세 줄을 물으면 된다.** 지금은 후보일 뿐이라 급하지 않지만, **쓰기로 정하기 전에는 반드시 답을 받아야 한다.**

1. 아동 대상(만 3~7세) 제품의 최종 사용자 발화를 `Input`으로 보내는 것이 정책상 허용되는가
2. `Input`의 **보존 기간**은 얼마이고 무보존 설정이 있는가
3. 만 13세 미만 개인정보가 `Input`에 포함될 경우 **별도 계약이나 절차**가 필요한가

### 2-2. 이 조사를 지금 다 해야 하나 — **아니다. 하나만 지금이다**

**둘로 갈린다.**

| | 언제 | 왜 |
|---|---|---|
| **TypeSafe 문의 한 통** | **지금** | 답이 며칠 걸리고, **Jev를 쓸지 정하는 입력값**이다. 5분이면 보낸다 |
| **OpenAI·Anthropic 콘솔 다섯 줄** | **다음 2주 시작 전** | **지금 아이 데이터가 밖으로 안 나간다** — 시연이 대본이고 앱에 `INTERNET` 권한조차 없다 |

**콘솔을 미뤄도 되는 근거가 분명하다.** ZDR이 필요한 이유는 *"만 13세 미만 개인정보를 처리하기 전에"*인데, **지금은 처리하지 않는다.** 실제 연결을 붙이는 날이 그 「전」이다.

⚠️ **미루는 것과 잊는 것은 다르다.** 다음 2주의 첫 커밋이 `INTERNET` 권한과 네트워크 계층인데,
**그 커밋 전에 콘솔을 봐야 한다.** `guidelines/9`의 조장 항목에 그 순서로 걸어 둔다.

**다음 멘토링에서는 「아직 안 봤다」가 답이 된다** — 멘토가 *"완성된 구현이 아니라 스케치로 충분하다"*고
했으므로. 단 **왜 안 봤는지**를 같이 말한다: *"지금은 대본이라 아이 데이터가 안 나갑니다. 실제 연결 전에 봅니다."*

#### 확인되지 않은 것 — **계정 설정을 봐야 채워지는 칸**

| 확인할 것 | 어디서 | 왜 |
|---|---|---|
| 조직 id · 프로젝트 id | 벤더 콘솔 | 조건이 조직/프로젝트 단위로 걸린다 |
| **호출 중인 엔드포인트 목록** | 콘솔 사용 기록 | 판정·낭독 말고 더 있나 |

| 계정에 적용된 서비스 이용 계약 버전 | 계정 문서 | 엔드포인트 조건과 **별개**로 걸린다 |
| 학원 계정인지 개인 계정인지 | — | 계약 주체가 다르다 |

**이 다섯 줄이 조사 2번의 실제 산출물이다.** 콘솔에 들어가서 채우면 된다.

#### 같이 생각해 볼 질문

- 세 칸 중 **지금 어느 칸이 채워져 있고 어느 칸이 비어 있나요?** 우리 경우 ①②③ 전부 비어 있는 것 아닌가요?

## 조사 3 — 수명주기와 동의·열람·삭제 스케치

조사 이종훈 · 멘토 검토(09-22) 「함께 해볼 조사 순서」 3번

**지금 저장이 아무것도 없다.** `SharedPreferences`·`DataStore`·`Room` 어느 것도 없고 세션이 끝나면 전부 사라진다. 그래서 보존 기간도 삭제 경로도 **없는 것이 아니라 대상이 없다.** 이게 이 조사에서 가장 중요한 사실인데, **뒤집어 보면 지금이 수명주기를 설계하기 가장 쉬운 시점**이다 — 이미 쌓인 데이터를 어떻게 처리할지 고민할 필요가 없다. 그리고 **저장은 곧 붙는다** — 책장·체크포인트 DB가 9/18 멘토 지시로 범위에 들어왔다. **저장을 붙이는 커밋과 수명주기를 정하는 커밋이 같아야 한다.**

---

### 이 조사의 범위

**근거로 쓴 것** — 앱 전체 grep(저장 관련 API 부재 확인) · `demo/Model.kt` `resetStory()`/`reset()` · `ui/Parent.kt`의 열람·삭제 버튼 상태 · `guidelines/3_API_명세.md` §3-5(책장·체크포인트) · 멘토 검토 4절.

**근거로 쓰지 않은 것** — 법률 자문. 개인정보 보호법 제22조의2 인용은 멘토 검토가 인용한 범위이고 **조문을 직접 해석한 것이 아니다.**

**따라서 이것은 구현 계획이 아니라 스케치다.** 멘토도 *"완성된 구현이 아니라 스케치로 충분하다"*고 적었다.

---

### 1. 지금의 수명주기 — 없다

#### 확인된 것

| 무엇 | 어디 있나 | 언제 사라지나 |
|---|---|---|
| 음성 원본 | 폰 (VAD가 자른 조각) | **전사 직후** — 설계상. 구현은 아직 |
| 전사 텍스트 | `DemoState`(메모리) | **이야기를 새로 시작하면** (`resetStory()`) |
| 아이가 한 말 인용 | `s.quotes`(메모리) | 〃 |
| 수준 신호 | `s.signals`(메모리) | 〃 |
| 이벤트 기록 | `s.events` — **60개 링 버퍼** | 61번째가 들어오면 앞이 밀려 나간다 |
| 턴 기록 | `s.notes`(메모리) | 〃 |
| 그림 | `res/drawable/`의 미리 만든 PNG | 앱을 지울 때 |
| 세션 id | **없다** | — |

**앱을 끄면 전부 사라진다.** 부모 리포트가 보여주는 것은 **지금 메모리에 있는 이야기 하나**뿐이다.

#### 조건부 함의

**그래서 「보호자 열람·정정·삭제」가 지금은 대상이 없다.** `ui/Parent.kt`의 내려받기·삭제 버튼이 `.alpha(0.5f)`로 흐려져 있고 *"데모에서는 누를 수 없어요"*라고 적혀 있는데, **그게 맞다** — 지울 것이 없다.

**그런데 `Parent.kt`에 「지난번」 비교 막대가 문자열 상수로 박혀 있다.** *"지난번 「바다」 한 낱말"*이 하드코딩이다. **기록이 없는데 기록이 있는 것처럼 보이는 화면**이다. 이건 저장이 붙기 전에 지워야 한다 — 저장이 붙으면 진짜 값이 들어가지만, 그 전까지는 **거짓을 보여주고 있다.**

#### 확인되지 않은 것

- 음성 삭제가 **실제로 언제** 일어나는지 — `/stt`가 미구현이라 코드가 없다
- `s.events`가 60개를 넘겨 밀려 나가는 것이 **의도된 보존 정책인지 그냥 데모 편의인지** — `Director.kt:135`에 상한만 있고 이유가 안 적혀 있다

#### 같이 생각해 볼 질문

- 60개 링 버퍼가 제품에서도 맞나요? 한 권이 19턴이면 이벤트가 몇 개 생기나요?
- 「지난번」 막대를 지금 지울까요, 저장이 붙을 때까지 두고 **화면에 「데모」 표시만 할까요?**

---

### 2. 저장이 붙으면 — 정해야 하는 것 여섯

#### 확인된 것

`guidelines/3_API_명세.md` §3-5에 **책장·체크포인트 DB/API**가 범위에 들어와 있다. **기기 식별키로 시작하고 구글 로그인은 나중에 얹는다**고 적혀 있다.

#### 조건부 함의

**기기 식별키가 들어오는 순간 이 문서의 성격이 바뀐다.** 지금은 아무것도 한 아이에게 묶이지 않는데, 식별키가 생기면 **그 키로 쌓인 것이 한 아이의 기록**이 된다. 그때 여섯 개가 동시에 정해져야 한다.

| | 정할 것 | 지금 기울어진 쪽 |
|---|---|---|
| **① 무엇을 저장하나** | 책 · 아이 말 인용 · 횟수 · 수준 신호 | **음성은 저장하지 않는다**(규칙) |
| **② 얼마나 두나** | 책은 오래, 원문 인용은? | 확인 필요 |
| **③ 어떻게 지우나** | 부모가 누르면 무엇이 지워지나 | 확인 필요 |
| **④ 누가 보나** | 부모 모드 PIN 뒤 | PIN은 있다. **데모에서는 아무 4자리나 통과**한다 |
| **⑤ 동의를 어떻게 받나** | 만 14세 미만 법정대리인 동의 + **그 사실의 확인** | 확인 필요 |
| **⑥ 무엇을 남겨야 「확인됐다」고 말할 수 있나** | ← **멘토가 짚은 핵심** | 확인 필요 |

**⑥이 가장 어렵다.** 멘토 질문을 그대로 옮기면 — *"화면에 체크박스가 있었다는 것과 확인되었다는 것 사이의 거리는 얼마나 되나요?"*

#### 확인되지 않은 것

- 기기 식별키가 **언제** 들어오는지 — 다음 2주 안인지
- 책을 서버에 두나 폰에 두나. `guidelines/3` §3-5가 DB/API라고 했으니 서버일 텐데, 그러면 **아이 말 원문이 우리 서버에 쌓인다**
- **아이가 만 13세가 되는 순간** 조건이 달라지는지 — 멘토가 질문으로 남긴 것이다

#### 같이 생각해 볼 질문

- 책은 남기고 **원문 인용만 짧게 두는 것**이 가능한가요? 그러면 부모 리포트의 「같은 질문 비교」가 성립하나요?
- 부모가 *"전부 지워 주세요"*라고 하면 **무엇까지 지워지나요?** 책도 지워지나요?
- 동의를 **누구에게, 언제** 받나요? 첫 실행인가요, 부모 모드에 처음 들어갈 때인가요?

---

### 3. 지금 할 수 있는 것 — 세 줄

#### 확인된 것

저장이 없어도 **지금 붙일 수 있는 것이 셋 있다.** 셋 다 화면 하나거나 문장 하나다.

| | 무엇 | 왜 지금 |
|---|---|---|
| **AI 음성 고지** | *"마스코트 목소리는 컴퓨터가 만든 소리예요"* | **OpenAI TTS 이용 정책이 요구한다**(멘토 4절). 저장과 무관하다 |
| **「지난번」 막대 정리** | 하드코딩을 지우거나 「데모」 표시 | 기록 없이 기록을 보여주고 있다 |
| **동의 화면 자리** | 첫 실행에 한 장 | 문구는 나중에. **자리를 비워 두면 나중에 끼우기 쉽다** |

#### 조건부 함의

**AI 음성 고지는 아이와 부모에게 다르게 해야 한다.** 다섯 살에게 *"AI가 생성한 음성입니다"*는 전달되지 않는다. 멘토가 그 질문을 따로 남겼다 — *"두 대상에게 같은 방식이 맞을까요?"*

→ 기울어진 쪽: **아이에게는 마스코트가 자기 입으로** (*"내 목소리는 컴퓨터가 만들어 줬어!"*), **부모에게는 부모 모드 설정에 한 줄.**

#### 확인되지 않은 것

고지를 **어디에** 두어야 정책 요구를 충족하는지. 정책 문구를 직접 읽어야 한다 — **나는 멘토 인용만 봤다.**

#### 같이 생각해 볼 질문

- 마스코트가 자기 입으로 말하는 것이 고지로 인정되나요? 어디까지가 고지인가요?
- 동의 화면을 미리 비워 두면 **나중에 끼울 때 무엇이 쉬워지나요?** 지금 만들면 오히려 틀린 자리에 박히나요?

**정했다**
- **저장이 없으므로 보존·삭제는 대상이 없다.** 그게 지금 정직한 상태다
- **저장을 붙이는 커밋과 수명주기를 정하는 커밋이 같아야 한다.** 나중에 붙이면 이미 쌓인 데이터를 처리해야 한다
- 지금 할 수 있는 셋 — **AI 음성 고지 · 「지난번」 막대 정리 · 동의 화면 자리**

**안 정했다**
- 여섯 개 전부. 특히 **⑥「무엇을 남겨야 확인됐다고 말할 수 있나」**
- 책을 폰에 두나 서버에 두나 — 이게 나머지를 다 바꾼다

## 조사 4 — 아이 말·부모 말·AI가 더한 말을 화면에서 구분하기

조사 이종훈 · 멘토 검토(09-22) 「함께 해볼 조사 순서」 4번

**데이터는 이미 다 있고, 화면에만 없다.** 출처(`by`)는 칸마다 저장되고 있고(`slotBy`), 협업 모드는 쪽마다 누가 지었는지까지 남긴다(`author`). **그런데 그 정보가 나오는 화면이 셋 중 하나뿐이다** — 책의 협업 모드 아이콘. 개발자용 데모 서랍에는 `[by: mascot]`이 찍히는데, **부모 모드에는 없다.** 즉 이 조사의 숙제는 *"무엇을 기록할까"*가 아니라 ***"이미 기록한 것을 어디에 어떻게 보일까"***다.

---

### 이 조사의 범위

**근거로 쓴 것** — `demo/Model.kt`(`slotBy`·`author`) · `demo/DiaryScenes.kt` `setDiarySlot()` · `demo/CoopScenes.kt` `pageAuthor()` · `ui/Book.kt:296` · `ui/Screen.kt:1032` · `ui/Parent.kt` · `guidelines/2_공통_데이터_모델.md` §1-4.

**근거로 쓰지 않은 것** — 아이나 부모에게 보여준 적이 없다. **읽히는지는 안 봤다.**

**따라서 이것은 화면 스케치이고, 만드는 것은 진웅님이다** — 설계와 구현을 나눠 갖기로 했다(`guidelines/9` §9-5).

---

### 1. 이미 기록되고 있는 것

#### 확인된 것

| 저장되는 것 | 어디에 | 값 |
|---|---|---|
| **칸을 누가 채웠나** | `s.slotBy[bookKey]` | `child` · `card` · `mascot` |
| **쪽을 누가 지었나** (협업) | `s.author[slot]` | `child` · `adult` |
| 아이 말 원문 | `s.quotes` | 아이가 한 말 그대로 |
| 마스코트가 메운 칸 | `slotBy == "mascot"` | 빈 칸을 이야기로 메울 때 기록 |

`DiaryScenes.kt:84-85`가 칸을 채울 때마다 둘을 같이 쓴다. **빠뜨리는 자리가 없다.**

#### 조건부 함의

**규칙 5가 요구하는 것은 이미 지켜지고 있다** — *"아이가 한 말과 우리가 채운 말이 섞이면 부모 리포트가 거짓말을 시작한다."* 섞이지 않게 저장은 되고 있다.

**그런데 멘토가 지적한 것은 저장이 아니라 「결과물에서 구분되는가」다.** 그건 화면 문제다.

#### 확인되지 않은 것

`slotBy`에 `adult`가 들어가는 자리가 있는지. 규칙 5의 `by` 3종은 `child`·`card`·`mascot`이고 **어른은 없다.** 협업 모드는 `author`라는 **별도 맵**에 `adult`를 쓴다 — 두 맵이 서로 모른다.

#### 같이 생각해 볼 질문

- `slotBy`와 `author`를 하나로 합칠까요, 따로 둘까요? 따로 두면 화면이 두 곳을 봐야 합니다
- `by`에 `adult`를 넣으면 규칙 5의 3종이 4종이 됩니다. **그게 규칙을 어기는 건가요, 규칙이 낡은 건가요?**

### 2. 지금 보이는 곳과 안 보이는 곳

#### 확인된 것

| 화면 | 출처가 보이나 |
|---|---|
| **책** (`ui/Book.kt:296`) | **협업 모드만** — 쪽마다 🧒/🧑 아이콘 하나. 숫자도 순위도 없다 |
| **데모 서랍** (`ui/Screen.kt:1032`) | **보인다** — `[by: mascot]`이 칸마다. 색까지 다르게 |
| **부모 모드** (`ui/Parent.kt`) | **안 보인다** |
| 동화·일기 모드의 책 | **안 보인다** — 협업일 때만 아이콘이 뜬다 |

⚠️ **개발자용 화면에는 보이고 부모용 화면에는 안 보인다.** 정확히 거꾸로다 — 이 구분이 필요한 사람은 부모다.

#### 조건부 함의

**책에서의 구분과 리포트에서의 구분은 목적이 다르다.**

| | 목적 | 어떻게 |
|---|---|---|
| **책** | 아이가 자기 말을 알아보게 | **약하게.** 아이콘 하나. 채점처럼 보이면 안 된다 |
| **부모 리포트** | *"아이가 한 말 그대로"*라는 약속을 눈으로 확인하게 | **분명하게.** 아이 말과 우리가 메운 말이 갈려야 한다 |

책 쪽은 이미 답이 있다 — 협업 모드 아이콘을 **모든 모드로 넓히면 된다.** 마스코트가 메운 쪽에는 🗣 하나.

**리포트 쪽이 실제 숙제다.** 지금 `Parent.kt`가 인용을 보여주는데 **그게 아이 말인지 마스코트가 메운 말인지 구분이 없다.** 규칙 5는 *"`mascot`은 리포트 인용에서 빠진다"*고 정했으니 **빠지는 것이 맞는데, 빠졌다는 사실이 화면에 안 보인다.**

#### 확인된 것 하나 더 — **마스코트 말은 걸러진다**

처음에 *"`Parent.kt`가 `s.quotes`를 그대로 쓰고 `slotBy`를 안 보므로 규칙 5 위반일 수 있다"*고 적었다가 **코드를 따라가 보니 아니었다.**

`quotes`에 넣는 곳은 **한 군데뿐**이고(`StoryBank.kt:770` `judge()` 안), 그 앞줄이 이렇다.

```kotlin
val a = (r as? Reply.Spoke)?.answer   // ← 말로 한 답만
…
if (a != null) quote(a.text)
```

마스코트가 고른 것은 `Reply.Tapped`이므로 **`a`가 `null`이고 `quote()`가 불리지 않는다.**
→ **리포트 인용에 마스코트 말이 섞이지 않는다.** 규칙 5가 지켜지고 있다.

⚠️ 다만 **카드로 고른 것(`Reply.Tapped` · `byMascot`이 아닌 것)도 `a`가 `null`**이라 인용에서 빠진다.
규칙 5의 표는 `card`를 *"리포트 원문 인용 ❌"*로 정했으니 **이것도 맞다.**

#### 확인되지 않은 것

**`quotes`에 아무 표시가 없다.** 지금은 "말로 한 답"만 들어가서 결과적으로 맞는데, **그 필터가 `judge()` 안쪽 한 줄에 숨어 있다.** 누가 나중에 `quote()`를 다른 데서 부르면 조용히 깨진다 — **테스트가 없다.**

#### 같이 생각해 볼 질문

- 아이에게도 구분이 보여야 할까요? 다섯 살이 *"이건 마스코트가 지어낸 거야"*를 알아야 하나요?
- 마스코트가 메운 칸이 많은 세션에서, 부모에게 **몇 개를 메웠다고 알릴까요?** 규칙 9가 점수를 금지하는데 그 숫자는 점수인가요?

### 3. 스케치 — 세 화면

#### 확인된 것

지금 자산으로 만들 수 있는 것만 적는다. `mk_child`·`mk_parent` 아이콘은 이미 있다(`ui/Book.kt:300`).

**① 책 — 지금 것을 넓히기**

```
 [🧒]  공룡 나라에 갔어요.            ← 아이가 채운 쪽
 [🧑]  아빠가 "조심해" 했어요.         ← 어른이 채운 쪽 (협업)
 [🗣]  그렇게 하루가 저물었어요.       ← 마스코트가 메운 쪽
```

아이콘 하나. **글자를 더하지 않는다.** 협업 모드에서 이미 이렇게 돌고 있다.

**② 부모 리포트 — 인용 옆에 표시**

```
오늘 아이가 한 말

  "무서워서 도망갔어."            🧒 아이가 한 말
  "뿌뿌도 데려갈 거야."           🧒
  ─────────────────────────
  "그렇게 하루가 저물었어요."      🗣 이야기를 메운 문장
                                    (아이가 한 말이 아닙니다)
```

**선 하나로 가른다.** 아래쪽에 *"아이가 한 말이 아닙니다"*를 한 번만 적는다.

**③ 부모 모드 설정 — 한 줄**

```
  이 책에서 아이가 직접 말한 것은 ●●●●●○○  (7칸 중 5칸)
  나머지는 마스코트가 이야기로 메웠습니다.
```

⚠️ **이 줄이 위험하다.** 규칙 9가 점수·등급을 금지한다. **5/7이 점수로 읽히면 안 된다.** 그래서 *"아이가 못 했다"*가 아니라 *"우리가 메웠다"*로 쓴다 — 주어가 우리여야 한다.

#### 조건부 함의

**③이 필요한 이유는 정직함이다.** 부모 리포트가 *"오늘 아이가 한 말 그대로"*를 팔고 있으니, **얼마가 아이 말이 아닌지도 말해야** 그 약속이 성립한다.

**다만 그게 아이 평가로 뒤집히면 규칙 9를 어긴다.** 안전한 쪽으로 기울이면 — **③을 부모 모드 첫 화면이 아니라 설정 안쪽에 두고**, 기본은 ②만 보이게 한다.

#### 확인되지 않은 것

- **읽히는지.** 아이콘 하나로 *"이건 AI가 더했다"*가 전달되는지 본 적이 없다
- ③을 **부모가 보고 싶어 하는지.** 보여주면 오히려 불안해할 수도 있다

#### 같이 생각해 볼 질문

- ③의 주어를 우리로 바꾸면 정말 점수로 안 읽히나요? 부모는 숫자를 보면 세지 않나요?
- ②의 선 하나로 충분한가요, 아니면 색이나 글꼴이 달라야 하나요?

---

### 이 조사가 정한 것 / 안 정한 것

**정했다**
- **데이터는 다 있다.** 숙제는 화면이다
- **책은 지금 협업 모드 방식을 모든 모드로 넓히면 된다** — 새로 만들 게 없다
- 리포트는 **선 하나로 가르고 아래에 한 줄** 적는다
- ③(얼마가 아이 말인지)은 **주어를 우리로 쓰고 설정 안쪽에 둔다**

**안 정했다**
- `slotBy`와 `author` 두 맵을 합칠지
- `by` 3종에 `adult`를 넣을지 — 규칙 5를 건드리는 판단
- ⚠️ **인용 필터에 테스트가 없다.** `quote()`를 다른 데서 부르면 마스코트 말이 리포트에 섞이고 **조용히 깨진다.** 규칙 5가 *"섞이면 부모 리포트가 거짓말을 시작한다"*고 한 그 자리인데 **지키는 장치가 관례뿐이다**

## 조사 5 — 모드별 평가 케이스와 수용 기준

조사 이종훈 · 멘토 검토(09-22) 「함께 해볼 조사 순서」 5번

**지금 평가셋 100문항은 동화 모드 전용이다.** 멘토 검토 5절이 정정한 대로 **출력 필드가 같다는 것이 평가를 덮는다는 증거가 되지 않는다** — 같은 모양을 내는 두 모드가 전혀 다르게 실패할 수 있다. 실제로 확인해 보니 100문항 중 **일기·협업 모드에서만 나는 실패를 짚는 문항은 0개**다. 그래서 이 조사의 산출물은 **더할 케이스 네 묶음과, 각 묶음이 무엇을 넘으면 통과인가**다.

---

### 이 조사의 범위

**근거로 쓴 것** — `eval/fixtures_judge.jsonl` 100문항 전수(`type` 분포 확인) · `eval/평가셋_라벨링_지침.md` · `docs/일기모드_설계.md` · `docs/부모협업모드_설계.md` · `guidelines/6` §6-4 합격선 표 · 멘토 검토 5절.

**근거로 쓰지 않은 것** — **새 케이스를 실제로 돌려 본 것.** 아래 네 묶음은 **제안이고, 아직 라벨이 없다.**

**따라서 이것은 측정 결과가 아니라 무엇을 측정해야 하는가의 목록이다.**

---

### 1. 지금 평가셋이 덮는 것

#### 확인된 것

100문항이 동화 모드 흐름(장소 → 사건 → 까닭 → 해결)을 전제한다. `type` 라벨이 이렇게 갈린다.

| 무엇을 짚나 | 모드 의존 |
|---|---|
| 다중 채움 (한 번에 두 칸) | 모드 무관 |
| 필수 해제 (`no_longer_needed`) | 모드 무관 |
| 모순 (앞말과 어긋남) | 모드 무관 |
| 까닭 신호 · 덧붙임 신호 | 모드 무관 |
| 알아들을 수 없음 | 모드 무관 |
| **일기 모드 고유 실패** | **0개** |
| **협업 모드 고유 실패** | **0개** |

#### 조건부 함의

**모드 무관 항목이 많은 것은 좋은 설계의 결과다** — 일기·협업이 **같은 슬롯 12종**을 쓰기로 했으므로 판정 자체는 공유된다. 기존 100문항을 버릴 이유가 없다.

**그런데 「같은 판정을 쓴다」와 「같은 방식으로 실패한다」는 다른 말이다.** 예를 들어 *"아무 말도 안 했을 때"*는 세 모드에서 결과가 전혀 다르다.

| | 아이가 아무 말도 안 하면 |
|---|---|
| **동화** | 마스코트가 대신 고른다. **무해하다 — 지어낸 이야기다** |
| **일기** | 마스코트가 대신 고르면 **아이가 하지 않은 일이 하루로 적힌다** |
| **협업** | 부모가 다시 묻는다. **AI가 끼어들 이유가 없다** |

**같은 입력, 같은 출력 필드, 전혀 다른 실패.** 멘토 지적이 정확히 이 지점이다.

#### 확인되지 않은 것

기존 100문항 중 **일기 모드에서 돌리면 다른 답이 정답이 되는 문항이 몇 개인지.** 세어 보지 않았다 — 세면 *"재사용 가능한 것"*과 *"모드별로 갈라야 하는 것"*이 나뉜다.

#### 같이 생각해 볼 질문

- 100문항을 일기 모드 프롬프트로 돌리면 **gold 가 그대로 유효한 문항은 몇 개**인가요?
- 모드별로 갈라야 하는 문항은 **문항을 복제해 gold 만 바꾸나요, 새로 쓰나요?**

### 2. 더할 케이스 네 묶음

#### 확인된 것

멘토가 제시한 네 가지가 우리 설계 문서의 미결 항목과 정확히 겹친다.

| | 케이스 | 어느 모드 | 우리 문서의 근거 |
|---|---|---|---|
| **A** | 아이가 아무 말도 안 할 때 **일기의 사실을 지어내지 않는가** | 일기 | `일기모드_설계.md` §3 *"아이가 하지 않은 일이 하루로 적힌다"* |
| **B** | 부모가 말했을 때 **화자 귀속이 맞는가** | 협업 | `부모협업모드_설계.md` §4-1 `speaker: adult` |
| **C** | 아이가 **걱정스러운 실제 이야기**를 꺼냈을 때 창작을 이어가기 전에 다뤄지는가 | 일기 · 협업 | 규칙 7 *"과차단이 더 위험하다"*와 **정면으로 당긴다** |
| **D** | 아이 말·부모 말·AI가 더한 말이 **결과물에서 구분되는가** | 전부 | 규칙 5 · **§4** |

#### 조건부 함의

**C가 가장 어렵다.** 규칙 7은 *무섭다·괴물·싸웠다·울었다*를 **이야기의 재료**로 보고 과차단을 경계한다. 그런데 **일기 모드에서는 그게 실제로 있었던 일**이다. 동화에서 *"괴물이 무서웠어"*는 상상이고, 일기에서 *"아빠가 소리질렀어"*는 사실이다.

→ **같은 낱말이 모드에 따라 다르게 다뤄져야 한다.** 이건 필터 문제가 아니라 **모드가 필터에 맥락을 줘야 한다**는 뜻이고, 지금 설계에 그 자리가 없다.

**D는 판정 평가가 아니라 화면 평가다.** 나머지 셋은 `eval/`에서 잴 수 있지만 D는 **사람이 화면을 보고 판정**해야 한다. 분리해야 한다.

#### 확인되지 않은 것

- **C의 합격선을 무엇으로 정하나.** *"적절히 다뤄졌다"*를 어떻게 채점하나 — 이게 이 조사에서 가장 안 풀린 것이다
- B를 지금 잴 수 있는지. **협업 모드에서 부모 발화가 판정에 들어가는지** 코드를 확인해야 한다

#### 같이 생각해 볼 질문

- C에서 *"적절히 다뤄졌다"*를 **모델이 무엇을 출력하면** 인정하나요? 새 필드가 필요한가요?
- A와 C 중 **지금 구현에서 통과하기 어려울 것 같은 것**은 무엇인가요? 그렇게 짐작하는 근거는요?
- D를 사람이 판정한다면 **몇 명이 보고 어떻게 합의**하나요? 기존 라벨링처럼 교차 검증하나요?

### 3. 수용 기준 — 무엇을 넘으면 통과인가

#### 확인된 것

`guinidelines/6` §6-4 합격선 표에 **`slot_1`·`next_slot` 칸이 비어 있다.** *"일부러 비어 있는 게 아니라 아직 못 정한 것"*이고, 네 모델이 0.43~0.66에 몰려 **선이 없으면 아무도 못 떨어뜨린다**고 적혀 있다.

#### 조건부 함의

**모드별 케이스는 정확도 기준이 아니라 「해서는 안 되는 일」 기준이 맞다.** 이유는 규칙 7·9와 같다 — 이 케이스들은 **틀리면 제품 약속이 깨지는 자리**이고, 그런 건 백분율로 재는 게 아니라 **0건**으로 재야 한다.

| | 기준 | 왜 0건인가 |
|---|---|---|
| **A** 없는 사실을 지어냄 | **0건** | 한 건이라도 나면 *"아이가 하지 않은 일이 하루로 적힌다"* |
| **B** 부모 말이 아이 말로 기록됨 | **0건** | 규칙 5 — *"리포트가 거짓말을 시작한다"* |
| **C** 걱정스러운 이야기를 무시하고 창작 진행 | **0건** | 아이 안전 |
| **C'** 과차단 (이야기 재료를 막음) | **≤ 5%** | 규칙 7이 *"놓치는 것보다 과차단이 위험하다"* |
| **D** 결과물에서 출처가 구분되지 않음 | **0건** | 규칙 5 |

⚠️ **C와 C'가 서로를 당긴다.** 걱정스러운 것을 놓치지 않으려면 조이고, 과차단을 막으려면 풀어야 한다. **둘을 같은 케이스로 묶으면 어느 쪽으로 튜닝했는지 모른다** — 따로 센다.

#### 확인되지 않은 것

**C'의 5%가 어디서 나온 숫자인가.** 내가 지금 쓴 것이고 근거가 없다. **비워 두는 게 정직하다** — 라벨링을 해 보고 실제 분포를 봐야 정해진다.

⚠️ **그리고 이 다섯 줄은 아직 `guidelines/6` §6-4에 안 들어갔다.** 넣기 전에 팀 합의가 필요하다 — 합격선은 한 사람이 정하는 것이 아니다.

#### 같이 생각해 볼 질문

- 0건 기준이 넷이면 **하나라도 걸리면 출시를 막나요?** 부트캠프 프로젝트에서 그 선이 현실적인가요?
- C'를 5%로 둘 근거를 어떻게 만드나요? **라벨링을 몇 건 해야** 분포가 보이나요?

### 4. 무엇부터 — 케이스 20건

#### 확인된 것

기존 100문항이 **손으로 쓴 것(`origin: handwritten`)과 픽스처 생성기로 만든 것**이 섞여 있고, 팀이 나눠 라벨링하고 **교차 검증**했다(치영님 20건 · 진웅님 100건 · Claude 20건).

#### 조건부 함의

#### 확인되지 않은 것

**누가 라벨링하나.** 기존처럼 나눠 하면 교차 검증까지 사람이 셋 필요한데, 오늘 세 사람이 각자 모드를 맡고 있다.

#### 같이 생각해 볼 질문

- 교차 검증을 생략하고 한 사람이 쓰면 무엇을 잃나요?

## 조사 6 — 정정된 연구 요약과 자기 맥락 실험 계획

조사 이종훈 · 멘토 검토(09-22) 「함께 해볼 조사 순서」 6번

**멘토가 정정을 요청한 지표는 화자 분리 DER인데, 그 기능이 09-22 설계 변경으로 범위에서 빠졌다.** 그래서 이 조사는 두 조각이 된다 — **① 인용 정정은 그대로 한다**(문서에 남아 있고, 잘못 옮긴 서술이 재인용될 수 있다). **② 「자기 맥락에서 직접 재라」는 지적은 대상을 옮긴다.** 지금 우리 맥락에서 남의 수치를 근거로 쓰고 있는 자리는 화자 분리가 아니라 **아이 음성 받아쓰기**다. 그것이 이 문서의 실험 계획이다.

---

### 이 조사의 범위

**근거로 쓴 것** — 멘토 검토 보고서 6절 · `eval/results.md`의 DER 항목(09-21 기록과 09-22 취소선) · `guidelines/6` §6-3 막고 있는 것 · `eval/stt_eval.py`(치영님이 만든 것).

**근거로 쓰지 않은 것** — **원 논문을 직접 다시 읽지 않았다.** 아래 정정은 멘토가 인용한 범위(III-A2·IV-B절)를 그대로 옮긴 것이다. 그리고 **아이 음성을 아직 한 건도 재지 않았다.**

**따라서 ①은 정정의 정리이고 ②는 계획이며, 둘 다 새 측정이 아니다.**

### 1. 정정 — DER을 「셋에 하나」로 옮긴 것이 틀렸다

#### 확인된 정정

우리가 쓴 서술: *"한국어 엄마+아이에서 최고 모델이 셋에 하나를 틀린다"* (덱 18장 · `README` · `results.md`)

**틀린 이유가 셋이다.**

| | 우리가 쓴 것 | 실제 |
|---|---|---|
| **지표의 뜻** | 발화 세 개 중 하나가 틀림 | **DER은 기준 화자 시간 대비 누락·오검출·화자 혼동을 합산한 비율.** 분모가 발화 개수가 아니라 **시간**이고, 분자에 혼동 말고 **두 종류가 더** 있다 |
| **어느 모델** | (우리가 올린 pyannote 3.1인 것처럼 읽힘) | **33.04%를 낸 것은 NeMo SortFormer.** 우리가 올린 것은 pyannote 3.1 |
| **표본** | 53명 녹음 | **조건을 만족한 34개 녹음의 부분집합** |
| **과업** | 자유로운 부모-아동 대화 | **아동의 단어 반복 상호작용** |

#### 조건부 함의

**인용의 역할이 「근거」에서 「동기」로 바뀐다.** 다른 과업·다른 표본·다른 모델의 수치는 *"이 정도 어려운 문제다"*는 주지만 *"우리 앱에서 이만큼 틀린다"*는 예측이 못 된다.

**그리고 우리가 그 수치로 결정을 내린 적은 없다** — 확인해 보니 화자 분리는 *"자리는 확보했고 정확도는 이 숫자가 상한"*으로만 쓰였고, 그 위에 세운 판단이 없다. **다행이다.**

⚠️ **다만 어제 내가 문장만 다듬고 내용은 틀린 상태로 뒀다.** *"셋에 하나"* → *"세 번 중 한 번"*으로 고쳤는데, **표현이 어색한 것이 문제가 아니라 지표를 잘못 옮긴 것이 문제였다.** 멘토 지적을 받고서야 알았다.

#### 처리 상태

| 어디 | 상태 |
|---|---|
| `eval/results.md` | ✅ **취소선 + 정정 세 줄** (09-22) |
| `README.md` | ✅ *"우리 조건에서 아직 안 재봤다"*로 교체 |
| 발표 덱 | ✅ 화자 분리 장이 **통째로 빠졌다**(설계 변경) |
| `guidelines/` | 인용이 없다 — 확인함 |

#### 같이 생각해 볼 질문

- 남의 측정치를 인용할 때 **근거인지 동기인지 구분하는 기준**을 무엇으로 하겠어요? `guidelines/0`에 한 줄로 적을 수 있나요?
- 표현만 고치고 내용을 못 고친 일이 또 있을까요? **숫자를 인용한 자리를 전수로 훑어야** 하나요?

### 2. 대상 이동 — 지금 자기 맥락에서 재야 할 것은 받아쓰기다

#### 확인된 것

화자 분리는 09-22 설계 변경으로 빠졌다 — **아이가 혼자 쓰고, 부모는 질문을 미리 넣는다.** 그래서 *"화자 귀속"*은 화면이 알고 있고, 모델이 가릴 일이 없다.

**그런데 남의 수치를 근거로 쓰고 있는 자리가 하나 남아 있다.**

> *"어른 모사로는 순위가 안 나온다 — **성인 7.8% vs 아동 120.8%**"* (`guidelines/6` §6-3)

이 숫자가 **받아쓰기 모델 선정 전체를 막고 있는 근거**다. 그리고 **우리가 잰 것이 아니다.**

#### 조건부 함의

**멘토 6절의 교훈이 여기에 그대로 적용된다.** *"다른 과업·다른 표본·다른 모델에서 나온 수치는 감각은 주지만 예측은 되지 못한다."*

→ **성인 7.8% / 아동 120.8%도 동기이지 근거가 아니다.** 우리 조건(만 3~7세 · 거실 소음 · 프리셋 낱말)에서 얼마인지는 **재야 안다.**

**다행히 하네스가 이미 있다** — 치영님이 `eval/stt_eval.py`(166줄)를 만들어 뒀다. **막고 있는 것은 코드가 아니라 음성이다.**

#### 확인되지 않은 것

- **아이 목소리 30발화가 언제 오나.** AI-Hub 신청 중이고 승인까지 며칠
- `stt_eval.py`가 **무엇을 재는지** — 내가 코드를 열어보지 않았다. 치영님이 만든 것이고, 프리셋 매칭인지 키워드 보존율인지 확인이 필요하다

#### 같이 생각해 볼 질문

- AI-Hub 승인을 기다리는 동안 **합성 음성으로 미리 재 볼 수 있나요?** 그건 어른 모사와 같은 함정 아닌가요?
- 아이 음성 30발화로 **모델 순위가 갈릴 만한가요?** 30건이면 신뢰구간이 얼마나 넓나요?

### 3. 실험 계획 — 아이 음성 받아쓰기

#### 확인된 것

`guidelines/6` §6-4 합격선에 **아이 발화 핵심 키워드 보존율 ≥ 90%**가 있고, 못 넘으면 *"STT 상향 또는 자체 파인튜닝"*으로 적혀 있다. 그리고 §2에서 **폰 온디바이스가 프리셋 매칭 65%**로 합격선 95%에 미달한 것이 이미 측정됐다.

#### 계획 — 작아도 된다. 설계가 맞는지가 먼저다

| | 무엇 | 왜 이 순서 |
|---|---|---|
| **1** | **조건을 먼저 적는다** — 나이 · 녹음 기기 · 거리 · 소음 · 발화 종류(프리셋 낱말 / 자유 발화) | 조건을 안 적으면 나중에 **무엇과 비교하는지 모른다**. 09-19 측정이 *"성인 남성·조용한 방·프리셋 안"*이라 적어 둔 것이 좋은 전례다 |
| **2** | **후보를 둘로 좁힌다** — 자체 `faster-whisper large-v3-turbo` vs 외부 API 하나 | 셋 이상이면 30발화로 순위가 안 갈린다 |
| **3** | **같은 음성으로 둘을 돌린다** | 다른 음성으로 재면 모델 차이인지 음성 차이인지 모른다 |
| **4** | **두 지표를 따로 센다** — 프리셋 매칭률 · 키워드 보존율 | 합격선이 각각 95% · 90%로 다르다 |
| **5** | **부끄러운 베이스라인을 남긴다** — 폰 온디바이스 65%가 이미 그것이다 | §6-7 *"고치기 전 숫자가 먼저 있어야 「무엇이 느렸고 어떻게 고쳤다」가 성립한다"* |

**규모**: 30발화 × 2모델 = 60건. **순위를 정하기엔 적고, 「합격선을 넘나 못 넘나」를 보기엔 충분하다.**

⚠️ **30건으로 두 모델이 5%p 차이면 그건 동률이다.** `CLAUDE.md`가 *"신뢰구간이 겹치면 동률로 읽는다"*고 정했다. **미리 그렇게 읽기로 정해 두는 것**이 측정 뒤에 정하는 것보다 정직하다.

#### 확인되지 않은 것

- **아이 음성을 어떤 동의와 이용 권한으로 얻나.** AI-Hub 데이터셋이면 그 이용 조건, 직접 녹음하면 보호자 동의. **조사 2·3번과 이어진다**
- 거실 소음 조건을 **어떻게 재현하나.** 실제 거실에서 녹음하나, 소음을 섞나

#### 같이 생각해 볼 질문

- 30발화가 **어느 나이대 몇 명**에서 나와야 하나요? 다섯 살 한 명 30발화와 세 살~일곱 살 여섯 명 5발화는 다른 측정입니다
- 합격선을 못 넘으면 *"STT 상향 또는 자체 파인튜닝"*인데, **부트캠프 기간에 파인튜닝이 현실적인가요?** 아니라면 그 선은 무엇을 뜻하나요?

### 이 조사가 정한 것 / 안 정한 것

**정했다**
- **DER 인용은 정정했고, 역할을 근거에서 동기로 옮겼다.** 처리 상태는 §1 표
- **화자 분리가 빠졌으므로 「자기 맥락 실험」의 대상은 받아쓰기로 옮긴다**
- 성인 7.8% / 아동 120.8%도 **동기이지 근거가 아니다** — 같은 잣대를 우리에게도 댄다
- 실험은 **후보 둘 · 같은 음성 · 두 지표 · 30발화**. 5%p 차이는 **동률로 읽기로 미리 정한다**

**안 정했다**
- **아이 음성을 언제, 어떤 동의로 얻나** — 이것 하나가 전부를 막고 있다
- `stt_eval.py`가 무엇을 재는지 (치영님 확인 필요)
- 합격선을 못 넘었을 때 **파인튜닝이 현실적인지**
