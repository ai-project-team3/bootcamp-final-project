# 동화 V1 검증과 담당자 인수인계 — 2026-09-30

## 현재 결론

동화 서버 연결, 생성 그림 연결, 원본 그림 보관, 완성 책 저장·재열기 코드는 `feature/minwoo`에 있다. 전체 Android 검사 244개와 디버그 APK 빌드는 통과했다. 그러나 에뮬레이터에서 첫 미션을 열 때 기존 공통 화면 코드가 충돌했다. **실제 기기에서 끝까지 플레이 완료했다고 보고할 수는 없다.** 실제 AI 검증도 조장 서버 주소를 받아야 한다.

## 추가 요청 세 가지

- **#34 완료 (`505e578`)**: `exchangeTurn(mode, …)`은 이름 가리기·요청·응답 복원만 담당한다. 슬롯·종료 상태는 바꾸지 않는다. `exchangeStoryTurn`이 동화 판정 적용을 맡는다. 일기 호출은 `template = null`이다. 해당 이슈에 완료 답변을 남겼다.
- **#37 방향 확인**: 동화·일기·협업 저장소와 책장은 따로, 각 12권이다. `StoryBookStore` 형식은 유지했다. 13번째 책에서 사용자에게 고르게 할지, 오래된 책을 제거할지는 미결정이다. 현재 동화 저장소에 임의 삭제 규칙을 넣지 않았다. 책장 화면 분리는 공통 UI 담당자와 통합해야 한다.
- **종료 조건 정리 (`c3f71d5`)**: `storyEndCondition()`에서 시간·마스코트 대리 선택 종료를 제거했다. `story_ready`만 책 제작을 시작한다. 해당 함수는 현재 동화 실서버 흐름에서 실제로 호출된다.

## 오늘 구현한 동화 연결

- 받아쓴 실제 글과 서버 판정 신호를 턴 기록에 유지한다. 서버의 `next_slot`과 질문으로 대화를 잇는다.
- 카드·마스코트 답도 서버에 판정시키고, 출처를 발화·수준·이벤트 기록에서 구분한다.
- 연결 실패는 같은 답으로 재시도하거나 방으로 돌아갈 수 있다. 차단된 재료는 책에 넣지 않고 다시 묻는다.
- 장소가 정해지면 대화와 함께 배경 생성을 시작한다. 지연 안내와 프리셋 대체 경로가 있다.
- 주인공 생성 PNG와 관절 정보를 선택·플레이·책에 연결한다. 음성과 카드가 섞인 외모 선택도 최종 선택을 설명에 포함한다.
- 새 친구 원본 획을 그리기 화면에서 받아 책에 보관한다. 원본 그림을 서버에 보내지 않는다.
- 템플릿마다 실제 쪽 종류·미션 번호를 `/story`에 보낸다. 미션 완료 문장은 앱에서 붙인다.
- 완성 책에 자막, 배경, 주인공 그림·속성, 친구 원본 획, 미션 결과·소품을 저장한다. 다시 읽을 때 진행 중인 대화 상태를 덮어쓰지 않는다.
- 공통 슬롯 밖의 재료를 요청용 `extra`에 투영하되 원본 상태와 출처를 훼손하지 않는다.

## 검증 증거

기준: `main 88c9547`을 포함한 `feature/minwoo 33fa750`.

- `:app:testDebugUnitTest :app:assembleDebug`: **244개, 실패 0, 오류 0**, 4분 14초. 기존 태블릿·터치·월드 검사도 통과했다.
- 저장·재열기, 생성 PNG 표시, 원본 획 보관, 미션 결과 복원은 자동 검사에서 확인했다.
- Android 35 `Pixel_Tablet`, 소프트웨어 그래픽에서 최신 APK를 설치했다. 고양이 UI, 동화 진입·주인공 선택, 원본 그림 작성, 배경 응답 연결, **7쪽 책 표지와 1~4쪽 표시**를 확인했다.
- 에뮬레이터 서버는 로컬 HTTP 테스트 응답이다. AI·STT·TTS·GPU를 사용하지 않았고 키도 읽지 않았다. 테스트 서버의 종료 응답은 아이 발화 수가 아닌 요청 횟수로 수정했다. 마스코트 답은 제품 규칙상 아이 발화 수를 증가시키지 않는다.
- **5쪽 RUB 진입 시 충돌**하여 미션 완료·저장·앱 재실행 후 재열기의 에뮬레이터 검증은 미완료다.

## 확인된 공통 화면 충돌 — 치영님·조장님

예외:

```text
Process: kr.clap.otto
java.lang.IllegalArgumentException: Padding must be non-negative
at com.example.finalproject_demo.ui.BookKt$Stand$1.invoke(Book.kt:180)
```

위치: `android/app/src/main/java/com/example/finalproject_demo/ui/Book.kt`의 `Stand()`.

`left = maxWidth * xf - wide / 2`를 계산하고 `Modifier.padding(start = left, top = top)`에 넣는다. RUB의 주인공은 `Stand(0.14f, 0.11f)`이다. 기본 깊이에서 `wide = height * 0.46`이므로 가로/세로 비가 약 1.643보다 작은 화면에서는 왼쪽 값이 음수가 될 수 있다. 이번 태블릿은 1280×800, 비율 1.6이다. 원래 물리 크기 2560×1600도 같은 비율이다.

이 배치 계산과 여백 코드는 기존 main에도 있다. `Stand()` 본체의 이력은 `c1aad396`이다. 최근 동화 연결부에서 새로 만든 여백 계산이 아니다.

**검토할 수정 방향**: 음수 위치를 표현할 수 있는 `offset`으로 배치하고 크기·그림자·부모 제약을 함께 점검한다. 단순히 0으로 자르면 화면 구도가 바뀔 수 있다. 태블릿 가로 1.6 비율과 세로에서 RUB·DRAG를 실제 렌더링하는 회귀 검사가 필요하다. 공통 UI는 담당자 확인 없이 수정하지 않았다.
