## 1. 무엇을 보내고 무엇을 안 보내나 (조장 결정 그대로 · 코드로 막는 자리)

| 항목 | 보냄 | 어디서 오나 |
|---|---|---|
| 분류 | 항상 | `image` 부적절한 그림 · `text` 부적절한 표현 · `error` 오류 · `other` 기타 |
| 시각 | 항상 | **서버가 받은 시각** — 폰 시계는 믿지 않는다 |
| 앱 버전 | 항상 | `BuildConfig.VERSION_NAME`(예 `0.5-closed`) |
| 모드 | 책에서 왔을 때 | `story` · `diary` · `coop` |
| 쪽 번호 | 책에서 왔을 때 | 1부터 |
| 보호자 설명 | 적었을 때 | 1000자까지(지금 `REPORT_NOTE_MAX` 그대로) |
| 첨부 하나 | **체크했을 때만** | 그 쪽의 AI 그림 하나 **또는** AI 문장 하나 |

**안 보내는 것 — 어떤 경로로도**: 아이가 그린 원본(`drawing` · `sceneDrawing` · `DiaryPiece.strokes`) · 녹음한 소리(`storySoundClip` · `ChildSound`) · 아이 목소리 · 책 id · 책 제목 · 기기 식별키 · 계정 정보 · 화면 캡처. 서버도 **IP · User-Agent 를 디스크에 쓰지 않는다**(남용 막기는 메모리만 · §3-4).

### 1-1. 「AI 그림」은 출처로 고른다 — 화면을 찍지 않는다

책 한 쪽의 화면은 AI 배경 위에 **아이 그림(획)이 겹쳐 그려진다.** 화면 캡처는 그래서 금지다. 첨부 후보는 **저장된 파일의 출처**로만 만든다.

| 모드 | 첨부 후보(그 쪽) | 출처 | 후보가 아닌 것 |
|---|---|---|---|
| 동화 · 협업 | 배경(서버가 만든 경우) | `bgName` 이 `local:` + `story_images/` 안 | `bgName` 이 앱 프리셋이면 **그림 대신 이름만**(`preset:<이름>`) — 우리 그림이라 파일을 보낼 까닭이 없다 |
| 동화 · 협업 | 주인공 펠트 인형(생성된 경우) | `visuals.hero.image`(`local:`) | 아이가 그린 주인공 획 `visuals.drawing` |
| 동화 · 협업 | 새 친구 인형(생성된 경우) | `visuals.friend.image` | — |
| 그림일기 | 오또가 다시 그린 조각 | `DiaryPiece.ottoPng`(`diary_images/`) — 그 쪽 `cast` 의 조각, 없으면 책 전체 | 원본 조각 획 · 판 그림 |

동화 · 협업의 배경 · 인형은 책 단위라 **모든 쪽에서 같은 후보**가 나온다 — 화면에서는 썸네일로 보여 주고 하나만 고르게 한다.

⚖️ **그림일기의 오또 그림** — AI 가 만든 그림이지만 **아이 조각의 모양을 따라 그린 것**이다(`/image` redraw). 「AI 가 만든 그림」에는 들어가지만, 아이 그림의 윤곽이 남아 있다. 권고는 **허용** — 부적절한 결과가 가장 나올 법한 자리가 바로 여기다. 조장이 「아이 그림에서 나온 것은 아무것도」로 읽으면 일기에서는 문장만 첨부한다(§8-③).

### 1-2. 「AI 문장」은 이름을 가려서

쪽의 문장(동화 `SavedStoryPage.caption` · 일기 `DiaryPage.text` · 협업 같은 자리)은 AI 가 썼지만 **오또가 아이를 부르는 말 · 친구 이름**이 실명으로 들어 있다. 보내기 전에 `NameMask` 로 「주인공」 · 「친구1」 자리표시로 바꾼다 — TypeSafe 로 보낼 때와 같은 방식이다. 미리 보기에도 **가린 문장 그대로** 보여 준다(보이는 것 = 가는 것). 500자에서 자른다.

## 2. 앱 (부모 모드)

### 2-1. 들어오는 길 둘

1. **책장 정리(`ShelfTidyTab`)의 책 카드** — 「빼기」 옆에 「신고」. 누르면 그 책의 맥락(모드 · 쪽 수 · 첨부 후보를 찾을 참조)을 들고 신고 시트가 열린다. 신고가 「이 그림이 이상해요」인 경우가 대부분이라 **주 입구는 여기다.** 아이 화면(책 읽기)에는 신고 단추를 두지 않는다 — 아이가 누를 자리다.
2. **설정의 「문제가 있었나요?」(`ReportSection`)** — 책 맥락이 없다. 분류 · 설명만 받고 첨부 칸은 숨긴다. 그 아래 한 줄 「책 속 그림 · 문장이라면 책장 정리에서 그 책의 [신고]를 눌러 주세요」.

### 2-2. 시트 차례 (한 화면 · 위에서 아래로)

| 칸 | 내용 |
|---|---|
| 쪽 | (책에서 왔을 때) 1 ~ n 칩 · 각 칩 아래 그 쪽 문장 앞 12자(실명 그대로 — 폰 안에서만 보임) |
| 분류 | 라디오 넷. 「부적절한 말」 → **「부적절한 표현」**(이슈 문구로 맞춤) |
| 설명 | 지금 입력칸 그대로 · 1000자 |
| ☐ 문제 된 그림 / 문장 같이 보내기 | **기본 꺼짐.** 켜면 그 아래 「그림」 / 「문장」 하나 고르기 → 그림이면 후보 썸네일(§1-1) 중 하나, 문장이면 가린 문장 · 후보가 없으면 그 칸은 흐리게 「이 쪽에는 오또가 만든 그림이 없어요」 |
| 「보낼 내용 미리 보기」 | **보내기 단추는 미리 보기 안에만 있다.** 보내는 필드 전부를 표로 — 분류 · 모드 · 쪽 · 앱 버전 · 설명 · 첨부(썸네일 또는 가린 문장) — 그리고 한 줄 「아이가 그린 그림 · 녹음 · 목소리는 보내지 않아요 · 처리가 끝나면 30일 뒤 지워요」 |

분류 기본값: 첨부를 그림으로 고르면 분류가 비어 있을 때 「부적절한 그림」을, 문장이면 「부적절한 표현」을 미리 고른다(바꿀 수 있음).

### 2-3. 보내기 · 결과

```
보내기 ─→ ReportUpload.send(payload)   // Server.post("/report", readMs = 10_000)
           ├ 200 {id}          → 「접수됐어요」 + 접수 번호 + 「처리가 끝나면 30일 뒤 지워져요.
           │                       지워 달라고 하시려면 이 번호를 ljh11442@gmail.com 으로 보내 주세요」
           ├ null(서버 없음 · 연결 실패 · 시간 초과) ─┐
           └ 4xx/5xx(429 · 413 · 503 …)              ─┴→ 「서버에 닿지 못했어요」
                                                        [메일로 보내기] [닫기]
```

- **메일 대체는 지금 `sendReportMail` 그대로** — 분류 · 설명 · 앱 버전에 모드 · 쪽만 더한다. **첨부는 메일에 싣지 않는다**(메일은 Google 을 지나 받은편지함에 기한 없이 남는다 — 30일 약속을 지킬 수 없다). 화면에 「메일로는 그림 · 문장이 가지 않아요」 한 줄.
- 메일도 자동으로 열지 않는다 — 보호자가 단추를 누를 때만. 서버가 받았는지 모르는 상태에서 메일까지 가면 두 번 접수된다.
- 보내는 동안 단추는 「보내는 중…」으로 잠근다(두 번 누름 막기). 10초 넘으면 실패와 같은 길.
- `CallLimits.blocks` 는 `/report` 를 막지 않는다(경로가 `/tts` · `/turn` 만 본다) — 그대로 둔다.
- 시연 서랍 「기록」 한 줄은 지금처럼(새 이벤트 종류 없음): `신고 — 분류 "image" · 3쪽 · 첨부 그림 · 서버 접수 R-1007-3FA2` / `… · 서버 실패 → 메일`.

### 2-4. 폰에 남기는 것

`ConsentStore.reports`(지금은 메모리 목록)를 **보낸 접수 번호 목록**으로 바꿔 `consent` prefs 에 최근 10개 — `{id, 날짜, 분류}` 만. 설정 신고 칸 아래 「보낸 신고 2건 · R-1007-3FA2 …」. 삭제 요청에 번호가 필요해서다. `LocalWipe`(탈퇴 · 기기 비우기)에 이 키를 더한다.

### 2-5. 코드 자리 (구현 세션 몫 — 모양만)

```kotlin
// net/ReportUpload.kt
sealed interface ReportAttachment {
    /** AI 그림 — [AiPicture] 로만 만든다. 생성자가 internal 이라 화면 · 비트맵에서 바로 만들 수 없다 */
    data class Picture(val source: AiPictureSource, val jpeg: ByteArray) : ReportAttachment
    data class Preset(val name: String) : ReportAttachment           // 프리셋 배경 — 이름만
    data class Sentence(val masked: String) : ReportAttachment       // NameMask 를 거친 문장
}
enum class AiPictureSource { BACKGROUND, HERO, FRIEND, DIARY_OTTO }

data class ReportPayload(
    val category: String, val mode: String?, val page: Int?, val note: String,
    val appVersion: String, val attachment: ReportAttachment?,
) { fun toJson(): JSONObject }          // 키는 §3-1 의 다섯 + attachment 뿐

/** 그 쪽의 첨부 후보 — 출처 표(§1-1)만 본다. 획 · 소리 · 화면은 매개변수로도 받지 않는다 */
fun aiPicturesFor(book: ShelfEntry, page: Int): List<AiPicture>
```

- 그림은 보내기 전에 **긴 변 1024px · JPEG 85** 로 다시 굽는다(투명 PNG 인 오또 그림은 흰 바탕에 얹어서). 1024×1024 펠트 그림이 대략 150~300KB.
- `sendReportMail` 은 `ReportUpload.mail(payload)` 로 옮기고 첨부 필드를 **읽지 않는다.**

## 3. 서버

### 3-1. `POST /report` — 공개(앱이 부름 · 로그인 없음)

요청(JSON · `/image` redraw 와 같은 base64 방식):
```json
{
  "category": "image",              // image | text | error | other
  "mode": "story",                  // story | diary | coop | null
  "page": 3,                        // 1~40 | null
  "note": "주인공 얼굴이 무서워요",   // 0~1000자
  "app_version": "0.5-closed",      // 1~32자
  "attachment": {                   // 없으면 null
    "kind": "image",                // image | preset | text
    "source": "background",         // image 일 때: background | hero | friend | diary_otto
    "data_base64": "/9j/4AAQ…",     // image 일 때
    "name": "forest_day",           // preset 일 때 (영문 · 숫자 · _ 64자)
    "text": "주인공은 친구1 과…"      // text 일 때 0~500자
  }
}
```

**검사 — 모르는 키는 422**(pydantic `extra="forbid"`, 첨부 안까지). `audio` · `drawing` · `device_id` 같은 키가 실수로 실려도 저장 전에 튕긴다.

| 검사 | 값 | 넘으면 |
|---|---|---|
| 요청 본문 전체 | **2.5MB** (`Content-Length` 먼저, 없으면 읽으며 셈) | 413 |
| 첨부 그림(디코드 뒤) | **1.5MB** | 413 |
| 그림 형식 | 앞 바이트가 JPEG · PNG · WebP 이고 Pillow 로 열려야 함 · 가로세로 각 64~4096 | 422 |
| 저장 | **서버가 다시 굽는다** — 긴 변 1024 · JPEG 85 · 메타데이터 없음 · 투명은 흰 바탕 | — |

다시 굽는 까닭: 받은 파일을 그대로 두면 EXIF · 숨은 덩어리까지 30일 남는다. 다시 구운 JPEG 만 남기면 「디스크에 남는 것은 그림 하나」가 참이 된다.

**⚖️ 크기 상한 · 형식(이슈의 「같이 정할 것」)** — 권고: 앱이 1024 · JPEG 85 로 줄여 보내고(보통 300KB 안), 서버 상한은 넉넉히 1.5MB · 저장은 JPEG 하나. 원본 PNG 를 받지 않는 이유는 모바일 데이터 · 디스크 둘 다. 판단에 필요한 화질은 1024 면 충분하다(관리자 페이지에서 크게 봐도 화면 폭).

응답 200: `{"id": "R-1007-3FA2", "keep_days_after_done": 30}`
오류는 §3-0 공통 모양. `MOCK=1` 이면 저장하지 않고 `{"id": "R-0000-MOCK", …}`.

### 3-2. 관리자 API — 모두 `Depends(admin.require_admin)`

경로를 `/admin/reports…` 아래에 둔다. 모니터 도메인에서는 nginx 의 기존 `location /admin/` 프록시로 오고, 백엔드 공개 주소(otto-back)로 바로 와도 쿠키 없이는 401 이다.

| 메서드 · 경로 | 하는 일 | 돌려줌 |
|---|---|---|
| `GET /admin/reports?status=open\|done\|all` | 목록(기본 `open` = 접수 + 확인 중) · 새것부터 | `[{id, received_at, category, mode, page, status, attachment_kind, note_head(80자)}]` + `counts` |
| `GET /admin/reports/{id}` | 상세 | 저장된 JSON 전부 + `delete_at`(완료면) |
| `GET /admin/reports/{id}/attachment` | 첨부 그림 | `image/jpeg` · `Cache-Control: no-store` · `X-Content-Type-Options: nosniff` |
| `POST /admin/reports/{id}/status` `{status}` | `received` → `reviewing` → `done` (되돌리기 허용 — `done` 에서 나오면 `done_at` 지움) | 바뀐 상세 |
| `DELETE /admin/reports/{id}` | 바로 지우기 — **보호자가 접수 번호로 삭제를 요청할 때**(처리방침 제7조 권리) | 204 |

`id` 는 `^R-\d{4}-[0-9A-F]{4}$` 로 검사한 뒤에만 경로에 쓴다(디렉터리 탈출 막기). 쿠키가 `SameSite=Strict` 라 다른 사이트에서 상태 바꾸기 요청을 보내도 세션이 실리지 않는다.



### 3-4. 남용 막기 (메모리만)

공개 경로라 누구나 부를 수 있다. 디스크를 채우지 못하게 셋을 건다.

| 무엇 | 값 | 넘으면 |
|---|---|---|
| 주소당 | 10분에 5건 — `main._forwarded_ip`(CF-Connecting-IP) 기준 · **메모리 deque**, 디스크에 안 씀 | 429 |
| 서버 전체 하루 | 100건 | 503 |
| 폴더 크기 | 200MB | 503 + 경고 로그 |

### 3-5. 30일 자동 삭제

```python
def purge(now) -> int:
    # done 이고 done_at + 30일 <= now 인 것의 .json 과 첨부를 지운다. 짝 잃은 .jpg · 남은 .tmp 도 지운다.
```

## 9. 확인하지 못한 것

- 서버가 만든 배경 PNG 의 실제 크기(SDXL 출력 해상도 · 바이트) — 1024 · JPEG 85 에서 300KB 안이라는 것은 어림이다. 구현 때 `story_images/` 에서 한 장 재 본다.
- `ShelfTidyTab` 의 `ShelfEntry` 에서 그 책의 `visuals` · 일기 조각까지 닿는 길 — 지금 카드는 제목 · 쪽 수만 쓴다. 저장소에서 id 로 다시 읽어야 할 수 있다(`d.shelfEntries` 옆에 하나).
- 일기 쪽 ↔ 조각 연결(`DiaryPage.cast` 와 `DiaryPiece.name`)이 모든 책에서 맞는지 — 안 맞으면 책 전체 오또 그림을 후보로.
- 공개 백엔드 주소에서 `CF-Connecting-IP` 가 늘 오는지 — 안 오면 주소당 상한이 전체 상한처럼 동작한다(안전한 쪽).
