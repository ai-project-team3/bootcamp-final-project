작성 이종훈. 받은 체크리스트 48줄을 **코드와 문서를 직접 열어** 한 줄씩 확인했다.
`file:line` 이 붙은 주장은 전부 실물과 대조했다.

## 이 문서의 범위

**확인한 것** — 체크리스트의 모든 항목. `android/` 전체 · `backend/` 전체 · `eval/` 전체 ·
`guidelines/` 9개 · `docs/` · `.gitignore` · 병합된 릴리스 매니페스트 · git 추적 상태.

**확인하지 않은 것** — 실기기(태블릿 세로 · R8 릴리스 빌드 · 동의 우회 실제 재현). 전부 코드 읽기다.
`pydantic-settings` 의 `extra` 동작은 패키지가 설치돼 있지 않아 실행 검증하지 못했다.

**판정** — 체크리스트는 **정확하다.** 48줄 중 사실이 아닌 것은 넷뿐이고, 그중 셋은 「원인이 다르다」 수준이다.
**문제는 빠진 것이다** — 검증 중에 **체크리스트에 없는, 더 심각한 것 다섯**이 나왔다.

## 2. 체크리스트가 놓친 것 — 심한 순서로 다섯

### ⚠️ 2-1. 동의 화면을 **터치로 우회할 수 있다** — 이게 목록 맨 위여야 한다

> **쉽게** — 동의 화면이 **유리문이 아니라 그림 걸린 벽**이었다. 가운데 그림(카드)만 막고 가장자리는 뚫려 있어서, 뒤에 있는 🎤 버튼에 손이 닿았다.
> **현황 ✅ 09-25 고침** — `Dialog` 로 감싸 창을 하나 더 띄운다. `ConsentGateTest` 가 루트 개수로 지킨다(되돌려 보니 정확히 그 검사만 깨졌다)

`GuardianConsentScreen` 이 `Dialog` 가 아니라 `MainActivity` 의 같은 `Box` 안 **마지막 자식**으로 그려진다
(`MainActivity.kt:169-171`). 그런데 그 루트(`Consent.kt:224`)는 `background` 만 있고 `clickable`·`pointerInput` 이 없어
**터치를 소비하지 않는다.** 카드가 화면의 78%×92%(`:229-230`)라 좌우 11%·상하 4%가 빈다. 그 빈 자리 아래에 **먼저 그려진**

- `FloatingControls` — 우하단 🎤 버튼, 지름 64dp (`MainActivity.kt:140-143`)
- 시연 서랍 롱프레스 핫스팟 — 우상단 48dp (`MainActivity.kt:146-153`)

이 그대로 놓여 있다. **동의 화면이 떠 있는데 아이가 오른쪽 아래를 누르면 마이크가 켜지고, 오른쪽 위를 길게 누르면
디버그 서랍이 동의 화면 위로 열린다.**

**이건 09-23에 이미 한 번 고친 문제다.** 진웅님이 *"아이가 부모 모드를 안 거치고 마이크에 닿는다"*고 지적해서
동의를 첫 실행으로 옮겼는데, **다른 경로로 그대로 남았다.** 같은 파일의 `MicNoticeSheet` 는
`Dialog(dismissOnBackPress = false, dismissOnClickOutside = false)`(`Consent.kt:328-334`)로 제대로 막는다 —
**고치는 방법이 같은 파일 100줄 아래에 있다.**

### ⚠️ 2-2. 금칙어 필터가 **아무 데서도 호출되지 않는다**

> **쉽게** — 욕설 거르개와 「whisper 가 지어낸 말」 거르개를 **만들고 시험까지 했는데 천장에 안 단 화재경보기**다. 상자 안에서는 잘 울린다. 지금 서버는 아이 말을 **거르지 않고** 모델에 보내게 짜여 있다. 구멍을 메우기 전에 **먼저 달아야** 한다.
> **현황 ⬜ 미착수** — `/judge` · `/stt` 라우터 구현과 같이 한다

체크리스트는 필터의 **구멍 셋**(허용어 면제 · 어절 정확일치 · 목록 부분집합)을 정확히 짚었다. 셋 다 사실이다.
**그런데 그보다 앞선 사실이 있다** — `is_blocked()` 와 `guard_report()` 를 **부르는 코드가 backend 전체에 없다**
(정의 2곳 외 참조 0건). `routers/judge.py` 는 `schemas.judge` 만, `story.py` 는 `schemas.story` 만 import 한다.

`guidelines/8_금칙어.md:29` 는 *"LLM을 부르기 전에 백엔드에서 자른다"* 이고
`3_API_명세.md:78` 은 *"금칙어에 걸린 발화는 LLM을 부르지 않고 되돌린다"* 인데 **현재 경로는 아무것도 자르지 않는다.**

같은 일이 헛문장 거르개에도 있다. `filters/hallucination.py`(83줄, 테스트까지 통과)를 `stt.py` 독스트링이
쓴다고 적어 뒀지만 **`check_transcript` 호출이 없다.** 그리고 `schemas/events.py`(22줄)도 import 하는 코드가 없다.

→ **「필터는 만들었다」가 「필터는 작동한다」로 읽히기 쉬운 자리다.** 배선이 P1이 아니라 **구멍 수리보다 먼저**다.
안드로이드 쪽에는 필터가 **아예 없고**(grep 0건), 실명 가리기(규칙 6)도 **로그 문구와 UI 안내뿐**이다.

### ⚠️ 2-3. 규칙 2 — 동화 모드에 `story_ready` 가 **아예 없다**

> **쉽게** — 지금 동화 모드(대본 데모)는 팀 규칙 아홉 중 **넷**을 어긴다. ① **8번 주고받으면 강제로 끝난다**(규칙 3) — 우리 핵심 지표인 「주고받은 횟수」를 우리가 깎는다 ② 「이야기가 됐나」가 아니라 **「칸 6개가 찼나」로 끝을 정한다**(규칙 2) ③ **공식 목록 12개에 없는 칸 이름 16개**를 쓴다(규칙 1) — 부모 리포트가 못 센다 ④ 아이 말에 `child` 대신 **`voice`** 를 붙이고 칸을 누가 채웠는지 안 적는다(규칙 5) — 리포트가 **아이가 한 말과 우리가 채운 말을 못 가른다.** 이 절은 ①②이고 ③④는 §3 P1 목록에 있다.
> **현황 ⬜ 미착수** — 진짜 판정(`/judge`)을 붙일 때 어차피 다시 짜는 자리라 **그때 같이** 고친다

체크리스트는 *"필수 칸이 `reqCount` 로 6개 고정"*을 짚었다(사실 — `Model.kt:852-857`). **더 근본은 이것이다:**
`storyReady`·`endReason` 을 grep 하면 **일기 모드에만** 있다(`DiaryScenes.kt`, `Model.kt:808,930`).
**동화 모드의 종료는 장면 시퀀스 + `budgetOver()`(8턴)뿐이다.** 규칙 2가 *"끝나는 기준은 `story_ready`"*라고
못 박았는데 동화 모드는 그 기준을 구현하지 않았다. **규칙 2와 규칙 3 위반이 같은 함수에 묶여 있다.**

그리고 일기 모드는 규칙 2가 금지한 것을 **이름만 바꿔** 쓴다 — `Model.kt:930`:
`val diaryReady: Boolean get() = isDiary && filled >= reqCount` 에 주석이 *"네 자리가 다 찼는가 = `story_ready`"*.
*"필수 N칸이 다 찼으니 끝"* 그 자체다. (완화 하나 — `DiaryScenes.kt:19-21` 이 마스코트가 메운 칸을 빼는 방어를 넣었다.)

### ⚠️ 2-4. 측정한 프롬프트와 「서비스가 쓸」 프롬프트가 **다른 파일이다**

> **쉽게** — 모델을 **긴 지시서(6,657자)** 로 시험해서 「10.5원 · 2.9초」를 얻었는데, 현황 문서는 서비스에 **짧은 연습용 지시서(450자)** 를 쓴다고 적었다. **짐을 가득 싣고 연비를 재 놓고 빈 차로 달리겠다는 것**이다 — 지금 숫자가 어느 차의 숫자인지 애매하다. 게다가 긴 지시서는 **4분의 1이 사람이 읽으라고 쓴 메모**인데 그것까지 모델에 보내고, 채워야 할 빈칸(`{utterance}` 등)도 빈 채로 나간다.
> **현황 ⬜ 결정 필요** — 어느 지시서가 진짜인지 하나로 정하고 → 정리하고 → 다시 잰다. 정하기 전에 재면 또 다른 숫자가 나온다

`guidelines/10_기능별_현황.md:69` 는 서비스 프롬프트를 **`eval/judge_prompt_demo.md`** 로 못 박았다.
그런데 그 파일은 **16줄·450자짜리 데모 스텁**이고(*"실제 팀의 judge_prompt.md가 도착하기 전까지 무료 mock 데모에서만"*),
우리가 기록한 원가·지연(3,983 토큰 · 21.6원 · p95 3.789초)은 **6,657자짜리 `judge_prompt.md`** 로 낸 값이다.

→ **정본 표와 `results.md` 의 숫자가 서로 다른 입력을 가리킨다.** 어느 쪽이 서비스인지 먼저 정해야 한다.

체크리스트가 짚은 「파일 전체를 보낸다」도 사실이고, 실측하면 **군더더기 35줄·1,683자 = 파일의 25.3%,
약 790 토큰(입력의 20%)**. 21.6원 중 약 4원이 이 값이다. 게다가 **자리표시자가 치환되지 않고 리터럴로 나가고**
(`{slots}`·`{asked_slot}`·`{utterance}`), 실제 값은 **다른 키 이름**(`slots:`·`asked:`)으로 따로 가고,
**`level`·`turn`·`question` 은 아예 안 보내고**(명세 §3-2는 보낸다고 규정), **스키마가 두 번 전송된다.**

### ⚠️ 2-5. 확정된 결정 하나가 3일째 코드에 안 들어갔다

`eval/providers/typesafe_adapter.py:82` — `CONFIDENCE_FLOOR = ... "0.0"`.
그런데 `results.md:1181-1190` 이 09-22에 **표로 근거를 냈다** — *"0.6에서 판단 23%를 버리고 정답률을 6.5%p 올린다"*

올릴 근거가 이것이다"*라고 적었다. **근거가 확정됐는데 코드는 그대로다.**

## 3. 사실로 확인된 것 — 체크리스트대로다

지면을 아끼려고 **판정만** 적는다. 전부 `file:line` 으로 확인했다.

**P0 릴리스 차단 (여섯 줄 전부 사실)**
- 시연 서랍이 릴리스에서 열린다 — **소스 전체에 `BuildConfig.DEBUG` 가 0건.** 서랍은 로그가 아니라 탭 7개짜리
  개발자 콘솔이고 `s.persona = p` 처럼 상태를 직접 쓴다
- PIN이 아무 숫자 4개로 통과 — 입력 숫자를 **어디에도 모으지 않는다.** 비교할 PIN이 코드에 없다.
  화면에 `"데모: 아무 숫자 4개"`(`Parent.kt:764`)가 그대로 적혀 있다
- 동의 화면 「초안」(`DRAFT = true`, `Consent.kt:77`) · 방침 링크 `clickable { /* 주소가 생기면 */ }` 빈 람다 ·
  `ConsentStore` 가 `mutableStateOf` 라 **껐다 켜면 초기화**
- 신고가 메모리 리스트에만 쌓인다. 로그 문구가 자백한다 — `"저장만 하고 보내지 않음"`. `Intent`·`mailto:`·HTTP 0건
- `Blow.kt:54-59` 가 화면 진입만으로(`active`) 권한 다이얼로그를 띄운다. `micNoticeShown` 확인 0건.
  🎤 경로(`Chrome.kt:292`)는 반대로 제대로 한다
- 마이크 고지가 *"소리는 우리 서버까지만 가고 바로 지워져요"*(`Consent.kt:352`)인데 **`INTERNET` 권한이 없고
  HTTP 클라이언트도 없다**(okhttp·retrofit·ktor 전부 없음, `HttpURLConnection` grep 0건). **고지가 구현보다 앞서 있다.**
  ⚠️ 그리고 앱 화면은 「서버까지 간다」, 처리방침은 「기기 밖으로 안 나간다」 — **둘이 반대다. 지금 코드로는 처리방침이 맞다**

**P1 규칙 위반 (전부 사실)**
- 규칙 3 — `budgetOver()` 에 `if (s.turn < 8) return false`. 장식이 아니라 **동화 6개 장면 입구에서 전부 호출**되고,
  시연 서랍에 턴을 8로 미는 스위치까지 있다(`Screen.kt:1138`). `Behind.kt:47` 은 반대로 적혀 **화면 설명과 실행이 다르다**
- 규칙 1 — 12종 밖 이름 **정확히 16개**: `stop saw response helper need role try1 fail consequence lesson upset truth
  contest cheer`(plot) + `goal reflect`(ending). `resolve` 만 `solution` 으로 바꿔 나간다.
  ⚠️ **옳은 패턴이 같은 파일에 있다** — `Scenes.kt:711` 은 `"slot" to "extra", "of" to "sight"` 로 제대로 한다
- 규칙 5 — `sourceOf()` 가 `"voice"` 반환(`Director.kt:449`), 하드코딩 3곳 더. `slotBy` 쓰기는 일기 계열 3곳뿐.
  ⚠️ **필드 이름도 어긋난다** — 정본은 `by` 인데 코드는 `source`, `utterance` 는 `speaker`+`mode`. **한 개념에 세 이름**
