## 0. 한 장 요약

### 만드는 것

영업 미팅을 돕는 AI 어시스턴트. 사전 브리핑 · 실시간 제안 · 사후 정리를 하되,
여기에 **"상대가 아직 무엇 때문에 막혀 있는지를 계속 들고 있는 기능"** 을 더합니다.

### 앞세우는 것 — 둘뿐입니다

```
1. 풀렸다가 다시 막히는 것을 잡아낸다        ← 재발
2. 미팅을 낱개 문서가 아니라 이어 붙인다      ← 차수별 누적
```

여기에 다른 걸 섞으면 "회의록 앱 하나 더"로 들립니다.

### 세 층으로 나눕니다

**"차별점이 아니다"와 "빼야 한다"는 다른 말입니다.**

| 층 | 무엇 | 예 |
|---|---|---|
| **1층** 앞세우는 것 | 발표·랜딩에서 이것만 말한다 | 재발 탐지 · 차수별 누적 |
| **2층** 기본으로 넣는 것 | 차별점은 아니지만 없으면 빈약하다 | 카드 · 실시간 전사 · 사후 요약 · 사전 브리핑 · 백채널 · 템플릿 1종 |
| **3층** 진짜로 빼는 것 | 넣으면 제품이 나빠진다 | **항목 자동 생성** · **필수 항목을 "완료"로 자동 판정** |

3층이 둘뿐인 것이 중요합니다. 나머지는 다 만들되 앞세우지 않습니다.

## 1. 시장 위치

### 1-1. 회의록이 아니라 영업 성과 시장에 섭니다

| | 회의록 제품 | 영업 어시스턴트 |
|---|---|---|
| 산출물 | 기록 | 매출 |
| 무료 대체재 | 많음 (클로바노트 등) | 적음 |
| 성과 측정 | 어려움 | 계약 성사 여부로 명확 |
| 가격 여력 | 월 1만원대 | 계약 하나가 수십~수백만 원 |

같은 기술이라도 어느 시장에 놓느냐로 가격이 10배 달라집니다.

### 1-2. ⚠️ Caret — 두 개를 구분해야 합니다

이 절은 **원본에서 가장 크게 바뀐 부분**입니다.

| | **caret.so** | **Aside "캐럿"** |
|---|---|---|
| 무엇 | AI 회의록 (사전 브리핑 · 실시간 제안 · CRM 연동) | **기술 영업팀용 실시간 AI 코파일럿** |
| 상태 | **2026-09-01 서비스 종료** | **운영 중.** YC F25 · 프리시드 15억 |
| 우리와 | 참조한 기능 목록 | **직접 경쟁** |

**종료 사유는 공개된 어디에도 없습니다** 🔍 — 공식 changelog 404, 티로 마이그레이션 글에도
"종료됨"만 있고 이유는 없습니다. 창업자 인터뷰·언론 보도도 찾지 못했습니다.

> **그래서 이 문서는 caret.so의 종료를 "확인된 사실"로 쓰지 않습니다.**
> §1-3의 사인 분석은 **정황에서 끌어낸 추정**이며, 전략의 유일한 근거로 삼지 않습니다.

**Aside 캐럿은 발표에서 반드시 먼저 꺼내야 합니다.** 이름이 같고 컨셉이 겹칩니다.
차별점 슬라이드를 따로 준비합니다 (`6-8` 미결 #7).

### 1-3. 추정 — 기능이 아니라 위치가 문제였다

> ⚠️ 아래는 **확인되지 않은 추정**입니다.

caret.so는 한국어 정확도 · 봇 없는 로컬 녹음 · 실시간 전사 · 실시간 답변 제안 ·
CRM 연동 · 사전 브리핑 · 팀 학습을 **다 갖추고도** 종료했습니다.

기능 목록이 아니라 **어느 시장에 서 있었느냐**가 문제였을 가능성이 큽니다 —
"회의록을 더 잘 만드는 제품"으로 서서 무료 경쟁자와 싸웠고, 품질 우위가 가격표를
정당화하지 못했습니다.

**❌ "그 기능을 했는데 죽었으니 우리는 빼자"는 틀린 추론입니다.**
실시간 답변 제안·회의록 요약·CRM 연동은 오히려 잘 팔리는 기능입니다.
**바꾸는 것은 기능이 아니라 배치입니다.**

## 2. 우리가 더하는 것

### 2-1. 신호등 — 항목별 상태 추적 ★ 핵심

미팅에서 상대가 걸려 있는 것들을 **항목별 색깔 상태**로 들고 있습니다.

```
⚪ 아직 안 나옴    🔴 나왔는데 못 끝냄
🟡 일부 끝남      🟢 끝남
```

**핵심은 "재발"입니다.**

```
18:40  고객 "예산이 좀 부담되는데…"     ← 나왔다      🔴
26:05  고객 "아 그 정도면 됐네요"        ← 끝난 듯     🟢
31:20  고객 "근데 위에서 좀…"           ← 다시        🔴 재발
```

사후 리뷰는 "놓친 점"을 알려주지만 **26:05 → 31:20은 못 잡습니다.**
녹취록에는 두 문장이 따로 적혀 있을 뿐입니다. **미팅 내내 이 항목의 상태를 들고 있어야만 보입니다.**

### ★ 항목을 "만들지" 않고 "고릅니다"

대화에서 항목을 자유롭게 뽑아내면 셋이 무너집니다.

```
❌ "예산이 부담"과 "가격이 비싸요"가 서로 다른 항목으로 두 개 생김
❌ 지나가는 말까지 항목이 되어 신호등이 20개로 불어남
❌ 정답이 없어서 잘 맞혔는지 채점할 수 없음
```

그래서 **영업 유형별로 항목 목록을 미리 만들어 둡니다.** 대화 중에는 그 목록에서 꺼내 켤 뿐입니다.

> 빈 종이에 받아쓰는 게 아니라 **미리 인쇄된 체크리스트에 표시하는 것**입니다.
> 앞은 정답이 없고, 뒤는 정답이 있습니다.

목록에 없는 게 나오면 `기타` 칸 하나에 **원문 그대로** 담고 분류 없이 상태만 추적합니다.

**여기가 바이브 코딩으로 해결되지 않는 유일한 부분이고, 동시에 유일한 기술 차별점입니다.**

### 2-2. 차수별 누적 리포트 — 해자

| 차수 | 성격 | 핵심 문장 |
|---|---|---|
| 1차 | 발견 | "이번에 이런 것들이 나왔습니다" |
| 2차 | 변화 | "1차 대비 무엇이 풀렸고 무엇이 그대로인지" |
| 3차+ | 패턴 | "이 고객은 계속 여기서 막힙니다" |

```
━━ 3회 누적 ━━━━━━━━━━━━━━━━━
예산 승인   1차 🔴  2차 🔴  3차 🔴
            ↑ 세 번 다 못 끝냄 — 이 고객의 핵심 장벽
```

**3차 리포트는 1·2차를 우리 제품으로 해야만 나옵니다.**
쓸수록 가치가 커지고, 갈아타면 누적 기록을 잃습니다. 그게 방어선입니다.

### 2-3. 카드 — "지금 다룰 것"

신호등만 있으면 *"당신 이거 안 했어요"* 라고 지적만 하는 도구가 됩니다.
**"그래서 어떻게 하라고"** 에 답하는 게 카드입니다.

```
후보 생성   신호등 상태에서 규칙으로 뽑음   ← LLM이 후보를 만들지 않음
순위        어느 항목을 먼저 다룰지 정함
문장        LLM이 마지막에 한 줄만 씀
```

**카드 ≠ 항목** — 카드는 매 턴 새로 만들고 버립니다. 틀리면 다음 턴에 교체됩니다.
항목을 자동 생성하면 신호등이 불어나 화면과 채점이 무너지지만, 행동 제안은 매번 새로 해도 됩니다.

**2순위까지만 만듭니다.** 같은 크기로 두면 미팅 중에 둘을 비교하게 되고, 그 비교 비용이
카드의 목적(빠른 행동)을 깎습니다.

### 2-4. 팀 백채널

확인한 모든 제품이 영업사원 한 명이 혼자 보는 도구입니다. 그런데 실제 미팅에는
담당자 + 매니저, 프리랜서 + 파트너처럼 **우리 쪽 2명**이 들어가는 일이 많습니다.

| | |
|---|---|
| 신호 방식 | 항목을 탭하면 정문구 자동 생성 |
| 표시 | 발표자 화면 하단에 6초, 소리·진동 없음 |
| 권한 | 동석자는 보기 + 신호만 |
| 접속 | **6자리 방 코드** → 짧은 수명의 토큰 |
| 기록 | 리포트에 신호 N건 / 반영 M건 |

🔴 **원본 음성을 전송하지 않습니다.** 🔍
대법원 2024. 2. 29. 2023도8603이 '청취'를 **대화 도중 실시간으로 듣는 행위**로 확정했습니다.
동석자에게 실시간으로 음성을 보내면 그 정의에 들어갑니다.
백채널 설계는 원래 음성이 필요 없으므로 **이 제약이 기능을 깎지 않습니다.**

**정직하게 — 사람들은 이미 카톡으로 합니다.** 우리 가치는 "신호를 보낼 수 있다"가 아니라
**"신호등과 연결돼 있어 탭 한 번이면 된다"** 입니다. 진짜 가치이지만 얇습니다.
다만 발표 데모에서 눈에 보이는 장면을 만들어 줍니다.

## 3. 화면 세 장

### 화면 ① — 미팅 전

딜을 고르고 지난 차수 상태를 확인합니다.

```
🔍 회사 · 담당자 · 건명으로 찾기            ＋ 새로 만들기
─────────────────────────────────────────────────────
    건명              차수 ⇅  상대    미해결 ⇅  최근 ▼
🔴  A사 신규 도입      2차    박부장    2건     6일 전
🟡  김OO님 종신보험    1차    김영희    1건     3일 전
─────────────────────────────────────────────────────
지난번에 못 끝낸 것          ← 우리만 할 수 있음
  🔴 예산 승인    31:20에 재발
  🔴 계약 기간    아예 언급 안 됨

참고 자료                    ← 회의록 제품이 하던 것
  · A사 최근 메일 3건    · 이전 견적서
                                    [ 이 상태로 시작하기 ]
```

**"지난 미해결"이 위, "참고 자료"가 아래입니다.** 자료를 모으는 건 누구나 할 수 있지만,
**"지난번에 무엇이 안 끝났는지"는 상태를 들고 있던 제품만 말할 수 있습니다.**

**1차 미팅에는 이월이 없습니다.** 대신 "이번 미팅 기본 체크" 5개를 같은 항목 풀에서
골라 보여줍니다. **가상의 과거 이력을 만들지 않습니다.**

### 화면 ② — 미팅 중 (본체)

```
┌──────────────────────────────────────────────────────────────────────────┐
│  A사 2차 미팅 · 31:20                         ● 듣는 중 · 👤 2명          │
├───────────────────────┬────────────────────────┬─────────────────────────┤

├───────────────────────┼────────────────────────┼─────────────────────────┤
│  예산 승인   🔴 (이월) │  ☑  보험료             │  1순위   결정권자       │
│   31:20 "위에 좀…"    │  ☑  보장 범위          │   "위에 한 번 물어봐야" │
│                       │  ☐  계약 기간          │   31:20                 │
│  결정권자    🔴        │  ☑  해지환급률         │                         │
│   31:20 새로 나옴      │  ☑  면책 기간          │  💬 "결정 과정에 함께   │
│                       │  ☐  부담보 사항        │      하실 분이          │
│  기존 계약   🟡        │  ☑  청약철회권         │      계실까요?"         │
│                       │                        │  ─────────────────      │
│                       │                        │  2순위 · 계약 기간      │
├───────────────────────┴────────────────────────┴─────────────────────────┤
│  👤 동석자 · "예산 먼저"                                          (6초)   │
└──────────────────────────────────────────────────────────────────────────┘
```

**요소는 넷뿐입니다** — 헤더 / 반대사유 / 필수 항목 / 카드.
미팅 중 곁눈질로 읽어야 하므로 더 늘리면 안 됩니다.

**세 열이 각각 다른 질문에 답합니다** — 좌: 상대가 뭘 걸고 있나 → 중: 내가 뭘 안 했나 →
우: 지금 뭘 해야 하나. **상황 → 의무 → 행동** 순서입니다.

**반대사유(1층)와 필수 항목(2층)은 성격이 다릅니다.**

| | 반대사유 | 필수 항목 |
|---|---|---|
| 무엇의 상태 | 상대의 상태 | 내 행동의 완료 여부 |
| 상태 수 | 5개 | **2개** |
| 방향 | 오르내림 · **재발 있음** | **단조 증가** |

**신호등 순서는 미팅 중에 바뀌지 않습니다.** 색·스티커·근거 줄만 갱신됩니다.
우선순위는 카드가 담당합니다. 항목이 움직이면 곁눈질로 못 읽습니다.

## 4. 영업 템플릿

### 4-1. 엔진과 템플릿을 분리합니다

```
        ┌─────────────────────────────────────┐
        │       엔진 (모든 영업 유형 공통)     │
        │  전사 · 항목 매칭 · 상태 추적       │
        │  · 백채널 · 리포트 생성             │
        └──────────────┬──────────────────────┘
                       │  템플릿을 끼운다
        ┌──────────────┼──────────────┬──────────────┐
        ▼              ▼              ▼              ▼
    첫 미팅        제안·견적       클로징        갱신·해지방어
```

**엔진·화면·리포트는 동일하고 갈아끼우는 건 템플릿뿐입니다.**
엔진에 영업 유형 분기를 하드코딩하지 않습니다.

### 4-2. 템플릿에 들어가는 것

| 구성 | 무엇 | 예 |
|---|---|---|
| **1층 반대사유 풀** | 상대가 걸릴 만한 것 **약 30개** | 보험료 부담 · 필요성 의문 · 타사 비교 · 가족 상의 · 가입 시기 |
| **2층 필수 항목** | 반드시 다뤄야 하는 것 **12개 이하** | 해지환급률 · 면책 기간 · 청약철회권 |
| **표현 사전** | 각 항목이 실제로 어떤 말로 나오는지 | 예산 → "금액이 좀" "위에 물어봐야" "여력이…" |
| **해결 조건(슬롯)** | 무엇이 나와야 🟢으로 볼지 | 예산 → 금액 + 승인 절차 **둘 다** |
| **차단 신호** | 무엇이 나오면 취소되는지 | 승인 절차 → "위에서 좀" "보고를 한 번 더" |
| **프리로드 규칙** | 어떤 상황에 어떤 항목을 미리 켤지 | "2차면 1차 미해결 자동 이월" |

**슬롯이 🟡(일부 끝남)을 자동으로 정의합니다.** 슬롯이 없으면 "일부"를 사람이 매번
판단해야 하고, 판단 기준이 없으면 **채점할 수 없습니다.**

### 4-3. 예시 — 보험 상담

법으로 설명 의무가 정해져 있어 2층이 명확한 좋은 사례입니다.
제품이 보험 전용이라는 뜻은 아닙니다.

**금융소비자보호법 제19조 설명의무** 🔍 — 보장성 상품에서 설명해야 하는 것:
보장성 상품의 내용 / 보험료 / 보험금 지급 제한 사유 및 절차 / 위험보장의 범위 /
그 밖에 대통령령으로 정하는 사항

**소비자 권리** 🔍 — 청약철회권, 위법계약해지권(위법 사실을 안 날부터 1년 이내)

**"3대 기본지키기"** 🔍 — 청약서 부본 전달 · 약관 전달 및 중요내용 설명 · 계약자 자필서명.
이행하지 않으면 계약일로부터 3개월 이내 청약철회·환급이 가능합니다.
**이것이 2층의 하한선입니다.**

⚠️ 제19조 5호의 "대통령령으로 정하는 사항" 세부 목록은 아직 확인하지 못했습니다.
실서비스에는 법무 검토를 거친 확정판이 들어가야 합니다.

### 4-4. 사전 브리핑을 재정의합니다

| | 회의록 제품이 하던 것 | 우리가 더하는 것 |
|---|---|---|
| 재료 | CRM · 이메일 · 캘린더 자료 | **지난 미팅의 미해결 상태** |
| 성격 | 모아서 보여줌 | **이어 붙임** |
| 예시 | "A사 최근 메일 3건" | "예산 승인이 31:20에 재발했고 그대로입니다" |

둘 다 화면 ①에 넣되 **위쪽(우리 것)이 먼저** 나오게 배치합니다.

### 4-5. 템플릿 제작이 진짜 비용입니다

바이브 코딩이 해결해 주지 않는 두 번째 항목입니다.
템플릿 1종 = 사람이 항목을 정의하고 표현 사전을 붙이는 일 = 며칠.

**다만 이 비용을 평가 데이터 작업과 합칩니다.**

```
fixture 라벨링 (전원이 어차피 하는 일)
   → 실제 발화에 항목이 붙는다
   → 표현 사전에 자동 적재
   → 라벨링할수록 사전이 두꺼워진다
```

수기 예문은 **씨앗 5개**만 쓰고 나머지는 자라게 합니다.

## 5. 냉정한 검토

### 5-1. 음성으로 자동 체크 — 어디까지 되나 🔍

| 단계 | 되나 | 이유 |
|---|:--:|---|
| 아직 안 나옴 | ✅ | 그 얘기가 안 나온 건 확실히 압니다 |
| 말은 나왔음 | ✅ | 해당 항목 얘기를 했는지는 잡힙니다 |
| **충분히 설명함** | ❌ | **기준을 정할 수 없습니다** |

```
"해지환급금 설명하셨나요?"

"해지하시면 좀 손해 보세요"           ← 말은 했다. 설명일까?
"3년 내 해지 시 낸 돈의 40%만 돌려받습니다"  ← 이게 설명이다
```

**★ 정확도 문제가 아니라 안전 문제입니다.**
"설명 완료"라고 잘못 표시되면 사용자가 안심하고, 그게 법정 의무 미이행을 만듭니다.

**그래서 이렇게 설계합니다.**

- 언급이 감지되면 **체크박스가 자동으로 채워집니다** (미팅 중 방해 없음)
- 다만 라벨은 **`언급`** 입니다. `완료`가 아닙니다
- **최종 확인은 미팅 종료 화면에서** 사람이 합니다
- 리포트에 `언급됨`과 `확인됨`을 **구분해 기록**합니다

**정확도가 완벽하지 않아도 제품이 안전하고, 오히려 사용자가 신뢰합니다.**

### 5-2. 차수별 맞춤 — 어디까지 되나

| | 무엇 | 판정 |
|---|---|---|
| **이월** | 1차 미해결을 2차에 켠 채 시작 | ✅ 매우 쉬움 |
| **선택** | 이 고객에게 켤 항목을 골라내기 | ✅ 쉬움 |
| **생성** | 이 고객만을 위한 새 항목 만들기 | ❌ **하면 안 됨** |

```
1차  "예산 부담" 생성
2차  "가격이 비싸다" 또 생성      ← 같은 얘긴데 다른 항목
3차  "돈이 좀" 또 생성
     → 신호등이 30개로 불어남 → 채점 불가
```

**프리로드 규칙 — 전부 규칙으로 처리됩니다**

| 차수 | 규칙 |
|---|---|
| 1차 | 유형별 기본 세트 5개를 켜고 시작 |
| 2차 | 1차 미해결 → **무조건 켜짐** / 1차에 나온 것 → 위로 / 안 나온 기본 → 아래로 |
| 3차+ | 2회 연속 미해결 → **최상단 + 경고** / 매번 나오는 항목 → "이 고객의 핵심 장벽" |

**AI가 만들어내는 게 아니라 골라내는 것입니다.**

### 5-3. 미팅 중 화면을 볼 수 있나 🔍

| 상황 | 볼 수 있나 |
|---|---|
| 화상 미팅 (Zoom·Meet·Teams) | ✅ 이미 보고 있음 |
| 사무실 대면 | ✅ **태블릿 영업지원이 업계 표준** |
| 카페 대면 상담 | ✅ 같음 |
| 폰만 있는 상황 | ⚠️ 힐끗 |

**원본에서 뒤집힌 부분입니다.** 국내 보험업계는 이미 설계사에게 태블릿을 지급해
고객관리·가입설계·전자서명을 현장에서 처리합니다.

다만 그 태블릿은 **고객에게 보여주는 공용 화면**입니다.
AI 코칭 문구는 거기 띄울 수 없습니다.

> **팀 결정: 영업사원 본인만 보는 화면(2nd 디바이스)이 항상 존재한다고 가정하고 설계합니다.**
> 이건 검증된 사실이 아니라 **채택한 설계 가정**입니다.

**그리고 국내 생명보험 가입의 93%가 설계사·GA(대면·전화) 채널입니다** 🔍.

### 5-4. ⚠️ 그런데 MVP는 화상으로 잡았습니다

**시장 판단이 아니라 난제를 하나로 유지하기 위한 선택입니다.**

화상은 내 마이크와 상대 목소리가 **물리적으로 다른 채널**이라 화자 분리가 공짜입니다.
대면은 마이크 하나에 둘이 들어와 화자 분리 모델이 필요하고, 그러면 **ML 난제가 두 개**가 됩니다.

이 프로젝트의 진짜 난제는 이미 하나 있습니다 — **항목 매칭과 상태 추적, 특히 재발.**
여기에 화자 분리 정확도를 얹으면 **재발 재현율이 낮게 나왔을 때 모델 탓인지 분리 오류 탓인지
구분할 수 없습니다.** 최종 발표 Q&A에서 방어가 불가능해집니다.

**대면은 W4에 조건부로 추가합니다.** 영업사원 목소리를 사전 등록해 2분류로 푸는 방식이고,
정확도가 목표에 못 미치면 **사후 리포트 전용**으로 강등합니다.

> 발표에서 이 구분을 반드시 말합니다 —
> *"대면을 못 하는 게 아니라, 실시간 정확도를 보장할 수 있는 조건부터 만들었습니다."*
