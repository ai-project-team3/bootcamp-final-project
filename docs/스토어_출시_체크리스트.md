# Google Play 출시 체크리스트 (2026-09-23)

작성 이종훈 · **계정·콘솔·서류는 조장, 화면 넷은 안치영, 문서 초안은 조장.**

**한 줄.** 대본 빌드를 **오늘** 내부 테스트에 올리고, 이번 주 안에 비공개 테스트를 열어 14일 시계를 돌린다.
그동안 「없으면 반려」 화면 넷을 넣고 빌드를 갱신한다. 정식 출시 신청은 14일 뒤.

---

## 이 문서의 범위

**확인한 것** — Play 정책 중 우리에게 걸리는 항목(개인 계정 14일 테스트 · `com.example` 금지 · 가족 정책 · 데이터 안전), 레포의 현재 상태(패키지·권한·targetSdk).
**확인하지 않은 것** — 계정 종류(조장 확인 필요) · 최종 발표 날짜 · 심사 소요일(경험칙 「며칠~2주」이지 보장이 아니다).
**Play 정책은 자주 바뀐다.** 콘솔에 들어갔을 때 여기와 다르면 **콘솔이 맞다.**

## 1. 심사는 세 겹이다

| 단계 | 심사 | 시간 | 우리 빌드 |
|---|---|---|---|
| 내부 테스트 (≤100명) | 없음 | 분 | **대본 빌드 그대로** |
| 비공개 테스트 | 가벼움 | 시간~며칠 | 같은 빌드. **여기서 14일 시계 시작** |
| 정식 출시 | 본심사 + 가족 정책 | 며칠~2주 | 「없으면 반려」 넷이 **다 들어간** 빌드 |

**14일 규칙** — 2023-11-13 이후 만든 **개인** 개발자 계정은 테스터 **12명 이상이 14일 연속** 참여한 비공개 테스트를 거쳐야 정식 출시 권한을 신청할 수 있다. 조직 계정은 없음. **빌드를 갱신해도 시계는 리셋되지 않는다.**

**바꿀 수 없는 것 하나** — 패키지 이름. 첫 업로드 뒤 영구. `kr.clap.otto` 로 정했다(09-23). 업로드 전이면 바꿀 수 있다.

## 3. 조장 — 콘솔에서 할 일 (순서대로)

1. **개발자 계정** — 있으면 종류 확인(개인/조직). 없으면 오늘 등록($25 · 개인은 신원 확인 며칠)
2. **앱 만들기** — 이름 「오또」 · 기본 언어 한국어 · 앱(게임 아님) · 무료
3. **내부 테스트** → `app-release.aab` 업로드 → 팀 4명 이메일 → 링크로 설치 확인
4. **앱 콘텐츠 선언** (아래 §5 답안대로): 개인정보처리방침 URL · 광고 없음 · **대상 연령 3~7** · 데이터 안전 · 콘텐츠 등급 설문 · 정부 앱 아님 · 뉴스 앱 아님
5. **비공개 테스트** 만들기 → 테스터 12명 이메일 목록 → 공개 → **시작일을 적어 둔다**
6. 14일 뒤 **「프로덕션 액세스 신청」** → 승인되면 정식 출시 신청
7. 스토어 목록 — 짧은 설명 · 긴 설명 · 스크린샷 8장(치영 화면 검사로 찍음) · 아이콘 512px · 특성 그래픽 1024×500

## 6. 일정 (최종 발표 날짜를 넣어 다시 계산)

```
D+0  (오늘)   내부 테스트 업로드 · 계정 확인
D+2~3        비공개 테스트 공개 → 14일 시작
D+3~16       화면 넷 · 네트워크 · /judge · /stt 붙이며 빌드 갱신 (versionCode 2, 3, …)
D+17         프로덕션 액세스 신청 (개인 계정일 때)
D+17~31      본심사 (가족 정책) — 여기는 우리가 못 줄인다
```

**최종 발표가 D+31 안이면** 정식 승인 없이 **비공개 테스트 링크로 시연**한다. "심사 진행 중 · 테스터 12명이 n일째 사용 중" 이 그 자체로 검증 근거다.
