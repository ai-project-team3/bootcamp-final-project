## 안건별 배경

### ⭐1. 연령 범위
- **배경**: 평균 연령은 만 5세로 정했다. 5세만 대상은 아니다. 기획안은 3~7세, 멘토 회의록은 4~7세
- **왜 지금**: 질문 난이도 · 템플릿 · 미션 난이도의 위아래 폭이 이 범위로 정해진다
- **선택지**: 3~7세 유지 / 4~7세 / 4~6세

### ⭐2. 교육적 가치를 설계에 넣을지
- **배경**: 선생님 피드백 — "아기에게 폰을 쥐어주고 싶지 않다". WHO는 3~4세 앉아서 보는 화면 1시간 이하와 보호자와 읽기 · 이야기를 권한다
- **메시지**: "화면을 더 주자는 게 아니라, 어차피 켜는 시간을 혼자 보는 영상에서 어른과 함께 짓는 이야기로 바꾸자"
- **설계 후보**
  - [ ] 끝이 있는 설계 — 책 한 권이 끝나면 다음 책 자동 권유 없음, "엄마한테 보여주러 가자"로 폰 밖으로
  - [ ] 어른 시작 화면 — 이야기 시작은 어른이 누른다 (조사3의 남은 권수 표시와 합침)
  - [ ] 부모 모드 하루 사용 한도
  - [ ] 화면 밖 놀이 한 줄 제안 — 책 끝 또는 부모 기록
- **과장 금지**: "발달시킨다", "효과 입증"은 쓰지 않는다

### ⭐3. 수준 3단계 확정
- **배경**: 안치영 수준표

| 단계 | 답하는 질문 | 맞는 동화 |
|---|---|---|
| 고르며 짓기 | 무엇 · 누구 + 그림 고르기 | 같은 일 3번 반복, 장면 4~5개 |
| 이어 짓기 (첫 시작) | 어디 · 뭐 했어 + 그림 달린 '왜' | 문제 → 해결 1번, 장면 6개 |
| 까닭 짓기 | '왜' · '어떻게' 열린 질문 | 시도 → 실패 → 다시 → 해결, 장면 6~8개 |

- **함께 정할 것**: 신호 2턴 연속이면 이동 · 매 세션 처음 2턴으로 다시 판단 · 템플릿 3턴째 확정 — 그대로 채택할지
- **판단 신호 (안치영 정리)**: 중심은 S1 '왜 · 어떻게'에 이유 · 방법을 담아 답했나, S2 배경 · 원인 · 시도 · 결과를 스스로 채웠나. 답 길이 · 잇는 말은 보조. 마음 말하기 · 응/아니 · 선택지로 고른 답 · 답까지 걸린 시간은 판단에 안 씀
- **확인할 점 셋**
  - **처음 2턴에 '왜' 질문이 하나는 있어야 한다.** "어디로 가?" "누구를 만났어?"만으로는 S1 신호가 안 나와 처음 판단을 할 수 없다
  - **낮은 단계에서도 가끔 '왜'를 물어야 올라갈 수 있다.** 고르며 짓기로 내려간 아이가 '왜' 질문을 한 번도 안 받으면 S1이 나올 기회가 없어 계속 그 단계에 머문다
  - **S2의 "스스로"를 정의한다.** 템플릿이 원인 · 결과를 하나씩 물으면 답한 칸은 전부 "채웠다"가 된다. 예: 묻지 않은 요소까지 말했을 때만 스스로로 센다
- **용어**: 내부에서도 "발달 상태 파악"이 아니라 **"이야기 난이도 수준"**으로 부른다. 부모 기록 · 발표 문구가 진단처럼 새는 걸 막는다

### ⭐4. 템플릿 수준 재배정
- **배경**: 같은 이야기 구조를 두 사람이 다른 수준에 놓았다
  - 박진웅: 도전-성취형(실패 → 재도전 → 성공)을 **수준 1**
  - 안치영: 시도 → 실패 → 다시 시도는 **가장 어려운 까닭 짓기**
  - 박진웅 템플릿 C · D가 둘 다 수준 2, 수준 3 템플릿 없음
- **결과**: 지금 mock 데이터로 돌리면 쉬운 아이에게 어려운 구조의 동화가 나간다
- **권고**: 안치영 수준표를 기준으로 박진웅이 템플릿 수준을 다시 붙인다. 수준 1용 "반복 3번" 템플릿이 하나 필요하다

### ⭐5. 무응답 흐름
- **배경**: 안치영 안 — 기다림(쉬운 질문 5초 · 어려운 질문 8초) → 더 쉬운 질문으로 한 번 → 그림 선택지 3번 교체 → 마스코트가 골라줌. 어른만 말하면 "지호는 어떻게 생각해?" 한 번
- **함께 정할 것**: 선택지는 그림으로, 순서는 섞고, "응/아니"로 확정하지 않는다 (아이는 뒤에 들은 걸 고르고, 예/아니오에 "응"으로 기운다)

### ⭐6. 가짜 아이 3명
- **배경**: mock.js는 성향 3종(말하기형 · 고르기형 · 그리기형), 계획 문서는 말 잘함 · 짧게 답함 · 말 안 함
- **권고**: 성향 3종 유지. 말 안 하는 아이는 결국 고르기형으로 간다. **고르기형의 첫 턴을 "무응답 → 쉬운 질문 → 선택지"로** 시작해 무응답 흐름을 시연에서 보여준다. 말하기형에는 수준이 한 칸 바뀌는 순간을 넣는다

### ⭐7. 미션 난이도 기준
- **배경**: 기준이 셋이다

| 동작 | 계획 §1-4 | 안치영 | 박진웅 |
|---|---|---|---|
| 탭 | 쉬움 | 쉬움 | 수준 1 |
| 문지르기 | 보통 | 쉬움 | 수준 2 |
| 끌어서 던지기 | 보통 | 보통 | 수준 2 |
| 끌어다 목표에 놓기 | 보통 | 어려움 | 수준 2 |
| 당겼다 놓기 | 어려움 | 어려움 | 수준 3 |

- **방식도 다르다**: 안치영은 말 수준과 따로(혼자 성공하면 올리고 도와주기면 내림), 박진웅은 말 수준에 묶음
- **권고**: 안치영 방식. 말 잘하는 아이가 손 조작도 잘한다는 근거가 없다. 표는 안치영 표로 통일하고 9/18 피드백에서 확인

### ⭐8. 도감 구조
- **배경**: 프리셋 조합과 말로 만들기 둘 다 도감에 쌓인다. 기존 기획안은 2×3 첫 칸 주인공 고정. 4~5세는 화면 밖에 숨은 것을 못 찾으므로 한 화면에 다 보여야 한다
- **선택지**: 주인공 줄 · 친구 줄 분리 / 한 격자에 섞고 이야기 시작 때 주인공 고르기

### ⭐9. 결말 도감 → 해결 방법 도감
- **배경**: 박진웅이 동화 21권을 분석했더니 거의 전부 기쁜 결말. 모든 결말이 기쁘면 "결말 종류"로는 모을 게 없다
- **권고**: 결말은 기쁜 결말로 간다. 도감은 **해결 방법**을 모은다 — 스스로 · 친구와 함께 · 어른에게 도움 요청 · 꾀를 내서
- **근거**: 박진웅 시범에서 "해결 칸 하나가 사실상 속성을 결정"했다. 해결 방법이 곧 이야기의 차이다
- **영향**: 조사3 업적 5번 조건을 "해결 방법 도감 한 칸"으로 바꾼다

## 부록 — ComfyUI 검토 (안건 10)

**선생님 말씀대로 품질을 낮게 잡으면 좋은 선택지다.** 가장 큰 장점은 **이미지 생성까지 우리 서버에서 끝나 아이 데이터가 외부 AI 회사로 전혀 나가지 않는다**는 것이다. 음성 인식을 우리 서버 Whisper로 옮긴 판단과 같은 방향이다.

| 항목 | 확인한 사실 | 판단 |
|---|---|---|
| ComfyUI | GPL-3.0. 워크플로를 프로그램에서 실행하는 로컬 API · 웹소켓 제공. SD1.5 · SDXL · Flux 지원, 저사양 메모리 관리 기능 `[확인]` | 백엔드에서 호출 가능 |
| 라이선스 의무 | GPL-3.0은 소프트웨어를 **배포할 때** 소스 공개 의무가 생긴다. 서버에서 돌리기만 하면 해당하지 않는 것으로 해석된다 `[해석]` | 앱에 넣어 배포하지 않는다 |
| 투명 배경 | ComfyUI-layerdiffuse 노드: Apache-2.0, **SDXL · SD1.5만 지원**, 문서상 마지막 갱신 2024-03 `[확인]` | 유지보수 위험. 대안은 배경 제거 노드 |
| 모델: FLUX.1 schnell | Apache 2.0, 상업 이용 가능 `[확인]` | 사용 가능. **조사3에서 뺀 건 BFL API(입력을 학습에 씀)였지 공개 가중치가 아니다** |
| 모델: FLUX.1 dev | 비상업 라이선스로 알려짐 `[미확인]` | 쓰지 않는다 |
| 모델: SDXL base 1.0 | CreativeML Open RAIL++-M `[확인]`. 모델 카드가 스스로 "읽을 수 있는 글자를 못 그림", "사람 얼굴이 제대로 안 나올 수 있음"을 한계로 적음 `[확인]` | 글자는 앱 자막으로 처리, 종이 인형이라 얼굴 영향 작음. 상업 조건은 원문 확인 필요 |

**주의할 것 셋**
1. **안전 필터가 사라진다.** 기획안의 "필터 2겹 + 1"에서 +1이 이미지 API 자체 필터였다. 자체 서버에는 없으므로 **부적절 이미지 분류 노드를 반드시 붙인다.** 아동 앱이라 빠뜨리면 안 된다
2. **GPU 서버가 필요하다.** Whisper와 같은 GPU를 쓸 수 있는지 메모리 합을 실측한다. 부트캠프가 GPU를 제공하는지 확인한다
3. **운영을 누가 하나.** 워크플로 파일 관리 · 모델 파일 · 큐 · 장애 대응이 역할 3에 붙는다. 데모 규모에서는 감당할 만하지만 W1 스파이크에서 한 번 띄워봐야 안다

**비교 테스트 (최민우, 조사 4에 추가)**
- 같은 설명("초록색 티라노, 종이 인형 그림체")으로 ComfyUI(SDXL 또는 FLUX.1 schnell) vs OpenAI 이미지 저품질 각 3장
- 장당 시간 · 투명 배경 품질 · 같은 캐릭터 유지 · 부적절 이미지 필터 구성 방법

- **ComfyUI 포트는 외부에 열지 않는다.** FastAPI만 호출한다. 외부 유료 API 노드는 끈다

- **라이선스**: ComfyUI GPL-3.0은 서버에서만 쓰면 공개 의무 없음 `[해석]`. **AGPL 노드(LLM_party · NudeNet 원본)는 붙이지 않는다**

## 부록 5 — 만든 그림 재활용 (안건 ⭐26 · 2026-09-15)

> **9/15 수정 — ComfyUI(GPU 제공)로 바뀌며 달라진 점**
> 장당 비용이 없어져 **비용 때문에 재활용할 이유는 사라졌다.** 그래도 재활용이 필요한 이유는 셋이 남는다.
> 1. **일관성**: 같은 트리케라톱스를 쪽마다 새로 그리면 모습이 달라진다(최민우 실측). 아이가 중간 확인에서 "이대로"를 누른 그림이 책에서 바뀌면 확인한 의미가 없다
> 2. **대기 시간**: 생성은 공짜여도 몇 초는 걸린다. 모호한 낱말 선택지 · 2턴 사건 그림은 0초여야 한다
> 3. **알아보기**: 다음 이야기에서 "내 공룡", 다른 그림 나라에서 "내 인형"을 알아보려면 같은 그림이어야 한다 (부록 6 의도된 섞임)
>
> **그래서 아래 표에서 바뀌는 것**
> - 1층 미리 만든 공용 소품 → **0초가 필요한 것만** (모호한 낱말 프리셋 · 장소별 사건 그림). 배경 · 미션 물체는 그때그때 생성해도 된다
> - 2층 서버 공용 캐시 → **하지 않는다.** 서버에 그림을 남길 이유가 없어져 "서버는 아무것도 저장하지 않는다" 원칙을 그대로 유지한다
> - 3층 · 4층 아이별 그림 · 아이가 그린 그림 → **그대로 유지**
> - 한 이야기 안에서 확정 캐릭터 재사용 · "바꿀래"를 생성 없이 처리하는 방법 → **그대로 유지** (비용이 아니라 속도 · 일관성 목적)

**왜 필요한가**: 매번 새로 그리면 ① 기다리는 시간이 늘고 ② 같은 캐릭터가 쪽마다 달라지고(최민우 실측) ③ GPU를 오래 쓴다. 한 번 만든 그림을 다시 쓰면 세 문제가 같이 줄어든다.

### 무엇을 어디서 다시 쓰나

| 층 | 무엇 | 어디에 둠 | 누가 봄 | 판단 |
|---|---|---|---|---|
| **1. 미리 만든 공용 소품** | 모호한 낱말 프리셋(20개 × 3) · 장소 배경 · 장소별 사건 그림(로켓 흔들림) · 미션 물체(비구름 · 물대포 · 우물) · 효과 연출 | 앱에 넣거나 서버 공용 저장소 | 모든 사용자 | ✅ **기본 경로.** 팀이 ComfyUI로 같은 그림체로 미리 만든다. 대기 0초 |
| **2. 새로 만든 공용 소품 캐시** | 이야기 중 새로 생성했지만 **정해진 낱말 조합만으로 만든** 그림 (예: `triceratops · red · paper-cutout`) | 서버 공용 저장소 | 모든 사용자 | ⚠️ 조건부. 같은 조합이 다시 나오면 생성 없이 바로 씀 |

### 한 이야기 안에서

- **확정한 캐릭터는 모든 쪽에 같은 레이어로.** 중간 확인에서 고른 빨간 트리케라톱스를 1~6쪽에 다시 그리지 않고 같은 투명 그림을 옮겨 놓는다 → 쪽마다 모습이 달라지는 문제가 사라진다
- **배경은 장소당 한 장 + 쪽별 소품만 바꿈.** 우주 배경 한 장에 로켓 · 불 · 우물 같은 소품 레이어를 얹는다
- **"바꿀래"는 대부분 다시 생성하지 않는다**

| 바꿀 것 | 방법 | 생성 |
|---|---|---|
| 크기 | 레이어 크기 조절 | 안 함 |
| 표정 | 눈 스티커 · 표정 4장 중 교체 (기획안) | 안 함 |
| 색 | 종이 인형 그림체는 면이 단색이라 색 영역만 바꿈. 어색하면 편집 모델 한 번 | 대부분 안 함 |
| 모양 · 종류 | 공용 소품에서 찾고, 없으면 생성 | 필요할 때만 |

- 지호가 또 "트리케라톱스!"라고 하면 **폰의 소품함에서 지난번 빨간 트리케라톱스를 먼저** 프리셋 3장 중 하나로 보여준다. 아이는 "내 공룡"을 알아본다

**후보 4종 (팀이 모은 참고 이미지)**: ① 양모 펠트 3D 인형 ② 아이 크레용 그림 ③ 한국 전래동화 수채 · 색연필 ④ 수채화 캐릭터

**방향은 좋다.** 부모가 설정의 주인이라는 원칙과 맞고, 상위 요금제 "그림체 묶음"으로도 쓸 수 있다. ComfyUI에서는 그림체를 설정 묶음으로 바꿔 끼우면 된다.

**다만 "프롬프트만 바꾸면 된다"보다 할 일이 많다**

| 걸리는 곳 | 내용 | 대응 |
|---|---|---|
| **그림체 일관성** | 프롬프트 단어만 바꾸면 쪽마다 그림체가 흔들린다 | 그림체 하나 = **모델 · 스타일 LoRA 또는 기준 이미지 · 스타일 단어 · 제외 단어 · 생성 설정** 묶음으로 고정. 같은 대상(예: 사자)을 4종으로 뽑아 비교하는 기준 시트를 만든다 |
| **재활용 캐시가 4배** | 부록 5의 공용 소품(프리셋 60장 · 배경 · 사건 그림 · 미션 물체)을 그림체마다 따로 만들어야 한다 | 캐시 열쇠에 그림체 버전을 넣는다. **1차는 2종만** |
| **아이 그림과 한 쪽에 섞임** | 아이 크레용 그림(뿌뿌)은 원본 그대로 쓴다. 펠트 3D 세계에 들어가면 그림체가 섞인다 | **섞임을 재미 요소로 쓴다 (9/15 조장).** 아래 "의도된 섞임" 규칙 참고 |
| **레이어 분리** | ③처럼 배경과 인물이 한 장에 그려진 그림체는 만지는 책(투명 레이어)과 안 맞는다 | 모든 그림체를 **캐릭터 · 소품 · 배경 따로** 뽑을 수 있는지 확인. 배경 제거가 번지는지(펠트 털 · 수채 번짐) 시험 |
| **주인공이 바뀐다** | 도감의 주인공은 한 그림체로 만들어져 있다 | **다시 뽑지 않고 원래 그림체 그대로 데려간다.** 아이가 "내 인형"을 바로 알아보고 생성도 줄어든다. 세계 그림체는 책 한 권 단위로 고정 |
| **사람 그림이 실사로 흐름** | 최민우 실측에서 아이가 사진처럼 나왔다. 3D 계열(①)에서 더 흔하다 | 사람은 인형 · 그림 느낌이 유지되는지 그림체별로 확인. 실사처럼 나오면 그 그림체는 동물 · 소품 전용 |
| **한국 소재** | ③ 한옥 · 한복을 해외 데이터 위주 모델이 제대로 못 그릴 수 있다 | 시험 대상. 박진웅 F패턴(전래 민담형)과 짝이 맞아 가치는 크다 |
| **참고 이미지 저작권** | ①과 ④에 스톡 사이트 워터마크가 보인다(④ "크라우드픽"). ②는 그리기 강좌 이미지로 보인다 | **팀 토론용 분위기 참고로만.** 기준 이미지 · LoRA 학습 · 참조 입력에 넣지 않는다. 기준 이미지는 우리가 공개 모델로 새로 만든다 |

**의도된 섞임 — "내 캐릭터가 다른 그림 나라에 들어간다"** (9/15 조장 방향)

섞임이 재미가 되려면 **실수가 아니라 연출로 보여야** 한다.

| 무엇 | 그림체 | 이유 |
|---|---|---|
| **세계** — 배경 · 프리셋 · 미션 물체 · 새로 만든 등장인물 | 부모가 고른 **한 그림체로 고정** | 생성물끼리 섞이면(수채 나무 옆에 펠트 바위) 오류로 보인다 |
| **아이 것** — 아이가 그린 그림 · 도감 주인공 · 전에 만든 친구 | **원래 그림체 그대로** | "내가 그린 애", "내 인형"이 한눈에 튄다. 기획안 차별점 "아이 그림이 원본 그대로 등장"이 더 드러난다 |

**연출 규칙**
- 아이 것은 **종이 인형처럼 흰 오려낸 테두리 + 세계 조명에 맞춘 그림자**를 얹어 "무대에 올라온 인형"으로 보이게 한다. 그림 자체는 바꾸지 않는다. 제품 이름 "인형극"과도 맞는다
- 크기는 세계 기준으로 맞춘다 (펠트 공룡 옆에서 크레용 지호가 너무 크거나 작지 않게)
- 새 그림체 나라에 처음 들어갈 때 마스코트가 한 줄로 알려준다: *"지호가 폭신폭신 나라에 왔어!"* — 그림체가 이야기 속 장소의 성격이 된다

**9/18 피드백에서 볼 것**: 아이 · 부모가 섞인 장면을 "재밌다"로 보는지 "깨졌다"로 보는지. 펠트 3D처럼 입체감이 강한 그림체와 평면 크레용의 차이가 제일 크니 그 조합을 꼭 보여준다

**1차 권고**
- 그림체 **2종**: 섞임 대비가 잘 보이는 조합으로. 예: ② 크레용 + ① 펠트 3D, 또는 ② 크레용 + ④ 수채화
- 부모 모드 설정 화면에서 고름. 아이 화면에는 없음. 유료 · 잠금 표시 없음 (1차는 결제 없음)
- 나머지 2종은 발표 자료에서 "그림체 묶음 확장" 예시로

**역할 3 시험 항목**: 같은 대상(사자 · 트리케라톱스 · 사람 아이) × 그림체 4종 → 그림체 유지 · 배경 제거 품질 · 사람이 실사로 흐르는지 · **아이 크레용 그림에 오려낸 테두리 · 그림자를 얹어 각 세계에 넣었을 때 연출로 보이는지**

### 부딪히는 곳 셋 — 정해야 한다

| # | 데모 시나리오 | 엔드픽처 초안 | 권고 |
|---|---|---|---|
| ⭐28 | 남은 권수를 **어른 화면 칩**으로만 표시 | 아이 화면 오른쪽 위 **별 3개 + 날아오는 애니메이션** (결정 2) | **결정: 별은 재화다.** 대기 화면 오른쪽 위에 아이콘 + **숫자**, 아이 화면도 동일. 시작 시 차감 + 날아오는 애니메이션. **0일 때 [이야기 만들기]를 누르면 마스코트가 말풍선으로 안내**([책장 보기] [괜찮아], 누를 때 한 번만). 구매하면 늘어남 (결제는 1차 미구현, 구매 버튼은 부모 모드에만) |
| ⭐29 | "싫어" → 카드로 고르게 | "싫어" → 바로 다시 그림 | **결정: 한 번 묻고 다시 그린다.** "어떤 게 마음에 안 들어?"를 **열린 질문으로** 묻고 그 말을 반영해 다시 그린다. 카드 없음. 남은 횟수는 버튼 아래 **1/2 · 2/2**. 다 쓰면 만든 3장 중 고르기 |
| ⭐30 | 선택지 카드가 **처음부터** 떠 있음 | 선택지는 **무응답일 때만** | **결정: 모든 질문을 열린 질문으로 통일한다.** 카드는 무응답 · 모호한 말 확인 · 아이가 직접 그리려 할 때만 나온다. 기획안 화면 5 원안으로 복귀 |

### ⭐30 보충 — 열린 질문으로 통일할 때 딸려 오는 일

카드는 **무응답 · 모호한 말 확인 · 직접 그리기**에만 나온다. 그래서 세 가지를 같이 정해야 한다.

| 딸려 오는 일 | 대응 | 담당 |
|---|---|---|
| **답이 무한해진다** ("공룡이랑 수영장!") | 미리 만들어 둔 **장소 유형 8~12개**에 LLM이 맞춘다. 맞는 게 없으면 배경을 새로 생성 (GPU 자체 서버라 가능) | 박진웅 · 최민우 |
| **장소별로 짜 둔 미션이 깨진다** | 미션을 장소에 묶지 않는다. 불 끄기 · 물 채우기 같은 **뼈대를 두고 소품 그림만** 장소에 맞춰 바꾼다 | 최민우 |
| **프리셋 재활용이 줄어 생성이 는다** | 자주 나오는 답부터 프리셋으로 쌓는다. 처음 나온 장소는 생성하고 폰 소품함에 남긴다 (⭐26) | 최민우 |
| **데모에서 마이크 없이 시연** | 답 후보 5개 방식 유지 (안치영 대본). 카드가 없어도 시연은 돌아간다 | 안치영 |
| **부모 기록의 "말한 방식" 비율** | 골라서 답한 비중이 크게 준다. 원그래프는 그대로 두되 대부분 "말로"가 된다 | 리포트 담당 |

**얻는 것**: 아이가 말할 기회가 늘고, 탭으로 넘어가던 턴이 수준 신호가 되고, "말로 짓는 인형극"이라는 이름과 흐름이 일치한다

### 합치면 좋아지는 점

- **데모 한 번에 세 가지가 보인다**: 아이 선택이 이야기를 바꾸고(장소 3갈래), 어른이 개입할 자리가 있고(어른 칸 · 되물을 3초), 끝나면 부모에게 기록이 남는다(6축)
- 반응 예산은 데모 기준 **18~22번**(첫날 +4)이다. 초안의 상한 문제(결정 23)는 그대로 남아 있으므로 9/18 관찰로 정한다
