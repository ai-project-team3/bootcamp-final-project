# 같이 만들기 — 아이가 질문으로 답할 때 · 부정하는 답을 할 때 (설계)

> 10-08 · 치영(부모 협업 모드 담당) · 기능 업그레이드 세션 요청(사용자 지시).
> 기준: main `7fd13824`. 코드 변경 없음 — 구현은 기능 업그레이드 세션.
> ⚖️ 표시는 사용자 · 조장이 정할 것(§8).

## 0. 한 줄 요약

- **알아보기는 앱 규칙으로 먼저 합니다.** 순수 함수 `classifyCoopReply(아이 말, 오또 질문)` 하나가 다섯 가지로 가릅니다: 답 · 답 아님 · 질문 · 전제 부정 · 고쳐 말하기. 서버 판정에 「답의 종류」 칸을 더하는 일은 앱 규칙을 실기기 로그로 재 본 뒤에 정합니다(⚖️1).
- **질문이면** 그 질문에 짧게 대답하고 **같은 질문을 다시** 합니다. 사다리를 내려가지 않고 판정도 부르지 않습니다.
  - 오또 질문의 뜻을 물으면(「뭐를 넣어?」) 더 쉬운 말로 풀어 묻습니다.
  - 옆 어른을 부르거나 떠올리는 꼴로 물으면(「엄마, 우리 뭐 먹었지?」) **「잘 기억이 안 나」로 읽습니다.** 어른을 부르거나 기다리지 않고, 아이에게 돌려줍니다: 「생각나는 만큼만 말해 줘!」 + 더 쉬운 질문(§4-2 · 10-08 고침).
  - 세상 일을 물으면(「기린은 뭐 먹어?」) 1단계는 앱 문장으로 받고, 2단계는 서버 대사가 대답합니다(⚖️2).
- **부정이면** 무엇을 부정했는지 오또 질문과 견줘 봅니다.
  - 질문의 전제(동사 · 이름)를 부정했으면 사실로 받고(「안 줬구나!」), 전제 없는 질문으로 한 번 다시 묻습니다.
  - 「아니, ○○야」처럼 고쳐 말했으면 ○○를 답으로 받습니다.
  - 그냥 「아니」면 지금처럼 쉬운 질문으로 내려갑니다.
- **PR 셋:** ① 알아보기 + 질문 대응(앱) · ② 부정 대응(앱) · ③ 서버 대답(조장 · 측정). ①②는 측정 없이 단위 테스트로 갑니다.

서버 쪽:
- 판정 스키마(`backend/app/schemas/judge.py`)에는 `contradiction` · `no_longer_needed` · `unclear` 가 있습니다. 「답의 종류」 칸은 없습니다.
- 앱은 `contradiction` 을 읽기만 하고 쓰지 않습니다. 이미 찬 칸은 덮지 않습니다(`!diaryFilled`).
- 대사 프롬프트 `eval/line_prompt.md:22` 에 「답을 알려주지 않습니다」가 있습니다. 이 줄의 뜻은 「칸의 답을 대신 정해 주지 않는다」입니다. 아이가 물은 것에 대답하는 경우는 다루지 않습니다.

**위 표에서 지금 바로 생길 수 있는 잘못 둘** (이 설계의 ①에서 같이 막습니다):
1. 아이 질문이나 부정 문장이 `rejected` 에 들어가 사다리 끝에서 **책 칸 값이 된다** (「그게 뭐야?」가 problem 에).
2. 같은 질문을 두 번 하면 「같은 음절 → 하고 싶은 말」 규칙이 그것을 칸에 넣는다.

## 3. 알아보기 — `classifyCoopReply`

### 3-1. 앱 규칙으로 하는 까닭 (⚖️1 권고)

| | 앱 규칙 | 판정(Jev)에 칸 더하기 |
|---|---|---|
| 속도 | 즉시 — 질문이면 `/turn` 을 아예 안 불러 한 왕복(6초 안팎)을 아낀다 | 판정을 기다려야 한다 |
| 서버 꺼짐 | 그대로 동작 | 동작 안 함 |
| 바꾸는 것 | 앱 파일 하나 + 단위 테스트 | API(`guidelines/3` §3-2-1) · 판정 스키마 · `fixtures_judge` 다시 라벨 · 측정. 다른 필드 정확도가 흔들릴 수 있다(평평한 스키마 원칙 · `judge.py` 머리말) |
| 약점 | 억양을 못 본다(받아쓰기라 「?」가 없을 수 있다) — 낱말 규칙으로 메운다 | 뜻으로 가르니 애매한 말에 강하다 |

**권고:** 앱 규칙으로 시작하고, 갈린 결과를 로그에 남깁니다(§7). 실기기 두세 번의 로그로 틀린 비율을 보고, 높으면 그때 판정 칸을 정합니다. Laya 전환 실험(로컬)에 「답의 종류」를 같이 재 보는 것도 방법입니다.

### 3-2. 나누는 종류

```kotlin
// 새 파일 demo/CoopReplyKind.kt — 순수 함수, Android 의존 없음
internal sealed interface CoopReply {
    data object Answer : CoopReply                      // 지금 길 그대로
    data object NonAnswer : CoopReply                   // 「몰라」 · 「응」 · 그냥 「아니」 — 지금처럼 사다리
    data class AboutQuestion(val text: String) : CoopReply    // 오또 질문의 뜻을 묻는다 「뭐를 넣어?」 「그게 뭐야?」
    data class Recall(val text: String, val who: String?) : CoopReply   // 떠올리려는 말 「엄마, 우리 뭐 먹었지?」 — 뜻은 「잘 기억이 안 나」 (10-08 · 옛 이름 ToPartner)
    data class World(val text: String) : CoopReply            // 그 밖의 질문 「기린은 뭐 먹어?」 「오또는 어디 살아?」
    data class PremiseDenied(val stem: String, val noun: String?) : CoopReply   // 「안 줬어」 · 「기린 없었어」
    data class Corrected(val instead: String, val denied: String?) : CoopReply  // 「아니, 수영장이야」 · 「놀이터 말고 수영장」
}
internal fun classifyCoopReply(said: String, question: String): CoopReply
```

판정 차례(위가 먼저):

1. **답 아님:** 지금 `isNonAnswer` 그대로입니다. 단, 「아니」 · 「없어」 · 「싫어」 낱말 하나는 아래 3-4 의 「있었나 질문」 예외를 먼저 봅니다.
2. **질문:** 다음 가운데 하나면 질문으로 봅니다.
   - (a) 끝에 「?」가 있다.
   - (b) 묻는 말(뭐 · 뭘 · 뭐를 · 무엇 · 무슨 · 왜 · 어떻게 · 어디 · 누구 · 누가 · 언제 · 몇 · 어느)이 있고, 끝 어절이 물음 끝(야 · 예요 · 에요 · 니 · 냐 · 나 · 까 · 지 · 래 · 는데 · 어 · 아 · 해)으로 끝나며, **6어절 이하**다.
   - 빼는 것 — 대답 속 「뭐」(「뭐 그냥 놀았어」 · 「뭐더라… 아 츄러스」): 「뭐」 뒤에 「그냥 · 더라 · 였지」가 오거나 묻는 말이 첫 어절이 아니면서 7어절 이상이면 답입니다.
   - 질문을 셋으로 가르는 기준:
     - **Recall (10-08 고침 · 옛 ToPartner):** 첫 어절이 부르는 말(엄마 · 아빠 · 할머니 · 할아버지 · 이모 · 삼촌 · 선생님 …)이거나, 끝이 「~지?」 · 「~더라?」 회상 꼴이다(「우리 뭐 먹었지?」 · 「누구랑 갔더라」).
       - **옆에 어른이 있든 없든 같게 봅니다.** `partner` 조건은 뺍니다. 대응이 어른을 부르지 않으니 가를 까닭이 없고, 혼자 있는 아이의 「엄마, 뭐 먹었지?」도 떠올리려는 말입니다.
       - **스스로 답을 이었으면 답입니다.** 떠올리는 꼴 뒤에 말이 더 있으면(「엄마 우리 누구랑 갔지? 아 할머니!」 · 「뭐 먹었더라 츄러스」) 뒤쪽만 떼어 Answer 로 보냅니다. 판정에는 그 뒤쪽 말만 갑니다.
     - **AboutQuestion:** 오또 질문의 낱말을 가리키거나(「그게」 · 「그거」 · 「뭐를」 · 「뭘 말해」 · 「무슨 말」 · 「어떻게 해」 · 「뭐라고」), 오또 질문의 낱말 앞 두 글자가 아이 질문에 다시 나온다(「까닭이 뭐야?」).
     - **World:** 그 밖입니다.
3. **고쳐 말하기:** 「아니(야|요)?[,]? ○○」 · 「○○ 말고 ○○」 · 「○○ 아니고 ○○」 · 「그게 아니라 ○○」에서 뒤쪽 ○○가 한 어절 이상 남으면 고쳐 말하기입니다(`instead` = 뒤쪽, `denied` = 앞쪽 이름).
4. **전제 부정:** 부정 꼴이 있고(「안 ~」 · 「못 ~」 · 「~지 않았」 · 「없었/없어」 · 「아니야/아닌데」), **부정된 낱말이 오또 질문에 있는 것**이면 전제 부정입니다.
   - 견주기는 #310 `causeAsksOtherEvent` 와 같은 「앞 두 글자」 방식입니다. 「줬어」와 「줬」, 「만났어」와 「만났」처럼 봅니다.
   - 오또 질문에 없는 말을 부정하면 **보통 답입니다.** 「기분이 어땠어?」에 「안 무서웠어」는 마음을 말한 답이라 판정으로 갑니다.
5. 나머지는 답입니다.

> 받아쓰기가 묻는 말을 틀리게 적을 수 있습니다. 그래서 Recall · World 로 갈린 말도 **칸에는 절대 넣지 않습니다.** 잘못 갈려도 잃는 것은 질문 한 번입니다.

### 3-4. 「없어」 · 「아니」 낱말 하나의 예외

- 「누구랑 갔어?」 · 「거기서 누굴 만났어?」처럼 **있었나를 묻는 질문**(누구 · 누굴 · 누가 + 갔/만났/있었)에 「없어」 · 「아무도」는 답입니다. 이때는 `/turn` 으로 보내 판정이 `no_longer_needed` 를 내게 합니다(`judge_prompt.md` 예시 83 과 같은 경우).
- 그 밖의 「아니」 · 「없어」 · 「싫어」 낱말 하나는 지금처럼 답 아님입니다.

## 4. 질문 대응

### 4-1. 흐름 — `coopAskInFlow` 안에서 끝냅니다

`askDiaryStep` 은 손대지 않습니다. `coopAskInFlow` 의 `ask(...)` 둘레에 작은 되풀이를 둡니다.

```
r = ask(질문)
repeat(최대 2번):                     // ⚖️5 — 한 걸음에 아이 질문은 두 번까지 받는다
    kind = classifyCoopReply(r.text, 질문)
    kind 가 질문이 아니면 break
    대답(kind)을 말한다 · 대화록에 남긴다 · 로그
    r = ask(다시 물을 말)              // 사다리를 내려가지 않는다
세 번째 질문이면 → 그 말은 NonAnswer 처럼 넘긴다(지금 흐름 = 쉬운 질문)
```

- 질문 차례에는 `coopLiveSignals`(`/turn`)를 부르지 않습니다. 수준 신호도 세지 않습니다. 지금은 신호 없는 답이 「내림」으로 세어질 수 있으니 질문은 신호 계산에서 뺍니다.
- `rejected` 와 `sameSyllables` 에 질문을 넣지 않습니다(§1의 잘못 둘).
- `track.asked`(부모 리포트 「고른 이야기에 한 답」)에는 **마지막 진짜 답만** 남깁니다.

### 4-2. 무엇을 말하나

| 종류 | 오또가 하는 말 (1단계 · 앱 문장) | 다시 물을 말 |
|---|---|---|
| AboutQuestion | 「쉽게 다시 물어볼게!」 | **그 걸음 사다리의 다음 칸**(더 쉬운 말). 사다리를 소모하지 않고 「미리 보기」로 씁니다 — 다음에 정말 내려갈 때는 그 다음 칸부터. 다음 칸이 없으면 같은 질문을 천천히(TTS 속도 그대로, 질문만) |
| Recall (10-08 고침) | 「생각나는 만큼만 말해 줘!」 · 「천천히 떠올려 봐도 돼!」 중 앞 말과 다른 것. **기다리지 않고 바로** 다음 칸으로 | **그 걸음 사다리의 다음 칸**(AboutQuestion 과 같은 미리 보기 — 고르기 · 좁혀 묻기라 떠올리기보다 쉽다). 다음 칸이 없으면 같은 질문 |
| World (1단계) | 「오또도 궁금하다! 이따 같이 알아보자.」 · 「좋은 질문이야!」 중 앞 말과 다른 것 | 「그럼 다시 물어볼게.」 + 같은 질문 |
| World (2단계 · ⚖️2) | 서버가 쓴 대답 한 문장(§6) — 못 받으면 1단계 문장 | 같은 질문 |

- 오또 말은 모두 **「?」를 넣지 않습니다.** 넣으면 `pendingQuestion` 이 되어 대화록이 꼬입니다(`MissionShell.kt:83` 과 같은 원칙).
- 「다시 물을 말」 앞에는 「그럼」을 붙이지 않습니다. 대답과 질문 사이에 `pause(700)` 만 둡니다.
- 받아주기(`coopServerReaction` · `coopAck` · `pastEcho`)는 질문 차례에 **부르지 않습니다.** 위 표의 말이 받아주기 자리를 대신합니다. 그래서 「응응!」 · 「우와!」 · 「뭐 먹었구나!」가 질문에 붙지 않습니다.

### 4-2-1. Recall 을 이렇게 받는 까닭 (10-08 사용자 판단으로 고침)

**처음 설계와 실기기 결과**
- 처음 설계는 「엄마한테 물어봐도 좋아!」 + 3초 기다림이었습니다.
- 실기기(S10) 「엄마 우리 누구랑 갔었지?」에서 설계대로 돌았지만, **부모가 답을 대신 채우게 이끄는 방향**이었습니다.
- 같이 만들기의 목적은 아이가 스스로 떠올려 말하는 것입니다. 부모 몫은 질문을 고르고 적는 데까지이고, 답은 아이 몫입니다(협업 §4-1 · `by` 3종에 어른이 없음).

**그래서 이렇게 고칩니다**
- **속뜻을 「잘 기억이 안 나」로 읽습니다.** 같이 겪은 어른에게 확인하려는 말이라 기억이 막힌 자리입니다. 「몰라」와 같은 자리이지만 **떠올리려 애쓰는 중**이라는 점이 다릅니다.
- **어른을 부르지도 기다리지도 않습니다.** 받아주기 한마디 뒤 바로 다음 질문을 합니다.
  - 마이크가 빈 틈이 없으니, 어른이 끼어들 3초 틈도 생기지 않습니다(§10 의 문제를 줄입니다).
- **떠올리기를 쉽게 만들어 줍니다.** 같은 질문을 되풀이하면 같은 곳에서 또 막힙니다. 사다리 다음 칸은 고르기나 좁혀 묻기라(「누구랑 갔어? 엄마, 아빠, 친구?」), 떠올리기보다 알아보기가 쉽습니다.
  - AboutQuestion 과 같은 「미리 보기」로 쓰고, 사다리를 소모하지 않습니다.

**받아주기 말**
- 평가 · 재촉이 없는 말만 씁니다. 「생각나는 만큼만 말해 줘!」 · 「천천히 떠올려 봐도 돼!」
- 「몰라도 괜찮아」는 쓰지 않습니다. 떠올리기를 그만두게 하는 말이기 때문입니다.
- 어른 · 부른 사람 이름(`who`)은 **말하지 않습니다.** 로그에만 남깁니다.

**다른 종류로 합치지 않는 까닭**
- NonAnswer 로 합치면 대응(쉬운 질문)은 비슷합니다. 하지만 세 가지가 달라집니다.
  - 사다리를 실제로 소모합니다.
  - 「몰라」 수에 들어갑니다.
  - 질문 꼴의 말이 판정에 가면 §1 의 잘못(칸 값이 됨)이 다시 열립니다.
- 그래서 종류는 따로 두고 대응만 「쉬운 질문」 쪽으로 맞춥니다.

**상한**
- 한 걸음 2번 안에 AboutQuestion · World 와 **같이 셉니다.**
- 세 번째부터는 NonAnswer 처럼 지금 사다리로 갑니다. 막힌 기억을 더 밀지 않습니다.

### 4-3. 대화록 (리포트 규칙 5)

- 아이 질문은 지금처럼 `talk("child", …)` 로 남습니다. 그 앞의 오또 질문(`pendingQuestion`)도 같이 남습니다.
- 오또의 대답은 「?」가 없어 지금은 남지 않습니다. **`Director.talkOtto(text)`** 를 하나 두어 바로 적습니다(`s.talk += TalkLine("otto", …)`). 부모가 대화록에서 「왜 같은 질문을 두 번 했지?」를 읽을 수 있게 하려는 것입니다.
- 다시 물은 질문은 `pendingQuestion` 이 되어, 아이 답과 함께 한 번 더 적힙니다(실제로 두 번 물었으니 맞습니다).

## 5. 부정 대응

### 5-1. 종류별

| 종류 | 받아주기 | 칸 | 다음 질문 |
|---|---|---|---|
| **Corrected**(「아니, 사과 줬어」) | `instead` 로 지금 받아주기 길(서버 대사 · `coopAck`) | `/turn` 에 `instead` 만 보낸다(부정 머리 「아니,」를 뗀 말). `denied` 가 들은 이름(`track.heard`)이면 뺀다 | 판정대로(지금 길) |
| **Corrected** + 이미 찬 칸을 고침(「놀이터 말고 수영장」 · place=놀이터) | 「아, 수영장이구나!」 | **덮어씀(⚖️4)** — `denied` 가 그 칸 값과 같고 판정이 같은 칸을 채웠을 때만. by child · 로그 · 리포트에는 고쳐 말한 원문을 남김 | 판정대로 |
| **PremiseDenied** — 필수 걸음(place · problem · cause · solution) | `negationAck`: 부정된 끝 어절에 「구나」(「안 줬구나!」 · 「안 갔구나!」). 못 만들면 「그랬구나!」. **「우와!」 · 「응응!」 금지** | `/turn` 은 그대로 부른다(판정이 다른 칸이나 `no_longer_needed` 를 낼 수 있다). 이 칸이 안 차면 `rejected` 에 **넣지 않는다** | **전제 없는 질문**(5-2)으로 한 번. 또 부정하거나 안 차면 지금 사다리 |
| **PremiseDenied** — 꼬리 걸음(detail · said · try · after) | 위와 같음 | **칸에 넣지 않는다(⚖️3)** — 「안 했어」만 책에 가면 빈 쪽 문장이 된다 | 다시 묻지 않고 다음 걸음으로 |
| **PremiseDenied** — 부모 질문 걸음 | 위와 같음 | **부모 질문 칸(`parentN`)에 그대로 넣는다** — 「기린한테 뭐 줬어?」의 답이 「안 줬어」인 것도 부모가 알고 싶은 답이다. 부모 질문은 몰래 고쳐 묻지 않는다 | 다음 걸음 |

`negationAck` 는 `pastEcho` 와 같은 안전 조건(5어절 이하 · 이음 끝 없음 · 거친 말 없음)을 따르고, 「아니,」 머리를 떼고 봅니다.

### 5-2. 전제 없는 질문 — `coopPremiseFree(key, reason)`

질문이 전제를 깐 곳은 넷입니다.
- 이어 받기의 들은 이름(`{thing:가} 왜 그랬을까?` · `{place:에서} 뭐 봤어?` · `CoopQuestions.kt`)
- 고른 이야기의 템플릿 질문
- 서버 질문
- 선택지(`withChoices`)

전제 없는 질문은 **이름 자리 · 선택지가 없는 열린 질문**입니다. 그 걸음 사다리의 마지막 칸(가장 넓은 질문)을 쓰고, 없으면 아래 표를 씁니다.

| 걸음 | 다녀왔어요 | 곧 해요 | 좋아해요 |
|---|---|---|---|
| place | 그럼 어디 갔었어? | 그럼 어디 갈 거야? | 그럼 어디로 가 볼까? |
| problem | 그럼 거기서 무슨 일이 있었어? | 그럼 거기서 뭘 할 거야? | 그럼 무슨 일이 생겼을까? |
| cause | 그럼 무엇 때문에 그런 일이 생겼을까? | (곧 해요 cause 는 지금 템플릿 그대로) | 그럼 무엇 때문에 그랬을까? |
| solution | 그럼 그다음엔 어떻게 됐어? | 그럼 그다음엔 어떻게 할 거야? | 그럼 그다음엔 어떻게 됐을까? |

- 갈무리(`coopGuard`)를 거칩니다.
- 이 질문에는 `track.heard` 의 부정된 이름을 끼우지 않습니다. 부정된 이름은 뺍니다(`heard.remove` · `:727` 과 같은 방식).

### 5-3. 판정 `contradiction` 과의 관계

- 판정이 `contradiction=true` 를 주고 아이 말이 Corrected 면 5-1 의 덮어쓰기 조건과 같이 봅니다.
- Corrected 가 아닌데 `contradiction` 만 온 경우는 지금처럼 쓰지 않습니다. 아이가 고친 것인지 판정이 잘못 본 것인지 모르기 때문입니다.

## 6. (2단계 · ⚖️2) 서버가 아이 질문에 대답하기

1단계 앱 문장(「오또도 궁금하다!」)은 안전하지만 사용자가 원한 「질문에 맞게 대답」은 아닙니다. 대답을 서버 대사가 쓰게 하려면 아래가 필요합니다. 담당은 **조장**(서버 · API)입니다.

- **API:** `TurnRequest` 에 `utterance_kind: Optional[Literal["answer", "question"]] = None` 을 더합니다. `"question"` 이면 서버는 **판정을 건너뛰고** 대사만 씁니다(칸을 채울 일이 없으니 판정 비용 · 시간을 아낌). `guidelines/3` §3-2-1 에 적습니다. 옛 앱은 안 보내니 그대로입니다.
- **대사 프롬프트(`eval/prompt_modes/line_coop.md` 또는 공통):**
  - 「아이가 질문을 했으면(utterance_kind=question) ack 에 그 질문에 대한 대답을 한 문장(10어절 이하)으로 씁니다. 물음표를 쓰지 않습니다. question · expand · options 는 null 입니다.」
  - 「아이의 하루 · 가족 · 아이만 아는 일은 모른다고 말합니다(예: "오또는 못 봤어. 엄마는 알지도 몰라."). 확실하지 않은 사실은 단정하지 않습니다(예: "기린은 나뭇잎을 좋아한대.").」
  - 「무섭거나 다치는 것 · 브랜드 · 사라는 말은 쓰지 않습니다.」
  - `line_prompt.md:22` 「답을 알려주지 않습니다」 옆에 「(이야기 칸의 답을 정해 주지 않는다는 뜻 — 아이가 물은 것에는 짧게 대답한다)」를 덧붙입니다.
- **앱:** World 질문이면 `exchangeTurn(..., utteranceKind = "question")` 을 부르고, ack 를 `usableReaction` 으로 거릅니다(「?」 · 40자 · 자리표시 · 거친 말). 못 쓰면 1단계 문장을 씁니다. 기다림은 지금 `/turn` 시간 한도를 따릅니다.
- **측정:** `eval/fixtures_line_child_question.jsonl` 에 20문항을 둡니다(World 12 · 아이 하루를 묻는 것 4 · 무섭거나 곤란한 질문 4). 검사는 이렇습니다.
  - 자동: 「?」 · 10어절 넘음 · 아이 하루를 단정함(「너는 ~했어」) · 거친 말
  - 사람이 읽기
  - 대사 벤치(`bench_turn_split.py` 계열)에 `--fixtures` 로 돌리고 결과를 `eval/results.md` 에 남깁니다. 프롬프트가 바뀌므로 기존 대사 문항도 전 · 후로 재서 다른 대사가 흔들리지 않는지 봅니다.

## 7. 로그 · 수치 (실기기에서 규칙을 고치는 재료)

- 갈릴 때마다 `log("[$key] 아이 말 종류 — ${kind} · 「$said」 ← 「$question」")` 와 `event("coop_reply_kind", "kind" to …, "text" to …)` 를 남깁니다.
