# 초안 A · B 비교 — 무엇을 보고 고를 것인가

> 2026-09-17 · 조장 · 회의에서 이 문서를 띄워 놓고 두 초안을 번갈아 켠다

## 왜 두 개를 만들었나

하나만 있으면 "이게 맞나?"를 물을 수 없다. **같은 대본으로 서로 다른 선택을 한 두 벌**을 만들어, 다섯 살 앞에 놓고 어느 쪽이 버티는지 본다.

| | 초안 A | 초안 B |
|---|---|---|
| 만든 사람 | 안치영 | 이종훈 (조장) |
| 형태 | 안드로이드 앱 (Kotlin + Compose) · APK 빌드됨 | HTML · 브라우저에서 바로 |
| 어디에 | `Desktop/finalproject_demo` | `final/prototype-b` |
| HTML 판 | `final/prototype` (A를 HTML로 옮긴 것) | — |

`final/prototype`은 A의 흐름과 그림을 그대로 HTML로 옮긴 것이다. **비교 대상이 아니라 A를 링크로 보여주기 위한 것**이다.

## 다르게 잡은 것 다섯

| # | 축 | 초안 A | 초안 B | B가 그렇게 한 이유 |
|---|---|---|---|---|
| 1 | **그림체** | 펠트·종이공예 3D (krea2 turbo) | **손으로 찢은 색종이 콜라주** (SDXL base 1.0) | 결정 27은 "세계는 한 그림체, 아이 그림은 원본 그대로 섞인다"이다. 아이 크레용 그림 옆에서 3D 펠트가 더 튀는지, 평면 종이가 덜 튀는지 눈으로 본다. 제품 이름도 '종이 인형극'이다 |
| 2 | **책이 보이는 시점** | 대화가 끝난 뒤 한 번에 (S8 "책 만드는 중") | **말할 때마다 왼쪽에 한 쪽씩 쌓인다** | 다섯 살이 15분을 버티는 이유를 중간에 만들어 준다. 자기 말이 책이 되는 걸 바로 본다 |
| 3 | **어른 자리** | 책마다 1칸. 3초 안에 답 없으면 마스코트가 넘어감 | **어른이 답해야 넘어가는 자리 1개** + 마무리 자리 1개 | "지금 흐름이면 아이 혼자 해도 된다"는 지적에 대한 반대 실험. 강제하면 정말 같이 하게 되는지, 아니면 짜증만 나는지 본다 |
| 4 | **턴 수** | 8턴 | **5턴** | 집중 시간. 짧게 해도 책이 되는지 본다 |
| 5 | **배경** | 그림 한 장. 만질 수 없다 | **배경판 + 소품 14종을 얹는다.** 소품도 만져진다 | 배경을 만질 수 있으면 아이가 더 오래 노는지 본다. 대신 그림 한 장의 밀도는 옅어진다 |

## 같게 둔 것 (비교를 위해 일부러 고정)

미션 2개(문지르기 · 끌어다 놓기) · 부모 리포트 6축과 원그래프 · 가로 화면 · 열린 질문만 · 답 후보 5개 · 마스코트 3조각 턴 · 수준은 규칙이 계산.

**이 여섯은 건드리지 않았다.** 한 번에 여러 개를 바꾸면 무엇 때문에 좋았는지 알 수 없다.

## 회의에서 볼 것

각자 켜 보고 아래 여섯 줄에만 답한다. 취향이 아니라 **판정 기준**이다.

| 무엇 | 어떻게 판정 |
|---|---|
| 아이 그림을 얹었을 때 | 두 그림체 위에 같은 크레용 그림을 얹어 본다. 어느 쪽이 "아이 것이 살아 있다"로 보이나 |
| 중간에 지루한 구간 | 각자 한 바퀴 돌리며 "여기서 아이가 딴짓하겠다" 싶은 지점을 표시한다. 개수를 센다 |
| 어른 강제 자리 | B의 어른 차례 띠에서 답답했나, 자연스러웠나 |
| 5턴 대 8턴 | 5턴으로 만든 책이 이야기처럼 읽히나. 얇으면 몇 턴이 필요한가 |
| 리포트 | 같은 6축인데 어느 쪽 세션이 숫자를 더 잘 남기나 |
| 배경 | B의 배경이 붙여넣은 티가 나나. A의 그린 배경과 견줘 어느 쪽이 보기 좋나 |

**9/18 부모·아이 관찰 때는 둘 다 보여준다.** 순서를 아이마다 바꿔서 앞에 본 것이 유리해지지 않게 한다.

## 각 초안의 약한 곳 (미리 적어 둔다)

**초안 A**
- 책이 마지막에 한 번에 나와서, 대화 10분 동안 아이에게 보이는 성과가 별 6개뿐이다.
- 어른 칸을 건너뛸 수 있어서 어른 없이 끝까지 갈 수 있다.
- 펠트 3D는 예쁘지만 아이 크레용 그림과 결이 가장 멀다.

**초안 B**
- 화면의 42%를 책이 가져가서 무대가 좁다. 인형 연출이 A보다 답답하다.
- 어른을 강제로 세우면 어른이 자리를 비운 상황에서 놀이가 멈춘다. (실제 1순위 사용자가 잠깐 봐주는 이모·삼촌이라는 점과 충돌한다)
- 5턴이면 칸이 덜 차서 이야기가 얇아질 수 있다.
- 배경판에서 뚜렷한 물체를 빼고 소품을 얹는 방식이라, **그림 한 장의 밀도가 A보다 옅다.**
- 배경 소품이 늘면 다섯 살이 미션 물체를 못 찾을 수 있다. 미션 물체만 빛나게 해 뒀지만 관찰이 필요하다.

## 이 비교로 정할 것

| 안건 | 어디에 |
|---|---|
| 세계 그림체 1차 2종을 무엇으로 할지 | 결정안건 27 |
| 책을 쌓아 보일지, 마지막에 한 번에 보일지 | **새 안건** |
| 어른 자리를 강제할지 | **새 안건** (결정 2와 이어짐) |
| 턴 수 상한 | 결정안건 12 · 상호작용 상한 |
| 배경을 소품으로 쪼갤지 | **새 안건** |

가운데 셋은 결정안건에 없던 축이다. 이번 비교에서 나온 것이니 안건 31 · 32 · 33으로 올린다.

**배경 안건에 딸린 결론 하나.** 배경을 소품으로 쪼개면 아이가 지어낸 세계도 프리셋만큼 만질 수 있어야 한다.
그래서 세계마다 소품을 새로 만들지 않고 **14종을 돌려 쓰고, 아이가 그린 것을 소품으로 얹는** 쪽으로 잡았다.
부모가 그림체를 바꿔도 좌표는 코드에 있으니 파일 폴더만 갈아 끼우면 된다.
다만 **이미 만든 책은 그대로 두는 것**을 권한다. 지난 책이 다른 그림체로 바뀌면 아이가 자기 책으로 못 알아본다.

## 여는 법

```
# 초안 B
cd final/prototype-b && python -m http.server 8778
→ http://127.0.0.1:8778/index.html

# 초안 A (HTML 판)
cd final/prototype && python -m http.server 8777
→ http://127.0.0.1:8777/index.html

# 초안 A (앱)
adb install Desktop/finalproject_demo/app/build/outputs/apk/debug/app-debug.apk
```

두 HTML 모두 오른쪽 위 구석을 길게 누르면 시연 서랍이 열린다. B의 서랍 첫 줄에 "A와 다르게 잡은 것"이 적혀 있다.
