## 확인한 원인과 실제 수정

| 경계 | 수정 전 재현 | 수정 |
|---|---|---|
| 판정 → 저장 슬롯 | 이미 채운 solution이 다른 질문의 보충 답으로 다시 채워지면 앞선 해결 행동이 덮어써졌다. | 같은 출처의 서사 보충은 ` / `로 이어 두 행동을 보존한다. 같은 칸 재질문과 contradiction 정정은 교체하며, 기존 보충값도 제거한다. 이름·장소의 교체는 그대로다. |
| 서로 다른 출처의 보충 | 카드가 기존 child solution을 바꾸면 앞선 아이 답과 출처가 함께 사라졌다. | 원래 칸과 출처를 유지하고 보충을 앱 내부 키에 출처와 함께 둔다. 요청할 때만 기존 extra에 투영한다. 혼합 extra를 전부 child로 표시하지 않는다. HTTP 슬롯은 기존 12종이다. |
| 생성 실패 → 기본 책 → 저장 | 템플릿 7종이 resolve를 수집하지만 마지막 쪽은 그 값을 읽지 않았다. 복합 결말 대신 고정 약속·교훈이 나왔다. | 실제로 수집한 solution/resolve가 있으면 solution·템플릿 결말·extra와 결말 보충을 인용해 기본 책을 만든다. 부정·미래 계획·그만두기를 임의로 문법 변환하지 않는다. 책장에도 같은 최종 자막을 저장한다. |

`storySupplement:<slot>:<index>`는 앱 내부 값이다. 새 서버 슬롯이나 저장 schema를 만들지 않는다. 기존 슬롯 맵의 초안·뒤로/앞으로 기록 경로를 사용한다. 같은 값 반복은 아이 답을 카드 답으로 다시 표시하지 않는다.

기본 책의 인용 문장은 생성 실패 때 내용을 보존하기 위한 복구다. AI가 자연스럽게 윤문한 출력의 품질 개선과 구분한다. 생성 성공 자막은 이 변경이 다시 쓰거나 원문 문자열 일치만으로 거절하지 않는다.

## 검증

독창적인 합성 입력으로 새 검사 10개 중 6개가 수정 전 내용·출처 손실로 실패했다. 추가로 정정 후 오래된 보충이 남는 검사 1개, 대본의 돌아보기 답이 해결 문장을 가리는 검사 1개가 실패한 것을 확인한 뒤 수정했다.

최종 관련 Android 검사 59개가 통과했다. 새 검사는 원문·보충·중복·정정·출처·템플릿 7종·부정·바람·생성 자막·다른 모드·기존 대본을 포함한다. Android API26의 로컬 저장/재로드/다시 읽기와 640×360dp 모의 화면에서도 복합 결말과 바람을 확인했다. 실기기 사용 검사는 아니다. 전체 검사와 APK·CI의 최종 결과는 PR에 기록한다.

리뷰에서 대본이 solutionLine에 저장한 해결 문장을 인용 마무리가 가리는 회귀를 발견했다. 실제 solution/resolve 수집값이 없으면 기존 대본을 사용하도록 수정했고, 단일 실패→통과와 기존 텍스트 검사로 확인했다. 기존 두 성인 책의 생성 당시 최초 손실 단계를 이 수정의 재현과 동일시하지 않는다.

## 실제 모델에서 남은 것

현재 생성 프롬프트는 허용된 동화 갈등도 비폭력 행동으로 바꾸도록 지시하고, extra 등 일부 채워진 칸의 생략을 허용한다. 서버는 동화 slot_by를 모델에 전달하지 않으며, 출력 후검사는 쪽 수·금칙어·자리표시자 중심이다. 이것은 현재 코드의 원인 후보/검사 범위이며 기존 책의 최초 변화 지점을 입증하지 않는다.

내용 보존 후보, 독창적 합성 입력 6개, 최대 24호출의 실행 도구와 [사전 등록 계획](윤문_내용보존_실측계획_1013.md)을 준비했다. 기본 준비 실행은 API 0회이고 사람 판정은 null이다. 실제 모델 전후 비교 전에는 운영 프롬프트를 바꾸지 않는다. 문체만 비교하는 PR #475의 별도 12권 준비와 이 내용 보존 실험을 합산하지 않는다.

이 PC에는 기존 AI 평가 연결 설정이 없다. 개인에게 새 키 발급을 요구하지 않는다. 팀의 기존 설정이 있는 환경에서 동일 요청·모델·effort로 전후 비교하고, 실패·보류·생성 거절을 포함해 의미 보존을 검토한 뒤 조장이 후보 적용을 검토한다. 실제 아동 모집과 아동 사용 효과 실험은 이번 범위에 없다.
