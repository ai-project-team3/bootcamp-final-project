# 조사 3 — 수명주기와 동의·열람·삭제 스케치 (2026-09-22)

조사 이종훈 · 멘토 검토(09-22) 「함께 해볼 조사 순서」 3번

**지금 저장이 아무것도 없다.** `SharedPreferences`·`DataStore`·`Room` 어느 것도 없고 세션이 끝나면 전부 사라진다. 그래서 보존 기간도 삭제 경로도 **없는 것이 아니라 대상이 없다.** 이게 이 조사에서 가장 중요한 사실인데, **뒤집어 보면 지금이 수명주기를 설계하기 가장 쉬운 시점**이다 — 이미 쌓인 데이터를 어떻게 처리할지 고민할 필요가 없다. 그리고 **저장은 곧 붙는다** — 책장·체크포인트 DB가 9/18 멘토 지시로 범위에 들어왔다. **저장을 붙이는 커밋과 수명주기를 정하는 커밋이 같아야 한다.**

---

## 이 조사의 범위

**근거로 쓴 것** — 앱 전체 grep(저장 관련 API 부재 확인) · `demo/Model.kt` `resetStory()`/`reset()` · `ui/Parent.kt`의 열람·삭제 버튼 상태 · `guidelines/3_API_명세.md` §3-5(책장·체크포인트) · 멘토 검토 4절.

**근거로 쓰지 않은 것** — 법률 자문. 개인정보 보호법 제22조의2 인용은 멘토 검토가 인용한 범위이고 **조문을 직접 해석한 것이 아니다.**

**따라서 이것은 구현 계획이 아니라 스케치다.** 멘토도 *"완성된 구현이 아니라 스케치로 충분하다"*고 적었다.

---

## 1. 지금의 수명주기 — 없다

### 확인된 것

| 무엇 | 어디 있나 | 언제 사라지나 |
|---|---|---|
| 음성 원본 | 폰 (VAD가 자른 조각) | **전사 직후** — 설계상. 구현은 아직 |
| 전사 텍스트 | `DemoState`(메모리) | **이야기를 새로 시작하면** (`resetStory()`) |
| 아이가 한 말 인용 | `s.quotes`(메모리) | 〃 |
| 수준 신호 | `s.signals`(메모리) | 〃 |
| 이벤트 기록 | `s.events` — **60개 링 버퍼** | 61번째가 들어오면 앞이 밀려 나간다 |
| 턴 기록 | `s.notes`(메모리) | 〃 |
| 그림 | `res/drawable/`의 미리 만든 PNG | 앱을 지울 때 |
| 세션 id | **없다** | — |

**앱을 끄면 전부 사라진다.** 부모 리포트가 보여주는 것은 **지금 메모리에 있는 이야기 하나**뿐이다.

### 조건부 함의

**그래서 「보호자 열람·정정·삭제」가 지금은 대상이 없다.** `ui/Parent.kt`의 내려받기·삭제 버튼이 `.alpha(0.5f)`로 흐려져 있고 *"데모에서는 누를 수 없어요"*라고 적혀 있는데, **그게 맞다** — 지울 것이 없다.

**그런데 `Parent.kt`에 「지난번」 비교 막대가 문자열 상수로 박혀 있다.** *"지난번 「바다」 한 낱말"*이 하드코딩이다. **기록이 없는데 기록이 있는 것처럼 보이는 화면**이다. 이건 저장이 붙기 전에 지워야 한다 — 저장이 붙으면 진짜 값이 들어가지만, 그 전까지는 **거짓을 보여주고 있다.**

### 확인되지 않은 것

- 음성 삭제가 **실제로 언제** 일어나는지 — `/stt`가 미구현이라 코드가 없다
- `s.events`가 60개를 넘겨 밀려 나가는 것이 **의도된 보존 정책인지 그냥 데모 편의인지** — `Director.kt:135`에 상한만 있고 이유가 안 적혀 있다

### 같이 생각해 볼 질문

- 60개 링 버퍼가 제품에서도 맞나요? 한 권이 19턴이면 이벤트가 몇 개 생기나요?
- 「지난번」 막대를 지금 지울까요, 저장이 붙을 때까지 두고 **화면에 「데모」 표시만 할까요?**

## 2. 저장이 붙으면 — 정해야 하는 것 여섯

### 확인된 것

`guidelines/3_API_명세.md` §3-5에 **책장·체크포인트 DB/API**가 범위에 들어와 있다. **기기 식별키로 시작하고 구글 로그인은 나중에 얹는다**고 적혀 있다.

### 조건부 함의

**기기 식별키가 들어오는 순간 이 문서의 성격이 바뀐다.** 지금은 아무것도 한 아이에게 묶이지 않는데, 식별키가 생기면 **그 키로 쌓인 것이 한 아이의 기록**이 된다. 그때 여섯 개가 동시에 정해져야 한다.

| | 정할 것 | 지금 기울어진 쪽 |
|---|---|---|
| **① 무엇을 저장하나** | 책 · 아이 말 인용 · 횟수 · 수준 신호 | **음성은 저장하지 않는다**(규칙) |
| **② 얼마나 두나** | 책은 오래, 원문 인용은? | 확인 필요 |
| **③ 어떻게 지우나** | 부모가 누르면 무엇이 지워지나 | 확인 필요 |
| **④ 누가 보나** | 부모 모드 PIN 뒤 | PIN은 있다. **데모에서는 아무 4자리나 통과**한다 |
| **⑤ 동의를 어떻게 받나** | 만 14세 미만 법정대리인 동의 + **그 사실의 확인** | 확인 필요 |
| **⑥ 무엇을 남겨야 「확인됐다」고 말할 수 있나** | ← **멘토가 짚은 핵심** | 확인 필요 |

**⑥이 가장 어렵다.** 멘토 질문을 그대로 옮기면 — *"화면에 체크박스가 있었다는 것과 확인되었다는 것 사이의 거리는 얼마나 되나요?"*

### 확인되지 않은 것

- 기기 식별키가 **언제** 들어오는지 — 다음 2주 안인지
- 책을 서버에 두나 폰에 두나. `guidelines/3` §3-5가 DB/API라고 했으니 서버일 텐데, 그러면 **아이 말 원문이 우리 서버에 쌓인다**
- **아이가 만 13세가 되는 순간** 조건이 달라지는지 — 멘토가 질문으로 남긴 것이다

### 같이 생각해 볼 질문

- 책은 남기고 **원문 인용만 짧게 두는 것**이 가능한가요? 그러면 부모 리포트의 「같은 질문 비교」가 성립하나요?
- 부모가 *"전부 지워 주세요"*라고 하면 **무엇까지 지워지나요?** 책도 지워지나요?
- 동의를 **누구에게, 언제** 받나요? 첫 실행인가요, 부모 모드에 처음 들어갈 때인가요?

## 3. 지금 할 수 있는 것 — 세 줄

### 확인된 것

저장이 없어도 **지금 붙일 수 있는 것이 셋 있다.** 셋 다 화면 하나거나 문장 하나다.

| | 무엇 | 왜 지금 |
|---|---|---|
| **AI 음성 고지** | *"마스코트 목소리는 컴퓨터가 만든 소리예요"* | **OpenAI TTS 이용 정책이 요구한다**(멘토 4절). 저장과 무관하다 |
| **「지난번」 막대 정리** | 하드코딩을 지우거나 「데모」 표시 | 기록 없이 기록을 보여주고 있다 |
| **동의 화면 자리** | 첫 실행에 한 장 | 문구는 나중에. **자리를 비워 두면 나중에 끼우기 쉽다** |

### 조건부 함의

**AI 음성 고지는 아이와 부모에게 다르게 해야 한다.** 다섯 살에게 *"AI가 생성한 음성입니다"*는 전달되지 않는다. 멘토가 그 질문을 따로 남겼다 — *"두 대상에게 같은 방식이 맞을까요?"*

→ 기울어진 쪽: **아이에게는 마스코트가 자기 입으로** (*"내 목소리는 컴퓨터가 만들어 줬어!"*), **부모에게는 부모 모드 설정에 한 줄.**

### 확인되지 않은 것

고지를 **어디에** 두어야 정책 요구를 충족하는지. 정책 문구를 직접 읽어야 한다 — **나는 멘토 인용만 봤다.**

### 같이 생각해 볼 질문

- 마스코트가 자기 입으로 말하는 것이 고지로 인정되나요? 어디까지가 고지인가요?
- 동의 화면을 미리 비워 두면 **나중에 끼울 때 무엇이 쉬워지나요?** 지금 만들면 오히려 틀린 자리에 박히나요?

## 이 조사가 정한 것 / 안 정한 것

**정했다**
- **저장이 없으므로 보존·삭제는 대상이 없다.** 그게 지금 정직한 상태다
- **저장을 붙이는 커밋과 수명주기를 정하는 커밋이 같아야 한다.** 나중에 붙이면 이미 쌓인 데이터를 처리해야 한다
- 지금 할 수 있는 셋 — **AI 음성 고지 · 「지난번」 막대 정리 · 동의 화면 자리**

**안 정했다**
- 여섯 개 전부. 특히 **⑥「무엇을 남겨야 확인됐다고 말할 수 있나」**
- 책을 폰에 두나 서버에 두나 — 이게 나머지를 다 바꾼다
