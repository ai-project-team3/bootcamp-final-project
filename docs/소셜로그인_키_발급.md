# 소셜 로그인 키 받기 — 사이트별로 할 일 (카카오 · 네이버 · Google)

> 10-05 · 안치영. 10-05 저녁에 **콘솔 화면 기준으로 다시 씀** — 카카오 콘솔이 개편되어 옛 「앱 설정 → 플랫폼」 메뉴는 없다.
> 앱 코드는 `android/app/src/main/java/com/example/finalproject_demo/net/SocialLogin.kt`.

## 0. 먼저 알아 둘 것

**받아야 하는 값은 넷이다.** 받으면 `android/local.properties` 맨 아래에 붙여 넣는다(이 파일은 깃에 안 올라간다).

```properties
OTTO_KAKAO_APP_KEY=카카오_네이티브_앱_키
OTTO_NAVER_CLIENT_ID=네이버_Client_ID
OTTO_NAVER_CLIENT_SECRET=네이버_Client_Secret
OTTO_GOOGLE_WEB_CLIENT_ID=숫자-영문.apps.googleusercontent.com
```

**사이트마다 우리 앱을 알려 줘야 하는 정보는 둘이다 — 「패키지 이름」 과 「서명 지문」.**

| | 개발용 앱 「오또 개발」 (내 PC에서 설치하는 것) | 스토어 앱 「오또」 (Play 에서 받는 것) |
|---|---|---|
| 패키지 이름 | `kr.clap.otto.dev` | `kr.clap.otto` |
| SHA-1 (Google · 네이버용) | `F4:50:0B:C8:CC:24:23:52:E8:E9:92:ED:D9:C8:A1:A1:08:A6:0C:47` | Play Console 에서 확인 (아래) |
| 카카오 키 해시 | `9FALyMwkI1Lo6ZLt2cihoQimDEc=` | Play Console 의 SHA-1 을 바꿔서 (아래) |

- 개발용 값은 **치영 PC 의 디버그 키**(`C:\Users\cyahn\.android\debug.keystore`)에서 10-05 에 뽑은 것이다. 다른 팀원 PC 는 값이 다르다 — 그 사람이 개발용으로 로그인해 보려면 자기 값도 등록해야 한다(아래 「다른 PC 값 뽑기」).
- 스토어 앱 SHA-1: **Play Console → 오또 → 테스트 및 출시 → 설정 → 앱 무결성 → 「Play 앱 서명」 탭 → 「앱 서명 키 인증서」 의 SHA-1**.
  같은 화면의 「업로드 키 인증서」 SHA-1 도 함께 등록해 두면 안전하다. (Play Console 은 조장 계정 — 조장에게 받아도 된다)
- 스토어 SHA-1 을 카카오 키 해시로 바꾸기: 콜론을 빼고 아래처럼 (PowerShell)
  ```powershell
  $hex = "AA:BB:CC:...".Replace(":","")
  [Convert]::ToBase64String([byte[]] -split ($hex -replace '..', '0x$& '))
  ```
  또는 그 SHA-1 을 알려 주면 Claude 가 바꿔 준다.

## 1. 카카오 — https://developers.kakao.com

1. 오른쪽 위 **로그인**(카카오 계정) → 위 메뉴 **「앱」**(또는 「내 애플리케이션」) → **「애플리케이션 추가하기」**
   - 앱 이름 `오또` · 회사명 `팀 CLAP` · 카테고리 「교육」 등 → 저장
2. 만든 앱을 누르면 왼쪽에 메뉴가 생긴다. **「앱」 → 「플랫폼 키」 → 「네이티브 앱 키」** 로 들어간다
   - ⚠️ 예전 문서의 「앱 설정 → 플랫폼」 은 **개편으로 없어졌다.** Android 등록은 이제 이 「네이티브 앱 키」 화면 안에 있다
   - 이 화면 맨 위의 **네이티브 앱 키(32자리 영문·숫자)** 를 복사 → `OTTO_KAKAO_APP_KEY`
3. 같은 화면의 **Android** 칸에서:
   - **패키지명**: `kr.clap.otto.dev` 를 넣고, 하나 더 추가해서 `kr.clap.otto`
   - **키 해시**: `9FALyMwkI1Lo6ZLt2cihoQimDEc=` (개발용). 스토어 키 해시는 Play Console 값을 받은 뒤 같은 칸에 줄을 바꿔 추가
   - **마켓 URL**: 비워 두거나 `market://details?id=kr.clap.otto` → 저장
4. 왼쪽 **「카카오 로그인」 → 「사용 설정」** → 상태를 **ON** (OFF 면 로그인할 때 KOE004 오류)
5. 왼쪽 **「카카오 로그인」 → 「동의항목」** → **닉네임** 의 「설정」 → 「필수 동의」 · 목적 「보호자 확인」 → 저장
   - **이메일은 지금 못 켠다.** 카카오계정 이메일은 「비즈 앱 전환 + 비즈니스 정보 심사 + 추가 기능 신청」 을 마쳐야 켜진다. 사업자 등록이 없는 부트캠프 팀이라 **건너뛴다**
   - 앱은 이메일이 없어도 동작한다 — 계정 탭에 「카카오 계정」 으로 보이고, 카카오 고유 번호로 같은 사람을 알아본다
6. 끝. Redirect URI 같은 것은 **넣지 않는다**(그건 웹용이다. 앱은 `kakao{앱 키}://oauth` 로 돌아오고, 그 설정은 코드가 이미 한다)

## 2. 네이버 — https://developers.naver.com

1. 오른쪽 위 **로그인**(네이버 아이디) → 위 메뉴 **「Application」 → 「애플리케이션 등록」**
2. **애플리케이션 이름**: `오또` (로그인 창에 이 이름이 보인다)
3. **사용 API**: 「네이버 로그인」 을 고른다
4. **제공 정보 선택**(네이버에서 받아 올 것):
   - **이메일 주소 — 필수** 체크
   - **별명 — 추가**(선택) 체크
   - 이름 · 성별 · 생일 · 연령대 · 휴대전화 번호 · 프로필 사진은 **체크하지 않는다**(보호자 정보는 최소로 — 약관에도 그렇게 적었다)
5. **로그인 오픈 API 서비스 환경**: 「환경 추가」 → **Android** 를 고른다
   - **다운로드 URL**: `https://play.google.com/store/apps/details?id=kr.clap.otto`
   - **안드로이드 앱 패키지 이름**: `kr.clap.otto` · 「추가」 로 하나 더 `kr.clap.otto.dev`
   - (PC 웹 · 모바일 웹을 꼭 넣으라고 하면: 서비스 URL `https://leejonghoona.github.io/otto-privacy/` · Callback URL 도 같은 주소)
6. **「등록하기」** → 내 애플리케이션 화면의 **「개요」** 에 **Client ID** 와 **Client Secret**(「보기」 를 눌러야 보임)이 있다 → 각각 `OTTO_NAVER_CLIENT_ID` · `OTTO_NAVER_CLIENT_SECRET`
7. **검수 전에는 아무나 로그인할 수 없다** — 「멤버관리」 탭 → **테스터 ID** 에 테스트할 네이버 아이디(팀원)를 넣는다. 출시 전에 「검수 요청」 을 한다

## 3. Google — https://console.cloud.google.com

> 메뉴 이름이 「OAuth 동의 화면」 → **「Google 인증 플랫폼(Google Auth Platform)」** 으로 바뀌었다. 안에 「브랜딩 · 대상 · 클라이언트 · 데이터 액세스」 가 있다.

1. 위쪽 프로젝트 선택 → **「새 프로젝트」** → 이름 `otto` → 만들기 (이미 팀 프로젝트가 있으면 그것을 고른다)
2. 왼쪽 메뉴(☰) → **「Google 인증 플랫폼」** → 처음이면 **「시작하기」**
   - 앱 이름 `오또` · 사용자 지원 이메일(내 이메일) → **대상: 외부** → 연락처 이메일 → 동의 → 만들기
3. **「브랜딩」**: 앱 로고(선택) · 앱 홈페이지 · **개인정보처리방침 링크** `https://leejonghoona.github.io/otto-privacy/` → 저장
4. **「대상」**: 게시 상태가 「테스트」 면 **「테스트 사용자 추가」** 로 로그인해 볼 Google 계정(팀원)을 넣는다. 출시 전에 **「앱 게시」**
5. **「데이터 액세스」**: 범위는 `.../auth/userinfo.email` · `.../auth/userinfo.profile` · `openid` **셋만** (기본값이면 손대지 않아도 된다)
6. **「클라이언트」 → 「클라이언트 만들기」** 를 **세 번** 한다
   - ① 유형 **Android** · 이름 `오또 개발` · 패키지 이름 `kr.clap.otto.dev` · SHA-1 `F4:50:0B:C8:CC:24:23:52:E8:E9:92:ED:D9:C8:A1:A1:08:A6:0C:47`
   - ② 유형 **Android** · 이름 `오또` · 패키지 이름 `kr.clap.otto` · SHA-1 = Play Console 의 앱 서명 키 SHA-1 (업로드 키 SHA-1 로 하나 더 만들어도 된다)
   - ③ 유형 **웹 애플리케이션** · 이름 `오또 서버용` · 주소는 비워 둔다 → 만들면 뜨는 **클라이언트 ID**(`…apps.googleusercontent.com`)를 복사 → `OTTO_GOOGLE_WEB_CLIENT_ID`
   - ⚠️ 앱에 넣는 것은 **③ 웹 애플리케이션의 ID** 다. ①② Android 클라이언트 ID 를 넣으면 「개발자 오류(10)」 가 난다. ①② 는 만들어 두기만 하면 Google 이 패키지 · SHA-1 로 우리 앱을 알아본다
   - 클라이언트 보안 비밀(secret)은 앱에 쓰지 않는다

## 4. 넣고 확인하기

1. `android/local.properties` 에 네 줄을 넣는다 (맨 위 0 번 참고)
2. Android Studio 에서 **Sync** → 개발용 앱을 폰에 설치
3. 로그인 화면에서 세 버튼을 하나씩 눌러 본다 → 부모 영역 → 계정 → 「로그인」 줄에 **「(개발용)」 이 없으면** 진짜로 로그인된 것이다
4. 안 되면 오류 메시지를 알려 주면 된다. 흔한 것:
   - 카카오 「Android keyHash validation failed」 → 키 해시가 틀렸거나 패키지명이 `kr.clap.otto.dev` 로 안 들어감
   - 카카오 KOE004 → 「카카오 로그인 → 사용 설정」 이 OFF
   - 네이버 로그인 창이 바로 닫힘 → 「멤버관리」 테스터에 그 아이디가 없음, 또는 패키지 이름이 안 들어감
   - Google 「개발자 오류」 / 아무 창도 안 뜸 → ③ 웹 클라이언트 ID 를 넣었는지, ① 의 SHA-1 · 패키지가 맞는지, 「테스트 사용자」 에 그 계정이 있는지

## 다른 PC 값 뽑기 (팀원이 자기 PC 로 개발용 로그인을 해 보려면)

```powershell
& "C:\Program Files\Java\jdk-17\bin\keytool.exe" -list -v -keystore "$env:USERPROFILE\.android\debug.keystore" -alias androiddebugkey -storepass android -keypass android
```

나온 `SHA1:` 값을 Google ① · 네이버(자동) 에 쓰고, 카카오 키 해시는 0 번의 PowerShell 두 줄로 바꿔 「네이티브 앱 키 → Android → 키 해시」 에 한 줄 더 넣는다.

## 키가 없을 때 앱은

| 빌드 | 키 없음 | 키 있음 |
|---|---|---|
| 개발용(`오또 개발`) · JVM 검사 | 개발용 가짜 계정으로 넘어감 — 계정 탭에 「(개발용)」 | 실제 로그인 창 |
| 스토어(release) | 「○○ 로그인은 아직 준비 중이에요」 — 넘어가지 않음 | 실제 로그인 창 |

## 서버 · 탈퇴 (참고)

- 지금은 로그인한 보호자를 **폰 안에만** 기억한다. 서버에 계정이 생기면 `SocialIdentity.token` 을 `/auth/{provider}` 로 보내 서버가 확인한다 — API 계약(`guidelines/3`)을 바꾸는 일이라 이슈로 먼저 알린다
- 회원 탈퇴는 카카오 `unlink` · 네이버 토큰 삭제 · Google 자격 증명 지우기를 부른다(`Accounts.withdraw`)
