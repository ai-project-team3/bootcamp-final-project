# 소셜 로그인 키 받기 (카카오 · 네이버 · Google)

> 10-05 · 안치영. 앱 코드는 `android/app/src/main/java/com/example/finalproject_demo/net/SocialLogin.kt`.
> 키는 **레포에 올리지 않는다.** `android/local.properties`(깃이 무시함)나 같은 이름의 환경 변수에 넣는다.

```properties
# android/local.properties
OTTO_KAKAO_APP_KEY=카카오_네이티브_앱_키
OTTO_NAVER_CLIENT_ID=네이버_Client_ID
OTTO_NAVER_CLIENT_SECRET=네이버_Client_Secret
OTTO_GOOGLE_WEB_CLIENT_ID=xxxxxxxx.apps.googleusercontent.com
```

키가 비어 있으면 그 버튼은 이렇게 된다.

| 빌드 | 키 없음 | 키 있음 |
|---|---|---|
| 디버그(`오또 개발`) · JVM 검사 | 개발용 가짜 계정으로 넘어감 — 부모 영역 → 계정에 「(개발용)」으로 보인다 | 실제 로그인 창 |
| 스토어(release) | 「○○ 로그인은 아직 준비 중이에요」 — 넘어가지 않는다 | 실제 로그인 창 |

## 등록할 앱 정보

| 항목 | 값 |
|---|---|
| 패키지 이름 | `kr.clap.otto` (스토어) · `kr.clap.otto.dev` (디버그 — 둘 다 등록) |
| 서명 SHA-1 · 키 해시 | ① 디버그 키(`~/.android/debug.keystore`) ② **Play 앱 서명 키**(Play Console → 앱 무결성 → 앱 서명) ③ 업로드 키 |

디버그 키의 SHA-1 · 카카오 키 해시:

```bash
keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android -keypass android   # SHA1: 줄
keytool -exportcert -alias androiddebugkey -keystore ~/.android/debug.keystore -storepass android | openssl sha1 -binary | openssl base64   # 카카오 키 해시
```

Play 앱 서명 키는 Play Console 의 SHA-1 을 쓰고, 카카오 키 해시는 그 SHA-1(16진수)을 base64 로 바꾼다:
`echo <SHA1 콜론 뺀 16진수> | xxd -r -p | openssl base64`

## 카카오 — developers.kakao.com

1. 내 애플리케이션 → 애플리케이션 추가(이름 「오또」)
2. 앱 설정 → 플랫폼 → **Android 플랫폼 등록**: 패키지 이름 두 개 · 키 해시(디버그 · Play 앱 서명 · 업로드)
3. 제품 설정 → 카카오 로그인 → **활성화 ON**
4. 동의항목: 닉네임(필수) · **카카오계정(이메일)** (선택 — 이메일은 비즈 앱 전환 뒤 「필수」로 바꿀 수 있다)
5. 앱 키 → **네이티브 앱 키** → `OTTO_KAKAO_APP_KEY`

로그인이 끝나면 `kakao{네이티브 앱 키}://oauth` 로 돌아온다 — 매니페스트의 `AuthCodeHandlerActivity` 가 받고,
그 주소는 `app/build.gradle.kts` 가 키로 채운다(손댈 것 없음).

## 네이버 — developers.naver.com

1. Application → 애플리케이션 등록 → 사용 API **네이버 로그인**
2. 제공 정보: **이메일 주소**(필수) · 별명(선택). 이름 · 생년 · 휴대전화는 받지 않는다(보호자 정보 최소 수집)
3. 환경 추가 → **Android**: 다운로드 URL(스토어 주소) · 패키지 이름 두 개
4. **Client ID** · **Client Secret** → `OTTO_NAVER_CLIENT_ID` · `OTTO_NAVER_CLIENT_SECRET`
5. 검수 전에는 「멤버 관리」에 넣은 네이버 아이디만 로그인된다 — 출시 전 **검수 요청**

## Google — console.cloud.google.com

1. 프로젝트 → API 및 서비스 → **OAuth 동의 화면**(외부 · 앱 이름 오또 · 지원 이메일 · 개인정보처리방침 주소
   `https://leejonghoona.github.io/otto-privacy/`) · 범위는 `email` · `profile` · `openid` 만
2. 사용자 인증 정보 → OAuth 클라이언트 ID → **Android** 를 패키지 · SHA-1 마다 하나씩(디버그 · Play 앱 서명 · 업로드)
3. 같은 곳에서 **웹 애플리케이션** 클라이언트를 하나 더 만든다 → 그 **클라이언트 ID** 가 `OTTO_GOOGLE_WEB_CLIENT_ID`
   (Credential Manager 는 웹 클라이언트 ID 를 `serverClientId` 로 받는다. Android 클라이언트 ID 를 넣으면 「개발자 오류」가 난다)
4. 테스트 중에는 「테스트 사용자」에 넣은 계정만 로그인된다 — 출시 전 **앱 게시**

## 서버에 붙일 때 (아직 안 함)

지금은 로그인한 보호자를 **폰 안에만** 기억한다(`LocalAccountApi`). 서버에 계정이 생기면
`SocialIdentity.token`(카카오 · 네이버 액세스 토큰 · Google ID 토큰)을 `/auth/{provider}` 로 보내 서버가 각 사에 확인하게 한다.
API 계약(`guidelines/3`)을 바꾸는 일이라 **이슈로 먼저 알린다.**

## 탈퇴할 때

부모 영역 → 계정 → 회원 탈퇴는 카카오 `unlink` · 네이버 `disconnect`(토큰 삭제) · Google 자격 증명 지우기를 부른다
(`Accounts.withdraw`). 각 사 정책상 탈퇴한 회원의 앱 연결을 끊어야 한다.
