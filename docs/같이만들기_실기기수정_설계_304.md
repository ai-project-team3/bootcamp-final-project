## 1. 까닭 질문이 문제가 아니라 해결을 물었다

### 1-1. 길 (로그 ↔ 코드)

```
[problem] "풍선을 놓쳤어"
[detail] "그때 뭐 하고 있었어?" → "아빠가 잡아줬어"
   coopLiveSignals (CoopScenes.kt:426) — 꼬리 자리라 asked_slot=null 로 /turn
   → 판정: solution 칸 채움 · next_slot=cause
   → 대사 모델: story_so_far 에 problem=…놓쳤어 · solution=아빠가 잡아줌 · next_slot=cause
       line_prompt.md 「질문은 지금까지의 이야기에서 다음 한 걸음」 + 까닭 짓기 예시 「{친구1}는 왜 그랬을까?」
       → "아빠는 왜 풍선을 잡아줬을까?"            ← 가장 최근 일(해결)의 까닭
   coopLiveValueAsSaid (CoopScenes.kt:677) — track.llmNext = ("cause", 그 질문)
[cause] coopAskInFlow (CoopScenes.kt:338)
   llmQuestionFor (CoopScenes.kt:251) — 걸음 key == next_slot 이면 통과. 질문이 「무엇의 까닭」을 묻는지는 안 본다
   guarded(…, LLM) — coopGuard 는 시제 · 거친 말 · 모양만 본다
   → 그대로 물음 → 아이 「몰라」 「뭐를 넣어?」
```

칸 이름 `cause` 의 뜻(이야기 뼈대의 「전」 — **문제가 왜 일어났나**)이 대사 프롬프트 어디에도 없다. 칸 뜻 표는 `cause 왜` 한 낱말뿐이다(`line_prompt.md` 「칸 이름 뜻」). 해결이 먼저 채워지는 협업 흐름(꼬리 답 하나가 해결을 같이 채움)에서 늘 날 수 있다.

### 1-2. 고칠 곳

**① 앱 — cause 자리의 서버 질문을 거른다 (바로 · 측정 없음)**

`llmQuestionFor` 뒤, `guarded` 앞에 한 단계:

```kotlin
/** cause 자리 서버 질문이 문제 대신 다른 일(해결 · 같이 간 사람의 행동)의 까닭을 묻나 — 그러면 쓰지 않는다 (#304 1) */
internal fun causeAsksOtherEvent(question: String, problem: String?, solution: String?): Boolean
```
- 낱말 앞 두 글자 비교(`saidAlready` 와 같은 `stems`)로, **해결에만 있는 줄기**(해결 줄기 − 문제 줄기)가 질문에 하나라도 있으면 참.
  - 이번 회차: 해결 {아빠, 잡아} − 문제 {풍선, 놓쳤} = {아빠, 잡아} → 「**아빠**는 왜 풍선을 **잡아**줬을까?」 걸림.
  - 「풍선은 왜 놓쳤을까?」 · 「왜 그렇게 됐을까?」는 통과.
- 걸리면 로그 `[cause] 서버 질문이 해결의 까닭을 물어 버림 — "…"` 를 남기고 null → 지금 순서 그대로 이어 받기(`coopFollowUp` 「{thing:가} 왜 그랬을까?」) · 템플릿 · 사다리로 간다.
- 해결이 비었으면 아무것도 거르지 않는다(지금과 같음).

**③ 서버 — `eval/prompt_modes/line_coop.md` 에 한 줄 (측정 뒤 · 공통 프롬프트 아님)**

```
  next_slot 이 cause 면 problem 칸의 일이 왜 일어났는지 묻습니다. 해결(solution)이나 다른 사람이 한 일의 까닭을 묻지 않습니다.
  예) problem=풍선을 놓쳤어 · solution=아빠가 잡아줬어 → "풍선을 왜 놓쳤을까?" (❌ "아빠는 왜 잡아줬을까?")
```
- 측정: `eval/bench_turn_split.py` 류로 협업 문항에 「해결이 먼저 찬 cause 차례」 6건을 더해 전후 각 3회 — 질문이 문제 줄기를 담는 비율 · 해결 줄기를 담는 비율 · 거절 0.
- 앱 거름(①)은 프롬프트가 고쳐진 뒤에도 남긴다 — 모델이 어길 때의 안전판.

### 1-3. 사다리도 같은 결점

사다리 두 번째 칸(`CoopSteps.kt:168`)은 같이 간 사람이 있으면 「**$w는** 왜 그랬을 것 같아?」 — 같이 간 사람(아빠)의 행동을 묻는 꼴이다. 이번에는 「그 일은 …」로 나와 맞았지만, 같이 간 사람이 잡히면 같은 헤맴이 난다. ① 에서 같이 고친다: 협업(`isCoop`)이면 이 칸을 「무엇 때문에 그런 일이 생겼을까?」로(일기 모드 사다리는 진웅 몫이라 건드리지 않음 — `CoopSteps.kt` 의 협업 분기만).

### 1-4. 테스트 (①)

- `CoopCauseQuestionTest`
  - problem 「풍선을 놓쳤어」 · solution 「아빠가 잡아줬어」 · llmNext=(cause, 「아빠는 왜 풍선을 잡아줬을까?」) → 물은 질문이 그것이 아니다 · 로그에 「해결의 까닭」.
  - 같은 상태에 llmNext=(cause, 「풍선은 왜 놓쳤을까?」) → 그 질문을 묻는다.
  - solution 이 빈 상태 → 거르지 않는다.
- `causeAsksOtherEvent` 단위 표 8줄(조사 붙은 줄기 · 문제와 해결이 같은 낱말을 공유 · 같이 간 사람이 문제에도 있는 경우).

## 2. 서버 대사가 있어야 할 답에 「응응!」

### 2-1. 확인한 것

- 서버는 꼬리 자리(`asked_slot=null`)라고 ack 를 비우지 않는다. `turn.py` `shape()` 는 `ask=false` · `story_ready` 일 때 **question · options 만** 비운다. ack 는 스키마상 필수(`Line.ack: str`).
- 앱은 `Server.turn` 의 `ask` 를 기본값 true 로 보낸다 — 꼬리 자리도 같다.
- 그러므로 「응응!」의 길은 둘 중 하나다.
  - (가) `line == null` — 서버가 대사를 거절(`check` 금칙어 · 모르는 자리표시) · 실패(`LLMError`) · 남은 시간 < 3초. 2918 ms 라 시간은 아니다. **PC1 `docker logs otto-backend` 의 그 시각 `line rejected` · `line failed` 로 확인 가능** — 조장 PC 라 이 세션은 못 봤다.
  - (나) 대사는 왔는데 `coopServerReaction`(`CoopServerLine.kt:24`)이 ack · expand **둘 다** 버림 — `?` 가 들었거나(「츄러스 맛있었어?」 꼴 ack), 40자 넘음, `{` 남음, 거친 말.
- **앱은 버린 까닭을 로그에 남기지 않는다.** 서버 대사를 쓰면 「받아주기 — 서버 대사 「…」」를 남기지만 못 쓰면 아무 말이 없다. 그래서 이번 로그로는 (가) · (나)를 못 가른다.
- 그다음 앱 한마디 `coopAck` 는 꼬리 자리(`detail · said · try · after`)에서 `roleOf` 가 null 이라 이름을 못 떼고(「츄러스 사 먹었어」 — 조사 붙은 이름 없음) `PLAIN_ACKS.random()` → 「응응!」.

### 2-2. 고칠 곳 (①)

1. **버린 까닭을 남긴다** — `coopServerReaction` 을 `(text, dropped: List<String>)` 로 돌려주고(또는 이유만 따로 묻는 함수), 못 썼으면
   `[$key] 받아주기 — 서버 대사 못 씀: 대사 없음` / `ack 물음표 「…」` / `expand 40자 넘음` … 를 로그에. 다음 실기기에서 (가) · (나)가 갈린다.
2. **꼬리 답 되비추기** — 이름이 없는 답이 **짧은 지난 일 말**이면 끝만 바꿔 되비춘다.
   - 조건 전부: 5어절 이하 · 끝 어절이 `었어 · 았어 · 했어 · 였어`(마침표 · 느낌표 무시) · 이음 끝(`서 · 고 · 니까 · 는데 · 면`)이 없음 · 1인칭(`나 · 내가 · 저 · 제가 · 우리`)이 없음 · 거친 말 없음.
   - 바꿈: 끝 `어` → `구나!` — 「츄러스 사 먹었어」 → 「**츄러스 사 먹었구나!**」, 「아빠가 잡아줬어」 → 「아빠가 잡아줬구나!」.
   - 조건 밖이면 지금처럼 `PLAIN_ACKS`.
   - 시제: 곧 해요(「먹을 거야」)는 조건에 안 걸려 지금처럼 맞장구. 상상 낱말 답은 이미 앞에서 「…면 깜짝 놀라겠다!」.
3. 서버에서 확인할 것(조장): 그 시각 docker 로그 한 줄. (가)면 거절 까닭이 무엇이었는지 — 금칙어 오탐이면 별도 이슈.

⚖️ **사용자(치영) 결정** — `CoopReact.kt` 머리 주석의 10-02 결정 「아이 문장을 활용형으로 바꾸지 않는다(「불이 크니까구나!」)」에 좁은 예외를 두는 일이다. 위 조건이 그 실패(이음 끝 + 구나)를 막도록 짰다. 싫으면 2만 하고 3은 하지 않는다 — 그래도 로그로 원인은 잡힌다.

### 2-3. 테스트 (①)

- `CoopAckTest` 에 표: 「츄러스 사 먹었어」 → 「츄러스 사 먹었구나!」 · 「불이 크니까 무서웠어」 → 맞장구(이음 끝) · 「나 츄러스 먹었어」 → 맞장구(1인칭) · 「츄러스 먹을 거야」 → 맞장구 · 6어절 → 맞장구.
- `CoopServerLineTest`: ack 에 `?` · expand 41자 → null 과 함께 까닭 둘.

## 4. 책 문장의 따옴표

### 4-1. 길

- 꼬리 질문 「아빠가 뭐라고 했어?」의 답 「괜찮다고 했어」가 `extra` 에 「질문」에 「답」 꼴로 간다(157431c8).
- `story_prompt_coop.md` 규칙 14: 「따옴표는 누가 한 말에만 — 「뭐라고 했어 · 뭐라고 할까」의 답 …」. 이 답은 그 자리라 따옴표 대상이 됐고, 모델은 글자 그대로 넣은 뒤 「라고 말했어요」를 붙였다.
- 아이 답이 **이미 옮긴 말**(간접 화법 「~다고 했어」 · 「~래」 · 「~라고 했어」 · 「~냐고 했어」)이면 따옴표 안에 넣을 직접 발화가 없다. 규칙이 이 경우를 가르지 않는다.

### 4-2. 고칠 곳 (③) — 규칙 14 에 한 줄

```
    답이 이미 남의 말을 옮긴 꼴(「~다고 했어」 · 「~래」 · 「~냐고 했어」 · 「~라고 했어」)이면 따옴표를 쓰지 않고 그대로 옮겨 씁니다.
    ✅ "아빠는 괜찮다고 했어요."  ❌ "아빠는 “괜찮다고 했어.”라고 말했어요."
```
- 앱 쪽 고침(책 문장을 폰에서 바꾸기)은 하지 않는다 — 생성 문장을 앱이 고치면 다른 쪽과 어긋난다. 프롬프트 한 곳에서.
