## 1. #255 — 「있었던 일로 준비하기」를 눌러도 반응이 없다

### 1-1. 원인 (✔ 코드 확인)
- 버튼은 `prepareAfter(a)`(`ui/Parent.kt:708-710`)를 부른다 — 메모리 초안만 바꾼다(`pick = CoopPick(kind, name, DONE)` · `fromAfter = a` · `editing = true`). 확정은 아래 [저장하기](`:854`)이고, 그 뒤 소파에 🎁 가 붙는다. **이 흐름 자체는 설계대로다**(협업모드_확장_설계 §2-2: 「[저장하기]로만 확정」).
- **버그는 초안이 화면에 안 보이는 것이다.** `CoopTemplateCards` 의 `var kindKey by remember { mutableStateOf(pick?.kind) }`(`:576`)는 처음 그릴 때 한 번만 읽는다. 상자가 떠 있던 화면에서 카드는 `pick == null` 로 먼저 그려져 `kindKey = null` 이 남고, `prepareAfter` 뒤에도 갱신되지 않아 `if (kind == null) return`(`:614`)에 걸린다. 종류 · 요소 · 「체험했어요」 칩이 하나도 선택되지 않은 채 보인다.
- 머리 문구도 일반 문구 그대로다(`:467`).

### 1-2. 고칠 것
1. `remember(c.fromAfter) { mutableStateOf(c.pick?.kind) }` — **열쇠를 `fromAfter` 로.** `pick?.kind` 를 열쇠로 하면 아이템을 고르기 전에 종류만 바꾼 부모의 선택이 `pick` 이 바뀔 때 되돌아갈 수 있다. `fromAfter` 는 상자에서 꺼낼 때 · 취소할 때만 바뀐다.
2. 머리 카드(`:466-469`) — `c.fromAfter != null` 이면
   - 제목 「‘${name}’ 다녀온 이야기를 준비하고 있어요」
   - 부제 「질문은 비워 두었어요. 더 물어볼 게 있으면 적고, [저장하기]를 누르면 소파에 🎁가 붙어요.」
3. 「저장하고 바로 시작」 버튼은 **넣지 않는다** — 부모가 준비하고 아이가 소파를 누르는 두 단계가 협업 모드의 뼈대다(부모가 아이 앞에서 시작하게). 문구로 다음 단계만 알린다.
4. `prepareAfter` · `save` · `dismissAfter` 에 OttoTrace 한 줄씩 — 「부모 · 다녀온 이야기 준비 ‘동물원’(가기 전 책 id)」 「부모 · 저장 — 짝 지을 책 id」. `Parent.kt` 에 로그가 0줄이라 이번 같은 일이 로그로 안 보였다.

### 1-3. 검사
- Robolectric Compose 테스트 하나(`CoopAfterPrepareScreenTest`): 상자에 칸 하나 → 같이 만들기 탭 → [있었던 일로 준비하기] 클릭 → 「체험했어요」(또는 그 종류의 DONE 이름) 칩이 선택돼 보이고, 머리 문구가 「다녀온 이야기」 → [저장하기] → `s.coopReady` · `CoopPlan.beforeBookId == 가기 전 책 id`.
- 기존 `CoopAfterBoxTest` 9개 그대로 통과.

### 1-4. 바로 넘겨도 되나 — **예.** 한 파일(`Parent.kt`)의 협업 절이고, 설계 판단이 필요한 곳이 없다. 1~4를 한 PR 로.

### 2-2. 고칠 것
1. **바뀐 내용 표** — `Terms.kt` 에
   ```kotlin

   val TERMS_CHANGES: Map<String, List<String>> = mapOf(
       "2026-10-06.3" to listOf("오또 목소리(타입캐스트)는 선택 동의로 바뀌었어요"),
   ```

2. **`ConsentStep(reconsent: Boolean)`** — `OttoShell` 이 `Shell.onboarded && Accounts.guardian != null` 일 때 `true` 로 부른다.
   - 진행 점을 숨기고 제목 「약관이 바뀌었어요」, 부제 「다시 확인하고 동의해 주세요. 바뀐 것:」 + 1의 줄들(최대 3줄 · 넘치면 「외 n개」).
   - 항목 목록 · 전체 동의 · 선택 항목 미리 체크하지 않기는 그대로(눈속임 설계 금지 — 지금 화면의 원칙 유지).

3. **판 올리기 규칙** — `Terms.kt` 머리 주석에:
   - 올린다: 동의 **대상**이 바뀔 때 — 수집 항목 · 목적 · 보유 기간 · 수탁사 · 제3자 제공 · 국외 이전 · 필수/선택 구분.
   - 안 올린다: 맞춤법 · 표현 · 화면 배치 · 거절 문구만 바뀔 때.
   - 올릴 때는 `TERMS_CHANGES` 에 한 줄을 같이 적는다(없으면 `TermsTest` 가 실패하게).
4. ⚖️ **선택 항목만 새로 생긴 경우**(예: 타입캐스트 선택 동의)는 전체를 다시 막지 않는 길도 있다 — 앱은 열고 부모 영역 설정에 「새 선택 항목이 있어요」 카드. 필수 항목이 바뀌었을 때만 다시 동의 화면으로. 법적으로 충분한지는 [확인 필요 — 조장 · 멘토]. 이 설계는 **지금처럼 막는 쪽을 기본**으로 두고, 결정되면 바꾼다.

## 3. #258 — 불기가 불지 않아도 저절로 끝난다

### 3-1. 원인 (✔)
- 판정은 마이크 **크기 하나**다: `ui/Blow.kt:84-86` 평균 진폭 ÷ 6000, 평활 0.6/0.4. 문턱 `BLOW_ON = 0.22`(`ui/missions/C1Blow.kt:51`). 같은 파일 주석의 실측으로 말소리 꼭대기가 0.12~0.6 이라 말소리가 문턱을 넘는다.
- 넘는 동안 매 프레임 **소품 셋에 동시에** `level × 0.09` 가 쌓인다(`C1Blow.kt:105-119`) — 0.22 에서 약 2.5초, 0.4 에서 약 1.4초면 다 끝난다.
- **미션 화면이 그려지는 순간 마이크가 열리고**(`DisposableEffect`), 같은 쪽에서 `announce()` → `say(bookCaption)`(`Scenes.kt:1533`)으로 오또 낭독이 스피커로 나간다. 에코 제거(`AcousticEchoCanceler` · `NoiseSuppressor`) 0건. 「오또가 말하는 중」을 밖에서 알 수 있는 공개 값이 없다(`Voice.player` · `Director.voiceJob` 은 private · `Voice.kt:191-193` · `Director.kt:333`).
- 완료할 때 효과음(SPARKLE)이 마이크가 열린 채 난다(`C1Blow.kt:100` · `A6Rub.kt:196,222` · `C3Sound.kt:152`).
- **A6 문지르기**도 소품 이름에 먼지 · 모래 · 가루가 있으면 같은 판정으로 마이크를 켠다(`A6Rub.kt:126-127,189-198`) — 동화 실시간의 기본 소품이 먼지라(§4) 자주 걸린다.
- C3 소리 미션도 낭독 음절을 박자로 셀 수 있다(같은 마이크 · 같은 순간).

### 3-2. 고칠 것 — 판정을 한 곳(`BlowDetector`)으로
1. **오또가 말하는 동안은 듣지 않는다** — `Voice` 에 공개 상태 하나:
   ```kotlin
   /** 마스코트 목소리 · 효과음이 스피커로 나가는 중 — 불기 · 소리 미션이 판정에서 뺀다 */
   val playing: StateFlow<Boolean>
   ```
   `Sfx.play` 도 소리 길이(0.28초)만큼 같은 값을 올린다. 판정기는 `playing` 이 참인 동안 **그리고 끝난 뒤 0.5초** 들어온 프레임을 버린다. (`Voice.kt` · `Director.kt` · `Sfx.kt` 는 조장 파일 — 리뷰어)
2. **들을 때를 알린다** — 미션 쪽을 열면 낭독이 끝난 뒤에 마이크 표시(`MicListeningTag`)를 켠다. 낭독 중에는 「오또 이야기가 끝나면 후~ 불어 봐」 대신 아무 표시 없이 기다린다(아이가 기다리는 법을 배운다).
3. **「후~」와 말소리를 가른다** — 크기만이 아니라 세 조건이 **함께 300ms 이상** 이어질 때만 「부는 중」:
   | 조건 | 출발값 | 까닭 |
   |---|---|---|
   | 크기 | 평활 크기 ≥ 0.30 (지금 0.22) | 말소리 아래쪽을 빼기 |
   | 영점 교차율(ZCR) | 프레임(64ms)의 ZCR ≥ 0.25 | 「후~」는 마찰 잡음이라 ZCR 이 높고, 모음은 낮다 |
   | 고음 비율 | 2kHz 이상 에너지 / 전체 ≥ 0.45 (16kHz 샘플 · 간단한 1차 고역 필터) | 숨소리 · 바람 소리 쪽 |
   출발값은 실기기 녹음(아래 검사)으로 고친다. 상수는 `BlowDetector` 한 곳에.
4. **쌓이는 속도** — 소품을 **하나씩** 날린다(셋 동시 X). 한 소품에 「부는 중」 누적 0.8초면 날아간다 → 셋이면 2.4초 이상 실제로 불어야 끝난다. 탭 · 쓸기 길은 그대로(못 부는 아이 · 시끄러운 곳).
5. **에코 제거** — `AcousticEchoCanceler.isAvailable()` · `NoiseSuppressor.isAvailable()` 이면 켠다(없는 기기는 1~3 으로 막는다). 오디오 소스는 그대로 `VOICE_RECOGNITION`.
6. **같은 판정기를 쓰는 곳** — C1(불기) · A6(먼지 불기 덤) · C3(소리 — 크기 조건만 쓰고, `playing` 게이트는 같이).
7. 효과음 중복 — 완료 반짝이 두 번 나는 다섯 미션(`A1Hose.kt:84` · `A4Turn.kt:78` · `E2Fix.kt:82` · `A5Stack.kt:79` · `A6Rub.kt:257/196` + `MissionShell.kt:61`)은 #260 공통 틀에서 한 번으로(여기서는 건드리지 않는다).

### 3-3. 검사
- **순수 함수 테스트**(`BlowDetectorTest`) — PCM 배열을 넣고 판정을 본다:
  - 오또 낭독 녹음(실기기에서 `say(bookCaption)` 를 같은 폰 마이크로 녹음한 16kHz wav 3개) → 진행 0

  - 실제 「후~」 3개 · 숨 길게 불기 → 완료
