# 질문 조절 전후 평가 — 10-13 사전 계획

## 범위와 기준

#320의 전후 수치를 얻기 위한 **동일 입력 재생 비교**다. 실제 아동 모집·실기기·운영 모델 호출은 포함하지 않는다. 결과를 보기 전에 이 문서와 #320 댓글로 기준을 고정한다.

- 기준 코드: main `5ece0938482a87650d6b5d9030d74831e9b89ddd`.
- 전: 이전 책의 기록을 제공하지 않는 조건. 기본 CHAIN에서 현재 세션의 기존 조절 규칙은 그대로 작동한다.
- 후: 같은 프로파일의 이전 책에서 측정한 기록을 저장·재로드한 조건. 실제 `initializeStoryQuestionStyle`을 사용한다.
- 이것은 #409의 **기록 이월 기능 유무** 비교이며, 과거 앱 전체와 현재 앱 전체의 비교 또는 조절 기능 전체 끄기 실험이 아니다.
- 합성 이력 여섯 조건: 짧은 직접 답 2개, 까닭+연결 답 2개, 연결만 2개, 까닭 답 1개, 선택 답 2개, 다른 아이로 전환.
- 각 조건에서 4개 직접 답과 서버 판정은 전후 동일하게 고정한다. HTTP 응답은 요청 단계에 맞춰 유리하게 바꾸지 않는다. 4번 중 3번은 서로 다른 칸을 채우고 1번은 채우지 않는다.
- 실제 로컬 HTTP → 판정 적용 → 질문 규칙 → 기기 저장 경로를 사용한다. 언어 모델이 만든 질문 문장·아이 반응의 변화는 측정하지 않는다.

## 지표와 판정

1. 채움률: 신규 칸이 채워진 요청 수 / 직접 답 요청 수. 두 조건의 분모는 각각 4이며, 필수 슬롯 완성률이 아니다.
2. 주고받기: 정상 응답을 받은 직접 답 `/turn` 왕복 수. 4개 고정 재생이므로 자발적 발화 증가를 측정하지 않는다. 앱의 counted turn도 별도 대조한다.
3. 요청 단계: `/turn.level` 4개를 순서대로 기록하고 시작 단계 및 바뀐 요청 수를 비교한다.
4. 부작용: 추가 `/judge` 호출, 이전 책 원문·연령 업로드, 선택 답 또는 다른 아이 기록으로 시작 단계가 바뀌는지 검사한다.
5. 성공 조건: 독립 조건 간 상태 누출 없이 같은 입력을 처리하고, 명시된 이력 조건만 시작 질문에 반영되며, 추가 호출 없이 칸 채움·직접 답 왕복을 보존한다. **개선 수치가 나와야만 통과시키지 않는다.**
