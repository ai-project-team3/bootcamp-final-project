# 윤문 문체 비교 사전 계획 — 2026-10-13

읽은 것: main `65396751`의 동화 책 프롬프트·시스템 블록 추출·쪽 계획·자막 검사·스키마 주석, #462 사전 기준, 국내 그림책 연구 원문과 원전 제공 기관의 정보. 이번 산출물은 문체 비교를 위한 자료 준비다. 모델 생성·실기기 실행·실제 아동 사용 실험은 하지 않았다. **실제 모델 실행은 0회이고 문체 개선 효과는 아직 가설이다.**

## 기존 평가와의 관계

[#462 사전 기준](https://github.com/ai-project-team3/bootcamp-final-project/issues/462#issuecomment-6141999428)을 유지한다. 성인 한 명의 시연 기록 2권에서 확인한 세 가지 의미 보존 문제는 사용자가 AI 제안을 보고 동의한 점검이다. 독립 전문가 정답이나 실제 아동 효과가 아니다. 해당 자료는 이미 검토했으므로 개발 동기로만 사용하고 잠금 평가 표본으로 쓰지 않는다. 기존 29개 직접 답·책 원문은 이 fixture에 복사하지 않았고 웹·새 모델 API로 보내지 않았다.

책 한 권의 통과 조건은 평가 가능한 핵심 정보·결말·고유 표현 100% 보존, 근거 없는 핵심 사실 추가·의미 반전·잘못된 귀속 0건, 모든 페이지의 이해 가능성 2점 이상이다. 1점은 뜻 파악이 어렵거나 비문, 2점은 뜻은 분명하나 어색함, 3점은 뜻이 분명하고 자연스러움이다. 불명확 원문·정책 충돌은 보류하고 보류를 통과로 세지 않는다. 생성 실패·fallback을 분모에서 빼지 않는다. 고유 표현이 없는 책의 고유 표현 비율은 적용 대상 없음으로 표시하며 0/0을 100%로 만들지 않는다.

문체가 선호되어도 이 조건을 어긴 결과는 내용 실패다. 원문의 폭력적 해결을 비폭력적 행동으로 조용히 바꾼 결과도 보존 성공으로 세지 않는다. 정책과 원문이 충돌하면 원문 기록은 보존하고 책 생성·게시를 보류하거나 별도 변경안을 확인받는 경로를 검토한다. 이번 비교에 안전 정책 변경을 섞지 않는다.

## 기존 문체 제약과 충돌

현재 런타임 프롬프트에는 이미 장면당 한 문장·15어절 이하·`-어요`체, 의성어·의태어와 이름 보존이 있다. 이번 A/B의 낭독 문체 목표는 이 기준을 그대로 사용한다. `backend/app/schemas/story.py`의 자막 주석은 1~2문장·문장 12어절·쪽 20어절로 달라서, 그 주석을 실제 길이 검사 결과로 소개하지 않는다. 비교 중 어느 한 조건만 새 길이 기준으로 바꾸지 않는다.

현재 `story.check()`는 쪽 수·금칙어·모르는 자리표시자를 검사하며 문체나 의미 보존을 자동으로 보증하지 않는다. [실제 요청 구성](https://github.com/ai-project-team3/bootcamp-final-project/blob/65396751dd8169c6a63d926ec7df32a45f7e88ef/backend/app/routers/story.py)은 동화의 슬롯·틀·수준·쪽 계획을 사용한다. 입력 전에 빠진 직접 답을 말투만으로 복원할 수 있다는 가정을 두지 않는다.

비폭력 결말 지시, 일부 슬롯 생략 허용, 미션 쪽 창작 허용은 등록한 핵심 정보 보존 기준과 충돌할 수 있는 후보다. 과거 두 권의 생성 당시 입력·프롬프트·후처리 기록이 없었던 점 때문에 그 원인을 현재 코드로 확정하지 않는다. 앞으로는 생성 자막과 앱 미션 결과가 붙은 최종 자막을 구분하여 같은 기준으로 별도 평가하고, 차이가 생긴 단계의 출처를 기록한다.

## 독창적 합성 fixture와 잠금

[합성 자료 JSONL](../eval/fixtures_story_rewrite_style_1013.jsonl)은 이 비교를 위해 직접 작성한 한국어 책 12개다. 실제 아동·성인의 기존 전사나 상업 동화책 문장을 포함하지 않는다. 입력 원문과 출처, 보호할 핵심 fact, 고유 표현, 허용된 배경 설정, 쪽 종류 stub와 예상 검토 상태만 있다. 생성 자막·가짜 모델 출력·가짜 통과 수치는 없다.

| 용도 | 책 ID | 확인할 범위 |
|---|---|---|
| 개발 4개 | DEV01~DEV04 | 장소·완료 결말, 명시적 까닭, 직접 대사·소리·의향, 카드/오또 출처 |
| 잠금 평가 8개 | LOCK01~LOCK08 | 인물 귀속, 완료/미래 구별, 까닭·부정, 복합 결말·중단, 고유 표현, 배경 출처, 명시적 이름 정정, 안전/보존 충돌 |

`source=child`는 합성 데이터의 역할 표기다. 실제 아동 자료라는 뜻이 아니다. `card`·`mascot` 설정은 허용된 배경의 출처로 따로 표시하며 아이의 직접 답 fact로 세지 않는다. LOCK08은 안전/보존 충돌 통제 사례다. 기대 검토 상태는 `policy_conflict_requires_review`이며 안전한 다른 행동으로 바꾼 결과를 통과로 인정하지 않는다. 이 보류도 전체 책 분모에 남긴다.

쪽 계획은 `is_execution_contract=false`인 6쪽 stub다. 아직 실제 앱 템플릿·미션 결과와 연결한 요청은 아니므로 JSONL 행을 API 요청처럼 바로 전송하지 않는다. 실행 전에 이 stub와 실제 요청/최종 후처리의 대응, 결과 수집 방법을 확인하고 요청 해시를 추가로 고정한다. 원문 fact를 바꾸거나 다른 쪽 계획으로 대체하면 새 자료 버전·새 사전 계획이다.

| 잠금 대상 | SHA-256 |
|---|---|
| 전체 JSONL 현재 파일 바이트 | `9f91eb01df4f19a153e53a72cb40ce75e8e9a0b9bf33a0a5483b0a0ed1ef5b18` |
| 잠금 평가 8행의 정규화 표현 | `d3c95cd7a64772d415a0bfbb5051bdbeefb019fc68938165491d60f4a3385720` |

정규화는 UTF-8 JSONL 파싱 후 `split=locked_evaluation` 행을 현재 순서대로 골라, 행마다 `json.dumps(row, ensure_ascii=False, sort_keys=True, separators=(',', ':'))`에 LF 한 개를 붙인 UTF-8 바이트다. 실행 전에 이 해시를 확인한다. 첫 모델 출력 이후 LOCK 자료·fact·기준·후보 문구를 그 결과에 맞춰 고치지 않는다. 실패를 보고하거나, 새 개발 자료에서 수정한 후 새 잠금 평가를 별도로 준비한다.

## 실행·검토 계획과 필요한 승인

최소 잠금 평가는 8책 × A/B 2조건 × 각 3반복으로 **48회 생성**이다. 개발용 4책의 모델 실행은 이 48회에 포함되지 않으며 추가 실행 횟수와 비용 승인이 필요하다. 지금 실행 횟수는 0회다. 이는 작은 기술 점검이고, 3~7세 전체의 문체 우월성이나 아동 발화 증가를 입증하는 표본 크기가 아니다.

모델·provider·버전·effort·출력 토큰 한도·timeout·스키마·요청 원문·쪽 계획·후처리를 양쪽에서 같게 고정한다. 제공자 seed 고정이 지원되지 않으면 고정했다고 쓰지 않는다. A/B 순서를 책·반복별로 번갈아 배치하고, 실패 재시도를 성공한 결과로 갈아치우지 않는다. 미완료·실패·fallback과 사용량·지연을 따로 기록한다. 모델 실행과 자동 LLM 채점은 모두 별도 비용 승인 전에는 하지 않는다.

한국어 검토자 2명이 가능하면 버전명을 가린 결과를 독립 판정한다. 먼저 원문·출처와 대조해 내용 통과 여부를 정한다. 문체 선호는 **동일 책·반복·자막 단계에서 A/B 양쪽이 내용 기준을 통과한 쌍**에만 기록한다. 한쪽만 내용 통과하면 의미 보존 차이로 보고하고 문체 선호의 쌍 분모에서 제외한다. 양쪽의 전체 내용 실패·보류 건수는 그대로 공개한다. 비교 가능 쌍(`eligible_pairs`)·A 선호·B 선호·동률·평가 불가를 별도 집계한다. 한 명 또는 AI 보조 검토만 가능하면 그 검토 범위를 그대로 공개한다. 검토자가 실제 아이를 대신하여 연령 적합성을 입증했다고 쓰지 않는다.

평가 행은 `attempt_id`, 실제 `book_id`(저장 실패면 null), `condition`, `repeat`, `caption_stage`, `page_index`를 연결한다. `caption_stage`는 앱의 파싱된 응답(`parsed`), 자리표시자를 복원한 채택 후보(`restored`), 미션 결과를 붙여 실제 저장한 자막(`final`)로 구분한다. 각 단계별 내용 통과·핵심 정보/고유 표현 보존·의미 반전·귀속·핵심 추가·이해 점수를 따로 기록한다. 파싱 전 원시 모델 출력은 앱 수집기에서 확보한 것처럼 적지 않는다. **주지표는 최종 저장 책의 통과 수/전체 시도 수**이며 생성 단계 지표와 후처리에서 추가된 오류(`postprocess_added_error`)는 보조 지표다. 저장 실패/취소도 전체 시도 분모에 남긴다. 최종 자막이 없는 시도에 생성 자막 점수를 대신 넣지 않는다.

| 보고 지표 | 분모와 해석 |
|---|---|
| 반복 실행별 책 통과 | 조건별 24실행. 실패·보류·fallback 포함 |
| 반복을 모두 통과한 고유 책 | 조건별 8책. 같은 책의 3반복이 모두 통과했는지 별도로 표시 |
| 핵심 정보·고유 표현 보존 | 적용 가능한 fact/표현 수. 원문·출처별 누락 근거 포함 |
| 의미 반전·귀속·근거 없는 핵심 추가 | 책과 페이지별 구체 근거. 알 수 없는 출처는 보류 |
| 문체 선호와 이해 가능성 | 동일 책·반복·동일 자막 단계에서 A/B 양쪽 내용 통과 쌍. 단계별 비교 가능 쌍·동률·평가 불가, 전체 시도의 내용 실패를 함께 공개 |

문체 선호가 높아도 새 의미 반전·귀속 오류나 핵심 정보 누락이 생기면 채택 근거로 삼지 않는다. 조건별 8개의 고유 책을 24명의 아이처럼 보고하지 않는다. LOCK08의 정책 보류 때문에 전체 통과율이 낮아지는 경우도 감추지 않고 사례 유형과 함께 보고한다.
