# 리포트 기반 맞춤 질문과 윤문대조 평가

2026-10-13 열람 · 소스 기준 main `0e0a2c64`. 읽은 것: 앱 발화 관찰·질문 이력·책 자막 경로, #462 사전 기준, #443·#454·#459의 결과와 보존된 평가 파일. 읽지 않은 것: 다른 팀원 기기의 원자료와 운영 서버 저장 자료. 아래는 기능 현황·기존 결과 재집계·윤문 평가 계획이며 실제 아동 사용 효과 검증은 아니다. 확인하지 못한 자료가 다른 환경에도 없다는 뜻은 아니다.

## 현재 구현과 확인 범위

- 질문 원문·유형·답 출처와 아이별 이력을 기기에 보관한다. 직접 말한 답과 카드·마스코트가 채운 말은 구별한다.
- 앱 `SpeechObservations`는 최근 50개 유효 직접 답에서 공백 낱말 수, 다른 표현 수, 까닭 표현을 계산한다. 형태소 MLU-m이나 형태소 NDW가 아니다.
- `QuestionStyle`은 답 길이·까닭·연결·이야기 구조의 신호에 두 번 연속 규칙을 적용한다. 이전 책의 유효 기록을 읽어 같은 아이의 새 책 시작 단계를 고르며, 현재 세션에서도 질문 방식을 조절한다.
- Kiwi 기반 `eval/language_metrics.py`는 오프라인 평가용이다. 앱이 매 턴 Kiwi를 실행하는 구조로 설명하지 않는다.
- 선택 나이와 별도 연구 참고 카드가 있다. 연구 수치를 개인 발달 진단이나 질문 문턱으로 쓰지 않는다. #434·#437·#441·#443은 병합 완료다.

근거: [PR #443](https://github.com/ai-project-team3/bootcamp-final-project/pull/443), [SpeechObservations](https://github.com/ai-project-team3/bootcamp-final-project/blob/0e0a2c64/android/app/src/main/java/com/example/finalproject_demo/demo/SpeechObservations.kt), [StoryQuestionStyle](https://github.com/ai-project-team3/bootcamp-final-project/blob/0e0a2c64/android/app/src/main/java/com/example/finalproject_demo/demo/StoryQuestionStyle.kt), [최종 정리](https://github.com/ai-project-team3/bootcamp-final-project/blob/0e0a2c64/docs/발화지표_최종정리_1013.md).

## 기존 자료의 오프라인 재집계

새 모델 호출 없이 보존된 `adaptive-history-ablation-1013.json`을 다시 합산했다. 원본 SHA-256과 계산값은 동봉한 [오프라인 재집계 JSON](../eval/baselines/adaptive-history-offline-audit-1013.json)에 기록했다.

| 지표 | 이전 책 이력 없음 | 같은 아이 이력 재로드 |
|---|---:|---:|
| 조건 | 6 | 6 |
| 로컬 HTTP 요청 | 24 | 24 |
| 새 칸을 채운 요청 | 18 | 18 |
| 채움률 | 75% | 75% |
| 리포트 주고받기 / counted turn | 24 / 24 | 24 / 24 |
| 추가 `/judge` | 0 | 0 |

6쌍·12실행·총 48요청이다. 24쌍 중 8쌍의 요청 단계가 바뀌었다. 짧은 직접 답 2회는 고르기, 까닭+연결 직접 답 2회는 까닭 묻기로 시작한다. 연결 표현만, 답 1회, 선택 답, 다른 아이로 전환한 네 조건은 이어 묻기를 유지한다.

합성 입력과 서버 판정이 고정된 재생으로 질문 단계와 기록 연결을 확인했다. 12명의 실제 아이 실험, 책 필수 슬롯 완성률, 발화량이나 실제 성공률 향상으로 해석하지 않는다.

## 윤문대조표 사전 기준과 결과

윤문대조표는 **아이 답 원문과 책으로 다듬어진 문장 비교**다. [#462 사전 기준 댓글](https://github.com/ai-project-team3/bootcamp-final-project/issues/462#issuecomment-6141999428)을 먼저 등록한 뒤 기존 파일만 탐색했다.

**현재 측정 가능한 동화 대응쌍은 0권이다. 통과율·보존율은 측정 불가(null)다.** 0% 통과라고 쓰지 않는다. 기존 합성 동화 fixture는 입력 또는 예시 출력만 있고, 같은 책의 대화 원문과 생성/최종 자막을 연결한 결과가 없다. 기존 일기 captions는 동화의 윤문 결과로 합치지 않았다.

탐색 범위:

- 현재 읽기 전용 checkout의 `eval` 파일 목록과 main `0e0a2c64` 트리. `eval/raw` 없음. 동화 관련 fixture와 bench는 있으나 생성출력 대응쌍 없음.
- 10-12 기존 동화 작업 트리의 `eval` 관련 파일 목록. `eval/raw` 및 `outputs` 폴더가 없음. 일기 results 폴더는 있으나 동화 대화-책 대응쌍은 없음.
- 앱 코드의 책 page plan·생성 자막 적용·미션 결과 후처리와 `eval/story_prompt.md`의 보존 규칙.

이는 확인한 폴더의 자료 확보 결과다. 다른 팀원 기기나 운영 서버 전체에 자료가 없다는 주장은 하지 않는다. PR #454의 일기 expand 수치와 PR #459의 Jev 판정·지연 수치를 윤문대조표 결과로 바꾸어 쓰지 않는다.

### 다음 자료의 보존 항목

책 ID(비식별), 앱/서버 커밋, 같은 책의 원문 대화와 출처(child/card/mascot), 최종 슬롯과 귀속, page plan와 허용 설정, 생성 자막, 앱 후처리를 거친 최종 자막, 생성 실패·fallback 여부, 입력·출력 파일 SHA-256을 함께 보존한다. 실제 아동 자료는 별도 동의·보관 범위를 정하기 전 수집하지 않는다.

### 통과 조건

책 1권을 단위로 각 페이지를 점검한다. 근거 없는 핵심 사실 추가·의미 반전·잘못된 귀속이 0건, 평가 가능한 인물·장소·행동·까닭·결말과 고유 표현 보존이 100%, 모든 페이지 이해 가능 점수가 2점 이상이면 통과한다. 1점은 뜻이 어렵거나 비문, 2점은 뜻은 분명하나 어색함, 3점은 분명하고 자연스러움이다.

원문에 없는 연결 문장은 page plan·허용 설정의 출처와 구별한다. 카드·앱 미션·템플릿 설정을 아이가 직접 말한 사실로 계산하지 않는다. 불명확 원문은 보류하며 보류를 통과로 세지 않는다. 생성 실패·fallback을 표본에서 빼지 않고 따로 집계한다.

책 통과 수/전체 책 수, 생성 성공률, 사실 오류 책 수/전체 책 수, 보존한 핵심 정보 수/평가 가능한 핵심 정보 수, 보류·fallback 건수를 보고한다. 페이지를 독립 아이 표본처럼 세지 않는다. 독립 사람 검토가 없으면 AI 보조 점검으로 표시한다. [대조표 CSV 헤더 양식](../eval/templates/story-utterance-book-review-1013.csv)에 원문·책 문장과 판정을 직접 입력할 수 있다. 헤더만 있으며 실제 측정 행은 없다. 파일에 행을 넣을 때에도 원문과 식별 가능한 개인정보를 공개 저장소에 올리지 않는다.

## 기능 로드맵

| 단계 | 다음에 확인할 것 | 결과에 따른 변경 | 완료 판단 |
|---|---|---|---|
| 1. 대응쌍 확보 | 기존 담당자 자료에서 원문·생성 자막·최종 자막 연결, 버전·해시·전체 건수 고정 | 쌍이 없으면 실패율을 만들지 않고 보존 형식부터 정함 | 같은 책의 출처와 입력/출력을 끝까지 추적 가능 |
| 2. 윤문 오프라인 평가 | 등록 기준으로 책·페이지별 추가/누락/반전/귀속/고유 표현/이해 가능성 확인 | 오류가 전사인지 슬롯인지 생성인지 후처리인지 후보 구분. 사람이 독립 검토하면 불일치도 기록 | 전체 분모와 보류·fallback 포함 수치 공개 |
| 3. 원인별 수정 | 원문과 슬롯이 다르면 판정, 슬롯은 맞고 자막이 다르면 책 생성, 생성은 맞고 화면이 다르면 후처리 점검 | 개발 자료에서 최소 수정 후 별도 고정 확인 자료로 재검증. 동일 표본에 기준을 맞추지 않음 | 등록 기준 유지, 기존 문제 재현 제거, 새 핵심 정보 오류 없음 |
| 4. 질문과 리포트 통합 | #456 반영 후 같은 아이 재로드·다른 아이 전환·선택 답 제외·기록 삭제와 최종 책 흐름 | 이력/화면/요청 연결 실패면 해당 경로 수정. 생성 질문의 문장 적합성은 고정 답 연결 검사와 별도 평가 | 실제 통합 화면 및 기록 경로 확인. 유료 모델 재실행은 별도 승인 후 |
| 5. 실제 아동 효과 확인(미래) | 동의와 모집 계획, 질문 유무 비교 및 직접 답 길이·까닭·응답 실패·교환 수 | 사전 기준과 동일 단위 확보 후 질문 방식 효과를 판단. 향상 없으면 이유 후보와 비용 함께 보고 | 별도 승인된 연구/사용 실험. 이번 실행 범위에서 제외 |

단계 4~5의 새로운 비교에서는 표본·반복 수·사전 통과 기준을 별도로 먼저 정한다. 현재 75%를 아동 효과 실험의 기준선으로 사용하지 않는다. 새로운 유료 API 호출, 실아동 모집, 운영 데이터 변경을 이번에 수행하지 않았다.

## 발표에서 구별할 다른 근거

공개 주석 385개는 제공된 형태소 목록의 합산 일치 검사다. 자동 분절 정확도 100%가 아니다. 아동 전사문 50개는 AI 제안을 본 사용자 검토이며 동의 45·보류 5, 독립 전문가 정확도 90%가 아니다. AI-Hub 108의 653명×50답에서 3/4/5/6세 평균 형태소 길이 5.68/5.60/5.63/5.73으로 뚜렷한 증가를 재현하지 못했다. 별도 국내 연구 참고 카드는 같은 단위의 개인 진단으로 쓰지 않는다.

## 검토할 결정

기존 동화의 대화-자막 대응쌍을 어디서 확보할 수 있는가? 대응쌍 보존부터 완료하면 같은 기준으로 윤문을 평가하고, 실패가 발생한 경로를 근거로 다음 수정을 고를 수 있다. 파일 보존 범위와 재실행 권한을 정하기 전에는 새 유료 생성이나 실제 아동 모집을 진행하지 않는다.
