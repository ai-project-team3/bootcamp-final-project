# 09-30 동화 실제 연결 작업 계획

기준: `main`의 `dab1442`, `guidelines/6_통합_체크포인트.md`의 「09-30(수) 오늘」과 사용자가 승인한 작업 순서.

## 완료 기준

동화 모드에서 실제 말 → 받아쓰기 → `/turn` → 다음 질문과 목소리 → 배경과 주인공 생성 → `/story` → 미션 → 책장 저장과 재열기가 이어진다. 실제 서버 결과와 가짜 응답 검증을 구별해 기록한다. 실제 서버 주소가 없으면 앱 연결과 에뮬레이터 검증을 진행하되 실제 AI 완주를 완료했다고 기록하지 않는다.

## 작업 단위

1. **실제 발화 기록**: 시연 답의 `answer`가 없어도 아이 원문과 서버의 S1/S2 신호를 기록한다. 회귀 검증 후 커밋한다.
2. **판정에 따른 질문 진행**: `nextStoryPrompt`를 실제 진행에 연결한다. 이미 채운 칸은 건너뛰고 `next_slot`을 우선한다. 최신 main `02d4010`의 규칙에 따라 `story_ready`만으로 종료한다. 카드와 마스코트 선택도 출처를 구분해 판정에 보내며 시간이나 연속 대리 선택으로 끝내지 않는다. 틀 고유 빈칸은 서버 다음 칸이 없을 때 묻는다. 회귀 검증 후 커밋한다.
3. **생성 주인공 표시와 선택**: 말로 받은 설명을 가리고 `Server.character`를 부른다. 생성 PNG와 `rig`를 공통 뼈대 입구에 넘긴다. 확인·수정·도감 선택까지 연결하고 검증한 단위별로 커밋한다.
4. **배경 연결과 실패 복구**: 장소 판정 후 배경을 요청하고 저장한다. 실패·시간 초과는 프리셋으로 진행한다. 생성 결과를 무대와 책에서 사용한다.
5. **책 보관**: 최종 자막·미션 결과와 등장인물·아이 그림을 저장한다. 재시작 후 저장한 책을 다시 읽어 같은 내용을 확인한다. 저장 실패를 성공으로 표시하지 않는다.
6. **통합 검증**: 전체 Android 테스트, 최신 APK, 이 PC 에뮬레이터에서 동화 완주·미션·책장 재열기를 확인한다. 실제 AI 확인은 조장이 운영하는 서버에 연결해 별도로 기록한다.

## 유지할 규칙

- 변경과 푸시는 `feature/minwoo`만. 공통 변경은 main을 통해 받는다.
- 13시·18시 병합 전에 최신 main을 반영하고 전체 테스트가 통과한 상태를 올린다.
- 기능이 검증될 때마다 관련 파일만 커밋하고 푸시한다. 실패한 중간 상태를 커밋 수를 위해 올리지 않는다.
- 12개 공통 슬롯은 유지한다. 틀 고유 답은 `extra`에 출처를 남긴다.
- 서버와 이름을 복원할 때 같은 `nameMask`를 사용한다. 목소리 이름 동의는 기존 공통 경로를 따른다.
- 페이지 목록과 미션 번호는 앱이 보낸다. 6장·8턴 강제 제한을 만들지 않는다.
- 공통 서버·마이크·음성 문제는 조장에게 구체적인 재현과 필요한 계약을 공유한다. 새 서버 계약을 임의로 만들지 않는다.
- 소리 만들기는 기존 일반 받아쓰기와 분리되어야 한다. 현재 공통 마이크가 음성을 서버로 전사하는 경로이므로, 로컬 소리 보관을 연결하기 전에 공통 담당자와 맞춘다.
