# 동화 모드 V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 실제 기기에서 아이의 말로 질문 순서와 책 내용이 달라지고, 생성 그림과 저장 결과까지 확인되는 동화 모드.

**Architecture:** 동화 모드 전용 흐름이 공통 입력과 `Server` 클라이언트를 사용한다. 공통 마이크·이름 가리기·음성 재생·이미지·저장 API는 조장 담당이다. 동화 모드는 판정 결과를 상태와 다음 질문에 적용하고, 서버가 돌려준 장면 목록을 그대로 책으로 넘긴다.

**Tech Stack:** Kotlin, Jetpack Compose, FastAPI, Android Gradle unit tests.

**Spec:** `guidelines/1_시스템_개요.md`, `guidelines/2_공통_데이터_모델.md`, `guidelines/3_API_명세.md`, `guidelines/6_통합_체크포인트.md`, `docs/조장_인수인계.md`. 동화 장수 고정 해제는 2026-09-29 조장 결정이라고 사용자가 전달했다. 문서의 6장 고정 문구는 이에 맞게 갱신되어야 한다.

## Global Constraints

- 작업 브랜치는 `feature/minwoo`; `main`에는 직접 쓰지 않는다.
- 슬롯 이름은 12종만 사용한다. 그 밖의 이야기 조각은 `extra`에 원문과 `of`를 남긴다.
- 끝나는 기준은 `story_ready`, `mascot_pick` 연속 2회, 15분이다. 8턴 상한은 사용하지 않는다.
- `by`는 `child`, `card`, `mascot` 중 하나다. 마스코트가 채운 말은 아이 발화로 기록하지 않는다.
- 실명은 폰에서 가린 뒤 서버에 보낸다. 가려지지 않은 입력은 라이브 요청으로 보내지 않는다.
- 이미지 결과는 안전 검사 후 보여주고, 실패 시 프리셋으로 진행한다.
- 장수는 템플릿 숫자로 고정하지 않는다. 생성 결과가 지나치게 길거나 반복될 때의 판정은 조장 소유 `/story` 계약에서 정한다.

## Review Focus

- 답 하나에 두 칸이 채워졌을 때 이미 나온 답을 다시 묻지 않는가.
- `next_slot`이 없거나 이미 찬 칸일 때 틀 빈칸 또는 다음 유효한 질문으로 이어지는가.
- 판정이 실패해도 아이가 한 말을 지어내지 않고 다시 답하거나 카드로 진행할 수 있는가.
- 8턴을 지나도 이야기 재료가 남으면 강제로 책을 만들지 않는가.
- 생성 장면 수가 6장이 아니어도 마지막 장면까지 넘기고 정확한 자막을 보여주는가.

## Integration Dependencies (2026-09-29)

- 조장이 공통 마이크 입력, 폰의 실명 가리기·복원, 음성 재생, `/image` 안전 검사 경로를 작업 중이며 이후 합칠 예정이라고 사용자가 확인했다. 공통 파일은 동화 브랜치에서 임의로 바꾸지 않는다.
- 현재 서버 `/story` 검증은 동화 6장 고정이고, Android `Server.story()`는 장면의 `keywords`를 버린다. 조장 결정인 유동 장수와 이미지 배치에 맞춰 API 계약을 합쳐야 한다.
- 유동 장수 책의 장면별 그림 종류와 미션 위치는 현재 `/story` 응답의 `caption`·`keywords`만으로 결정하기 어렵다. 이 계약이 정해지기 전에는 기존 템플릿의 미션 위치를 생성 자막에 임의로 적용하지 않는다.
- 현재 `adb devices -l`에서 연결된 실기기가 0대다. 실제 음성·서버·그림·재시작 검증은 공통 기능 통합과 기기 연결 후 진행한다.
