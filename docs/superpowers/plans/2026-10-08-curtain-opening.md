# 오또 커튼 시작 연출 구현 계획

> 실행: `superpowers:executing-plans`로 단계별 구현·검증한다. 사용자와 조장이 승인한 10-08 HTML 연출을 기준으로 한다.

## 목표와 승인된 사양

오른쪽 줄을 아래로 당겨 놓으면 커튼이 열리고 두 간판이 내려온다. 가운데에 맞춘 「말로 만드는 그림책」과 「오또」 간판이 내려온 후 번들 「오또!」 음성을 끝까지 재생한다. 간판이 올라가고 카메라가 뒤로 빠지면서 실제 메인 화면의 작은 극장임을 보여 준다. 전신 오또가 커지며 카펫의 실제 대기 위치로 네 번 통통 이동한다. 소리는 소개 음성과 말랑 젤리(A2)만 사용한다. 도착 울음·포탈은 없다.

기준: 사용자 승인 `poc-html/app-preview`의 1200×675 구도·타이밍. 앱은 화면 비율별 기존 방 좌표를 사용한다. 실제 메뉴·계정·동의 흐름을 그대로 연결하며 연출 중 메뉴 입력은 막는다. 처음 설정이 필요한 경우 기존 로그인/동의로 간다.

## 구조와 제한

- Kotlin/Compose, 기존 최소 API 24 유지. 새 라이브러리·서버 호출 없음.
- `ui/shell/OpeningMotion.kt`: 드래그 저항, 타임라인과 점프 좌표. 순수 함수 테스트.
- `ui/shell/OpeningArt.kt`: 승인 이미지와 간판을 Canvas에 그림. 전신 이미지의 동일 비율 변환만 사용.
- `ui/shell/CurtainOpening.kt`: 제스처, 프레임 시계, 생명주기, 번들 소리, 건너뛰기.
- `Room.kt`: 실제 방 배치를 공유하고 인트로 중 입력·마스코트·대기 안내를 억제.
- `OttoShell.kt`: 기존 TITLE의 완료 콜백에 연결. Director/API/데이터 계약 변경 없음.
- 자산 출처: 사용자가 승인한 PoC. 선택한 두 소리만 번들에 포함. 소리 설정 존중, 화면 종료 시 해제.

## 검토 초점

짧은 드래그·취소는 시작하지 않아야 한다. 음소거·오디오 오류는 멈춤 없이 끝나야 한다. 백그라운드에서는 소리와 시간이 멈춰야 한다. S7/태블릿 비율에서 밧줄이 눌리고 간판이 잘리지 않아야 한다. 건너뛰기가 로그인·동의·메뉴를 우회하면 안 된다.
