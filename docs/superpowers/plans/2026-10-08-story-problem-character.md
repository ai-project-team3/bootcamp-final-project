# 동화 문제 인물 추가 구현 계획

> 실행: `superpowers:executing-plans`로 단계별 구현과 검증을 진행한다.

**목표:** 주인공·아이 그림과 별도로 이야기 속 문제 인물 한 명을 무대와 책에 보여 주고 다시 열어도 보존한다.

**구조:** 역할별 생성 인물 목록을 공통 저장 형식에 추가한다. 기존 단일 친구 접근과 이전 책은 호환한다. 동화에서만 인물 추출과 그림 선택 후 요청을 적용하고, 협업의 기존 생성 조건은 유지한다.

**기술:** Kotlin, Compose, 기존 Server.character, 로컬 JSON 책장, Robolectric.

**명세:** GitHub #339 본문 및 2026-10-08 조장 보충 댓글. 시작 main fab62a41.

## 제약과 검토 지점

- 아이 그림을 외부로 보내지 않는다. 그 친구 그림 요청도 보내지 않는다.
- 추가 문제 인물은 child 출처 problem/cause의 명확한 생물·인물 표현에서만 찾는다. 애매한 표현은 보류한다.
- 기존 /image 안전 검사와 비동기 15초 제한을 유지한다. 서버 계약은 변경하지 않는다.
- 주인공·새 친구와 같은 인물을 중복 생성하지 않는다. 늦은 응답이 바뀐 이야기에 끼어들지 않는다.
- 이전 저장 책, 협업, 손상된 메타데이터의 이미지 보존을 검사한다.
- 그림판/확인 화면을 비동기 완료가 덮지 않아야 한다. 세 인물은 배경 조각과 미션 조작 영역을 가리지 않는다.
