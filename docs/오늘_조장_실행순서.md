### 8. 레포 갈아엎기 순서

**⚠️ 커밋이 먼저다. 삭제의 되돌리기가 그것뿐이다.**
영업 쪽(`backend/` `frontend/` `guidelines/` `gaps/`)은 **이미 커밋돼 있어 지워도 이력에 남는다.** 그런데 **`docs/` 27개는 커밋된 적이 없다.** 순서가 거꾸로면 오늘 작업이 날아간다.

1. **현재 상태 통째로 커밋** — 안전망
2. 삭제 — `backend/` · `frontend/` · `guidelines/` · `gaps/` · `fixtures/` · `docs/역할_배정_*` 2개
3. `CLAUDE.md` · `README.md` 인형극용 재작성
4. `eval/` 신설 — 오늘 세 명이 만드는 파일이 들어갈 자리

**결정이 필요한 셋** (§아래 「물어볼 것」)

### 9. guideline — 무엇을 쓸 것인가

지금 `guidelines/0`~`6`은 **영업 어시스턴트 동결 스펙**이다. 인형극에는 **그 자리에 들어갈 문서가 이미 `docs/`에 있다.**

| 옛 guidelines | 인형극에서 그 자리 |
|---|---|
| 1 시스템 개요 | `기술개요.md` |
| 2 공통 데이터 모델 | **없다 — 새로 써야 한다** (슬롯 11종 · 이벤트 11종 · `by` 3종) |
| 3 API 명세 | **없다 — 백엔드를 만들 때** |
| 4 프롬프트 브리프 | `프롬프트_모음.md` |
| 5 기술스택·폴더구조 | **없다 — 레포를 갈아엎으며 정한다** |
| 6 통합 체크포인트 | `현재상태_다음세션.md` + `오늘_모델검증_역할.md` |

> **새로 쓸 것은 둘뿐이다 — 데이터 모델과 폴더 구조.** 나머지는 이미 있고, 없는 걸 또 만들면 **어느 쪽이 최신인지 모르게 된다.**
> **데이터 모델이 급하다.** 오늘 세 명이 슬롯 이름·이벤트·`by`를 각자 코드에 박는데, **한 곳에 안 적어 두면 내일 안 맞는다.**
