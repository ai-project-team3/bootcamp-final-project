# 오프닝 화면 비율과 #453 흐름 검토

확인일: 2026-10-13. 기준: 원격 main `3a846762`. 요청: 최민우, #453.

## 1. 결론

- **#453의 방향은 권장한다.** 커튼 무대에서 보호자 준비를 마친 뒤 오또가 방으로 이동하면, 놀이 입장 연출 뒤에 다시 설정 화면으로 돌아가는 현재의 단절을 줄일 수 있다. 이는 설계 판단이며, 실제 아동 사용성 시험으로 효과를 검증했다는 뜻은 아니다.
- 로그인·약관을 로고 크기의 좁은 자리 안에 축소해서 넣는 방식은 권장하지 않는다. 무대 배경을 유지하고, 읽을 수 있는 보호자 패널을 올린다. 오또는 패널 옆에서 대기하고 설정 중에는 움직임·음성을 멈춘다.
- 최신 main에서 신고된 다른 폰의 양옆 잘림은 **아직 재현하지 못했다.** 수치 검사가 통과했고 실제 앱의 FitScreen을 포함한 35장 렌더를 생성해 대표 장면을 시각 확인했다. 기준 이미지와 자동 비교한 결과는 아니다. 해당 기기의 모델·앱 종류·설치 소스·잘린 장면 사진이 필요하다.
- 이 변경은 검증과 검토 문서다. 카메라·오프닝·인증·동의의 실제 동작을 바꾸지 않는다. #453 구현 또는 실기기 잘림 해결을 완료로 표시하지 않는다.

## 2. 비교한 모바일 게임 사례

공식 안내에서 확인할 수 있는 계정 진입·보호자 경로만 비교했다. 게임을 설치해 최신 전체 오프닝을 직접 재생한 것은 아니며, 아래 자료가 동일한 커튼 연출을 입증하지는 않는다.

| 사례 | 공식 자료에서 확인한 흐름 | 오또에 적용할 판단 |
|---|---|---|
| Minecraft 모바일 | 메인 메뉴의 Sign In에서 로그인 안내로 진입하고, 계정 정보가 맞는지 확인한다 | 브랜드 시작 화면과 인증 진입을 연결할 수 있다. 외부 인증 화면까지 앱 배경으로 강제로 감싸는 것은 별개의 일이다 |
| Clash Royale / Supercell ID | 계정 전환 때 타이틀에서 Login with Supercell ID 또는 Play without Supercell ID를 선택한다 | 로그인 필요 여부를 분기할 수 있다. 오또는 보호자 동의가 필요하므로 게임의 게스트 정책을 그대로 가져오지 않는다 |
| Sago Mini World | Get Started 뒤 계정 생성 안내로 진입하고, Parents 영역의 Account 탭에서도 계정 생성이 가능하다고 안내한다 | 아이의 놀이 경로와 보호자 계정 입력의 역할을 구분하면서 브랜드 흐름은 이어갈 수 있다 |

## 3. 권장 순서

### 처음 설치 · 아직 보호자 준비가 끝나지 않은 상태

1. CLAP.
2. 줄 당기기 → 커튼 열기 → 로고와 오또 소개.
3. 로고가 완전히 올라간 뒤, 열린 무대에 보호자 패널. 오또는 대기.
4. 기존 로그인 → 약관 → 마이크 안내·권한 → 부모 PIN → 맞춤 설정을 진행한다. 만 나이 선택은 선택 항목 그대로 둔다.
5. 기존 보호자 기능 안내와 ‘아이에게 건네기’까지 마친다.
6. 오또가 무대에서 방으로 이동한다.
7. 처음인 아이에게 기존 방 둘러보기·말하기 연습을 제공한 뒤 메뉴를 연다.

### 같은 보호자로 준비가 끝난 재실행

CLAP → 커튼·소개 → 보호자 준비 단계 건너뛰기 → 오또가 방으로 → 메뉴.

### 약관 변경 · 로그인 만료 · 다른 보호자

- 먼저 기존 `Shell.startStep()` / `afterLogin()`의 계정별 판정으로 필요한 단계만 정한다.
- 열린 무대의 보호자 패널에서 필요한 재로그인·재동의·마이크 안내를 진행한다.
- 다른 보호자에게 이전 보호자의 동의를 물려주지 않는다. 약관 취소·로그인 실패·뒤로 가기를 동의 완료로 처리하지 않는다.
- 외부 계정 앱·브라우저·안드로이드 권한 창이 뜨는 동안에는 무대 시계와 음성을 멈춘다. 돌아오면 같은 패널 단계로 복귀한다.
- 샘플 책 경로는 기존 로그인·녹음·동의 제한을 유지하는 별도 분기다.

## 4. #427 · #422와의 관계

- #427의 ‘앱을 새로 켤 때 커튼’은 유지한다. 로그인 창에서 복귀하거나 약관 취소로 되돌아가는 순간에는 새 오프닝으로 간주하지 않는다.
- #422의 시작 화면은 별도의 전체 화면으로 또 이동시키기보다 무대의 시작 상태 안에 합치는 방향을 권장한다. 줄 당기기가 이미 시작 행동이므로 정상 경로에 ‘눌러서 시작’을 한 번 더 요구하지 않는다.
- ‘건너뛰기’는 연출만 생략하고 기존 준비 판정을 거쳐야 한다. 미동의 사용자를 방의 실제 놀이로 곧장 보내면 안 된다.

## 5. 구현 시 분리할 것 — 제안, 이번 PR 미구현

- 연출을 `소개 → 보호자 준비 → 방 입장`의 세 구간으로 나눈다. 현재 `4050ms`부터 무대가 사라지고 `4480ms`부터 오또가 이동하므로, 현재 시계를 임의의 시점에 멈추는 것만으로는 로고 완전 퇴장·무대 대기 조건을 만족하지 못한다.
- 보호자 준비 구간은 독립된 정지 무대다. 별도의 방 입장 시계를 시작하기 전에는 무대 페이드·카메라 이동·오또 점프를 실행하지 않는다.
- 기존 로그인·동의의 데이터 및 조건은 재사용한다. 화면 배경을 그리는 부분과 인증 상태를 판단하는 부분을 구분한다. 기존 화면이 자체 불투명 배경을 채우므로 뒤에 무대 그림을 추가하는 것만으로는 보이지 않는다.
- 긴 약관·PIN·키보드를 고려한 스크롤 패널을 사용한다. 폴드·태블릿·세로에서 폼을 작게 줄이지 않고 읽기 영역을 확보한다.
- 메뉴·뒤의 마이크가 입력을 받지 않도록 기존 Shield를 유지한다. 설정 중 움직임을 기다리는 무한 루프나 애니메이션 완료 전 메뉴 활성화가 없어야 한다.

## 6. 화면 비율 점검

`OpeningFramesTest`의 캡처를 실제 앱과 같은 `MaterialTheme(PuppetTypography) → FitScreen → OpeningScene` 경로로 바꿨다. 기존 캡처는 화면 맞춤을 제외한 장면만 그렸다.

| 구분 | 논리 화면 dp | 검증 |
|---|---|---|
| S7 유사 16:9 | 640×360 / API26 | 7개 시점 렌더 |
| 긴 가로 폰 | 915×412 / API34 | 7개 시점 렌더 |
| 폴드 안쪽 비율 | 768×640 / API34 | 7개 시점 렌더 |
| 태블릿 | 1280×800 / API34 | 7개 시점 렌더 |
| 세로 창 | 800×1280 / API34 | 7개 시점 렌더 |
| 더 긴 외부 창 · 4:3 | 940×360 · 1024×768 | 무대 경계 수치 검사 |

- 렌더 시점: 0, 2920, **4250(카메라 전환)**, 5200, 6400, 8000, 9800ms. 총 35장.
- 추가 수치 검사: 7개 비율에서 무대가 보이는 0~4848ms를 16ms 간격으로 확인, 총 2,128개 상태. 무대 네 경계가 화면 안에 있음을 검사했다. 기존 밧줄 위치·점프 귀·발 경계 검사도 유지했다.
- `OpeningFramesTest`: 7개 검사 통과. 확대는 현재 코드의 `min(width/stageWidth, height/stageHeight)` 방식으로 전체 무대를 보존한다. 넓은 화면의 좌우 여백, 좁은 비율의 위아래 여백을 이미지 잘림으로 기록하지 않는다.
- 실제 신고된 폰, 카메라 구멍·노치·내비게이션 영역·제조사 표시 설정·분할 화면은 이 렌더만으로 검증하지 않았다. 모델명만으로 실제 화면 dp를 단정하지 않는다.
- 다른 폰의 실제 장면과 캡처를 대조해 내용 잘림이 확인되면 그때 재현 검사를 실패시키고 해당 원인을 고친다. 지금은 재현되지 않은 증상을 숨기는 확대율 보정을 넣지 않았다.

산출물: `android/app/build/opening/<구분>-<시각>.png`. 생성 이미지는 커밋하지 않는다.
