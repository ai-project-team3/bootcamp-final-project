## 1. 모델 — 하나는 없는 모델이고, 하나는 진짜다

### 확인된 것

멘토 권고는 *"GPT-6과 Claude Sonnet 5.5로 올려라. 5.5가 더 싸다"* 였다. 둘을 따로 봐야 한다.

#### 1-1. `Claude Sonnet 5.5`는 **없는 모델이다**

Anthropic 현행 목록에 Sonnet 5.5는 없다. Sonnet 계열 최신은 **`claude-sonnet-5`**, 값은 **$2 / $10** (입력/출력 100만 토큰).
"더 싸다"도 성립하지 않는다 — 우리는 이미 Claude를 재 봤다.

| | 입력 단가 | 우리 프롬프트 입력 토큰 | 한 권 판정 값 |
|---|---|---:|---|
| `gpt-5.6-luna` (지금) | $0.20 | 3,987 | **21.6원** |
| `claude-haiku-4-5` (측정 완료 09-20) | $1.00 | **6,129** | **157원 — 7배** |
| `claude-sonnet-5` (미측정) | **$2.00** | 재 봐야 함 | 단가만으로 haiku의 2배 |

`claude-haiku-4-5`가 7배가 된 이유는 단가 5배 **곱하기** 토큰 1.5배였다. 같은 한국어 프롬프트인데
Claude 토크나이저가 54% 더 쪼갠다. Sonnet 5는 haiku보다 단가가 두 배라, 토큰 배수가 그대로면
**한 권 300원대**가 된다. 한 권 합격선이 총 200원이고 그 90%를 이미지가 쓴다.

→ **권고를 받지 않는다.** 레포 규칙대로 *추천은 측정 우선순위만 바꾼다.* 다만 품질이 갈리는 곳이 있는지는
보고 싶으므로, **haiku 측정 때 쓴 같은 배터리를 Sonnet 5로 한 번 돌려 대안 칸에만 숫자를 채운다**(값 200원 내외, 1회).

#### 1-2. `GPT-6`은 실재하고, **여기에 건질 것이 있다**

9월에 두 번 나왔다. 9/3 Astra, 9/22 Sol·Luna 가격 인하.

| 모델 | 입력 | 출력 | 우리에게 |
|---|---|---|---|
| `gpt-6-astra` | $10.00 | $50.00 | 후보 아님 — luna의 50배 |
| `gpt-6-sol` | $2.00 | $10.00 | 후보 아님 — luna의 20배 |
| **`gpt-6-luna`** | **$0.10** | **$0.50** | **지금 쓰는 것의 입력 절반 · 출력 42%** |
| `gpt-5.6-luna` (지금) | $0.20 | $1.20 | |

**같은 이름의 같은 체급이 세대만 올라가며 값이 반으로 내려갔다.** 토큰 수가 같으면 21.6원 → **약 10원/권**.

값이 이유의 전부는 아니다. 미해결로 남겨 둔 것이 하나 있다 — **p95가 2.389초에서 3.789초로 밀렸다**
(`eval/results.md` 두 번의 100문항 배터리). 판정은 아이를 기다리게 하는 자리라 이 숫자가 값보다 중요하다.
세대가 올라가면 여기가 같이 달라질 수 있고, 안 달라지면 그것도 답이다.

### 조건부 함의

**오늘 돌릴 수 있고, 사실상 공짜다.** 배터리가 이미 있다.

```
python -m eval.run_team_eval --models gpt-6-luna --yes-spend
```

100문항 1회 ≈ **10원**. 뒤집기 조건을 먼저 박아 둔다(규칙: 기준을 데이터보다 먼저 정한다):

| 합격선 | 기준 | 근거 |
|---|---|---|
| JSON 성공률 | **100.0%** | luna·nano 둘 다 100을 냈다. 이건 타협 항목이 아니다 |
| 필수해제 | **≥ 0.750** | 지금 luna 값. 규칙 2(`no_longer_needed`)가 여기 걸려 있다 |
| `s1_reason` | **≥ 0.842** | 지금 luna 값 |
| p95 | **≤ 2.4초** | 첫 측정값. 지금 3.789초로 밀려 있어 **회복도 합격**이다 |

셋 중 하나라도 떨어지면 `gpt-5.6-luna`를 유지한다. 신뢰구간이 겹치면 동률로 읽고, **동률이면 싼 쪽으로 간다**
— 값이 같은 체급에서 절반이므로, 동률은 교체 사유가 된다.

#### 1-3. 「모델을 쉽게 갈아탈 수 있게 자리를 비워 두라」 — **이미 그렇다**

멘토 액션 아이템 8번이다. 우리는 이미 `.env`의 `LLM_MODEL`을 읽고(`config.py:7`),
`CLAUDE.md`에 *"모델 ID를 상수로 박지 않는다"*가 규칙으로 적혀 있다. **할 일 없음.**
교체는 `.env` 한 줄이고, 그래서 위 측정이 값싸다.

#### 1-4. 오늘 눈에 걸린 어긋남 하나

`backend/.env.example:12`가 `STT_MODEL=large-v3-turbo`다. **09-23에 `large-v3`로 확정했다**
(3~6세에서 turbo 대비 CER 절반). 새로 받는 사람이 이 파일을 복사하면 탈락한 모델로 시작한다. **1줄 수정.**

## 2. 내레이션 — TypeCast

### 확인된 것

멘토 권고: *"TypeCast 무료 티어가 넉넉하고 한국어 목소리가 자연스럽다."*

발표용 해설은 **이미 끝났다** — `eval/tts_out/demo/narration_echo.wav`(`gpt-4o-mini-tts` · `echo`).
시연 영상 길이에 맞춰 잘라 놨다. **9/28 발표를 위해 TypeCast를 쓸 이유는 없다.**

### 조건부 함의

쓸 자리가 따로 있다. 아직 미결인 두 칸이다.

| 자리 | 지금 | TypeCast가 후보인가 |
|---|---|---|
| 고정 대사 번들 | *"무엇으로 구울지 미정"* | **예.** 사전 합성이라 지연·값이 무관하고 귀 판정만 남는다 |
| 가변 낭독(아이 문장 읽기) | **미결** — 폰 TTS는 9/19 귀 판정 3연속 「아니오」로 탈락 | **조건부.** 런타임 호출이면 그림·음성이 아닌 **글자**가 외부로 나간다. 규칙 5·6과 대조해야 한다 |

기준은 값이 아니라 **귀**다. 폰 TTS를 떨어뜨린 방식대로 같은 문장 셋을 세 목소리로 굽고 눈 가리고 듣는다.
**값싼 것이 근거가 되지 않는다** — 무료라는 이유만으로 표를 바꾸지 않는다.

## 3. 타겟 기기가 태블릿으로 확정됐다 — 이게 가장 큰 파장이다

### 확인된 것

멘토가 **대상 기기를 태블릿(갤럭시 탭·갤럭시 A)으로 확정**하고 *"태블릿에 맞춰 UI를 설계하라"*고 했다.

우리 앱은 **가로 전용으로 만들었다**(`screenOrientation="sensorLandscape"`). 그런데 `targetSdk 36`부터
**폭 600dp 이상 큰 화면에서는 이 설정이 무시된다**(09-23 박진웅 지적 6). 그래서:

- 09-23에 태블릿 세로에서 `Padding must be non-negative`로 **앱이 죽는 것을 고쳤다**(`Screen.kt`, `TabletPortraitShotTest`가 잡았다)
- **죽지만 않게 됐고, 레이아웃은 아직 깨진다** — 배경이 좌우로 잘리고 인물이 하늘에 더 크게 뜬다(`무대_배치_규칙.md` §3-1)

### 조건부 함의

**우선순위가 바뀐다.** 태블릿 세로는 「선택 스크린샷」이 아니라 **심사자와 테스터가 실제로 보는 첫 화면**이다.
스토어 등록정보에 "태블릿 스크린샷 — 선택"으로 적어 둔 것을 **필수로 올린다**(`스토어_등록정보.md` 아직 없는 것).

그리고 이것은 치영님이 지금 하고 있는 **무대 배치 규칙 구현과 같은 파일**이다(`Screen.kt` `WorldItemView`).
따로 하면 두 번 고친다 → **한 작업으로 묶어 치영님에게 넘긴다.** 문서는 이미 §3-1에 있다.

## 4. 레이어 분리 · 이미지 사전 생성 — 하나는 이미 있고, 하나는 규칙과 부딪힌다

### 4-1. 레이어 분리 (배경 / 에셋 / 상호작용) — **문서에 이미 있다**

멘토가 말한 그 구조가 `무대_배치_규칙.md` §2 마지막 줄이다:
*"그리는 순서: 배경 → (뒤 인물) → 그림자 → 인물 → 앞 레이어 → 핫스팟"*.
핫스팟(상호작용)이 별 레이어로 이미 분리돼 있고, 인물 앞뒤로 배경 띠를 한 번 더 그리는 것까지 숫자로 적혀 있다.
**추가 설계 없음. 구현 대기(치영님).**

### 4-2. 「질문 받으면 이미지를 여러 장 미리 만들어 DB에 넣어라」 — **규칙 8과 대조가 필요하다**

**확인된 것.** 규칙 8은 *"그림은 세션 중에 만들되 아이를 기다리게 하지 않는다"*이고, 배경 생성은 **3.74초**로
측정됐다(09-21, 8스텝 LoRA). 만지는 오브젝트는 **프리셋 — 0초**다.

**조건부 함의.** 멘토 권고는 규칙 8의 **부정이 아니라 연장**으로 읽힌다 — 세션 중 생성은 그대로 두고,
**만든 것을 버리지 않고 저장**하는 것. 그러면 같은 장소가 두 번 나올 때 0초가 되고, 책장에 남길 그림도 생긴다.
여기까지는 규칙과 부딪히지 않는다.

**부딪히는 건 「여러 장」이다.** GPU가 RTX 3060 12GB 하나이고, 조합 A(이미지+STT+화자분리)가 이미 **10.4GB**다.
그래서 시간 공유로 쓴다 — *아이가 말하는 동안에는 이미지를 만들지 않는다*(겹치면 STT가 3.6배 느려진다).
질문 하나에 미리보기 여러 장을 만들면 그 예산을 넘는다. **몇 장까지 되는지는 재 봐야 안다.**

→ **받을 부분:** 생성한 그림을 저장해 재사용(값 0, 규칙 8 유지).
→ **측정 뒤로:** 한 질문에 여러 장 사전 생성(3060에서 몇 장·몇 초인지 모른다).

### 4-3. 일기 모드 화이트보드 — **차별점 1을 정면으로 본다**

멘토 아이디어: 인터뷰 대신 **화이트보드에 그리게 하고 AI가 실시간으로 그림을 알아보고 질문**한다.

*"AI가 다시 그리지 않는다"*와는 부딪히지 않는다 — 알아보는 것과 고쳐 그리는 것은 다르다.
**부딪히는 건 「그림이 어디로 가나」다.** 차별점 1과 규칙 6이 *"아이가 그린 그림은 폰 밖으로 안 나간다"*고
못 박았고, 데이터 보안 양식에서 그림을 「수집」에서 **뺀 것**이 바로 이 때문이다(09-23 박진웅 지적 1).

→ **서버로 그림을 보내는 인식은 할 수 없다.** 온디바이스 인식(ML Kit 잉크 인식 등)이면 성립하고,
그게 아니면 이 아이디어는 **우리 제품의 차별점 둘 중 하나를 버리는 값**이다. 조사 대상이지 채택 대상이 아니다.

### 4-4. 부모 모드 고정 템플릿 — 작고 값싸다, 진웅님 몫

지금은 어른이 질문을 **직접 적는다**(진웅님이 만든 자유입력 + 흐름 + 검사). 멘토 권고는
*"채우게 하지 말고 고정 템플릿(어린이집 테마·할머니집 테마)을 주고 탭만 하게 하라"*다.

자유입력을 없애자는 게 아니라 **위에 얹는 것**이다. 우리 구조가 `List<String>` 위치 슬롯이라
템플릿은 그 목록을 채워 주는 버튼일 뿐이다. **구현 작다. 만든 사람이 하는 게 맞다.**

## 5. 데이터베이스 — 조장이 물은 것

### 확인된 것 — 설계는 이미 있고, 구현은 0이다

**설계.** `guidelines/3_API_명세.md` §3-5에 **9/18 멘토 지시로 이미 명세가 들어와 있다.**
`POST /device/register` · `GET /shelf/{id}` · `POST /shelf/{id}/book` ·
`PUT /session/{id}/checkpoint` · `GET /session/{id}/checkpoint`. 기기 식별키로 시작하고 구글 로그인은 나중.
**새로 설계할 게 없다.**

**구현.** 아무것도 없다. 세 곳을 다 봤다.

| 어디 | 상태 |
|---|---|
| `backend/requirements.txt` | `fastapi · uvicorn · pydantic · pydantic-settings · python-multipart · httpx` — **DB 의존성 0개** |
| `backend/main.py` | 라우터 셋(`judge`·`story`·`stt`)뿐. **`shelf`·`checkpoint`·`device` 라우터가 없다** |
| 앱 | `INTERNET` 권한 없음 · HTTP 클라이언트 없음 · **Room·DataStore·SharedPreferences 중 아무것도 없음** |

즉 앱의 모든 상태는 `Director` 메모리에만 있다. **앱을 끄면 전부 사라지는 게 지금 맞다.**

### 조건부 함의 — **순서가 결과를 가른다**

조장이 든 두 쓰임은 **성질이 다르다.** 같이 묶으면 순서를 틀린다.

| 쓰임 | 무엇이 문제인가 | 누가 풀어야 하나 |
|---|---|---|
| **중간에 나가면 이어하기** | 앱이 꺼졌다 켜진다 | **폰.** 서버는 필요 없다 |
| **만든 책 보관(책장)** | 기기를 바꿔도 남아야 한다 | **서버.** §3-5가 이것 |

**"중간에 나가면 이어하기"는 서버 문제가 아니다.** 같은 폰에서 앱이 다시 켜지는 것뿐이므로 폰 안에 쓰면 끝난다.
서버로 가면 네트워크 왕복·권한·오프라인 실패 경로·비행기 모드까지 새로 만들어야 하고, **그 셋 다 이 쓰임에는 필요 없는 것이다.**
지금 앱은 네트워크를 아예 못 쓰므로 서버부터 하면 **없는 것 두 개를 동시에** 만드는 셈이다.

**그래서 순서는 이렇다.**

| 단계 | 무엇 | 어디 | 왜 이 순서 |
|---|---|---|---|
| **1** | 체크포인트 — 턴마다 덮어쓰기 | **폰** (`DataStore` 파일 하나면 된다. 작고 자주 쓰는 것이라 Room이 과하다) | 네트워크 없이 된다. 오늘 할 수 있다. **다섯 살이 15분 쌓은 것을 지키는 건 이 단계에서 이미 끝난다** |
| **2** | 책장 — 책 목록·쪽·발화 | **폰** (`Room`. 책–쪽–발화 관계가 생기므로 여기서는 Room이 맞다) | 책이 남는다. 여전히 네트워크 없이 |
| **3** | 서버 책장 + 기기 식별키 | **백엔드** §3-5 그대로. **SQLite로 시작한다** — 파이썬 표준 라이브러리라 의존성 0개, 비공개 테스트 12명에는 넘친다 | 기기를 바꿔도 남는다. 앱 네트워크 계층(`/judge`·`/stt`)과 **같이** 붙는다 |

1·2를 건너뛰고 3으로 가면 **되는 일이 하나도 없다.** 3만 있으면 비행기 모드에서 앱이 아무것도 기억하지 못한다.

### 확인되지 않은 것 — 그리고 §3-5가 답하지 않는 것 하나

**규칙 6과 차별점 1이 서버에 올릴 것을 이미 제한한다** — 그림과 음성은 폰 밖으로 안 나간다.
그러면 **서버 책장에는 책의 그림이 없다.** 글자와 목록만 있다.

→ 기기를 바꿨을 때 *"책장이 따라온다"*가 **절반만 성립한다.** 제목과 아이가 한 말은 오고, 그림은 안 온다.
§3-5에 이 답이 없다. **결정해야 한다** — (ㄱ) 글자만 옮기고 그림은 프리셋으로 다시 그린다,
(ㄴ) 그림도 올리고 차별점 1을 다시 쓴다, (ㄷ) 책장 이전은 안 되는 것으로 두고 폰 안 백업만 한다.
**지금 판단으로는 (ㄱ)** — 아이가 **그린** 그림은 못 옮기고, **생성한** 배경은 프리셋·시드로 다시 만들 수 있다.

그 밖에 못 잰 것:

- **체크포인트를 턴마다 쓰면 얼마나 느려지나** — 안 재 봤다. 규칙 8이 *"아이를 기다리게 하지 않는다"*이고 이건 저장에도 걸린다
- **그림이 폰에서 얼마를 차지하나** — 책이 쌓이면 용량이 문제가 된다. 122장이 이미 번들에 있다
- **기기 식별키가 재설치·기기 초기화 때 어떻게 되나** — 진웅님이 짚었고 아직 답이 없다. 지금 설계로는 **책장을 잃는다**
